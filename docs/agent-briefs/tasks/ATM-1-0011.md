# [ATM-1-0011] 統一 Atomic ID canonical 命名並清除雙軌識別

> **ATM 上游契約修正開卡** — 收斂 Atomic ID 為唯一 canonical 主鍵，並清除 planning / schema / registry / fixture 的雙軌識別。
> **定位**：ATM-1
> **前置依賴**：ATM-0-0002、ATM-1-0003 已完成；ATM-1.5-0001/0002 與 ATM-2-0012 為受影響實作/追蹤卡

## 問題描述

現行 ATM 規劃把 task card ID、planning `ATM-CORE-*` 與 upstream spec/registry 的 dot-notation（如 `atom.core-seed`、`atom.plugin-rule-guard.neutrality-scanner`）混成多層識別，導致 Agent 合法地把 dot-notation 當 canonical atomic id。此卡要求把 Atomic ID 收斂為唯一主鍵 `ATM-{bucket}-{NNNN}`（4 位流水號），dot-notation 只能退回 `name/logicalName`；並同步修正 roadmap、active plan、evolution docs、schema、registry、fixtures、validators 與 workbench path，避免再出現第二種 atom id。

## INPUT_CONTRACT

- 名詞定義文件目前只規範任務卡 ID，尚未把 Atomic ID 寫成正式條目
- ATM-1-0003 已交付 Atomic Spec / Registry schema v0.1，但 `id` / `atomId` 尚未強制 `ATM-{bucket}-{NNNN}` pattern
- ATM-1.5-0001/0002 已把 `ATM-CORE-0001` 降成 `legacyPlanningId`，現行 spec/registry 改用 `atom.core-seed`
- upstream `atomic-registry.json`、`specs/atom-seed-spec.json`、`specs/neutrality-scanner.atom.json`、`packages/core/seed.js` 與 validate scripts / fixtures 已實際接受 dot-notation 作 id
- 3KLife 規劃文件（historical roadmap、AI原子框架開發計畫書、關於進化版的原子提案、open-source-extraction-plan、dev-plan/evolution shards）已混用 `ATM-CORE-*` 與 `atom.*` 範例

## OUTPUT_CONTRACT

- [ ] upstream `schemas/atomic-spec.schema.json`、`schemas/registry.schema.json` 對 canonical Atomic ID 加上 hard pattern，`id` / `atomId` 不再接受 `atom.*` 或 `map.*` dot-notation
- [ ] upstream `atomic-registry.json`、`specs/atom-seed-spec.json`、`specs/neutrality-scanner.atom.json`、`packages/core/seed.js`、相關 validate scripts / fixtures / workbench path 全面改用 `ATM-CORE-0001`、`ATM-CORE-0003` 等 canonical id
- [ ] dot-notation 僅保留在 `name` / `logicalName` / `semanticName` 類欄位，不得再作第二種 Atomic ID；`legacyPlanningId` 不得再承擔主識別語意
- [ ] `docs/遊戲規格文件/系統規格書/名詞定義文件.md` 明確新增 Atomic ID 條目，正式區分 `task card id`、`atomicId`、`mapId`、`logicalName` 的角色

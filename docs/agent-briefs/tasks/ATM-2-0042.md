# [ATM-2-0042] Unified Atomic Map Generator — Provisioning Facade & Map ID Policy

> **ATM 原子 map 產生器開卡** — 建立 AtomicMapGenerator 作為新 map 誕生的唯一正式入口，收編 mapId policy、scaffold、mapHash/semanticFingerprint、registry 登錄與測試骨架。
> **定位**：ATM-2（map provisioning / naming convergence / birth facade）
> **前置依賴**：ATM-2-0023 已完成 atomic map schema / registry；ATM-2-0038 已完成 AtomGenerator façade

## 問題描述

目前 atomic map 已有 schema、mapHash 與 registry entry helper，但還沒有像 ATM-2-0038 那樣的正式 birth facade。更關鍵的是，上游 `atomic-map.schema.json` 仍把 `mapId` 綁在 `map.*` pattern，而本地實作／規劃又已出現 `ATM-MAP-*`；若不先收斂 canonical identity、schema pattern、map home/workbench 與 dogfood test，後續 generator 只會再複製一套雙軌識別。

- ATM-2-0023 已定義 atm.atomicMap schema、mapHash helper 與 registry atom/map union
- ATM-2-0038 已證明 generator façade + allocator + registry 寫回模式可行

- 目前 `schemas/registry/atomic-map.schema.json` 的 `mapId` pattern 仍是 `map.*`，與 canonical `ATM-*` 主識別方向不一致
- `atomic_workbench/registry-catalog.md` 與 `atomic-registry.json` 目前尚無第一類 generated map entry 可作 dogfood 證明

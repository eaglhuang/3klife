# [ATM-2-0024] Map-Level Upgrade & Extract-vs-Bump Decision

> **ATM 演進規劃 v2 附錄 B 開卡** — 把「升版 vs. 拆原子」這個關鍵架構決策正式機讀化，避免演化階段隱性破壞 consumer。
> **定位**：ATM-2
> **前置依賴**：ATM-2-0020 / ATM-2-0023 / ATM-2-0042

## 問題描述

在 upgrade pipeline 加入 decomposition decision：判斷某次改動應走 atom-bump、atom-extract、map-bump、polymorphize、extract-shared、infect 或 atomize，並落地對應 proposal、canonical map workbench 與 review path。

## INPUT_CONTRACT

- `ATM-2-0020` 已提供 upgrade proposal schema 與 `behaviorId`。
- `ATM-2-0023` 已提供 Atomic Map schema / registry。
- `ATM-2-0042` 已提供 map generator、canonical `atomic_workbench/maps/<mapId>/` 路徑與 generator provenance。
- ATM 演進規劃書 v2 附錄 B 與 identity / behavior 提案追加 enum 都視為本卡正式 scope。

## OUTPUT_CONTRACT (acceptance)

1. CLI atm upgrade --target map --map <id> --to <ver> 可產出 map-level proposal
2. decompositionDecision 規則明文：API 不變→atom-bump；行為斷裂→atom-extract；跨原子改動→map-bump
3. atom-extract 模式下 proposal 必須同時列舊 atom 保留資訊與新 atom spec stub
4. map-bump 模式下 proposal members[] 必須含舊→新 atomId@version 對照
5. review queue 視 decompositionDecision 路由至對應 reviewer template
6. decompositionDecision enum 加入四個新值：`polymorphize`（多形變體；不改 atomId）、`extract-shared`（不同 map 抽出共用 atom）、`infect`（legacy 注入既有 atom；不創新原子）、`atomize`（legacy 抽出新原子）
7. 每個新增 enum 值對應 ATM-2-0029 reference behavior pack 的某個 behavior plugin；reviewer template 同步擴充
8. decompositionDecision 路由須驗證 `mapId` 符合 `ATM-MAP-{NNNN}` canonical pattern；legacy `map.*` ID 須拒絕或自動遷移
9. `map-propose.ts` 須從 canonical `atomic_workbench/maps/<mapId>/` 讀取 map spec（非舊路徑 `atoms/<owner>/map/`）
10. Upgrade proposal for maps 須帶 `generatorProvenance` 欄位，標示 map 是否由 generator 誕生
11. invalid decompositionDecision / behaviorId pairing 必須 hard fail，避免把 infect / atomize 誤套 evolve template。

# [ATM-2-0049] Task id reservation and lock race hardening

> **Task card system race 修復** — 收斂 `task-id-guard`、`task-card-opener`、`task-lock` 的開卡與鎖卡流程，避免撞號、殘留 reservation-only lock，以及 CLI wrapper 與舊實作漂移。
> **定位**：ATM-2 / 3KLife governance tooling
> **前置依賴**：`ATM-3-0006`、`ATM-3-0010`、`ATM-3-0015`

## 問題背景

今天開卡流程暴露出 task id race：`task-card-opener --next-id-prefix` 會先透過 `task-id-guard` 寫入 `.task-locks/<id>.lock.json` 作為 reservation，但後續成功寫出 Markdown / JSON 後沒有把 reservation 升級成正式 scope lock，導致 `task-lock check` 仍看到 `reservationOnly: true` 與 stale fingerprint。

同時，`task-lock.js` 已改為 LockAdapter thin wrapper，但檔案下半部仍殘留一整份舊 CLI 實作；`lock-adapter-config.js` 的 human override 判斷也反向，讓人名覆寫解鎖失效。這些漂移會讓 reserve / allocate / lock 的真相分散，後續 agent 很容易再次撞號或卡在 stale lock。

- [x] `task-card-opener` 在 write 模式成功後呼叫 `LockAdapter.lock()`，把 reservation-only lock 升級成正式 scope lock；失敗時釋放自己剛建立的 reservation。
- [x] `task-lock.js` 移除舊 CLI 死碼，只保留 thin wrapper，避免 wrapper / legacy 雙實作漂移。
- [x] `LockAdapter.lock()` 對同 agent reservation 進行正式 promotion，清掉 `reservationOnly` / `reservationPrefix` 並重算 fingerprint。
- [x] `lock-adapter-config` 修正 human override 判斷，人名可覆寫解 stale lock，agent slug 不可偽裝成人類覆寫。
- [x] task card path 改走 `task-card-paths` helper，支援 `docs/agent-briefs/tasks/<GROUP>/...` 目錄。
- [x] 補 regression test 覆蓋 reservation reuse、foreign collision、opener promotion、cross-shard lock 與 fingerprint drift。

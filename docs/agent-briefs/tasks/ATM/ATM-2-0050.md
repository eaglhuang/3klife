# [ATM-2-0050] Framework Function Atomization Coverage Gate

> **ATM dogfooding coverage gate** - 建立 Framework Function Atomization Manifest 與 coverage gate，證明 ATM framework Layer 2 功能都有 atom / map / adapter facade 或正式例外。
> **定位**：ATM-2 / framework-wide dogfooding coverage
> **不重複範圍**：ATM-2-0038 / ATM-2-0041 / ATM-2-0042 已承接 AtomGenerator / MapGenerator / provenance；ATM-3-0015 只覆蓋 task card system atomic map。

## 問題描述

ATM 規劃書與任務卡已多次聲明「每個框架功能也必須原子化」，且已有 seed self-governance、neutrality scanner、AtomGenerator、MapGenerator、task card system atomic map 等局部承接；但目前仍缺一份 framework-wide coverage manifest 與 deterministic gate，能逐項證明 CLI、registry、spec / scaffold、test / report、evidence、police、adapter、task lifecycle、map、PEV / lifecycle docs 等 Layer 2 功能都有 atom / map / adapter facade 或正式例外。此卡補的是總控 coverage，不重複任何既有功能卡。

## 固定路線

後續所有「ATM framework-wide 原子化」的補卡與 validator 落地，一律遵守下列固定路線，不得跳步：

1. `ATM-2-0048` 先完成 task-router / onboarding contract，將新工作與無卡意圖都導回 AtomGenerator / MapGenerator canonical path。
2. `ATM-3-0015` 再完成 task card lifecycle atomic map，明確定義 `allocateTaskId -> reserveTaskId -> openTaskCard -> lockTaskScope -> writeTaskShard -> validateTaskShard -> syncDocRegistry -> finalizeTaskLifecycle` 的 governed flow。
3. `ATM-2-0050` 最後才啟用 framework-wide coverage validator，把 CLI、registry、spec / scaffold、test / report、evidence、police、adapter、task lifecycle、map、PEV / lifecycle docs 等 Layer 2 functions 納入統一 gate。

補充規則：

- `ATM-2-0049` 已完成 task id reservation / lock race hardening，視為固定路線的已落地前置，不另占順序節點。
- 在 `ATM-2-0048` 與 `ATM-3-0015` 未完成前，`ATM-2-0050` 底下只允許做 manifest backwrite、gap mapping、advisory analysis；不得把 coverage validator 升級成 block gate。
- 任一 follow-up card 若宣稱處理「全框架原子化」，都必須在 `notes` 或 acceptance 中標明自己屬於上述哪一階段，避免把 task lifecycle coverage 誤判成 framework-wide completion。

## INPUT_CONTRACT

- Layer 1 constitutional schema 只要求 hash-lock / migration gate，不要求自我 atom。
- Layer 2 governed framework functions must have atom / atomic map / governed adapter facade coverage.
- Layer 3 mutable host config 只要求 git / adapter config 管理，不列入必須原子化。
- Existing cards must be reused; do not duplicate generator / task-card / gate-map work.
- ATM-3-0015 covers only task card lifecycle, not the whole framework.
- 不清楚的功能邊界需回查 `docs/ai_atomic_framework/` 規劃書，不以任務卡 notes 片段自行推斷完成。

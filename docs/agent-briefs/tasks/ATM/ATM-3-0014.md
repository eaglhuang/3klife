# [ATM-3-0014] 3KLife UsageEvidence shadow adapter

> **ATM 演進規劃 v2 開卡** — alpha1 期間第一個 evolution-evidence 來源；以最小侵入方式餵養 evolution 管線。
> **定位**：ATM-3
> **前置依賴**：ATM-3-0001 / ATM-2-0009 / ATM-2-0016

## 問題描述

建立 3KLife UsageEvidence shadow adapter，從 artifacts / compute-gate report / logs / canonical map evidence 路徑只讀收集使用回饋，轉成 upstream `usage-feedback` evidence。adapter 必須維持 shadow/parity，不修改既有 CLI、工具輸出或 runtime 行為；所有 host-only 欄位都要隔離，避免污染 upstream evidence schema。

## INPUT_CONTRACT

- 依賴卡 `ATM-3-0001`、`ATM-2-0009`、`ATM-2-0016` 已 done，或提供與其輸出相容的 schema / adapter stub。
- 讀取來源限於 3KLife 現有 artifacts、compute-gate report、logs，以及 `atomic_workbench/maps/` / `atomic_workbench/atoms/` 內的 canonical evidence artifacts。
- `ATM-2-0009` 已提供 `usage-feedback` / `usage-feedback-skipped` evidence schema；本卡只能做 schema-additive 對接，不得要求 upstream schema 破壞式變更。
- `ATM-2-0031` lifecycle police 需要 atom caller-count / zero-caller 資訊作 sweep 輸入；本卡只產 evidence，不直接改 atom lifecycle status。
- 來源欄位到 upstream 欄位的映射必須可審計；host-only 欄位不可出現在 evidence payload 主體。

## OUTPUT_CONTRACT (acceptance)

1. `usage-evidence-shadow` adapter 全程 read-only；任何非 artifact-output 目錄的 file mutation 都視為違規。
2. adapter 同時掃描 `atomic_workbench/maps/` 與 `atomic_workbench/atoms/`，能辨識 atom evidence 與 map evidence artifact。
3. 輸出 payload 必須通過 `ATM-2-0009` 的 `usage-feedback` schema；來源格式漂移時，lenient 模式輸出 `usage-feedback-skipped` 並帶 `skipReason`。
4. usage-feedback evidence 必須包含 atom 層級 `callerCount`，供 `ATM-2-0031` lifecycle police 判斷 zero-caller sweep。
5. usage tracking 必須支援 sub-function / export symbol 粒度，不只記 atomId；此資訊供後續 Demand Police 判斷是否需要 split。
6. 定義 `mapping-table.json`，固定列出來源欄位到 upstream `usage-feedback` 欄位的映射；host-only 欄位一律放入 `extras.adopterPrivate{}`。
7. neutrality scanner 對輸出 payload 跑 dry-run；若 host-only 欄位出現在 payload 主體，strict 模式 hard fail。
8. 提供 `--strict` 與 `--lenient` 兩種模式：strict 對缺欄位或格式漂移 hard fail；lenient 不阻斷 alpha0 / alpha1 critical path，但必須產生可追蹤 skipped evidence。
9. 3KLife 既有 CLI、compute-gate 與工具行為完全不變；需以 shadow/parity fixture 證明 adapter 不影響現有流程。

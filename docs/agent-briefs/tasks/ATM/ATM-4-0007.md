# [ATM-4-0007] H2U normalizeCssColor v1.0→v1.1 evolution pilot

> **ATM 演進規劃 v2 開卡** — 把 alpha1 evolution pipeline 在 H2U case 上做端到端落地，作為 alpha1 acceptance 證據。
> **定位**：ATM-4
> **前置依賴**：ATM-4-0003 / ATM-2-0020 / ATM-2-0021

## 問題描述

以 normalizeCssColor case atom 跑第一次完整 evolution 閉環：proposal → automatedGates → human review → registry update or rollback。此 pilot 必須明確使用 `behavior.evolve`；若實際改動屬於 split、dedup-merge、atomize 等其他行為，必須改開對應 proposal。

## INPUT_CONTRACT

- `ATM-4-0003` 已提供 normalizeCssColor v1.0 case atom 與 registry entry。
- `ATM-2-0020` upgrade proposal 已支援 `behaviorId`。
- `ATM-2-0021` review decision / decision log 已可接 proposal。
- ATM 演進規劃書 v2 附錄 A 與 identity / behavior 追加 acceptance 均視為本卡正式 scope。

## OUTPUT_CONTRACT (acceptance)

1. normalizeCssColor v1.0 進 registry；v1.1 透過 atm upgrade --propose 產 proposal.json
2. automatedGates（nonRegression / qualityImprovement / newCapability）全綠才進 review queue
3. human review approve 後 registry currentVersion 指向 v1.1；reject 後保持 v1.0 並寫 decision log
4. 完整 evidence 鏈可由 atm replay 重新跑 + neutrality scanner 全綠
5. upgrade-proposal.json 必須帶 `behaviorId: behavior.evolve`；若改動本質上是 split / dedup-merge / atomize，必須改用對應 behavior 開新 proposal，不能套 evolve template
6. pilot report 必須列出 proposal、quality report、review decision、registry currentVersion 更新與 rollback proof 路徑。

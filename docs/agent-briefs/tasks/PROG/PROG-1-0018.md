## 開單原因

對 PROG-1-0017（Agent1 完成）進行驗收審查時，發現 2 項驗收條件未達標：

1. **`BattleResult` 型別仍在 4 個地方定義**，未收斂至 `BattleTypes.ts` 唯一來源：
   - `battle/runtime/BattleRuntimeContract.ts:1` — 完整重複定義
   - `battle/controllers/BattleController.ts:45` — re-export 別名 `export type BattleResult = RuntimeBattleResult`
   - `battle/controllers/BattleFlowStateMachine.ts:3` — 局部別名 `type BattleResult = RuntimeBattleResult`

2. **`FRONT_DEPTH` 常數仍有本地副本**：
   - `battle/runtime/phases/BattleSpecialResolvePhase.ts:13` — 未改引用 `BattleTypes.ts` 的 `BATTLE_FRONT_DEPTH`

## 完整描述

### 修補 1：BattleResult 型別去重

- 刪除 `BattleRuntimeContract.ts` 第 1 行的 `export type BattleResult = ...`，改從 `BattleTypes.ts` import
- 刪除 `BattleController.ts` 的 `export type BattleResult = RuntimeBattleResult` 別名，改 import `BattleResult` from `BattleTypes.ts`
- 刪除 `BattleFlowStateMachine.ts` 的局部 `type BattleResult = RuntimeBattleResult`，改 import from `BattleTypes.ts`
- 確保所有用到 `BattleResult` 的檔案仍能正常 import（TS 0 error）

### 修補 2：FRONT_DEPTH 常數去重

- 刪除 `BattleSpecialResolvePhase.ts:13` 的本地 `const FRONT_DEPTH`
- 改 import `BATTLE_FRONT_DEPTH` from `../../BattleTypes`
- 將該檔內所有 `FRONT_DEPTH[...]` 用法改為 `BATTLE_FRONT_DEPTH[...]`

## 如何驗證

```bash
# 1. BattleResult 只剩一個定義
grep -rn "^export type BattleResult\|^type BattleResult" assets/scripts/battle/ | grep -v ".meta"
# 期望：只有 BattleTypes.ts 一行

# 2. FRONT_DEPTH 只剩 BattleTypes.ts 的 BATTLE_FRONT_DEPTH
grep -rn "^const FRONT_DEPTH\|^export const FRONT_DEPTH" assets/scripts/battle/ | grep -v ".meta"
# 期望：0 行

# 3. TS 0 error
node tools_node/compute-gate.js --gates ts-syntax

# 4. 全閘門
node tools_node/compute-gate.js --profile standard --agent-feedback
```

## 建議作法

逐檔修改，每改完一個檔案立即執行 ts-syntax gate 確認不破壞現有引用。

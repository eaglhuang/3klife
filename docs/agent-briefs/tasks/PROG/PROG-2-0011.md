# [PROG-2-0011] CSS coverage → UCUF slot trace（封閉 selectorTracePending）

## 開單原因

PROG-2-0009 Slice #4 已完成 capture/geometry protocol gate，但 zone ownership 報告中 `traceability.sourceDomSelectors` 仍為 `selectorTracePending=true`，導致 non-bake residual zones 無法把「看到的 pixel diff」對回「哪條 CSS selector / UCUF slot」。

新 agent 接到「修這塊區域」的 nextFix 時，需自己重做 trace，效率低且容易誤派工。本卡實作 selector → slot 的可追蹤機制，讓 nextFixes 可直接帶 selector 清單。

## INPUT_CONTRACT

- PROG-2-0009 Slice #4 已完成（capture/geometry protocol gate）
- `compare-html-to-cocos-editor.js` 已能輸出 zone ownership compact summary
- 已有 puppeteer-based CSS coverage API 可用（Page.css.startCoverage / stopCoverage）

## OUTPUT_CONTRACT

- [ ] 新建 `tools_node/lib/dom-to-ui/css-coverage-trace.js`，實作：
  - `startCoverage(page)` / `stopCoverage(page)` — 包裝 puppeteer CSS coverage API
  - `mapZoneToSelectors(zoneRect, coverageData, layoutBundle)` — 給定 zone bbox，回 `{ sourceDomSelectors: string[], ucufNodeIds: string[] }`
- [ ] `compare-html-to-cocos-editor.js` 在 zone ownership 階段呼叫 css-coverage-trace
- [ ] 重跑 gacha-ds3 compare 後，top 20 residual zones 全部具備非空 `sourceDomSelectors` 陣列
- [ ] `selectorTracePending` flag 從 zone ownership report 中移除（或永遠 false）
- [ ] rule-registry.json 新增 H2U-P5-* 規則（例如 H2U-P5-011：`selectorTracePending must be false in formal compare report`）
- [ ] rule-checkers 檢查此規則

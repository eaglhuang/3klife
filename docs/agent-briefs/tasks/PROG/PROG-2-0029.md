## 開單原因
`DataLifecycleScheduler`、`GeneralArchiver`、`SpiritCard` 都寫好了但沒有任何呼叫端；`GameSession` 只會把超齡死亡的武將標成 `dead` 留在名冊，沒有退役流程。MVP 驗收要跑通「祖→父→子」三代循環。

## 範圍
- `LegacyService`：玩家決定的退役（≥65 歲）→ `MentorCard`；季結時死亡武將 → `GeneralArchiver` 英靈卡 + L5 歸檔 + 移出名冊；再呼叫 `DataLifecycleScheduler.onSeasonEnd`，跨年另呼叫 `onYearEnd`
- `GameSession`：`setLifecycle()`、`retireGeneral()`、新事件 `GeneralRetired` / `SpiritCardCreated`，`SeasonAdvancedPayload.lifecycle`
- `ServiceLoader`：與存檔共用同一個儲存後端注入 `LegacyService`
- `GeneralArchiver` 可注入 `PendingDeleteStore`（舊呼叫端不變）
- headless 測試：退役規則、死亡歸檔、C/D 分類、季結/年底排程、三代循環

## 不在範圍
- 退役 UI、教官在培育中的實際作用、5 歲開獎與 36 回合培育（另一張卡；測試內只用「滿 5 歲揭曉」的最小替身）、虎符卡結算

## 實作決策（規格缺口，已採預設）
- 依《武將壽命系統》§M-1：退役只產生教官傳承資料（`MentorCard`），**不**產生英靈卡；最終死亡才產生 `SpiritCard`，退役過的人死亡時照常補發
- 退役後武將仍留在名冊（`isMentorCard=true`，已被結緣規則擋下），會繼續老化、仍可能死亡；死亡後教官資料保留（教官鏡像快照不受外界變化影響）
- 不使用各服務的 `getInstance()` 單例：單例只認第一個 adapter，換存檔後端或多個測試會串資料
- 退役不自動發生，由玩家呼叫 `retireGeneral()`；季結只廣播 `GeneralReachedRetirementAge`
- `hasLivingDescendants` 以名冊內 `fatherId/motherId` 判斷；歸檔後死者離開名冊，後代的祖譜仍由 `BloodlineGraph` 保存

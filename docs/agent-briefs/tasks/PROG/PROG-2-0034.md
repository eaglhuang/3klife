# [PROG-2-0034] 開獎與培育最小可玩畫面

## 開單原因
開獎（GeneralUnveiled、unveiling.choose）與 36 回合培育（services().nurture）只有純邏輯，玩家看不到也按不到。

## 做法
- 純 TS 流程控制器 `NurtureFlowController`（不依賴 cc）：整理畫面要顯示的資料並轉接按鈕動作，headless 可測。
- UCUF JSON 兩個畫面（執行期組裝，不開編輯器）：`unveiling-fate-screen`（開獎結果＋順應 / 抗命）、`nurture-session-screen`（培育回合、訓練格、教官站位、畢業結算）。
- `NurtureFlowHost` 掛進 LobbyScene，由季度 HUD 的「培育」按鈕進入。

## 完成內容
- `ui/core/NurtureFlowController.ts`（不依賴 cc）：挑出待處理子嗣（待選宿命 → 培育中 → 可開場）、整理 FlowView、轉接順應 / 抗命 / 入學 / 訓練 / 休息 / 畢業 / 放棄，每個動作後存檔。
- `ui/core/NurtureFlowViewApplier.ts`：把 FlowView 套到 UCUF 節點（文字、顯示、按鈕可按與否）。
- UCUF JSON：`nurture-flow-screen` / `nurture-flow-main` / `nurture-flow-default`（沿用既有 `nurture-session-*` 之外另立新名，不覆蓋）。
- `LobbyScene`：季度 HUD 新增「開獎・培育」按鈕；收到 `GeneralUnveiled` 時 toast 提醒；`ServiceLoader.legacy` 供取退役教官卡。
- `tests/NurtureFlow.test.ts`：開獎畫面、順應 / 抗命、非培育季擋入學、36 回合到畢業完整流程、view key 與版面 id 對照。

## 未做
- 手動挑選教官與換教官（目前自動帶前 6 位）。
- 正式美術（目前為色塊 + 文字）。

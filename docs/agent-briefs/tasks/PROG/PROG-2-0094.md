## 開單原因
進入戰場不代表勝敗結算已驗收；新增能在實際 Web 包正常操作、自然落敗並重讀存檔的冒煙流程。

## 完整描述
- 新增 run-web-smoke --flow battle-settlement；只改工具與本卡，不改戰場規則、UI、資料、存檔格式或 meta。
- 點擊座標經 UI 相機 worldToScreen 投影，先驗證在視窗內才操作。戰場 Canvas 世界原點與大廳不同，不能直接把世界座標當畫面像素。
- 玩家正常招募與選主將後出戰，以正常結束回合與拒絕單挑走自然落敗路徑。不得改 HP、推定勝負、呼叫 recordBattle 或植入名冊。

## 如何驗證
1. 啟動本機同步後端，使用已有的 debug Web 包：node tools_node/run-web-smoke.js --flow battle-settlement --viewport 1920x1080 --out artifacts/PROG-2-0094-battle-settlement。
2. 報告 completed=true、errorCount=0；玩家名冊武將真正進場，敗場增加 1、精力減 30，其餘勝／平場不變。
3. IndexedDB 存檔的完整該武將資料與名冊相同，結果等待不重複結算，重新登入仍讀回完全相同資料。
4. node --check 新 helper、既有 web-lifecycle-flow 測試與 compute-gate standard。

## 建議作法
- 唯讀斷言檢查名冊、結果與存檔；狀態改變只透過滑鼠或公開登入入口。
- 回合上限 50；每回合等待有上限，卡住或未自然落敗明確失敗，不跳過必要步驟。

## 開單原因
0095 實際勝利驗收時發現：指令區 DuelBtn 發出 GeneralDuelChallenge {faction: Player}，但戰場只接舊 DeployPanel 的 generalDuel 節點事件；全域棋盤放手又只處理技能選取，正常點擊無法出陣。

## 完整描述
- BattleUIBridge 接指令區的玩家出陣事件，忽略使用 challengerFaction/defenderFaction 的既有單挑結果，避免遞迴或把敵方結算當成新出陣。
- BattleScene 注入棋盤放置回呼；Bridge 在等待武將放置時轉接 touch-end/mouse-up，沿用 TurnFlowManager.doDeployRaycast 的格子驗證與放置邏輯。
- 技能選取優先；回合推進／單挑彈窗中不轉接。取消訂閱清除回呼；放置狀態清除後的相容滑鼠事件不重複放置。
- 只改這兩個入口檔與本卡，不改 Controller、計算、資源、地形、資料、spec 或 meta。

## 如何驗證
1. 新 debug Web 包正常招募→選主將→進戰場→實際 DuelBtn→點我方前排。旗標由 false 變 true，產生一位 player-general 部隊。
2. 重複點棋盤、再點出陣，部隊 ID 與數量不變，errors=[]；改前相同操作不進放置也不產武將。
3. 直接載入本檔 transpiled class 的隔離橋接診斷：玩家請求、單挑結果忽略、重訂閱、防重複放手、技能優先、推進／彈窗 guard、取消訂閱。
4. 既有 headless 與 compute-gate standard 通過；實機可作為 0095 原驗收的前提，不替代自然勝利。

## 建議作法
- 出陣與格子驗證維持原流程；不在 Bridge 複製部署規則，與 Unity UI 輸入轉接至原 GameController 的作法相同。

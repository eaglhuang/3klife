# [PROG-2-0135] 實機驗收：AI 委任 Toggle 勾選與事件（PROG-2-0494、#473）

## 為什麼做
引擎先前不為 type 建立 Toggle 元件，任務詳情對話框的 AI 委任開關取不到 `cc.Toggle`，會在 `:306` 丟錯。#473 讓 toggle 節點掛上 `cc.Toggle`，開關改回 toggle 型別，對話框可監聽 `toggle` 事件。引擎端接線已有測試守護，但開關的視覺與勾選行為需實機確認。

## 步驟
1. `git fetch origin`，用最新 master 建置 Web 版，記下 HEAD。
2. 開啟任務詳情對話框：AI 委任開關顯示，預設未勾選；無錯誤訊息。截圖。
3. 點開關：勾選狀態更新（視覺由未勾變勾），再點一次恢復。各截一張。
4. 點擊時 `_onAiDelegateToggleChanged` 應被呼叫：觀察到的行為（例如勾選後委任狀態改變）記錄於 PR 說明。
5. 關閉對話框再開啟：勾選狀態與委任狀態一致。截圖。
6. 開關大小與文字不遮擋對話框其他按鈕；截圖。

## 驗收標準
- 步驟 2 到 6 皆有截圖或錄影；PR 說明寫明 Before/After 與 HEAD。
- 任一步不符：記錄截圖、節點座標與 HEAD，回報 PM 另開卡。
- composite 節點（character-ds3 bloodline、overview）的 rendererHint 不在本卡範圍（PM 待提供來源）。

## 不要做
- 不使用緊急授權、Quick Fix 或 backend import。
- 不改 `toggle` 型別或引擎程式；只回報現象。

# [PROG-2-0150] 實機驗收：退役畫面因子媒介選擇（PROG-2-0866、#590）

## 為什麼做
#590 在退役畫面的工具列加上「媒介：無／子嗣名」按鈕。點按會循環選擇 0~5 歲、未開獎的子嗣當因子媒介，退役時一併注入；換退役目標時媒介會清空。程式與測試已過，但按鈕的寬度、座標與循環行為需實機確認。

## 步驟
1. `git fetch origin`，用最新 master 建置 Web 版，記下 HEAD。
2. 進入名冊，選一位武將開啟退役流程，確認工具列出現「媒介：無」按鈕，文字完整、未遮擋其他控制。截圖。
3. 有候選子嗣時，連續點按媒介按鈕：應依序循環選擇候選子嗣，最後回到「無」。截圖每一步的按鈕文字。
4. 候選子嗣只限 0~5 歲、未開獎者；超出範圍的子嗣不應出現在循環中。記錄候選名單與子嗣年齡。
5. 選定媒介後，換另一位退役目標：媒介應清空回到「無」。截圖。
6. 選定媒介後完成退役：遊戲結果應反映所選媒介（以遊戲內可查的紀錄核對）。記錄結果。
7. 版位：目標文字區縮窄後仍可讀，按鈕不超出畫面；窄版視窗（手機寬度）同樣檢查。截圖。

## 驗收標準
- 步驟 2 到 7 皆有截圖；PR 說明寫明 Before/After 與 HEAD。
- 若無符合條件的候選子嗣，步驟 3 到 6 記為「無法驗收」並說明原因，不得視為通過。
- 按鈕寬度與座標為 PM 暫定，若需調整，記錄數值，不要自行改版面。

## 不要做
- 不使用緊急授權、Quick Fix 或 backend import。
- 不改媒介取得來源（商業設計待使用者裁決，不在本卡範圍）。
- 不改程式碼或版面 JSON；只回報現象。

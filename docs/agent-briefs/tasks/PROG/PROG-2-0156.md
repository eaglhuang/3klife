# [PROG-2-0156] 實機驗收：大廳任務派遣（任務牆→派遣→結算）（PROG-2-0836、#635）

## 為什麼做
#635 讓任務牆點「接取」即派遣：通過派遣條件後指派武將，依成敗結算官職經驗，並以 toast 顯示任務成功或失敗。晉升提示沿用既有流程。武將戰力暫用 `estimateSortiePower`，派遣即結算與沙盤遠征牆不給經驗皆為 PM 暫定。程式與 headless 測試已過，但派遣流程的畫面行為與 toast 需實機確認。

## 步驟
1. `git fetch origin`，用最新 master 建置 Web 版，記下 HEAD。
2. 進入大廳任務牆，選一個任務點「接取」：不符派遣條件時，應有明確提示，不會誤派。截圖。
3. 選一位符合條件的武將接取任務：應完成指派，並顯示任務成功或失敗的 toast。記錄 toast 文字與結果。截圖。
4. 依結果核對官職經驗：成功或失敗的經驗變化應與遊戲內官職顯示一致（官職區塊見 PROG-2-0155）。記錄前後數值。
5. 若結算後觸發晉升，提示應沿用既有流程顯示一次。無法觸發時記為「無法驗收」並說明原因。
6. 版位：toast 與任務牆不重疊；窄版視窗（手機寬度）同樣檢查。截圖。

## 驗收標準
- 步驟 2 到 6 皆有截圖；PR 說明寫明 Before/After 與 HEAD。
- 步驟 4 若無法核對經驗變化，記為「無法驗收」，不得視為通過。
- 戰力估算、派遣即結算與沙盤遠征經驗規則為 PM 暫定，只記錄觀察，不判定對錯。

## 不要做
- 不使用緊急授權、Quick Fix 或 backend import。
- 不改派遣規則或程式碼；只回報現象。

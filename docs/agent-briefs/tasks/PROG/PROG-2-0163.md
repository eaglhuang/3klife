# [PROG-2-0163] 實機驗收：存檔從備份還原時大廳 toast（PROG-2-1000）

## 為什麼做
主存檔損毀、改從上一份備份還原時，大廳要以 toast 告知玩家「存檔損毀，已從上一份備份還原」。文案已接四語系，程式與 headless 測試已過，但 toast 出現的時機、可讀性與版位需實機確認。

## 步驟
1. `git fetch origin`，用最新 master 建置 Web 版，記下 HEAD。
2. 依測試方式模擬主存檔損毀（例如改寫主存檔為無效內容），啟動遊戲，讓它從備份還原。
3. 確認大廳出現 toast，文字為「存檔損毀，已從上一份備份還原」（或該語系對應譯文）。截圖。
4. 量測 toast 的停留時間、位置，確認未被其他元件遮住。
5. 切換語系（zh-CN、en、ja）各看一次 toast 文字，確認未溢出或被裁切。截圖。
6. 正常存檔（未損毀）啟動時，確認不出現此 toast。截圖。

## 驗收標準
- 步驟 3 到 6 皆有截圖；PR 說明寫明 Before/After 與 HEAD。
- 若無法模擬損毀，記為「無法驗收」並說明原因，不得視為通過。
- 文案與停留時間為 PM 暫定，只回報量測數值，不要改。

## 不要做
- 不使用緊急授權、Quick Fix 或 backend import。
- 不改程式碼與文案；只回報截圖與 HEAD。

# [PROG-2-0173] 實機驗收：Hazard 格換皮掛點（PROG-2-1307、#1099）

## 為什麼做
火海與毒沼改為同一套 Hazard 格，格子的換皮（Decal／VFX）掛點已接上，兩者共用同一傷害邏輯。程式與 headless 測試已過，但貼圖與特效的位置、層級與可讀性需實機確認。

## 步驟
1. `git fetch origin`，用最新 master 建置 Web 版，記下 HEAD。
2. 進入戰鬥，找到一個火海格與一個毒沼格。各截一張，確認格子換皮（Decal）顯示正確、位置貼齊格子。
3. 確認火海與毒沼的 VFX 特效位於格子之上、不遮住單位，且不超出格子範圍。截圖。
4. 讓單位站上火海格與毒沼格各一次，觀察傷害數字與回合結算是否一致（同一傷害邏輯）。記錄兩次的數值。
5. 窄版視窗（手機寬度）重做步驟 2。截圖。

## 驗收標準
- 步驟 2 到 5 皆有截圖與數值紀錄；PR 說明寫明 Before/After 與 HEAD。
- 兩種格子的傷害數值不一致，記為不通過並附數值。
- 戰場沒有火海格或毒沼格可測，記為「無法驗收」並說明原因。
- 貼圖位置與特效大小只回報，不要自行改版位；微調由 Codex 依實機結果決定。

## 不要做
- 不使用緊急授權、Quick Fix 或 backend import。
- 不改程式碼與傷害規則；只回報截圖、數值與 HEAD。

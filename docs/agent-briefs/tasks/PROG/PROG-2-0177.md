# [PROG-2-0177] 實機驗收：命頁 14 人樹節點命名統一（PROG-2-1273、#1127）

## 為什麼做
命頁左欄原本有兩套 14 人樹命名（`G1_i`／`G2_i`／`G3_i`），與底座 `BloodlineTreeBinding` 的 `NodeCard_G{row}_{i}` 不一致。#1127 把命頁節點統一成同一份命名契約，兩邊共用。這次是無行為變更的重構，實機要確認樹的外觀與卡片內容沒有因改名而消失或錯位。

## 步驟
1. `git fetch origin`，用最新 master 建置 Web 版，記下 HEAD。
2. 進入命頁的血統分頁，截圖整棵 14 人樹。
3. 確認 14 個先祖卡都有顯示、名字與頭像正確，沒有空白或重複卡。截圖。
4. 點擊任一先祖卡，確認詳情可開啟且資料對應該卡。截圖。
5. 窄版視窗（手機寬度）重做步驟 2。截圖。

## 驗收標準
- 步驟 2 到 5 皆有截圖；PR 說明寫明 Before/After 與 HEAD。
- 14 張卡全數顯示；缺卡或錯位記為不通過，只回報截圖與座標。
- 若畫面無法進入血統分頁，記為「無法驗收」並說明原因，不得視為通過。

## 不要做
- 不使用緊急授權、Quick Fix 或 backend import。
- 不改程式碼；只回報截圖、座標與 HEAD。

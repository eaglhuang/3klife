## 完整描述
關卡設計系統 §C-1 規定：挑戰關卡可由多個子關卡串接成連環破主鏈，玩家需按正式順序完成前置關卡，才能解鎖後續 Boss 關卡。本卡實作順序解鎖的判定：某關卡是否解鎖，只看同一主鏈中前一關是否已通關。

Unity 對照：像一條依序解鎖的 Level Gate，判定只讀「已通關集合」，不改場景或存檔。

## 設計選擇（我的判斷）
- 不屬於任何主鏈的獨立關卡一律解鎖。
- 主鏈中第一關（最小 order）一律解鎖。
- 其他關卡要求同鏈中 order 前一關已通關；若通關順序亂序（例如跳過前一關直接通關後面的），不解鎖後面的關卡。
- 通關紀錄用不可變的 Set 語意：標記通關回傳新集合，不改原集合。

## 尚未完成 / 暫定
- 「已通關集合」的持久化（存檔欄位）未做，留待後續卡。
- 關卡資料還沒有 chainId／order 欄位，現有 encounters.json 只有兩筆，全部視為獨立關卡。

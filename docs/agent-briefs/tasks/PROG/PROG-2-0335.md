# [PROG-2-0335] 轉蛋規格機率與保底接線（GCH-02）

## 開單原因
WBS v4 6b 節 P1 待接線項。LocalGachaService 仍用估算權重抽卡，沒有規格的稀有度機率、Up 與保底。PM 裁定 (a)：直接換成規格機率與保底。

## 完整描述
- GachaDraw 純邏輯：稀有度 SSR 3% / SR 10% / R 87%；SSR 70%、SR 80% 從 Up 抽；第 50 抽的倍數若擲到 R 則提升為 SR；大保底只記累計抽數。
- LocalGachaService 抽卡改用 GachaDraw；保底計數依 poolId 分開保存，舊資料缺值從 0 開始。
- 固定 seed 統計測試：SSR/SR 比例、Up 占比、小保底、保底計數累加、池空時的降階。

## 如何驗證
1. tests/GachaDraw.test.ts（8 條）。
2. run-cli ALL PASS；compute-gate standard。

## 預設選擇與偏離（需 PM 知悉）
- 保底計數存 localStorage（ucuf.gacha.pity.v1），與錢包相同層級，未併入 PlayerSave。原因：抽卡目前不經 GameSession，要併入存檔需要改 GachaFlowCoordinator 與 session 的接線，範圍較大；待裁定。
- Up 名單由呼叫端傳入，沒有 Up 來源時全部走常設。
- 大保底只記計數，不發天命商店。

# [PROG-2-0426] 戰法施放接入精力閘門（LIFE-10 接線）

## 開單原因
PM 指示（2026-10-14）：LIFE-10 純邏輯（PROG-2-0425）的下一步是把 `VitalityBattleGate` 接進戰法施放流程，放在 `BattleSkillDispatcher` 這層，與戰場的 tcond 檢查並排。撤退機制另卡。

## 完整描述
- `core/models/GeneralUnit.ts`：新增 `vitality` 與 `maxVitality`。缺值時預設滿值 100，和 `BondingSetupController` 的預設一致。
- `battle/runtime/BattleSkillDispatcher.ts`：`executeBattleSkillRequest` 在天氣與 tcond 之後呼叫 `checkVitalityGate`。
  - 只擋兩種來源：`Ultimate`（奧義）對應 `ultimate-tactic`，`SeedTactic`（種子戰法）對應 `active-tactic`。
  - 其他來源（虎符、師承、血統、計謀等）不在此閘門內。
  - 施放者找不到所屬武將時放行，不猜測。
  - 擋下時回傳 `blockedReason: 'vitality-restricted'`，不扣資源、不進入執行器。
- 擋下的文字：中段奧義為「精力低迷，無法發動終極戰法」；耗盡段戰法為「精力耗盡，無法發動戰法」。

## 解讀選擇（PM 已確認的部分）
- 中段只禁終極、耗盡段禁全部戰法，依 PM 裁定。
- 撤退風險 0.1 仍是暫定值，本卡沒有接到任何撤退判定。

## 如何驗證
1. tests/BattleVitalityGate.test.ts 5 條：耗盡段種子戰法被擋、中段奧義被擋、耗盡段奧義被擋、缺精力資料預設滿值、虎符來源不受閘門影響。
2. run-cli ALL PASS。

## 未做（後續卡）
- 撤退機制本身（目前專案沒有撤退判定）。
- 戰場 UI 的精力狀態顯示與按鈕灰階，需要 cc 接線與 Codex 實機驗收。
- 精力扣除（奧義 vitalityCostPct、戰鬥 -30 等）尚未接線，本卡只讀取精力，不改變數值。

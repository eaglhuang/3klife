# [PROG-2-0429] 奧義扣精力與戰後結算基準（LIFE-10）

## 開單原因
PM 裁定（2026-10-14 18:47Z）：
1. `ultimateId` 一路傳到派發器，cc 層照寫，交 Codex 驗收。
2. 結算以戰鬥結束時精力為基準再扣 30，兩者疊加，下限 0。

## 完整描述
- **成本來源**：`ultimate-definitions.json` 的 `vitalityCostPct`（小數，例如 0.05）。同一戰法的三個奧義共用 battleSkillId，成本不同（5%/6%/7%），所以必須用 ultimateId 區分，不能用 battleSkillId 反查。
- **傳遞路徑**：
  - `UltimateSelectPopup`、`UltimateSelectPopupComposite` 的選項與 emit 帶上 `ultimateId`。
  - `BattleSceneLoader.buildUltimateSkills` 把 `slot.ultimateId` 填進選項；新增匯出 `findUltimateVitalityCostPct`。
  - `BattleUIBridge._onUltimateSkillSelected` → `BattleSkillTargetingFlow.beginPlayerSkillFlow(…, ultimateId)`。
  - targeting flow 的「再次點選取消」判斷連 ultimateId 一起比，避免同戰法的不同奧義被誤判。
  - `BattleController` 的派發器上下文加上 `getUltimateVitalityCostPct`。
  - `GeneralSkillCastOptions` 與派發器 request 帶上 `ultimateId`。
- **扣減**：派發器在奧義 `applied` 後扣減。成本 = 精力上限 × 比例，四捨五入，下限 0；比例或上限無效時不扣。
- **結算**：`settleBattle` 新增 `vitalityAfterBattle`；`GameSession.recordBattle` 與 `BattleUIBridge` 戰後傳入主將的戰鬥結束精力，結算以此為基準再扣 `BATTLE_VITALITY_COST`（30）。沒有提供時沿用名冊值，舊行為不變。
- **純函式**：`spendUltimateVitality` 放在 `VitalityBattleGate.ts`，單元測試覆蓋。

## 解讀選擇
- 結算只對主將（`playerGeneral`）帶入戰鬥結束精力；其他出戰武將沒有戰場單位，沿用名冊值。
- 扣減與結算疊加，符合 PM 裁定。

# [PROG-2-0437] 撤退的擲骰結算與戰場接線（PM 暫定規則）

## 開單原因
協調者（2026-10-14 19:20Z 與 19:24Z）指示：依 PM 撤退規則接戰場與撤退按鈕。

## 完整描述
- PM 暫定規則：
  - 撤退時擲骰；roll 小於風險即失敗，否則成功。
  - 成功：部隊脫離戰場，保留現有 HP，不算陣亡，不給戰功。
  - 失敗：不設被俘機制；部隊受最大 HP 20% 傷害，留在場上，當回合不能再行動。
  - 基礎風險 0.2；精力耗盡段經 `retreatRiskOf` 加 0.1。
- 新增 `BattleRetreat.ts`（純邏輯）：`resolveRetreat(maxHp, currentHp, risk, roll)`，不擲骰，roll 由呼叫端傳入。
- `BattleTurnManager`：新增 `actionBlockedUnitIdsThisTurn`，`markUnitActionBlocked` 同時視為已移動，因此既有移動閘門會擋住；下一回合清空。
- `BattleController.attemptRetreat(unitId, band='high', roll=Math.random())`：成功時 `state.removeUnit`；失敗時扣血並鎖回合。

## 解讀選擇
- 撤退對象是 `TroopUnit`（部隊）。部隊沒有精力欄位，風險的精力段由指揮武將決定，本卡預設 `high`，呼叫端需傳入指揮武將的精力段。
- 「不能再行動」先接到移動閘門（經 movedUnitIds）。技能閘門尚未讀取本回合封鎖集合，留待後續。

1. tests/BattleRetreat.test.ts 7 條全綠：擲骰邊界、成功保留 HP、失敗扣 20%、扣到 0 為止、無效輸入保護、回合閘門與跨回合清空。

# [PROG-2-0439] 撤退 QA 修正：0 血照陣亡處理、擲骰改用存檔亂數

## 開單原因
QA 在 #369（已合併）留了兩點，協調者（2026-10-14 19:41Z）指示從 master 開修正 PR：
1. 撤退失敗後會留下 0 血的單位（未走陣亡）。
2. 預設擲骰用了 `Math.random`，應改用戰場或存檔的亂數源。

## 完整描述
- 撤退結果判斷抽成純函式 `retreatNextStep`：脫離（escape）、陣亡（dead，失敗且血量歸 0）、鎖回合（blocked）。
- `BattleController.attemptRetreat`：
  - escape：`state.removeUnit` 並 `buff.clearUnit`。
  - dead：`combatResolver.onUnitKilled(unit, null, svc)`，走既有陣亡路徑，發 `UnitDied`；killer 為 null，不加 SP。
  - blocked：寫回 HP 並 `markUnitActionBlocked`。
- 預設亂數改為 `services().session.randomSource()`（存檔亂數，與戰場 `random` 來源一致）。

## 解讀選擇
- 「照陣亡處理」採既有路徑（同一個 `onUnitKilled`），沒有另外發明死亡事件。
- 撤退成功也清除 buff，與陣亡路徑對齊，避免殘留。

## 如何驗證
1. tests/BattleRetreat.test.ts 8 條全綠（含新增的 `retreatNextStep` 三情境）。
2. run-cli ALL PASS（2100 passed, 3 skipped）。

# [PROG-2-0441] 撤退失敗部隊的戰法／奧義閘門（補 PROG-2-0437 缺口）

## 開單原因
撤退失敗的部隊在當回合不能行動（PM 暫定）。普攻已由 `hasUnitMovedThisTurn` 擋下（markUnitActionBlocked 同時加入 moved 集合），但部隊發動的戰法與奧義沒有讀 `actionBlockedUnitIdsThisTurn`，等於鎖回合只擋住了一半。

## 完整描述
- `BattleSkillDispatcherContext` 新增可選的 `isUnitActionBlocked?(unitId)`。
- `executeBattleSkillRequest` 在精力閘門前檢查施放者（`ownerUid`）是否為本回合撤退失敗；是則回傳 `blockedReason: 'action-blocked'`，不扣資源、不進執行器。
- `BattleController` 建立 dispatcher 時注入 `turnManager.isUnitActionBlockedThisTurn`。
- 測試：撤退失敗單位的戰法請求被擋；未鎖定單位放行條件不變（既有精力閘門測試仍綠）。

## 解讀選擇
- 只擋被鎖定的施放者，武將本身不會因此被擋（武將不走撤退）。
- 檢查放在精力閘門之前，避免鎖定中的單位扣到精力。

## 未覆蓋
- 放行路徑仍需完整戰鬥環境，沿用 BattleVitalityGate 的阻擋路徑測試寫法。

# [PROG-2-0492] 啟用 UI 版面資料契約測試，並補 BattleRoster 型別

## 開單原因
PROG-2-0491 將 UISpecParser 改寫為 run-cli suite 但未啟用，因啟用後有 38 項失敗。PM 裁定（2026-10-15 05:03）：掃描規則排除報表檔、修正資料違規後啟用；BattleRoster 2 筆補型別。

## 範圍
1. **掃描規則**：只掃版面檔（`<id>.json`、`<id>.layout.json`）；其餘帶額外 `.` 後綴者為中介 / 報表檔（24 個），略過。實測規則不會誤傷任何有 root 的版面（67 個全部保留）。
2. **舊 nodes 格式**：5 個工具用檔（gacha-main、gacha-destiny-shop、support-card-main、support-card-detail-main、support-card-team-edit-main）使用 `nodes` 而非 `root`，執行期 UISpecLoader 不讀，只被 tools_node 腳本引用，明確列為 LEGACY_NODES_FORMAT 略過，並有同步檢查。
3. **白名單**：與 UIPreviewBuilder 的 switch 分支一一對應（container、panel、label、button、scroll-list、scroll-view、image、resource-counter、spacer、composite-image）。
4. **$ref**：解析到 fragments/ 的碎片檔再驗證。
5. **註解物件**：只含 `_` 開頭鍵的物件視為註解（battle-hud-main 的 `_comment`），不是節點。
6. **已知例外**：sprite（4）、Toggle（1）、popup（1）、shadow（parchment-panel 碎片）。引擎沒有對應分支，節點會建立但不掛視覺元件。列出並附建議，待 PM 裁定。同步檢查確保修正後會提醒移除。
7. **BattleRoster**：`BattleRosterGeneral` 補可選欄位 `isMercenary`、`templateFlag`。執行期 `isTrialMercenary` 已讀取這兩欄，本卡只對齊型別，行為不變。

## 與 PM 裁定的差異
- PM 指示把 popup、scroll-view、sprite 補進白名單。scroll-view 已在引擎分支中，故納入白名單。sprite、popup 引擎無分支，若加入白名單會把不渲染的 type 合法化，因此改列為已知例外，待裁定。
- battle-hud-main 缺 type 的節點實為 `_comment` 註解，沒有對應 skin 用途，故不補 type，改為註解略過。

## 如何驗證
1. run-cli：UISpecParser 全數通過，ALL PASS。
2. tsc：BattleRoster 與 UISpecParser 錯誤消失。
3. 閘門 `node tools_node/compute-gate.js --profile standard --agent-feedback`。

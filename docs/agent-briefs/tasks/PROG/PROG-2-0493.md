# [PROG-2-0493] 版面 type 修正為引擎支援類型

## 開單原因
PROG-2-0492 啟用 UI 版面資料契約後，列出引擎無分支的 type（sprite、Toggle、popup、shadow）。PM 裁定：改資料為引擎支援的 type。FirstBattleCleared 測試的 `player-lose` 非法字面值一併修正。

## 範圍
| 型別 | 改為 | 數量 | 檔案 |
|---|---|---|---|
| sprite | image | 6 | fragments/layouts/gd-tab-basics.json（2）、gd-tab-stats.json（3）、layouts/lobby-main-main.json（2）、network-status-main.json（1）、shop-main-main.json（1） |
| popup | panel | 1 | layouts/duel-challenge-main.json |
| shadow | panel | 2 | fragments/layouts/item-cell.json、parchment-panel.json |
| Toggle | button | 1 | layouts/lobby-mission-detail-dialog-main.json（AiDelegateToggle） |

只改 `type` 值，不改 name、skinSlot、widget 等其他欄位。
另：tests/FirstBattleCleared.test.ts 的 `player-lose` 改 `enemy-win`（與 StageProgressSave 同理）。

## ⚠ 需 Codex 實機驗收
1. **Toggle → button（AiDelegateToggle）**：`LobbyMissionDetailDialogComposite.ts:206` 以 `getComponent(Toggle)` 取得元件，並監聽 `toggle` 事件、設定 `isChecked`。引擎的 UIPreviewBuilder 從不為任何 type 建立 Toggle 元件，所以改動前此處即為 null，`:306` 會丟出「missing aiDelegateToggle」。改為 button 不改變這個結果，但 AI 委任的勾選狀態與事件路徑目前沒有實際運作。實機需確認對話框是否能開啟，以及 AI 委任開關是否可用。根本修法是引擎補 toggle 支援或調整元件，需 PM 另行裁定。
2. **sprite → image**：改為 image 後會依 skinSlot 渲染；實機確認背景與頭像有顯示。

## 不在範圍
- `composite`（character-ds3-bloodline-content、overview-content、stats-content 各 1 個 SVG 節點）：不在本卡裁定範圍。stats 有 rendererHint 走 SVG 路徑；bloodline、overview 無 hint，行為未明，待 PM 裁定。
- 舊 nodes 格式 5 個工具用檔：依 PM 裁定維持排除，記入待辦檔。

# [PROG-2-0494] 引擎支援 toggle 節點，AiDelegateToggle 改回 toggle

## 開單原因
PROG-2-0493 將 AiDelegateToggle 由 Toggle 改為 button 作為暫時處理。但 LobbyMissionDetailDialogComposite 依賴 Toggle 元件（`getComponent(Toggle)`、`toggle` 事件、`isChecked`），button 無法提供，等於 AI 委任功能失效。PM 裁定：引擎補 toggle 支援，版面改回 toggle。

## 範圍
1. **UISpecTypes**：`UINodeType` 加入 `'toggle'`。
2. **UIPreviewBuilder**：switch 新增 `case 'toggle'`，呼叫 `nodeFactory.buildToggle`。
3. **UIPreviewNodeFactory**：
   - `buildButton` 的外觀與文字流程抽成 `_buildButtonVisuals(node, spec, button)`。
   - 新增 `buildToggle`：掛 `cc.Toggle`（預設 `isChecked = false`），再共用同一外觀流程。Cocos Toggle 繼承 Button，外觀邏輯不重複。
4. **版面**：lobby-mission-detail-dialog-main 的 AiDelegateToggle 由 button 改回 toggle。
5. **tests/cc.mock.ts**：補 `Toggle extends Button { isChecked }`。
6. **tests/ToggleNodeWiring.test.ts**：守護四處一致：版面型別、UIPreviewBuilder 分支、buildToggle 掛 Toggle 並共用流程、對話框以 Toggle 元件取得並監聽 toggle 事件。

## ⚠ 需 Codex 實機驗收
- 開啟任務詳情對話框，AI 委任開關可點、勾選狀態會更新，且 `LobbyMissionDetailDialogComposite` 的 `_onAiDelegateToggleChanged` 會被呼叫。
- 驗收前不能確認 AI 委任路徑正常；先前因為引擎沒有 Toggle 元件，`:306` 會丟錯，本卡應已解決。

## 與其他 PR 的關係
- #470（PROG-2-0493）把同一行 AiDelegateToggle 改為 button。本卡改為 toggle。兩者合併時會衝突，應以本卡的 `toggle` 為準。

## 未處理

# [PROG-2-0495] 基礎清單 REV-01 / REV-02 / REV-03

## 開單原因
WBS v8 M0 底座清單：REV-01（Constants.ts DP 命名殘留）、REV-02（terrain.json 抽取）、REV-03（VIT_Max → Vitality_Max 統一）。依正式規格矛盾審查 §2.4、§2.5、§2.6。

## REV-01：DP 命名殘留
- 盤點：程式碼已無 `INITIAL_DP`、`DP_PER_TURN`、`MAX_DP` 的使用者；常數名為 `INITIAL_FOOD`、`FOOD_PER_TURN`、`MAX_FOOD`。殘留只在 Constants.ts 的註解「原 INITIAL_DP」等。
- **與審查建議不同**：§2.4 建議改為 `GRAIN`，但名詞定義文件把「糧草」的英文名定為 **Food**。依名詞定義，保留 FOOD 名稱，本卡只清註解。
- 變更：Constants.ts 三處註解改為「名詞：糧草 = Food」。

## REV-02：terrain.json 抽取
- 新增 `assets/resources/data/terrain.json`（含 `.meta`），攻擊與防禦修正值各六種地形。
- 新增 `core/config/TerrainConfig.ts`（純 TS，`parseTerrainConfig`），驗證六種地形鍵齊全且為有限數字。
- runtime 仍以 Constants.ts 的 `TERRAIN_ATTACK_MOD` / `TERRAIN_DEFENSE_MOD` 為準（專案目前沒有 JSON 載入器，TS 也未開 resolveJsonModule）。`tests/TerrainConfig.test.ts` 交叉比對兩邊，與 NUM-04 相同做法。
- 後續：接上 runtime 載入器後，Constants.ts 的表可改由 terrain.json 產生，屆時測試可移除。

## REV-03：VIT_Max 統一（2026-10-20 已完成）
- 盤點：程式碼只用 `Vitality_Max`（名詞定義文件：精力上限 = Vitality_Max）。原殘留於結緣系統（配種）文件第 216 行。
- 原阻塞：該文件未分片，doc-shard-health 擋下修改。PROG-2-0496 已分片並改名，阻塞解除。
- PM 裁定（2026-10-20）：規格優先，殘留已照規格清除，無須另列待裁決。
- 注意：審查 §2.6 指稱的「教官系統（支援卡）.md」中找不到 `VIT_Max` 或精力欄位，該處已無此問題，僅改結緣系統文件。

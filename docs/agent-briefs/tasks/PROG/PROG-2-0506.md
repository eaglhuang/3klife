## 完整描述
PM 指示（2026-10-14）：接轉蛋池抽到支援卡的路徑。規格的教官來源 Gacha = 支援卡池。
抽到目錄裡的支援卡武將時，產生一張 source=Gacha 的教官卡，放進教官持有清單；之後培育中靈感即可觸發。
驗收條件：轉蛋抽到目錄內武將 → 教官持有清單出現 Gacha 來源的卡；同一武將不重複；已有的卡（含退役來源）不被覆蓋。

## 設計選擇（我的判斷）
- 純邏輯：`mentorCardFromGachaDraw`、`addGachaMentorCards`（沿用 MentorSources.addMentorToHoldings，同 uid 保留舊卡與舊來源）。
- 轉蛋沒有退役資料：年齡欄位填 0，季與年填抽卡當下的時間（暫定）；parentUids 留空字串（轉蛋沒有父母）。
- LegacyService 新增 addGachaMentors，寫入同一個 mentor_cards 存檔鍵。
- 掛勾點：LobbyScene 的 _onGachaPullSuccess（已有 addGenerals 的成功回呼），目錄以既有 _loadSupportCatalog 讀取。
- 注意：趙雲同時是一般武將與支援卡，轉蛋抽到趙雲會同時產生教官卡。這是按「支援卡池 = 目錄武將」的簡化，規格若要求獨立支援卡池，之後再拆。

## 驗收
- `tests/GachaMentorSource.test.ts`：產生卡的來源與支援資料、非目錄武將不產生、重複不新增、既有退役卡不被覆蓋、產生的卡可以開場用（mentorFromCard 帶 inspire）。
- run-cli ALL PASS，compute gate 通過。

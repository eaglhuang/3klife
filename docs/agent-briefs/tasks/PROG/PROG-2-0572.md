## 完整描述
PM 裁定：在戰法資料加 `tcond` 欄位。先依戰法描述填有明確兵種或天氣限定的，其餘留空代表無條件。

## 設計選擇（我的判斷）
- 規格書 `戰法系統.md` 只有 TCOND 原語表，沒有逐個戰法的條件文字，因此「明確限定」以 `tactic-library.json` 的 `aptitudeRules` 為依據：`scope: troop` 對應 `troopType`，`scope: weather` 對應 `weather`。
- 兵種代碼對應 `TroopType` 的值：`CAVALRY` → `cavalry`、`INFANTRY` → `infantry`、`ARCHER` → `archer`；天氣 `WINDY` 與 `Weather.Windy` 同值。
- 水路伏擊只有地形限定（`WATER`），不屬於兵種或天氣，留空。
- 火計佈陣的 `PLAIN` 地形同樣不進 tcond。
- 兵種等級門檻（如 `CAVALRY ≥ A`）留在 `aptitudeRules`，tcond 只描述發動時的兵種或天氣。
- JSON 以相同格式寫回（縮排與 Unicode 與原檔一致），`generate-general-tactics.js` 只讀 `aptitudeRules`，不受影響。

## 驗收
- 有明確兵種或天氣限定的 7 個戰法填入 tcond；水路伏擊留空。
- tcond 的值都是合法的 `TroopType` / `Weather` 代碼。
- 用資料實際跑 `evaluateTacticConditions`：騎軍衝鋒只允許騎兵，火計佈陣只允許大風，水路伏擊無條件。
- run-cli 全部通過；compute gate standard 通過。

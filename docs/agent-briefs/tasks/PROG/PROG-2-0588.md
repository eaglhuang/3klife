# [PROG-2-0588] 狀態代號接上施放流程

## 開單原因
PROG-2-0586（#570）已合併，`statusModuleTagOf` 可以從 master 使用。PM 要求把狀態代號也接上施放流程，與 PROG-2-0587 的傷害代號合在同一個回報清單。

## 做法
1. `moduleTagsOfSkill(profile)` 合併傷害代號（TDIR／TLINE／TFAN）與狀態代號（THEAL／TBUFF／TDEBUFF）。
2. `BattleSkillExecutor.execute` 依 profile 填入 `moduleTags`（選填欄位，定義在 `SkillRuntimeContract.ts`）。
3. 測試用固定 stub resolver：無視防禦回報 TDIR，鼓舞回報 TBUFF，緩速回報 TDEBUFF，無 profile 回空清單。
4. 測試名稱校正：lu-bu-rampage 的遊戲內名稱是「天下無雙」。
5. 本卡取代 PROG-2-0587 的 PR #573（兩者改同一檔案，#573 合併後會衝突），#573 會關閉。

## 如何驗證
1. BattleSkillModuleTags 測試通過（含施放執行器回報代號）。
2. run-cli 全綠；compute-gate standard。

## 缺口
- 無 UI 或戰報消費端，`moduleTags` 只提供呼叫端與測試。

- `assets/scripts/battle/skills/BattleSkillExecutor.ts`、`assets/scripts/battle/skills/BattleSkillModuleTags.ts`、`assets/scripts/shared/SkillRuntimeContract.ts`、`tests/BattleSkillModuleTags.test.ts`、本卡。

# [PROG-2-0706] 因子階段判定改為「等級 > 門檻」（LUK-04）

## 來源
- WBS v8 LUK-04：Phase 3（Lv46+）紫色因子可見性解鎖。
- 規格：因子解鎖系統 §三階段表（Phase 2 Lv21~45、Phase 3 Lv46+，表內門檻欄 20 / 45）、運氣系統 UI_LUK_HIDDEN「Lv46 解鎖」。
- PM 裁定 B（2026-10-15）：門檻數值保留，判定改為「等級 > 門檻」，紫紅 46 起、綠白 21 起，紅一起適用。

## 範圍
- `core/systems/FactorVisibility.ts`：新增 `isFactorLevelUnlocked(level, required)`（> 門檻；門檻 ≤ 1 視為 Lv1 起可見）；`getFactorVisibility`、`isGeneFactorVisible` 改用它。
- `core/systems/FactorAwakening.ts`：`discoveryPhase` 改用它（21+ → 2，46+ → 3）。
- `core/systems/FactorMask.ts`：`factorMaskView`、`visibleFactorColors` 改用它；遮罩文字 Lv 顯示為門檻 + 1。
- `core/systems/SageFactorPreview.ts`：提前預覽改用它。
- 測試：FactorAwakening、FactorVisibility、FactorMask、FactorMaskState、FactorMaskWiring、WiringBatch0513、SageFactorPreview、SageOracleDirectionHint 的邊界案同步修改。

## 暫定
- 門檻 ≤ 1 的特例：藍粉門檻為 1，若套 > 規則 Lv1 會隱藏，所以視為 Lv1 起即可見。
- 固定測試資料（gene fixture 的 discoveryLevel: 45 等）未改，它們代表門檻數值本身。

## 不在本卡
- LUK_Max 與紫因子 Lv 上限（LUK-03，待使用者裁決）。
- UIPreviewNodeFactory 的 cc 型別錯誤屬既有問題，與本卡無關。

# [PROG-2-0721] 培育紀錄畢業寫入（NUR-15 接線，MVP 存檔欄位）

## 來源
- WBS v13 NUR-15：培育紀錄 server 表只有定義（002_nurture_records.sql + nur15-row-validators），沒有執行期呼叫端。
- PM 裁定：MVP 期間存在存檔欄位，畢業時寫一筆；取不到的欄位設 null 並列在卡上，不填假值。

## 範圍
- `core/systems/NurtureRecordRow.ts`（新，純邏輯）：`buildNurtureRecordRow(session, graduation, endSeason)` 回傳 snake_case 列與 `unavailable` 清單，不修改輸入。
- `core/services/NurtureService.ts`：`NurtureState.graduationRecords`；`graduate()` 在移除會話後寫入一筆。
- `tests/NurtureRecordWiring.test.ts`（新）：4 案，含以 `server/schema/nur15-row-validators.ts` 驗證列。

## 欄位來源
- 有來源：session_id、child_uid、start_season（會話開始季）、end_season（畢業當季）、mentor_id（第一位教官，沒有則 null）、final_stats_json（會話實力層）、graduation_tags_json（畢業標籤）、rating（畢業評級）、tp_total（會話 totalTp）。
- 無來源，寫 JSON `"null"`（可解析，表示未紀錄）：phase_block_history_json、mentoring_mode_log_json、reveal_log_json。
- 無來源，寫 null：revelation_level；舊存檔缺 totalTp 時的 tp_total。

## 缺口（2026-10-21 已依 PM 裁定暫定填入，見 notes）
- revelation_level：server 列驗證要求 0~3 整數，這筆紀錄會被驗證報錯。要嘛允許 null（server 表欄位是 NOT NULL，需一併改 schema），要嘛定出揭露層級來源。
- 三份歷程 JSON 與 tp_total 舊存檔的來源，目前都沒有。
- server 表未部署，本卡不連外部服務，也沒有讀取或查詢畢業紀錄的 UI。

# [PROG-2-0739] 退役提示與武職退役虎符

## 開單原因
PM 2026-10-20 裁定：規格 §H 優先，武職退役也發虎符；退役回顧要顯示獎勵。

## 做法
1. `GameSession.retireGeneral`：路線為 WARRIOR 時，以 `produceRetireTally` 產一張虎符，寫入 `_tallyCards`，由君主持有；SCHOLAR、DUAL_CLASS 維持發竹簡。
2. `TigerTally.produceRetireTally`：沿用陣亡產卡的品質與兵種算法，uid 前綴 `tally-retire-`，source 為 `retire`。`TigerTallyCard.source` 新增 `retire`。
3. `RetireReviewController`：`retireGrantText` 依路線回傳「獲得虎符 ×1」或「獲得竹簡 ×1」；缺 key 時退回 zh-TW；`buildRetireReviewTexts` 多 `retireGrant`。版面新增 `retireGrant` 節點（top 470）。
4. 語系：`ui.retire_review.grant_scroll`、`ui.retire_review.grant_weapon` 四語補齊（非 zh-TW 為暫定譯文）。
5. `TallyDeathSettlement.settleDeathTallies`：跳過 `isMentorCard`（已退役）武將的死亡產卡，避免退役後再死亡發第二張虎符。
6. 測試：`RetireReviewController.test.ts` 改為新文案；`RetireDeathTallyChain.test.ts` 改為「武職退役產一張退役虎符，死亡只產一張陣亡虎符」。

## 如何驗證
1. headless 全綠（ALL PASS 2849，略過 3）。
2. `tsc -p tsconfig.test.json --noEmit` 與 master 基線比對，無新增錯誤。
3. 計算型閘門 standard。

## 缺口
- 獎勵句與竹簡句為暫定文案，已取消「竹簡：竹簡」的重複格式。
- 退役虎符的品質沿用陣亡算法，規格未另定。
- 版面位置（top 470）為暫定，待 Codex 實機確認。
- 退役者仍留在名冊（只標 isMentorCard），之後死亡由 `settleDeathTallies` 跳過（PROG-2-0739 追加），由 `RetireDeathTallyChain` 測試鎖住；若之後要改成死亡才發虎符，需 PM 另行裁定。

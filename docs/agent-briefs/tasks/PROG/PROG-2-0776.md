# [PROG-2-0776] 七進七出接入移動流程（Ghost_Move 接線）

## 開單原因
PROG-2-0798 只做了穿透路徑的純規則層（`resolveGhostPath`），沒有接進實際移動。協調者 PM 要求接到 `BattleAutoMovePhase` 的移動流程上。

## 完整描述
規格（g.md）：`七進七出`，`Ghost_Move = True`，裝備[龍膽]符，移動穿透敵格、閃避反擊。PM 暫定裁定：路徑上每個敵軍各受一次傷害；不可穿越岩石與友軍；終點必須空。

## 做法
1. `TallyPassive.ts`：`TallyPassiveSpec` 新增 `ghostMove?: boolean`；表項新增 `tiger-tally-long-dan`（龍膽符，暫定 id）；新增 `hasGhostMove(unit)`。
2. `BattleAutoMovePhase.ts`：帶 Ghost_Move 的部隊不走逐格停下的 `while` 迴圈，改走 `stepGhostMoveUnit`：
   - 依剩餘移動力由遠到近找最長一段「路徑有效」的終點（`resolveGhostPath`），終點必須空。
   - 找不到有效終點則原地不動（PM 規則：終點必須空）。
   - 移動後，對路徑上每個被穿透的敵軍各扣一次傷害（經 `applyGhostPassDamage` 回呼）。
3. `BattleController.ts`：玩家與敵方 auto-move 都傳入 `applyGhostPassDamage`，走 `combatResolver.applyUnitDamage`（damageSource `ghost-pass`，不連鎖）。

## 如何驗證
1. 新增 `tests/GhostMoveWiring.test.ts`：無 Ghost_Move 的部隊行為不變；穿越敵軍移動並各扣一次；穿越岩石/友軍不動；終點被佔時退回到較近的有效終點；龍膽符 profile 表項存在。
2. run-cli 全綠；compute-gate standard；`tsc -p tsconfig.test.json` 無本卡新增錯誤。

## 缺口
- 穿透傷害數字未寫入規格：暫定以穿越者 `getEffectiveAttack()` 計。
- 「閃避後反擊」（反擊率降為 0）未做。
- 龍膽符目前不在 `TallyCardCatalog`，所以 `tiger-tally-long-dan` 在出陣前不會有單位帶到，接線先行、資料另補。
- 移動途中踩到的地格（tile enter 效果）不在穿透格上套用，只在終點套用一次。

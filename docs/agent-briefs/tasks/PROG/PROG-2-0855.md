## 完整描述
NUR-15 要求 Server 端有培育紀錄表，畢業後寫入、可依 session 查詢。本卡只交付 repo 內的 schema 定義與純 TS 驗證：

- `server/schema/002_nurture_records.sql`：`nurture_records` 表定義，主鍵 `session_id`。
- `server/schema/nur15-row-validators.ts`：與 SQL CHECK 對齊的列驗證；JSON 欄位只驗「可解析」，內部結構屬培育系統紀錄格式，不在本檔定義。
- `tests/ServerSchemaNur15.test.ts`：驗證規則與「畢業寫入、依 session 查詢、非法列不寫入」的寫入流程。

## 設計選擇（我的判斷）
- 不加 FK 到子嗣表：子嗣表尚未建立（屬後續卡），先保留 `child_uid` 欄位。
- 寫入流程在測試內以 Map 模擬，不引入 `in-memory-table.ts`，因為該檔屬 MVP-12 分支，本卡保持自給自足。
- 評級與揭露層級在 SQL 與 TS 兩端各寫一次 CHECK，讓 TS 測試能在沒有資料庫時擋住壞列。

## 未涵蓋
- 未執行 SQL、未建立資料庫、未接任何外部服務，也未加雲端憑證（依 PM 裁定）。
- 培育紀錄的 JSON 內部結構（階段、教官、揭露明細）待培育線定案後再補。
- 與 MVP-12 `mvp12-row-validators.ts` 的整併留待 MVP-12 合併後處理。

## 完整描述
雲端的 TypeScript 檢查只跑純邏輯測試（tsconfig.test.json），`assets/scripts` 下依賴 cc 的程式完全沒有型別檢查。
主 tsconfig.json 繼承的 `temp/tsconfig.cocos.json` 是 Cocos 編輯器產生的，雲端沒有，所以無法直接用。

本卡新增 `tsconfig.cc-check.json`：
- 不繼承 temp/，直接引用 repo 內已追蹤的 `@cocos/creator-types/engine.d.ts` 作為 cc 型別來源，不另寫 stub。
- 檢查範圍 `assets/scripts/**/*.ts`，排除 `_pending-delete`。
- `noEmit`、`skipLibCheck`，不產生任何檔案。

## 基線（2026-10-20）
`npx tsc -p tsconfig.cc-check.json`：**69 個錯誤**，集中在 battle/views、ui/components、ui/scenes、ui/platform/cocos 等。
主要類型：TS2554（參數數量）15、TS2339（屬性不存在）10、TS2415（類別繼承）8、TS2345（參數型別）8。
另有 4 處 `Cannot find module 'cc/env'`（cc/env 不在 engine.d.ts 內，屬 stub 缺口）。

## 設計選擇（我的判斷）
- 選 engine.d.ts 而不是寫 cc.d.ts stub：這份宣告是 repo 內已有的官方型別，比手寫 stub 更貼近實際 API，也不需維護。
- 關閉 strict，對齊主 tsconfig.json 的 `strict: false`，避免報告被大量 null 檢查噪音淹沒。
- 不修任何既有錯誤。報告模式只記錄基線，修正由各線依自己的範圍處理。

## 未涵蓋
- 接入 CI：依 PM 裁定不接。
- 修復 69 個既有錯誤。
- cc/env 型別補充：屬後續，若要處理需另開卡。

## 驗收
- `tsconfig.cc-check.json` 存在且可在雲端執行 `npx tsc -p tsconfig.cc-check.json`，輸出錯誤數為 69（基線）。
- 未修改 tsconfig.json、temp/ 或任何 assets 檔案。

## 完整描述
cc-check 基線中的 TS2554（參數數量不符）有 15 處。其中 14 處屬於同一類根因：
介面（抽象型別）宣告的參數比實際實作少，呼叫端依實作寫法傳入額外參數，型別檢查報錯。

- `IDeployRuntimeLike.showToast(message)` 只宣告 1 個參數，實際 `DeployPanel` / `DeployComposite` 的 `showToast(message, duration = 1.2, options?)` 支援 duration 與 options。`BattleScene` / `TurnFlowManager` / `BattleSceneFlow` / `BattleUIBridge` 等 13 處呼叫端依實作傳入 duration 或 options。
- `IBattleUIComponents` 的 `skillTargetingFlow.beginPlayerSkillFlow(skillId, sourceType, sourceLabel)` 只宣告 3 個參數，實際 `BattleSkillTargetingFlow.beginPlayerSkillFlow` 有第 4 個可選參數 `ultimateId`，`BattleUIBridge.ts:629` 傳入奧義 ID。

## 設計選擇（我的判斷）
- **拓寬介面，不改呼叫端**：呼叫端的 duration / options 是有意的功能（Toast 時長、顏色、奧義 ID），刪掉參數會改變行為。
- **可選參數**：`duration?: number`、`ultimateId?: string`，不影響既有呼叫。
- **options 用結構型別 `{ color?: Color }`**，不 import `ui/components/ToastMessage` 的 `ToastOptions`，避免 shared 層反向依賴 ui 層。battle 呼叫端目前只用到 color。
- **不碰 `CocosNodeFactory.ts:65`**（`Expected 4 arguments, but got 2`）：根因是 `buildScrollList` 需要 width/height，屬於另一類（平台 wrapper 對 spec 欄位的對應），另開卡處理。

## 範圍

- `assets/scripts/battle/views/BattleUIBridge.ts`：拓寬 `skillTargetingFlow` 內嵌介面的 `beginPlayerSkillFlow` 簽章（第 86 行）。

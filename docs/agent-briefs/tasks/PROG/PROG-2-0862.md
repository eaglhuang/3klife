## 完整描述
規格 `同名武將系統.md §血脈歸宗` 寫明「消耗『歸宗令』」，但 master 的 `mergeBloodlineFor` 目前不扣道具，註解標為待辦。本卡補上扣除。

歸宗令在名詞表是 `Merge_Token`（「執行血脈歸宗的道具」），目前程式裡沒有此道具。

## 設計選擇（我的判斷，PM 授權可逆選擇自行決定）
- **道具沿用既有庫存**：比照 `ITEM_JOB_CHANGE_ORDER`（轉職令）的做法，在 `PlayerInventory.ts` 新增 `ITEM_MERGE_TOKEN`，起始庫存 0，不進 `STARTER_INVENTORY`。存檔欄位沿用既有 `inventory`，不改 schema。
- **取得來源**：規格沒寫，本卡不加發放途徑，只能靠 `addItem`（商城／活動）。
- **扣除時機**：只在歸宗成功時扣 1 張。失敗（NOT_FOUND、SAME_GENERAL、NO_BLOODLINE、DIFFERENT_BLOODLINE、NO_TRANSFERABLE）一律不扣。
- **不足的拒絕原因**：新增 `NO_MERGE_TOKEN`。檢查放在 planBloodlineMerge 成功之後，所以「本來就不能歸宗」的情況先回原因。
- **不足時的畫面呈現**：規格未定，本卡只回傳原因，UI 文案由 PM 另裁。

## 範圍
- `assets/scripts/core/systems/PlayerInventory.ts`：新增 `ITEM_MERGE_TOKEN` 與顯示名「歸宗令」。
- `assets/scripts/core/managers/GameSession.ts`：`mergeBloodlineFor` 扣歸宗令、回傳型別加入 `NO_MERGE_TOKEN`。
- `assets/scripts/core/systems/BloodlineMerge.ts`：更新註解（扣令在 GameSession）。
- `tests/BloodlineMergeE2E.test.ts`、`tests/BloodlineMergeWiring.test.ts`：既有測試改為先發足歸宗令，讓原本的斷言仍在驗同一件事。
- `tests/BloodlineMergeToken.test.ts`（新增）：驗拒絕、扣 1、失敗不扣、重讀存檔後數量保留。

## 未涵蓋
- 歸宗令的取得來源（商城定價、活動、季度發放）：規格未定，另卡或待 PM 裁定。
- 不足時的 UI 提示文案與傳承／配種入口：另卡。
- 特殊因子範圍、名門預設家譜加成：規格未定，不在本卡。

## 驗收
- 有歸宗令時歸宗成功，數量 −1，名冊與存檔一致。
- 沒有歸宗令時回傳 `NO_MERGE_TOKEN`，名冊與數量都不變。
- 任一失敗原因都不扣歸宗令。
- `run-cli` 全綠；compute gate standard 9/9。

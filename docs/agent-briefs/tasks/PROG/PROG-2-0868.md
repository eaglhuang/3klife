## 現況
- `core/systems/LegendaryMentoring.ts`：`checkLegendaryMentoring`、`performLegendaryMentoring`。純邏輯，原本沒有 src 呼叫端。
- 純邏輯要求呼叫端持有傳道令存量、保存「一生一次」的名將集合。

## 設計
- `PlayerInventory.ts`：新增 `ITEM_LEGENDARY_MENTORING_TICKET`（顯示名「傳道令」），起始庫存 0，不進 `STARTER_INVENTORY`；取得來源待裁決。
- `GameSession.performLegendaryMentoringFor(generalId, childId, exclusiveSkillId)`：先 check，通過才 perform；寫回培育會話（`mentoringModeLog` 一筆 `Legendary_Mentoring`）、扣 1 張傳道令、記名將一生一次、自動存檔。失敗回傳原因、不扣令、不寫入。
- 存檔：`PlayerSaveSnapshot.legendaryMentoringUsedIds?: string[]` 為後加的選填欄位；舊檔讀回為空陣列。`validatePlayerSaveSnapshot` 有白名單，同步加入正規化。版號不升。
- 專屬奧義 id 由呼叫端傳入。名將資料模型目前沒有專屬奧義欄位，這是未涵蓋的缺口。

## 範圍
- `assets/scripts/core/systems/PlayerInventory.ts`：新增傳道令道具與顯示名。
- `assets/scripts/core/services/PlayerSaveService.ts`：選填欄位與正規化。
- `assets/scripts/core/managers/GameSession.ts`：新增 `performLegendaryMentoringFor`、快照與還原、新遊戲時清空。

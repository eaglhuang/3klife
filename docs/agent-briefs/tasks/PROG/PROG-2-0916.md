# [PROG-2-0916] 戰法施放共用入口 castBattleSkill（敵方與玩家同一套結算）

## 開單原因
PM 決議（2026-10-21 07:17Z）：敵方戰法目前直接呼叫 `skillDispatcher.dispatchSeedTactic(Faction.Enemy, …)`（`BattleController` 兩處 `castEnemySeedTactic`），玩家走 `triggerPlayerSeedTactic` 內的同一個 dispatcher 呼叫，兩條路各自寫死參數，之後敵方選技接線容易分歧。改成單一入口，確保兩邊結算一致。

## 完整描述
1. `BattleController` 新增 `castBattleSkill(faction, options, sourceType = SkillSourceType.SeedTactic): SkillExecutionResult`：
   - 戰法來源（SeedTactic）→ `skillDispatcher.dispatchSeedTactic(faction, options)`。
   - 其他來源 → `skillDispatcher.dispatchDirectBattleSkill(options.battleSkillId, sourceType, faction, options)`。
   - 只做分派，不扣資源、不發事件；資源與事件仍由各呼叫端（玩家路徑）處理。
2. `triggerPlayerSeedTactic` 改呼叫 `castBattleSkill(Faction.Player, …)`，行為不變。
3. `executeBattleSpecialResolvePhase` 收到的 `castEnemySeedTactic` 兩處（`enemy-special-resolve`、`player-special-resolve`）改呼叫 `castBattleSkill(Faction.Enemy, { battleSkillId })`。
4. 敵方路徑不扣計謀點、不重設 SP（與現行一致，本卡不改敵方資源規則）。

## 如何驗證
1. 玩家既有行為不變：`triggerPlayerSeedTactic` 在有戰法點與無戰法點兩情境的結果與扣點，與改前一致（沿用既有測試 + 新增斷言）。
2. `castBattleSkill(Faction.Player, opts)` 與 `dispatchSeedTactic(Faction.Player, opts)` 回傳相同結果；敵方同理用 `Faction.Enemy`。
3. run-cli 全綠；`npx tsc -p tsconfig.test.json --noEmit` 只剩 master 既有 4 個錯誤；compute-gate standard。

## 不做的事
- 不接敵方選技（pickEnemyTactic）進敵方回合，那是下一張卡。
- 不改 `BattleSkillDispatcher` 與 `executeBattleSkillRequest`。

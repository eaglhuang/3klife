# [PROG-2-0923] 單挑回合上限

## 開單原因
PROG-2-0922 測試時發現：`resolveAcceptedGeneralDuel` 是 `while` 迴圈，只靠雙方血量歸零結束。骰子若每次都閃躲（例如 RNG 固定為 0），傷害永遠為 0，迴圈不會結束。正式亂數下理論上會結束，但沒有保險絲。PM 裁定現在就加上限。

## 現況（開卡時核對）
- `AI武將強度系統.md` E-7、`數值系統.md` E-14 只定義接受判定與拒絕懲罰，沒有單挑結束回合數，也沒有平局規則。
- 單挑結束條件目前只有「一方武將陣亡」。

## 完整描述
1. `BattleGeneralDuelFlow.ts` 新增匯出常數 `DUEL_MAX_ROUNDS = 50`（暫定）。
2. `resolveAcceptedGeneralDuel` 的 `while` 改為計數的 `for`，達上限即結束。
3. 達上限仍雙方存活 → 平局：不產生死亡、不呼叫 `onGeneralUnitKilled`、不套用懲罰。結果交由 `checkVictory()` 依原有規則處理。
4. 新增 `tests/DuelRoundCap.test.ts`（2 案例）：上限為正整數；骰子固定 0 時單挑在上限內結束，雙方存活、血量不變。

## 裁決（暫定，記入待辦檔）
- 平局而非「沿用規格結束規則」，因為規格沒有結束規則可沿用。
- 上限 50 回合為暫定數值，企劃可再調。

## 如何驗證
1. `DuelRoundCap` 2 案例全綠。
2. `run-cli` 全綠。
3. `npx tsc -p tsconfig.test.json --noEmit` 只剩 master 既有 4 個錯誤。
4. compute-gate standard。

## 不做的事
- 不改接受判定、懲罰、武將化身傷害公式。
- 不處理 `BattleDuelResolver.ts` 重複實作（待辦檔另立清理項）。

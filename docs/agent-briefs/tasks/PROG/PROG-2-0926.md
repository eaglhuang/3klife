# [PROG-2-0926] 場景 preset 對精銳部署上限的影響（DEP-12）

## 開單原因
WBS v16.2 戰場 MVP 的 DEP-12：攻城戰保留器械槽；集齊五虎將符觸發同場加成。

## 現況（開卡時核對）
- 五虎將符同場加成：`TigerTallySetBonus.fieldTallySetMods` 已由 `BattleCombatResolver.tallySetMods` 套用，`TigerTallySetBonus.test.ts` 已覆蓋。不需改動。
- 攻城部署上限：`getEliteDeployCap` 已有攻城 +1，但正式流程從未傳入場景 preset（`scenePresetId` 只在 SortieDeploy 內使用），等於沒有呼叫端。
- 來源：`EncounterConfig.battleKind`（PROG-2-0237）已有 `'siege'`，對應規格的 SCENE_SIEGE（攻城戰）。

## 完整描述
1. `SortieDeploy.ts` 新增 `SCENE_PRESET_SIEGE` 常數與 `scenePresetIdOf(battleKind)`：siege → SCENE_SIEGE，其他 → null。
2. `BattleScene.ts` 與 `BattleSceneFlow.ts` 開局時把 `scenePresetIdOf(encounter.battleKind)` 寫進出征軍勢；`BattleScene` 的戰前檢查 read model 也改用同一個場景值。
3. 新增 `tests/ScenePresetDeploy.test.ts`（3 案例）：推導規則、上限 4→5、`configureSortie` 產生的 eliteCap。

## 裁決（暫定）
- 攻城戰 = SCENE_SIEGE 採用 `battleKind === 'siege'` 推導，沒有新增資料欄位；沒有另外的場景表。若企劃要獨立的場景 preset，再改資料來源。

## 如何驗證
1. `ScenePresetDeploy` 3 案例全綠。
2. `run-cli` 全綠。
3. `tsc -p tsconfig.test.json --noEmit` 只剩 master 既有 4 個錯誤（views 不在測試 tsconfig 內，改動已逐行核對）。
4. compute-gate standard。

## 不做的事
- 不改五虎將符數值與結算。
- 不改 `DelegateAi` 的保留槽邏輯（已有 `reserveSiegeSlots`）。
- 不改 encounters.json 的任何遭遇資料。

# [PROG-2-0927] 奧義傷害接進戰場傷害流程

## 開單原因
PROG-2-0925 只有純公式。PM 裁定 stat_modifier 採 STR（物理）／INT（謀略）÷ 100，要求接進戰場傷害流程。

## 現況（開卡時核對）
- `ultDamage` 與 base_power 查表：#819（PROG-2-0925）。
- 戰場傷害：`BattleSkillDamageResolver.resolveDamage` 以施放者的 scalingStat 攻擊值 × coefficient × falloff 算出 scaledAttack，再進 formula.calculateDamage。
- base_power 表原本沒有載入到執行期（`NumericalConfig` 只有測試讀取）。
- 奧義定義有 `slot`（1~5）與 `scalingStat`。

## 完整描述
1. `UltimateDamage.ultimateAttackOf(level, table, scalingStat, {str, int})`：str → str/100、int → int/100，其他屬性回 null。
2. `BattleSceneLoader` 額外載入 `data/numerical-config`，提供 `findUltBasePowerTable` 與 `findUltimateDamageDef`。
3. `BattleSkillDispatcher.withUltimateAttack`：奧義施放時把 `ultimateAttack` 寫進 request。查不到定義、表未載入、主屬性未定時不寫。
4. `BattleSkillDamageResolver.resolveDamage` 新增可選參數；有值時取代 scaledAttack，之後的防禦、地形、天氣等加成照常。
5. 測試：`UltimateDamage` 新增攻擊基準 1 案例；`UltimateDamageWiring` 5 案例（STR、INT、查不到定義、非奧義來源、真實多回合流程）。

## 裁決（暫定，記入待辦檔）
- 奧義攻擊基準**取代** coefficient 與 falloff（規格只給 ult_damage 公式，沒有說明與 coefficient 的關係）。
- 其他屬性（cha、lea）沒有規則，維持一般傷害路徑。

## 多回合真實流程測試（PM 指示 2026-10-21 12:49Z）
- 測試以 fs 讀 `ultimate-definitions.json` 與 `numerical-config.json`，經 `seedUltimateDataForHeadless` 注入載入器，不靠 spy。
- 真實流程：玩家關羽（ult-guan-yu-1，STR）施放奧義後，與無奧義資料的對照組比較傷害，並檢查精力扣減 = round(maxVitality × 5%)；之後跑 3 個完整回合（玩家、敵方、收尾）。

## 如何驗證
1. `UltimateDamage` 與 `UltimateDamageWiring` 全綠。
2. `run-cli` 全綠。
3. `npx tsc -p tsconfig.test.json --noEmit` 只剩 master 既有 4 個錯誤。
4. compute-gate standard。

## 不做的事
- 不改精力消耗（PM 裁定維持百分比）。
- 不改奧義定義資料與 encounters.json。
- 不改 `shared/skill-runtime.ts` 的重複 enum（另案）。

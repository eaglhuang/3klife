# [PROG-2-0929] 適性 Server schema 與天氣道具（APT-15）

## 開單原因
WBS v16.2 APT-15：適性 Server schema 與天氣道具（祈風令／祈雨符）、適性預言。驗收條件：aptitude 表落地；道具可改變戰場天氣。

## 現況（開卡時核對）
- 規格 §I「Server 端」有 aptitude 表欄位草稿（aptitude_id、player_id、general_uid、dimension、sub_type、grade、source_gene_id），repo 內尚無對應 SQL 或驗證器。
- `server/schema/` 已有 002～005 與各線驗證器，寫法是「SQL 定義 + 列驗證器 + 測試」。
- 規格 §C 只寫「付費道具可改變戰場天氣（如祈風令、祈雨符）」，沒有寫道具改成哪種天氣、持續、次數上限。
- `assets/scripts/core/systems/WeatherSchedule.ts`（APT-06）已是戰場天氣排程，與道具的優先序規格未定。

## 完整描述
1. `server/schema/006_aptitude_records.sql`：aptitude_records 表。dimension 與 sub_type 以 CHECK 綁定（TROOP 4 種、TERRAIN 5 種、WEATHER 6 種），grade 限 S～D，(general_uid, dimension, sub_type) 唯一。僅定義，不部署。
2. `server/schema/apt15-row-validators.ts`：`validateAptitudeRecordRow(row): string[]`，規則與 SQL 對齊。
3. `assets/scripts/core/systems/WeatherItem.ts`：`applyWeatherItem(current, item)` 回傳 `{ weather, changed }`。祈風令 → 大風（WINDY），祈雨符 → 雨天（RAINY）。
4. 測試：`tests/ServerSchemaApt15.test.ts`（5 案例）、`tests/WeatherItem.test.ts`（4 案例）。

## 裁決（暫定，記入待辦）
- 祈風令→大風、祈雨符→雨天：依道具名稱對應，規格未寫。
- 道具直接覆寫本場天氣，不考慮持續與次數；一場能否多次使用，待企劃確認。
- 地形代碼：只有 PLAIN 出現在規格範例，MOUNTAIN／WATER／FOREST／DESERT 為暫定英文代碼。

## 殘留（不在本卡）
- 天氣道具尚未接進戰場流程，目前沒有呼叫端；依 WBS 規則「src 有呼叫端才算已接線」，APT-15 在接線前不算完全落地。接線需先確定道具與 WeatherSchedule 的優先序。
- 適性預言（名士消耗求籤令預言子嗣適性）：規格細節不足，未實作。
- 006 SQL 未部署；general_uid 無外來鍵，待武將表定案。

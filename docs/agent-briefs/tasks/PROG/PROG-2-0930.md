# [PROG-2-0930] 天氣道具接進戰場流程

## 開單原因
PROG-2-0929（APT-15）只有純邏輯，沒有呼叫端。PM 裁定（2026-10-21）：道具優先於 WeatherSchedule，生效 3 回合後回到排程天氣，每場每種道具限用 1 次；要求多回合真實流程測試。

## 現況（開卡時核對）
- `BattleController.setWeatherSchedule` 設定排程；`applyWeatherForTurn(turn)` 每回合依排程改 `state.weather`，改變時發 `WeatherChanged`。
- 技能派發以 `state.weather` 判定天氣限制（WeatherTacticRestriction）。
- 回合數取自 `services().battle.getSnapshot().turn`。

## 完整描述
1. `WeatherItem.ts`：新增 `WEATHER_ITEM_DURATION_TURNS = 3`、`WeatherItemOverride`、`weatherItemActiveAt(override, turn)`。生效區間為 startTurn 起算 3 回合（含起始回合）。
2. `BattleController`：
   - `useWeatherItem(item)`：同一種道具已用過時回傳 `ALREADY_USED` 且不改天氣；否則記錄覆寫（startTurn 為使用當回合），立即套用。
   - `applyWeatherForTurn`：道具生效中以道具天氣為準，否則取排程天氣；只在天氣改變時發 `WeatherChanged`。沒有排程也沒有道具時不動。
3. 測試 `tests/WeatherItemBattleFlow.test.ts`（3 案例，真實 BattleController 跑完整回合，不用 spy）：
   - 祈風令生效第 1～3 回合，第 4 回合回到排程晴天。
   - 同一種道具重複使用被擋，天氣不變。
   - 不同道具各用一次，第二個道具重新計 3 回合，第 5 回合回到排程。

## 裁決（PM 2026-10-21，暫定）
- 道具優先於排程；生效 3 回合後回到排程天氣。
- 每場每種道具限用 1 次。

## 未定（記入待辦）
- 生效中再用另一個道具時，新道具覆寫舊的並從使用當回合重新計 3 回合；規格沒寫，目前是這樣處理。
- 道具是否消耗行動、是否扣成本：規格沒寫，本卡不處理。

## 殘留（不在本卡）
- `useWeatherItem` 目前沒有 UI 呼叫端。接線需 cc 畫面的道具按鈕，依 WBS 規則，接線前不算完全落地。
- 本卡疊在 PR #834（APT-15）上，#834 合併後需 rebase 到 master。

# [PROG-2-0931] 虎符星級突破成本依目標星級修正（NUM-12 餘項）

## 開單原因
NUM-12 核對時發現：數值系統 F-5 的突破表以目標星級為鍵（4★：金 3000／精華 50／成功率 0.8；5★：金 10000／精華 200／成功率 0.5），但程式只有一組 3000／50／0.8，而且只允許 4→5。PM 裁定：鍵為目標星級，3→4 用 4★ 那組，4→5 用 5★ 那組。

## 現況（開卡時核對）
- `TigerTallyBreakthrough.ts`：`TALLY_BREAKTHROUGH_4_TO_5` 單組常數；只接受 4★；封頂判斷以 5★ 為目標。
- 測試 `TigerTallyBreakthrough.test.ts` 鎖的是舊數字。
- 呼叫端：只有測試，`src` 無其他引用。

## 完整描述
1. 常數改為 `TALLY_BREAKTHROUGH_TABLE`，鍵為目標星級 4 與 5。
2. 新增 `breakthroughTargetStar(star)`：3→4、4→5，其餘回 null。
3. `breakthroughSuccessRate(quality, targetStar)`：依目標星級基礎率，UR 加 10%，上限 100%。
4. `resolveTallyBreakthrough`：
   - 星級不可突破回傳 `NOT_BREAKTHROUGH_STAR`（原 `NOT_4_STAR`，改名因為 3★ 也能突破）。
   - 目標星級超過品質封頂回傳 `CAP_REACHED`：R 不能 3→4，SR 不能 4→5。
   - 成功依目標星級扣成本、升星；失敗扣一半、不降星；保底符照舊。
5. 測試 9 案例改為依目標星級鎖定。

## 裁決（PM 2026-10-21）
- 成本與成功率以目標星級為鍵。
- 失敗扣一半、同時套用金幣與精華（暫定，沿用舊規則，規格只寫「材料」）。

## 殘留（不在本卡）
- 突破的 UI 入口（cc 畫面）未接，本卡只改純邏輯。
- 本卡之前的舊註解「5★ 突破與品質封頂衝突」已依 PM 裁定移除。

# [PROG-2-0932] 天氣道具庫存與使用流程（邏輯部分）

## 開單原因
PROG-2-0930 讓戰場能使用天氣道具，但沒有數量來源，也沒有扣庫存。PM 裁定：道具進 PlayerInventory，每用一次扣 1；取得來源屬商業設計，先不做，起始 0。

## 現況（開卡時核對）
- `PlayerInventory.ts`：純 Record 庫存，已有 `itemCount`、`consumeItem`、`addItem`，以及 `ITEM_*` 常數與顯示名稱。
- 戰場的天氣道具入口是 `BattleController.useWeatherItem(item)`（PROG-2-0930），本身不碰庫存。

## 完整描述
1. `PlayerInventory.ts`：新增 `ITEM_WEATHER_WIND = 'item-weather-wind'`（祈風令）、`ITEM_WEATHER_RAIN = 'item-weather-rain'`（祈雨符），並加入顯示名稱。
2. `battle/controllers/WeatherItemUseFlow.ts`：
   - `WEATHER_ITEM_INVENTORY_ID`：天氣道具 → 庫存 id。
   - `weatherItemStock(inventory, item)`：小選單顯示用的剩餘數。
   - `useWeatherItemFromInventory(ctrl, inventory, item)`：先確認庫存 > 0，再呼叫戰場套用天氣，成功才扣 1；庫存不足回 `NO_STOCK`，同場已用回 `ALREADY_USED`，兩者都不改天氣、不扣庫存。
3. 測試 `tests/WeatherItemInventory.test.ts` 5 案例，真實 BattleController 跑多回合。

## 未做（另卡）
- 副按鈕「天氣」與小選單（列兩種道具與剩餘數，數量 0 或本場已用則灰掉）：屬 cc 畫面與版面 JSON，需要 UI 規格鏈（validate-ui-specs --strict）。目前邏輯已提供 `weatherItemStock` 與 `useWeatherItemFromInventory` 給畫面呼叫。
- 道具取得途徑（商城、活動、獎勵）：商業設計，待使用者裁決。
- 新局起始 0；debug 加量的入口未做。

# [PROG-2-0933] 殼戰法不可施放（QA 對 TRP-15 的提醒）

## 開單原因
QA 審 PR #831 時提醒：TRP-15 的 23 條殼 profile（coefficient 0）效果尚未實作，在效果實作前不可施放；UI 要灰掉，且不扣 SP／TP。

## 現況（開卡時核對）
- 殼 profile 由 `BattleSkillProfiles` 尾端迴圈建立，沒有任何「不可施放」標記。
- `triggerPlayerBattleSkill` 與 `BattleSkillDispatcher.executeBattleSkillRequest` 都沒有檢查殼，所以殼戰法可以施放成功（coefficient 0 造成 0 傷害，但仍會重置 SP、發出施放事件）。

## 完整描述
1. `BattleSkillProfiles.ts`：殼 profile 加 `pendingEffect: true`；新增 `isBattleSkillImplemented(id)`，殼回傳 false，已實作與查無 profile 的 id 回傳 true（維持既有行為）。
2. `BattleSkillDispatcher.executeBattleSkillRequest`：殼回傳 `blockedReason: 'not-implemented'`，`applied: false`，在任何資源扣除之前返回。
3. `BattleController.triggerPlayerBattleSkill`：殼直接回傳 false，SP 不重置。
4. 測試 `tests/TigerTallyShellGate.test.ts` 3 案例：查詢函式；真實多回合（殼施放被擋、SP 不變、三回合敵方血量不變）；正向對照（陷陣同場景可施放並造成傷害）。

## QA 第 (1) 點：虎符戰法 TP 成本（未改，待 PM 裁定）
- 規格 E-9「戰法 TP 消耗表」只有 28 招一般戰法（TAC_*），沒有任何虎符戰法的列。
- 目前虎符戰法的施放走 `triggerPlayerBattleSkill` 的 SP 路徑，不經過 `triggerPlayerSeedTactic` 的 TP 扣費，因此它們實際上不會落到預設 30 TP。
- 所以「照規格查表」在現況下沒有可查的值。要不要讓虎符戰法吃 TP、用什麼值，需要 PM 裁定，本卡不擅自決定。

## 裁決
- 殼戰法不可施放、不扣任何資源：依 QA 提醒，屬既定規則，直接實作。

## 殘留
- UI 灰掉：本卡只提供 `isBattleSkillImplemented` 查詢與施放層的拒絕；畫面按鈕的 interactable 接線屬 cc 畫面，另卡處理。
- 虎符戰法 TP 成本：待 PM。
- 殼效果本身：各戰法另卡實作，實作後把 `pendingEffect` 移除即可施放。

## 如何驗證
1. `TigerTallyShellGate` 3 案例全綠。
2. `run-cli` 全綠（3607 passed，3 skipped）。
3. `npx tsc -p tsconfig.test.json --noEmit` 只剩既有 4 個錯誤。
4. compute-gate standard。

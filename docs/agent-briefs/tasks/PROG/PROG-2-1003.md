# [PROG-2-1003] 抽卡扣款與入冊併成同一次存檔（原子提交）

## 開單原因
QA 發現抽卡流程分兩段存檔：`LocalGachaService` 抽完先寫錢包與保底（每次寫入都會存檔），之後大廳 `_onGachaPullSuccess` 才讀教官卡目錄、再入冊存檔。兩段之間有非同步空窗，強關會留下「已扣款、未入冊」的存檔。

## 完整描述
把入冊放進扣款的同一個提交批次：

1. `GameSession.enrollGenerals(generals, options)`：同步入冊（改名冊、轉生、結緣點、發 RosterChanged），不存檔。`addGenerals` 改為「呼叫 enrollGenerals + 有變動才存檔」，對外行為不變。
2. `GachaSaveStore` 新增選填 `enroll(results)` 與 `batch(fn)`。`LocalGachaService._performGacha` 在紀錄寫入成功後，於 `batch` 內依序：入冊、寫保底、扣款。沒有 `batch` 的存放處仍逐筆寫入。
3. 大廳的存放處：`enroll` 呼叫 `enrollGenerals`；`batch` 期間的存檔請求會被壓住，批次結束只存一次。`_onGachaPullSuccess` 改讀入冊結果做提示，不再自己入冊。

中途強關時，存檔裡要嘛同時有扣款與入冊、要嘛都沒有。

## 範圍外（另案）
教官卡（`LegacyService.addGachaMentors`）仍在入冊之後、由 `_onGachaPullSuccess` 呼叫。它存在獨立的 legacy 存檔，不在這次的批次裡。強關時最壞的情況是「武將已入冊、教官卡少一張」，不會丟抽數或扣款。若要把教官卡也併進同一次提交，需要另開卡處理 legacy 存檔。

## 做法
1. `assets/scripts/core/managers/GameSession.ts`：`addGenerals` 拆成同步的 `enrollGenerals` 與其外層的存檔。
2. `assets/scripts/core/services/LocalGachaService.ts`：`GachaSaveStore` 新增 `enroll`、`batch`；`_performGacha` 的扣款與保底寫入改放進 commit 區塊。
3. `assets/scripts/ui/scenes/LobbyScene.ts`：`enroll`、`batch` 接線；`_saveGachaState` 在批次中不存檔；`_onGachaPullSuccess` 讀 `_gachaEnrollResult`。
4. `tests/GachaPullToRosterE2E.test.ts`：新增「強關模擬」案例。抽完不存檔就讀回，錢包與名冊仍是抽卡前；存檔後三者一起到位。

## 如何驗證
1. run-cli 全綠（含新案例）。
2. compute-gate standard 9/9。
3. 實機（Codex 端）：十連抽後立即強關再開，錢包與名冊一致。

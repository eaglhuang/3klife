# [PROG-2-1004] 抽卡教官卡併入同一次提交（日誌補寫）

## 開單原因
PROG-2-1003 把扣款、保底、入冊併成同一次存檔，但支援卡的教官卡仍寫在獨立的 legacy 存檔（`mentor_cards`），不在這次批次裡。強關最壞會留下「武將已入冊、教官卡少一張」。

## 完整描述
教官卡無法直接放進同一次存檔（它在 legacy 存放處），因此改用日誌：

1. 抽卡入冊時，同一批把「待補教官卡」寫進 GameSession 的日誌（`gachaMentorJournal`，存檔欄位）。日誌與扣款、入冊同一次存檔，所以三者一致。
2. 入冊存檔後，大廳寫入 legacy 的教官卡，寫完一筆就從日誌移除並存檔。
3. 進大廳時若日誌還有待補項目，先補寫。強關在任何一步之後，下次都會補上。

教官卡的生成仍是 `addGachaMentorCards`（只有支援卡池、PM 裁定 PROG-2-0506），`addMentorToHoldings` 以 uid 去重，因此重複補寫不會多出卡。

## 做法
1. `PlayerSaveService.ts`：新增選填欄位 `gachaMentorJournal`、`GachaMentorJournalEntry` 型別與 `normalizeGachaMentorJournal`；讀檔時經正規化，舊檔沒有欄位讀回空陣列。
2. `GameSession.ts`：日誌欄位、`gachaMentorJournal` 唯讀副本、`queueGachaMentorDraw`（不存檔）、`completeGachaMentorDraw`；新遊戲清空；快照與讀檔接上。
3. `LobbyScene.ts`：`enroll` 同批登記日誌；`_onGachaPullSuccess` 與 `onLoad` 呼叫 `_applyGachaMentorJournal`，逐筆補寫、移除、存檔。失敗只記 warn，日誌保留待下次。
4. `tests/GachaPullToRosterE2E.test.ts`：新增「教官卡日誌」案例：未存檔強關不留日誌；存檔後強關日誌仍在；補寫後移除並存檔。

## 如何驗證
1. run-cli 全綠（含新案例）。
2. tsc cc-check 無錯誤。
3. compute-gate standard 9/9。
4. 實機（Codex 端）：十連抽到支援卡後立即強關再開，教官卡數量與武將名冊一致。

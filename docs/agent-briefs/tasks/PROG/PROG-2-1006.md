# [PROG-2-1006] 大廳任務 AI 委任與回看紀錄（存檔接線）

## 開單原因
WBS HALL-05 第二段：AI 委任（AI_Assign_Enabled 的任務由 AI 選將執行）與委任回看紀錄。純邏輯 `HallAutoAssign` 已在，但沒有呼叫端，紀錄也沒有存檔。

## 完整描述
本卡把純邏輯接到 GameSession 與存檔：

1. `autoAssignHallMission(task, assignedAt)`：候選為目前可出戰武將，戰力以既有粗估 `estimateSortiePower` 計算；選將規則沿用 `pickAutoAssignGeneral`（戰力高者優先、同分取 id 較小者，暫定）。未開啟委任或無候選時拒絕，不寫紀錄。
2. 委任紀錄存進存檔欄位 `hallAssignLog`；自動存檔開啟時委任後即存檔，否則由呼叫端存檔。
3. `listHallAssignRecords(taskId?)`：回看紀錄，新到舊。
4. `settleHallAssign(taskId, outcome, settledAt)`：結算同一任務最新一筆未結算的紀錄；已結算者不可重複結算。結算結果由戰後系統傳入。

## 範圍外（留待後續卡）
- **大廳入口未接**：`LobbyScene` 目前只在 `previewMissionDetailSmoke` 開啟任務詳情彈窗，真實任務板沒有開啟彈窗的入口，「委任」按鈕 `onActionSelected` 也沒有處理。要接的是「任務板點任務 → 彈窗 → 委任 → autoAssignHallMission → 顯示結果」，屬於 UI 接線，需另開卡。
- 戰後結算呼叫 `settleHallAssign`：沒有戰後流程接入點，待任務結算卡處理。
- 選將權重屬暫定（規格未寫）。

## 做法
1. `PlayerSaveService.ts`：`hallAssignLog` 欄位、`HallAssignLogEntry`、`normalizeHallAssignLog`，讀檔時正規化。
2. `GameSession.ts`：`_hallAssignLog`、快照與讀檔、新遊戲清空；`autoAssignHallMission`、`listHallAssignRecords`、`settleHallAssign`。
3. `tests/HallAssignLog.test.ts`：未開啟、無候選拒絕；存檔後讀回、結算、重複結算拒絕；未存檔強關讀回無紀錄；自動存檔即存。

1. run-cli 全綠（含 HallAssignLog 4 案）。
2. tsc cc-check 無錯誤。

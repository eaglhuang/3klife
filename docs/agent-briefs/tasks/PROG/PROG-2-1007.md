# [PROG-2-1007] 大廳任務板開啟任務彈窗與委任按鈕接線（HALL-05 缺口一）

## 開單原因
PROG-2-1006（PR #767）完成委任與回看紀錄的後端流程，但大廳任務板仍沒有開啟任務彈窗的真實入口（目前只有 LoadingScene 的 smoke route），彈窗的「委任」按鈕也還沒接到 `autoAssignHallMission`。

## 完整描述
1. 任務板每一列可開啟 `LobbyMissionDetailDialog`，彈窗內容由該列的 `HallTaskRow` 轉成 `state`（標題、簡述、難度與需求階級、獎勵），其餘欄位沿用彈窗預設值。
2. 彈窗的 `assign` 動作呼叫 `GameSession.autoAssignHallMission(task, now)`；成功時刷新任務板與委任紀錄，失敗時顯示理由（無候選、未開啟委任）。
3. 純邏輯部分（列資料 → 彈窗 state）獨立成不依賴 cc 的函式，並補單元測試。

## 做法（待 #767 合併後執行）
1. 從新的 master 開分支，`task-lock.js lock PROG-2-1007` 後再動手。
2. 新增純 TS helper（列資料 → 彈窗 state）與測試。
3. `LobbyScene`：任務板列的詳情入口與彈窗 `onActionSelected` 的 `assign` 分支。
4. 佈局：為每列加一個詳情按鈕（hall-board-main.json），多語 key 依「多語佔位 key 分工」歸底座線。

## 如何驗證
1. run-cli 全綠（含新測試）；tsc cc-check 無新增錯誤；compute-gate standard 9/9。
2. 實機點擊由 Codex 驗收（cc 畫面接線不另開驗收卡，批次併入驗收工單）。

## 未定事項（暫定）
- 彈窗的成本與獎勵欄位沿用戰鬥任務格式，大廳任務只顯示獎勵基礎值（暫定）。
- 委任時的選將沿用 `autoAssignHallMission` 的規則，不另開手動選將（暫定）。

# [PROG-2-1021] 統一物件庫存檔與虎符同步（DS-08 儲存段）

## 開單原因
DS-08 裁定：統一物件庫（Inventory_Service）是唯一真相。目前虎符散在 `_tallyCards` 與 `_tallyHoldings` 兩份，沒有統一列，`InventoryProjection.deriveInventoryViews` 沒有任何呼叫端。PM 裁定採 dual-write：`inventoryRecords` 為 canonical 並存檔，讀取走 `deriveInventoryViews`，舊的 `_tallyCards` 暫時保留作過渡。

## 完整描述
1. 新增純函式 `tallyCardToInventoryRecord(card, holder)`：把一張虎符卡與持有者轉成一列 `InventoryRecord`（Item_Type=TALLY，Quantity=1）。
2. 來源映射：`death` → `DeathSettlement`、`reward` → `WarConquest`、`surrender` → `Recruitment`；`retire` 不產生列（PM 裁定：退役不發虎符）。
3. 存檔：`PlayerSaveSnapshot` 新增選填欄位 `inventoryRecords`；有內容才寫入；讀回時逐列驗證形狀，壞列丟棄。
4. 讀檔：有 `inventoryRecords` 欄位就用它；舊存檔沒有時由 `tallyCards` + `tallyHoldings` 重建，不改版號。
5. GameSession：每次寫 `_tallyCards` 或 `_tallyHoldings` 後同步重算 `_inventoryRecords`（過渡期 dual-write）。
6. 新增 `inventoryViews` 讀取 getter，內部呼叫 `deriveInventoryViews`。
7. 英靈卡：只保留列形狀與讀取路徑，本卡不建立任何 SPIRIT_CARD 列。

## 如何驗證
1. `tests/InventoryRecordBridge.test.ts`：映射三種來源、retire 不產生列、欄位對應正確、經 `deriveInventoryViews` 可讀回。
2. `tests/InventoryRecordSave.test.ts`：存讀往返、舊存檔缺欄位時由虎符重建、壞列被丟棄。
3. run-cli 全綠；`npx tsc -p tsconfig.cc-check.json --noEmit` 無新增錯誤；compute-gate standard 9/9。

## 未做
- 英靈卡寫入來源（英靈世家系統尚未接線）。
- `_tallyCards` 移除（待所有讀取改走 `inventoryViews` 後另卡處理）。
- TALLY 列的 `Slot_Type`、`Display_Bucket` 規格未定義枚舉，本卡暫用 `TALLY`，投影函式不讀這兩欄。

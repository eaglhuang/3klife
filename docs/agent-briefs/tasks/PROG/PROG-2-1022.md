# [PROG-2-1022] 武將人物頁 Data Read Model 映射層（GDUI-13）

## 開單原因
PM 在 ECO-09 等付費貨幣裁定期間，指定從底座可開工清單挑下一個純邏輯、不涉及商業設計的項目。GDUI-13 對應《武將人物介面規格書》§10 Data Read Model 與 §12 狀態表，是人物頁六個分頁（將／屬／命／技／寶／兵）的讀取前置層。

## 完整描述
1. 新增純函式模組 `GeneralReadModel`，為 §10 表中的 16 個欄位各提供一個 mapper，把原始武將資料轉成 `{ state: 'VALUE', value }` 或 `{ state: 'NO_DATA' }`。
2. 欄位值不合法（型別錯、列舉不在清單內、數量不符）一律回 `NO_DATA`，不填預設值，不造假資料。
3. Story_Strip_Cells 只接受 5~6 格字串；Default_Tab 只接受 `Overview / Stats / Bloodline / Tactics / Equip / Aptitude`；Bloodline_StoryDock_State 只接受 `COLLAPSED / HALF / EXPANDED`。
4. 屬性揭露：`mapStatDisclosure(value, level)` 重用 `StatRevelation.revealStat`。數值缺漏回 `NO_DATA`；揭露層級不合法時退回最保守的 `HIDDEN`，避免洩漏精確值。
5. 狀態表中的 `BATTLE_LOCKED` 不在本卡範圍（屬於戰鬥狀態，由 UI 層讀取）。

## 如何驗證
1. `tests/GeneralReadModel.test.ts`：16 個欄位各有至少一個 VALUE 與一個 NO_DATA 案例；列舉與格數邊界；揭露四階與缺漏、非法層級。
2. run-cli 全綠；`npx tsc -p tsconfig.cc-check.json --noEmit` 無錯誤；compute-gate standard 9/9。

## 未做
- 人物頁 UI 接線（CompositePanel、Layout JSON、LobbyScene 掛載）屬於各畫面線，本卡只提供純映射。
- 資料來源（`Ancestors_JSON`、`Bloodline_Ultimate` 等）尚未在 master 的 GeneralConfig 完整定義，本卡只驗形狀，不假設其內容。

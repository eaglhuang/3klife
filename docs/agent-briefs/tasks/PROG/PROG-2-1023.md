# [PROG-2-1023] 資料中心名詞對應：PersonRegistry 與 LoreCache（TERM-06）

## 開單原因
名詞定義文件 §J 規定資料中心的核心名詞都要有對應類別。盤點後，DataCatalog、BloodlineGraph、SaveSerializer、DeltaPatchBuilder、DataGrowthMonitor 已存在；PersonRegistry 與 LoreCache 尚未實作，本卡補上這兩個。

## 完整描述
1. `PersonRegistry`（人物登記冊）：去重的中央人物主檔，每個 uid 只有一筆 PersonRecord（uid、template_id、name、gene_refs、ep_base、faction、is_virtual）。
   - 登記時驗證欄位形狀；不合法回 `INVALID_RECORD`。
   - uid 已存在回 `DUPLICATE_UID`，不覆蓋原紀錄。
   - 讀取回傳副本，外部改動不影響登冊內容。
2. `LoreCache`（lore LRU 快取）：最多 20 位武將故事常駐記憶體（`LORE_CACHE_CAPACITY = 20`）。
   - `get` 會把該項標為最近使用；`set` 超過容量時淘汰最久未用的一項。
   - 同一 key 重複 `set` 更新值並視為最近使用，不增加容量。

## 如何驗證
1. `tests/PersonRegistry.test.ts`、`tests/LoreCache.test.ts`：各類別的正常路徑、非法輸入、去重、LRU 淘汰順序與容量上限。
2. run-cli 全綠；`npx tsc -p tsconfig.cc-check.json --noEmit` 無錯誤；compute-gate standard 9/9。

## 未做
- PersonRegistry 與 LoreCache 尚無 src 呼叫端；接入血統樹與故事載入屬於後續卡。

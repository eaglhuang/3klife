# [PROG-2-1024] 人物頁 presenter 接上 Data Read Model（GDUI-13 呼叫端）

## 開單原因
PROG-2-1022 的 `GeneralReadModel` 已合併，但沒有任何 src 呼叫端。巡檢指定先接人物頁 presenter，讓讀取模型真的被呼叫。

## 完整描述
1. `buildGeneralDetailOverviewContentState` 在既有的 overview 內容狀態上新增 `readModel` 欄位，值由 `mapGeneralReadModel(config)` 產生。
2. 新增欄位是附加的：既有欄位與畫面顯示不變，本卡不改任何 UI 元件的外觀。
3. 原始 `GeneralConfig` 目前沒有 §10 的全部欄位（例如 `General_Fame`、`Learned_Tactics`），這些欄位會正確顯示為 `NO_DATA`，不補假資料。

## 如何驗證
1. `tests/GeneralDetailReadModelCaller.test.ts`：overview 內容狀態含 `readModel`；既有欄位（如 `headerName`）不變；缺少 §10 欄位的武將其 `readModel` 欄位為 `NO_DATA`。
2. run-cli 全綠；`npx tsc -p tsconfig.cc-check.json --noEmit` 無錯誤；compute-gate standard 9/9。

## 未做
- 人物頁各分頁依 `readModel` 切換 NO_DATA 佔位的畫面行為，屬於 UI 線（需要 layout 與 presenter 設計決定）。
- `GeneralConfig` 補上 §10 欄位的資料來源，屬於武將資料線。

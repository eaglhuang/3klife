# [PROG-2-1025] 人物頁分頁的空欄位佔位規劃（純邏輯）

## 開單原因
巡檢指定：人物頁分頁依 `readModel` 切換佔位的 cc 畫面由本線自做。cc 畫面無法在雲端容器建置驗收，因此先把「哪一頁哪一欄沒有資料」這段規劃做成純邏輯，由測試鎖住；cc 綁定待後續接上。

## 完整描述
1. 依規格 §10「顯示頁」欄，建立欄位對分頁的對照表 `PERSON_PAGE_FIELD_TABS`：
   - `Ancestors_JSON`、`Bloodline_*`、`Equipped_Spirit_UID`、`Story_Strip_Cells`、`Bloodline_StoryDock_State` → Bloodline（命）
   - `General_Rank`、`Command_Capacity` → Overview（將）
   - `General_Fame` → Overview（將）與 Bloodline（命）
   - `Talent_Stats`、`Prowess_Stats` → Stats（屬）
   - `Learned_Tactics` → Tactics（技）
   - `Equipment_Loadout` → Equip（寶）
   - `Equipped_Tally_UID`、`Aptitudes` → Aptitude（兵）
   - `defaultTab` 屬於外層 chrome，不列入分頁。
2. `listEmptyFieldsByTab(model)`：回傳每個分頁中狀態為 `NO_DATA` 的欄位清單；全部有資料時每頁清單為空。
3. 本卡不改任何既有檔案，也不接 cc 畫面。

## 如何驗證
1. `tests/PersonPagePlaceholders.test.ts`：對照表涵蓋 §10 除 defaultTab 外的 15 個欄位；`General_Fame` 同時出現在 Overview 與 Bloodline；空武將時每頁列出正確欄位；完整武將時每頁為空。
2. run-cli 全綠；`npx tsc -p tsconfig.cc-check.json --noEmit` 無錯誤；compute-gate standard 9/9。

# [PROG-2-1026] 兵分頁虎符槽讀取統一物件庫（inventoryViews 呼叫端）

## 開單原因
PROG-2-1021 的 `GameSession.inventoryViews` 沒有 src 呼叫端（QA 回報）。PM 裁定讀取端選「兵分頁虎符槽」，戰場 BattleScene 不動。

## 完整描述
1. 新增純函式 `equippedTalismanSlot(views, generalId)`：在 `InventoryViews.talismans` 中找出 `Equipped_General_UID === generalId` 的虎符；有則回傳 `{ state: 'EQUIPPED', talisman }`，沒有回 `{ state: 'EMPTY' }`。多筆時依 `Tally_ID` 排序取第一筆，結果固定。
2. 人物頁 overview 內容狀態新增 `tallySlot` 欄位。`buildGeneralDetailOverviewContentState(config, views?)` 的 `views` 預設為空視圖，既有呼叫端行為不變。
3. 人物頁主要建構點（`GeneralDetailComposite` 的 DS3 路徑）改傳入 `services().session.inventoryViews`，成為 inventoryViews 的 src 呼叫端。
4. 戰場 BattleScene 不變；兵分頁的 cc 槽位綁定屬 UI 線，本卡不改 layout。

## 如何驗證
1. `tests/TalismanSlotView.test.ts`：裝備中回 EQUIPPED；未裝備回 EMPTY；多筆依 Tally_ID 排序；其他武將的虎符不被取到。
2. 既有 overview 測試（`GeneralDetailReadModelCaller`）仍通過；內容狀態含 `tallySlot`。
3. run-cli 全綠；`npx tsc -p tsconfig.cc-check.json --noEmit` 無錯誤；compute-gate standard 9/9。

## 未做

- 其他 `buildGeneralDetailOverviewContentState` 呼叫端改傳 views，等需要時再接。
- 戰場讀取切換，等有 troopType 與戰鬥經驗欄位後另卡。

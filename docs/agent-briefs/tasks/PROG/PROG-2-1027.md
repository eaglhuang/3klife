# [PROG-2-1027] NPC_Memory 最小 read model（DS-09）

## 開單原因
WBS DS-09：依 Data Schema §2-3／§2-3a 建立本機 `NPC_Memory` 的最小讀寫模型，供離線模板選句使用。
現有 `NpcDialogueService` 走伺服端 HTTP，本卡只處理本機資料形狀，不接網路。

## 完整描述
1. 新增 `assets/scripts/core/systems/NpcMemoryReadModel.ts`（純 TypeScript，不依賴 cc）：
   - `createNpcMemory(playerId)`：Player_ID 為空回 null；否則建立空記憶，路徑與人設版號採規格預設。
   - `appendRecallContext(record, entry)`：寫入一筆回憶，回傳新物件；同 Vector_ID 去重並移到最新；超過 `RECALL_CONTEXT_LIMIT`（20）丟最舊；Snippet 截至 180 字。
   - `recallForGeneral(record, generalUid)`：依武將讀回，最新在前。
   - `normalizeNpcMemory(raw, playerId)`：Player_ID 與目前玩家不符回 null（Player_ID 綁定）；壞回憶與非字串槽位丟棄。
2. MVP 只保存 `Template_Slot_Values` 與 `Recall_Context`（§2-3 第 4 點）。`Recent_Context`、`Pending_Unknown_Events` 留第二階段，不加進模型。
3. 不接 save 服務、不改 PlayerSaveService：存檔接線另卡處理。

## 如何驗證
1. `tests/NpcMemoryReadModel.test.ts`：空 ID、寫入不改原值、去重、上限、依武將讀取順序、Player_ID 不符、壞資料、Snippet 截斷。
2. run-cli 全綠；`npx tsc -p tsconfig.cc-check.json --noEmit` 無錯誤；compute-gate standard 9/9。

## 未做
- 存檔接線（PlayerSaveService 寫入／還原 NPC_Memory）：另卡。
- 離線模板選句本身：本卡只提供讀寫函式，選句邏輯屬 NPC 對話線。
- 上傳前摘要化（§2-3 第 5 點）：屬伺服端同步，不在本卡。

## 自行決定的選擇（PM 可改）
- `Recall_Context` 上限取 20，與規格未給數字；若規格日後有數字，改常數即可。
- `Snippet` 截至 180 字，與 `NpcMemoryAdapter` 摘要長度一致。

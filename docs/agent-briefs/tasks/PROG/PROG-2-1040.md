# [PROG-2-1040] 一般裝備穿戴與卸下（純邏輯）

## 開單原因
QA 發現：寶頁六格（PROG-2-1037）已能顯示，但全程式沒有任何地方寫入 `equippedBy`／`slotId`，寶頁永遠是空的。需要先有穿戴與卸下的純邏輯，再由 GameSession 與寶頁點擊接上。

## 完整描述
1. 新增 `assets/scripts/core/systems/GearEquipFlow.ts`：
   - `equipGear(records, gearUid, generalUid, slotId, canEquipInSlot)`：穿戴到指定格；格內舊件自動卸下回倉庫。
   - `unequipGear(records, generalUid, slotId)`：卸下指定格，兩欄清為 null。
2. 拒絕原因：`NOT_FOUND`、`NOT_GEAR`、`OWNED_ELSEWHERE`、`NOT_EQUIPABLE`、`SLOT_LOCKED`。
3. 解鎖判斷沿用 `deriveGeneralBackpack` 的 unlocked，不另存解鎖狀態；進階欄空格拒絕，已有裝備時可替換。
4. 「能否放入該格」由呼叫端 `canEquipInSlot` 傳入。本卡不讀 `Gear_ID`，因為它在 #1028（未合併）上；避免疊卡。
5. 一律回傳新陣列，不修改傳入的 records。

## 如何驗證
1. `tests/GearEquipFlow.test.ts`：寫入、舊件自動卸下、非裝備／查無列／他人已裝／不可放入／未解鎖拒絕、背包視圖往返、卸下。
2. run-cli 全綠；`npx tsc -p tsconfig.cc-check.json --noEmit` 無錯誤；compute-gate standard 9/9。

## 未做（另卡）

- 寶頁格點擊、從背包選可裝備道具的 cc 畫面接線。
- 背包使用按鈕 cc 接線（等 #1020 合併後接 `useItem`）。

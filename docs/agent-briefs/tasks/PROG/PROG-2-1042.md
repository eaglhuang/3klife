# [PROG-2-1042] 技頁三態檢視模型（GDUI-10）

## 開單原因
武將人物介面規格書 §7 要求技頁分成已習得、可習得、未解鎖三態，並依三態用彩色、半透明、灰階呈現。目前 master 沒有這個檢視模型，這張卡先把資料轉換做成純邏輯。

## 完整描述
1. 新增 `assets/scripts/core/systems/TacticsTabView.ts`：`buildTacticsTabView` 依已習得、可習得、未解鎖三組 id 建出列表。
2. 可習得的細節顯示學習需求 TP，沿用 `tacticLearnThreshold`（TP 消耗 × 2）。
3. 戰法定義（名稱、等級、TP、類型、簡述）由呼叫端注入的 `lookup` 提供；查無定義時顯示 id，不補資料。
4. 同一戰法只會出現在一個列表：已習得優先，其次可習得，最後未解鎖。

## 如何驗證
1. `tests/TacticsTabView.test.ts`：分組與細節、meta 格式、去重、查無定義、主戰法狀態、三態呈現對應。
2. run-cli 全綠；`npx tsc -p tsconfig.cc-check.json --noEmit` 無錯誤；compute-gate standard 9/9。

## 未做（另卡）
- 戰法詳情抽屜與 cc 技頁 layout 接線。
- 可習得戰法的「來源」欄位：規格只寫「顯示需求與來源」，來源資料未定義，暫不顯示。

# [PROG-2-1080] 打包後展開 Set/Map/迭代器失效（宿命轉蛋抽不到武將）

## 來源
- MVP 無頭實機測試：新玩家按「轉蛋」永遠回 `pool-too-small`，抽不到第一位武將，循環從開局就斷。
- 原因：Cocos 打包使用 Babel 寬鬆模式，`[...new Set(pool)]` 轉成 `[].concat(new Set(pool))`，得到長度 1 的陣列。單元測試在 Node 跑原生語法，所以全綠。同類寫法遍布存檔、培育、出戰名冊、資源載入、戰場等 36 處。

## 範圍
- `assets/scripts` 內 36 處展開 Set / Map / 迭代器 / 字串改用 `Array.from(...)`（`String.fromCharCode(...typedArray)` 走 apply，型別陣列可用，保留）。
- `tests/IterableSpreadGuard.test.ts`（新）：掃描禁止直接展開 `new Set/Map` 與 `.values()/.keys()/.entries()`。

## 缺口
- 展開 Set 變數無法以文字比對防回歸；可用 `tsc --target es5` 找 TS2802。根治需改 Cocos 專案腳本設定的 loose 選項，另議。

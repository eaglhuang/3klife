# [PROG-2-1174] 晨報摘要生成並於登入時顯示（JRN-02）

## 為什麼做
武將日誌與離線互動系統.md (doc_spec_0015) §E-2 晨報摘要為 P0：每次登入把離線期間最值得知道的 1~3 則日誌整理成摘要。目前日誌（JRN-01）、晨報畫面流程（JournalHubController）都有，但沒有產生晨報的邏輯；離線互動判定需要的「未讀晨報數」也沒有來源，一律填 0。

## 做什麼
- 新增 MorningReport.ts（純邏輯）：依 §F-1 篩掉 HIDDEN、依 Priority 由高到低挑；名額＝官職階位 ≥4 給 3 則，否則 2 則；同類別只留最高的一則（§F-1 規則 3 折疊重複）；開頭句用 §G「晨鼓既響，昨夜諸事已整理成報。」。
- 時間窗：日誌只增不刪，以「上次登入時的條目數」為標記，標記之後新增的條目才是這次的候選。
- GameSession：recordLoginAt 時產生晨報；提供未讀晨報行、未讀數、標記已讀；存讀檔。offlineInteractionDue 未傳未讀數時改用實際未讀數。
- LobbyScene：日報 toast 之後接著依序顯示晨報行，顯示後標記已讀。

## 不做
- §F-1 的 freshnessWeight／characterAffinityWeight 規格未給數值：暫定皆為 1（等同依 Priority 排序），不做加權亂數。
- 晨報彈窗（JournalHubController 的大廳掛載）。

## 驗收
- 單元測試覆蓋挑選、名額、折疊、時間窗、存讀檔。
- compute-gate standard 9/9；實機待驗收。

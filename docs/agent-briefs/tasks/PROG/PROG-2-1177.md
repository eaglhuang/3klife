# [PROG-2-1177] 派遣品質評分（JRN-03 第一段）

## 為什麼做
武將日誌與離線互動系統.md (doc_spec_0015) §E-3 派遣整備（P1）尚無實作。§F-2 給了派遣品質評分公式與四級品質區間，可先做成可獨立測試的純邏輯。

## 做什麼
- DispatchQuality.ts（純邏輯）：
  - getDispatchScore：角色契合×45＋能力契合×25＋心情×15＋日誌親和×15，四捨五入（§F-2）。
  - 子項（規格只給函式名，算法暫定）：角色契合＝任務標籤中武將具備的比例；能力契合＝各需求能力 min(1, 實際/需求) 的平均；心情對照表 LOW/NORMAL/HIGH；日誌親和＝故事標籤中武將日誌標籤的比例。
  - dispatchQualityOf：分數對到 POOR / NORMAL / GOOD / EXCELLENT（門檻暫定 40/60/80，集中在資料表）。
  - canAutoDispatch：高風險任務不得自動代勞（§F-2 規則 3）。
  - dispatchCompleteLine：§G「{GeneralName} 已完成『{JobName}』，帶回 {RewardText}。」
- 標籤為空時該子項視為滿分（暫定：任務沒有要求即不扣分）。

## 不做
- 派遣任務清單、進行中／已完成的存檔狀態與大廳派遣板接線（後續卡）。
- 武將心情系統（目前沒有，呼叫端傳入，預設 NORMAL）。

## 驗收
- 單元測試覆蓋公式、各子項、品質區間、高風險、完成句。
- compute-gate standard 9/9。

# [PROG-2-1178] 派遣任務狀態與登入結算（JRN-03 第二段）

## 為什麼做
武將日誌與離線互動系統.md (doc_spec_0015) §E-3 派遣整備：閒置武將在玩家離線時執行低風險任務，回傳結果與日誌。§I 的 General_Dispatch 有 Active_Jobs／Completed_Jobs／Dispatch_Cooldowns，但目前沒有任何狀態；PROG-2-1177 只做了評分。

## 做什麼
- DispatchJobs.ts（純邏輯）：
  - startDispatch：派遣時以 §F-2 評分快照分數；擋下高風險任務的自動派遣、武將忙碌、冷卻中、同任務進行中、時長非法。
  - settleDueDispatches：到期的任務轉為已完成，品質依分數對到 §F-2 區間，武將進入冷卻。
  - 已完成紀錄上限、冷卻時長、各品質的日誌重要度：暫定，集中在常數。
  - normalizeDispatchState：讀檔時清掉壞資料。
- GameSession：startDispatchJob、settleDispatchJobs（寫 DISPATCH 日誌，摘要用 §G 完成句）、dispatchState；recordLoginAt 先結算派遣再產生晨報，離線期間完成的派遣會進晨報；存讀檔 generalDispatch。

## 不做
- 派遣任務清單（規格未給，由呼叫端提供）與獎勵發放（§F-2 規則 1：品質不覆寫主獎勵權威）。
- 大廳派遣板 UI 接線。

## 驗收
- 單元測試覆蓋派遣阻擋、到期結算、冷卻、存讀檔、登入結算進晨報。
- compute-gate standard 9/9。

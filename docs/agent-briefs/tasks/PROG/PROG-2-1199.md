# [PROG-2-1199] 大廳許願祭壇彈窗（doc_spec_0002 §E-7／§F-4）

## 為什麼做
PROG-2-1198 已完成許願池邏輯與存檔，但大廳沒有入口，玩家無法許願。大廳規格 §E-7 要求祭壇以早／中／晚三巡呈現，插槽有空位、進行中、完成待領取三種狀態；§F-4 要求把進行中許願映射成插槽、加速後剩餘時間不低於零、完成立即轉可收取。

## 做什麼
- WishAltarController（純邏輯）：巡次標題（UI_WISH_ROUND）、本巡剩餘可許願數、加速卡持有數；5 個插槽三態；商品選擇（上一個／下一個）；許願（UI_WISH_START）、點進行中插槽用 1 張加速卡、領取（UI_WISH_DONE）。
- UCUF 彈窗 wish-altar-screen（版面、screen、skin 沿用挑戰賽 skin）。
- 晨報派遣板入口列加「許願祭壇 ▶」（四鍵各寬 220）；LobbyScene 掛載並在成功操作後存檔。

## 暫定
- 入口暫放晨報派遣板（大廳場景熱點待美術）；倒數只在開啟或操作時更新。
- 課金即買軌與加速卡來源不在本卡。

## 驗收
- 單元測試：三態插槽文字、按鈕可用、許願／加速／領取訊息、版面節點與 FlowView key 對齊。
- 全套測試、tsc、validate-ui-specs、compute-gate standard。

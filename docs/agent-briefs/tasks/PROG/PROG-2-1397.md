# [PROG-2-1397] 抽卡結算產生同步列（GCH-14）

## 為什麼做
GachaSyncRecord 有純邏輯與校驗，但 src 沒有呼叫端，客戶端抽卡後沒有產生伺服端需要的 Total_Pulls／Pity／Bonding／Last_SSR_Pull。

## 做什麼
- 保底狀態記下最後一次 SSR 的抽數（lastSsrPull）。
- 轉蛋結算時，同步佇列的召喚紀錄帶 gachaSync。
- 流程測試：結算後的同步列與存檔一致，且通過校驗。

## 不做
- 不連外部服務、不接伺服器寫入（規格要求的伺服器端寫入另案）。

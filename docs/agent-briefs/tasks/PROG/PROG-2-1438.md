# [PROG-2-1438] NPC_Memory read model 存讀檔與 UI 字串（NPC-09）

## 範圍
- NpcMemoryReadModel.ts：新增 `npcPlayerIdFromSeed`（種子推導擁有者 id）、`normalizeNpcPlayerId`、公開 `cloneNpcMemory`。
- PlayerSaveService.ts：快照新增選填欄位 `npcPlayerId`、`npcMemory`；只在 id 合法時寫入，記憶與 id 不符時只保留 id。
- GameSession.ts：建構時與新局時由種子產生 id 並建立空記憶；存檔寫入；讀檔時沿用存檔的 id，缺欄位則補產並在讀檔尾端存回；記憶擁有者不符時改為空記憶。提供唯讀 `npcMemory`。
- i18n：zh-TW／en／ja 新增 UI_NPC_DIALOGUE_TITLE、CONTEXT_SELECT、SPEAK_BUTTON、LOADING、FALLBACK、OFFLINE_MODE、SOURCE_HINT（{0} 為來源標題）。
- 測試：tests/NpcMemoryPersistence.test.ts，5 條（新局存讀、舊檔補產並存回、擁有者不符、id 正規化、三語字串齊全）。

## 暫定決策
1. Player_ID 由 GameSession 的種子推導（npc-＋種子 base36）；讀檔時以存檔的 id 為準，不重算。
2. 舊檔缺 id：讀檔時用亂數補產一組，尾端存回，之後每次讀都是同一個 id。
3. SOURCE_HINT 的佔位符由規格的 {SourceTitle} 改為專案慣用的 {0}。
4. 只提供唯讀 npcMemory，寫入（Recall_Context 累積）留給之後的 NPC 對話線，避免沒有呼叫端的寫入方法。

## 不在範圍
- NPC 對話 UI 與 UI_NPC_* 的實際顯示（待 NPC-07/08 的對話面板）。
- Recent_Context、Pending_Unknown_Events（第二階段）。

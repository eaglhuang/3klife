# [PROG-2-1440] 登入窗限流疊上 Utility AI 評分（NPC-05 續）

## 為什麼做
PROG-2-1379（#1254）已導入 F-1 評分，但規格 F-1 第 3 點「同一武將同一登入窗只允許 1 則高權重互動」還沒做。原 PR #1259 與 #1254 重複，依 PM 裁定關閉，限流改疊在 #1254 的檔案上。

## 做什麼
- NpcUtilityAI.ts：新增 NPC_HIGH_WEIGHT_THRESHOLD（暫定 0.5）與 NpcInteractionLimiter.tryClaim(windowId, generalId, score)。
- tests/NpcUtilityAI.test.ts：新增一條限流測試（同窗同將擋第二則、不同將與低權重不受限、換窗重算）。

## 暫定決策
1. 沿用 #1254 的檔名 NpcUtilityAI.ts，不另開大小寫不同的新檔。
2. 高權重門檻 0.5 暫定；#1254 目前所有權重都是 1，也就是每則都算高權重，接線前要先決定門檻或權重表。
3. 本卡只加純邏輯，不接呼叫端，所以不改變目前的離線互動行為。

## 不在範圍
- 把限流接到離線互動挑選流程（待門檻與權重定案）。
- 好感與情緒修正（規格 F-1 其餘因子）。

# [PROG-2-1440] 登入窗限流接上離線互動（NPC-05 續）

## 為什麼做
PROG-2-1379（#1254）已導入 F-1 評分，但規格 F-1 第 3 點「同一武將同一登入窗只允許 1 則高權重互動」沒有實作。原 PR #1259 與 #1254 重複，依 PM 裁定關閉，限流改疊在 #1254 的檔案上。PM 指示需接上呼叫端，不能只放純邏輯。

## 做什麼
- NpcUtilityAI.ts：NpcInteractionLimiter 提供 canClaim（只查）、claim（登記）、tryClaim（查並登記）；低權重永遠可以。
- NPC_HIGH_WEIGHT_THRESHOLD = 1（PM 暫定）：分數嚴格大於 1 才是高權重。
- OfflineInteractionEvents.ts：pickOfflineInteraction 新增選填的 limiter 與 weights。有 limiter 時，兩位武將在本窗都還能排高權重才進候選，選定後登記；weights 預設為 NPC_RELATION_WEIGHTS。
- GameSession.ts：runOfflineInteraction 傳入 session 內的 limiter（記憶體內，不寫入存檔）。
- 測試：tests/NpcUtilityAI.test.ts，新增 3 條（門檻邊界、挑選接上限流且換窗重算、預設權重結果與不帶限流相同）。

## 暫定決策
1. 高權重門檻 1（PM 裁定）：預設權重全為 1 時沒有互動被限流，行為不變。
2. 限流狀態不寫入存檔；讀檔後同一窗會重置。目前因權重為 1 沒有影響，若權重調高要再決定是否存檔。
3. weights 作為挑選的注入參數，方便測試，正式值仍是 NPC_RELATION_WEIGHTS。

## 不在範圍
- 限流狀態存檔。
- 好感與情緒修正（規格 F-1 其餘因子）。
- 把挑選結果做成對話 UI（NPC-07/08）。

# [PROG-2-1443] 七天玩家體驗歷程與關鍵留存觸發點（RET-12）

## 為什麼做
留存系統 §K 規定新玩家前 7 天的關鍵留存觸發點（Day 1 晚日報、Day 2 子嗣誕生、Day 4 Is_Daqi 批語、Day 7 三代血統樹）。現況沒有任何程式記錄這些節點。

## 做什麼
- `SevenDayJourney.ts`（純邏輯）：
  - 第 1 天＝首次登入日（UTC+8），第 8 天起歷程結束。
  - 觸發點表 `SEVEN_DAY_TRIGGERS` 為資料，改數值只改這張表；每個觸發點在「歷程第 N 天以後」且事實成立時寫一次（漏登會晚到，不重複）。
  - 事實：日報已存在、有子嗣誕生、有 Is_Daqi 子嗣、三代（子嗣的父或母是另一位子嗣）。
- `GameSession.recordLoginAt`：在日報更新後推進歷程，觸發點寫成 `SYSTEM` 類日誌（優先度 60）。
- 存檔：新增選填欄位 `sevenDayJourney`（只在有首次登入日時寫入；舊檔缺欄位視為從未登入）；版號不升。
- 新局重設；讀檔走正規化。

## 不做什麼
- 不做 UI；觸發點以日誌條目呈現，由既有日誌畫面顯示。
- 無課／課長軌判定規則規格未定義，預設為無課（暫定）；課長軌專屬內容待企劃。
- 不接戰鬥、不改數值。

## 驗收
- 純邏輯測試：日數邊界、觸發一次、漏登補發、事實未成立不觸發、三代判定、正規化。
- 流程測試：真實 `recordLoginAt` 寫入日誌；存檔 JSON 往返後不重寫、子嗣紀錄保留、Day 4 仍可觸發；舊檔相容。
- 全套測試 ALL PASS；`tsc -p tsconfig.test.json --noEmit` 錯誤數 0；`compute-gate.js --profile standard --agent-feedback` 全綠。

# [PROG-2-1445] 日誌與晨報畫面接上 i18n 字串（JRN-07 UI 接線）

## 為什麼做
PROG-2-1442 已把規格 §H、§G 的字串放進三語 i18n，但畫面上的標題與空狀態仍是寫死的中文，切語系不會變。

## 做什麼
- 新增 `ui/core/JournalTexts.ts`：`journalText(lookup, key)`，有譯文用譯文，缺 key 或空值退回 zh-TW 預設（與 `withBreedFallback` 同一模式）。
- `JournalHubController`、`GeneralJournalController` 增加可選的 `lookup` 依賴；未提供時用 zh-TW 預設。
- 接上的 key：
  - 晨報標題 `UI_MORNING_REPORT_TITLE`、晨報空狀態 `UI_MORNING_REPORT_EMPTY`
  - 派遣板標題 `UI_DISPATCH_BOARD_TITLE`
  - 日誌標題 `UI_JOURNAL_TITLE`（無武將時）、日誌空狀態 `UI_JOURNAL_EMPTY`（有武將無紀錄時）
- `LobbyScene` 兩處建構傳入 `services().i18n.t`。
- 修正 PROG-2-1442：規格 §H 用「」標示引文，不是畫面字，但我把它寫進了 zh-TW 與 ja 譯文。已去掉外層「」，並在測試鎖住。

## 畫面文字的變化（照規格 §H）
- 晨報標題：「晨報」→「晨報摘要」
- 派遣板標題：「派遣板」→「派遣整備」
- 晨報空狀態：「今日尚無晨報」→「昨夜風平浪靜，暫無要事。」
- 日誌空狀態：「尚無日誌記錄」→「近日尚無值得記錄之事。」

## 不做什麼
- 不接 UI_OFFLINE_INTERACTION_TITLE、UI_OFFLINE_BATTLE_SNAPSHOT：畫面上目前沒有對應位置。
- 不接 UI_DISPATCH_COMPLETE、UI_DISPATCH_QUALITY 與五句劇本文案：它們是核心模組寫入日誌摘要的文字（純邏輯，不依賴 i18n），要在顯示端再翻譯，另案。
- zh-CN 不補（與前卡相同）。

## 驗收
- 新測試（查表、預設退回、zh-TW 與預設一致、兩個控制器走查表）與引號測試通過；全套 ALL PASS。
- `tsc -p tsconfig.test.json --noEmit` 錯誤數 0；`compute-gate.js --profile standard --agent-feedback` 全綠。

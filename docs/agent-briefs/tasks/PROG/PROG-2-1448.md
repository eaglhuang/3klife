# [PROG-2-1448] 日誌劇本句改回傳查表 key＋參數（JRN-07 後續）

## 為什麼做
PM 同意讓核心改成回傳 key＋參數（#1297 只把譯文查表接到日誌畫面，但派遣完成、晨報條目的句子仍是核心組好的 zh-TW 字串，切語系不會變）。

## 做什麼
- `JournalEntry` 新增選填 `summaryKey`、`summaryArgs`。寫入與複製時驗證：key 須為非空字串，參數須全為字串；非法參數整組省略，key 合法時仍保留。`summary` 永遠是 zh-TW 原句，當作退回值。
- 派遣完成：寫入 `UI_JOURNAL_STORY_DISPATCH_DONE`，參數為武將名、任務名、獎勵文字（對應 {0}{1}{2}）。
- 晨報條目沿用日誌的 key 與參數；讀檔正規化保留合法值。
- `journalSummaryText(lookup, item)`：有 key 且譯文非空、不等於 key 時用譯文，否則退回 `summary`。武將日誌與晨報派遣板改用它。
- `JournalTextLookup` 改為 `(key, ...args)`，LobbyScene 的查表會帶參數。

## 不做什麼
- 離線互動開場（`OFFLINE_INTERACTION_OPENING`）：後面會接 zh-TW 的 `detail`，單換開頭會中英混排。需要先 key 化 detail，另卡。
- 日報面板（`DailyReportController`）：該檔的 lookup 參數在 RET-06（#1300）內，待 #1300 合併後另卡。
- `UI_JOURNAL_STORY_OFFLINE_SUPPORT`、`UI_JOURNAL_STORY_LOG_REVIEW`：目前沒有核心來源。
- 存檔版號不升；新欄位皆選填，舊存檔讀回後照常用 summary 顯示。

## 驗收
- `tests/JournalSummaryKey.test.ts`：合法與非法的 key／參數寫入、複製、晨報沿用、讀檔正規化、查表退回規則、派遣參數順序。
- `tests/JournalSummaryKeyPersistence.test.ts`：真實 `GameSession` 寫入帶 key 的條目，經 JSON 往返後 key、參數與 summary 都保留；讀檔後再寫入不改寫舊條目；舊條目（無 key）照常。
- 全套 ALL PASS；`tsc -p tsconfig.test.json --noEmit` 與 `tsc -p tsconfig.cc-check.json --noEmit` 錯誤數 0。
- cc 實機驗收（日誌與晨報畫面的文字）待 Codex，標 in-review。

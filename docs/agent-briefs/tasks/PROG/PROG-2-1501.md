# [PROG-2-1501] 日報插槽引擎 key 化（復仇、代勞、切磋、特訓、八卦）

## 為什麼做
#1300 與 #1500 讓登入面板的標題、晨報走查表，但日報各則的行為與結果仍是核心組好的 zh-TW 字串。這是 RET-06 留下的尾巴，範圍在日報插槽的五類。

## 做什麼
- `DailyNewsEngine`：`NarrativeSlot` 新增選填 `actionKey／actionArgs／resultKey／resultArgs`；五類的句型集中在 `DAILY_NEWS_TEMPLATE`，組出的 zh-TW 原文與原本逐字相同。
- `DAILY_NEWS_EMOTION_KEY`：五類情緒的查表 key。
- `normalizeDailyNewsState`：保留合法的 key 與字串參數，非法參數整組省略。
- `DailyReportController`：未讀日報各則逐條查表（情緒、行為、結果各自退回 zh-TW），格式與核心 `dailyNewsToastLines` 相同。
- 三語新增 15 個 `UI_DAILY_NEWS_*` key。

## 不做什麼
- 代勞的任務名、特訓的屬性名、切磋與八卦的對象名仍是 zh-TW 資料字串，需要資料名稱表另卡。
- 安慰（COMFORT）與購物（SHOPPING）未 key 化。
- 大廳 toast（`dailyNewsToastLines`）維持 zh-TW，本卡只接登入面板。

## 驗收
- `tests/DailyNewsKeys.test.ts`：句型與參數、安慰與購物不帶 key、zh-TW 與核心模板一致、三語 key 與佔位符數量、讀檔正規化、面板查表與退回、無查表時與核心 toast 行文字相同、GameSession 登入→存讀檔→面板取譯文。
- 全套 ALL PASS；`tsc -p tsconfig.test.json --noEmit` 與 `tsc -p tsconfig.cc-check.json --noEmit` 錯誤數 0。
- cc 實機驗收（登入面板的日報文字）待 Codex，標 in-review。

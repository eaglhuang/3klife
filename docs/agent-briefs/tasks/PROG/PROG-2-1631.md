# PROG-2-1631 HTML→UCUF 轉換管線全面體檢

背景：UCUF 原為把 Claude Design 產出的 HTML 轉成 Cocos UI，經多次改版而混亂。本卡盤點工具鏈與規格使用率，產出問題清單與單一路徑提案，並拆出後續卡。

## 盤點數字（2026-10-31，origin/master）
- tools_node 共 278 支，UCUF／HTML 相關 53 支，其中 12 支無任何引用（孤兒）
- ui-spec 共 595 個 JSON、約 5.9MB
- 規格引用率（被 assets/scripts 或其他規格引用）：layouts 106/125、skins 86/92、screens 109/229、fragments 43/92、recipes 2/10、templates 3/4、contracts 1/21、proof 1/4
- 程式直接以 id 掛載的 screen 71 個；91 個 screen 為 layout+skin 三檔一畫面；82 個 layout 被 screen 引用，其中 9 個被多個 screen 共用

## 問題清單（依嚴重度）
1. **嚴重：轉換副產品寫進遊戲資源目錄。** 127 個 .r-guard／.visual-review／.logic-inventory／.bundle-suggestion／.css-coverage／.optimizer-scan 等 JSON（約 524KB）放在 assets/resources/ui-spec，會被打進遊戲包；screens 未引用的 120 個多數就是這些。→ PROG-2-1638
2. **高：兩條產生路徑並存。** HTML 工作流（html-to-ucuf skill 正式路徑）與 參考圖→MCQ→recipe→compile-recipe-to-* 路徑（ui-vibe-pipeline 系列 skill）同時被描述為主流程；recipe 只剩 2/10 被用，新 agent 容易走錯路。→ PROG-2-1640
3. **中：孤兒工具與死規格。** 12 支工具（含 gen-ui-v3/v4/v5 三代 crop 腳本）、contracts 20/21、recipes 8/10、skins 6、proof 3 未被引用。→ PROG-2-1639
4. **中：對齊邏輯分散（已處理）。** 尺寸雙來源、多次重算、事後搬 __safeArea、字數估寬 → PROG-2-1628／1629／1636／1630 已合併。
5. **低：技術文件與實作不符（已處理）。** → PROG-2-1632 已合併。

## 單一路徑提案
HTML 來源包（含 ui-design-tokens.json、colors_and_type.css）→ dom-to-ui-json → run-html-to-ucuf-workflow（優化、per-tab fragment、規則守衛、Cocos 最終比對）→ 只把執行期需要的 layout／skin／screen／fragment 同步到 assets/resources/ui-spec，其餘證據寫 artifacts。沒有 HTML 時，recipe／MCQ 只負責先產 HTML，不直接產 Cocos 規格。

三檔一畫面（screen 指向 layout＋skin）**保留不合併**：layout 共用與換皮都依賴這個分離，合併會讓 9 個共用 layout 複製成多份。

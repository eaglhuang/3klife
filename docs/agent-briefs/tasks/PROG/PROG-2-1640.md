# PROG-2-1640 UCUF 產生路徑收斂為單一 HTML 工作流

目前並存兩條產生路徑：
1. HTML 來源包 → dom-to-ui-json → run-html-to-ucuf-workflow（html-to-ucuf skill 指定的正式路徑）
2. 參考圖 → proof → MCQ → recipe → compile-recipe-to-screen-spec / panel-scaffold（ui-vibe-pipeline 系列 skill）

recipes 10 個只有 2 個被引用，第 2 條路實際上已少用，但 skill 仍把它當主流程，造成新 agent 走錯路。

## 範圍
- 定案：HTML 工作流為唯一產生 layout/skin/screen 的路徑；recipe 路徑改為「沒有 HTML 時先產 HTML」的前置，或退役
- 同步改寫 ui-vibe-pipeline、ui-spec-scaffold 等 skill 的入口說明
- 三檔一畫面（screen→layout+skin）保留：9 個 layout 被多個 screen 共用、skin 換皮需要，不合併

## 驗收
- skill 文件只指一條路；舊路徑工具標 deprecated 或刪除

# PROG-2-1997 商業化純邏輯接口（EQP-11／OFC-12）

使用者裁決第 19 項：商業功能「單日免費 1 次＋超額 60 玉璧」，只做純邏輯接口，不接支付 SDK，不動 UI 與 LobbyScene。

## 交付

- core/systems/PaidFeatureQuota.ts：previewPaidFeatureUse（看價）、consumePaidFeatureUse（用一次，回 gemsSpent）、normalizePaidFeatureQuota（讀檔正規化）。
  - 登入日沿用 LoginStreak.loginDayOf（UTC+8）；跨日歸零；時鐘回撥不重置（同 DailyFreeEnroll 高水位做法）。
  - 玉璧由呼叫端持有與扣款；玉璧不足回 insufficient-gems，狀態不變。
  - 各功能額度獨立，功能識別碼為字串。
- tests/PaidFeatureQuota.test.ts

## 沿用與不沿用

- 沿用：DailyFreeEnroll 的登入日高水位概念、TournamentLocal.dailyFreeEntries 的「每日免費 N 次＋超額付費」概念。
- 沒有直接重用 TournamentLocal 的 entriesToday：它綁競賽期與日序，這裡要的是依功能分開的通用計數器。

## 暫定（回報）

- 功能識別碼 EQP_AUTO_ORGANIZE、OFC_REFRESH 是暫定名稱，實際對應哪些功能由接線方決定。
- 沒有接進 GameSession 與存檔（只改 core 與 tests）；存檔欄位與呼叫端另卡。

## 未涵蓋（不在第 19 項裁決內，未做）

- EQP-11：欄位解鎖（倉庫擴容已有 WarehouseCapacity 與玉璧文案，但價格階梯未見於裁決）、強化材料消耗。
- OFC-12：月卡官職經驗加成倍率、高階試用 buff 與到期不改正式階位、刷新券與外交加速包的個別數值。
- 倉庫擴容的玉璧價格、月卡倍率等數值查不到，沒有自己編。

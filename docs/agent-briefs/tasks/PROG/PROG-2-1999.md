# PROG-2-1999 教官卡被動接進培育公式

PROG-2-2096 把荀彧（VITALITY_SAVE 0.2）、郭嘉（TP_Bonus 0.3）寫進 mentor-support-cards.json，但 MentorArchetype 只拿來分類，帶著卡培育時沒有任何效果。本卡把兩項被動接進培育公式。

## 交付

- core/systems/MentorPassiveSavings.ts（新）：`passiveSavingsOfSupport`（依 Min_Star 解鎖、同類相加）、`totalVitalitySave`、`totalTacticTpDiscount`（多張卡相加、封頂 `MENTOR_PASSIVE_SAVE_CAP`）、`applyPassiveSave`（乘算）。
- core/systems/NurtureSystem.ts：`TrainingMentor` 加選填 `vitalitySave` / `tacticTpDiscount`；`mentorFromCard` 依星等寫入；`executeRound` 訓練精力消耗套體力減免（亂數消耗順序不變，休息不受影響）。
- core/managers/GameSession.ts：`learnTactic` 的戰法 TP 成本套 TP 折扣（畢業兌換戰法）。
- tests/MentorPassiveSavings.test.ts：鎖住數值（沒帶卡不變、0.2 → 15→12／25→20、相加封頂、Min_Star、GameSession 學戰法 30→21 門檻 42）。

## 暫定（裁決未寫）

- 乘算：消耗 ×（1 − 減免）。
- 多張卡減免相加；同類總減免封頂 0.6（規格 6.1 範例「TP 折扣 60%」）。
- 體力消耗減免後仍四捨五入（15 × 0.7 = 10.5 → 11，可降到 0）；TP 成本減免後無條件進位（沿用 learnTactic 的 ceil），綠因子折扣先套、教官折扣後套。
- TP_Bonus 解讀為「畢業兌換戰法的 TP 消耗折扣」（與 MentorArchetype 的「戰法 TP 折扣」一致）；不是培育中的 TP 獲得量（那條仍是 `tpBonus`／computeTpGain，未動）。戰鬥中施放戰法的 TP 消耗（TacticCastTpCost）也沒動。

# PROG-2-2110 留存伺服端統計欄位（RET-13）

留存系統.md §I「Server 端」列了 player 留存統計表（Player_ID / Total_Illustrations / Legacy_Count / Last_Login / Consecutive_Days / Daily_News_Count）。WBS RET-13 驗收為「伺服端保存並回傳留存統計，並有測試」，目前只有客端本機存檔欄位（Legacy_Count 等），伺服端沒有表。

## 交付

- server/schema/011_retention_stats.sql：`player_retention_stats` 表（僅定義、未部署）。
- server/schema/ret13-retention-stats-row.ts：列型別、`validateRetentionStatsRow`、`buildRetentionStatsRow`（壞值歸 0）、`mergeRetentionStatsRows`（只增不減）、`retentionStatsValidator`（給記憶體表）。
- tests/ServerSchemaRet13.test.ts：合法列、各欄位錯誤、時鐘容差、組列、合併、記憶體表往返、DDL 欄位與型別一致。

## 暫定（規格只列欄位）

- 三個累計欄位（插畫數、世代成就次數、日報累計數）合併取較大值；Last_Login 與 Consecutive_Days 取較新那筆一起走。
- Last_Login 超前伺服端時間 5 分鐘以上驗證不過（沿用 BAG-11 的容差）。
- 計數上限 INT 2147483647。

## 未做（要回報）

- 沒有掛進實際 HTTP 路由（sync 協議的 patch 白名單 sync06 與留存統計怎麼對接規格未寫，且 server/src 屬同步協議線），本卡只到「列定義＋驗證＋合併＋記憶體表往返」，與 BAG-11、OFC-10 同層級。
- 客端 Total_Illustrations（總解鎖插畫數）與 Consecutive_Days 的客端來源欄位尚未在 PlayerSaveService 存在，組列時由呼叫端傳值。

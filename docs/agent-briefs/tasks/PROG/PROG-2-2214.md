# 集中大廳返回路由樞紐與轉蛋功能修復

針對使用者於 2026-11-10 提出之兩大關鍵問題：
1. **集中大廳返回路由（Single Source of Truth）**：各子系統返回時會誤退回舊大廳底層，需集中至 `returnToLobbyHall()` 確保一律回歸幕府主政廳。
2. **轉蛋頁面（Gacha / 招募）功能損壞排查與修復**：修復轉蛋按鈕點擊無反應、池位載入、或是流程 coordination 異常。

## 修正範圍
1. **大廳返回路由集中管理**：
   - 在 `LobbyScene` 定義統一的 `returnToLobbyHall()` 方法。
   - 盤點所有子面板的關閉/返回回呼（如 `GeneralList`、`GeneralDetail`、`Domestic`、`GachaMain`、`ShopMain`、`SortieSetup` 等），在返回時確保呼叫 `returnToLobbyHall()`，將 `LobbyHallHost` 置頂並刷新狀態。
2. **轉蛋（GachaMain）排查與修復**：
   - 檢查 `GachaFlowCoordinator`、`GachaActionBindings`、按鈕綁定與點擊響應。
   - 修復轉蛋介面各功能與單抽/十連/票券/金幣招募。

## 驗收標準
- [ ] 任意子系統點擊返回，100% 穩定回到幕府大堂，不露出舊大廳。
- [ ] 轉蛋介面按鈕能正常響應、抽卡與結果展示正常運作。
- [ ] TypeScript 編譯 0 錯誤、驗收測試全數通過。

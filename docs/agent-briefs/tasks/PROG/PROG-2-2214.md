# 集中大廳返回路由樞紐與轉蛋功能修復

針對使用者於 2026-11-10 提出之兩大關鍵問題：
1. **集中大廳返回路由（Single Source of Truth）**：各子系統返回時會誤退回舊大廳底層，需集中至 `returnToLobbyHall()` 確保一律回歸幕府主政廳。
2. **轉蛋頁面（Gacha / 招募）功能損壞排查與修復**：修復轉蛋按鈕點擊無反應、池位載入、或是流程 coordination 異常。

## 修正範圍
1. **大廳返回路由集中管理**：
   - 在 `LobbyScene` 定義統一的 `returnToLobbyHall()` 樞紐方法。
   - 盤點所有子面板的關閉/返回回呼（如 `GachaReturnToLobby`、`ShopMain`、`RecruitHall`、`bloodlineMirror` 系列等），一律導向 `this.returnToLobbyHall()`，確保 100% 穩定回到幕府大堂。
2. **轉蛋（GachaMain）排查與修復**：
   - 修復 `UIPreviewBuilder.ts` 中 `shadowManager` 為 null 時的 `clearDetachedShadows` 與 `tokens` TypeError 崩潰，解除轉蛋與鏡像面板初始化中斷。
   - 升級 `GachaActionBindings.ts`：增加 `touch-end` 雙重事件響應保險，確保單抽、十連、票券、切池按鈕在觸控與滑鼠環境皆可正常觸發。
   - 實測單抽／十連召喚入冊、展示 `gacha-pull-result`、點擊返回卡池與返回政廳順暢閉環。

## 驗收標準
- [x] 任意子系統點擊返回，100% 穩定回到幕府大堂，不露出舊大廳。
- [x] 轉蛋介面按鈕能正常響應、抽卡與結果展示正常運作。
- [x] TypeScript 編譯 0 錯誤、全量驗收測試 100% 通過。

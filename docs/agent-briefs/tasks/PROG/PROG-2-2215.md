# 首戰退場、回合與 SP 一致性

## 根因
- HTML 匯入 HUD 的齒輪與「退」是 label/panel，沒有 Button 與事件；既有設定面板及撤退事件實際可用但入口斷線。
- HUD 的「SP 5/5」、充能說明與 READY 是設計稿常數，不讀 GeneralUnit；奧義按鈕快取也可能錯過初始化事件。
- 第二步只等 sp-ready，沒有回合事件；失敗沒有收起路徑。
- 部署後會排程自動結束回合，沒有失效 token，可能在手動結束後又推進；控制器單次雙方回合基線實測只加一，未發現其固定加二。增加重入及過期 callback 防護。
- 正常戰役只有主將／城池歸零或50回合上限；沒有小兵全滅就輸的規則，所以空城仍能磨很久。

## 修正
HUD入口開既有設定／撤退確認（設定面板三秒內再按撤退確認）；撤退先鎖 Finished，清除待結算，遲到的敵方 callback 不再推進。每次 refresh 從 controller.playerGeneral 發出真實 SP，HUD文字、填充與選單均讀同一事件，不足提示列當前／上限／需求。教學在回合完成後進第三步，任意勝負收起。部署自動回合排程被手動推進後作廢。

## 設計假設（須審閱）
只在 battleParams.tutorial 的首戰加入十二完整回合的教學時限，仍未分勝負則以撤退／敵勝結算，開場戰報明示；不改傷害、HP、SP、一般戰役50回合上限。這是讓流程可結束的暫定教學規則，不宣稱平衡或首戰保證獲勝。保留原季報、開場與獎勵設計，不改流程順序。小兵全滅不直接判敗，因仍可能重新部署。

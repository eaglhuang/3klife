# 線上首開黑畫面縮短：開場面板優先掛載

使用者回報線上試玩按「開始遊戲」後 45 秒畫面仍全黑，要求調查能否縮短。

## 調查
- 線上實測：按開始到開場旁白可見約 70 秒；按開始後 290 個請求 6.8MB（247 個 import JSON）。中位數 307ms／請求，同時進行的請求長時間只有 1 個。
- 原因：LobbyScene.start() 依序 `await` 約 60 個面板掛載，開場面板排在約第 41 個之後；頻寬不是瓶頸，是逐一往返的延遲疊加。

## 修正
- 新玩家或讀檔接回開場時（`shouldMountOpeningFirst`），語系字串與開場面板（宿命轉蛋、信件、第一幕、新手引導）最先掛，第一幕旁白立刻顯示；其餘面板之後照原順序掛。舊玩家順序不變。
- 後掛的面板會放在最上層，因此每掛一個就把正在顯示的開場面板拉回最上層（`_keepOpeningOnTop`、`LobbyOpeningPanels.activeHostNodes`）。
- 宿命轉蛋要用武將資料：開場優先時一開始就並行預載武將資料（`_loadGenerals`，只載一次）；進轉蛋幕時若尚未載完，等資料到再開，不等整個大廳。
- 轉蛋鎖定時若其餘面板還沒掛完，顯示「幕府大堂整備中，請稍候……」提示，掛完自動開幕府大堂；新手引導等大廳掛完（`lobbyReady`）才出現，不會疊在空畫面上。
- 本卡疊在 PROG-2-2215（#2077）之上，兩者都改到同一段掛載順序。

## 驗證
- 單元：7424 → 7427 passed／3 skipped（新增 3 個）；測試 tsc 0；compute-gate standard。
- 網頁建置本機實測（模擬每請求 300ms 延遲、40Mbps）：按開始到旁白可見，改前 74.7 秒 → 改後約 6 秒（進 LobbyScene 後 5.5 秒）。
- 全程無頭走完：第一幕 → 信件 → 六名將 → 宿命轉蛋（31 秒）→ 鎖定後約 39 秒幕府大堂開啟，新手引導 1/3 在最上層；頁面錯誤 0。
- 大廳全部掛完的總時間不變（約 100 秒），但玩家在這段時間都在看開場，不再是黑畫面。

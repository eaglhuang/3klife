# Web 開始遊戲及戰場載入進度

## 根因
LoadingScene 原本雖有 preloadScene callback，只更新可能尚未掛載的 Cocos Label，不能涵蓋切入目標場景後的非同步初始化。BattleScene 又把整個 Canvas 設成 opacity=0，直到最後才打開；大廳則有數十個順序 await 掛載，期間無回饋。

## 修正範圍
無遊戲資源依賴的 Web DOM 底部狀態條（不阻擋遊戲點擊，避免干擾並行的開場先行工作），在 switchScene 當下即顯示，不被 Cocos Canvas 隱藏，也能跨場景保留。預載階段使用 director.preloadScene 真實完成數／總數。大廳掛載總量因條件分支不固定，以原 helper 實際完成的介面數＋原生不定進度條顯示，不捏造總數／百分比。戰鬥以七個真實初始化里程碑顯示階段進度。完成才移除；載入錯誤顯示重新載入選項，避免永久假進度。

未調整任何大廳面板順序、未平行化掛載、未改開場幕序；只在 start、共用 helper 與 ready 添加少量回報。無額外圖像、字型或套件；不更動原 Cocos Loading 動畫。

## 驗證及界線
新增7個state／DOM／接線測試；另跑既有MirrorLoadingRotation、LoadingTips相關案例。tsconfig.test、standard gate及編碼檢查提交前執行。這是Web專用補強；native保留原Cocos載入畫面。百分比是各階段完成量，不是剩餘秒數，也不宣稱已改善載入效能。大廳只計由共用helper建成的介面，不把非helper子系統偽裝為已量測進度。

## 待驗
Windows重新建置後測開始遊戲及出征：預載百分比→大廳已完成介面數／戰鬥七階段→實際畫面；錯誤重試；小螢幕文字與進度條可讀性；不得被 Canvas opacity 或場景釋放一起隱藏。

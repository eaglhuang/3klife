# [PROG-2-9037] 轉蛋右側資訊面板切池／切人物後疊層

## 問題
轉蛋畫面切換卡池（或重進轉蛋畫面）後，右側資訊面板（池名、副標、保底進度、機率格、餘額）新舊內容同時存在：標題兩個池名、保底「0/50」與「28/80」重疊、機率格數字重疊。

## 根因
1. `LobbyScene._setupGachaPoolCarousel` 每次進轉蛋都 new 一個 `GachaPoolSwitcher`，並以新的匿名閉包呼叫 `bindGachaActions`。`GachaActionBindings` 的 `node.off(event, handler, owner)` 對新閉包無效，於是上／下一池、單抽等按鈕的監聽器會累積。一次點擊會同時觸發多個舊 switcher，各自持有不同的 `_index`，各自把不同池的右側片段掛上 `RightPanel`。
2. `UIScreenPreviewHost._switchPreviewSlot` 不序列化：連續切換時，前一次的載入尚未完成，後一次的 destroy 與 build 交錯，兩份片段都會被 append 到插槽。

## 修正
- `GachaPoolSwitcher` 新增 `cancel()`，使舊 switcher 的在途切換失效。
- `LobbyScene` 只在 binder 改變（畫面重建）時才建立 switcher 並綁定按鈕；同一畫面再進入時重用既有 switcher，只 `show(keepIndex)`。
- `UIScreenPreviewHost._switchPreviewSlot` 改經 `LazySlotSerialQueue` 序列化：同一插槽一次只跑一個切換，且只有最後一次請求會真正建置（跳過中間過期的片段，省記憶體）。

## 驗收
- tests/GachaPoolSwitcher.test.ts 新增：舊 switcher cancel 後不再掛片段；連點切池只掛最後一池。
- tests/LazySlotSerialQueue.test.ts：序列化、過期請求略過、同插槽不重疊。
- 7456 編輯器預覽切換四池與人物多次後，右側無疊字，附截圖。
- compute-gate standard 12/12、tsc 0 錯誤、run-cli ALL PASS。

## 問題
驗證人員每次要走 登入 -> 開場 -> 大廳 -> 出征才能看到戰場，耗時 1～4 分鐘，且大廳預建 44 個介面很吃 CPU。

## 做法
- 網址帶 `?qaBattle=1`，LoginScene 啟動後（不掛標題、不進大廳）驗證參數並呼叫 `services().scene.switchScene(SceneName.Battle, IBattleEntryParams)`，與大廳出征同一個交接點。
- 純邏輯在 `core/systems/QaBattleEntry.ts`；執行端 `ui/scenes/QaBattleEntryRunner.ts`；不合法時照常掛標題並在畫面顯示紅字錯誤。
- 不讀寫玩家存檔：`ServiceLoader.useEphemeralStorage()` 把存檔後端換成記憶體、名冊改記憶體（驗證通過才切換）。
- 戰場端只加可選欄位：`IBattleEntryParams.enemyDeployTroops`、`entrySource: 'qa'`；BattleScene 兩處最小改動，BattleController 新增 `overrideEnemyDeployTroops`。

## 驗證
- 新增 tests/QaBattleEntry.test.ts（參數解析與驗證純函式）。
- compute-gate standard、tsc、tests/run-cli.ts。

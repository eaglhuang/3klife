## 開單原因
使用者回報線上試玩版非常卡，Chrome 吃到 50% CPU。實測線上版大廳 FPS 4～20、腳本佔 56～85%。
熱點是 `PlayerRosterService.getAll()`（每次 JSON 深拷貝整份名冊）與 `GameSession._mindContext`。

## 根因
大廳每 5 秒重算出場武將（`LobbyScene._buildHallCast`）：
- 每位武將呼叫 `volunteerTaskFor` → 重算全部任務牆 → 任務服務對每個任務呼叫 `volunteerIdsFor`。
- `volunteerIdsFor` 再對每位武將查 `hallStageProfile` 與 `_mindContext`，每次都深拷貝整份名冊。
- 結果是名冊被深拷貝上萬次，武將越多越慢。

## 修法
1. `RosterStore` 加選用的 `version()`；`PlayerRosterService` 與 `InMemoryRosterStore` 寫入時遞增版本號。
2. `GameSession._rosterRead()`：依版本號快取唯讀快照，給 `_mindContext`、`hallStageProfile`、`volunteerIdsFor`、`missionGeneralFacts` 這些只讀路徑使用。
3. `HallBoardPanelController.volunteerTaskLookup()`：任務牆一次算好再逐位查，`_buildHallCast` 改用它。

## 驗收
- 本機建置帶效能探針跑試玩流程，大廳腳本佔比與 FPS 前後對照。
- tsc 測試設定 0 錯、run-cli 單元測試、compute-gate standard 通過。

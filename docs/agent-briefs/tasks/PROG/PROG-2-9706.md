## 開單原因
`SpineUnitOverlay.load()` 每次部署都 new Node + addComponent(sp.Skeleton)（帶頭者加 squad 隊員），移除時 destroy。骨架資料與貼圖本來就共用，部署與陣亡密集時造成建立銷毀的卡頓與 GC，手機效能優先。風險：被打過的單位閃白沒還原就回收，下次拿出來殘留顏色。

## 修改
1. `SpineGeneralOverlay.ts`：新增 `nodePool: Map<骨架路徑, Node[]>`，每路徑上限 `SPINE_UNIT_POOL_MAX_PER_PATH = 24`，超過直接銷毀。
2. `remove()` 改為回收：節點保留在 uiRoot 下 `active=false`；`clear()`（UnitRenderer.onDestroy 呼叫）整池銷毀，不跨場景殘留。單挑進行中的 `pendingRemovals` 邏輯不變。
3. 還原 `resetNode()`：u_flash 歸零（寫 `_materialCache` 全部實例）、skeleton.color 白、timeScale 1、clearTracks、setToSetupPose、setSkin('default')、scale／position 歸位；回收與取出各做一次。
4. 取出時節點已失效（父節點被銷毀）就丟棄改新建；閃白材質 callback 對已移除單位不再動作，避免誤改被重用節點。
5. `tests/cc.mock.ts` 補 `sp` 型別替身與 `Vec4.set`；`pickAttackClip` 呼叫改用現成的 `has`（型別更嚴時 runtime 可能為 undefined，行為不變）。

## 驗收
- `tests/SpineUnitPool.test.ts` 4 項：被打閃白（強度大於 0）後 remove，同 path 新單位拿到同一節點且 u_flash 為 0、顏色白、造型預設、active 正確；小隊隊員一起重用；池上限生效；clear 後池空且節點全銷毀，失效節點被丟棄。
- 單元測試 8977 全過、`tsc -p tsconfig.test.json` 0 錯。

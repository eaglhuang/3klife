## 開單原因
11/24～25 PROG-2-9953/9954/9955/9959/9962 被不同 Agent 重複開號。現有 task-id-guard 只看當前 worktree 的卡檔、tasks-atm 與 .task-locks，看不到 origin/master、其他 worktree、未合併分支／PR 與 commit 訊息。

## 完整描述
- 卡號占用來源擴大為：本地卡檔／tasks-atm／.task-locks、origin/master（自動 fetch）、本機與遠端未合併分支的 commit 訊息與檔名、`gh pr list --state all --search <prefix>` 的 PR、git common dir 共用預約表 `task-id-reservations.json`。
- 共用預約表以 `wx` lockfile 原子 check-and-insert，持有者以 agent + worktree 區分，TTL 168 小時，卡號落地 master 後自動清除；open 狀態開卡後仍保留共用預約，開卡失敗才釋放。
- 指定卡號撞號時：`task-lock.js reserve <task-id>` 直接改保留下一個可用卡號；程式錯誤 `TASK_ID_COLLISION` 附 `suggestedTaskId`；opener 錯誤訊息印出下一個可用卡號。
- 規則參數集中於 `tools_node/lib/task-id-allocation-policy.json`；gh 不可用或離線時降級為警告。

## 如何驗證
1. 預約時比對 origin/master、開著與近期的 PR（gh pr list --state all）、未合併分支與 commit 訊息、本機所有 worktree 共用預約表
1. 預約表以原子寫入（wx lockfile）並有 TTL
1. 指定卡號撞號時回傳下一個可用卡號（broker ticket），不只拒絕
1. docs/agent-briefs/Readme.md 鎖卡流程寫入新流程
1. 單元測試覆蓋遠端占用、共用預約、撞號建議

## 建議作法
- 開卡前：`node tools_node/task-lock.js reserve PROG-2 <AgentName>` 或 `task-card-opener --next-id-prefix PROG-2`。

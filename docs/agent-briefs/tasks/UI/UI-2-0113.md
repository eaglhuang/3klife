## 開單原因
轉蛋主頁 gacha-preview-main 的 BannerCharacterArt 目前固定綁關羽。改為依當前卡池的有效候選武將動態選擇人物立繪，並支援預覽指定角色或固定 seed，讓 QA 能穩定檢視。

## 完整描述
- 轉蛋主頁人物立繪動態綁定與選擇邏輯。
- 同步更新任務卡、UI task shard/manifest 與協作索引。
- focused 驗證結果；預覽截圖或具體 runtime blocker 紀錄。

## 如何驗證
1. 主頁 BannerCharacterArt 依卡池候選武將選擇有效 *_portrait SpriteFrame，不再只固定顯示關羽。
1. 支援預覽指定武將或 deterministic seed；人物名稱、卡池狀態與人物立繪一致。
1. 至少能用趙雲立繪呈現主頁預覽；大喬在其正式資產可用時可納入輪替。
1. 缺少或無效立繪時回退現有關羽預設，不影響抽卡互動或十連結果。
1. 新增候選選擇與立繪路徑解析的 focused test/validator，並在預覽環境可用時保留 runtime 截圖證據。

## 範圍與限制

- 修改轉蛋主頁預覽的 banner 人物選擇、立繪載入與人物標籤，來源限於正式卡池候選名單。
- 每次進入預覽隨機選擇有可用立繪的候選人物；可用 previewVariant 指定人物供穩定 QA。
- 沒有可用立繪時保留關羽預設圖；不改抽卡機率、消耗、抽卡結果頁或人物資料真相。
- 預計檔案： assets/scripts/ui/scenes/LoadingScene.ts、assets/scripts/ui/core/GachaPreviewStateRoute.ts、tools_node/capture-ui-screens.js、tests/GachaPreviewStateRoute.test.ts、相關 UI task/manifest/index 檔案與 doc-id registry。

## 實作步驟

1. 由預覽狀態解析名將池／紅顏池，取得真實卡池候選名單。
2. 隨機排列候選並優先載入 sprites/generals/{id}_portrait；指定 preview id 時先嘗試該人。
3. 圖片載入成功後同步更新人物圖、姓名與稱號／稀有度標籤；缺圖時保留預設人物。
4. 加入選擇／路徑 focused tests，並新增趙雲的穩定預覽案例。
5. 在可用的真實預覽環境補畫面證據；環境不可用時紀錄具體原因與已完成的靜態驗證。

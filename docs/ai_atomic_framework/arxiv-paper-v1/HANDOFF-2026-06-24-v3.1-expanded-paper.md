## 4. 重要論文主線

核心定位：

ATM 不是 Git / PR merge 替代品，也不是跨電腦 distributed locking。ATM 處理的是同一受控 filesystem / worktree / service domain 內，多個 LLM agent 在寫入共享 repository 前的 admission decision。

核心技術思路：

1. 先把模糊的 file-level write intent 分解成可治理 atom。
2. 透過 atom map 對齊 owner、validator、dependency、CID、hash lock。
3. 覆蓋不足時使用 virtual atom 補足未原子化區段的衝突判斷。
4. 透過 CID broker 做 progressive admission：
   file overlap -> known atom -> atom map surface -> virtual atom -> ConflictKey -> verdict。
5. 安全案例進 deterministic composer / neutral steward；不安全或不可證明安全時 fail closed。

重要邊界：

- AgenticFlict 只能當 motivation，不能宣稱 ATM 已解決跨 clone / PR merge conflict。
- npc-brain 三週採用只能支撐 governance recoverability / atomization / validator path，不能單獨支撐 same-file parallel admission。
- POS2 是 same-file bounded-region 正向 field evidence 的核心。
- B-12 是 late enforcement / admission boundary 的誠實負向案例。
- 12-scenario 是 coverage design，不是 12/12 deterministic evidence 已全部完成；目前 deterministic runner MVP 主要是 B-02、B-08、B-13。

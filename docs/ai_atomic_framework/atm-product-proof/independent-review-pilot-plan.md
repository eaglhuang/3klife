## 目的與不做事項

以第三方案「獨立對話、高推理、不同模型的唯讀審核員」降低方向偏移、無效重試及返工。
不先開發 Team SDK、自動訊息橋接、儀表板、command、gate 或 registry。
本輪不啟動模型、不花 API 費、不修改 ATM source、不發布套件。
正式啟用前需確認精確模型、工具權限及已核准成本上限；未確認不得開始計費。
審核员可反對隊長，並非只要求實作者服從。不同模型不等於客觀正確，更不構成獨立外部 benchmark。
低推理只適用已定位的小修補，高風險併發／根因工作依實測能力選擇，不固定交低推理。

## P1–P6 共用驗收原則

- P1 產品結果：安裝可用、正確行為與原始意圖優先；task closed 不代表交付。
- P2 減少複雜度：先移除無效操作，再合併重複、缩範圍、重用有效結果，最後才优化演算法。
- P3 完整成本：命令毫秒作診斷，固定工作端到端時間才是主要結果；不漏審核、等待、修正、整合。
- P4 可比較證據：固定版本、輸入、環境與計時範圍；不加總重疊區間，不將未知填零，不刪失敗樣本。
- P5 保留必要能力：不移除多 AI 並行、真衝突防護與可追溯足跡來換速度。
- P6 有界修正：一張卡一個結果；不擴大範圍或降低驗收，兩輪仍有爭議就裁決或停止。

每卡逐項列 PASS／FAIL／UNKNOWN／有理由的 N/A 與證據。不把文字勾選當執行測試。
卡片可證明實驗完成而假設失敗；不可因此標示產品优化成功。
審核成本本身受上述原則約束，不另要求為治理補文件。

## 時機、權限與訊息

只在短方案、第一個有效 patch／範圍變動／反覆 blocker、整合前三類事件審核。
輸入：原始目標、卡號、revision＋dirty diff digest、相關測試與直接證據連結；禁止只看實作者自述。
輸出：最多三項主要發現，每項包含目標ID、證據、影響、最小修正、重驗條件。
結論為通過／需修正／證據不足；風格偏好僅 advisory。
審核員無寫入、提交、結案或擴權能力。優先使用無工具文字對話；有工具時須技術上限制唯讀，不只提示詞宣告。
執行端接收回饋後只暫停受影響的實作／整合；獨立工作繼續。未接入工具的訊息不宣稱可以即時中斷。
超時不視為通過：缺必要驗證的整合等待裁決，其餘獨立工作可繼續。
版本改變後舊審核失效，僅重審受影響部分。
最多兩輪修正，仍有異議由 Owner 裁決，保留反對理由。
搜尋只從已知證據入口開始；來源未變不重跑相同 blocker，禁止全磁碟盲搜。

## 量測與試行判定

主要指標：固定任務從開始到可驗證交付的 wall-clock ms。
分項：實作、功能驗證、審核、等待、返工、整合；分類重疊單列或採互斥口徑，工具活動採區間聯集。
並行同時報 makespan 與全部 agent 工時，不把兩者混為一談。
命令／必經 gate：記錄次數、p50/p95、cold/warm 與環境，依頻率×單次成本和關鍵路徑排序；優先高秒數項。
複用既有 dashboard/metrics；只缺少特定欄位時先記錄在現有表，勿重造量測系統。
Token／USD 使用真實 usage／帳單；不可得為 unknown，不能以命令耗時代替人工工時。
審核 overhead＝審核＋因審核新增的等待與修正區間聯集／任務總 wall-clock；另報 agent 成本總量。
15% 是初始檢討線，不是品質自動否決；不可把必要 bug 修正時間全算審核浪費。
校準使用 5 偏移＋5 正常案例，至少抓到4個偏移且無硬誤擋才進 live；不以10例宣稱廣泛可靠。
Live 先3卡，不為湊樣本延伸新功能。因果比較須固定可比基線；不可比則只報描述性結果。
不可虚構避免的返工時間。少量樣本不足以宣稱顯著勝過單 agent 或 worktree＋Git。
raw logs／對話／量測檔留在 C:/Users/User/atm-benchmark-sink/，Git 僅放精簡結論與證據定位。

## 去留與交接

有具體修正價值且產品驗證不退步才考慮保留；頻繁誤擋、成本高或只有風格意見應減少觸發或停止。
只有試行證據支持，才提出 Team 自動化的另外決策；本計畫不授權該開發。
獨立審核不取代 deterministic tests、外部 benchmark、npm clean install 或 CI 長期驗證。
最終只交付一頁操作單與直接證據索引，不增加永久管理角色、狀態系統或治理程式碼。

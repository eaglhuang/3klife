# ATM 框架 100% 自我原子化計畫書

## 摘要

本計畫把 ATM framework 從「治理模型高度原子化」推進到「框架自身 production capability 也具備 100% atom/map ownership」。

這裡的 100% 不是把每個 function 都包成 `runAtm(...)`。那會犧牲可讀性，也會讓維護者把簡單 helper 看成黑箱。更好的定義是：

> 100% production capability 都有 atom/map ownership、spec、evidence、rollback、hash/version lineage；只有跨邊界、可重用、可替換、可審核的能力才強制用 readable ref 的 `runAtm` / `runAtmMap` 呼叫。

換句話說：治理覆蓋要 100%，執行入口要 100%，內部 helper 不硬包，但必須歸屬到某個 atom。

## 目前基線

- ATM framework 語意層已具備 atom spec、registry、map、behavior pack、evidence、rollback、hash lock 等 contract。
- production source 實體覆蓋仍偏低，主要 dogfood 仍集中在少數 atom/map。
- `packages/core` 與 `packages/cli` 是最高 ROI 區域，兩者承載 ATM 語意核心與所有 Agent 入口。
- 3KLife 保存中文推進脈絡，ATM repo 保持 product contract 與 machine-verifiable evidence。

## 目標

- 任一 production source path 都能追到 owner atom 或 owner map。
- 任一 public CLI command 都有 command atom 或 map spec。
- 任一新增 production source path 都會被 coverage guard 檢查。
- 任一 `runAtm` / `runAtmMap` 呼叫都必須使用語意 readable ref。
- 任一 atom/map 變更都有 evidence command、rollback instructions、provenance 與 version lineage。
- ATM 自己可以成為 adopter repo 最有說服力的 dogfood 範例。

## 非目標

- 不把每個小 helper function 都改成 `runAtm`。
- 不把中文任務歷史塞回 ATM framework repo。
- 不直接手改 `.atm/` runtime state。
- 不用一次巨型 commit 改 production logic；先建工具、量測、回填 governance artifacts，再做穩定邊界遷移。

## 100% 覆蓋定義

| 指標 | 完成定義 |
|---|---|
| Source ownership coverage | 100% production source path 被 atom/map 覆蓋，或有機器可讀 exclusion reason |
| Public command coverage | 100% `atm.mjs <command>` 有 command atom 或 command map |
| Runtime behavior coverage | core runtime contract、registry、generator、guard、release builder 都有 atom/map |
| Evidence coverage | 每顆 production atom 有 test/report/provenance/rollback evidence |
| Readable callsite coverage | 100% `runAtm` / `runAtmMap` 第一參數是 semantic readable ref |
| Exclusion coverage | generated、fixture、snapshot、release output 都有明確 exclusion reason |

## Map-first 架構

ATM 自我原子化應先建立高階 map，再批次補 atom。人類維護時先看 map，不直接翻 100+ 個 atom。

| Map | 覆蓋能力 |
|---|---|
| `atm.bootstrap-runtime-map` | next、welcome、doctor、bootstrap、ATMChart |
| `atm.cli-command-router-map` | CLI dispatch、command specs、help、JSON result |
| `atm.atom-registry-lifecycle-map` | registry load/save/sync、hash lock、catalog、provenance |
| `atm.atom-birth-map` | atom generator、id allocator、spec scaffold、test report |
| `atm.guard-validation-map` | guard、validate、test facade、encoding/mutation/git/readability |
| `atm.behavior-pack-map` | split、merge、compose、evolve、infect、atomize、expire |
| `atm.integration-pack-map` | Codex、Claude、Cursor、Copilot、Gemini adapters |
| `atm.release-build-map` | root-drop、onefile、package dist、version checks |
| `atm.language-adapter-map` | JS/Python adapter contracts |
| `atm.review-evidence-map` | human review、advisory、rollback proof、handoff |

## 最有效率執行路線

1. 先做 coverage inventory，知道缺口在哪。
2. 定義 exclusion policy，避免把 generated output 算成 debt。
3. 產生 dogfood score，讓進度有可比較的量化指標。
4. 加上 atomization-coverage guard，讓未來 Agent 不能再新增未歸屬 production source。
5. 以 bulk backfill 批次產生 atom spec / registry / evidence shell，不先改 production logic。
6. 建 top-level maps，讓大量 atom 對人類仍可讀。
7. 優先覆蓋 `packages/core` 與 `packages/cli`。
8. 補齊 validator/evidence pipeline 與 behavior pack。
9. 只在穩定邊界做 readable entrypoint dogfood migration。
10. 把 score 與 coverage guard 變成 release gate。

## 風險控制

| 風險 | 對策 |
|---|---|
| atom 太碎 | map-first，atom 對 capability，不對每個 function |
| `runAtm` 太多導致黑箱 | 只在 stable boundary dogfood，helper 用 ownership coverage |
| registry 膨脹難讀 | 產生 map catalog 與 score report |
| evidence 太重 | evidence 分級：smoke、standard、release |
| AI Agent 亂命名 | readable ref guard + id-like ref fail |
| bulk backfill 低品質 | generatedDraft 標記，review gate 後才升級 |
| 100% 變假數字 | exclusion reason 必須機器可讀 |

## Repo 邊界

- 本計畫書與任務卡保留在 3KLife。
- ATM repo 只接受正式 tooling、contract、guard、validator、atom/map spec 與 evidence。
- 任務完成時，3KLife 任務卡記錄人類推進脈絡；ATM repo commit 保留可驗證結果。

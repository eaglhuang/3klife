# 原子警察家族計畫書

## 0. 定位

本文件是 3KLife 內部 upstream roadmap / control plane，用來追蹤 AI-Atomic-Framework 的原子警察家族。它不是 protected public contract，也不把 3KLife 規則寫進 upstream。

M14 修訂後的基準語意：

- 「警察」至少必須能被 validation gate 或 named runtime scanner/facade 呼叫，並產生 machine-readable finding/report。
- 文件卡的 `status: done` 不等於 upstream runtime 完成；必須同看 `artifact_status`、`runtime_status`、`upstream_mutation_status`。
- 所有 finding 仍走 `ReviewAdvisory.machine-finding + metadata.policeFinding + HumanReviewDecision`，不新增第二套審核或獨立任務路由器。
- 每個 police/scanner/facade 預設只能輸出 report / finding / proposal draft；除 lifecycle 既有權限外，不得直接 mutate registry。

## 0.1 2026-05-19 M10/M11 修訂結論

M10/M11 的 Decomposition Police 與 Evolution Police 經 deterministic audit 後保留 runtime-active 判定，原因是 upstream 已有：

- `packages/core/src/source-inventory/source-inventory.ts`
- `packages/core/src/police/family.ts` 的 `runDecompositionPolice` / `runEvolutionPolice`
- `fixtures/police-family/decomposition/*`
- `fixtures/police-family/evolution/*`
- `scripts/validate-police-family.ts` 對 oversized source、recurrence、suppression、stale base、usage-only negative 的檢查

因此 M10/M11 不是只有 roadmap；它們已進入 validation gate。

## 0.2 2026-05-19 M12/M13 修訂結論

M14 原始假設曾要求 M12/M13 維持 planned；但本輪 audit 發現 upstream 已存在 named scanner、shared gate、fixtures 與 validator 覆蓋，因此不能降級成 missing runtime。

保留 runtime-active 判定的證據：

- `packages/core/src/police/family.ts` 的 `runPolymorphPolice`、`runRollbackPolice`
- `runEvidenceIntegrityGate`、`runReversibilityGate`、`runNoiseControlGate`
- `runRegistryContractDriftCheck`，且輸出由 Registry Consistency Police 承載
- `fixtures/police-family/polymorph/*`、`rollback/*`、`shared-gates/*`、`contract-drift/*`
- `scripts/validate-police-family.ts` 對 Polymorph / Rollback / shared gates / contract drift 的 positive + negative 檢查

M14 不新增 runtime；本輪只修補文件控制面的 metadata、critical path、readModel 語意與後續 hardening 任務。

## 1. 狀態標記

| 狀態 | 定義 |
|---|---|
| `implemented` | 已有獨立 runtime/plugin/scanner 或 validator 可直接執行 |
| `embedded` | 功能已存在，但散在 validator、map-curator、guidance、status-machine、lifecycle-police 等模組 |
| `fixture-only` | schema / fixture / 測試語意存在，但尚未有正式 runtime scanner |
| `missing runtime scanner` | 文件或 route 已提到，但缺少可重跑 scanner / report producer |
| `gate-active` | 已接入 validation gate，會被 `validate:standard` 或 `validate:full` 呼叫 |
| `productized-gate-active` | 已有 named scanner/facade、可產 `PoliceFamilyGateReport` / `PoliceFinding`、接入 validator profile、有 positive/negative fixtures |
| `shared-gate-active` | 非獨立 police family，但已作為共用 gate 接進 police family gate |
| `registry-consistency-extension-active` | 不是新 family；作為 Registry Consistency Police 的內部 extension 運作 |
| `planned` | 已開 roadmap/task/spec，但尚未進入 upstream runtime |

## 7. Rollback critical path

Rollback Police protects already active flows: map replacement, evolution, atomization, infect, expire, and retirement. Therefore APF-0043 / APF-0044 is a critical-path dependency before expanding Polymorph Police usage at scale.

Execution priority:

1. APF-0043 / APF-0044：先確保 reversibility / rollback proof envelope 守住 existing flows。
2. APF-0041 / APF-0042：再擴大 template / instance map / variant explosion governance。
3. APF-0045～0048：shared gates harden evidence, reversibility, noise, contract drift。
4. APF-0049～0050：orchestrator/profile/fixtures closure。

## 8.1 M15 Janitor apply planning lane

M15 是 janitor apply 的規劃與驗證前置線；它只補 APF finding 到 reviewable apply plan 的控制面，不執行 apply、不新增 24hr 自動修復、不改 registry runtime，也不把 scheduler runtime 視為已完成。

M15 分成兩段：

- Phase 0 contract：定義 finding -> apply plan 與 scheduler decision 的文件契約。
- Phase 1 contract implementation seed：把 Phase 0 契約轉成 schema / validator / fixture 或純函式 conflict model；仍禁止 apply execution 與 runtime scheduler loop。

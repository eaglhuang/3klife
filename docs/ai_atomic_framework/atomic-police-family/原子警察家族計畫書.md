# 原子警察家族計畫書

## 0. 定位

本文件是 3KLife 內部的 AI-Atomic-Framework upstream roadmap / control plane。它追蹤原子警察家族如何從概念、validator、embedded implementation，逐步走到 validation gate 與 named runtime scanner。

2026-05-19 之前的 M8 已把既有核心警察推到 `productized-gate-active`：Schema / Boundary / Dependency Graph / Registry Consistency / Lifecycle / Dedup / Demand / Quality / Map Integration / Atomization 都已有 gate report 或 named scanner/facade 的產品化方向。後續 M10/M11 補上 Decomposition Police 與 Evolution Police，處理大型功能拆解與 evidence-driven evolution。

本文維持一個原則：警察只能輸出 report / finding / proposal draft，不能建立第二套 approval workflow，也不能繞過 ReviewAdvisory、HumanReviewDecision 與 registry transition gate。

## 0.1 2026-05-19 M10 修訂結論

M10 新增兩個規劃中的警察 family：

1. `Decomposition Police`：根據「拆解大型功能優化原子map計畫書」掃描大型 source surface，例如超過可配置門檻的腳本或程式碼檔案。預設門檻可用 1000 LOC，但必須是 config，不是硬式 public contract。它只提出「此處應走 decomposition plan -> atomic map replacement」的 finding，不直接拆 code。
2. `Evolution Police`：根據 `Atom Evidence-Driven Evolution` 讀取 usage / quality / review / conversation / map evidence，偵測 atom 或 atomic map 是否需要 evolve、compose、merge、dedup-merge 或 sweep。Evidence 只能說明為什麼應該考慮演化，不能自行批准演化。

判定：兩者應獨立成 named police family，而不是硬塞進既有警察。原因是它們的 read model、trigger 與 noise-control 都不同。但它們必須和既有警察協作：Decomposition Police 將 finding 交給 Atomization / Map Integration Police；Evolution Police 將 finding 交給 Quality / Map Integration / ReviewAdvisory gate。

## 0.2 2026-05-19 M12 修訂結論

M12 再新增兩個 named police family 與四個 shared gate：

1. `Polymorph Police`：專門管理 polymorph template / instance map 的 template drift、instance propagation 與 variant explosion。短期可由 Dedup / Quality / Evolution 覆蓋，但若 polymorph 大量使用，必須獨立成 scanner，避免 template 與 instance 悄悄分裂。
2. `Rollback Police`：把 rollback / reversibility 升成一等守門語意。Map replacement、Evolution、Atomization、Decomposition proposal draft 都必須能被 Rollback Police 檢查是否有 rollback-proof、equivalence、retirement proof 或可逆性說明。
3. `Evidence Integrity Gate`：所有警察共用，檢查 evidence 是否 stale、missing、duplicate、untrusted。
4. `Reversibility Gate`：所有會產 proposal draft 的警察共用，檢查 rollback / equivalence / retirement proof。
5. `Noise Control Gate`：所有 advisory police 共用，處理 suppression、daily cap、confidence threshold、recurrence window。
6. `Contract Drift Check`：先併入 Registry Consistency Police，不獨立成警察；負責檢查 atom spec、implementation、test、registry metadata、map member contract 是否漂移。

判定：Polymorph / Rollback 應獨立成 named police；四個 shared gates 不應各自變成新警察，否則 family 會爆炸。它們應作為 orchestrator 前置/後置 gate，被所有 family 呼叫。

目前狀態：M10～M13 都是 `planned / missing runtime scanner` 或 `shared-gate-planned`。本輪只回寫 roadmap、spec 與 task cards，不宣稱 runtime 已產品化。

## 5. 新增警察採用判斷

### 5.1 Decomposition Police

應獨立。它不是 Atomization Police 的替代品，而是 Atomization Police 的上游偵測器。Atomization Police 關心 legacy route plan、dry-run patch、neutrality 與 host mutation guard；Decomposition Police 關心 source inventory、LOC threshold、entrypoint hint、candidate map replacement surface。

最小 trigger：`oversized-source-surface`。

### 5.2 Evolution Police

應獨立。Quality Police 可以判斷 regression，Map Integration Police 可以判斷 map propagation，但 Evidence-driven Evolution 需要跨 usage-feedback、quality-comparison、human-review-decision、conversation feedback、map-curator report 與 stale base version。這是一個 evidence orchestration scanner，不應塞進單一 quality 或 map scanner。

最小 trigger：`evidence-evolution-signal`、`map-evolution-signal`、`stale-evolution-draft`。

### 5.3 Polymorph Police

應獨立。Polymorph 不是單純 dedup，也不是單純 quality regression。它的核心風險是 template 與 instance 之間的治理關係變形：template drift、instance propagation 遺漏、variant explosion、polymorph dimension 無證據擴張、instance map 未同步。

最小 trigger：`template-drift`、`instance-propagation-missing`、`variant-explosion`、`polymorph-dimension-drift`。

### 5.4 Rollback Police

應獨立。Rollback / Reversibility 應是 proposal safety 的一等警察，而不是散落在各 scanner 的 notes。Map replacement、Evolution、Atomization、Decomposition、Polymorph 都會提出可能改動 registry/map/code 的 proposal draft；Rollback Police 負責確認「改了能不能退」。

最小 trigger：`rollback-proof-missing`、`irreversible-proposal`、`equivalence-proof-missing`、`retirement-proof-missing`、`rollback-scope-drift`。

## 6. Interface rule

- 新 police family 只能產 `PoliceFamilyGateReport` / `PoliceFinding` / proposal draft。
- Finding 預設進 `ReviewAdvisoryFinding.metadata.policeFinding`。
- 不新增第二套 approval workflow、獨立任務路由器、registry writer 或 promotion path。
- `Decomposition Police` 不直接拆 code，不直接建立 map。
- `Evolution Police` 不直接 promote atom/map，不因 usage count alone 產 evolve proposal。
- `Polymorph Police` 不直接產生 template/instance mutation，只提出 propagation 或 review finding。
- `Rollback Police` 不直接 revert，不直接 apply rollback，只檢查可逆性與證據缺口。
- Shared gates 是 orchestrator gate，不是新的 approval authority。
- Public upstream docs 仍需 adopter-neutral；3KLife/Cocos 私有規則不得寫進 protected public contract。

# ATM-GOV-0395 Give closed-task generated residue one governed reconciliation entry

## Intent

A close writes records, and the pre-commit residue cleanup deletes records, and
both happen *after* the claim that would authorize committing them has been
released. The result is a state ATM can enter but not leave: files it generated
itself, which it will not let anyone commit.

Observed on 2026-08-14 after ATM-GOV-0392 closed. Two records were left dirty:

```
 D .atm/history/evidence/ATM-GOV-0392.bundle-manifest.json
 M .atm/history/evidence/ATM-GOV-0392.live-index-reconciliation.json
```

Every governed route refused, each for a different reason:

- `git commit --task ATM-GOV-0392 --auto-stage` — the framework-development gate
  demanded a claim covering *other lanes'* dirty `packages/cli/**`, paths this
  operator never touched.
- `git record-commit` — its own `--dry-run` accepted the staged record-only
  scope (`ATM_GIT_RECORD_COMMIT_DRY_RUN`), and the real run then refused with
  `ATM_GIT_COMMIT_FRAMEWORK_CLAIM_REQUIRED`. A preview that disagrees with the
  action it previews is its own defect.
- `framework-mode claim` — with `ATM_LANE_SESSION_ID` exported, the lock is
  written as `ATM-FRAMEWORK-TEMP-<actor>-lane-<laneId>.lock.json` and the commit
  resolver does not find it. Without the lane, the lock is written unsuffixed
  and the resolver rejects it as "not bound to the current lane". Both spellings
  of the same live claim are unusable.

The operator's only remaining moves were raw git or hand-editing `.atm`, both
forbidden. The owner ruling of 2026-08-15 froze the two records as evidence and
opened this card instead.

## Design direction

Authority for reconciling generated residue must come from **durable ownership
recorded when the residue was produced**, not from a claim that has since been
released. The close already knows which records it generated; that knowledge,
plus a reconciliation receipt, is the authority. A closed task should therefore
have exactly one diagnosable, governed entry for converging its own residue.

Two rules constrain the shape of the fix:

- The lane-identity half must be repaired at the resolver, not by choosing a
  lock filename. A live claim must be findable by its owner whether or not a
  lane session is active; a naming convention that only one caller understands
  is the bug, not the interface.
- Nothing may key on `ATM-GOV-0392`, on `.atm/history/evidence/*`, on a task id
  pattern, or on a filename. If the repair mentions this incident anywhere
  outside a test comment, it is the wrong repair.

## Acceptance

- [ ] ACC-1: Records generated by a task close, including deletions performed by
  the pre-commit residue cleanup, remain committable through exactly one
  governed route after that task is closed and its claim released.
- [ ] ACC-2: That route is discoverable from the refusal itself: the error names
  the entry and the command, so an operator is never left choosing between raw
  git and abandoning the residue. `git record-commit --dry-run` and its real run
  agree on the outcome.
- [ ] ACC-3: A live framework claim resolves for its owning actor whether or not
  a lane session is active. Both lock spellings observed above resolve, or one
  is made canonical and migration is automatic — in neither case may the
  operator have to guess.
- [ ] ACC-4: Both required cases are red against the reproduction above before
  the fix and green after, and neither names a task id, actor, or file path.
- [ ] ACC-5: The ATM backlog records the root cause, and the two frozen
  ATM-GOV-0392 records are converged through the new route as the closing
  demonstration — not by hand.

## Evidence and rollback

# 原子行為參考手冊（Atom Behavior Reference）

> 本文件是 ATM 框架中所有原子行為的完整參考。主計畫書（`關於進化版的原子提案.md` Part V §6~§9）引用本文件。
> 對應任務卡 chain：`ATM-IDENTITY-BEHAVIOR-V1`（ATM-2-0028 ~ ATM-2-0033）
> 對應實作：`tools_node/atm-atomize.js`、`tools_node/atomic-framework/policies/capsule-governance.default.json`、`atomic_workbench/{capsules,anchors,policies}/`。

---

## 1. 概覽

### 1.1 設計原則

1. **行為本身就是原子**：每個 behavior 是一顆 governed atom（spec + code + test），可被 registry 管理、hash-lock 鎖定、被另一個 behavior 觸發。
2. **行為由 plugin 提供**：core 只定義 `AtomBehavior` interface 與 evidence schema；具體行為由 reference plugin pack 實作；專案可加自己的 behavior plugin。
3. **每個行為都有 5 個合約面**：trigger → evidence → gates → registry transition → rollback。
4. **行為可組合**：dedup-merge = similarity-scan + merge + sweep；polymorphic-evolve = polymorphize + evolve。
5. **實作落地走 capsule 階梯**：所有 in-repo 的原子化都先落 `atomic_workbench/capsules/`（local-capsule-candidate），通過 demand-police 與 promotion gate 後升級到 governed-atom／shared-atom。

### 1.2 行為分類（4 類）

| 分類 | 英文 | 包含的行為 | 說明 |
|---|---|---|---|
| **拓撲類** | Topology | split / merge / compose / dedup-merge / atomize | 改變原子數量或 map 結構 |
| **品質類** | Quality | evolve / polymorphize | 改能力不改身份 |
| **衛生類** | Sanitation | sweep / expire | 移除或棄用 |
| **整合類** | Integration | infect / atomize | 接入 legacy 系統 |

> 注意：`atomize` 同時屬於 Topology 和 Integration（因為它既產新原子又接入 legacy）。

### 1.3 與 capsule tier 的關係

10 種行為定義**邏輯**身份轉換；capsule tier 系統定義**實作**進入 registry 的流程。兩者搭配：

- `behavior.atomize` 在 host repo 的具體實作 = `atm-atomize scan → scaffold → validate → demand-police → promote`（產出 `local-capsule-candidate`，再 promote 為 `governed-atom`）。
- `behavior.merge / dedup-merge` 的 finding 來自 demand police 的 `duplicate-fingerprint` 規則。
- `behavior.split` 的 finding 來自 demand police 的 `high-fan-in-shared-suggestion`（>=2 caller）與 sealed-split 拒絕。
- `behavior.polymorphize` 的 finding 來自 demand police 的 `family-promotion-threshold`（同 family ≥3 capsule）。
- `behavior.infect` 的 dry-run 仍走 ATM-2-0029 review gate，不可直接 apply。

## 3. 各行為詳細說明

### 3.1 behavior.split（分裂）

| 項目 | 說明 |
|---|---|
| **觸發** | (1) 手動——人類判斷原子職責過多；(2) size police——程式碼行數/複雜度超標；(3) demand police——原子中特定子功能被 ≥2 外部 caller 引用 |
| **前置狀態** | active |
| **結果** | 2+ 個 active atoms（各帶 `lineage.bornBy: split`、`parentRefs: [原 atom FQID]`） |
| **evidence** | split-plan + 新舊 sf 比對 |
| **狀態轉換** | 原 atom → deprecated（若全部功能都轉移）或 active（若只分出部分） |
| **rollback** | 合併回原 atom + 刪除新 atoms |
| **限制** | `splitPolicy: sealed` 的 capsule 拒絕被進一步切割（見 §6.4） |

### 3.2 behavior.merge（合併）

| 項目 | 說明 |
|---|---|
| **觸發** | 手動 / dedup proposal |
| **前置狀態** | 所有參與者都是 active |
| **結果** | 1 個 active（合併後）+ N 個 deprecated |
| **evidence** | merge-plan + 合併後 sf |
| **狀態轉換** | 被吸收者 → deprecated |
| **rollback** | split 回各自 atom + 恢復 caller refs |

### 3.3 behavior.compose（串接/組合）

| 項目 | 說明 |
|---|---|
| **觸發** | 手動 / pattern detection |
| **前置狀態** | n 個 active atoms |
| **結果** | 同 atoms 不變，新增 1 個 map（active） |
| **evidence** | map composition + members[] + edges[] |
| **狀態轉換** | 新增 map entry in registry |
| **rollback** | 刪除 map entry |

### 3.4 behavior.dedup-merge（自動吞噬/去重）

| 項目 | 說明 |
|---|---|
| **觸發** | dedup police 偵測 sf 100% 或 similarity ≥ 90% + human approve |
| **前置狀態** | 兩個 active atoms |
| **結果** | 1 個 active + 1 個 deprecated |
| **evidence** | similarity-report + dedup-decision |
| **狀態轉換** | 被吸收者 → deprecated；所有 caller refs 導向存活者 |
| **rollback** | 恢復被吸收者為 active + 恢復 caller refs |
| **對應 demand-police 規則** | `duplicate-fingerprint`（severity=error 當未標 `duplicateResolution`，否則 warning） |

### 3.5 behavior.sweep（清理）

| 項目 | 說明 |
|---|---|
| **觸發** | unused-caller scan（0 callers 持續 N 天） |
| **前置狀態** | active 且 0 callers |
| **結果** | 1 → 1（deprecated） |
| **evidence** | unused-report + caller list（空） |
| **狀態轉換** | active → deprecated |
| **rollback** | 恢復為 active |

### 3.6 behavior.evolve（演化）

| 項目 | 說明 |
|---|---|
| **觸發** | usage-feedback / human propose / quality police |
| **前置狀態** | active@vN |
| **結果** | active@vN+1（舊版仍 active 直到 sweep） |
| **evidence** | upgrade-proposal + quality-comparison + automated gates |
| **狀態轉換** | 新版 active；舊版維持 active（callers 可自行遷移） |
| **rollback** | 刪除新版 + registry 回指舊版 |
| **限制** | 必須委派到 `ATM-2-0020 ProposeAtomicUpgrade`，不得繞過 automated gates 與 human review |

### 3.7 behavior.expire（自我毀滅/TTL）

| 項目 | 說明 |
|---|---|
| **觸發** | scheduled scan + ttl.expiresAt 已過 |
| **前置狀態** | deprecated 且 TTL 已到 / sweep 已過寬限 |
| **結果** | 1 → 1（expired，終態） |
| **evidence** | expiry-report |
| **狀態轉換** | deprecated → expired |
| **rollback** | 不可 rollback（終態） |

### 3.8 behavior.polymorphize（多形）

| 項目 | 說明 |
|---|---|
| **觸發** | 偵測高度相似 spec——差異可被維度參數解釋（見 §4 廣義多形化） |
| **前置狀態** | active |
| **結果** | active (template) + N validated（實例為 lazy，不展開到 registry） |
| **evidence** | polymorph-template + dimension-spec |
| **狀態轉換** | 原 atom 成為 template；被統一的 atoms → deprecated |
| **rollback** | 展開 template 回各自獨立 atoms |
| **對應 demand-police 規則** | `family-promotion-threshold`（同 family ≥`familyPromotionMinCount`，預設 3） |

### 3.9 behavior.infect（感染）

| 項目 | 說明 |
|---|---|
| **觸發** | legacy 區段被偵測 sf 與已有 atom 相同 |
| **前置狀態** | 目標 atom 是 active |
| **結果** | 0 新 atoms；產生 patch plan（legacy 呼叫改為 atom 呼叫） |
| **evidence** | infect-plan + dry-run patch + 新 caller refs |
| **狀態轉換** | 目標 atom 不變；legacy 注入點記錄到 caller list |
| **rollback** | 移除 caller ref + 還原 legacy 呼叫 |
| **限制** | dry-run patch 必須以 `ATM-2-0020` proposal 形式包裝，`decompositionDecision` 預設 `atom-extract`；review 通過前不得 apply |

### 3.10 behavior.atomize（轉化/原子化）

| 項目 | 說明 |
|---|---|
| **觸發** | 手動 case study / 提案 / legacy pattern detection / `atm-atomize scan --changed`（authoring-time auto） |
| **前置狀態** | legacy 區段識別 + sf 計算 + 對應 core anchor 存在 |
| **結果** | 1 個 capsule（`tier: local-capsule-candidate` → 走完整 promote 流程到 `governed-atom`） |
| **evidence** | atomize-proposal + capsule.manifest.json + 對映 legacy patch + sf |
| **狀態轉換** | scan 產候選 → scaffold 產生骨架 → validate strict → demand-police PASS → promote → governed-atom |
| **rollback** | 刪除 capsule 目錄 + 還原 legacy（如已 promote 還需 deprecate registry entry） |
| **Lineage** | capsule 階段：`bornBy: authoring-time-auto-atomization`；正式 `behavior.atomize` proposal：`bornBy: atomize`；`parentRefs: ["legacy://<host>/<path>#L<start>-L<end>"]` |
| **CLI** | `node tools_node/atm-atomize.js <scan\|scaffold\|validate\|demand-police\|promote>`（見 §6） |

### 3.11 behavior.anchorize（錨點化，A1）

| 項目 | 說明 |
|---|---|
| **觸發** | 大型 legacy module（如 `tools_node/lib/dom-to-ui/draft-builder-core.js`）需要 semantic parent 才能允許 capsule 落地 |
| **前置狀態** | 存在 ≥1 capsule 候選；anchor 尚未建立 |
| **結果** | 1 個 `core-anchor` manifest（`atomic_workbench/anchors/<slug>/anchor.manifest.json`） |
| **evidence** | anchor.manifest.json（含 schemaId、anchorId、source.file、children[]、lineage、splitPolicy） |
| **狀態轉換** | 新增 anchor → 後續 capsule 必須宣告 `anchorId` 指向此 anchor |
| **rollback** | 刪除 anchor 目錄；同時 capsule 必須改指或一併刪除 |
| **Lineage** | `bornBy: anchorize`，`parentRefs: ["legacy://<host>/<path>"]` |
| **限制** | 預設 `allowSharedPromotion: false`，core anchor 不允許升級為 shared |

### 3.12 behavior.promote（晉升，A2）

| 項目 | 說明 |
|---|---|
| **觸發** | demand-police PASS + validate strict PASS + 通過 `promotionPolicy` 門檻 |
| **前置狀態** | `local-capsule-candidate`（升 `governed-atom`）或 `governed-atom`（升 `shared-atom`） |
| **結果** | capsule manifest `promotion.currentTier` 更新；`promotion.history[]` 追加 entry |
| **evidence** | promotion.report.json + capsule manifest diff + 對應 demand-police 報告 |
| **狀態轉換** | local-capsule-candidate → governed-atom（單機過閘）；governed-atom → shared-atom（需要 cross-workflow 證據） |
| **rollback** | 還原 `promotion.currentTier` 與 `promotion.history` 末項 |
| **CLI** | `node tools_node/atm-atomize.js promote --capsule <id> --to governed-atom\|shared-atom` |

## 4. 廣義多形化原則（ATM-POLY-001）

> **若兩個原子的 semantic fingerprint 差異可以被一個或多個「維度參數」解釋（即：用同一個 template + 不同參數值可以產出兩者的 spec），則它們必須被視為同一顆多形原子的不同實例。**

### 4.1 可多形化的維度

| 維度 | 範例 | 多形方式 |
|---|---|---|
| 參數 | `parseCssColor(format: 'hex')` vs `(format: 'rgb')` | template + `params.format` |
| 輸入類型 | `normalize(input: string)` vs `(input: Buffer)` | template + `typeParam.input` |
| 輸出形狀 | `parse → {value}` vs `→ {value, metadata}` | template + `outputProfile` |
| 語言 | 同 spec 的 TypeScript vs Rust 實作 | template + `lang` dimension |
| 品質 budget | 同功能但 timeout=100ms vs 1000ms | template + `performanceProfile` |
| 行為變體 | `sort(stable: true)` vs `(stable: false)` | template + `variant` |

### 4.2 對去重流程的影響

```
Dedup 比對流程（含多形判斷）：

1. sf 完全相同 → 強去重（demand-police duplicateFingerprint=error，建議 merge）
2. sf 高相似（≥90%） →
   2a. 差異可用「維度參數」解釋?
       → YES → 建議 polymorphize（不是 merge）
       → NO  → 弱去重 report
3. sf 不同，但同一 family（同前綴／同動詞群） →
   3a. 同 family 計數 ≥ familyPromotionMinCount（預設 3）
       → 觸發 `family-promotion-threshold` finding，建議 governed-family 或 shared 抽出
4. sf 不同、family 不同 → 不重複
```

### 4.3 原子數量效益

多形化能大幅降低 registry 中的原子總數——多個變體只佔 1 個 template entry，其餘為 lazy instantiation 不佔 registry slot。

## 5. 行為 × 警察 使用關係表

| 警察類型 | 使用的行為 | 偵測機制 | 對應任務卡 |
|---|---|---|---|
| **Dedup Police** | dedup-merge / infect / sweep | sf 比對 + LLM similarity skill + fingerprint-index O(1) lookup | ATM-2-0030 |
| **Quality Police** | evolve | automated gates（nonRegression / qualityImprovement / newCapability） | ATM-2-0005 |
| **Lifecycle Police** | sweep / expire | TTL scan / unused-caller scan / 非法 status transition 偵測 | ATM-2-0031 |
| **Boundary Police** | split / extract / atomize | layer 邊界檢查（atom 不得跨 adapter boundary） | ATM-2-0010 |
| **Map Integration Police** | split / merge / atomize / infect | map-level propagation test（任一成員行為觸發全 map 整合測試） | ATM-2-0025 |
| **Demand Police** | split / polymorphize / promote | duplicate-fingerprint、family-promotion-threshold、high-fan-in-shared-suggestion、orphan-capsule、large-module-anchor-missing、sealed-split-attempt、candidate-without-behavior-tests、single-use-stay-local | ATM-2-0030 |
| **Atomization Police** | atomize / anchorize | neutrality scan 整合（確保新原子不引入 host coupling）；anchor 缺失偵測 | ATM-2-0033 |

### 5.1 Police 主動巡邏契約

| 欄位 | 定義 |
|---|---|
| `trigger` | 什麼事件觸發 police 執行 |
| `scope` | police 觀察的文件、registry、map 或 evidence 範圍 |
| `severity` | `info / advisory / warn / block` 等嚴重度 |
| `action` | 要路由到哪個後續動作：task-router、advisory、follow-up task card、quarantine |
| `routeHint` | 給 task-router 或 human queue 的路由提示 |
| `readModel` | 對應的 index / metrics / snapshot 真相 |
| `mode` | `fast` 或 `slow` police |

### 5.2 執行時機

- `authoring-time`：寫卡、寫規劃、寫 registry 時先掃；`atm-atomize scan --changed` 屬於此時機。
- `transition-time`：task、registry、map 狀態切換前後掃；`atm-atomize validate / demand-police / promote` 屬於此時機。
- `sweep-time`：定時掃全域 drift、過期、遺漏、重複。
- `fast police`：deterministic hot path，CI 內即刻 fail。
- `slow police`：semantic audit、跨文件比對、歷史 drift sweep，跑背景或 sweep job。

### 5.3 路由原則

- 低風險 finding 先進 advisory / needs-review。
- 高風險 finding 可直接開 follow-up task card，或觸發 quarantine / hard fail。
- police 不只報 pass / fail，還要能把 machine-readable finding 送到 review / coverage / task-router。

### 5.4 Demand-police 規則目錄（`tools_node/atm-atomize.js#evaluateDemandPolice`）

| ruleId | severity（預設） | 阻擋發布？ | 含義 |
|---|---|---|---|
| `candidate-without-behavior-tests` | error | ✅ | local-capsule-candidate 缺 `base/boundary/invalid` 任一 case set |
| `sealed-split-attempt` | error | ✅ | 試圖在 `splitPolicy: sealed` 的範圍內額外切 capsule |
| `orphan-capsule` | error | ✅ | capsule 宣告的 `anchorId` 無對應 anchor manifest |
| `duplicate-fingerprint` | error / warning | ✅（未標 duplicateResolution）／❌（已標） | 多個 capsule 共用同一 `semanticFingerprint` |
| `large-module-anchor-missing` | error | ✅ | capsule 來源檔案沒有任何 core anchor 覆蓋 |
| `family-promotion-threshold` | warning | ❌ | 同 family（symbol 前綴）capsule 數量 ≥ `familyPromotionMinCount` |
| `high-fan-in-shared-suggestion` | warning | ❌ | usageRefs 達 shared promotion 門檻（≥2 refs、≥2 distinct files、≥2 distinct kinds，並有 cross-workflow kind） |
| `single-use-stay-local` | info | ❌ | usageRefs 未達 shared 門檻，建議續留 governed/local |

> `passed` 旗標 = blocking 規則（前 5 條 error）數量為 0；warning / info 不影響 `passed` 但會出現在 finding 列表。

## 6. Capsule 階梯與 atm-atomize CLI

> 對應實作：`tools_node/atm-atomize.js`、`tools_node/atomic-framework/policies/capsule-governance.default.json`、`atomic_workbench/capsules/`、`atomic_workbench/anchors/`、`atomic_workbench/policies/capsule-governance.policy.json`（host override）。

### 6.1 Tier 階梯

| Tier | 用途 | 進場條件 | metadataRequired | behaviorTemplateRequired |
|---|---|---|---|---|
| `local-capsule` | 已被 host 廣泛接受、但尚未進 candidate 流程的快照 | 手動標記 | ✅ | ❌ |
| `local-capsule-candidate` | scan 階段產出，待 validate + demand-police 通過 | `atm-atomize scan` 自動產出 | ✅ | ✅（base/boundary/invalid） |
| `governed-atom` | 已通過 candidate-to-governed promotion gate | `validate --strict` + `demand-police` PASS + anchor 存在 | ✅ | ✅ |
| `shared-atom` | 已通過 governed-to-shared promotion gate，可跨 workflow 共用 | demand-police 給出 `high-fan-in-shared-suggestion` + cross-workflow 證據 | ✅ | ✅ |

### 6.2 必備 test case sets（policy.testRequirements）

| 場景 | 必須的 case sets |
|---|---|
| `candidate` | base、boundary、invalid |
| `blockRelease` | base、boundary、invalid、regression |
| `sideEffectRisk`（capsule 標 `classification.sideEffectRisk: true`） | 至少包含 boundary、invalid |
| 共同 oracle | `oracleMode: template-contract`（由 `capsule.behavior.test.ts` 強制） |

### 6.3 Promotion gates（policy.promotionPolicy）

```jsonc
"candidateToGoverned": {
  "requireValidateStrict": true,
  "requireAnchor": true,
  "requiredCaseSets": ["base", "boundary", "invalid"]
},
"governedToShared": {
  "requireDemandPoliceSuggestion": true,
  "requireCrossWorkflowEvidence": true,
  "minUsageRefs": 2,
  "minDistinctFiles": 2,
  "minDistinctKinds": 2,
  "crossWorkflowKinds": ["map", "workflow", "case-study", "runtime", "tooling"]
}
```

- `shared-atom` 升級需先取得 `high-fan-in-shared-suggestion` 並至少跨 2 種 kinds，其中至少 1 種是 `crossWorkflowKinds` 列表中的成員。
- 升級時 manifest 會：更新 `promotion.currentTier`、寫入 `promotion.sourceIdentityStable: true`、更新 `promotion.semanticFingerprint`、把 `{promotedAt, fromTier, toTier, reason}` 追加到 `promotion.history`。

### 6.4 Sealed policy（policy.sealedPolicy）

預設禁止切割的 symbol 樣式：`compress|decompress|encrypt|decrypt|cipher|decipher|stateMachine|serializeState|deserializeState`，原因 `state-coupled-or-lossy-transform`。命中的 capsule 取得 `splitPolicy: sealed`，後續任何試圖在其 source range 內再切的 capsule 會被 `sealed-split-attempt` 攔下。host 可在 `atomic_workbench/policies/capsule-governance.policy.json` 用 `sealedPolicy.rules[]` 追加。

### 6.5 Anchor policy（policy.anchorPolicy）

| 欄位 | 預設值 | 說明 |
|---|---|---|
| `required` | `true` | 每個 capsule 都必須宣告 `anchorId` 指向一個 anchor |
| `idPrefix` | `H2U-ANCHOR` | anchor 命名必須以該前綴開頭 |
| `kind` | `core-anchor` | anchor manifest schema 對應 `atm.coreAnchorManifest` |
| `role` | `semantic-parent` | anchor 為其下 capsule 的 semantic parent |
| `allowSharedPromotion` | `false` | core anchor 不可升 shared |

Anchor manifest 必填：`schemaId / specVersion / anchorId / kind / role / logicalName / source.file / source.lineCount / semanticFingerprint / children[] / lineage / splitPolicy / promotion`。

### 6.6 usageRefs 與 usageRefStats

`usageReferencePolicy.enabled = true` 時，scan 自動透過 ripgrep（找不到 ripgrep 改用 fallback walker）對 `includeGlobs` 範圍搜尋 capsule 的 `symbolName`，記錄到 `usageRefs: ["<kind>:<file>#L<line>", ...]`。預設 includeGlobs：

```
tools_node/**/*.js
tools_node/**/*.mjs
assets/scripts/**/*.ts
docs/case-studies/**/*.md
atomic_workbench/maps/**/*.json
specs/**/*.json
```

excludeGlobs 預設排除：`node_modules/**`、`artifacts/**`、`atomic_workbench/capsules/**`、`library/**`、`temp/**`、`server/dist/**`、`.git/**`。

`usageRefStats` 計算：`totalRefs / distinctFiles / distinctKinds / externalRefs / kinds`，並依 `inferUsageRefKind` 將 ref 分類為 `map / case-study / workflow / runtime / test / tooling / docs / other` 之一。

每個 symbol 最多保留 `maxRefsPerSymbol`（預設 24）個 refs；外部目錄掃描深度上限 `externalScanMaxDepth`（預設 2）。

### 6.7 CLI 指令一覽（`tools_node/atm-atomize.js`）

```
Usage: node tools_node/atm-atomize.js <scan|scaffold|validate|demand-police|promote> [options]

scan        --changed | --file <path> [--usage-ref-file <json>] [--report <out>]
            產出 candidate manifest 列表（`artifacts/atm-atomize/candidates.json`）
scaffold    --candidate-report <json> [--report <out>]
            根據 candidate 報告，在 atomic_workbench/capsules/<slug>/ 建出
            capsule.manifest.json / capsule.test.ts / capsule.behavior.test.ts /
            tests/{base,boundary,invalid}.cases.json
validate    [--strict] [--report <out>]
            檢查 capsule 目錄完整性、required case sets、anchor 對應、tier 合法性等
demand-police [--strict] [--report <out>]
            執行 §5.4 全套規則，產出 `artifacts/atm-atomize/demand-police.report.json`
promote     --capsule <H2U-CAPSULE-...> --to <governed-atom|shared-atom>
            晉升 capsule tier；governed-atom 需先 validate strict；shared-atom 需

```

常用 flags：`--workbench-root <dir>`（預設 `atomic_workbench`）、`--policy <json>`（覆蓋預設 policy）、`--policy-hook <js>`（自訂 hook）、`--registry <json>`、`--strict`、`--json`。

### 6.8 與 H2U 案例的具體形狀

H2U 是目前唯一全量原子化的 host workflow，落地形狀：

- Anchor 範例：`atomic_workbench/anchors/draft-builder-core-82992a5f/anchor.manifest.json`
  - `anchorId: H2U-ANCHOR-DRAFT-BUILDER-CORE-82992A5F`
  - 下掛 180+ 個 capsule
- Capsule 命名前綴：`H2U-CAPSULE-<SYMBOL-IN-KEBAB>`
- Capsule manifest 範例欄位：`schemaId=atm.localCapsuleManifest`、`specVersion=0.2.0`、`source.semanticFingerprint=sf:sha256:...`、`tier=local-capsule-candidate`、`recommendedTier=governed-atom`、`classification.{exported,lineCount,severity,riskScore,sideEffectRisk}`、`behaviorContract.{oracleMode,manualTestRequired,templateCompletenessRequired}`、`policyFindings[]`、`lineage.bornBy=authoring-time-auto-atomization`、`promotion.{currentTier,history,sourceIdentityStable,semanticFingerprint}`。

import { behaviorRegistry } from '@ai-atomic/core';

## 8. 狀態機快速參考

> 完整狀態機定義見 `關於進化版的原子提案.md` Part V §7。
> 視覺圖見 [atom-lifecycle-state-machine.svg](atom-lifecycle-state-machine.svg)。

### 8.1 合法 transition 矩陣（邏輯行為 → 狀態變化）

| 行為 | 起點 | 終點 |
|---|---|---|
| split | active | 2+ active |
| merge | active + active | 1 active + N deprecated |
| dedup-merge | active + active | 1 active + 1 deprecated |
| evolve | active@vN | active@vN+1 |
| sweep | active (0 callers) | deprecated |
| expire | deprecated (TTL) | expired |
| polymorphize | active | active (template) + N validated |
| compose | n active | same + 1 new map active |
| infect | target active | target unchanged |
| atomize | legacy | 1 draft → validated → active |

### 8.2 Capsule tier 轉換矩陣（A2 promote）

| 起始 tier | 終點 tier | 必要條件 |
|---|---|---|
| `local-capsule-candidate` | `governed-atom` | `validate --strict` PASS + anchor 存在 + 必備 case sets 完整 |
| `governed-atom` | `shared-atom` | demand-police 開出 `high-fan-in-shared-suggestion` + ≥2 usageRefs / distinctFiles / distinctKinds + 至少 1 個 cross-workflow kind |
| `governed-atom`（core anchor 下） | `shared-atom` | ❌ 拒絕；core anchor 預設 `allowSharedPromotion: false` |
| 任意 tier | 降階 | 不允許；只能透過 sweep/expire 走 sanitation |

### 8.3 mutabilityPolicy 限制

| mutabilityPolicy | 允許的 behavior |
|---|---|
| `mutable` | 所有 |
| `frozen-after-release` | 僅 `evolve`（產新版），不允許 in-place 修改 |
| `immutable` | 僅 `sweep` / `expire`（退役），其餘全部拒絕 |

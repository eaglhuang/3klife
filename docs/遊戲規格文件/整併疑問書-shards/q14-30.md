> 這是 `整併疑問書.md` 的「Q14–Q30」分片。完整索引見 `docs/遊戲規格文件/整併疑問書.md`。

## Q14. 退役武將是否仍保留「因子媒介 / 靈魂傳承」作為教官之外的第二出口？ B

來源衝突：`血統理論系統.md` (doc_spec_0011) 仍保留「退役時可選擇教官或因子媒介路徑」，但 `keep.summary.md` (doc_index_0012)、`教官系統（支援卡）.md` (doc_spec_0027)、`武將壽命系統.md` (doc_spec_0018) 目前已把退役主路線收斂到教官，死亡時才正式結算英靈卡 / 虎符卡。若不先拍板，後續 Data Schema 與 UI 入口會繼續雙軌並存。

A. 保留雙路：退役時可選教官或因子媒介，死亡時另照正式規則補發雙卡。

B. 收斂成單路：退役一律轉教官，因子媒介概念取消或併入教官 / 培育事件。

C. 僅史實名將或女性名將可走因子媒介，其餘角色只能轉教官。

D. 單機 / 長局模式保留因子媒介，正式主線伺服器世界線只保留教官。

## Q15. 名士預言、血統模擬器與 `Revelation_Level` 的正式關係要收斂到哪一層？ C

來源不清：`培育系統.md` (doc_spec_0026) 已把子嗣揭露收斂為 `隱藏 → 傾向 → 區間 → 精確值`，但 `名士預言系統.md` (doc_spec_0006)、`結緣系統（配種）.md` (doc_spec_0028) 目前只寫「方向性提示 / 矛盾批語」，尚未明定它們是否能推進 `Revelation_Level`，還是只能當作獨立敘事提示。

A. 名士預言永遠只屬方向性提示，不直接推進 `Revelation_Level`。

B. 名士預言可把子嗣從 `0` 推進到 `1`（傾向），但不能到區間或精確值。

C. 高階名士 / 特殊工具可推進到 `2`（區間），但 `3`（精確值）仍只能靠成年 / 鑑定事件。

D. 名士預言、血統模擬器、成年鑑定都可推進揭露，只是成本與誤差率不同。

## Q16. 場景戰法（Scene Gambit）的正式入口要收斂到哪裡？ B

來源衝突：`戰法場景規格書.md` (doc_spec_0039) B-1 仍寫「唯一觸發來源」是治理大廳軍事任務，但 `大廳系統.md` (doc_spec_0002)、`官職系統.md` (doc_spec_0014)、`治理模式他國AI系統.md` (doc_spec_0020) 已把雙牆任務、世界沙盤與軍事任務品質都拉進同一條大廳 / 官職 / 沙盤鏈。若不拍板，之後大廳與沙盤會各自長出平行入口。

A. 維持唯一入口：只有治理大廳軍事任務可正式觸發場景戰法。

B. 大廳雙牆任務與世界沙盤遠征共用同一條場景戰法入口，治理大廳只是 UI 呈現面。

C. 世界沙盤成為唯一正式入口，大廳只顯示任務摘要與推薦，不直接發動。

D. 大廳、世界沙盤、特定關卡都可各自直接發動，允許多入口並存。

## Q17. 組合奧義應歸屬哪一層正式規格？ C

來源不清：`戰法場景規格書.md` (doc_spec_0039) 的 J 節已列出赤壁大火、桃園結義、五虎將降臨，但標成「詳細規則未定」；目前也未釐清它是 `場景戰法`、`格子戰法`、`一般戰法`，還是獨立的全屏演出系統。

A. 歸在 `場景戰法`：只要進入特定場景，符合組合條件就由場景層統一觸發。

B. 歸在 `戰法系統`：當作角色帶入的高階組合技，場景只提供加成或演出載體。

C. 另開獨立 `組合奧義` 子系統，由戰法系統與場景規格共同引用。

D. 先不做正式規則，只保留敘事型全屏演出，數值與觸發延後定義。

## Q18. 混種戰法（Hybrid Skills）的母規格要以哪份文件為權威？ A

來源衝突：`戰法系統.md` (doc_spec_0038) 目前未正式承接混種戰法，實際定義散落在 `血統理論系統.md` (doc_spec_0011)。若不先收斂，未來 Data Schema、技能圖鑑與培育事件會不知道該以戰法母系統還是血統母系統為準。

A. 以 `戰法系統.md` (doc_spec_0038) 為母規格；`血統理論系統.md` (doc_spec_0011) 只描述來源與解鎖條件。

B. 以 `血統理論系統.md` (doc_spec_0011) 為母規格；`戰法系統.md` (doc_spec_0038) 只保留交叉引用與 UI 顯示。

C. 新開 `混種戰法 / 血統戰法` 獨立規格書，讓兩邊都只引用。

D. 暫不升格正式規格，只保留少數白名單案例，不建立通用系統。

## Q19. 宿敵配對的正式懲罰要採哪一套？ A

來源衝突：`家族關係（史實相性）系統.md` (doc_spec_0024) 一處寫宿敵「不再直接給固定 EP 加成」，但關係類型表又保留 `RIVAL = -10 EP`；`正式規格矛盾審查.md` (doc_spec_0001) 也已將此列為跨文件衝突。若不拍板，配種 UI、數值公式與文案會繼續不一致。

A. 保留 `-10 EP + 受孕率 -30% + 狼性因子` 的三重懲罰。

B. 取消固定 EP 懲罰，只保留 `受孕率 -30% + 狼性因子`。

C. 保留固定 EP 懲罰，但取消受孕率懲罰，改成純後代質變路線。

D. 依宿敵等級分層：輕度宿敵只影響 EP，重度宿敵再加受孕率與特殊因子。

## Q20. `LobbyMain` 要維持「單一中樞畫面 + 子入口」，還是正式拆成多個主畫面？ A

來源不清：`大廳系統.md` (doc_spec_0002) 與 `UI 規格書.md` (doc_ui_0027) 已把雙牆任務、官職、世界沙盤視為同一中樞畫面的三個資訊層，但目前實作上已先有 `lobby-main-screen` 骨架與各區塊掛點，尚未拍板未來到底是留在單一 hub screen，還是要把官職 / 沙盤升成各自主畫面。

A. 維持單一 `LobbyMain` 中樞，官職 / 沙盤 / 祭壇都從卡片或抽屜展開。

B. `LobbyMain` 只保留摘要卡；官職與世界沙盤各自升成獨立全屏畫面。

C. 世界沙盤獨立，官職仍留在 `LobbyMain`，採混合模式。

D. 手機版維持單一 hub，平板 / PC 版再拆多主畫面。

## Q21. EP 評級門檻要以哪一套為正式標準？ C

來源衝突：`血統理論系統.md` (doc_spec_0011) 將 `天命之子` 定義為 `EP ≥ 90`，但 `武將人物介面規格書.md` (doc_ui_0012) 又寫成 `EP ≥ 98`。這會直接影響人物頁評語、培育預覽、結緣 UI 與名士預言的評等文案。

A. 以 `EP ≥ 90` 為準，`90+` 一律是 `天命之子`。

B. 以 `EP ≥ 98` 為準，`90~97` 仍只是 `良才美質`。

C. 折衷成五階：`90~97 = 天命將成`、`98+ = 天命之子`。

D. 人物頁與結緣預覽可用不同評語層級，但核心公式仍維持單一 EP 數值。

## Q22. 結緣 / 女性來源 / 精力 / 相性 的受孕率要收斂成哪一條正式總公式？ A

來源衝突：`結緣系統（配種）.md` (doc_spec_0028) 使用 `Base(70%) × CHA × LUK × Vitality_Factor`；`可結緣女性來源系統.md` (doc_spec_0003) 又有 `base_rate = 0.6` 的來源修正式；`武將壽命系統.md` (doc_spec_0018)、`家族關係（史實相性）系統.md` (doc_spec_0024)、`道具系統（付費免費道具）.md` (doc_spec_0036)、`遊戲時間系統.md` (doc_spec_0034) 也各自附加懲罰或加成。現況缺的是「哪一條是主公式、其餘哪些是乘區補正」。

A. 以 `結緣系統.md` 的 `70%` 為全域 base；女性來源、季節、相性、道具、精力都作為乘區修正，最後統一 `clamp ≤ 95%`。

B. 以 `可結緣女性來源系統.md` (doc_spec_0003) 的 `60%` 為全域 base；`結緣系統.md` 改為展示層或早期草案。

C. 依母體來源分不同 base rate，但都共用同一套 `CHA/LUK/Vigor/Affinity/Item/Season` 補正鏈。

D. 不收斂成單條總公式，維持各來源各自定義受孕率。

## Q23. 大廳公式中的 `hallLevel` 要不要正式收斂到 `Officer_Tier`？ D

來源衝突：`大廳系統.md` (doc_spec_0002) 的 `rollHallCharacters()` 仍使用 `hallLevel` 決定武將刷新數量，但現行正式共識已把大廳進度權威收斂到 `官職系統.md` (doc_spec_0014) 的 `Officer_Tier`。如果不拍板，後面會同時存在 `HallLevel` 和 `Officer_Tier` 兩套平行進度。

A. 廢除 `hallLevel`，全部改用 `Officer_Tier` 作為大廳內容解鎖與刷新公式的唯一進度變數。

B. 保留 `hallLevel` 作為大廳內部裝潢 / 武將點位進度，`Officer_Tier` 只管任務與世界沙盤。

C. `hallLevel` 只是 `Officer_Tier` 的 UI 別名，不另存真實資料欄位。

D. 短期相容保留雙變數，等 `LobbyMain` 正式拆屏後再收斂。

## Q24. 自告奮勇事件是否需要補「出現權重 / 冷卻」公式，而不是只有布林條件？ C

來源不清：目前 `大廳系統.md` (doc_spec_0002) 只定義 `roleTags + mood + 未顯示過` 的布林判定，符合 Q13 的「不做固定成功率公式」，但仍缺最小可執行的事件頻率控制。若不補，實作端很容易出現事件過密或過稀。

A. 維持現狀，只要布林條件成立就可出現，不再補權重公式。

B. 補 `出現權重 + 冷卻回合`，但仍不定義成功率與獎勵加成公式。

C. 補 `出現權重 + 冷卻 + 角色好感 / mood 權重`，維持純彩蛋，不碰成功率。

D. 直接補完整的成功率與獎勵品質公式。

## Q25. 場景戰法要求的「情報值 ≥ 50%」應以哪個正式基準計算？ C

來源衝突：`戰法場景規格書.md` (doc_spec_0039) 目前只寫「對目標國家的情報值 ≥ 50%」即可發動，但 `領地治理系統.md` (doc_spec_0037) 只定義偵查產出的絕對值公式，尚未說明這個 50% 是相對於國別情報條、場景需求值，還是官職 / 大廳輸出的情報段位。若不拍板，關卡、世界沙盤、大廳 intel 顯示會各自實作一套分母。

A. 以目標勢力的 `Intel_Current / Intel_Max` 為準，50% 代表該國情報條過半。

B. 以各場景的 `requiredIntel` 為分母，達成需求值的一半即可顯示可發動提示。

C. 百分比寫法取消，正式改成固定 `requiredIntelValue` 數值門檻，由各場景直接標值。

D. 由官職 / 大廳輸出 `intelTier` 段位，場景戰法不再直接使用百分比語言。

## Q26. `Pregnancy_Lock` 期間，母方精力的自然回復與補元散是否仍可生效？ D

來源衝突：`結緣系統（配種）.md` (doc_spec_0028) 一方面寫「待產凍結期間母方精力不回復」，另一方面又寫「補元散可快速回復精力縮短冷卻」；`數值系統.md` (doc_data_0001) 與 `武將壽命系統.md` (doc_spec_0018) 又把精力自然回復寫成全域季度公式。若不先拍板，實作端會不知道待產鎖住的是「精力數值」、「再次結緣權限」，還是兩者都鎖。

A. 全部凍結：自然回復與補元散都無效，直到生產完成才恢復。

B. 自然回復凍結，但補元散仍可回精力；只是待產月數與再次結緣時點不提前。

C. 自然回復凍結，補元散可回精力，且可部分縮短待產冷卻。

D. 只凍結再次結緣權限；精力仍照常自然回復，也可被補元散補滿。

## Q27. 近親判定要以 `Bloodline_ID` 還是「共同祖先代數」作為正式權威？ C

來源衝突：`血統理論系統.md` (doc_spec_0011) 與 `結緣系統（配種）.md` (doc_spec_0028) 前段都以 `same Bloodline_ID` 判定近親劣化，但後段新補的 K 節又引入 `Inbreeding.BlockGenerations`，改成用共同祖先代數直接禁止配對。現在同時存在「同血源警告」與「代數阻擋」兩套權威，還沒有定義誰先、誰重、誰只是快取欄位。

A. 以 `Bloodline_ID` 為唯一權威；`BlockGenerations` 移除或只作輔助說明。

B. 以共同祖先代數為唯一權威；`Bloodline_ID` 只作查詢快取，不單獨決定禁配。

C. 兩者混合：先用 `BlockGenerations` 判斷是否禁止配對，再用 `Bloodline_ID` 決定較輕的劣化警告與 UI 提示。

D. 單機 / 劇情模式走代數規則，正式長局與伺服器世界線走 `Bloodline_ID`。

## Q28. 兵種剋制、地形、天氣與適性的多層戰鬥修正，應如何正式疊加？ C

來源衝突：`數值系統.md` (doc_data_0001) 已把 `counter_mod / terrain_atk_mod / weather_atk_mod / troop_atk_mod` 都放進主傷害公式；`戰場適性系統.md` (doc_spec_0041) 又定義 S~D 級地形 / 天氣 / 兵種適性修正；`兵種（虎符）系統.md` (doc_spec_0012) 另有五角兵種剋制倍率。若不先拍板，後續很容易出現「全部相乘導致爆炸」或「部分改成加法卻與舊關卡不相容」的雙重世界線。

A. 全部維持獨立乘區，完全累乘，不另外設總上限。

B. 兵種剋制保留獨立乘區；地形 / 天氣 / 適性先合併成單一 `environment_mod`，再乘到主公式。

C. 兵種剋制先乘，地形 / 天氣 / 適性改成加法修正或百分點修正，避免乘區爆炸。

D. 保留多乘區，但新增總上下限，例如 `0.4 ~ 2.0`，超出部分一律 clamp。

## Q29. 因子池中「同名因子重複出現」時，要如何正式合併權重？ A

來源不清：`結緣系統（配種）.md` (doc_spec_0028) 只定義父母 / 祖父母 / 曾祖父母進入因子池的代際權重，`運氣系統.md` (doc_spec_0035) 又額外定義 `Inheritance_Rate` 與高 LUK 的繼承加成，但沒有說明當同一個因子從多位祖先重複入池時，究竟是直接疊權重、取最高星等，還是只保留一次。若不拍板，配種模擬器、名士預覽與實際抽樣會出現不同結果。

A. 同名因子全部疊權重，來源越多就越容易被抽到，也可順勢推高星等。

B. 同名因子只保留最高星等，其他重複來源只轉成少量加權，不再完整堆疊。

C. 先保底父母直系，再從祖輩池補抽；重複因子只在祖輩池內部做權重競爭。

D. 不建立通則，依紅 / 綠 / 粉 / 紫等不同因子類型各自定義合併規則。

## Q30. 虎符品質（UR / SSR / SR / R）的正式評級，要以哪套公式為權威？ B

來源不清：`兵種（虎符）系統.md` (doc_spec_0012) 只寫「依死亡快照戰績與傳承品質決定虎符品質」，`數值系統.md` (doc_data_0001) 卻已經先使用 `UR ×1.5 / SSR ×1.3 / SR ×1.15 / R ×1.0` 的品質乘數。也就是說，下游數值已經假設品質存在，但上游還沒有正式說明品質是怎麼被評出來的。

A. 只看死亡時的戰績快照與名將原始 rarity，傳承品質不納入。

B. 以死亡戰績為主、傳承品質為次要加權，先算單一 `TigerTallyScore` 再映射到 UR / SSR / SR / R。

C. 以名將原始 rarity 決定品質上限，死亡戰績只影響星等、詞條與附加效果。

D. 不做通用公式，只保留少數白名單名將固定品質，其餘後補。

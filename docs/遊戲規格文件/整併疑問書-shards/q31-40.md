## Q33. 格子屬性 JSON 結構

來源衝突：`doc_spec_0089`（模組化戰場系統開發策略.md）。文件建議正式定義「格子屬性表（Tile Property Sheet）」，包含狀態 ID（Fire/Water/Stone/Forest）、觸發時機（Enter/Stay/Round_End）、對應特效名稱等欄位，但提出三種資料結構方案而未定論：靜態 JSON 方便版本控制與策劃直接編輯；動態 ScriptableObject 允許 Editor 時期即時預覽調整；混合模式分層處理兩者需求。若不拍板，戰場系統各模塊會各自選型，後期格式不統一將難以橫向擴充新戰法。

A. 靜態 JSON：所有格子屬性以純 JSON 定義，版控方便，策劃可直接修改，無需打開 Editor。

B. 動態 ScriptableObject：在 Unity/Cocos Editor 內管理，runtime 反序列化，方便即時預覽效果。

C. 混合模式：基礎屬性（狀態 ID、觸發時機、數值）用靜態 JSON；特效名稱與美術掛載用 ScriptableObject。

D. 混合模式：基礎屬性（狀態 ID、觸發時機、數值）用靜態 JSON；發生戰場有特殊需求如淹水 落石的時候程式會動態計算需要產生特效的格子做出隨機感, 不會讓每次進落石戰或 或火攻偷襲戰的時候就 落石跟火永遠都在相同的格子上, 這樣會沒有 roughlike 的感覺

# Q版動作系統與動畫管理器規格書（QACT-01）

> **規格代碼**：`QACT-01`　**任務卡**：PROG-2-10188　**裁決來源**：使用者 2026-11-27 本人（武將生活化；Q 版三套系統＋Q 版社會架構）
> **狀態**：規格草案（只有規格，不含程式；數值是 PM 暫定，全放 JSON 可調）
> **定位**：「Q 版社會」四份規格的第 1 份。**獨立可重用**：戰場以外的小遊戲、大廳小人、生活場景都能用，不依賴生活系統、表情系統。
> **姊妹篇**：Q版表情系統（QFACE-01）、Q版生活系統（QLIFE-01）、Q版社會總規格書（QSOC-01，組合層）
> **依賴**：共用框架總綱（`doc_spec_1182`，共通底層工具層：亂數、時鐘）、手機記憶體優先（使用者長期裁決）、兵種符號全遊戲一致（單色圖形）
> **不碰**：戰場核心規則（五路對撞、小兵只打同路正面）交戰場專家；本書單挑是「Q 頭碰撞小遊戲」，不是戰場戰鬥。

## 0. 結論（先看這段）

1. 動作系統只管「一顆 Q 版大頭怎麼動」：走路、跳、待機呼吸、單挑碰撞、揮武器、跳字、血條。**全部用程式即時算，不用逐幀圖**（使用者裁決：逐幀記憶體太大）。
2. **動畫管理器（AnimMgr）是共用底層**，不算框架（沒有伺服器 API），跟「共通底層工具層」同級，放 `assets/scripts/shared/`。動作系統、表情系統、符號系統都向它登記，由它每幀統一推進。
3. 動作 = 資料檔裡的「動作片段（clip）」。要加新動作，只加 JSON，不加程式（除非要新的曲線種類）。
4. 單挑是「兩顆頭＋一把武器＋血條」的小模組，輸入是兩邊數值，輸出是勝負與過程事件；**不寫友誼、不寫存檔**，結果由呼叫端（生活系統或小遊戲）決定怎麼用。
5. 手機優先：一個場景同時最多 24 顆頭在動，每顆頭最多 10 個節點，節點全部走物件池。

## 1. 名詞

| 名詞 | 意思 |
|---|---|
| Q 頭 | 一顆 Q 版武將大頭，加影子，是這套系統的基本演員 |
| 演員（Actor） | 動畫管理器管的一個對象，通常就是一顆 Q 頭 |
| 動作片段（clip） | 一段程式動態，例如 `walk`、`jump`。由數個「通道」疊起來 |
| 通道（channel） | 一個被動的屬性：垂直位移、縮放 X／Y、旋轉、影子縮放、透明度 |
| 掛點（socket） | Q 頭上掛東西的位置：武器、符號、情緒泡泡 |
| 事件 | 動畫播到特定時間點對外發的通知，例如「落地」「命中」 |

## 2. 動畫管理器（共用底層）

### 2.1 職責

1. **全場唯一一個 update 迴圈**：管理器每幀只跑一次，推進所有演員的所有通道。禁止每顆頭各掛 `schedule`、各開 `tween`。
2. 統一播放、暫停、停止、混合（淡入淡出）、佇列（做完 A 接 B）。
3. 統一降級（遠處、低階機降頻；見第 7 章）。
4. 統一暫停（切分頁、開彈窗時全停）。
5. 發事件給外部（落地灰塵、腳步聲、命中停格）。

### 2.2 介面（草案）

```ts
interface IQAnimManager {
  register(actor: IQActor): ActorHandle;          // 取得控制把手，節點從物件池領
  unregister(h: ActorHandle): void;               // 還回物件池
  play(h: ActorHandle, clipId: string, opts?: PlayOpts): void;
  queue(h: ActorHandle, clipId: string, opts?: PlayOpts): void;
  stop(h: ActorHandle, fadeSec?: number): void;
  setLod(h: ActorHandle, lod: 0 | 1 | 2): void;   // 0 全速 1 半速 2 凍結
  setPaused(paused: boolean): void;
  on(evt: 'land' | 'hit' | 'clipEnd' | string, cb): void;
}
interface PlayOpts { loop?: boolean; speed?: number; seed?: number; fadeInSec?: number; }
```

> 管理器不知道「武將」「場景」「符號」，只認「演員＋通道＋片段」。表情、符號是另外兩個使用者，各自提供自己的演員種類（`IQActor`）。

### 2.3 資料檔

| 檔案（建議） | 內容 |
|---|---|
| `assets/resources/data/q-motion-clips.json` | 動作片段庫（本書第 3、4、5 章） |
| `assets/resources/data/q-anim-budget.json` | 預算與降級門檻（第 7 章，生活系統共用） |
| `assets/resources/data/q-actor-sockets.json` | 掛點預設（可被每位武將覆蓋，見表情書錨點檔） |

## 3. 基本動作片段

單位：長度以「頭高 H」為單位（H＝Q 頭顯示高度），所以頭大頭小、近大遠小都不必改參數；角度為度；時間為秒。

### 3.1 走路 `walk`

使用者定案：每步上下彈、左右歪頭約 ±6 度、落地壓扁彈起拉長、腳下影子跟著縮放。

| 參數 | 暫定值 | 說明 |
|---|---|---|
| `stepPeriod` | 0.36 | 一步的時間（走一步＝一次彈跳）。跑步 0.24 |
| `bobHeight` | 0.10 H | 上下彈的高度 |
| `tiltDeg` | 6 | 左右歪頭，隨腳步左右交替，正弦平滑 |
| `squashLand` | (1.12, 0.88) | 落地瞬間 (scaleX, scaleY)，持續 0.06 秒 |
| `stretchApex` | (0.94, 1.08) | 彈到最高點 (scaleX, scaleY) |
| `shadowScaleMin` | 0.78 | 彈到最高點影子縮到這個比例，落地回 1.0 |
| `shadowAlphaMin` | 0.55 | 同上，影子也變淡 |
| `faceFlip` | 依行進方向 | 水平翻轉整顆頭（不重畫，scaleX 取負） |
| `landEvent` | true | 落地發 `land` 事件（腳步聲、塵土符號） |
| `ease` | `sineInOut` | 上升、下降各用一條曲線，落地前加速 |

> 走路感的關鍵是「落地那一下」：壓扁 → 彈回 → 拉長，三段時間比約 0.06 : 0.08 : 0.22。其他由 `stepPeriod` 等比縮放。

### 3.2 跳 `jump`

| 參數 | 暫定值 | 說明 |
|---|---|---|
| `duration` | 0.50 | 開心、到達目的地、被嚇到都用 |
| `height` | 0.60 H | 跳高 |
| `spinDeg` | 0 或 180 | 開心跳可加半圈旋轉（繞垂直軸用 scaleX 翻轉模擬，不做 3D） |
| `squash` | 起跳前蹲 0.08 秒 (1.15, 0.85) | 預備動作 |
| `landSquash` | (1.18, 0.82) 後回彈 | 落地 |

### 3.3 待機 `idle`

| 參數 | 暫定值 | 說明 |
|---|---|---|
| `breathScale` | 1.00～1.03 | 呼吸縮放，週期 2.4 秒；每顆頭起始相位用 `seed` 錯開，避免整排同步 |
| `microSway` | ±1.5 度，週期 4 秒 | 微晃 |
| `lookAround` | 每 4～9 秒左右轉一下頭 | 水平翻轉，不是轉頭畫面 |

> 眨眼不在動作系統，在表情系統（QFACE-01）。

### 3.4 其他可選基本動作（第一版資料先放，之後可加）

`run`（跑）、`sit`（坐下，Y 壓低 0.12 H＋呼吸變慢）、`sleep`（躺平：旋轉 −80 度＋影子拉長，配合 ZZZ 符號）、`bow`（拜，前傾 20 度再回）、`shake`（搖頭，±12 度快速三下）、`nod`（點頭）、`tremble`（發抖，高頻 ±2 像素）、`dizzy`（被打暈，畫圈轉）。

## 4. Q 頭單挑（碰撞小遊戲）

使用者定案：兩顆 Q 頭可以單挑，碰撞、跳數字、血條，可再掛 Q 版武器揮打。

### 4.1 流程

```
入場（兩邊面對面站好） → 回合循環 { 蓄力 → 衝撞 → 命中停格 → 擊退 → 跳字＋扣血 } → 一方歸零或回合上限 → 勝負演出（勝者跳、敗者暈）
```

| 階段 | 時間（暫定） | 動作 |
|---|---|---|
| 蓄力 | 0.30 秒 | 往後退 0.4 H，壓扁 (1.1, 0.9)，武器舉起到預備角度 |
| 衝撞 | 0.18 秒 | 加速衝向對手，拉長 (0.92, 1.1)，武器揮出 |
| 命中停格 | 0.08 秒 | 兩邊時間凍結（hitstop），白閃一下（Sprite.color 瞬間提亮，不用 shader） |
| 擊退 | 0.25 秒 | 被打的一方往後飛 0.7 H，旋轉 ±15 度，再彈回 |
| 震動 | 0.15 秒 | 整個場景（或兩顆頭）震動，振幅 4 像素，遞減 |
| 跳字＋扣血 | 0.60 秒 | 傷害數字往上飄、血條平滑扣（見 4.3、4.4） |

### 4.2 傷害與勝負（小遊戲預設，不是戰場公式）

| 項目 | 暫定值 |
|---|---|
| 血量 | 100，基礎；高將階可 ×1.2 |
| 單擊傷害 | `base 8～14 × (自己武力 ÷ 對手武力)^0.5`，取整 |
| 暴擊 | 10%，×1.5，跳字放大並變色 |
| 閃避 | 對手武力＋智力高於自己時最多 15%，閃避時被打方側跳，跳字「閃」 |
| 回合上限 | 12 回合；到上限看剩餘血量比 |
| 亂數 | 用共通底層的確定性亂數（`seed` 由呼叫端給），相同種子相同過程，方便重播與驗證 |
| 切磋 | 血量降到 30% 就「點到為止」自動收手；呼叫端可關掉改成打到 0（小遊戲用），但**這個模組本身不產生任何「死亡」結果**，只回報 `ko`（血量歸零）。傷勢由呼叫端換算：生活層見 QLIFE-01 第 6.4.1 節（使用者 11/28 裁決：單挑有真實後果、最重輕傷、不致死；戰場戰力影響需與戰場專家對齊） |

> 輸入只要兩個數字：武力與智力（可加兵種或武器種類）；輸出是 `DuelResult { winner, rounds, hpLeft, events[] }`。生活系統用這個結果換友誼、心情；其他小遊戲愛怎麼用都行。

### 4.3 武器掛點

| 項目 | 規則 |
|---|---|
| 掛點 | Q 頭右側 `weaponHand`，座標見表情書錨點檔 `sockets.weaponHand` |
| 武器圖 | 單色或簡化小圖，沿用兵種符號風格（劍、槍、刀、戟、弓）；一種武器一張小圖，放符號共用圖集 |
| 揮動 | 繞掛點旋轉：預備 −60 度 → 揮出 +70 度 → 回收，時間跟隨衝撞階段 |
| 數量 | 同時揮武器最多 4 組（兩場單挑），其他場景中的武器只是符號 |

### 4.4 跳字與血條

| 元件 | 規則 |
|---|---|
| 跳字 | 池大小 12。往上飄 1.2 H、0.6 秒、先放大 1.3 倍再縮；普通白、暴擊金、回復綠、閃避灰。位數字用同一個圖集字型（Label 的 BitmapFont），不逐個建 Label |
| 血條 | 池大小 4。頭頂上方 0.35 H，寬 1.2 H；平滑扣（前條立刻扣、後條 0.4 秒追上）；只畫兩段 Sprite（Sliced 一張圖，用 fillRange），不用 Graphics |
| 受傷顏色 | 血條 > 50% 綠、20～50% 黃、< 20% 紅（只改 Sprite.color） |

    "duelRush":   { "loop": false, "duration": 0.18, "channels": { "x": { "type": "dashTo", "target": "opponent" }, "scale": { "type": "hold", "to": [0.92, 1.1] } }, "events": [{ "t": 0.18, "name": "hit" }] }

## 6. 節點與物件池

| 項目 | 規則 |
|---|---|
| 每顆 Q 頭節點數 | 最多 10：根（位置）、影子 1、頭 1、臉部 3（眼、嘴、紅暈，歸表情系統）、符號掛點 1、武器掛點 1（空時 inactive）、情緒泡泡 1、預留 1 |
| 物件池 | 整個 Q 社會共用一個 Q 頭池（上限＝本機等級可見頭數＋4，見第 7 章）；移出畫面、進店、換場景都還回池，不 destroy |
| 跳字池 | 12；血條池 4；武器池 4 |
| 紋理 | Q 頭圖用武將「大頭」圖（Codex 四件組之一）；場景內只載當下需要的武將。**不另做走路幀圖**。不佔 CHAR 大圖集（使用者長期裁決：手機記憶體優先） |
| 圖集合批 | 影子、血條、跳字、符號共用 1 張小圖集（`q-common.atlas`，≤ 512×512），讓同一畫面合批 |

## 7. 效能預算與降級（動畫管理器負責）

數字是 PM 暫定。本機等級由啟動時量測（記憶體、幀率）決定，也可玩家手動改。

| 項目 | 低階 | 中階 | 高階 |
|---|---|---|---|
| 同畫面 Q 頭上限 | 12 | 16 | 24 |
| 全速動畫（LOD0）頭數 | 6 | 10 | 16 |
| 半速（LOD1，每隔一幀更新、只做位移與呼吸） | 其餘 | 其餘 | 其餘 |
| 凍結（LOD2，只顯示靜態頭＋影子，不跑通道） | 畫面外、被彈窗蓋住、離焦點很遠 | 同左 | 同左 |
| 同時單挑 | 1 | 1 | 2 |
| 每幀動畫管理器耗時目標 | ≤ 1.0 ms | ≤ 1.5 ms | ≤ 2.0 ms |
| 目標幀率 | 30 | 30（可 60） | 60 |

LOD 判斷（每 0.25 秒重算，不是每幀）：

1. 離「焦點」（玩家點的店、跟隨的武將、單挑中的人）最近的 N 顆 → LOD0。
2. 其餘在畫面內 → LOD1。
3. 畫面外或被蓋住 → LOD2（還是更新位置，只是不跑視覺通道，位置用簡化直線插值）。

## 8. 給其他系統的介面保證

| 對象 | 保證 |
|---|---|
| 戰場（戰場專家） | 可以直接拿走 `walk`、`jump`、`hitstop`、跳字池，不必接受生活系統；戰場核心規則不受影響 |
| 小遊戲 | 單挑模組可獨立呼叫，輸入兩人數值與武器圖即可 |
| 表情系統 | 提供「臉部演員」型別，與動作並行播放；動作系統不知道眼嘴細節 |
| 生活系統 | 呼叫 `play`／`queue`；訂閱 `land`、`hit`、`clipEnd` |

## 9. 驗收

1. 走路 30 秒，肉眼看得出：彈、歪、壓扁、拉長、影子縮放。
2. 24 顆頭同時走（高階機），幀率不掉到目標以下；低階機 12 顆。
3. 單挑一場 12 回合內結束，傷害數字、血條、擊退、震動都出現；同一 `seed` 重播結果相同。
4. 換場景 10 次，節點數與記憶體不增長（物件池歸還）。
5. 不使用 `tween` 每顆頭一份、不使用逐幀圖。

## 0. 結論（先看這段）

1. 每位武將都有「場景偏好」，一天分 7 個時段，每個時段自己挑下一個去哪。挑法是加權抽籤，偏好被 8 種因素改變：官職、生小孩、季節、心情、羈絆、跟主角的關係、世界大事件、所屬勢力。
2. 場景共 7 張大圖、72 個場景、另有 5 個節慶疊層（見第 3 章）。**每位武將都能去任何場景**，不分職業。
3. 武將頭上永遠顯示「正在做什麼」的小符號（睡覺飄 ZZZ、練武一把武器飛舞、喝酒酒罈倒＋紅暈＋酒香）。符號用資料檔對照（活動 → 符號組 → 動態參數），共 50 種，由動畫管理器統一播放，風格跟兵種符號一致（單色簡單圖形）。
4. 主角可以：搭話、送禮、邀約同行、切磋單挑、搶走對方正在用的物品、點符號偷聽想法。每種互動都有明確的友誼、羈絆、心情影響，並串接物品庫存與友誼框架。**每季有 6 次免費互動，用完可花銀兩買（6.0）**；單挑輸方會進傷勢、只透過傷勢旗標扣下一場屬性（6.4.1，已與戰場專家對齊（11/28 審查））；搶物品的後果看關係（6.5）。
5. 每位武將有專屬稀有舉止（關羽捋鬚、張飛打噴嚏…），看到就收進「舉止簿」。
6. 這份書全部是資料驅動：喜好、作息、符號、互動數值都在 JSON，不寫死。

## 2. 喜好模型

### 2.1 每位武將的生活資料（`life-profile.json`）

```json
{
  "schema": "life-profile.v1",
  "generals": {
    "zhang_fei": {
      "homeScene": "home_general",
      "affinityTag": { "martial": 80, "drink": 90, "official": 15, "scholar": 10, "family": 40, "play": 45, "nature": 30, "trade": 35, "faith": 10, "medical": 10, "adventure": 40 },
      "affinityScene": { "mil_barracks": 95, "mkt_tavern": 100, "mil_arena": 70, "home_nursery": 0 },
      "chronotype": "night",
      "sociability": 85,
      "stubbornness": 30,
      "likes":   ["酒", "兵器", "肉"],
      "dislikes": ["文書", "茶"],
      "props": { "mkt_tavern": "item_wine_jar", "mil_barracks": "item_spear" }
    }
  },
  "defaults": { "chronotype": "day", "sociability": 50, "stubbornness": 40 }
}
```

| 欄位 | 說明 |
|---|---|
| `affinityTag` | 對 11 類場景標籤的基礎喜好，0～100 |
| `affinityScene` | 針對個別場景的覆寫（優先於標籤），0～100 |
| `homeScene` | 回家睡覺的地方；預設自宅，單身或無房者可是客棧 |
| `chronotype` | `day`（日行）、`night`（夜貓），影響時段偏好 |
| `sociability` | 愛湊熱鬧程度，影響跟人同去、聚在人多的場景 |
| `stubbornness` | 固執度，影響換場景頻率（越高越不愛換）與抗拒干擾 |
| `likes`／`dislikes` | 送禮偏好標籤（第 6.2 節）。**存標籤 id（如 `tag_wine`），不存中文字面**；顯示字走 i18n（第 8 章 i18n 規則）。上方範例的中文只是示意 |
| `props` | 在某場景預設拿的物品，也是「搶物品」的標的 |

資料來源優先順序：手動覆寫 > 性格與專長自動推導 > 預設值。批次初始化由工具依武將性格（`Brave`、`Loyal`、`Wise`、`Playful`）、專長、史實愛好產生草稿，企劃再校。

### 2.3 挑下一個場景

每個時段開始時，每位武將挑一次（不是每幀）。

1. 候選＝該時段開門的場景（`openSlots`）。
2. 過濾：已被人員占用（`doc_spec_1248`，`academy`、`campaign`、`medical:pregnant／nursing` 等）→ 只能在占用決定的地點；**`medical:injured`（傷勢）不是地點鎖**，只套用 6.4.1「生活層效果」的醫館、自宅、溫泉 +30 偏好，仍可挑別的場景（11/28 審查，與「傷者可出戰」一致）；場景人數滿（`capacity`）→ 排除。
3. 算 `score(s)`。
4. 修正：目前所在地 +20（懶得動）；最近 2 個時段去過 −30（避免老在兩地跳）；固執度高的武將目前地加成再 ×(1+stubbornness/100)。
5. 加權抽籤：機率 ∝ `score^k`，`k=1.6`（偏好差距越大越集中，但不鎖死）。亂數用共通底層確定性亂數，`seed＝(generalId, 季度序號, 時段序號)`，其中「時段序號」＝本季內從 0 起連續累計的時段數（生活時鐘每轉滿 7 個時段算一個生活日，換季歸零；11/28 審查補：原「日」未定義），方便重現與驗證。
6. 時段中途有 10% 機率換到同大圖內的相鄰場景（逛攤、串門子）。

**使用者 11/28 裁決：生活層看得到的武將＝我方家臣＋本城訪客（外交使者、傭兵、浪人、俘虜）。**他國武將不常駐；只在「遊歷」事件時偶爾出現（事件規格見 `doc_spec_1362` QENC-01；作息卡見 `doc_spec_1363` QSCHED-01）。前期家臣少、街上冷清時，**多放他國武將遊歷事件**補人氣（使用者 11/28 裁決）；**不做無名路人 Q 頭**，街上每顆 Q 頭都是有名有姓的武將。範圍寫在 `life-roster.json`，日後要調只改資料。

### 3.2 生活時鐘跟遊戲時鐘的關係

| 項目 | 規則（PM 暫定） |

### 3.5 場景日夜四季全域規則（使用者 11/28 本人裁決，適用全部大場景）

**裁決**：所有生活場景（`gov`、`mil`、`mkt`、`edu`、`home`、`out`、`mtn` 七張大圖）都要分**日夜＋四季**，每個場景 2×4＝**8 種樣子**。節慶疊層（第 4.8 節）疊在這 8 種樣子之上，不另算。

**做法原則（手機記憶體優先）**：**不畫 8 張完整大圖**。一張「春季白天」底圖，加上程式調色、遮罩換色、小張疊層與少量補丁組出 8 種樣子。能用程式處理的一律不畫。

#### 3.5.1 8 種樣子怎麼組

| 樣子 | 組法（由底至頂）|
|---|---|
| 春・日 | L0 天空＋L1 底圖（本身就是春日）＋L2 前景（春）|
| 夏・日 | 春日底圖＋**遮罩換色**（樹冠加深加飽和）＋夏季補丁（遮陽棚）＋夏季粒子 |
| 秋・日 | 春日底圖＋遮罩換色（樹冠轉橘紅）＋**秋季落葉疊層**＋秋季粒子 |
| 冬・日 | 春日底圖＋遮罩換色（樹冠轉灰褐、整體降飽和偏冷）＋**冬季積雪疊層＋屋頂積雪補丁**＋雪粒子 |
| 四季・夜 | 對應的「季・日」組合，再加：夜間乘色（程式）＋**光源圖集**（窗光、燈籠、爐火，加色混合）＋星空（L0）|

#### 3.5.2 能用程式處理的（不畫）

| 項目 | 程式做法 |
|---|---|
| 日夜色調 | 對 L0、L1、L2 的 Sprite 乘色（`Sprite.color`），顏色從第 3.5.4 表以 `lerp` 漸變，不換圖 |

#### 3.5.4 乘色與光源強度（PM 暫定，放 `life-area-maps.json` 的 `lighting` 區塊，可調）

四個光照階段 × 四季的乘色（RGB，十六進位）。日間春為基準白，故其他組合只會變暗或偏色。

| 日 | FFFFFF | FFF6DC | FFE6BE | E8F0FF | 0 |
| 昏（夜開始前 2 小時）| FFC89A | FFC48C | FFB27C | F0B8A8 | 0.7 |

#### 3.5.5 日夜接「一天的時段排程」

日夜**不是**獨立時鐘，直接吃第 3.1 節的 7 個時段與第 3.3 節各季「夜開始／晨起」：

| 項目 | 規則 |
|---|---|
| 小時換算 | 第 3.1 節時段按經過比例換成 0～24 小時，時段代表時：晨 6.5、上午 9.5、午 12.5、下午 15.5、傍晚 18.5、夜 22、深夜 2.5 |
| 階段判定 | 小時 < 晨起：夜；晨起至晨起＋1.5：晨；其後至夜開始－2：日；夜開始－2 至夜開始：昏；≥ 夜開始：夜 |
| 各季「夜開始／晨起」 | 春 20／05、夏 21／05、秋 20／06、冬 19／07（第 3.3 節）|
| 漸變 | 換階段時每個階段的前 15 秒（真實時間）把乘色與光源強度 `lerp` 到新值，其餘時間固定 |
| 手動切時段 | 右上角手動切時段時，同樣 `lerp`（0.6 秒），不載入新圖 |
| 進入場景 | 直接用當下時段算出階段，無過場載入 |

## 5. 生活動態符號系統（本章為使用者追加需求）

### 5.1 原則

1. 每位武將頭上要顯示他正在做什麼。符號掛在 `sockets.symbol`（QFACE-01 錨點檔）。
2. **每種活動對應一組符號動態**，用程式做，由動畫管理器（QACT-01）統一播放；**不用逐幀圖**。
3. 符號沿用全遊戲同一套**簡單單色圖形**風格（跟兵種符號一致：盾、長槍、劍…；筆畫粗細一致、單色）。美術用**白色單通道圖**，執行時用 `Sprite.color` 上色，所以一張圖可變多色。
4. 資料檔對照三層：**活動 → 符號組 → 動態參數**，加新活動只改 JSON。
5. 圖集 `q-symbols.atlas`：1 張 512×512，每格 64×64，共 64 格，已用約 56 格。

### 5.2 動態種類（可重用）

| `motion` | 做法 | 例子 |

互動入口：點武將 Q 頭 → 彈出一個圍著頭的小圓形選單（半徑 0.9 H、按鈕 ≥ 44 像素，拇指易按）：搭話、送禮、邀約、切磋、（搶物品）、（偷聽＝點符號）。

所有互動走友誼框架（`FriendshipService.add(generalId, delta, reason)`，伺服器權威），行為代號用 `life_` 前綴，數值先暫定，**新行為要在實作卡時補進 `friendship-action-weights.json`**。心情值（−50～+50）與羈絆點數（`bondPoints`）由生活層另管，同樣走 API。

#### 6.4.1 傷勢與戰場影響（使用者本人 11/28 裁決；數值為 PM 暫定；已與戰場專家對齊（11/28 審查））

**核心原則**：重用現有傷勢，不新增數值系統。生活單挑的傷勢與戰場受傷（`doc_spec_0720` 的 WOUNDED 輕傷休養）是**同一個狀態**，同一人身上只會有一筆，**不疊加**。

| 項目 | 規則 |
|---|---|
| 輕傷 | 輸方進**輕傷**＝人員占用 `medical:injured`（`level=light`）；休養 **1 季**，屬性 **−10%**（乘算，走戰場既有 buff 乘算管線）；與 `doc_spec_0720` 的 WOUNDED 為同一狀態 |
| 重傷 | **連輸才進重傷**：輕傷尚未痊癒時再度在生活單挑落敗（暫定：同一人連續兩場落敗，或輕傷中落敗），升為 `level=severe`；休養暫定 **2 季**，屬性暫定 **−20%**；與輕傷**不疊加，取較重的那一個**（不會 −30%）；重傷也與 0720 的 WOUNDED 取較重者，不疊加 |
| 切磋上限 | 一般切磋（含點到為止）**永不致死，最重＝重傷**；點到為止收手＝`draw`，不受傷 |
| 死鬥 | **只有雙方為宿敵關係才會觸發死鬥**。死鬥輸方走**被擒處置**（`doc_spec_0021` §L，由擒獲方君主處置），**仍然不陣亡**；不是宿敵時不提供死鬥選項。**不存檔的小遊戲死鬥照舊**（模組只回 `ko`，不寫任何後果）|
| 結果分級 | QACT-01 回傳 `outcomeTier`：`draw`／`lightInjury`／`severeInjury`／`captured`（見 `doc_spec_1354` §4.2）；呼叫端依輸方目前傷勢與關係決定最終分級 |
| 誰受傷 | **主角不受傷，主角不死**：主角代理頭落敗只演出暈，不寫任何傷勢；指定家臣代打時，**由該家臣承擔傷勢**；對方為家臣時照常受傷 |
| 伺服器權威 | 單挑的**呈現在客戶端，傷勢結果由伺服器權威**：呼叫端把 `DuelResult` 送伺服器，經 API `occupancy.acquire(kind=medical, sub=injured)`（見 `doc_spec_1248`）寫入，冪等鍵 `duel:<seed>:<季>`；客戶端不直接寫傷勢；單機版走本機 adapter |
| 戰場影響 | **只透過傷勢旗標影響下一場的屬性**（輕傷 −10%、重傷 −20%，取較重者，不疊加）。**不改戰場 HP 與兵力**；兩套單挑規則（生活 Q 頭 `doc_spec_1354`／戰場 `doc_spec_0314`）各自獨立，門檻、回合數互不共用。**戰場 HP 不跨場持久**（每場開場滿血），所以生活單挑剩餘血量**不**換算成戰場開場 HP |
| 傷者出戰 | **輕傷、重傷都能出征與守城，只扣屬性**；`injured` **不放進出征互斥表**（見 `doc_spec_1248` §3）|
| 痊癒 | 休養期滿的季度推進時自動痊癒（傷在季末受傷，從**下一季**起算 1 季，不當季折算）；療傷：去醫館（`mkt_clinic`）看診，輕傷花 20 兩立即痊癒、重傷花 40 兩降為輕傷（暫定，商店框架 SHP）；醫官／華佗照 `doc_spec_0720` 可治 |
| 生活層效果 | 受傷期間改走醫館／自宅／溫泉的偏好（+30）；頭上包頭符號；重傷者拒絕單挑邀約 |
| 次數上限 | 每武將每季被單挑 3 次（見上表）；同一人當季最多被升級一次重傷 |
| 不外溢戰場獎懲 | 生活單挑**不產生**戰場斬將名聲、士氣、晉升、拒絕懲罰，也不計功業；唯一的戰場連結就是傷勢旗標 |
| 用詞 | 本書一律稱**精力（Vitality）**（`doc_spec_0397`、`doc_spec_0573`），不再用「體力」；生活單挑**不扣精力、不扣 HP 持久值**，後果只有傷勢旗標與友誼、心情 |
| 友誼附帶 | 把對方打成傷勢：對方非 Brave 性格友誼 −1（`life_duel_injure`）；之後你送藥或陪看診可補回（`life_visit_clinic` +2）|

### 6.5 搶走正在用的物品 `grab`（使用者原創；11/28 裁決後果看關係）

| 項目 | 規則（PM 暫定）|
|---|---|
| 標的 | 武將的「使用中物品」：資料 `props`（酒壺、書、釣竿、羽扇、武器…）。不是從背包偷，是畫面上他手上那一件（符號旁一個小圖示可點）|
| 做法 | 點使用中物品 → 確認「搶走」→ 判定 → 依關係走三種後果 |
| 判定 | 成功率 = `0.45 + (主角智力 − 對方智力)/100 + 友誼/200`，限 0.1～0.9；對方 `stubbornness` 高再 −10%（11/28 審查：原「機敏、警覺」不是現有屬性，暫以既有的智力代替，不新增屬性；主角智力取主角資料，家臣代打時取代打者）|
| 成功 | 物品**暫借**進主角背包（`inventory.transfer`，標記 `loanedFrom`），之後依下表後果走 |
| 失敗 | 被反制：友誼 −3，心情 −3，主角被「推開」演出（Q 頭彈開）|
| 追逐小劇場 | 成功搶到後有 **25% 機率**觸發：對方 Q 頭追著主角跑約 8 秒（動作系統 `run`、追逐跳字「站住！」），被追上就當場歸還（歸還後按下表關係結算），沒被追上則對方「算了」，物品照下表後果處理 |

**後果看關係（友誼值分三段）**

| 關係 | 反應 | 結算 |
|---|---|---|
| 好友（友誼 ≥ +20）| **笑笑搶回去**：對方哈哈笑著衝過來把東西拿回（物品自動 `transfer` 回對方），頭上「哈」符號＋星 | 友誼 +3（`life_grab_prank_laugh`）、心情 +3、羈絆點 +1 |
| 普通（−19～+19）| 「欸！還我！」要求歸還；主角 3 個時段內點「歸還」| 歸還：友誼 +1；逾時沒還：友誼 −6（`life_grab_overdue`）、心情 −8，需賠禮（送一件他喜歡的物品）才解除 |
| 關係差（友誼 ≤ −20）| **生氣**：吵架符號（閃電），物品立即強制要求歸還 | 友誼 −6（`life_grab_angry`）、心情 −8；該武將當季再被搶 ×2 扣分；對方 1 個時段內拒絕互動 |
| 摯友／結義 | 同「好友」，另外兩人一起大笑 | 羈絆點 +1（`bondPoints`）|
| 仇人 | 同「關係差」，直接吵架 | 友誼 −8 |

| 項目 | 規則 |
|---|---|
| 交換 | 對方（普通以上）可提「換你的東西」：主角挑一件等價物走 `transfer`，成交友誼 +2（`life_grab_swap`）|
| 禁止 | 傳世名器、任務綁定、他人已裝備的核心武裝、被占用中（出征、學府）的武將；主角府邸物不能搶 |
| 次數 | 每武將每季 2 次；同一件物品當季 1 次；每次算 1 次季度互動（6.0）|
| 神秘圖鑑 | 搶到的若是近現代道具，記入「近現代道具冊」且武將會說溜嘴（`doc_spec_1350`）|

### 6.8 抓起放下 `pickPlace`（使用者 11/28 新點子；PM 暫定；延伸玩法見 6.9）

#### 6.8.1 操作

| 步驟 | 規則 |
|---|---|
| 抓起 | **長按 Q 頭 0.35 秒**（小於 0.35 秒仍是點開圓形選單）；手機拇指友善，感應半徑 ≥ 44 像素。抓起時武將腳離地、Q 頭放大 1.15 倍、地面留影子，手指離開前其作息暫停（`lifeClock` 凍結該武將，不丟時段）|
| 拖曳 | 跟著手指移動，頭上符號換成「被拎起」符號（`S_PICKED`，掙扎兩腳晃動）；拖到邊緣自動捲動場景；拖曳中可滑到場景切換鈕上方 0.6 秒換區（只在同一大圖切區，不跨大圖）|
| 熱區提示 | 拖到可放的建築熱區：建築外框亮起（亮度 +20%）；拖到另一位武將身上：目標武將 Q 頭亮圈＋雙方連線虛線；不可放的位置：紅色禁止符號＋手放開會彈回原處 |
| 放手 | 在熱區放手 → 傳送到該場景入口（`sceneEnter` 動畫 0.4 秒）→ 播反應（6.8.2）。在空地放手 → 原地落下站穩，不算放置。在非法位置放手 → 彈回抓起前位置，不扣次數、不冷卻 |
| 取消 | 拖回自己原位置、或按取消鈕（右下角，≥ 44 像素） |
| 高階機／低階機 | 抓起的 Q 頭走單一「拖曳層」節點（重用，不 new），拖曳中場景符號全降為靜態（手機記憶體優先）|

> 版面保留直式彈性：熱區、取消鈕走錨點與 `life-area-maps.json` 區域資料，不寫死橫式。

#### 6.8.2 放到建築：反應演出

放下後取該武將對該場景的**評價**，三級：`love`（喜歡）、`neutral`（普通）、`hate`（討厭），算法：

```
score = affinityScene[sceneId] ?? affinityTag 取該場景 tag 最大值   // 0～100，見 2.1
level = score >= 70 ? love : score <= 25 ? hate : neutral
```

| 評價 | 演出 | 後續 |
|---|---|---|
| `love` | 頭上「開心」符號（星＋哈）＋跳字台詞 1 句（走台詞框架 `pickplace_scene_love`）；Q 頭跳一下 | 該武將接下來 **1 個時段**留在該場景做原本活動（作息被覆寫），心情 +3 |
| `neutral` | 「？」符號，看一圈，台詞「嗯？來這裡做什麼」 | 原地待 1 個時段後回到正常作息，心情 ±0 |
| `hate` | 抱怨符號（汗＋怒氣），台詞抱怨；0.8 秒後**自己走回**原本所在場景（`run`＋跳字「我走了」），性格 `Brave` 加碼罵一句，`Loyal` 對主角不發怒只嘆氣 | 心情 −3；友誼不扣（只是被拎來拎去，主角是在玩）；**連續 3 次**被放進同一討厭場景，該武將 1 個時段拒絕被抓（頭上小「哼」）|
| 特殊 `prop` | 該場景有該武將專屬 `props`（如酒館酒罐）時，`love` 會自動拿起道具，順便觸發稀有舉止（5.8）機率 ×2 | 計入舉止簿 |
| 特殊 `event` | 場景有互動事件表（3.4 `events`）時，`love` 有 20% 機率直接觸發該場景事件（如酒館拼酒）| 走原事件流程，事件的次數與獎勵照該事件規則 |

**生活條件**：場景營業時段（`openSlots`）外放下，建築是關門的：武將站在門口，跳字「打烊了」，視為 `neutral`，且不留在場景（直接回原位）。場景人數已滿（`capacity`）時放下的武將擠在門口，跳字「滿了」，同樣視為 `neutral`。

#### 6.8.3 放到另一位武將身上：相遇聊天

放手對象是**另一位在場景中的武將 Q 頭**（需在同一大場景、在畫面中，不在占用）：

1. **兩人湊在一起**：被抓的武將落在目標旁（`pairSocket`），兩人 Q 頭各自轉頭面對對方（`faceTo`），頭上冒「驚訝」「！」。
2. **判定相遇類型**（取第一個符合的，由 `life-pickplace-meet.json` 定義，見 6.8.7）：夫妻／結緣中 → `couple`；友誼 ≥ +20 → `friend`；友誼 −19～+19 → `acquaint`；友誼 ≤ −20 → `rival`；宿敵／仇人 → `enemy`；雙方都是老友且同一勢力主君以下 → `sworn`（結義時為 `sworn` 加成）。
3. **聊天演出**：兩人中間掛雙人互動符號（5.5，單一元素、占 1 個符號名額）：`couple` 愛心；`friend` 大笑；`acquaint` 對話泡；`rival` 閃電吵架；`enemy` 吵架＋被主角拉開。演出約 6～8 秒，點擊可跳過。
4. **台詞**：走武將台詞共用框架（`dialogue.request`，不自己寫死）。請求參數：`speakerId`、`listenerId`、`topic: "pickplace_meet"`、`meetType`、**性別參數**（說話者性別、聽者性別，用於「兄台／姑娘／夫人」等稱呼與語尾）、`relationTags`（友誼段、是否結義／夫妻／宿敵、同勢力）、`favorability`（友誼值）、`mood`、`scene`（所在場景 id）、`season`、`worldEvent`。聊天 2～3 句交替，台詞由中台跨玩家快取＋遊戲端快取供應；**離線／AI 失敗時用 `life-pickplace-meet.json` 的備援罐頭句**（每 `meetType` ≥ 6 句，含男男、男女、女女、女男四種性別變體）。
5. **後果**：依 `meetType` 結算（下表）；友誼加值一律經 `FriendshipService.add`，伺服器權威。

| meetType | 友誼 | 心情 | 其他 |
|---|---|---|---|
| `couple` | +2（`life_pickplace_couple`）| 雙方 +4 | 羈絆點 +1（每季 1 次）|
| `friend` | +2（`life_pickplace_friend`）| 雙方 +3 | 小機率交換消息（情報 +1，走情報系統）|
| `acquaint` | +1（`life_pickplace_acquaint`）| 雙方 +1 | 初識者有 10% 機率「互相自我介紹」解鎖彼此名冊關係 |
| `rival` | −1（`life_pickplace_rival`）| 雙方 −3 | 主角可點「勸架」：友誼回 +1、心情 −0，需該武將 `stubbornness` < 70 |
| `enemy` | −2（`life_pickplace_enemy`）| 雙方 −5 | 宿敵觸發 `rivalBrawl` 小劇場（見第 10 章勾選項）|

**友誼防刷**：同一對武將（無序）每日（遊戲 1 季內的生活時鐘轉 1 圈為 1 日）只有**第 1 次**相遇加友誼；之後只有演出與台詞，不加友誼；每位武將每季因「被放到別人身上」獲得的友誼總量 ≤ +6（`perSeasonCap` 於 `life-friendship-actions.json` 設定）。

#### 6.8.4 次數與成本（建議，待確認）

| 項目 | 規則 |
|---|---|
| 抓放本身 | **不扣每季 6 次免費互動**（6.0），也不收銀兩：看熱鬧型玩法，應該能自由玩、不用算次數 |
| 相遇加好感 | 只有「放到另一位武將身上」且**友誼有變動**時，才算 1 次互動，從每季 6 次扣（用完可花銀兩買，規則同 6.0）；沒變動的（防刷後的第 2 次）不扣 |

| 被季上限擋下 | 不扣次數、不收銀兩（同 6.0）|
| 抓放冷卻 | 同一武將被抓起放下後 **15 秒（真實時間）** 內不可再被抓（頭上「暈」符號）；同一玩家 60 秒內最多抓 8 次；連續 10 次無效操作（彈回、空地放）暫停 30 秒 |

#### 6.8.6 與生活層其他系統的關係

- **作息**：抓放是覆寫（`lifeClock` override），結束後回到 2.3 正常挑場景；覆寫最長 1 個時段，不改 `life-profile.json`。
- **神秘圖鑑**：把武將放到近現代主題場景（若有）不會觸發說溜嘴；偷聽仍照 5.7。
- **舉止簿**：放進愛好場景提高稀有舉止機率（見 6.8.2）。
- **存檔**：抓放結果（位置覆寫、友誼加減、次數）經伺服器 API；單機版走本機 adapter。位置覆寫只存在生活層暫態，不存檔。
- **情報**：被放到同場景的武將不洩漏情報，除非是 `friend` 相遇的 10% 交換消息。

#### 6.8.8 驗收

1. 長按 0.35 秒抓起、拖曳、放下，手機拇指單手可操作；短按仍開圓形選單。

3. 打烊、滿員場景放下都視為 `neutral`，不扣次數。
4. 放到另一位武將身上：夫妻（愛心）、好友（大笑）、普通（對話泡）、宿敵（吵架）各走一次；台詞經台詞框架，帶性別參數，離線備援四種性別變體都有。

6. 被占用中武將、5 歲以下、傷重者、主角代理頭不能抓；他國訪客可抓但不加友誼。
7. 抓放本身不扣每季 6 次；放到武將身上且友誼有變動才扣 1 次；被季上限擋下不扣。
8. 所有友誼變動經 `FriendshipService.add`；客戶端不直接改值；重新登入後一致。

### 6.9 抓起放下延伸玩法 `pickPlaceExt`（使用者 11/28 本人勾選：6 項全做；數值由 PM 暫定，全放 JSON）

> 來源：6.8 原列 5 個延伸點子，使用者本人勾選全部要做，並新增「放小孩進私塾」「抓小偷給治安官」兩項。本節把「待使用者勾選」轉為正式規格。**只有規格，不含程式**；實作卡由總 PM 另開。

#### 6.9.0 六項總表與共用規則

| 2 | `drinkContest` | 酒館拼酒小遊戲 | 武將 → 武將，或雙方都在酒館 | FRD、RWD（小）、舉止簿 |

**共用規則（六項皆適用，6.8 的限制全部沿用）**

1. **判定順序**：放手後先判定 6.8.3 的 `meetType`／場景，再依下表「觸發條件」看是否進入延伸玩法；條件不符則退回 6.8 原本的相遇聊天或建築反應，不丟錯誤。
2. **友誼防刷（合併上限）**：6.8 基本相遇的「每武將每季 ≤ +6」不變；**延伸玩法另設合計每武將每季 ≤ +4**（`perGeneralSeasonFdCapExt`），兩者互不佔用，總上限 +10。同一對武將（無序）每日（生活時鐘轉 1 圈）對**同一種延伸玩法**只有第 1 次加友誼，之後只有演出與台詞。
3. **次數成本**：沿用 6.8.4——抓放本身不扣每季 6 次；只有「友誼有變動」的那一步才扣 1 次；被季上限擋下不扣。`pat`、`tutorEnroll`、`thiefCatch` 的結果不是武將間友誼，**不扣**每季 6 次，改用各自的每日／每季上限（見各項）。
4. **占用（OCC）**：延伸玩法**不新增占用類型、不寫占用**；被 OCC 占用中的武將不能抓、也不能當放下對象（6.8.5）。一切「停留／自動對練」都是 6.8.6 的 `lifeClock` 覆寫（最長 1 個時段）。出征、學府、閉關、待產者全數排除。
5. **伺服器權威**：所有友誼、經驗、獎勵、報名經伺服器 API，單機版走本機 adapter；客戶端只播演出。位置覆寫不存檔。
6. **台詞**：全部走台詞共用框架 `dialogue.request`，共用參數同 6.8.3（`speakerId`、`listenerId`、`relationTags`、`favorability`、`mood`、`scene`、`season`、`worldEvent`），**必帶性別參數**（`speakerGender`、`listenerGender`，用於稱呼與語尾；幼童與小偷也要帶性別）。離線備援罐頭句每個 `topic` ≥ 6 句，含 `mm／mf／ff／fm` 四種變體，進 `life-pickplace-ext.json` 的 `fallbackLinesKeyPrefix`（i18n key，不存中文字面）。
7. **性別與年齡一致性**：稱呼與演出以性別參數決定（例如「大叔／大姐」「小弟弟／小妹妹」），不寫死男性。懷孕待產、傷重者不能參與（6.8.5）。
8. **他國訪客**：只做演出，不加友誼、不給獎勵、不計報名；`thiefCatch` 若治安者是訪客則不成立（只有我方家臣可擔任）。

#### 6.9.1 宿敵大吵 `rivalBrawl`

| 項目 | 規則 |

#### 6.9.8 延伸驗收

1. **宿敵大吵**：宿敵放到一起出現閃電連線與【勸架】【煽風】；勸架成功友誼 +1，煽風成功只發單挑邀約（由 6.4 接手）；6 秒不選視為放任；煽風每季 ≤ 2 次；`stubbornness` ≥ 90 勸架必失敗。
2. **拼酒**：兩人在酒館出現 5 拍拼酒；贏家心情 +3、雙方友誼 +2（同日同對只加 1 次）；輸家微醺下時段回家睡；未成年、`abstain` 者進不了拼酒。
3. **摸頭**：成年武將放到 0～4 歲幼童身旁觸發；親人親近值 ×2；家長感謝每季 1 次；幼童本身不能被抓、5～14 歲孩子才可被抓。
4. **媒人**：符合 FEM-03 條件才出現紅線與【去提親】；不符合不洩漏原因；點【去提親】進既有姻緣流程並預選該對，無任何新分支；`matchmakerBonus` 有上限 +0.15。
5. **對練**：演武場／兵營放進兩人對練 1 時段，各得小量經驗與疲勞旗標（只影響生活層心情）；每武將每季練兵經驗 ≤ 6 次、友誼 ≤ +3。
6. **私塾**：5～14 歲孩子放到已開班武將旁，依 `p_enroll` 成功後發「試聽邀請」，玩家點【報名】才扣學費（減免 20%）；沒開班、班級已滿、0～4 歲、15 歲以上都不觸發；每老師每季 ≤ 3 位。
7. **小偷**：治安 ≥ 80 不出現小偷；`UNREST` 起依機率出現，每時段 ≤ 1 隻；小偷放到太守／縣令／治安巡查中／帶 `guard` tag 的校尉身上才判定破案；被占用者不算；成功發獎池與治安 +1，每日 ≤ 2 次、每季 ≤ 6 次；失敗小偷可再放一次。
8. **共通**：六項台詞皆走台詞框架且帶性別參數，離線備援四種性別變體齊全；友誼變動全經 `FriendshipService.add`；延伸友誼合計每武將每季 ≤ +4；不寫 OCC；重新登入後結果一致。

## 9. 驗收

1. 同一位武將在同一時段、同一季、同一世界狀態下，用同一 `seed` 挑出同一個場景（可重現）。
2. 改變 8 因素任一個，該武將前 3 名場景排序有預期變化（張飛生小孩後育嬰房進前 5；諸葛亮冬天茶館升高）。
3. 50 種符號全部能在符號預覽頁播放；睡覺飄 ZZZ、練武武器飛舞、喝酒酒罈傾倒＋紅暈＋酒香三項肉眼可辨。
4. 高階機 22 個符號同時動不掉幀；低階機 8 個，其餘靜態。
5. 搶物品：成功、失敗、追討、歸還、超時各走一次，友誼、心情、物品庫存都正確變化，重新登入後狀態一致。
6. 送禮、搶物品、單挑全部經由 `FriendshipService.add`，客戶端不直接改值。
7. 偷聽出現說溜嘴句，神秘圖鑑言論頁收錄。
8. 第 7 次互動起要扣銀兩，價格依序 5、7、9…最高 15；換季後恢復 6 次免費。
9. 單挑輸方進輕傷（1 季、屬性 −10%），連輸進重傷（−20%，不與輕傷或 0720 WOUNDED 疊加）；傷者仍可出征；主角代理頭落敗不寫傷勢；只有宿敵死鬥輸方會被擒，全程沒有任何武將陣亡；傷勢經伺服器 API 寫入。（已與戰場專家對齊（11/28 審查））
10. 搶物品：好友笑笑搶回、普通歸還、關係差生氣各走一次，追逐小劇場至少出現一次。
11. 抓起放下：依 6.8.8 八項驗收。
12. 抓起放下延伸玩法：依 6.9.8 八項驗收（宿敵大吵、拼酒、摸頭與媒人、對練、放進私塾、抓小偷、共通）。

# Q版社會總規格書（QSOC-01）

> **規格代碼**：`QSOC-01`　**任務卡**：PROG-2-10188　**裁決來源**：使用者 2026-11-27 本人（武將生活化；「三國版模擬市民」；第一張先做市井大街；場景美術插隊由 Codex 先畫；Q 版三套系統＋最上層 Q 版社會）
> **狀態**：規格草案（只有規格，不含程式；數值是 PM 暫定）
> **定位**：「Q 版社會」四份規格的**最上層**：把動作、表情、生活三套系統組起來，再加情報系統與場景切換。本書包含：架構、情報系統、場景切換 UI、市井大街第一版範圍、給 Codex 的美術需求、共用框架評估、裁決紀錄。
> **下層三份（各自獨立可重用）**：Q版動作系統與動畫管理器（QACT-01）、Q版表情系統（QFACE-01）、Q版生活系統（QLIFE-01）
> **依賴**：共用框架總綱（`doc_spec_1182`）、大廳任務情報度（`doc_spec_0454`，與本書情報**分開**，見第 5.5 節）、神秘圖鑑總規格書（`doc_spec_1350`）、說溜嘴（`doc_spec_1348`）、每季小報（`doc_spec_1345`）、人員占用（`doc_spec_1248`）、UI 保留直式彈性（使用者長期裁決）、手機記憶體優先（使用者長期裁決）、大廳右下角「下一季」按鈕（`裁決 11/23`）

## 0. 結論（先看這段）

1. 「Q 版社會」＝**三套獨立系統＋最上層組合**，各有獨立 doc id、資料檔、介面，可單獨重用（例如動作系統給戰場以外的小遊戲用）：
   - 動作（QACT-01）：走路、跳、單挑碰撞、揮武器、跳字、血條；**動畫管理器是共用底層**。
   - 表情（QFACE-01）：眼睛變化、張嘴、紅暈，用共用部件圖集＋每位武將錨點 JSON（不用逐人畫全套表情）。
   - 生活（QLIFE-01）：喜好、作息、72 個場景、動態符號 50 種、互動、搶物品、送禮、稀有舉止。
   - 社會（本書）：組合三者，加情報系統與場景切換。
2. 7 張 2.5D 大圖＋5 個節慶疊層；市井大街先做（使用者裁決），場景美術由 Codex 先畫（第 10 章寫需求）。
3. 要找到武將在哪，靠**既有的情報系統**養成（使用者 11/28 裁決：不另開新線）：同一個玩家情報值 `intel`（0～100）升高，大地圖情報與生活找人一起變強；低級只看到模糊「?」。
4. 場景切換：任一場景可直達任一場景（地圖、最近、收藏、搜尋武將直接跳到他所在的場景），拇指單手可操作。
5. 共用框架評估（第 12 章，**使用者 11/28 裁決**）：Q 版呈現層只當「呈現底層」，**不升框架、不需要伺服器 API**。收藏／圖鑑（COL）已是第 9 套框架，本書不再新增框架。

## 4. 場景切換 UI

### 4.1 原則

1. **任一場景可直達任一場景**，不必先走回大廳或先經過某個區。
2. 單手拇指操作：主要按鈕在下半部。
3. UI 全部走**錨點＋相對比例＋區域資料檔**（`life-ui-layout.json`），不寫死橫式，保留日後改直式或手機橫式（使用者長期裁決）。
4. 文字走 i18n 四語系，圖示可換主題（使用者長期裁決）。
5. 未做美術的場景可以進入，顯示通用底圖＋「施工中」標籤，不擋切換。

### 4.2 元件

| 元件 | 位置（錨點） | 說明 |
|---|---|---|
| **常駐地圖鈕** | 左下角（`anchor: bottomLeft`，距邊 0.03 螢幕寬）| 圓形 64 像素等效，單點展開「場景面板」。刻意放左下：右下角已被大廳「下一季」鈕占用（`裁決 11/23`），生活層沒有該鈕，但兩邊拇指都留位置；慣用右手玩家可在設定改左右鏡像 |
| **場景面板**（底部抽屜） | 底部對齊，高度 60% 螢幕，可下拉收起 | 四個分頁：地圖、最近、收藏、找人 |
| 分頁「地圖」 | 面板內 | 先顯示 7 個區（大圖）的圖示格（3×3 內），點區後列出該區場景（單欄清單，每列 ≥ 56 像素高）；區內有「一鍵進入」|
| 分頁「最近」 | | 最近去過 8 個場景（依時間，含時段）|
| 分頁「收藏」 | | 玩家釘選的場景，上限 12，長按場景列加入／移除 |
| 分頁「找人」 | | 搜尋框（可輸入武將名、拼音、勢力、官職）→ 結果列表，每列顯示武將頭像＋「在哪」（見 4.3）；點結果直接跳到他所在場景，並讓鏡頭對焦到他 |
| 時段切換 | 右上角（`anchor: topRight`）| 顯示目前時段與季節，點開可手動切時段 |
| 同行者列 | 左上角下方 | 同行武將頭像，最多 2 位 |
| 返回大廳 | 面板底端或左上角 | 一鍵回大廳 |

> 直式版：面板改為整幅底部 70%，分頁在面板頂端，其他元件相對比例不變。

### 4.3 搜尋武將直接跳到所在場景

| 情報等級 | 顯示「在哪」 | 可跳 |
|---|---|---|
| Lv0 | 全部「?」 | 只能進「?」的模糊所在：只提示「這個時段他在城裡」，不給位置|
| Lv1 | 大區名稱（官署區、市井大街…）| 跳到該大圖，鏡頭置中 |
| Lv2 | 場景名稱＋「?」符號（不知在做什麼）| 跳到該場景 |
| Lv3 | 場景名稱＋頭像 | 跳到並對焦 |
| Lv4 | 同 Lv3＋正在做什麼（符號）| 同上 |
| Lv5 | 同 Lv4＋下一個時段預測 | 同上 |

特例：**熟人例外**——友誼 ≥ +30 或有羈絆的武將，顯示等級比自己情報等級高 1 級（最高 Lv5）。這讓早期玩家至少找得到熟人。

### 4.4 切換流程與成本

1. 點場景 → 0.25 秒淡出 → 載入 → 0.25 秒淡入。
2. 快取：最近 2 張大圖保留在記憶體，其餘釋放；預載「最近」第 1 筆。
3. 互動成本見 4.4.1：每季有免費互動次數，用完可花銀兩；**切換場景本身不耗任何東西**。
4. 切換歷史寫入「最近」；收藏存本機設定並走存檔 API。

### 4.4.1 每季互動次數（使用者 11/28 裁決）

| 項目 | 規則（PM 可調） |
|---|---|
| 範圍 | 生活層的主角互動：搭話、送禮、邀約同行、切磋單挑、搶物品、偷聽想法；切換場景、看畫面、點符號只看不算 |
| 每季免費次數 | **6 次**／遊戲一季（換季時重置，由時間發動機的換季事件觸發；不看真實日，也不看生活時鐘轉一圈）|
| 用完之後 | 可以花**銀兩**（家族私房，不是金）買額外互動：第 7 次 5 兩，之後每次 +2 兩，單次上限 15 兩；每季最多額外買 12 次 |
| 走哪個框架 | 商店框架（SHP）：商品 `life_extra_interaction`；扣款走錢包，次數是每季重置的計數器（寫在伺服器權威的季度狀態，單機走本機 adapter）|

| 資料檔 | `life-interaction-quota.json`：`{ freePerSeason, extraPriceBase, extraPriceStep, extraPriceCap, extraSeasonMax }`（`freePerSeason` 預設 6，換季重置，不再有 `resetHour`） |

## 5. 情報系統（併入現有情報系統，使用者 11/28 裁決）

### 5.1 定位

**不另開新線**。遊戲現有的玩家情報值 `intel`（整數夾在 0～100，見 `doc_spec_0460` `hallPlayerOf`，累積自監獄審訊每季產出，見 `doc_spec_0506`；大廳任務牆可見性與任務情報度見 `doc_spec_0454`）就是唯一的情報養成線。**同一個情報值升高，大地圖情報（任務牆、軍事任務品質）和生活找人（武將在哪、做什麼、想什麼）一起變強**。

| 項目 | 規則 |
|---|---|
| 唯一數值 | 玩家情報值 `intel`（0～100），不新增「人事情報點」、不新增第二條階梯 |
| 生活層等級 | 由 `intel` 換算成 Lv0～Lv5（見 5.2），純顯示用，不另存 |
| 不併的 | 單場戰前偵查值（場景戰法 `Required_Intel_Value`，`doc_spec_0039`／情報雙門檻模型）是「這一場仗偵查到多少」，沿用原規則，不跟 `intel` 混；他國 AI 的情報值上限（`INTEL_CAP`）也是它自己的 |
| 與任務情報度 | 大廳任務的「揭露度 %」（`doc_spec_0454`）仍是每個任務各自的偵察進度；它跟 `intel` 的關係維持原規則，本書不改 |

### 5.2 等級與每級看得到什麼

換算（PM 暫定，`life-intel-levels.json`）：

| 等級 | `intel` 門檻 | 生活層看得到什麼 |
|---|---|---|
| Lv0 | 0～9 | 場景裡只看到模糊人影，頭上「?」；找人只回「這個時段他在城裡」|
| Lv1 | ≥ 10 | 知道武將在哪個**大區**；場景內只看到人影＋「?」 |
| Lv2 | ≥ 25 | 知道在哪個**場景**；人影帶輪廓，不知道是誰 |
| Lv3 | ≥ 45 | 看到**是誰**（頭像＋名字）|
| Lv4 | ≥ 65 | 看到**在做什麼**（動態符號）；可偷聽想法 |
| Lv5 | ≥ 85 | 看到**下一時段預測**去哪（使用者 11/28 裁決：不加偷聽說溜嘴機率，說溜嘴機率一律照 `doc_spec_1348`）|

> 自家家臣的身分永遠可見（臉與名不受情報等級限制，使用者 11/28 裁決）；情報等級只限制家臣的**位置與活動**：Lv0～2 於場景內不顯示其活動符號，也無法查詢或預知他在哪個場景。
>
> 場景內的 Q 頭顯示：Lv0～2 的**非自家**武將（訪客、他國遊歷者）畫成「剪影＋?」，仍會走動（維持社會熱鬧感），但**不暴露身分與活動**；Lv3 顯示臉與名；Lv4 才顯示頭上符號；自家家臣一律顯示臉與名，其餘依上述位置與活動規則。

### 5.3 怎麼升

保留既有來源（監獄審訊每季產出等，數值不動）。生活層**新增**的來源也入同一個 `intel`，走獎勵框架 `reward.grant`（貨幣 `intel`；11/28 審查：該貨幣種類要在 `doc_spec_1247` 補登記為情報值資源，累計的小數寫在 `hallPlayerOf` 的 `rawIntel`，取整規則沿用 `doc_spec_0460`），每項有每季上限防刷（PM 暫定，單位為 `intel` 點，可小數，累計後取整）：

| 新增來源 | 每次 | 每季上限 |
|---|---|---|
| 客棧聽八卦（符號 S29 互動）| +0.5 | 3 |
| 讀每季小報（書肆）| +1 | 1 |
| 首次到達某場景 | +0.2 | 3 |
| 眼線（花銀兩請客棧、書肆、驛站老闆當眼線，每處一次性設施）| 每季被動 +1／處 | 3 處 |
| 軍師「洞察」技能、家臣「間諜」專長 | 每季被動 +1 | 1 人 |
| 任務、事件獎勵 | 依任務 | — |

`intel` 不衰減，超過 100 夾回 100。資料檔：`life-intel-sources.json`、`life-intel-levels.json`。

### 5.4 武將端影響

| 條件 | 效果 |
|---|---|
| 對單一武將的熟悉度（友誼 ≥ +30 或有羈絆） | 顯示等級 +1（上限 Lv5）|
| 武將 `sociability` 高 | 更容易被看到（站在大街中心路徑）|
| 武將主動躲避（友誼 ≤ −20 且避開主角） | 顯示等級 −1（躲你）|
| 世界大事件 | 戰爭時軍事區自動顯示 +1 級（大家看得到烽火）|

## 12. 共用框架評估（使用者 11/28 裁決已定）

依共用框架總綱第 3 章判準：「兩處以上出現類似功能」「差異可只用設定表達」，且框架要有共通 API 與伺服器權威。

| 候選 | 重複處 | 是否需要共通 API／權威 | 結論 |
|---|---|---|---|
| Q 版呈現層（動畫管理器、動作、表情、符號） | 戰場（跳字、血條、受擊）、大廳小人（`wanderCore`）、生活層、單挑小遊戲、彈窗頭像表情 | **呈現本身不需要**（客戶端呈現）；**單挑的傷勢結果不在此列：呈現在客戶端、傷勢結果由伺服器權威**（已與戰場專家對齊（11/28 審查））| **使用者 11/28 裁決：只當呈現底層，不升框架、不需要伺服器 API** |
| 社會（情報、場景切換） | 只有生活層 | 情報值沿用既有 `intel` API | 不抽，歸生活／社會包裝 |
| 收藏／圖鑑（COL） | 寶物、虎符名錄、血統、言論、神秘圖鑑、舉止簿 | 要（收集度、獎勵）| **已是第 9 套共用框架**（使用者告知）；舉止簿掛在它底下 |

**結論**：

1. Q 版呈現層設為**呈現底層（PRS：Presentation Foundation）**，與「共通底層工具層（FND）」並列：包含動畫管理器、Q 頭演員池、動作片段庫、臉部系統、符號系統；位置 `assets/scripts/shared/presentation/`，零依賴框架，戰場、大廳、生活層都能引用，不放進任何玩法目錄。**不新增框架編號、不新增 API。**
2. 框架編號現況：1 商店、2 庫存、3 任務、4 獎勵、5 技能、6 劇情、7 人員占用、8 友誼、**9 收藏／圖鑑（COL）**。若日後 Q 版呈現層真要升框架，會是**第 10 套**；目前不升。
3. 生活層新增的 `life_` 友誼行為、每日互動次數（商品 `life_extra_interaction`）、情報來源都走既有框架與既有 API，本書不新增 API。
4. 總綱 shard-d 候選 H 已改為「已裁決：不升框架」。

# Q版表情系統規格書（QFACE-01）

> **規格代碼**：`QFACE-01`　**任務卡**：PROG-2-10188　**裁決來源**：使用者 2026-11-27 本人（Q 頭表情：每位武將至少會換眼睛表情、會張嘴；評估共用貼圖遮罩或 shader）
> **狀態**：規格草案（只有規格；數值是 PM 暫定；技術方案由 PM 決定，不列待裁決）
> **定位**：「Q 版社會」四份規格的第 2 份。**獨立可重用**：任何顯示 Q 頭的地方（大廳小人、單挑、彈窗頭像、小遊戲）都能用。
> **姊妹篇**：Q版動作系統與動畫管理器（QACT-01）、Q版生活系統（QLIFE-01）、Q版社會總規格書（QSOC-01）
> **依賴**：動畫管理器（QACT-01，共用底層）、彈窗武將頭像與台詞規格書（`doc_spec_1343`，頭像表情若要共用本書）、Codex 武將四件組（大頭件）

## 0. 結論（先看這段）

1. **目標**：每位武將不用另外畫一整套表情，只靠「一張共用的眼嘴部件圖集」＋「每位武將一份臉部錨點 JSON」，就能換眼睛、張嘴、紅暈。
2. **建議方案：方案 A「空臉底圖＋共用部件疊加」**，眨眼、瞇眼靠換部件幀＋縮放，不靠 shader。理由：合批友好、Cocos 3.x 不需自訂 effect、手機成本最低（見第 4 章比較）。
3. **前提**：武將的 Q 大頭要有一個「空臉版」（沒畫眼睛嘴巴，或眼嘴區塊用乾淨膚色）。這是給 Codex 的新增件，本書第 6 章寫需求。已畫完含眼嘴的舊大頭，用「膚色蓋片」暫時過渡。
4. 表情只管臉。身體動作交 QACT-01，兩者並行播放。

## 1. 表情要有哪些

### 1.1 眼睛（至少 8 種）

| id | 說明 | 做法（方案 A） |
|---|---|---|
| `eye_open` | 睜眼，預設 | 部件幀 |
| `eye_blink` | 眨眼（閉） | 部件幀，0.10 秒 |
| `eye_squint` | 瞇眼（得意、算計） | 部件幀（弧線） |
| `eye_happy` | 笑眼（^ ^） | 部件幀 |
| `eye_angry` | 怒目（內側下壓） | 部件幀 |
| `eye_sad` | 垂眼、含淚 | 部件幀＋小水珠 |
| `eye_wide` | 驚訝瞪大 | 部件幀，放大 1.15 倍 |
| `eye_dizzy` | 暈（漩渦／叉叉） | 部件幀＋旋轉 |
| `eye_half` 半睜（睏）、`eye_heart` 愛心眼、`eye_side` 側目 | 預設表情 `drunk`／`sleepy`／`love`／`shy` 會用到，**屬必備，不是選配**（11/28 審查） | 部件幀 |
| （擴充）`eye_star` 星星眼 | | 部件幀 |

> 預設表情表（1.4）內的眼嘴 id 省略 `eye_`／`mouth_` 前綴（`happy` ＝ `eye_happy`）。必備眼 11 種、必備嘴 8 種（見 1.2）。

### 1.2 嘴巴（至少 6 種）

| id | 說明 |
|---|---|
| `mouth_closed` | 閉嘴，預設 |
| `mouth_open_s` | 微張（說話小） |
| `mouth_open_m` | 張嘴（說話中） |
| `mouth_open_l` | 大張（大笑、吶喊） |
| `mouth_smile` | 微笑 |
| `mouth_frown` | 不悅下彎 |
| `mouth_o` 驚訝 O 形、`mouth_wavy` 慌張波浪 | 預設表情 `surprised`、`dizzy` 用到，**必備**（11/28 審查） |
| （擴充）`mouth_tongue` 吐舌 | |

說話時嘴巴在 `closed → open_s → open_m` 之間用節拍切換（每 0.12～0.2 秒換一幀，隨台詞長度），不做真口型同步。

### 1.3 臉部附加

| 附加 | 說明 |
|---|---|
| 紅暈 | 兩團半透明圓；喝酒、害羞、發燒。強度 0～1 控制透明度 |
| 汗滴、青筋、淚珠 | 小部件，掛在固定錨點，歸「情緒標記」 |
| 眉毛（選配） | 第二版；先用眼睛部件內含眉形 |

| 預設 | 眼 | 嘴 | 附加 |
|---|---|---|---|
| `neutral` | open | closed | — |

| `sad` | sad | frown | 淚珠 |

| `sleepy` | half | closed | — |

## 2. 資料格式

### 2.1 每位武將的臉部錨點檔

建議路徑：`assets/resources/data/q-face-anchors.json`（一檔全武將，按 id 查；大量後可依勢力分檔）。座標以**大頭圖左上為原點、單位為大頭圖寬度的比例（0～1）**，這樣換圖尺寸不必改資料。

```json
{
  "schema": "q-face-anchors.v1",
  "defaults": { "eyeScale": 1.0, "mouthScale": 1.0, "blushScale": 1.0, "partSet": "std_male_a" },
  "generals": {
    "zhang_fei": {
      "headTex": "q-head/zhang_fei",
      "blankFace": true,
      "partSet": "std_male_b",
      "eyeL":   { "x": 0.36, "y": 0.52, "rot": 0, "scale": 1.05 },
      "eyeR":   { "x": 0.64, "y": 0.52, "rot": 0, "scale": 1.05 },
      "mouth":  { "x": 0.50, "y": 0.72, "scale": 1.10 },
      "blushL": { "x": 0.28, "y": 0.62, "scale": 1.0 },
      "blushR": { "x": 0.72, "y": 0.62, "scale": 1.0 },
      "sockets": {
        "symbol":     { "x": 0.50, "y": -0.10 },
        "bubble":     { "x": 0.85, "y": 0.05 },
        "weaponHand": { "x": 1.00, "y": 0.60 }
      },
      "skinTint": "#E8B896",
      "eyeColor": "#2A1A12",
      "flags": { "hasEyepatch": false, "hasBeard": true, "faceTilt": 0 }
    },
    "xiahou_dun": {
      "headTex": "q-head/xiahou_dun",
      "blankFace": true,
      "eyeL": { "x": 0.36, "y": 0.52, "scale": 1.0, "disabled": true },
      "flags": { "hasEyepatch": true, "eyepatchSide": "L", "asymmetric": true }
    }
  }
}
```

要點：

1. `eyeL`、`eyeR`、`mouth` 必填；`blush` 缺省取 `eye` 下方預設偏移。
2. **眼罩、獨眼、長鬚**這類特徵走 `flags`＋`disabled`（夏侯惇左眼一律蓋住，沿用使用者 11/17 裁決「眼罩左眼」）。左右不對稱的特徵要設 `flags.asymmetric: true`：動作系統對這類頭**不做水平翻轉**（QACT-01 3.1 `faceFlip`），否則眼罩會跑到右邊，違反本書驗收 3。
3. `sockets` 的符號、泡泡、武器掛點座標同檔，QACT 與 QLIFE 共用，不另開檔。
4. `partSet` 指定眼嘴部件風格（男、女、老、少、猛將等），共用圖集裡每組風格一套部件。

### 2.2 共用部件圖集

| 項目 | 規格 |
|---|---|
| 檔案 | `q-face-parts.atlas`（1 張，≤ 512×512） |
| 內容 | 每個 `partSet` 11 眼＋8 嘴（第 1.1、1.2 節必備項）＋紅暈＋少量標記；共 6 組風格上限（男、女、少年、老者、猛將、文士）。容量若 512×512 放不下，可拆成 2 張（合計壓縮後仍 ≤ 0.5 MB），不降低風格組數 |
| 色彩 | 眼嘴線條用**黑白灰通道圖**（alpha＋灰階），執行時用 `Sprite.color` 乘上 `eyeColor`；紅暈用單張白圓乘紅色 |
| 風格 | 單純、粗線條，跟全遊戲簡單單色圖形風格一致（兵種符號同一套美術語言） |

## 3. 執行方式（方案 A 細節）

臉部由 5 個子節點組成（QACT-01 第 6 章節點預算內）：`eyeL`、`eyeR`、`mouth`、`blushL`、`blushR`（錨點檔左右眼、雙頰各自定位，所以各一節點；眼罩 `disabled` 的那一邊節點 inactive）。

| 動作 | 做法 |
|---|---|
| 眨眼 | `eye_open → eye_blink → eye_open`，0.10 秒；間隔 2.5～6 秒隨機（確定性亂數，每人錯開） |
| 瞇眼、笑眼 | 換部件幀，加 0.15 秒縮放過渡 |
| 瞪大 | `eye_wide` 幀，縮放 1.15 倍 0.1 秒彈出 |
| 張嘴 | 換 `mouth_*` 幀；縮放 Y 在 0.9～1.1 之間輕彈 |
| 紅暈 | `blush` 節點透明度 0～0.8，0.3 秒淡入淡出；酒量一路升時跟 `drunkLevel` |
| 看向旁邊 | 眼部件整體偏移 ±0.02 頭寬，0.15 秒 |
| 受傷、暈 | 白閃（Sprite.color 瞬間）＋ `eye_dizzy` |

臉部不用逐幀動畫，只是「換幀＋縮放＋透明度」，全由動畫管理器的「臉部演員」登記。

### 3.1 心情變色（使用者延伸，全收）

| 心情 | 頭圖顏色（Sprite.color 乘色） | 臉部附加 |
|---|---|---|
| 開心 | 提亮：`#FFFFFF`，加 1.05 倍亮度的一層加色（`brightBoost` 0.06） | 笑眼，偶爾冒小星 |
| 平靜 | `#FFFFFF` | 無 |
| 不爽 | 偏紅：`#FFC8BC` | 青筋，怒目 |
| 鬱悶 | 偏灰：`#B8BFC9`，影子變淡 | 垂眼，頭上掛雲符號 |

不用 shader，用 `Sprite.color` 乘色即可（灰色只是偏灰藍，不是真去飽和，這個取捨 PM 接受）。真去飽和要 shader，列為第二階段選配。

## 4. 方案比較（技術方案，由 PM 決定）

| | A. 空臉底圖＋共用部件疊加（建議） | B. shader 偏移／遮罩 | C. 每位武將畫整套表情 |
|---|---|---|---|
| 做法 | 頭圖不含眼嘴；眼嘴從共用圖集依錨點疊上去，換幀換表情 | 頭圖含眼嘴；shader 取眼睛區 UV 做偏移縮放（眨眼、瞇眼），嘴巴區用遮罩切開合貼圖 | 每位武將另畫 8 眼 × 6 嘴 × 全臉變化 |
| 眨眼、瞇眼 | 換幀，簡單 | UV 縮放 Y，可行，但眼睛形狀是原圖畫的，閉眼只能壓扁 | 最自然 |
| 張嘴 | 換 6 種嘴幀，容易 | 要另備一張「嘴內部」貼圖與遮罩，每位武將一份 | 最自然 |
| 紅暈 | 疊一張圓 | 可在 shader 加色，但仍要區域遮罩 | 要畫 |
| 擴充新表情 | 只加部件幀，所有武將立刻能用 | 新表情要新 shader 分支或新遮罩 | 每人都要補畫 |
| 繪製量 | 每位武將只多 1 張空臉＋1 份 JSON；共用 1 套部件圖集 | 每位武將要 1 張眼嘴遮罩圖＋調參 | 每人 14 張以上 |
| 繪圖流程風險 | 要 Codex 出空臉版（舊圖需補） | 不改舊圖，但遮罩要逐人做 | 最重 |
| Cocos 3.x 成本 | 零自訂 effect；5 個 Sprite 同圖集合批 | 每張頭一個自訂 material，**打斷合批**（每顆頭 1 個 draw call），24 顆頭多 24 次 | 圖多，記憶體大 |
| 手機記憶體 | 共用 1 圖集 ≤ 0.25 MB（壓縮後） | 每人多 1 張遮罩圖 | 每人 14 張，最大 |
| 手機 GPU | 低（Sprite 合批） | 中（多 material、多 pass） | 低 |
| 風格一致 | 全員表情同一語言，好管 | 保留原畫風，最像原圖 | 最好，但最貴 |
| 可行性風險 | 空臉件要補；舊頭可用蓋片過渡 | 嘴巴「開合」做不乾淨，易穿幫 | 量產做不完 |

### 建議

1. **主方案 A**。理由：成本最低、擴充最快、手機合批最友好、符合「工具鏈不是雕刻、要能量產」的長期裁決。
2. **舊頭過渡**：已有含眼嘴的大頭，先用「膚色蓋片」（`blankPatch`，在錨點處蓋一塊膚色圓角矩形 Sprite，用 `skinTint`）再疊部件；能接受粗糙的先上，Codex 逐步補空臉版後把 `blankFace` 改 `true` 並移除蓋片。
3. **只在需要時再加 B**：極少數特寫（單挑勝利大頭、立繪）若要精緻眨眼，可選配單一 shader（眼睛區 UV 縮放），僅限同時 ≤ 2 顆頭，不進場景群像。
4. **不做 C**（量產不可行）。

### 成本估算（方案 A）

| 項目 | 數字（暫定） |
|---|---|
| 每顆頭額外節點 | 5（eyeL、eyeR、mouth、blushL、blushR） |
| 每顆頭額外 draw call | 0（與頭、影子、符號共用或相鄰合批；實測要驗） |
| 圖集記憶體 | 部件圖集 512×512 壓縮約 ≤ 0.25 MB |
| 每幀 CPU | 24 顆頭同時換幀 ≤ 0.2 ms（多數幀沒有表情變化，只在事件時更新） |
| 眨眼計時 | 管理器統一排程，不在每顆頭各自 schedule |

## 5. 介面（草案）

```ts
interface IQFace {
  setPreset(h: FaceHandle, preset: string, fadeSec?: number): void;
  setEye(h, eyeId: string): void;
  setMouth(h, mouthId: string): void;
  setBlush(h, strength: number): void;
  setMoodTint(h, mood: 'happy' | 'calm' | 'angry' | 'gloomy'): void;
  speak(h, durationSec: number, intensity?: 'low' | 'mid' | 'high'): void; // 自動切嘴幀
  setAutoBlink(h, enabled: boolean): void;
}
```

資料來源：`q-face-anchors.json`、`q-face-parts.atlas`、`q-expression-presets.json`（第 1.4 章表）。

## 6. 給 Codex 的美術需求（臉部件）

> 與市井大街場景需求（QSOC-01 第 10 章）分開，這裡只管表情部件。

1. **空臉大頭**：每位武將的 Q 大頭多一張版本，眼睛、嘴巴、紅暈位置完全空白（乾淨皮膚、保留鬍鬚、眉毛、眼罩、頭盔等特徵），尺寸同現有大頭。優先順序：市井大街常出現的武將、六大名將。
2. **共用眼嘴部件**：6 組風格 × 11 眼 × 8 嘴＋紅暈＋標記，單色線條（黑白灰），統一線寬，圖集 512×512。
3. 部件視覺要跟兵種符號一致的簡單單色語言。
4. 每位武將的錨點 JSON 由我們用工具先自動估（臉部中心偵測），再由企劃人工校。

## 7. 驗收

1. 同一套部件在 5 位風格迥異的武將（張飛、諸葛亮、呂布、大喬、關羽）上換表情，看起來都對位、不穿幫。
2. 24 顆頭同時眨眼、說話，幀率不低於目標。
3. 夏侯惇左眼始終蓋住；不因換表情露出左眼。
4. 新增 1 種表情只改部件圖集與預設表 JSON，不改程式。
5. 方案 A 合批實測：場景內臉部部件與頭、影子的 draw call 增量 ≤ 2。

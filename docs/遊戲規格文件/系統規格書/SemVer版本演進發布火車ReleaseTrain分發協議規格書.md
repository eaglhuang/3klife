# 3KLife SemVer版本演進發布火車ReleaseTrain分發協議規格書

> **規格代碼**：SPEC-OPS-RELEASE01  
> **關聯 WBS**：RELEASE-TRAIN-01（SemVer 版本演進發布火車分發協議）  
> **文件版本**：v1.0.0 (單一真相來源，無補丁整併版)  
> **所屬系統**：全域架構總控（Global Architecture & Index Governance）

---

## 1. 核心宗旨與設計哲學

為使遊戲版本演進兼具敏捷節奏與極致穩定性，杜絕熱更新版號混淆、存檔遷移斷裂與未測代碼流出，本規格書制定**語意化版本（SemVer 2.0.0）三段階梯**與**雙週發布火車（Release Train）管理協議**。

---

## 2. 語意化版本階梯與分發管道矩陣

版本號格式嚴格遵循 `v{Major}.{Minor}.{Patch}`：

```
+-------------------------------------------------------------------------------+
| Major (主版號)  | 破壞性架構變更、引擎大升級 | 嚴禁熱更，強制商店全量安裝下載 |
+-----------------+----------------------------+--------------------------------+
| Minor (次版號)  | 新武將、新玩法、大型活動   | 每雙週開班，走 Asset Bundle 差異下載 |
+-----------------+----------------------------+--------------------------------+
| Patch (補丁號)  | 緊急數值調優、嚴重 Crash 修復 | 隨時開車，走輕量腳本熱更 (<5MB) |
+-------------------------------------------------------------------------------+
```

### 2.1 版本變更判定樹

1. **是否有不相容的存檔結構破壞或原生 SDK 升級？**
   - 是 $\rightarrow$ 升級 **Major**（如 `v1.4.2` $\rightarrow$ `v2.0.0`），觸發強更導流彈窗。
2. **是否有向下相容的新玩法功能或資料表結構擴充？**
   - 是 $\rightarrow$ 升級 **Minor**（如 `v1.4.2` $\rightarrow$ `v1.5.0`），納入雙週發布火車。
3. **是否為單純的文字勘誤、數值平衡或已存在 Bug 修復？**
   - 是 $\rightarrow$ 升級 **Patch**（如 `v1.4.2` $\rightarrow$ `v1.4.3`），走輕量熱修復通道。

---

## 3. 發布火車時序與 48 小時代碼凍結期 (Code Freeze)

雙週發布火車（Minor Release）嚴格依循固定行車時序：

```
[Day 1~12: 功能開發] -> [Day 13: 48h 代碼凍結 Code Freeze] -> [Day 14: 預發放量驗收] -> [Day 15: 正式發布]
```

- **凍結期約束（Freeze Rules）**：
  - 自火車發車前 48 小時起，嚴禁合併任何新功能 PR。
  - 僅允許帶有 `P0_HOTFIX` 標籤之修復代碼進入 `release/*` 分支。
  - 必須 100% 通過 `compute-gate --profile full` 與無頭 E2E 驗收測試。

---

## 4. 驗收測試案例 (Test Cases)

- **TC-RELEASE-01【版本號判定樹自動推導】**：提交僅包含數值 JSON 修改之 PR，管線自動建議升級 Patch 版號，禁止誤升 Major。
- **TC-RELEASE-02【48 小時凍結期 PR 攔截】**：在發布前 24 小時嘗試合併新 UI 功能 PR，CI 門禁自動偵測到處於 Freeze Window，阻斷合併。
- **TC-RELEASE-03【發布清單 Manifest 自動生成】**：火車發布時，工具自動生成 `release-manifest.json`，記錄當前 commit hash、版號與升級路徑。

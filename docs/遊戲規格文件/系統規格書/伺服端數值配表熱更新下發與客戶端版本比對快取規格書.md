# 伺服端數值配表熱更新下發與客戶端版本比對快取規格書

> **所屬模組**：`3.6 數值、架構與底層支援 (NUM-17 / NUM-04)`  
> **單一真相來源**：定義伺服端 `numerical_config` 資料庫表結構、熱更常數差分下發 API、客戶端本地快取機制，以及執行期向 `FormulaRegistry` 動態覆寫之安全協議。

---

## 1. 數值熱更架構與動態覆寫流

為避免平衡性微調（如暴擊率上限、兵種克制係數、精力消耗）頻繁觸發客戶端重新發版，數值常數採「本地出廠預設 + 伺服端增量下發覆寫」之架構：

```
+-------------------------------------------------------+
|  [伺服端 numerical_config 資料庫]                     |
|  - 儲存最新平衡性數值常數與遞增版本號                 |
+-------------------------------------------------------+
                           |
          [GET /api/config/numerical?v={clientVer}]
                           |
+-------------------------------------------------------+
|  [客戶端啟動 / 登入同步時序]                           |
|  1. 比對本機快取版本號與遠端最新版本號                 |
|  2. 若遠端版本較新，拉取變更常數差分包                 |
|  3. 寫入本地安全快取 (NumericalConfigCache.json)       |
|  4. 調用 FormulaRegistry.overrideNumericalConstants()  |
|  5. 戰鬥與養成公式立即以最新常數運算                   |
+-------------------------------------------------------+
```

---

## 2. 伺服端資料庫結構與 API 契約

### 2.1 伺服端資料庫表（`numerical_config`）
```sql
CREATE TABLE numerical_config (
    config_key VARCHAR(64) PRIMARY KEY,     -- 常數唯一鍵，如 "BATTLE_CRIT_CAP"
    category VARCHAR(32) NOT NULL,          -- 分類: BATTLE / NURTURE / BREEDING / TALLY
    value_json JSON NOT NULL,               -- 數值本體 (支援數值、陣列、字典)
    version INT NOT NULL DEFAULT 1,         -- 單項版本號
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

### 2.2 查詢與增量下發 API
- **請求端點**：`GET /api/config/numerical`
- **查詢參數**：`clientVersion`（客戶端當前持有之最大 version）
- **回應格式**：
```json
{
  "success": true,
  "latestVersion": 18,
  "hasUpdates": true,
  "configs": {
    "BATTLE_CRIT_CAP": 0.55,
    "VITALITY_COST_BATTLE": 28,
    "TROOP_COUNTER_BONUS_BASE": 1.35
  }
}
```

## 3. 客戶端本地快取與動態注入協議

### 3.1 雙層常數查詢順序 (Fallback Mechanism)
在遊戲執行期，公式系統查詢常數遵循嚴格的兩層尋址：
$$\text{FormulaRegistry.get(key)} \Longrightarrow \text{RemoteHotCache} \longrightarrow \text{LocalDefaultConfig}$$
1. **優先讀取熱更快取**：若 `numerical_config_cache.json` 中存在該鍵值，直接採用熱更值。
2. **安全回退出廠預設**：若無網路或該鍵未曾熱更，平滑回退至包體內置之 `assets/resources/data/master/numerical-config.json`。

### 3.2 執行期熱注入與邊界校驗防呆
當客戶端接收到新配置時，注入 `FormulaRegistry` 前必須執行邊界防護：
```typescript
export interface NumericalValidatorRule {
  min?: number;
  max?: number;
  allowedKeys?: string[];
}

// 範例：暴擊率上限不得低於 0.1 或高於 0.9，防止非法配表引發戰鬥崩潰
export const NUMERICAL_SAFETY_BOUNDS: Record<string, NumericalValidatorRule> = {
  BATTLE_CRIT_CAP: { min: 0.1, max: 0.9 },
  VITALITY_COST_BATTLE: { min: 10, max: 50 },
  TROOP_COUNTER_BONUS_BASE: { min: 1.0, max: 2.0 }
};
```
- 若伺服端下發之數值超出安全邊界，客戶端拋出警告、拒絕套用該項，維持本地出廠值，並上報異常日誌。

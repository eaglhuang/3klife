## 1. 系統定位與架構

本模組定義短期試用傭兵（Mercenary）在戰場與結義過程中的兩大保護契約：
1. **出戰戰績隔離與戰俘豁免（MERC-06）**：傭兵可受編組參與任何戰鬥，但其作戰數據不記入家族常駐歷史戰績庫（`BattleRecordStats`），且戰敗時享有絕對免俘虜豁免，防止戰局失利導致外借武將遺失或污染世代戰功。
2. **結義數值快照凍結（MERC-12）**：當試用傭兵成功結義轉為常駐武將時，其在 6 日試用期內累積之等級、點數分配與特質完整凍結為快照，原子移轉為永久武將的初始基礎屬性，杜絕數值重置回 1 級的損耗感。

## 2. 戰場戰績隔離機制（MERC-06）

### 2.1 數據結算隔離
戰鬥結束後，`BattleSession` 進行全軍結算時，對參戰武將進行身分過濾：

```typescript
export interface IBattleResultFilter {
  readonly generalId: string;
  readonly isMercenary: boolean;
  readonly kills: number;
  readonly damageDealt: number;
  readonly isDefeated: boolean;
}

export function applyBattleRecordStats(
  result: IBattleResultFilter,
  permanentStatsService: IPermanentBattleRecordService
): void {
  // MERC-06 硬邊界：試用傭兵禁止沉澱進常駐生涯數據
  if (result.isMercenary) {
    return;
  }
  permanentStatsService.recordBattle(result);
}
```

### 2.2 戰俘豁免權（Immunity to Capture）
- 戰鬥判定敵方「俘虜敵將」演算法時，若目標為 `isMercenary === true`：
  1. 豁免判定命中率，強制判定結果為 `CAPTURE_IMMUNE`。
  2. 傭兵觸發「破圍回營」動畫，體力扣至最低 1 點，但永不轉移至敵國牢房。
  3. 保證試用期結束前，玩家始終具備調度該傭兵的權利。

## 3. 結義數值快照凍結（MERC-12）

### 3.1 屬性快照抽取結構
在結義操作確認時，系統即時凍結傭兵之最新狀態，建立不可變快照：

```typescript
export interface IMercenaryStatsSnapshot {
  readonly generalId: string;
  readonly level: number;
  readonly exp: number;
  readonly allocatedAttributes: Readonly<{
    str: number;
    int: number;
    lea: number;
    pol: number;
    cha: number;
  }>;
  readonly learnedTactics: readonly string[];
  readonly frozenTimestamp: number;
}
```

### 3.2 無縫繼承轉換
- 將 `IMercenaryStatsSnapshot` 直接指派為新生成永久武將實例的初始起點。
- 玩家在 6 日內為傭兵投入的升級丹藥、策論研習經驗 100% 保留。
- 原始傭兵實例執行析構，釋放暫存指標，避免重複實例並行。

## 4. 驗收與測試標準

1. **戰績隔離驗證（TC-MERC-06-01）**：
   - 傭兵出戰擊殺 100 敵軍並獲勝，檢核 `getPermanentRecord(mercenaryId)` 不存在或勝場數維持為 0。
2. **免俘虜測試（TC-MERC-06-02）**：
   - 模擬全軍覆沒戰役，常駐武將依機率被俘，傭兵 100% 觸發 `CAPTURE_IMMUNE` 回營。
3. **快照凍結測試（TC-MERC-12-01）**：
   - 傭兵在試用期練至 15 級並學會新戰法，結義轉正後新武將初始等級確為 15 級且戰法齊全。

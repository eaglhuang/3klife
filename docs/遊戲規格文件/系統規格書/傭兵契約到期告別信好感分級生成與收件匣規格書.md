# 傭兵契約到期告別信好感分級生成與收件匣規格書

## 1. 核心定位與設計理念
本規格書定義三國生活（3KLife）留存與傭兵系統之「傭兵契約到期（Expired）告別信生成、好感度分級與收件匣管理」規範（對應 WBS `RET-03` 與 `PROG-2-0982`）。
告別信機制旨在當傭兵 6 日試用期滿未轉永久時，給予玩家正向的情感回饋與臨別紀念，堅持**好感分級、唯一防重、容量保護**原則：
1. **好感度階梯分級生成**：親密度低於 20 點不生成信件（普通萍水相逢）；20 點以上分流為「普通版」與「深情版」信件。
2. **同日同人唯一識別**：信件 ID 綁定傭兵 UID 與到期日，徹底防止跨日輪詢時重複寄信。
3. **收件匣先進先出保護**：信箱設定 50 封容量上限，超出時平滑淘汰最舊已讀信件，防止存檔資料膨脹。

---

## 2. 告別信好感度分級模型 (`farewellTierOf`)
當傭兵合約到期時，系統讀取其當前親密度（`affection`）決定信件階級：

| 親密度區間 (`affection`) | 信件階級 (`FarewellTier`) | 信件主旨與情感基調 | 內文樣式範例 |
| :---: | :---: | :--- | :--- |
| **$< 20$ 點** | `null` (不生成) | 萍水之交，無信離去 | 無信件生成，直接自隊伍除名 |
| **$20 \sim 39$ 點** | `normal` (普通) | 禮貌辭別，互道前程 | 「主公，短短數日，承蒙關照。山高水長，願主公前程似錦——{GeneralName} 敬上」 |
| **$\ge 40$ 點** | `moving` (深情) | 知遇感懷，約定他日再聚 | 「主公，與君同袍數日，勝過平生所歷。此去雖遠，若有徵召，必當策馬來歸！——{GeneralName} 敬上」 |

- **常數定義**：
  - `FAREWELL_MIN_AFFECTION = 20`（最低寄信門檻）。
  - `FAREWELL_MOVING_AFFECTION = 40`（感人版門檻）。

## 3. 信件結構與生成演算法 (`createFarewellLetter`)
```typescript
export interface FarewellLetter {
    id: string;               // 唯一信件 ID（如 FL-GEN_ZHAOYUN-6）
    uid: string;              // 傭兵實體 UID
    generalName: string;      // 武將姓名
    affection: number;        // 到期時的好感度數值
    tier: 'normal' | 'moving';// 信件階級
    body: string;             // 信件內文
    day: number;              // 到期之遊戲天數
    read: boolean;            // 是否已讀
}
```
- **生成函式校驗**：
  若 `farewellTierOf(affection)` 為 `null`，函式回傳 `null`；若達標，組裝並回傳未讀狀態（`read = false`）之全新信件物件。

## 4. 收件匣管理與未讀追蹤 (`FarewellLetterInbox`)
- **加入收件匣 (`appendFarewellLetter`)**：
  - 檢查收件匣中是否已存在相同 `id`，若已存在則不重複寫入。
  - **容量淘汰 (FIFO)**：收件匣上限為 50 封（`FAREWELL_INBOX_LIMIT = 50`）。若加入後超過 50 封，自動自頭部截斷剔除最舊信件（`next.slice(next.length - 50)`）。
- **標記已讀 (`markFarewellLetterRead`)**：
  玩家點開信件時將 `read` 標記為 `true`，回傳不可變之新陣列。
- **未讀信件計數 (`unreadFarewellCount`)**：
  計算 `read === false` 的信件總數，供主介面信箱圖示繪製紅點數字角標。

## 6. 驗證條件與測試矩陣 (Acceptance Gate)
1. **TC-RET03-01 門檻未達不生成**：好感度為 19 點到期，驗證 `createFarewellLetter` 回傳 `null`。
2. **TC-RET03-02 40分水嶺精準分流**：好感 39 回傳 `normal`；好感 40 回傳 `moving`。
3. **TC-RET03-03 50封上限先進先出**：收件匣已有 50 封信，寫入第 51 封，驗證總數維持 50 且最舊信件被淘汰。
4. **TC-RET03-04 閱讀狀態標記與角標**：標記 1 封信已讀後，驗證 `unreadFarewellCount` 精準減少 1。

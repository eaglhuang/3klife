# 傭兵結義永久化後同名卡自動二轉與屬性上限突破規格書

> **所屬模組**：`3.5 血統、家族與培育傳承 (MERC-09 / SAME-06)`  
> **單一真相來源**：定義傭兵透過結義點數轉為永久武將後，再次抽到同名卡觸發「自動轉生突破（Auto-Promotion）」之狀態機、每轉單項五維上限 `+5`（`+5%`、五轉最高 `125`）數值模型，以及繞過常規重複卡分流彈窗之無縫整合協議。

---

## 1. 核心業務流程與判定狀態機

當玩家自轉蛋（Gacha）或招募中獲得武將卡時，系統依據目標武將之永久與結義狀態執行以下分流判定：

```
                     [抽得武將卡 (General_ID)]
                                |
                    [是否已存在同名角色實體？]
                      /                  \
                   [否]                  [是]
                    |                      |
             [正常加入名冊]        [檢查目標武將狀態]
                                   /              \
                    [非永久傭兵 / 一般武將]   [已結義永久傭兵 (MERC_PERMANENT)]
                            |                           |
                  [依 doc_spec_0649 分流]     [自動觸發同名轉生突破 (不跳分流彈窗)]
                   - 復生重練 (新UID)                   |
                   - 血脈灌注 (等級+1)       +------------------------+
                                             | 1. 單項五維上限每轉 +5 |
                                             | 2. 抽卡突破台詞顯示新上限|
                                             | 3. 最高五轉上限 125    |
                                             +------------------------+
```

## 2. 轉生突破屬性上限數值模型（MERC-09 定案）

### 2.1 零基規格與一基實作對照表
為了同時符合「每轉單項五維上限 `+5%`（`+5`）」與「五轉累計 `+25%`（上限 `125`）」，正式規範如下（徹底廢除早期舊草案之「+10%、限一次」或「1000/1250」過時設定）：

| 規格轉數 (0-based) | 程式轉數 (`rebirthCount`, 1-based) | 狀態標籤 | 單項五維上限 (`singleStatCap`) | 上限增幅比例 | 觸發條件與表現 |
|:---:|:---:|:---:|:---:|:---:|:---|
| **0 轉 (初結義基準)** | `0` (未抽重複卡) | `BOND_BASE` | **100** | `+0%` | 6 日結義轉正完成，成為永久武將，解除退場倒數 |
| **1 轉 (首次同名突破)** | `1` | `BOND_TIER_1` | **105** | `+5%` | 結義後第 1 次抽到同名卡，自動突破，台詞顯示上限 105 |
| **2 轉 (二次同名突破)** | `2` | `BOND_TIER_2` | **110** | `+10%` | 結義後第 2 次抽到同名卡，自動突破，台詞顯示上限 110 |
| **3 轉 (三次同名突破)** | `3` | `BOND_TIER_3` | **115** | `+15%` | 結義後第 3 次抽到同名卡，自動突破，台詞顯示上限 115 |
| **4 轉 (四次同名突破)** | `4` | `BOND_TIER_4` | **120** | `+20%` | 結義後第 4 次抽到同名卡，自動突破，台詞顯示上限 120 |
| **5 轉 (極限五轉滿額)** | `5` | `BOND_TIER_5` | **125** | `+25%` | 結義後第 5 次抽到同名卡，達成五轉滿額上限 125 |

### 2.2 計算公式
$$\text{SingleStatCap}(n) = 100 + \min(5, \max(0, n)) \times 5$$
- 其中 $n$ 為結義轉正後累計抽到同名卡觸發自動轉生之次數（$n \in \{1, 2, 3, 4, 5\}$）。
- 當程式端轉數從 `1` 起算時，`1` 轉即對應首次同名突破，上限為 `105`，至 `5` 轉恰好為 `125`（`+25%`）。

## 3. UI 演出與分流彈窗覆寫規則

1. **繞過重複卡分流彈窗**：
   - 抽卡結算時，若偵測該武將為「已結義轉正之傭兵」，**直接執行自動轉生突破，不跳出「復生重練／血脈灌注」雙向選擇彈窗（`doc_spec_0649`）**。
2. **抽卡突破台詞差異化**：
   - 結義傭兵觸發自動突破時，抽卡突破台詞動態顯示新解鎖之單項五維上限（如 `105`、`110` … `125`）。
   - 一般非傭兵武將之抽卡台詞維持原樣不變。

---

## 4. 資料模型與持久化

```typescript
export interface MercenaryTierPromotionRecord {
  generalUid: string;
  templateId: string;
  /** 轉生突破次數 (1 ~ 5，每轉 +5，1轉=105 ... 5轉=125) */
  promotionTier: 1 | 2 | 3 | 4 | 5;
  /** 單項五維屬性上限 (105 | 110 | 115 | 120 | 125) */
  singleStatCap: number;
  promotionTimestamp: number;
}
```

- **單一真相約束**：武將五維成長與培育檢核應統一讀取 `singleStatCap` 作為屬性天花板，嚴禁在多個陣列中重複建立同名武將實體。

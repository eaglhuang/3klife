# 內政任務詳情單屏重排與固定底部行動列規格書

> 對應任務卡：PROG-2-10105（規格）；實作卡見 §9。
> 來源：使用者 2026-11-27 回饋——內政任務詳情畫面（任務概要、情報揭示、行動人物、AI 委任、再探／執行／等待／委任按鈕）超過一屏要往下捲，很難用。
> 關聯規格：doc_spec_1178（大廳任務完整循環，§5 詳情視窗、§6 四個行動）、doc_spec_0454（情報度與 AI 委任）、doc_spec_0455（自告奮勇）、doc_spec_0668（適合度）。**欄位內容、顯示條件、按鈕停用條件全部沿用 1178 §5～§8，本文只重排版面。**
> Mockup：`docs/遊戲規格文件/設計參考/ui-asks-1127/mission-detail-onescreen.html`（截圖同名 .png，1920×1080）。

## 1. 現況（只讀程式與資料的結論）

- 版面檔：`assets/resources/ui-spec/layouts/lobby-mission-detail-dialog-main.json`；元件：`LobbyMissionDetailDialogComposite.ts`。
- 對話框 800×900，內有 `ScrollView`（可視 646）裝 `ScrollContent`（高 1192），五個區塊**單欄由上往下堆**：概要 140、情報 372、人物 180、耗費 270、獎勵 208；底部 `FooterBar` 162（AI 委任列＋四按鈕）。
- 問題：橫式 1920×1080 的畫面只用了 800 寬的窄直欄，內容 1192 > 可視 646，必須捲動；情報區 372 高裡 `EnvScoutPanel` 常是空的；人物下拉展開時還會把 `ScrollContent` 撐更高。
- 結論：不是資訊太多，而是**單欄直排浪費了橫向空間**。

## 2. 設計原則

1. **一屏看完**：1920×1080 下所有資訊（概要、情報、人物、成功率、耗費、獎勵、AI 委任、四按鈕）同時可見，**中央內容區不得出現捲動條**。
2. **四按鈕固定底部**：標題列、底部行動列固定高度，不隨內容移動。
3. **分欄＋摘要展開＋圖示化**：橫向三欄；長文字只留摘要，點「展開」才看全文；每區塊配圓形圖示章。
4. **錨點與比例**：不寫死像素座標，保留日後改直式。

## 3. 橫式版面（基準 1920×1080）

### 3.1 外框

- 對話框錨點置中，**寬 84%、高 90%**（約 1613×972）；遮罩全螢幕。
- 縱向三段：`HeaderBar` 固定 84px → `Body`（彈性，吃剩餘高）→ `FooterBar` 固定 104px。
- `Body` 內取消 `ScrollView`；僅在「極端內容或小螢幕保護」時啟用（見 §6.3）。

### 3.2 `Body` 三欄（比例 30 : 36 : 34，欄距 20px、外邊距 24px）

| 欄 | 區塊（由上而下） | 說明 |
|---|---|---|
| 左欄 30% | ① 任務概要 ② 情報揭示 ③ 獎勵 | 「讀情報」欄：這任務是什麼、看得到多少、做完拿什麼 |
| 中欄 36% | ④ 行動人物（含成功率） | 「做決定」欄：派誰、成功率多少、精力、回報時間 |
| 右欄 34% | ⑤ 派出耗費 ⑥ AI 委任 ⑦ 再探／等待說明 | 「付代價與選方式」欄 |

### 3.3 各區塊內容與壓縮方式

| 區塊 | 內容 | 壓縮方式 |
|---|---|---|
| ① 任務概要 | 標題（移到 HeaderBar）、`Task_Brief` | 只顯示簡述，最多 3 行，超過顯示「展開全文 ▾」（展開為浮層，不撐高版面）；`Task_Detail` 放展開內容 |
| ② 情報揭示 | 揭露度進度條＋百分比、重點屬性、成功率（區間或確切值）、迷霧列（敵方／完美加成：???）＋「再探後揭示」小標 | 取消獨立 `EnvScoutPanel` 大框；迷霧列單行；情報度同時顯示在 HeaderBar 的 chip |
| ③ 獎勵 | 基礎獎勵、完美加成（情報不足顯示「???」）、武將經驗／官職經驗 | 兩格並排＋一行「另得」 |
| ④ 行動人物 | 頭像、姓名、自告奮勇徽章、關鍵屬性、精力、**預估成功率（大字 44px）**、更換武將下拉、精力耗費、回報季數 | 下拉維持單行；不可派武將收在「不可派的 N 位（點開看原因）▾」 |
| ⑤ 派出耗費 | 黃金／糧草／兵源（依牆別）、精力、耗時 | 2×2 小格；付不起者紅框並標「差多少」（沿用 1178 §5） |
| ⑥ AI 委任 | 一句話說明、本次預選人選與成功率 | 開關移到 FooterBar 左側（見 §4） |
| ⑦ 再探／等待 | 各一行說明（耗費與效果） | 純說明；真正按鈕在底部 |

### 3.4 HeaderBar（固定 84px）

左起：任務標題（34px）、牆別 chip（內政／軍事／沙盤）、難度 chip、耗時／剩餘期限 chip、情報度 chip；最右關閉鈕（錨點右上，44px 熱區）。

## 4. 底部固定行動列（FooterBar，固定 104px）

- 左側：`AI 委任` 開關＋一行說明（`AI_Assign_Enabled` 為 false 時開關灰化並顯示原因）。
- 右側：四個等寬按鈕（200×64，間距 14），順序固定：**再探 ｜ 等待 ｜ 執行 ｜ 委任**；「執行」為主要按鈕（金色）。
- 每個按鈕有**主標＋副標**：副標顯示耗費或停用原因，玩家不需點進去才知道為什麼不能按。

| 按鈕 | 副標（可用） | 副標（停用，沿用 1178 §6 條件） |
|---|---|---|
| 再探 | 糧草 −50 | 情報度已 100／糧草不足 50 |
| 等待 | 期限 +1 季 | 已等待過 |
| 執行 | 自己選人派出 | 沒有可派武將／付不起耗費（寫缺什麼） |
| 委任 | 系統代選 | 沒有可派武將／付不起耗費／此任務不可委任 |

## 6. 直式彈性與保護

### 6.1 直式（寬 < 高）

- 對話框改寬 96%、高 94%；三欄改**上下堆疊**為單欄，順序：概要 → 情報 → 行動人物 → 耗費 → 獎勵 → AI 委任。
- 次要區塊（概要、獎勵、再探說明）預設收成「摘要＋展開」，使「概要＋人物＋成功率＋耗費」一屏可見；仍允許 `Body` 垂直捲動，但**底部行動列與標題列依然固定**。

### 6.2 資料驅動

欄數、欄比例、區塊歸欄全部放在 `lobby-mission-detail-dialog-main.json` 的 `layoutMode`（`landscape3col`／`portrait1col`）與 `columns[]`；元件依 `UITransform` 寬高比切換，不在 TS 內寫死。

### 6.3 小螢幕保護

可視高度低於 720px（等效）時：`Body` 退回可捲動，但四按鈕列仍固定；此情況需記 `UCUFLogger.warn`，供 QA 發現。

## 7. 驗收標準

1. 1920×1080 下，**所有區塊與四按鈕同時可見，Body 無捲動條**（截圖證據，視窗尺寸 1920×1080）。
2. 人物下拉展開時以浮層疊在上方，不撐高 Body、不推動底部按鈕。
3. 迷霧／完整揭露兩種狀態（情報度 50 與 100）、可派武將 0 人、付不起耗費三種情況各截圖一張，按鈕副標原因正確（對齊 doc_spec_1178 §5、§6）。
4. 軍事、沙盤牆的任務同樣使用本版面（耗費列依牆別換成兵源／黃金），不限內政。
5. 切換直式視窗（模擬 1080×1920）不爆版、行動列固定。
6. `lobby-mission-detail-dialog-content.schema.json` 欄位不變；舊測試（任務詳情相關）全過。
7. 玩家視角驗收：實點「再探→執行／等待→委任」流程各一次附截圖。

## 8. 範圍外

- 不改任務數值、成功率公式、情報度規則、按鈕停用條件（皆屬 1178）。
- 不新增美術資產；圖示章用文字圓章，後續可由主題包替換。

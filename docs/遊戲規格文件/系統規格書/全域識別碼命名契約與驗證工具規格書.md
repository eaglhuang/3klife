# 全域識別碼命名契約與驗證工具規格書

> **文件狀態**：單一真相來源（Single Source of Truth）  
> **系統代碼**：`TERM-01`、`SYS-ID-VALIDATOR`  
> **核心職責**：收斂遊戲全域八大識別碼（UID, Template_ID, Bloodline_ID, Gene_ID, V_PID, SIGIL, SPIRIT_TALLY, ATM-ID）格式契約，消除規格書與現有資料集（generals.json, gene-dictionary.json）之歷史歧異，提供確定性校驗工具標準。

---

## 1. 架構原則與權威仲裁

1. **資料現狀權威（Data-as-Code Authority）**：
   - 現行 235 筆 `generals.json` 與因子庫命名已成既定事實，驗證器嚴格採用「雙軌兼容契約」，消除歷史誤報。
2. **無跨域混淆**：
   - 執行期實例 ID（UID）與靜態配置模板 ID（Template_ID）徹底分離，嚴禁將動態實例直接作為配置查詢鍵。
3. **零容錯驗證**：
   - 任何新入庫資料或儲存檔還原皆必須通過本規格之正規表示式（Regex）校驗，非法字元立即拋出警告或阻絕。

---

## 2. 八大全域識別碼正規契約

| 識別碼類型 | 適用範圍 | 正規表示式 (Regex) | 命名樣式範例 | 說明與約束 |
|---|---|---|---|---|
| **UID** | 執行期武將實例、裝備實例 | `^u_[0-9a-f]{8,16}$` | `u_3fa85f64` | 執行期動態生成，全域唯一，不可重複 |
| **Template_ID** | 武將/NPC 靜態模板 | `^[a-z][a-z0-9_]{2,31}$` | `cai_wenji`, `guan_yu` | 小寫蛇形命名，對齊現況 235 筆 master 資料 |
| **Bloodline_ID** | 史實/動態血系識別碼 | `^(BLOOD_[A-Z0-9_]+|BL_[A-Z0-9_]+)$` | `BLOOD_LIU`, `BL_SUN_01` | 大寫前綴，標定核心宗族主系與分流 |
| **Gene_ID** | 遺傳因子與特質字典 | `^([a-z][a-z0-9_]{2,31}\|GENE_[A-Z0-9_]+)$` | `brave_vanguard`, `GENE_STR_01` | 雙軌包容現存字典與擴充編碼 |
| **V_PID** | 虛擬先祖與歷史譜牒人物 | `^V_[A-Z0-9_]{3,31}$` | `V_ANCESTOR_001` | 虛擬人物前綴，不可作為出陣實體 |
| **SIGIL** | 兵符印記與特殊紋章槽 | `^SIGIL_[A-Z0-9_]+$` | `SIGIL_TIGER_01` | 兵符專屬裝配槽唯一識別碼 |
| **SPIRIT_TALLY**| 虎符物件識別碼 | `^TALLY_[A-Z0-9_]+$` | `TALLY_DRAGON_SCALE` | 虎符全域型別，無冷卻且具糧耗綁定 |
| **ATM-ID** | 工程任務卡與治理卡號 | `^[A-Z]{2,6}-\d-\d{4}$` | `PROG-2-1902`, `UI-2-0117` | 任務卡與治理卡標準卡號契約 |

## 3. 識別碼解析與驗證器管線（IdContractValidator）

```typescript
export interface IdValidationResult {
  valid: boolean;
  category: string;
  targetId: string;
  errorReason?: string;
}

export class IdContractValidator {
  private static readonly REGEX_MAP: Record<string, RegExp> = {
    UID: /^u_[0-9a-f]{8,16}$/,
    Template_ID: /^[a-z][a-z0-9_]{2,31}$/,
    Bloodline_ID: /^(BLOOD_[A-Z0-9_]+|BL_[A-Z0-9_]+)$/,
    Gene_ID: /^([a-z][a-z0-9_]{2,31}|GENE_[A-Z0-9_]+)$/,
    V_PID: /^V_[A-Z0-9_]{3,31}$/,
    SIGIL: /^SIGIL_[A-Z0-9_]+$/,
    SPIRIT_TALLY: /^TALLY_[A-Z0-9_]+$/,
    ATM_ID: /^[A-Z]{2,6}-\d-\d{4}$/
  };

  public static validate(type: string, id: string): IdValidationResult {
    const regex = this.REGEX_MAP[type];
    if (!regex) return { valid: false, category: type, targetId: id, errorReason: 'Unknown ID Category' };
    const valid = regex.test(id);
    return {
      valid,
      category: type,
      targetId: id,
      errorReason: valid ? undefined : `ID [${id}] violates contract for ${type}`
    };
  }
}
```

## 4. 驗收標準與 CI 閘門（Acceptance Criteria）

1. **現況資料 100% 通過**：
   - 執行驗證器掃描 `assets/resources/data/generals.json`（235 筆）及 `gene-dictionary.json`，違規數必須為 0。
2. **非法輸入精確攔截**：
   - 含有大寫字母的 Template_ID（例如 `Guan_Yu`）或包含特殊符號之 UID 一律回報失敗。
3. **單元測試涵蓋**：
   - 包含正向範例與負向邊界測試（至少 8 大類別各 2 組測試例）。

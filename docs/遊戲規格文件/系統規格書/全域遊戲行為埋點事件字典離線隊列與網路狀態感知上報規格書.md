# 3KLife 全域遊戲行為埋點事件字典離線隊列與網路狀態感知上報規格書

> **規格代碼**：SPEC-OPS-TEL01  
> **關聯 WBS**：OPS-TELEMETRY-01（全域埋點事件字典、離線隊列與網路狀態感知上報）  
> **文件版本**：v1.0.0 (單一真相來源，無補丁整併版)  
> **所屬系統**：數值、架構與底層支援（Formula, Architecture & Backend）

---

## 1. 核心宗旨與設計哲學

為支援遊戲平衡性數據分析、新手指引漏斗優化與商業化轉化率評估，本規格書制定全域**標準埋點事件字典（Telemetry Event Dictionary）**、**本地離線環形佇列（Offline Buffer Queue）**與**網路狀態感知自適應批次上報機制（Network-Aware Batching）**。確保數據不丟失、傳輸不搶頻寬、且嚴格恪守隱私合規。

---

## 2. 全域標準埋點事件字典 (Event Dictionary)

所有業務系統調用 `TelemetryService.trackEvent(eventName, payload)`，事件命名一律採用大寫蛇形：

| 事件名稱 (Event Name) | 觸發時機 (Trigger Moment) | 核心載荷參數 (Payload Schema) | 優先級 (Priority) |
|---|---|---|---|
| **EVENT_ONBOARDING_STEP** | 新手指引每通過一小步 | `{ stepId: string, durationSec: number }` | 高 (P1) |
| **EVENT_GACHA_PULL** | 玩家進行單抽或十連抽 | `{ poolId: string, pullCount: 1\|10, acquiredRarities: string[] }` | 高 (P1) |
| **EVENT_BATTLE_END** | 戰鬥勝利、失敗或撤退結算 | `{ stageId: string, isVictory: boolean, roundsCount: number, casualtyRate: number }` | 中 (P2) |
| **EVENT_NURTURE_FINISH** | 潁川書院 36 回合結業 | `{ generalId: string, finalGrade: string, epScore: number, finalStats: object }` | 中 (P2) |
| **EVENT_ECONOMY_FLOW** | 銅錢/靈玉等重要貨幣收支 | `{ currencyType: 'COIN'\|'JADE', delta: number, currentBalance: number, reason: string }` | 高 (P1) |

## 3. 本地離線佇列與網路感知自適應上報

```typescript
export interface TelemetryEventPayload {
  eventId: string;                    // UUID
  eventName: string;                  // 如 EVENT_BATTLE_END
  userIdHash: string;                 // 脫敏加鹽雜湊 ID
  timestamp: number;
  networkType: 'WIFI' | 'CELLULAR' | 'OFFLINE';
  parameters: Record<string, any>;
}

export interface TelemetryBatchRequest {
  batchId: string;
  sentTimestamp: number;
  eventsCount: number;
  events: TelemetryEventPayload[];
}
```

### 3.1 網路狀態感知自適應策略

| 當前網路狀態 | 批次打包門檻 (Batch Flush Threshold) | 上報定時間隔 (Flush Interval) | 流量與頻寬優化處置 |
|---|---|---|---|
| **WIFI** | 滿 20 筆事件立即上報 | 每 30 秒自動觸發 | 開啟 gzip 壓縮，優先保證數據及時性。 |
| **CELLULAR (4G/5G)** | 滿 50 筆事件上報 | 每 60 秒自動觸發 | 聚合批次，減少行動網路射頻晶片喚醒耗電。 |
| **OFFLINE (斷網/弱網)** | 禁止發起網路請求 | 暫停定時器 | 事件安全緩衝於本地佇列（上限 200 筆，FIFO）。 |

## 4. 驗收測試案例 (Test Cases)

- **TC-OPS-TEL-01【事件字典格式校驗】**：以 `EVENT_GACHA_PULL` 觸發埋點，驗證載荷欄位型別通過 Schema 檢驗，缺漏必要參數立即在開發期給予 Warning。
- **TC-OPS-TEL-02【斷網暫存與恢復批次上報】**：在斷網狀態下累計產生 15 筆戰鬥事件，網路切回 WiFi 後，系統在 3 秒內自動將 15 筆事件一次性打包發送成功。
- **TC-OPS-TEL-03【佇列 200 筆上限 FIFO 淘汰】**：極端斷網環境下產生 250 筆事件，驗證本地佇列嚴格維持最新 200 筆，最舊的 50 筆低優先級事件被安全淘汰，無記憶體溢出。

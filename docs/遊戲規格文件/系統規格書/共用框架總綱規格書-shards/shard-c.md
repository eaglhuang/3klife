## 6. 依賴關係

```
共通 API 層（第 5 章）
   ├─ 物品庫存（ITM）        ← 最底層；貨幣是 kind=currency 的物品（待裁）
   │     ▲        ▲
   ├─ 買賣商店（SHP）─┘        依賴 ITM、RWD（寶箱商品）
   ├─ 獎勵（RWD）──────────────依賴 ITM、STY（給獎演出）
   ├─ 任務（QST）──────────────依賴 RWD（獎懲）、ITM（物品條件）、STY（任務劇情）
   ├─ 技能（SKL）──────────────依賴 ITM（技能書）、RWD（習得），STY（奧義演出）
   └─ 劇情演出（STY）──────────依賴 RWD、QST、ITM（選項後果，經命令呼叫，不直接耦合）
```

規則：框架之間只能經 API 命令或事件互相呼叫，不得直接 import 對方內部狀態；不得形成循環依賴（STY 對 RWD 的依賴限於「播放 RWD 指定演出」，RWD 對 STY 只送演出請求）。

## 8. 檢查清單

### 企劃
- [ ] 這個新玩法的本質是哪一個框架？已寫成「設定＋薄包裝」？
- [ ] 有沒有出現第二處類似功能？有就登記第 11 章候選。
- [ ] 所有重要數值與結果都以命令表達？有沒有寫成「客戶端自己算」？
- [ ] 規格書有「伺服器 API」章？權威欄位與錯誤碼寫清楚？
- [ ] 價格、機率、商業化與戰場核心規則，已列待決選擇題而非自行定案？

### 工程
- [ ] 沒有直接改庫存、貨幣、存檔？`check-api-bypass` 通過？
- [ ] 狀態命令有 `idemKey` 與已完成標記？
- [ ] 新效果種類／演出模組／服務型商品以註冊方式加入，沒有複製框架邏輯？
- [ ] 本機 adapter 與網路 adapter 契約測試通過？
- [ ] 舊存檔缺值補預設，不破壞？
- [ ] 文字檔 UTF-8 無 BOM；`compute-gate standard` 通過。

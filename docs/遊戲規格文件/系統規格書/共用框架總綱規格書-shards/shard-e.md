## 12. 一年循環 MVP 切分（PROG-2-9213）

> 目標（使用者里程碑）：**新玩家玩滿第 1 年不卡關，加上第 2 年能玩學府主玩法**。第 9 章的完整順序約 8～12 個 AI 日，且第 10、11 章全是草案；本章只切出「一年循環必經」的最小子集，其餘延後。只寫建議卡清單，**不開卡**；卡名、卡號僅供主控與總 PM 參考。
> 依據：一年循環缺口稽核（缺口 #1 學府結業未串接、#2 框架全是草案、#8 人員占用）、學府 doc_spec_1179 第 9～10 章、歷練 doc_spec_1180、家業 doc_spec_1181。B0 共通 API 層已有工程子代理在做，本章從 B0 之後排。

### 12.1 切分判準

1. 第 1～2 年玩家碰得到的流程才算 MVP：學府修業（36 回合、打斷、結業、開獎、戰法習得）、入學令與教官持有、定期發放（入學令季發）。
2. 第 1 年已經能玩、且不依賴新框架的系統（任務牆、領地、年報、守城）**不遷移**，維持現狀；遷移卡放 MVP 之後（5.9 優先序）。
3. 只做「學府第一次會用到的欄位與命令」；其餘欄位只留擴充點（介面與 schema 欄位保留，實作不做），避免日後破壞存檔。
4. 凡是第 10、11 章尚未裁決、但 MVP 不依賴其結果的，先做「中立版」（不論裁決選 A 或 B 都不重工）。
5. 商店、歷練、家業、網路 adapter 都不在一年循環關鍵路徑。

### 12.5 MVP 的存檔相容要求

- 所有 MVP 卡都在存檔補 `schemaVersion` 與缺值預設，舊存檔開檔不壞。
- 保留但不實作的欄位（`solver=progress`、`autoResolve`、`currency` 持有者）寫在 schema 註解與 `TODO(第二版)`，不得用暫時欄位名佔位，避免日後改名遷移。
- `check-api-bypass` 基準每張卡只減不增（Q4 A）。

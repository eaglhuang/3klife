# 出征整隊編制預設儲存與失效安全推薦規格書

## 1. 核心定位與編制預設契約

本規格書為玩家戰前出征編制配置預設持久化儲存與戰前智慧推薦推薦模型（Sortie Loadout Preset & Recommendation，代號 `DEP-14`）的單一真相來源（Single Source of Truth）。系統依據每位主將（Commander）分別記憶其專屬的參謀官（Strategist）與後勤官（Deputy）支援陣容，並在武將狀態流轉（重傷、陣亡、閉關、培育）時提供無害的失效安全過濾。

```typescript
export interface SortieSupport {
  strategistUid: string | null;
  deputyUid: string | null;
}

export type SortiePresetStore = Readonly<Record<string, SortieSupport>>;
```

---

## 2. 預設持久化儲存契約（`savePresetFor`）

1. **主將唯一複合鍵**：
   - 預設資料庫以主將唯一識別碼 `commanderId` 作為字典鍵值。
   - 玩家於出征編制介面調整並保存時，原子更新該主將之預設記錄，不污染其他主將之歷史設定：
     $$\text{Store}_{\text{new}} = \{ \dots\text{Store}_{\text{old}}, [\text{commanderId}]: \text{support} \}$$
2. **純淨無副作用**：
   - 儲存函式維持純函數設計，返回全新之唯讀儲存物件（Immutable Store）。

---

## 3. 失效安全推薦與動態過濾演算法（`resolvePreset`）

當戰役開打、系統向玩家推薦歷史預設編制時，必須針對當前最新武將名冊狀態進行四道動態安全過濾：

### 3.1 支援可用性檢定（`usable(uid)`）

某候選武將 $\text{uid}$ 唯有同時滿足以下三項條件，方能被納入推薦：
1. **非空性**：$\text{uid} \neq \text{null}$。
2. **非主將身分**：$\text{uid} \neq \text{commanderId}$（嚴禁主將自任幕僚）。
3. **出戰資格名冊檢驗**：$\text{deployableIds.has(uid)} == \text{true}$。
   - 若該武將目前處於以下狀態，判定為不可出戰：
     - 已於先前戰役戰死（`dead`）或自然老死。
     - 轉任為退役專任教官（`retired-mentor`）。
     - 正在學府受訓研習中（`in-nurture`）。
     - 體力嚴重不足（$\text{vitality} < 30$）。

### 3.2 失效欄位置空原則（Fail-Safe Nulling）

- 若預設中之參謀官或後勤官已不符合出戰資格，**該欄位直接回傳 `null`（視為空缺），嚴禁系統擅自挑選其他替代武將遞補**。
- 保障玩家意圖純粹性，避免盲目推薦非玩家偏好之角色。

### 3.3 角色衝突優先序

- 若歷史預設中，參謀官與後勤官意外為同一武將：
  $$\text{strategistUid} = \text{usable}(\text{preset.strategistUid})$$
  $$\text{deputyUid} = (\text{candidate} == \text{strategistUid}) \ ? \ \text{null} : \text{candidate}$$
- 優先保留先出現之參謀官，後勤官欄位安全置空。

## 4. 自動化測試與驗收標準

1. **單元測試對齊**：
   - 對齊 `tests/SortieLoadoutPreset.test.ts`。
   - 驗收條件 1：驗證保存主將編制後，再次讀取能正確還原參謀官與後勤官 UID。
   - 驗收條件 2：驗證當參謀官陣亡不在 `deployableIds` 時，解析推薦結果該欄精確為 `null`。
   - 驗收條件 3：驗證當參謀與後勤指派同一武將時，後勤官欄位安全置為 `null`。

# 出征編制槽位角色互斥鎖與同血脈檢驗規格書

## 1. 核心定位與編制架構契約

本規格書為戰前部隊出征整隊編制槽位合法性檢驗系統（Sortie Loadout Validation，代號 `DEP-08`）的單一真相來源（Single Source of Truth）。出征編制由一位主將（Commander）與最多兩位幕僚（參謀官 Strategist、後勤官 Deputy）組成，透過 `validateSortieLoadout` 執行嚴格的角色互斥鎖與同名武將同血脈限制。

```typescript
export interface SortieLoadout {
  commanderUid: string;           // 主將 UID（必填）
  strategistUid: string | null;   // 參謀官 UID（選填，可為 null）
  deputyUid: string | null;       // 後勤官 UID（選填，可為 null）
}

export type SortieLoadoutIssue =
  | 'MISSING_COMMANDER'           // 未指派主將
  | 'ROLE_LOCK'                   // 同一武將兼任多職
  | 'SAME_BLOODLINE'              // 同名/同血脈武將同場
  | 'UNKNOWN_GENERAL';            // 無效或不存在武將
```

---

## 2. 四大編制檢驗規則體系

### 2.1 主將必填約束（`MISSING_COMMANDER`）

- **規則**：`commanderUid` 必須為非空字串。
- **阻絕裁定**：三軍不可無帥，若未選定主將，嚴禁建立出征帳本或進入戰場。

### 2.2 角色互斥鎖（`ROLE_LOCK`）

- **規則**：集合長度必須等於有效角色數量：
  $$\text{Distinct}(\{ \text{Commander}, \text{Strategist}, \text{Deputy} \}) = N_{\text{assigned}}$$
- **阻絕裁定**：同一位武將實例不可身兼兩職（如不可同時指派為「主將」與「參謀官」）。

### 2.3 同名武將血脈限制（`SAME_BLOODLINE`）

- **規則**：出征整隊中，所有上陣武將之 `Bloodline_ID` 必須全局唯一：
  $$\text{Distinct}(\{ \text{Bloodline}(\text{Member}_i) \}) = N_{\text{withBloodline}}$$
- **機制意義**：貫徹名號限定制，即便玩家透過轉生或異化版本持有同一人物（例如【趙雲】與【常山龍騎·趙雲】），因血脈皆為 `BLOOD_ZHAO`，嚴禁同時編入同一戰鬥整隊中出陣。
- **豁免條件**：虛擬先祖或未配備血脈標籤之泛用自訂武將不參與血脈衝突比對。

### 2.4 名冊存在驗證（`UNKNOWN_GENERAL`）

- **規則**：指派之 UID 必須存在於當前玩家可用武將名冊中，杜絕過期資料或記憶體游離指針。

---

## 3. 運行期雙重檢核機制（Double Check）

1. **出征編制介面（UI Layer）**：
   - 玩家於 `SortieSetupController` 選派武將時，即時調用 `validateSortieLoadout`。
   - 若發生衝突，介面按鈕灰化，提示「不可重複指派同一武將」或「同名名將不可並肩作戰」。
2. **戰場核心初始化（Runtime Layer）**：
   - `createSortieState` 在戰鬥加載時再次調用 `checkFormationBloodlines`，若檢測到衝突強制拋出例外中斷，杜絕作弊繞過。

## 4. 自動化測試與驗收標準

1. **單元測試對齊**：
   - 對齊 `tests/SortieDeploy.test.ts` 與 `tests/ReadModelValidators.test.ts`。
   - 驗收條件 1：驗證主將為空時回報 `MISSING_COMMANDER`。
   - 驗收條件 2：驗證主將與參謀指定同一 UID 時回報 `ROLE_LOCK`。
   - 驗收條件 3：驗證主將與後勤官不同 UID 但血脈 ID 相同時，精確回報 `SAME_BLOODLINE`。

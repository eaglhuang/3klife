# 友誼行為權重表規格書（草案）

> 任務卡：PROG-2-9866（只做資料與規格，不含遊戲邏輯程式）
> 資料檔：`assets/resources/data/friendship-action-weights.json`（status: active，36 項行為）
> 框架：`assets/scripts/core/services/FriendshipService.ts`（`add(generalId, delta, reason)`）
> 上游：`武將私塾補習班系統規格書-shards/shard-b.md` 第 7、8 章
> 裁決：使用者 2026-11-23 武將友誼由玩家行為權重表決定；PM 2026-11-23 裁決 5 題（第 6 節）。

## 1. 欄位與單位

| 欄位 | 說明 |
| --- | --- |
| `actionId` | 行為代號，前綴即分類（`combat_`、`admin_`、`reward_`、`personnel_`、`equipment_`、`diplomacy_`、`bonding_`、`capture_`、`dialogue_`）。 |
| `tag` | 性格倍率分類，對應 `personalityModifiers`。 |
| `delta` | 基礎友誼變化，整數，−30～+30。 |
| `personalityAffected` | 是否套用性格倍率。 |
| `perSeasonCap` | 每季每武將最多觸發次數（次數上限，非分數上限）。單位為**季**。 |
| `cooldownSeasons` | 同武將同行為的冷卻，單位**季**，0 為無冷卻。 |

## 2. 結算順序

1. 查 `delta`。
2. 若 `personalityAffected` 為 true 且武將有性格，乘上該性格對應 `tag` 的倍率。**同一武將只取一種性格**，不疊乘。
3. 半數遠離 0 四捨五入，clamp 到 −30～30。正負號不因倍率改變。
4. 檢查每季次數與冷卻；超過則本次不計分，不累積、不延後。
5. 呼叫 `FriendshipService.getInstance().add(generalId, delta, actionId)`。伺服器權威結算，客戶端不得直接改值。

性格倍率（同檔 `personalityModifiers`）：Loyal 對 reward／personnel／equipment／capture 為 1.25；Brave 對 combat／personnel／admin 為 1.5；Wise 對 admin 為 1.5、diplomacy 為 1.25；Playful 對 bonding／dialogue 為 1.5。未列分類為 1.0。

行為內容以 JSON 為準（戰鬥、內政、賞賜、人事、裝備、外交、結緣、俘虜、對話九類）。俘虜類：`capture_her_companion`、`capture_her_side_member` 扣分；`capture_enemy_of_her` 加 +4（PM 新增）。

## 3. 與台詞分段的對接（PM 裁決：5 段）

現況：`HallChatLines.ts` 與 `LobbyDialogueProvider.ts` 以 `minFriendship` 解鎖台詞，大廳目前傳入友誼恆為 0（PROG-2-2251 阻塞）。

| 段 | 友誼區間 | 約略對應私塾等級 | 台詞語氣 |
| --- | --- | --- | --- |
| 0 | ≤ −30 | −2 宿敵、−1 對手 | 敵意、冷言 |
| 1 | −29～19 | 0 陌生 | 公事公辦 |
| 2 | 20～59 | 1 點頭之交、2 熟識 | 客氣、閒聊 |
| 3 | 60～79 | 3 好友 | 親近、談私事 |
| 4 | ≥ 80 | 4 摯友、5 至交 | 推心置腹 |

台詞 `minFriendship` 取各段下限（段 0 以範圍下限計）。分段為純函式，不存檔。

**範圍（已裁決，PROG-2-9867）**：友誼值範圍為 −100～+100，與私塾規格一致；`FriendshipService` 下限 `_minCap` 已改為 −100，段 0 可達。台詞 `minFriendship` 接受 −100～100 的負值（超界視為 0）。舊存檔皆 ≥0，載入不變。

## 4. 「有感而發」成就與友誼加成

成就已合併（PR 2570，PROG-2-9864），規格見 `獎勵系統Base框架規格書-shards/shard-c.md` 第 13 節。
- 首次新台詞：友誼 +10（`BUNDLE_INSIGHT_FIRST`）；之後每句新台詞：友誼 +2（`BUNDLE_INSIGHT_STEP`），每武將每日上限 3 次。
- 友誼加成**沿用 `FriendshipService.add`**（經宿主效果種類 `insight` 讀 `source.ref` 取得武將），不另走本權重表，避免雙計。

## 5. 實作掛點（PROG-2-9954 已實作）

- 引擎：`assets/scripts/core/systems/FriendshipActionEngine.ts`；`GameSession.applyFriendshipAction(actionId, generalId, targetId?)` 為唯一入口（其他系統如 Antigravity 的提親被拒 `bonding_proposal_refused` 直接呼叫）。
- 事件：`GAME_SESSION_EVENTS.FriendshipActionApplied`，payload `{ generalId, targetId?, actionId, delta, applied, newValue, reason? }`；`applied=false` 時 `reason` 為 `season-cap`／`cooldown`／`no-change`。未知 actionId 或權重表未載入不發事件。
- 對象分記：省略 `targetId`＝玩家↔武將（`FriendshipService.get/add`）；帶 `targetId`＝武將↔武將配對（`getPair/addPair`，只存與我方接觸者）。次數與冷卻依「武將（或配對）＋行為」分記。
- 存檔：`friendships`、`friendshipPairs`、`friendshipActionLog`（選填，舊檔相容）。
- 已掛觸發點：
  - 戰後 `_recordMindBattle`：`combat_main_commander`（主將）、`combat_deploy_in_army`（編入）、`combat_victory_together`／`combat_defeat_together`。
  - 心智請求 `resolveMindRequest`：自告奮勇（ASK_BATTLE）答應 `admin_volunteer_accepted`／拒絕 `admin_volunteer_rejected`；建議（ADVISE）答應 `admin_advice_adopted`／拒絕 `admin_advice_ignored`。
  - `equipGear`（賞賜）：`reward_grant_equipment`／`reward_grant_treasure`（TREASURE 欄）。
  - `unequipGear`（剝奪）：`equipment_strip_gear`／`equipment_strip_treasure`。
  - `capturePrisoner`：配對友誼 ≥20 → `capture_her_companion`、≤−20 → `capture_enemy_of_her`、同 `nationId` → `capture_her_side_member`（皆結算在名冊武將對玩家的友誼）。
  - 大廳任務換季結算 `_onMissionSettled`（PROG-2-9965）：自告奮勇者 `admin_volunteer_accepted`；大成功 `admin_mission_critical`（+7）、成功 `admin_mission_success`（+4）、大失敗 `admin_mission_disaster`（−3，一般失敗不扣）。三者為新增行為（tag=admin、每季每人上限 1、受 Brave／Wise 倍率）。季報「大廳任務」行尾顯示友誼變化。
- 尚未掛（資料已備）：攻打她所在城、升降官、遣使、對話選項、結緣約會；`bonding_proposal_refused` 由 Antigravity 接。

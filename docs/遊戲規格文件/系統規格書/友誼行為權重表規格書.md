# 友誼行為權重表規格書（草案）

> 任務卡：PROG-2-9866（只做資料與規格，不含遊戲邏輯程式）
> 資料檔：`assets/resources/data/friendship-action-weights.json`（status: draft，36 項行為）
> 框架：`assets/scripts/core/services/FriendshipService.ts`（`add(generalId, delta, reason)`）
> 上游：`武將私塾補習班系統規格書-shards/shard-b.md` 第 7、8 章
> 裁決：使用者 2026-11-23 武將友誼由玩家行為權重表決定；PM 2026-11-23 裁決 5 題（第 6 節）。

## 1. 欄位與單位

| 欄位 | 說明 |
| --- | --- |
| `actionId` | 行為代號，前綴即分類（`combat_`、`admin_`、`reward_`、`personnel_`、`equipment_`、`diplomacy_`、`bonding_`、`capture_`、`dialogue_`）。 |
| `tag` | 性格倍率分類，對應 `personalityModifiers`。 |
| `delta` | 基礎友誼變化，整數，−30～+30。 |
| `personalityAffected` | 是否套用性格倍率。 |
| `perSeasonCap` | 每季每武將最多觸發次數（次數上限，非分數上限）。單位為**季**。 |
| `cooldownSeasons` | 同武將同行為的冷卻，單位**季**，0 為無冷卻。 |

## 2. 結算順序

1. 查 `delta`。
2. 若 `personalityAffected` 為 true 且武將有性格，乘上該性格對應 `tag` 的倍率。**同一武將只取一種性格**，不疊乘。
3. 半數遠離 0 四捨五入，clamp 到 −30～30。正負號不因倍率改變。
4. 檢查每季次數與冷卻；超過則本次不計分，不累積、不延後。
5. 呼叫 `FriendshipService.getInstance().add(generalId, delta, actionId)`。伺服器權威結算，客戶端不得直接改值。

性格倍率（同檔 `personalityModifiers`）：Loyal 對 reward／personnel／equipment／capture 為 1.25；Brave 對 combat／personnel／admin 為 1.5；Wise 對 admin 為 1.5、diplomacy 為 1.25；Playful 對 bonding／dialogue 為 1.5。未列分類為 1.0。

行為內容以 JSON 為準（戰鬥、內政、賞賜、人事、裝備、外交、結緣、俘虜、對話九類）。俘虜類：`capture_her_companion`、`capture_her_side_member` 扣分；`capture_enemy_of_her` 加 +4（PM 新增）。

## 3. 與台詞分段的對接（PM 裁決：5 段）

現況：`HallChatLines.ts` 與 `LobbyDialogueProvider.ts` 以 `minFriendship` 解鎖台詞，大廳目前傳入友誼恆為 0（PROG-2-2251 阻塞）。

| 段 | 友誼區間 | 約略對應私塾等級 | 台詞語氣 |
| --- | --- | --- | --- |
| 0 | ≤ −30 | −2 宿敵、−1 對手 | 敵意、冷言 |
| 1 | −29～19 | 0 陌生 | 公事公辦 |
| 2 | 20～59 | 1 點頭之交、2 熟識 | 客氣、閒聊 |
| 3 | 60～79 | 3 好友 | 親近、談私事 |
| 4 | ≥ 80 | 4 摯友、5 至交 | 推心置腹 |

台詞 `minFriendship` 取各段下限（段 0 以範圍下限計）。分段為純函式，不存檔。

**範圍衝突（待決）**：現行 `FriendshipService` 預設 clamp 為 [0, 100]，私塾規格為 −100～100。若維持現行範圍，段 0 不可達。需 PM 確認範圍；改 `_minCap` 屬 ts 改動，本卡不做。

# 友誼行為權重表規格書（草案）

> 任務卡：PROG-2-9866（只做資料與規格，不含遊戲邏輯程式）
> 資料檔：`assets/resources/data/friendship-action-weights.json`（status: draft，35 項行為）
> 上游：`武將私塾補習班系統規格書-shards/shard-b.md` 第 7、8 章（友誼 −100～100、稀疏偏移量、`friendship.add`）
> 裁決：使用者 2026-11-23，武將對玩家的友誼值由「玩家行為統一權重分數表」決定。

## 1. 欄位

| 欄位 | 說明 |
| --- | --- |
| `actionId` | 行為代號，前綴即分類（`combat_`、`admin_`、`reward_`、`personnel_`、`equipment_`、`diplomacy_`、`bonding_`、`capture_`、`dialogue_`）。 |
| `tag` | 性格倍率分類，對應 `personalityModifiers`。 |
| `delta` | 基礎友誼變化，整數，−30～+30。 |
| `personalityAffected` | 是否套用性格倍率。 |
| `dailyCapPerGeneral` | 每日每武將最多觸發次數（次數上限，非分數上限）。 |
| `cooldownDays` | 同武將同行為的冷卻天數，0 為無冷卻。 |

## 2. 結算順序

1. 查 `delta`。
2. 若 `personalityAffected` 為 true 且武將有性格，乘上該性格對應 `tag` 的倍率。**同一武將只取一種性格**，不疊乘。
3. 半數遠離 0 四捨五入，clamp 到 −30～30。正負號不因倍率改變。
4. 檢查每日次數與冷卻；超過則本次不計分，不累積、不延後。
5. 以 `friendship.add(reason=actionId)` 寫入偏移量。伺服器權威結算，客戶端不得直接改值。

性格倍率（同檔 `personalityModifiers`）：Loyal 對 reward／personnel／equipment／capture 為 1.25；Brave 對 combat／personnel／admin 為 1.5；Wise 對 admin 為 1.5、diplomacy 為 1.25；Playful 對 bonding／dialogue 為 1.5。未列分類為 1.0。

行為內容與數值以 JSON 為準（戰鬥、內政、賞賜、人事、裝備、外交、結緣、俘虜、對話九類）。

## 3. 與台詞分段的對接

現況：`HallChatLines.ts` 與 `LobbyDialogueProvider.ts` 以 `minFriendship` 決定台詞解鎖，大廳目前傳入友誼恆為 0（PROG-2-2251 阻塞）。專案內**沒有** `relationBucket` 或「5 段」定義，正式分段只有私塾規格的 7 級。

建議（待決，見第 5 節 Q1）折成 5 段：

| 段 | 友誼區間 | 約略對應私塾等級 | 台詞語氣 |
| --- | --- | --- | --- |
| 0 | ≤ −30 | −2 宿敵、−1 對手 | 敵意、冷言 |
| 1 | −29～19 | 0 陌生 | 公事公辦 |
| 2 | 20～59 | 1 點頭之交、2 熟識 | 客氣、閒聊 |
| 3 | 60～79 | 3 好友 | 親近、談私事 |
| 4 | ≥ 80 | 4 摯友、5 至交 | 推心置腹 |

台詞 `minFriendship` 取各段下限（−100／−29／20／60／80）。分段為純函式，不存檔。

# 名將挑戰賽賽季歷史存檔結構與最高連勝留存規格書

> **模組識別碼**：`TRN-09`  
> **系統歸屬**：名將挑戰賽（Tournament）賽季歸檔與歷史記錄  
> **單一真相來源**：本規格書確立名將挑戰賽歷史賽季紀錄（TournamentSeasonHistory）資料模型、最高連勝與快照關聯留存、以及跨季連續 Rollover 狀態機之唯一權威標準。

---

## 一、系統概述與架構原則

當名將挑戰賽每 14 天賽季結束時，系統需對當季之競技成果進行歷史封存。無論玩家在當季是否活躍、甚至長達數月未登入，狀態機均需以確定性演算法補齊過渡賽季紀錄，確保個人生涯戰報與待領獎勵完整無缺。

### Unity / 架構對照
- **生涯歷史庫**：類似 Unity 存檔中的 `SeasonArchiveEntry[]`，支援本機 JSON 序列化與伺服端雲端存檔雙向同步。
- **純狀態機推進**：以毫秒時間戳記（`nowMs`）為唯一驅動力，避免依賴每幀 Update。

---

## 二、賽季歷史條目資料模型

```typescript
export interface TournamentSeasonHistory {
    seasonIndex: number;         // 賽季序號（1, 2, 3...）
    finalPoints: number;         // 賽季結束時的最終排名積分
    finalTier: RankTier;         // 依最終積分判定之最終段位
    bestWinStreak: number;       // 當季創下之最高連勝紀錄
    snapshotId: string | null;   // 當季參賽之鏡像快照 ID；未參賽為 null
    rewardClaimed: boolean;      // 該季段位獎勵是否已領取
}
```

### 關鍵欄位約束
1. `snapshotId`：若玩家在當季曾完成陣容登錄或參戰，此欄位必定記錄快照 ID（如 `TRN_S1_1762512000000`）；若整個 14 天未曾登錄陣容，則記為 `null`。
2. `rewardClaimed`：封存時預設為 `false`，唯有經由玩家於介面手動領取獎勵後方可翻轉為 `true`。

## 三、跨季連續 Rollover 推進狀態機

當客戶端開啟或伺服器排程運作時，若當前時間已超越賽季 14 天邊界，執行迴圈推進：

```typescript
export function rolloverTournament(state: Readonly<TournamentState>, nowMs: number): TournamentState {
    let next: TournamentState = { ...state, history: state.history.slice() };
    
    // 每次跨越 14 天即結算一季，支援一次跨越多季
    while (tournamentDayOf(next, nowMs) >= TOURNAMENT_SEASON_DAYS) {
        // 1. 封存當季紀錄進歷史表
        next.history.push({
            seasonIndex: next.seasonIndex,
            finalPoints: next.points,
            finalTier: rankTierOf(next.points),
            bestWinStreak: next.bestWinStreak,
            snapshotId: next.team?.snapshotId ?? null,
            rewardClaimed: false,
        });

        // 2. 推進至新賽季並執行軟重置扣分
        next = {
            ...next,
            seasonIndex: next.seasonIndex + 1,
            seasonStartMs: next.seasonStartMs + TOURNAMENT_SEASON_DAYS * TOURNAMENT_DAY_MS,
            points: softResetPoints(next.points),
            team: null,                    // 清空參賽快照，新賽季需重新登錄
            entryDay: 0,
            entriesToday: 0,              // 重置每日參戰次數
            lastPrepRegisterDay: -1,
            competitionReplaces: 0,        // 重置替換配額
            winStreak: 0,
            bestWinStreak: 0,             // 重置新賽季最高連勝計數
            bracketRound: 0,              // 重置淘汰賽樹回初賽
            championships: 0,             // 重置當季奪冠數
        };
    }
    
    return next;
}
```

## 四、驗收條件與測試案例 (Test Cases)

- **TC-TRN-29（單季正常跨季結算）**：
  - 賽季第 14 天觸發 rollover，歷史陣列增加 1 筆紀錄，記錄第 1 季之積分、段位與快照 ID，新賽季 index 變為 2。
- **TC-TRN-30（連續多季離線追趕）**：
  - 玩家離線 42 天（跨越整整 3 個賽季），狀態機正確生成 3 筆歷史紀錄，每季依序套用段位軟重置，新賽季 index 遞增 3。
- **TC-TRN-31（未參戰賽季快照為 null）**：
  - 當季完全未登錄陣容，跨季時封存之 `snapshotId` 為 `null`，最高連勝為 0。
- **TC-TRN-32（獎勵初始狀態未領）**：
  - 所有新生成的歷史條目其 `rewardClaimed` 均為 `false`。

# 名將挑戰賽陣容鏡像快照凍結與替換配額狀態機規格書

> **模組識別碼**：`TRN-03`  
> **系統歸屬**：名將挑戰賽（Tournament）陣容快照與替換管理  
> **單一真相來源**：本規格書確立名將挑戰賽參賽陣容鏡像快照（TournamentTeamSnapshot）之凍結機制、資料隔離原則與培育/競賽期替換配額之唯一權威標準。

---

## 一、系統概述與架構原則

為了確保非同步離線對戰（Asynchronous PvP）的確定性、公平性與伺服端快速比對，參戰武將隊伍在特定時機進行**不可變深拷貝凍結（Immutable Deep Freeze）**。

### Unity / 架構對照
- **鏡像快照**：類似 Unity 伺服器端的 `TeamSnapshotDTO`，對戰時只讀取該 DTO，不受本體實例（Instance）數值變更干擾。
- **配額控管**：純狀態機維護，防止無限制變更陣容洗分或惡意試探。

## 二、陣容快照資料結構

```typescript
export interface SnapshotGeneral {
    uid: string;
    name: string;
    category: 'WARRIOR' | 'SCHOLAR'; // 武官 / 文官
    stats: {
        str: number;
        int: number;
        lea: number;
        pol: number;
        cha: number;
    };
    factorTags: readonly string[];      // 繼承之六色因子標籤
    tallyId: string | null;             // 配戴虎符 ID
    tallyBossTags: readonly string[];   // 虎符附加之剋制標籤
    tactics: readonly string[];         // 攜帶戰法清單
    power: number;                      // 單將戰力
}

export interface TournamentTeamSnapshot {
    snapshotId: string;
    seasonIndex: number;
    teamMembers: readonly SnapshotGeneral[];
    totalPower: number;
    createdAtTimestamp: number;
    isLocked: boolean;
}
```

## 三、首次參戰凍結與資料隔離原則

1. **凍結時機**：
   - 培育期：玩家點擊「確認登錄」時產出初始快照。
   - 競賽期：若培育期未手動登錄，在第 7 天首次點擊「進入對戰」時強制以當前隊伍自動生成快照並凍結。
2. **絕對隔離（Firewall Isolation）**：
   - 快照生成後，本體武將的後續等級提升、裝備替換、退役、結緣或傳承，**絕對不影響已凍結之快照**。
   - 對戰模擬引擎（Simulation Engine）僅讀取快照數值，不向外部實體回寫任何戰損或消耗。

## 四、雙相位替換配額狀態機

```typescript
export interface TournamentQuotaState {
    seasonIndex: number;
    preparationReplacesUsedToday: number; // 培育期今日已用替換次數
    competitionReplacesUsedSeason: number; // 競賽期整季已用替換次數
}

export const TOURNAMENT_QUOTA_RULES = {
    preparationDailyReplaceLimit: 1, // 培育期每日可重登錄上限
    competitionSeasonReplaceLimit: 1, // 競賽期整季緊急替換上限
} as const;
```

### 替換權限檢驗演算法
```typescript
export function canReplaceSnapshot(
    phase: TournamentPhase,
    quota: TournamentQuotaState
): { allowed: boolean; reason?: string } {
    if (phase === 'ENDED') {
        return { allowed: false, reason: 'SEASON_ENDED' };
    }
    
    if (phase === 'PREPARATION') {
        if (quota.preparationReplacesUsedToday >= TOURNAMENT_QUOTA_RULES.preparationDailyReplaceLimit) {
            return { allowed: false, reason: 'PREPARATION_DAILY_LIMIT_REACHED' };
        }
        return { allowed: true };
    }
    
    // phase === 'COMPETITION'
    if (quota.competitionReplacesUsedSeason >= TOURNAMENT_QUOTA_RULES.competitionSeasonReplaceLimit) {
        return { allowed: false, reason: 'COMPETITION_SEASON_LIMIT_REACHED' };
    }
    
    return { allowed: true };
}
```

## 五、原子更新與狀態流轉

1. **培育期重登錄**：
   - 若 `canReplaceSnapshot` 檢驗通過，產出新快照覆蓋 `teamSnapshot`。
   - 狀態計數：`preparationReplacesUsedToday += 1`。
2. **競賽期緊急替換**：
   - 若 `canReplaceSnapshot` 檢驗通過，產出新快照覆蓋 `teamSnapshot`。
   - 狀態計數：`competitionReplacesUsedSeason += 1`。
   - 當 `competitionReplacesUsedSeason >= 1` 時，標記 `isLocked = true`。
3. **每日跨日重置**：
   - 跨日維護時，僅重置 `preparationReplacesUsedToday = 0`。
   - `competitionReplacesUsedSeason` 跨日**不重置**，持續累積直至整季結算。

## 六、驗收條件與測試案例 (Test Cases)

- **TC-TRN-09（深拷貝隔離測試）**：
  - 生成快照後，將本體武將武力屬性由 100 修改為 500，重新讀取快照武力值仍為 100。
- **TC-TRN-10（培育期每日 1 次限制）**：
  - 培育期當日首次更換陣容成功，第二次更換被拒絕並回傳 `PREPARATION_DAILY_LIMIT_REACHED`；跨日後可再次更換 1 次。
- **TC-TRN-11（競賽期整季僅限 1 次緊急替換）**：
  - 競賽期第 8 天使用 1 次緊急替換成功；第 9 天再次請求替換被拒絕並回傳 `COMPETITION_SEASON_LIMIT_REACHED`。
- **TC-TRN-12（結束期絕對鎖定）**：
  - 賽季進入 `ENDED` 相位後，任何替換請求一律回傳 `SEASON_ENDED`。

## 1. 核心宗旨與設計哲學

血脈命鏡主面板（`BloodlineMirrorPanelComposite`）中，`mirror-lock-badge`（鎖定印鑑徽章）、`mirror-unowned-state-tag`（未持有狀態標籤）與 `mirror-confirm-cta`（主操作確認按鈕）構成命鏡之核心互動三角。為確保前端元件接線一致、事件響應確定，並杜絕快速連擊造成之狀態錯亂，本規格書正式規範三大元件之**節點命名**、**資料綁定契約**與**點擊防刷狀態機**。

### 2.2 前端元件資料綁定介面

```typescript
export interface MirrorInteractionWiringContract {
  state: 'UNOWNED' | 'UNAWAKENED' | 'AWAKENING' | 'AWAKENED' | 'OWNED_LEGENDARY';
  
  // 1. 鎖定徽章控制
  lockBadge: {
    visible: boolean;                 // UNOWNED 或 UNAWAKENED 時為 true
    spriteFrame: string;              // db://assets/resources/sprites/mirror/lock_seal.png
    unlockAnimationTrigger: boolean;  // 突破瞬間播放碎裂金光動效
  };
  
  // 2. 狀態標籤控制
  unownedStateTag: {
    visible: boolean;                 // UNOWNED 時必顯示
    i18nKey: string;                  // 如 UI_MIRROR_TAG_UNOWNED
    textColorHex: string;             // 如 #E5E7EB
  };
  
  // 3. 確認按鈕控制
  confirmCta: {
    enabled: boolean;                 // 當前條件是否允許點擊
    labelI18nKey: string;             // 如 UI_MIRROR_CTA_AWAKEN
    sfxTrigger: string;               // 點擊音效 (sfx_mirror_chime)
    cooldownMs: 400;                  // 防刷冷卻時間 (毫秒)
  };
}
```

## 3. 防刷連擊與事件響應狀態機

1. **防刷冷卻（Debounce Control）**：
   - 點擊 `mirror-confirm-cta` 瞬間，按鈕立即進入 `BUSY` 狀態，外觀呈半透明置灰（Opacity: 0.75），並啟動 $400\text{ms}$ 倒數。
   - 冷卻期間遮斷所有後續觸控事件，避免向服務端重複發送覺醒請求。
2. **解鎖演出時序（Unlock Sequence）**：
   - 當武將首次覺醒時，`mirror-lock-badge` 執行 0.4 秒水墨震顫 $\rightarrow$ 0.2 秒金芒碎裂 $\rightarrow$ 節點完全隱藏（`active = false`）。
   - 演出完畢後，`mirror-confirm-cta` 立即更新為「命鏡洗髓」狀態。

## 4. 驗收測試案例 (Test Cases)

- **TC-BMV3-07-01【未持有狀態元件顯隱連動】**：在武將未獲得時，`mirror-lock-badge` 與 `mirror-unowned-state-tag` 皆為顯示狀態，按鈕文案為「尋訪求籤」。
- **TC-BMV3-07-02【400ms 防刷連點阻斷】**：使用自動化腳本以 50ms 間隔連續點擊 `mirror-confirm-cta` 10 次，系統嚴格僅觸發 1 次後台喚醒事件。
- **TC-BMV3-07-03【解鎖碎裂動效與按鈕切換】**：觸發覺醒後，鎖定徽章順暢播放碎裂動畫並隱藏，按鈕平滑切換為「洗髓」，無破圖閃爍。

# 大廳官職快照讀取與功能欄位熱點解鎖規格書

## 1. 核心定位與設計理念
本規格書定義三國生活（3KLife）主城大廳系統讀取「官職快照（Officer Snapshot）」以解鎖各項核心功能、任務欄位與場景熱點之驅動規格（對應 WBS `HALL-11`）。
大廳作為遊戲玩法分流樞紐，堅持**權限單一真相來源（Single Source of Truth）與只讀解耦原則**：
1. **大廳只讀快照**：官職系統為玩家官位與晉升條件的唯一真源；大廳僅讀取由存檔或伺服端派發之快照物件，絕不私自修改官職階位。
2. **階位防呆平滑退回**：若快照資料損毀、格式不符或超出邊界，系統自動平滑降級為第 1 階（鄉里義士），保證客戶端零當機崩潰。
3. **查表映射動態解鎖**：任務難度、任務並行欄位、沙盤入場階段、熱點開放度完全依階位查表，杜絕條件硬編碼。

---

## 2. 官職階位與防呆規範 (`normalizeOfficerSnapshot`)
官職系統劃分為 1 至 5 階（`OFFICER_TIER_MIN = 1`, `OFFICER_TIER_MAX = 5`）：
- **階位代碼標準**：代碼字串格式為 `OFFICER_TIER_{N}`（$N \in [1, 5]$）。
- **快照標準結構**：
  ```typescript
  export interface OfficerSnapshot {
      tier: number;  // 1 ~ 5
      code: string;  // 如 "OFFICER_TIER_1"
  }
  ```
- **正規化容錯規則**：
  若傳入物件為空、型別非物件、代碼格式不符，或 `Current_Tier` 數值非介於 1 至 5 之整數，一律自動糾正為預設值：`{ tier: 1, code: 'OFFICER_TIER_1' }`。

## 3. 大廳功能與欄位解鎖矩陣 (`officerUnlocksOf`)
系統依據標準化之官職階位，由純邏輯函式 `officerUnlocksOf` 計算對應之解鎖權限集：

| 階位 (Tier) | 代表官職範例 | 任務難度上限 (`questDifficultyCap`) | 任務欄位數 (`questColumns`) | 沙盤階段 (`sandtableStage`) | 熱點數 (`hotspotCount`) | 特殊高階權限 |
| :---: | :--- | :---: | :---: | :---: | :---: | :--- |
| **1** | 鄉里義士 | `basic` (初級) | 1 欄 | `null` (未解鎖) | 1 個 | 無 |
| **2** | 縣尉縣丞 | `normal` (普通) | 2 欄 | `null` (未解鎖) | 2 個 | 無 |
| **3** | 郡守刺史 | `elite` (精英) | 2 欄 | `S1` (郡國經略) | 3 個 | 無 |
| **4** | 州牧都督 | `advanced` (進階) | 3 欄 | `S2` (跨州會盟) | 4 個 | 聯盟文書 (`allianceDocs = true`) |
| **5** | 霸府重臣 | `hell` (地獄) | 4 欄 | `S3` (天下遠征) | 5 個 | 反霸權會盟 (`antiHegemonySummit = true`) |

## 4. 大廳任務牆玩家狀態映射 (`hallPlayerOf`)
為滿足雙牆任務板之過濾與情報匹配需求，系統提供 `hallPlayerOf` 將解鎖權限轉換為統一之玩家屬性視圖：
```typescript
export function hallPlayerOf(
    unlocks: OfficerUnlocks, 
    intel = 0
): { rankTier: number; worldStage: number; intel: number }
```
- **世界沙盤階段平滑轉換**：
  若沙盤階位存在（如 `S1`, `S2`, `S3`），提取數字轉換為對應數值（1、2、3）；若尚未解鎖（`null`），為避免既有常態任務牆被完全隱藏，退回安全基數 `worldStage = 1`。
- **情報度邊界約束**：
  情報值（累積自監獄提審產出）強制透過整數運算與區間夾回約束於 $[0,\, 100]$：
  $$\text{intel} = \min\left(100,\, \max(0,\, \lfloor \text{rawIntel} \rfloor)\right)$$

## 5. Unity 與 Cocos Creator 概念對照
| 概念維度 | Cocos Creator 實作架構 | Unity 引擎對照架構 |
| :--- | :--- | :--- |
| **快照資料流** | `OfficerSnapshot` 作為不可變 DTO 由 GameSession 傳入 | 唯讀 struct 或 C# `record ProgressionSnapshot` |
| **UI 權限控制** | `OfficerDisplay` / `OfficerPanelsController` 依 `unlocks` 切換節點 active | 透過 Presenter/ViewModel 綁定按鈕 Interactable 與 GameObject 顯隱 |
| **非破壞性解鎖** | 純查表對照，資料異常退回 Tier 1，無拋錯崩潰風險 | 使用 Fallback Null-Object 模式保證 UI 元件安全渲染 |

## 6. 驗證條件與測試矩陣 (Acceptance Gate)
1. **TC-OFC-01 壞值與空資料容錯**：傳入 `null`、`{}`、負數或無效字串，驗證皆回傳 Tier 1 與預設欄位。
2. **TC-OFC-02 沙盤階段分水嶺驗證**：驗證 Tier 1~2 沙盤階段為 `null`，Tier 3~5 分別精確為 `S1`、`S2`、`S3`。
3. **TC-OFC-03 欄位與高階特權階梯**：驗證 Tier 4 解鎖 `allianceDocs`，Tier 5 解鎖地獄難度與 `antiHegemonySummit`。
4. **TC-OFC-04 任務牆玩家情報映射**：驗證傳入浮點數或超出 100 之情報值均能正確夾回整數區間 $[0, 100]$。

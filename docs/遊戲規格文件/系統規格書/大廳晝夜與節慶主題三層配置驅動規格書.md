# 大廳晝夜與節慶主題三層配置驅動規格書

## 1. 核心定位與設計理念
本規格書定義三國生活（3KLife）主城大廳場景之「晝夜光影與節慶活動主題」三層配置驅動模型（對應 WBS `HALL-09`）。
大廳作為玩家每日登入與頻繁進出的核心視覺門戶，需具備時段動態氛圍感與節日活動變裝能力。本系統堅持**純配置驅動（Data-Driven）與無分支解耦原則**：
1. **主程式零節慶硬編碼**：場景腳本嚴禁撰寫 `if (isSpringFestival) { ... }` 等特定節日硬編碼分支。
2. **三層視覺分離**：將主題資產嚴格解耦為**背景層（Background）**、**裝飾層（Decorations）**與**前景粒子層（Particle）**。
3. **查表降級防呆**：若節慶主題 ID 查無配置或設為未啟用，自動平滑退回基礎背景與常態氛圍，不丟出異常、不殘留前次活動資產。

---

## 2. 晝夜時段與光影濾鏡模型
大廳之時間氛圍依據伺服端或本地時段（UTC+8）自動切換晝夜模式：
- **四態模式代碼 (`HALL_DAY_NIGHT_MODES`)**：
  - `DAWN`（清晨）：晨光拂曉，清冷微光。
  - `DAY`（白天）：日光充沛，高明度暖色。
  - `DUSK`（黃昏）：落日餘暉，金橘色斜陽。
  - `NIGHT`（夜晚）：月色靜謐，深藍冷光。
- **色調疊加（`Overlay_Tint`）**：
  - 由 `Current_Theme.Overlay_Tint` 定義十六進位色碼或 RGBA 參數，透過 UI/場景材質的全域色彩疊加實現自然過渡，毋須為不同時段重繪整套 2D 背景底圖。

## 3. 節慶三層配置與解析架構 (`LobbyThemeResolver`)
系統透過資料表 `HallThemeCatalog` 載入所有註冊之節慶配置，並由純邏輯解析器 `resolveHallTheme` 輸出扁平結構 `HallThemeFrame`。

### 3.1 三層結構定義 (`HallFestivalLayers`)
每個節慶插槽均由三層構成：
1. **背景層 (`backgroundId: string | null`)**：
   - 節慶專屬之主背景底圖（如春節張燈結綵宮闕）。若為 `null`，則直接沿用當前基礎背景 `theme.Background_ID`。
2. **裝飾層 (`decorationIds: string[]`)**：
   - 疊加於大廳樑柱、屏風、地面之裝飾資產列表（如紅燈籠、爆竹花籃、雪人等）。若節慶未啟用，回傳空陣列 `[]`。
3. **前景粒子層 (`particleId: string | null`)**：
   - 浮動於最上層之全域粒子特效（如漫天飛雪、落櫻紛飛、煙火光芒）。若無特效則為 `null`。

### 3.2 扁平解析幀 (`HallThemeFrame`)
```typescript
export interface HallThemeFrame {
    dayNight: HallDayNightMode;
    overlayTint: string;
    baseBackgroundId: string;
    festivalActive: boolean;
    layers: {
        background: string;
        decorationIds: string[];
        particleId: string | null;
    };
}
```

### 3.3 解析邏輯與防呆鐵律
- **哨兵值常數**：節慶未啟用時之識別碼統一為 `NO_FESTIVAL_ID = "NONE"`。
- **解析決策鏈**：
  $$\text{festivalActive} = (\text{Theme\_ID} \neq \text{"NONE"}\ \land\ \text{Theme\_ID} \in \text{Catalog.festivals})$$
- 若 `festivalActive` 為 `true`，以節慶背景覆蓋基礎背景（`festival.backgroundId ?? theme.Background_ID`），複製裝飾清單與前景粒子。
- 若 `festivalActive` 為 `false`，背景嚴格維持 `theme.Background_ID`，裝飾清單為 `[]`，粒子特效設為 `null`。

## 4. Unity 與 Cocos Creator 概念對照
| 概念維度 | Cocos Creator 實作架構 | Unity 引擎對照架構 |
| :--- | :--- | :--- |
| **主題資產解耦** | `LobbyThemeResolver` 解析 `HallThemeFrame`，依 ID 動態載入 `SpriteFrame` | 類似 Addressables / AssetBundle 以 Label 標籤分組載入 |
| **場景單一入口** | `LobbyHallThemeApplier` 監聽 Theme 變更並指派節點 Sprite 與 Particle | `ThemeManager` 監聽 ScriptableObject 事件並更換 Image / ParticleSystem |
| **零腳本分支** | 腳本只認三層資料結構，新增節慶只需擴充 `hall-theme.json` | 透過 `ThemeConfigSO` 配置檔驅動，無任何 `switch(festival)` |

## 5. 驗證與驗收矩陣 (Acceptance Gate)
1. **TC-HALL09-01 常態無節慶解析**：傳入 `Festival_Theme_ID = "NONE"`，驗證輸出 `festivalActive = false`，背景為 `baseBackgroundId`，裝飾清單為空。
2. **TC-HALL09-02 未知節慶優雅降級**：傳入未在 Catalog 登記之未知節慶字串，驗證不拋出例外，系統平滑降級為常態顯示。
3. **TC-HALL09-03 節慶覆蓋與三層完整性**：傳入有效節慶 ID，驗證背景成功置換、裝飾清單深層複製（不可引用原始陣列造成污染）、粒子層正確就緒。

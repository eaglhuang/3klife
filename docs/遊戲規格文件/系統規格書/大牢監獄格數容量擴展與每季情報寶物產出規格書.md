# 大牢監獄格數容量擴展與每季情報寶物產出規格書

> 標籤：`系統規格` `戰場俘虜` `監獄系統` `格數擴充` `情報產出` `POW-06`
> 狀態：`正式生效` · 責任模組：`PrisonerOfWar` · 參照：`POW-06` / `ECO-14` / `EQP-09`

---

## 1. 模組定位與設計理念

在三國征伐中，敵將若暫不招降亦不願輕易放虎歸山，投入大牢關押是榨取敵國軍政機密與地方資產的重要手段。
本規格書定義監獄系統之容量擴展階梯、季度情資產能與傳家寶物上繳機制（`PrisonerOfWar.ts`），遵循以下原則：
1. **城池等級驅動擴容**：監獄容量與太守府主城等級嚴格綁定，隨領地建設自然解鎖更多牢房格位。
2. **數值化季度審訊產出**：依據在押囚犯的智力（INT）與政治（POL），每季穩定產出軍事情報與物資。
3. **無期徒刑傳家寶進貢**：被長期關押之名將，每季有機率被獄卒搜出或自願進貢傳家寶物。
4. **容量滿額防溢出**：當關押人數達到當前格位上限時，嚴禁繼續收監，防止牢房超載。

## 2. 監獄容量階梯表 (PRISON_CAPACITY_BY_LEVEL)

主城太守府等級（`territoryLevel`）決定監獄可用格數（`slots`）：

$$\text{Capacity}(\text{Lv}) = \min\left(10, 3 + \left\lfloor \frac{\max(1, \text{Lv}) - 1}{2} \right\rfloor\right)$$

### 2.1 門檻配置矩陣
- `PRISON_SLOTS_INITIAL = 3`（初始最低保底 3 格）。
- `PRISON_SLOTS_MAX = 10`（城防大牢最高上限 10 格）。
- 每提升 2 個主城等級，牢房格位 $+1$。

## 3. 季度情資與物資產能 (prisonYieldOneSeason)

每季時間推進時，全體關押中之囚犯（`PrisonEntry`）合併計算產能：

$$\text{TotalIntel} = \sum_{p \in \text{Prisoners}} \lfloor \text{INT}_p \times 0.1 \rfloor$$
$$\text{TotalResource} = \sum_{p \in \text{Prisoners}} \lfloor 50 + \text{POL}_p \times 0.5 \rfloor$$

| 產能類別 | 單一囚犯計算公式 | 設計詮釋與用途 |
|---|---|---|
| **情報 (`intel`)** | **$\lfloor \text{int} \times 0.1 \rfloor$** | 獄中審訊套取之敵國布防機密，提升大地圖軍事任務品質 |
| **物資 (`resource`)** | **$\lfloor 50 + \text{pol} \times 0.5 \rfloor$** | 督促俘虜勞作與清查其私庫產出之地方補貼物資 |

## 4. 傳家寶物每季進貢演算法 (rollPrisonTreasureDonors)

長年關押之囚犯具備微小機率上繳家族密藏之傳家重寶（對應 `EQP-09` 裝備系統）：
- **掉落檢定率 (`PRISON_TREASURE_DROP_RATE = 0.05`)**：每季每位在押囚犯獨立執行一次 5% 機率判定。
- **演算法**：
  $$\text{isDonor} = (\text{random}() < 0.05)$$
- **劇本文案**：命中進貢之俘虜觸發專屬劇本行：
  `「囚犯 {Name} 交出了一件傳家寶：{ItemName}」`。

---

## 5. 關押前置檢核與邊界約束

1. **滿額阻斷 (`PRISON_FULL`)**：
   在戰後四選一處置中，若 $\text{prisonUsed} \ge \text{slots}$，拒絕執行 `imprison` 決策，回傳失敗代碼 `PRISON_FULL`。
2. **舊檔規格化容錯 (`normalizePrisonState`)**：
   讀取存檔時，若 `slots` 遺失或毀損，安全夾取於 $[3, 10]$ 區間；損壞之囚犯條目自動剔除。

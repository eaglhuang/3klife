## 18. 共用 base 框架對應（PROG-2-9198 追加，使用者特別強調）

原則：同本質的系統一律用共用 base 框架，玩法只做包裝與差異 JSON。本規格前面各章的 JSON（第 6、7、11、14~17 章）都是「差異資料」，實作時掛在下列四套 base 的擴充欄位上，**不另外定義一套物品結構或事件結構**。

### 18.1 四套 base 與本規格各項的對應

| base | 本規格項目 | 只寫差異欄位 |
| --- | --- | --- |
| **任務**（接任務、解任務、發獎懲） | 歷練格子事件（屬性格、事件格、試煉格、貴人格、機緣格、岔路、風景，第 6 章）；自動開寶每一間房（第 17 章，同一個任務實例以自動解算）；生日小事件（第 3.3 節）；AI 委託季內的日常任務與活動處理（第 14.3 節） | `cellType`、`pathId`、`weight`（抽選權重）、`trial`（試煉成功率公式）、`rewards[]`（用任務既有獎懲結構，獎勵種類 = 職業屬性點／物品／旗標）、`autoResolve`（自動解算旗標與 `pointsMul`）、`delegateEfficiency`（委託折扣 0.9） |
| **物品庫存**（道具、寶物（傳家寶）、裝備同一套；持有者不同只換名字：背包、庫房、公庫、倉庫） | 歷練寶物與道具獎勵（第 7.4 節）、信物槽；出生禮的綁定寶物、路引、因子引（第 2.5 節）；控骰符、改名令；時光藥水（第 15.4 節）；特殊食物（第 16 章）；成長信物（結業後保留） | `boundChildId`（綁定孩子）、`rarity` 1~4、`effectKind`（`signet`、`routeGuide`、`awakenBias`、`dice`、`ageBoost`、`rename`）；`ageBoost` 效果欄位：`boost`、`durationSeasons`、`compRate`、`ageBands`（0.6 倍等）、`dispatchedMul`；持有者名稱：孩子「成長紀念欄」、家族「庫房」，不新增庫存結構；食物與藥水就是「消耗品」ItemDef |
| **商店** | 市集購買食物（蜜棗糕等，第 16.2 節）、乳母雇用（第 15.3 節）、廚師或家族酒店製作的食物上架（預留，PROG-2-9199） | `costMultPerExtraMinor`（人數成本倍率，第 15.7 節）、`freeForFirstTwo`（前兩位子嗣免費額度）、`supplierType`（market／chef／familyHotel），價格與庫存沿用商店 base |
| **技能**（人物、戰場、培育、家族技能與個人天賦） | 職業屬性 `careerAttr`（武將、領袖、文官、教官，第 5.3 節）；專長 8 種（第 5.5 節）；廚藝專長 `cuisine`（預留，第 16.3 節） | `kind`（`career`、`specialty`）、`value` 0~100、`cap`、來源標籤（`trial`、`growth`…）；效果表 `careerEffects` 用技能 base 的加成欄位；不新增獨立屬性系統 |

### 18.2 不屬於這四套、但需注意的地方

- 歲月成長點 `yearPoints`（第 16.5 節）：入學時轉成起始五維，掛在培育（技能 base 的培育類加成）上，不獨立成系統；若技能 base 沒有「入學前累積值」概念，列為候選（18.3 第 5 項）。
- 年回合與委託（第 14 章）、催長引擎（第 15 章）本身是流程與規則，不是上述四類；其中「持續 N 季的效果」見 18.3 第 4 項。

### 18.3 建議新增共用框架候選（發現兩處以上類似、不屬於四類；只列候選，不自行定案，請總 PM 裁決）

| # | 候選框架 | 類似的出現處 | 共同本質 |
| --- | --- | --- | --- |
| 1 | 確定性隨機與防 SL 工作階段（`DeterministicRngSession`） | 學府 AcademyAntiSLManager、歷練（第 4.4 節）、自動開寶（17.5）、AI 委託（14.7）、命名建議（2.4）、心願（5.4） | 固定種子、`(seedHex, stepIndex)`、先存後顯示、重開自愈、連續 3 次異常退出的保底懲罰 |
| 2 | 加權抽樣表（`WeightedTable`） | 歷練屬性格與寶物稀有度、出生禮抽取、命名建議、心願權重、自動開寶等階與房間抽選、機緣格，另有轉蛋池 | JSON 權重表 + 整數抽樣 + 保底與去重 |
| 3 | 人生節點儀式流程（`MilestoneFlow`） | 周歲抓周、開蒙揭曉、歷練、入學、結業、及笄分流、生日事件 | 觸發（跨越檢查）→ 彈窗 → 選擇 → 結算 → 回寫 → 佇列與必中斷 |
| 4 | 持續數季的狀態效果（`SeasonEffect`） | 母乳、乳母、時光藥水、食物催長、學府增益、戰場 buff 的季級版本 | 來源、強度、持續季數、疊加與上限規則、凍結時不遞減 |
| 5 | 解鎖條件評估（`UnlockCondition`） | 年回合解鎖、名門乳母解鎖、廚師與家族酒店等級、學府入學令、祠堂教官槽 | 以資料表達「年份、進度、建築等級、人員條件、冷卻」並統一評估與提示缺哪項 |
| 6 | 自動解算與折扣（`AutoResolve`） | AI 委託（內政、任務、小戰）、自動開寶、學府自動培育、任務牆加速 | 「玩家省時間，換取固定折扣」的規則與報表式結算 |
| 7 | 必中斷事件佇列（`InterruptQueue`） | 多子嗣同季節點佇列、委託與年回合中斷、學府期中打斷、年終守城 | 事件優先序、排隊、處理完繼續 |

以上 7 項皆為候選，未影響本規格內容；本規格的 JSON 已盡量以「權重表」「持續季數」「解鎖條件」三種通用形狀書寫，方便日後抽成共用框架。

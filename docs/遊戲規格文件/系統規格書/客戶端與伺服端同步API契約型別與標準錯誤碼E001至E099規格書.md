# 客戶端與伺服端同步API契約型別與標準錯誤碼E001至E099規格書

> **所屬模組**：`3.6 數值、架構與底層支援 (SYNC-01 / DS-01)`  
> **單一真相來源**：定義客戶端與伺服端資料同步之共用 API 契約型別（`/sync/delta` 與 `/sync/full`）、標準錯誤碼表（E001 ~ E099）與錯誤退避重試狀態機。

---

## 1. 雙軌同步 API 契約型別

客戶端與伺服器間之資料同步採增量優先、全量保底之雙軌協議：

```typescript
// 增量同步請求: POST /sync/delta
export interface SyncDeltaRequest {
  playerId: string;
  sessionToken: string;            // 24 小時輪換憑據
  baseHash: string;                // 前次同步完成之 64-char SHA256
  actionRecords: Array<{
    seqId: number;
    actionType: string;
    timestamp: number;
    payload: Record<string, unknown>;
  }>;
  patches: Array<{                 // RFC 6902 標準 JSON Patch
    op: "add" | "remove" | "replace";
    path: string;                  // 必須在白名單內
    value?: unknown;
  }>;
}

export interface SyncDeltaResponse {
  success: boolean;
  newHash: string;                 // 本次套用後的新 Hash
  appliedSeq: number;              // 伺服器已確認之最高序號
  serverTime: number;              // 伺服器校時時間戳記
  nextSessionToken?: string;       // 若憑據即將到期則輪換
}

// 全量快照請求: POST /sync/full
export interface SyncFullRequest {
  playerId: string;
  sessionToken: string;
  saveVersion: string;             // 如 "1.4.0"
  compressed: boolean;             // 固定為 true
  payloadGzipBase64: string;       // 完整存檔 Gzip 壓縮後的 Base64 字串
}

export interface SyncFullResponse {
  success: boolean;
  snapshotHash: string;
  serverTime: number;
}
```

## 2. 標準錯誤碼表 (Error Codes E001 ~ E099)

當伺服器拒絕同步請求時，統一回傳 `{ "errorCode": "E0xx", "message": string }`：

| 錯誤碼 | HTTP 狀態 | 錯誤名稱 | 觸發原因與防護措施 | 客戶端處理動作 |
|:---:|:---:|:---|:---|:---|
| **E001** | 400 | `INVALID_SCHEMA` | Request Body 不符合 JSON Schema 定義 | 終止同步，記錄日誌 |
| **E002** | 400 | `PATCH_PATH_FORBIDDEN`| JSON Pointer 超出安全白名單範圍 | 阻斷作弊行為，回滾本地狀態 |
| **E003** | 401 | `TOKEN_EXPIRED` | Session Token 超過 24 小時有效期限 | 重新發起身分認證 |
| **E004** | 401 | `DEVICE_MISMATCH` | 該帳號已在其他裝置登入換機失效 | 彈出強制下線並退回標題畫面 |
| **E005** | 409 | `SCHEMA_TOO_OLD` | 客戶端資料庫結構版本落後伺服器 | 提示玩家前往商店進行強更 |
| **E006** | 409 | `VERSION_CONFLICT` | 存檔版本發生不可逆之衝突 | 提示版本錯誤，拒絕覆蓋 |
| **E007** | 413 | `PAYLOAD_TOO_LARGE` | 壓縮後封包體積超過 5MB 上限 | 拆分批次或清理無效日誌 |
| **E008** | 429 | `RATE_LIMITED` | 單一帳號每分鐘請求超過 10 次 | 啟動冷卻等待 60 秒再試 |
| **E011** | 409 | `BASE_HASH_MISMATCH`| 客戶端 baseHash 與伺服端存檔不一致 | **自動觸發 fallback 至 /sync/full** |
| **E021** | 403 | `SIGNATURE_TAMPERED`| 滾動雜湊鏈驗證失敗，疑似本地外掛竄改 | 鎖定帳號同步權限並上報 |

## 3. 客戶端容錯與指數退避重試狀態機

客戶端 `SyncManager` 遭遇網路波動或伺服端錯誤時，依循確定性狀態機流轉：
1. **409 衝突回退 (`E011`)**：
   - 立即中斷增量佇列，封裝完整最新本地存檔，呼叫 `POST /sync/full` 進行全量覆蓋。
2. **5xx 伺服器異常或網路中斷**：
   - 啟動指數退避重試（Exponential Backoff）：
     $$\text{RetryDelay} = 2^{attempt} \times 1000\text{ms} \quad (1\text{s} \rightarrow 2\text{s} \rightarrow 4\text{s})$$
   - 最多重試 3 次；若均失敗，將未送出之 `actionRecords` 保留於本地離線儲存庫，待下次網路恢復或使用者手動觸發時重送。

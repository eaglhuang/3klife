### 13.2 待裁決選擇題（只剩大方向；每題建議放第一個）

數值、產出、職缺、家業清單細節與道具已由企劃定案。

**Q1 家業要不要獨立經營畫面**
- A（建議）：獨立「幕府後院」畫面加大廳熱點，家業詳情用共用面板。
- B：併入太守府畫面做分頁。
- C：只在季報與年報彈窗管理，無獨立畫面。

**Q2 家業可否被敵國破壞**
- A（建議）：不可被直接破壞；只有年終守城失敗、天災、事件造成「停業 1 季」與收益損失上限 50%，無永久損失。
- B：完全不可被影響。
- C：可被攻擊、占領、掠奪（需防守玩法，工程大）。

**Q3 要不要接商業化**
- A（建議）：第一版不接，只留 `monetizationHook` 空欄位；成長膳相關物品不得用付費取得。
- B：只接「加速月卡」類（縮短家業升級等待、離線補收），不碰成長膳。
- C：另售家業外觀與建築造型。

**Q4 家業託管程度**
- A（建議）：年初下年度方針，管事自動結算，重大事件才彈選擇題。
- B：每季強制手動確認方針。
- C：完全自動，無選擇。

**Q5 義勇營是否可手動進戰場**
- A（建議）：第一版只自動結算，預留 `battleEntryRequest`／`battleResult` 接口，之後交戰場專家排程。
- B：第一版就做手動出戰。
- C：永遠只做自動結算。

**Q6 家業名望轉入家族名聲的比例**
- A（建議）：每季轉入 50%，上限 60，避免取代戰功與官職。
- B：完全不轉入，只作世家聲望階。
- C：1:1 全轉入，不設上限。

## 14. 後續實作卡拆分建議

> 只列卡名、範圍、依賴。實際卡號開卡時由主控配；六套共用框架的正式規格卡由另一位企劃寫（9200 起），**實作時缺 base 的框架排第一批，其他卡全部依賴它**。

### 14.1 第 0 批：共用框架實作卡（排第一）

| 卡名（暫） | 範圍 | 依賴 |
| --- | --- | --- |
| B1 物品庫存 base | 抽 `PlayerInventory`／`ItemDef` 成持有者容器（武將背包、家庫房、幕府公庫、家族倉庫），舊呼叫端相容 | 9200 系列物品庫存規格 |
| B2 商店 base | 抽 `ItemShopPricing`／`WishPool` 購買核心，加上架、打折、換期、庫存、限購、多貨幣 | B1 |
| B3 任務 base | 抽 `HallMissionLoop`／`DispatchJobs` 的接取、派人、結算、記錄；只管接、解、結算 | B1 |
| B4 獎勵 base | 獎池、掉落、保底、懲罰、給獎演出（寶箱、藏寶圖、骰子、轉盤）；從任務拆出 | B1、B3 |
| B5 技能 base | `SkillRuntimeContract` 擴充 domain 與 modifier，專長、perk、家風可用 | 無 |
| B6 劇情 base | 事件條目、選項、條件、歷史／培育／羈絆／任務／傳記五類劇情 | B4（效果發放） |
| 人員占用（候選 A，視 PM 裁決） | 占用登記與互斥矩陣 | 無 |

### 14.3 第一版：先做三個家業

| 卡名 | 範圍 | 依賴 |
| --- | --- | --- |
| E1 家族商店 | 上架、方針、掌櫃挑貨、風險事件 6 條 | E0、B2、B4、B6 |
| E2 家族酒店與廚房 | 酒店等級、主廚與專長、食材、一般菜與成長膳、`tonicMealServed` 接口 | E0、B1、B2、B3、**PROG-2-9198 接口欄位** |
| E3 貿易商行（簡化派遣） | 江東、荊揚、南海三條航線、季風、結算、港市 | E0、B2、B3、B4 |

選這三個的理由：商店最簡單，驗證框架；酒店是成長膳的產出端，和 9198 連成玩家看得到的價值；貿易提供 I4 海味，讓 T4 成長膳有穩定食材，三者形成閉環。若貿易延後，酒店 T4 食材改由事件與傭兵獵獲暫代。

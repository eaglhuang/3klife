# 寶物圖鑑收集度統計與解鎖檢視模型規格書

## 1. 核心定位與職責範圍

本規格書定義三國稀世珍寶的收集度圖鑑與動態檢視模型，對應 WBS **BAG-08**。
寶物圖鑑專為深度收集家目標群體（Collector Target Audience）設計，記錄玩家歷經戰役搜繳、府庫尋訪、名將贈禮與市集拍賣所接觸過之所有珍寶遺產。
本模組由純邏輯無副作用函式庫（`TreasureCodex.ts`）驅動，圖鑑本身**不額外持久化獨立狀態**，而是直接由「物品取得日誌（`ItemAcquisitionLog`）」與「當前玩家背包（`PlayerInventory`）」動態推導生成，保證資料單一真相來源。

## 2. 寶物圖鑑動態推導資料流架構

```mermaid
flowchart TD
    subgraph StateInputs [資料來源輸入]
        Log[物品取得日誌 ItemAcquisitionLog 最多200筆]
        Inv[當前背包持有物 PlayerInventory]
        Def[道具定義集中表 ITEM_DEFS]
    end
    
    subgraph ProjectionEngine [動態投影引擎 buildTreasureCodex]
        Def --> FilterTreasures[篩選 category === '寶物']
        FilterTreasures --> MapEntries[逐筆計算取得進度]
        Log --> MapEntries
        Inv --> MapEntries
        MapEntries --> CalcTotal[統計 totalAcquired 累計取得量]
        MapEntries --> CalcOwned[統計 owned 目前持有量]
        MapEntries --> JudgeObtained{totalAcquired > 0 || owned > 0}
        JudgeObtained -- 是 --> SetObtainedTrue[obtained = true 點亮圖鑑]
        JudgeObtained -- 否 --> SetObtainedFalse[obtained = false 灰態隱藏]
    end
    
    subgraph OutputView [輸出檢視模型 TreasureCodexView]
        SetObtainedTrue --> ViewResult[組裝完整檢視模型]
        SetObtainedFalse --> ViewResult
        ViewResult --> Stats[計算 obtainedCount / totalCount]
        ViewResult --> CompleteFlag[判定 complete 全收集達成]
        ViewResult --> SummaryStr[格式化 summaryLine 寶物圖鑑 X/Y]
    end
```

## 3. 圖鑑資料結構與型別契約

### 3.1 寶物單項條目契約（`TreasureCodexEntry`）
```typescript
export interface TreasureCodexEntry {
    readonly itemId: string;         // 道具唯一代碼
    readonly name: string;           // 道具繁中名號（如：方天畫戟、青囊書）
    readonly obtained: boolean;      // 是否曾解鎖並登錄圖鑑
    readonly totalAcquired: number;  // 取得日誌中累計獲得數量（不扣除消耗）
    readonly owned: number;          // 目前背包/倉庫持有的現存數量
}
```

### 3.2 圖鑑整體檢視契約（`TreasureCodexView`）
```typescript
export interface TreasureCodexView {
    readonly entries: TreasureCodexEntry[];  // 全量寶物條目清單
    readonly obtainedCount: number;         // 已解鎖寶物種類數
    readonly totalCount: number;            // 遊戲內全域寶物總種類數
    readonly complete: boolean;             // 是否達成 100% 全圖鑑收藏
    readonly summaryLine: string;           // 介面標準摘要文字（例："寶物圖鑑 12/24"）
}
```

## 4. 解鎖判定模型與邊界保護

### 4.1 雙軌解鎖保障原則
寶物解鎖判定條件為：
$$\text{obtained} = (\text{totalAcquired} > 0) \lor (\text{owned} > 0)$$
- **日誌滾動保護**：系統歷史取得日誌預設保留上限為 200 筆，若極度古老的取得紀錄已被滾動截斷，只要玩家背包或倉庫內尚持有該物品（$\text{owned} > 0$），系統依然判定為已解鎖。
- **舊檔無縫相容**：對於未啟用歷程日誌功能的既有舊存檔，載入時直接由現有持有清單點亮圖鑑，無痛升級不卡檔。

### 4.2 摘要文字格式化契約
- 統一由純函式輸出繁體中文標準字串：
  $$\text{summaryLine} = \text{"寶物圖鑑 " } + \text{obtainedCount} + \text{"/" } + \text{totalCount}$$
- 當且僅當 $\text{totalCount} > 0$ 且 $\text{obtainedCount} === \text{totalCount}$ 時，`complete` 標記置為 `true`，可觸發收藏家成就解鎖。

## 5. 畫面呈現規範與驗收條件

1. **圖鑑介面渲染規範**：
   - 已解鎖（`obtained === true`）：顯示完整彩色圖示、傳奇背景框與詳細背景列傳考證。
   - 未解鎖（`obtained === false`）：顯示剪影黑態（Silhouette）或問號圖示，隱藏具體數值加成，保留探索懸念。
2. **驗收測試對齊**：
   - 驗證空日誌與空背包下，所有寶物均為 `obtained: false`，`complete: false`。
   - 驗證手動注入取得日誌後，對應寶物自動點亮，累計取得數量正確累加且不因物品消耗而歸零。

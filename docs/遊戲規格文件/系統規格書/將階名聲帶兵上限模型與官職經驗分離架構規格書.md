# 將階名聲帶兵上限模型與官職經驗分離架構規格書

> 標記：Single Source of Truth（單一真相來源）  
> 涵蓋工作包：`OFC-11`  
> 狀態：正式發布 / 核心邏輯規格

---

## 1. 系統定位與架構

本模組規範遊戲中「武將個人軍階體系」與「主公朝廷官職體系」的架構解耦標準。過去設計中常將「武將個人帶兵上限」與「主公政治官職 EXP」混為一談，造成數值與 UI 嚴重偶合。本規格確立嚴格的雙軌分離模型：
1. **武將個人軍階（General_Rank & Fame）**：決定該名武將在沙盤與戰場上的個人部隊編制帶兵上限（`Command_Capacity`）。
2. **主公政制官職（Officer_Tier）**：代表玩家家族在東漢朝廷中的政治階位，僅解鎖全域系統權限（外交、任務牆、沙盤標記等），不直接決定個別武將的戰場部隊人數。

```mermaid

```

## 2. 帶兵上限精算公式模型（OFC-11）

武將個人的部隊編制上限由「將階基底」、「名聲加成」與「統率屬性修正」三者共同決定：

$$\text{Command\_Capacity} = \text{BaseCapacity}(\text{Rank}) + \lfloor \text{Fame} \times 2.0 \rfloor + \lfloor \text{LEA} \times 15.0 \rfloor$$

## 3. 雙軌資料結構與 UI 呈現隔離

### 3.1 核心介面定義
```typescript
export interface IGeneralMilitaryProfile {
  readonly generalId: string;
  rank: number;                  // 1 ~ 10 階
  fame: number;                  // 個人戰功名聲
  commandCapacity: number;       // 即時精算之帶兵上限
}

export function calculateCommandCapacity(rank: number, fame: number, lea: number): number {
  const baseTable: Record<number, number> = {
    1: 1000, 2: 1500, 3: 2200, 4: 3000, 5: 4000,
    6: 5200, 7: 6600, 8: 8200, 9: 10000, 10: 12500,
  };
  const base = baseTable[Math.min(10, Math.max(1, rank))] || 1000;
  return base + Math.floor(fame * 2.0) + Math.floor(lea * 15.0);
}
```

### 3.2 UI 文案與組件邊界規範
- **出征與部隊編制頁面**：展示武將個人的 `General_Rank`（如「裨將·關羽」），帶兵進度條顯示當前兵力 / `Command_Capacity`。嚴禁在此出現主公之朝廷官職（如校尉、偏將軍）經驗進度。
- **大廳政制面板**：展示主公在朝廷的政治印綬（`Officer_Tier`）與政績 EXP，顯示解鎖之政務與外交特權，嚴禁與個別武將之帶兵量混淆。

## 4. 驗收與測試標準

1. **帶兵上限精算校驗（TC-OFC-11-01）**：
   - 輸入 Rank 1、Fame 100、LEA 80，計算：$1000 + 200 + 1200 = 2400$ 兵力，檢核數值完全一致。
2. **出征取值隔離檢驗（TC-OFC-11-02）**：
   - 驗證 `SortieArmyBuilder` 僅調用 `calculateCommandCapacity`，無任何引用 `OfficerState` 之相依。
3. **將階邊界保底測試（TC-OFC-11-03）**：
   - 輸入非法 Rank 0 或 11，檢核函式自動箝制於 1 至 10 區間，不拋出未捕捉異常。

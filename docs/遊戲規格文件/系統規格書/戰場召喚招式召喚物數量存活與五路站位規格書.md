# 戰場召喚招式召喚物數量存活與五路站位規格書

> 責任邊界：本檔只定義「武將主動施放戰法／奧義而產生召喚物」的規則；Boss 半血親衛隊由 `戰場BOSS半血親衛隊召喚與護主屏障狀態機規格書.md (doc_spec_0604)` 負責，不在此重寫。
> **硬約束**：不得改動五路對撞核心規則（小兵只打同路正面、旁邊經過不打、只有武將經過才與旁邊小兵互打；`GAME_CONFIG.troopEngageAdjacent` 維持 false）。本檔凡可能動到此規則處，一律標「**需問使用者**」。
> 數值一律寫「建議範圍」，由總 PM／企劃定案，不在本草稿寫死。

## 1. 目標

讓「召喚類招式」有一份可實作的規格：召喚什麼、最多幾隊、活幾回合、放在哪一格、跟士氣／援護怎麼互動、AI 何時用、特效音效怎麼掛。召喚物的定位是「短命的額外小兵」，用來補路、卡位、分攤壓力，不是第二支主力，也不改變五路對撞的玩法。

## 2. 規則

### 2.1 召喚物種類（先做 A，B 列為後續）
| 類 | 名稱 | 內容 | 本草稿 |
|---|---|---|---|
| A | 部隊型召喚物（summon-unit） | 一隊普通小兵（占 1 格、走既有 TroopUnit），兵種固定為盾／步／弓三選一，攻防走「鄉勇民兵」折算（參考 `BattleUnitSpawner` 的 militia，攻防為基礎 40%） | 本次範圍 |
| B | 地格型召喚物（summon-tile） | 障礙、旗幟等地格物件，沿用 `TSUMMON`（戰法系統 g5 §Obstacle／Spawn），不是單位、不交戰 | 只列介面，後續另卡 |
| C | 猛獸類 | 見 `三國戰場驅使虎豹豺狼猛獸撕咬與金鐵巨響破法狀態機規格書` | 不在本草稿 |

### 2.2 數量與存活
- 單次施放：召喚 1 隊（建議範圍 1～2 隊）。
- 同陣營同時存活的召喚物上限：建議範圍 2～4 隊；到上限時，新召喚依 §7 問題 2 處理。
- 存活回合：建議範圍 3～5 回合（含召喚當回合），到期淡出、不留遺體；提早被擊殺照一般陣亡結算。
- 召喚物不吃糧草、不佔出戰名額、不計入「出兵上限」；但計入全場單位數以供效能預算（§5）。
- 同一招式一場戰鬥的冷卻／次數沿用該招式既有 SP／冷卻欄位，不另開。

### 2.3 站位（五路格子，不破壞五路對撞）
- 生成格順序：① 施放者所在路、施放者前方第一個空格 → ② 同路後方第一個空格 → ③ 空路中最靠中間者（沿用 `bossGuardLanes` 的「靠中間、同距取小路號」排序）。
- 不可生成在：有人佔據的格、阻擋地形、水攻水流格、敵方底線格（避免直接斬首）。
- 無空格：施放失敗，不扣 SP／不進冷卻（與 Boss 親衛的「無空格轉怒氣補償」不同，主動招式不給補償）。
- 生成後就是一般小兵：只與「同一路正面」的敵軍交戰，不側擊、不斜角交戰、不能跨路移動（**維持五路對撞；若企劃想讓召喚物可換路，需問使用者**）。
- 生成當回合不可行動（召喚虛弱），下一回合起走既有移動／交戰流程。

### 2.4 與士氣、援護的關係
- 士氣：召喚物不持有獨立士氣，不計入陣營平均士氣；其陣亡不觸發「友軍陣亡扣士氣」。主將施放時的士氣加成不外溢到召喚物（建議範圍：召喚物攻防不吃士氣）。
- 援護（羈絆「生死相隨」承傷分攤）、合攻聯動（`doc_spec_0323`、`doc_spec_1358`）：召喚物既不能當援護者，也不能當被援護者，也不觸發合攻（羈絆只認真實武將所屬部隊）。
- 擊殺召喚物：不給擊殺 SP（`SP_PER_KILL` 不適用）、不計戰後統計擊殺數、不產生戰利品。
- 召喚物不吃陣營 aura 以外的羈絆光環（義兄弟光環、`kinAura` 不套用）。

### 2.5 AI 何時用（對照 `doc_spec_0390`、`doc_spec_0391`）
- 打分加成條件（建議）：己方有空路 ≥ 1、己方在場部隊數 < 對手、或某路己方被對手壓到底線前 2 格。
- 不用條件：無空格（§2.3）、本場已達同時存活上限、敵方只剩主將（無對撞價值）。
- 智力分級：低智 AI 只在「己方部隊數落後」時用；高智 AI 才會「補被壓制的那一路」。分級門檻沿用 `doc_spec_0390`，本檔不另設。
- 玩家端：與其他戰法同為手動／自動施放；自動施放走 `天賦戰法自動施放設定檔與AI決策節奏規格書`。

## 3. 資料格式（建議新增，不寫死數值）

於 `BattleSkillProfile`（`assets/scripts/battle/skills/BattleSkillProfiles.ts`）新增 `effectKind: 'summon'` 與選填欄位：

```json
{
  "battleSkillId": "example-summon",
  "targetMode": "self",
  "effectKind": "summon",
  "coefficient": 0,
  "summon": {
    "kind": "unit",
    "troop": "shield",
    "count": 1,
    "durationTurns": 4,
    "spawnRule": "caster-lane-front",
    "statScale": 0.4
  },
  "battleLogKey": "skill.example_summon.cast"
}
```

- `count`、`durationTurns`、`statScale` 皆填「建議範圍」內的值，由企劃定案；`troop` 限盾／步／弓。
- `spawnRule` 目前只有 `caster-lane-front`（§2.3 順序）；新增規則需另審。
- 召喚物單位以 `TroopUnit.summonedBy`（施放者 id）與 `TroopUnit.summonExpireTurn` 兩欄記錄（新增，存檔不持久化，戰場結束即清）。

## 5. 效能預算（手機優先）
- 召喚物節點：重用單位節點池，不每次 new；全場召喚物節點 ≤ 同時存活上限 × 2 陣營（建議範圍 ≤ 8）。
- 特效：沿用 `TACTIC_VFX_BUDGET`（同時 fx ≤ 14、粒子 ≤ 140、單次施放命中格 ≤ 5、總秒數 ≤ 1.0）；召喚特效單格粒子建議 ≤ 14，峰值 fx ≤ 3。
- 入場／到期淡入淡出走 tween 一條，結束即回收，不留殘留節點。
- 圖示、飄字、音效沿用既有節流（`StatusCueThrottle` 120 ms 視窗）。

## 6. 驗收項
1. 純函式單測：生成格排序（同路前方 → 同路後方 → 靠中間空路）、無空格回傳失敗且不扣 SP、上限判定、到期回合。
2. 單測：召喚物不出現在援護／合攻候選、擊殺不給 SP、不計擊殺統計。
3. 單測：召喚物只與同路正面交戰（對照 `troopEngageAdjacent === false` 現有測試不被改動）。
4. 表完整性：每個 `effectKind: 'summon'` 的招式必有特效分組與音效 clip（併入 `GeneralSkillVfxCoverage` 類測試）。
5. 實跑 web-desktop：召喚當下出現次數 = 召喚隊數、峰值 fx／粒子／節點在預算內、到期淡出無殘留；截圖須實看。
6. tsc 0 錯、`tests/run-cli.ts` 全過、compute-gate quick。

## 7. 已裁決問題（2026-11-28，使用者／總 PM）

裁決依據：使用者／總 PM 11/28 指示——召喚物**不可換路、固定出生路**，遵守五路對撞核心規則，不得改；其餘待決題一律採本檔「建議」選項。實作卡：PROG-2-10253。

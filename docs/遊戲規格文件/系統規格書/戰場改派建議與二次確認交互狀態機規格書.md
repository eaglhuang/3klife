# 戰場改派建議與二次確認交互狀態機規格書

## 1. 核心定位與防呆契約

本規格書為戰場部隊部署受阻時的改派建議與防呆二次確認交互狀態機（Deploy Suggestion & Two-Step Confirmation，代號 `DEP-10`）的單一真相來源（Single Source of Truth）。為保障玩家戰術自由度與防止非預期糧草誤扣，系統在部隊部署失敗時主動推薦低耗備選方案，但嚴禁自動調換，必須經由狀態機完成明確的玩家二次確認。

```typescript
export interface RedirectPrompt {
  deniedType: string;             // 本次被阻絕的原始兵種
  lane: number;                   // 欲部署的目標車道
  suggestedType: string;          // 系統推薦之可用低耗兵種
}

export type RedirectAction = 'none' | 'arm' | 'confirm';
```

---

## 2. 改派候選優先序與文案契約

### 2.1 備選部隊篩選順序（`DEPLOY_SUGGESTION_CANDIDATES`）

當某高階精銳因軍勢或糧草匱乏受阻時，系統自標準候選庫中依序檢測：

$$\text{Candidates} = [\text{cavalry}, \text{infantry}, \text{shield}, \text{archer}, \text{pikeman}]$$

1. 逐一執行 `checkDeploy` 驗證。
2. 挑選首個滿足資源與名額要求之可用兵種作為 `suggestedType`。
3. 若所有候選兵種均不可用，回傳 `null`，不提供改派建議。

### 2.2 提示文案規範

當改派候選確立後，介面調用標準文案產生器：
$$\text{deploySuggestionCopy(troopName)} \to \text{「可改派低耗部隊：\{TroopName\}。」}$$
- 於畫面下方跳出微型提示氣泡（Tooltip）或 Toast，伴隨建議兵種按鈕微幅呼吸光效。

## 3. 三態防呆交互狀態機（Redirect State Machine）

狀態機核心函式為 `nextRedirectStep(prompt, attempt, suggestion)`：

$$\begin{CD}
\text{Initial (None)} @>\text{首次點選受阻目標}>> \text{Armed (裝填提示)} @>\text{同格同兵種二次點選}>> \text{Confirmed (確認改派)} \\
@. @VV\text{點選不同車道/不同兵種}V @. \\
@. \text{Re-armed (更新提示)} @.
\end{CD}$$

1. **無建議狀態（`none`）**：
   - 若 `suggestion == null`，直接回傳 `{ action: 'none', troopType: null }`。
2. **裝填提示狀態（`arm`）**：
   - 玩家初次點擊不可部署之兵牌，系統記憶該次操作快照（`deniedType`、`lane`、`suggestedType`）。
   - 回傳 `action: 'arm'`，介面僅展示改派建議文案，不扣除資源、不發起出陣。
3. **確認執行狀態（`confirm`）**：
   - 僅當玩家於**完全相同的車道（`lane`）**、點選**完全相同的受阻兵種（`deniedType`）**、且建議兵種未變更時：
   - 狀態機判定為玩家明確確認，回傳 `action: 'confirm'` 與 `troopType: suggestedType`。
   - 戰場控制器正式扣除糧草與軍勢，將建議部隊部署至該車道。
4. **目標異動重置（Re-arm）**：
   - 若玩家在 `arm` 狀態下改點其他車道或切換其他兵牌，舊快照立即作廢，重新進入新目標之 `arm` 提示狀態。

## 4. 自動化測試與驗收標準

1. **單元測試對齊**：
   - 對齊 `tests/SortieDeploySuggestion.test.ts` 與 `tests/DeployComposite.test.ts`。
   - 驗收條件 1：驗證初始狀態下點選受阻部隊，回傳狀態嚴格等於 `arm` 且 `prompt` 被完整記錄。
   - 驗收條件 2：驗證在 `arm` 狀態下第二次點選同一目標，回傳狀態精確等於 `confirm` 並攜帶建議兵種。
   - 驗收條件 3：驗證二次點選時若變更車道（如 Lane 2 改 Lane 3），狀態嚴格維持 `arm`，不得提前觸發部署。

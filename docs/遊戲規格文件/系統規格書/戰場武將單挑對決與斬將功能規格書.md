## 1. 系統目標與設計哲學

單挑（Duel）是三國演義中最具戲劇性的武勇對決，也是戰場局勢瞬間逆轉的關鍵樞紐：
1. **臨陣亮劍的高風險博弈**：拒絕單挑有恥辱性的軍心代價，接受則以命相搏。
2. **客觀綜合決策模型**：AI 與玩家依主將生命、部隊兵力與總戰力計算接受分數（`DuelScore`）。
3. **拒絕單挑嚴懲（畏戰懲罰）**：膽怯拒戰導致全軍攻防與主將 HP 減半。
4. **斬將晉升即時閉環**：單挑勝利斬將立刻提供 $+15$ 點即時功業名聲，驅動 `InBattleAscension` 觸發即時升階！

## 2. 單挑發起與接受決策模型 (NUM-01 + NUM-02)

### 2.1 接受評分公式 (Duel Score Formula)
$$\text{DuelScore} = 0.45 \times \text{HpRatio} + 0.35 \times \text{SquadRatio} + 0.20 \times \text{PowerRatio} + \text{Jitter}$$
- $\text{HpRatio} = \text{CurrentHP} / \text{MaxHP}$（主將當前生命比，權重 0.45）
- $\text{SquadRatio} = \text{SquadTroops} / \text{MaxTroops}$（分隊現存兵力比，權重 0.35）
- $\text{PowerRatio} = \text{CombatPower} / \text{EnemyPower}$（總體戰力對比，權重 0.20）
- $\text{Jitter} \in [-0.05, +0.05]$（依確定性亂數注入之隨機抖動）

### 2.2 接受閾值 (Thresholds)
- **NORMAL / HARD / HELL 難度**：$\text{Threshold} = 0.58$（分數 $\ge 0.58$ 接受，否則拒絕）。
- **EASY 難度**：$\text{Threshold} = 0.45$（防守方更容易迎戰）。

## 3. 拒絕單挑之懲罰機制 (Cowardice Penalty)

防守方若拒絕單挑，全軍士氣崩潰並受到嚴厲戰場懲罰（2026-11-17 使用者裁決：維持程式現況，整場有效、沒有回合期限）：
1. **全軍攻擊與生命減半**：防守方在場全體部隊攻擊力 $-50\%$、生命上限 $-50\%$、當前生命 $-50\%$（至少留 1），持續到本場戰鬥結束。不影響防禦力。
2. **主將受挫懲罰**：主將因軍心渙散與威名掃地，當前生命值扣減 $-50\%$（至少留 1）。
3. **戰場廣播提示**：UI 播報拒絕方「攻擊力與生命力減半」。

## 4. 單挑對決回合與勝負結算 (NUM-03)

單挑進入獨立對決演出，雙方輪流交手（普攻、格擋、暴擊、武將戰法），不限回合數（2026-11-17 使用者裁決）：
- **一般戰鬥**：任一方主將生命掉到上限 $20\%$ 以下即落荒而逃，分出勝負、戰鬥繼續；只有一擊直接把生命打到 0 才算斬將。
- **教學戰**：主將生命掉到上限 $50\%$ 即分出勝負，不會被斬；勝方照 4.1 取得獎勵，敗方不套用 4.2 的代價。

### 4.1 勝利方福祉 (Victory Spoils)
- **即時功業名聲**：獲勝主將立刻獲得 $+15$ 點斬將戰功名聲，計入 `InBattleAscension` 晉升門檻。
- **全軍士氣如虹**：勝方全軍士氣拉滿至 $100$，獲得暴擊率 $+15\%$ 加成持續 2 回合。
- **斬將神效**：若單挑中直接擊殺敵將，敵全軍陷入【潰散混亂】，直接喪失當回合行動。

### 4.2 戰敗方代價 (Defeat Penalty)
- 若我方主將被斬殺：視同被擒（PROG-2-9140，2026-11-17 裁決），改由擒獲方君主處置，見 `doc_spec_0021` §L；**只有被斬首才進入陣亡結算**，依 `doc_spec_0313` 產出對應品質之傳承虎符卡，其餘結果（投降、關押、釋放）不陣亡。戰場端尚未回報被擒紀錄時，維持舊行為（直接陣亡）。無君主關卡只當一般戰敗，不處罰。
- 若負傷落荒而逃：當前 HP 歸 1，分隊兵力崩潰 $50\%$。

- [ ] **TC-DUEL-01**：決策分數精準依 $0.45\text{HP} + 0.35\text{兵力} + 0.20\text{戰力} \pm 0.05$ 計算。
- [ ] **TC-DUEL-02**：分數 $\ge 0.58$ 接受單挑；拒絕時防守方全軍攻防減半、主將 HP 減半。

## 6. 主將出陣、逐格推進與單挑觸發規則（使用者 11/22 裁決，PROG-2-9719）

> 本章取代 `docs/demo_playbook.md (doc_spec_0161)` §12.15.1～12.15.6 的舊 Demo 描述；demo_playbook 該段僅作歷史資料。

| 編號 | 規則 | 裁決 |
|---|---|---|
| R1 | 主將平時跟著自己的格子走（逐格推進）；單挑演出時兩將移到**棋盤外側場邊**對站交鋒，演出結束各自走回出發位置（主將回到原本格子） | 使用者 11/22 Q1=B |
| R2 | 兩將**同路相鄰**才觸發單挑。敵將不上棋盤、站在敵方底線外，因此我方主將走到**敵方底線任一路**（depth＝敵方前線）即視為相鄰並觸發單挑（維持現行 `isGeneralFacingEnemyGeneral`）；不做敵將上棋盤 | 使用者 11/22 Q2=A；敵將不上場時的判定由使用者 11/22 裁決選 C |
| R3 | 敵方**小兵**攻擊範圍內有我方主將時優先打主將。只限小兵對武將的目標選擇；小兵擦身不打旁路小兵的五路對撞規則不變 | 使用者 11/22 Q3=B |
| R4 | 主將只能從己方**出兵口（depth 0）**衝出上場，不可直接放到前排或任意格；點其他格提示「主將只能從出兵口出陣」。自動代打同樣放出兵口 | 使用者 11/22 Q4=A |
| R5 | 主將出陣時己方全軍攻擊加倍（出陣期間新部署的小兵也加倍）；**主將倒下時加倍立即全部消失**，不做撤回指令。倒下後新部署的小兵不再加倍 | 使用者 11/22 Q5=A |

### 6.1 實作對照
- 出陣加倍：`assets/scripts/battle/shared/GeneralSortieBoost.ts`（`applyGeneralSortieBoost` 記錄在 `TroopUnit.generalSortieAttackBoost`，`clearGeneralSortieBoost` 於兩個 `onGeneralUnitKilled` 扣回，只扣加倍量、不動其他攻擊加成）。
- 出兵口限制：`TurnFlowManager` 點格出陣檢查 `isGeneralSortieDepth`。
- 場邊單挑：`UnitRenderer.duelSidelineArena()` 取兩軍中線往棋盤外側延伸 1.1 路、畫面上方那側；`SpineGeneralOverlay.playDuel(..., arenaCenter)`。
- 出陣衝刺與逐格走：PROG-2-9715（`UnitRenderer.boardGeneralFoot`）。

# 戰場減益狀態持續視覺表現疊放上限與效能預算規格書

<!-- doc_id: doc_spec_1361 -->

> **已裁決（2026-11-28，使用者／總 PM）；待決問題全部定案，見 §7。** 來源卡：PROG-2-10248（承 PROG-2-10240「減益上身掛點」）。
> 責任邊界：定義減益狀態「持續期間」在單位身上的視覺表現（頭頂圖示、身上循環特效、顏色濾鏡）、多狀態疊放與上限、效能預算、結束淡出。狀態的數值與結算不在此，見 `戰鬥增益減益效果堆疊與治療結算規格書 (doc_spec_0359)`。不改五路對撞等戰場核心規則；純表現層。
> 數值一律寫「建議範圍」，由總 PM 定案。

## 1. 目標

現況：減益只有「上身當下」一段（`STATUS_DEBUFF_VFX_GROUP`：weak／no-shoot → weaken、slow → ice，約 1 秒）與頭頂小圖示（`UnitStatusIcons`，最多 3 格＋「+N」）。玩家在狀態持續的 2～3 回合裡，除了小圖示外看不出誰被減益，尤其戰場縮小後小圖示約 9～30px。本檔補「持續表現」：讓被減益的單位一眼可辨，但不增加畫面雜訊與效能負擔。

## 2. 規則

### 2.1 範圍：哪些狀態有持續表現
| 狀態 | 來源 | 頭頂圖示（現有） | 身上循環特效（新） | 顏色濾鏡（新） |
|---|---|---|---|---|
| 虛弱 weak | `StatusEffect.Weak` | 弱 | 肩頭下垂的暗紫小霧（沿用 `weaken` 配色，低頻 1 顆／0.6 秒） | 整體略降飽和（建議範圍 −10%～−20%） |
| 封射 no-shoot | `StatusEffect.NoShoot` | 封 | 弓上疊一個小「禁」記號（單一精靈／Graphics 圖形） | 無 |
| 緩速 slow | `StatusEffect.Slow` | 緩 | 腳下淡青冰霜圈（靜態環＋緩慢呼吸） | 輕微偏青（建議 +5%～+10%） |
| 混亂 confuse（離間／魅惑，`control-override`／`discord`，圖示「控」） | 控制 | 控 | 頭頂一圈旋轉小星／心形（沿用 `confuse` 配色） | 輕微偏粉紫 |
| 恐懼 fear（**獨立狀態，11/28 裁決**） | `StatusEffect.Fear` | 懼 | 冷汗滴＋身側顫動短線（motif `shiver`，`weaken` 組配色） | 無 |
| 暈眩 stun／定身 rooted | 控制 | 暈／定 | 沿用第一批 stun「繞頭星星」做成循環版（建議範圍 2 顆低頻） | 無 |
| 毒 poison、燃燒 burn | DOT | 毒／燃 | 既有毒光罩、火焰，不重做 | 不重做 |

> 恐懼已於 11/28 裁決為獨立 `StatusEffect.Fear`（見 §7），不再是虛弱的視覺意象。

### 2.2 同時多狀態的疊放與上限
- 頭頂圖示：沿用 `STATUS_ICON_MAX_VISIBLE = 3` 與優先序（控制 > 毒燃 > 弱 > 緩 > 封…；減益在增益之前），超出顯示「+N」，不改。
- 身上循環特效：**每個單位同時最多 1 個**，取圖示優先序最高的減益當「主減益」播循環；其餘減益只留圖示。換主減益時舊循環 0.2 秒淡出、新循環 0.2 秒淡入。
- 顏色濾鏡：**同時只取 1 個**（同樣取主減益），不疊乘，避免色偏混濁。
- 增益與減益同時存在：減益視覺優先；增益只剩圖示（沿用 `kin-aura`「義」只在圖示列＋腳下光環的作法）。
- 全場上限：同時播放循環特效的單位數 ≤ 建議範圍 6～8；超過時只保留「我方主將、敵方主將、控制類、離畫面中央近者」，其餘退回只有圖示（不排隊、不新增節點）。

### 2.3 結束淡出
- 狀態到期或被淨化：循環特效與濾鏡 0.3 秒淡出（建議範圍 0.2～0.4），同時圖示依既有流程消失；淨化（`purify` 組）可同步播一次小光點，不另算持續特效。
- 單位陣亡：立即回收，不淡出。
- 重新上身（刷新回合）：不重播入場，只重置剩餘回合；入場段仍由既有 `STATUS_DEBUFF_VFX_GROUP` 負責。

### 2.4 參考現有「義」狀態圖示的做法
`kin-aura`（義）：圖示由 `STATUS_ICON_DEFS` 一行定義（字、極性、排序），畫在 `UnitStatusIconBar`（圓底＋字，增益金邊、減益紅紫邊）；腳下光環由 `StatusHaloPool`（全場共用、≤ 8 個、約 0.5 秒淡出）；只在狀態簽名改變時重畫，新增時「放大再回彈」約 0.2 秒。本檔沿用同樣三個原則：表驅動（一行一狀態）、節點池共用、簽名不變不重畫。

## 3. 資料格式（建議新增表，不寫死數值）

新增 `STATUS_PERSIST_VFX`（純資料，放 `TacticVfxExtraGroups.ts` 旁，與 `STATUS_DEBUFF_VFX_GROUP` 同風格；之後可整表搬 JSON）：

```json
{
  "weak":     { "motif": "droop-mist", "group": "weaken", "emitPerSec": 1.7, "tint": { "saturation": -0.15 }, "fadeOutSec": 0.3, "priority": 4 },
  "slow":     { "motif": "frost-ring", "group": "ice",    "emitPerSec": 0,   "tint": { "r": 0, "g": 5, "b": 10 }, "fadeOutSec": 0.3, "priority": 5 },
  "no-shoot": { "motif": "ban-mark",   "group": "weaken", "emitPerSec": 0,   "tint": null, "fadeOutSec": 0.3, "priority": 6 },
  "controlled": { "motif": "orbit-swirl", "group": "confuse", "emitPerSec": 2, "tint": { "r": 8, "g": 0, "b": 8 }, "fadeOutSec": 0.3, "priority": 2 }
}
```
- `priority` 直接引用 `STATUS_ICON_DEFS` 的 `order`，不另起一套排序。
- `group` 引用既有特效分組配色，不新增配色。
- 缺表的狀態＝沒有持續表現，不報錯。

## 4. 與現有系統介面
| 系統 | 介面 | 說明 |
|---|---|---|
| 狀態盤點 | `buildUnitStatusIcons`／`UnitStatusContext` | 主減益＝圖示清單中第一個減益；不重複掃狀態 |
| 圖示列 | `UnitStatusIconBar`（簽名變才重畫） | 持續表現掛在同一簽名變化事件上，不加每幀輪詢 |
| 腳下光環 | `StatusHaloPool` | 緩速冰霜圈可重用光環節點，不新增節點池 |
| 特效引擎 | `TacticVfxPlayer`（整場一個加色 Graphics 節點） | 循環特效以低頻粒子畫在同一 Graphics，不新增節點；受 `TACTIC_VFX_BUDGET` 約束 |
| 上身段 | `BattleUIBridge._onBuffApplied`、`STATUS_DEBUFF_VFX_GROUP` | 不改；持續段從上身段結束後接力，不重疊 |
| 顏色濾鏡 | 單位 Spine 容器 color（乘色） | 只改 `color` 乘值，不加 shader；單位陣亡或到期歸還原色 |
| 極性 | `StatusApplyFeedback.statusPolarityOf` | 沿用，不改 |

## 5. 效能預算（手機優先）
- 循環特效：同時單位數 ≤ 6～8；每單位粒子 ≤ 4（建議範圍 3～5）；全場循環粒子 ≤ 32，且與施放特效共用 `TACTIC_VFX_BUDGET`（總 fx ≤ 14、總粒子 ≤ 140），循環特效永遠讓位給施放特效（預算吃緊時先砍循環）。
- 節點：新增 0（全部畫在既有加色 Graphics；顏色濾鏡改既有節點 color）。
- 每幀配置：0；粒子用固定陣列重用，不 new。
- 更新頻率：循環粒子 30 Hz 以下即可；畫面外單位不更新。
- 峰值驗收門檻（建議）：6 隻單位同時帶減益時，峰值 fx ≤ 14、粒子 ≤ 140、新增節點 0。

## 6. 驗收項
1. 單測（純邏輯）：主減益選擇（優先序）、同時單位數上限與取捨、濾鏡只取 1 個、缺表狀態不報錯。
2. 單測：到期／淨化／陣亡的回收（無殘留）；刷新回合不重播入場。
3. 表完整性：`STATUS_PERSIST_VFX` 的 `group` 皆存在於 `TACTIC_VFX_EXTRA_GROUPS` 或第一批 7 組。
4. 實跑 web-desktop：依序構造單一減益、雙減益、四減益、6 單位同時減益，逐種定格截圖並量測峰值 fx／粒子／節點；到期後 0.5 秒內清乾淨；看見次數與預期一致（不能只看沒報錯）。
5. 手機縮小視圖（寬 480 等效）下，被減益單位仍可與正常單位一眼區分。
6. tsc 0 錯、run-cli 全過、compute-gate quick。

## 7. 已裁決問題（2026-11-28，使用者／總 PM）

裁決依據：使用者／總 PM 11/28 指示——**恐懼做成獨立狀態（fear）**；**同一單位身上減益最多 6 個**；其餘待決題一律採本檔「建議」選項。實作卡：PROG-2-10253。

| 問 | 裁決 | 內容 |
|---|---|---|
| 1 身上循環特效 | A（建議） | 做虛弱、封射、緩速、混亂＋控制循環版；毒／燃燒維持現狀 |
| 2 同時單位數上限 | A（建議） | 6 隻；超出只留圖示（優先我方主將、敵方主將、控制類、近畫面中央） |
| 3 恐懼是否獨立狀態 | **B（使用者裁決，推翻建議）** | 新增獨立 `StatusEffect.Fear`（圖示「懼」、減益極性），納入戰鬥狀態機；結算見下 |
| 4 顏色濾鏡 | A（建議） | 做，只改既有 Spine 骨架乘色、同時只取 1 個、幅度小 |
| 5 淨化解除演出 | A（建議） | 是，沿用 `purify` 組一次小光點（淨化清單加入 Fear） |

### 7.1 fear 狀態結算（企劃授權設計，不動五路對撞）
- 效果：被恐懼單位的攻擊傷害 ×0.8（`FEAR_ATTACK_MULTIPLIER`），與虛弱（×0.7）同走攻擊端結算；**不改移動、不改交戰對象、不改站位**，故不碰五路核心規則。虛弱與恐懼同時存在時兩者相乘。
- 來源：目前沒有招式直接上恐懼；狀態與表現先備好，之後的恐嚇／威壓類招式用 `statusEffect: StatusEffect.Fear` 即可掛上。
- 回合與刷新：與其他狀態相同（同名刷新取 max，層數規則沿用 `doc_spec_0359` §1）。
- 圖示：`STATUS_ICON_DEFS.fear`＝字「懼」、減益、排序與虛弱同級（4）；飄字「恐懼」；極性 debuff。
- 持續表現：獨立動機 `shiver`（`weaken` 組配色）——冷汗滴＋身側顫動短線，與虛弱的下垂霧氣可分辨。

### 7.2 單位減益上限 6（新增規則）
- 同一單位同時存在的減益種類最多 **6 個**（BuffSystem 的減益狀態＋毒＋燃燒＋被控制＋全體減益換算的圖示合計，圖示盤點端同樣截到 6）。
- 超過時：新減益若回合比現有最短者長就取代最短者，否則忽略；同名減益視為刷新，不占新名額。
- 與「頭頂最多顯示 3 格＋+N」「身上循環特效每單位最多 1 個」互不衝突：6 是狀態上限，3 與 1 是顯示上限。

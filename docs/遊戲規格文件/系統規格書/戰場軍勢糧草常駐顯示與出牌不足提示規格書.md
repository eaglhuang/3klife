# 戰場軍勢糧草常駐顯示與出牌不足提示規格書

> 對應任務卡：PROG-2-10105（規格）；實作卡見 §9。
> 來源：使用者 2026-11-27 回饋——戰場出牌跳「軍勢不足，這張卡派不出去」，但畫面上看不到軍勢數字、糧草從哪扣、總量多少。
> 關聯規格：doc_spec_0377（部署合法性與三態阻絕，DEP-03）、doc_spec_0378（糧草即時扣除，DEP-04）、doc_spec_0379（精銳上限）、doc_spec_0380（民兵）。衝突時，**判定邏輯以 0377 為準，本文只管「看得到」與「說得清楚」**。
> Mockup：`docs/遊戲規格文件/設計參考/ui-asks-1127/battle-resource-hud.html`（截圖同名 .png，1920×1080）。

## 1. 現況盤點（只讀程式的結論）

| 項目 | 現況 | 缺口 |
|---|---|---|
| 軍勢（`SortieState.poolCurrent / poolMax`） | 純邏輯已有；戰場畫面**完全沒有常駐顯示**（只有極速決戰內部拿來算預備兵力） | 玩家不知道還剩多少、總量多少 |
| 糧草（`food / maxFood`） | `BattleHUD` 有「🌾 糧草 x / y」，但規模小、與軍勢分開、卡片上看不出每張要多少 | 數字不顯眼；卡片未標需求 |
| 卡片費用 | `DeployComposite` 只顯示「費用：N 糧草」，**沒有兵力需求** | 兵力（`troopCost`）完全沒顯示 |
| 不足提示 | `DeployComposite / DeployPanel.getDeployFailMessage` 寫死「⚠ 軍勢不足，這張卡派不出去（本場兵力快用完了）」 | 沒講缺多少、從哪扣、怎麼補；字串寫死在元件內，沒走 i18n |
| 糧草補給 | `configureFood({perTurn: 0})`，戰中不回補，戰後結算退還 | 玩家不知道不會自己長 |
| 軍勢補給 | 撤回／陣亡的殘兵退回軍勢（`retireUnit`）；主將升階補兵（`refillSortiePool`） | 玩家不知道有這兩條路 |

## 2. 設計目標

1. **常駐**：戰鬥全程看得到「軍勢 目前/總量」「糧草 目前/總量」。
2. **卡上標需求**：每張兵牌固定兩個費用章（兵／糧），夠付＝綠框，缺＝紅框。
3. **不足時說人話**：說明缺多少、從哪扣、怎麼補；語氣輕鬆口語，不責備。
4. **不改判定**：`checkDeploy` 與阻絕原因列舉不動；本文只新增「資源快照」與「缺口計算」兩個純函式供 UI 用。

## 3. 常駐資源列（BattleResourceBar）

### 3.1 版面（1920×1080 橫式，用錨點與比例）

- 錨點：**上方置中**（`top-center`），寬度 62% 畫面寬、高 84px（直式時寬 96%、高 72px，兩項資源上下排）。
- 由左至右：`軍勢`｜`糧草`｜`計謀`（計謀沿用現有，僅併入同一條，不新增規則）。
- 每項：圓形圖示（兵／糧／謀）＋名稱＋**目前值（大字 34px）**＋`/ 總量`（小字）＋進度條＋「ⓘ」小標籤（點開見 §3.4）。
- 與現有 `BattleHUD` 的 `FoodLabel` 合併：舊「🌾 糧草 - / -」節點由本資源列取代，避免兩處重複。

### 3.2 資料來源與總量定義

| 顯示 | 目前值 | 總量 | 說明 |
|---|---|---|---|
| 軍勢 | `sortie.poolCurrent` | `sortie.poolMax` | 本場出征從城市兵源帶出的兵（`min(帶兵上限, 城市兵源, 關卡上限)`，doc_spec_0377 兵源鏈） |
| 糧草 | `sortie.food`（`battle.getFood()`） | `sortie.maxFood` | 本場軍糧，含後勤官加成 |

非名冊出征（沒有出征帳本，走舊 `GAME_CONFIG.INITIAL_FOOD` 路徑）：軍勢整項隱藏，只顯示糧草；卡片只標糧耗章。

### 3.3 狀態色

| 條件 | 數字色 | 進度條 |
|---|---|---|
| 剩餘 ≥ 25% 總量 | 金（`--gold`） | 金色漸層 |
| 剩餘 < 25% | 紅 | 紅色漸層，數字更新時做 0.2 秒縮放跳動 |
| 剩餘 = 0 | 紅＋「用完了」小標 | 空條 |

數值變動時數字做「滾動到新值」0.25 秒（沿用既有 tween 規範，不新增節點，重用 Label）。

### 3.4 ⓘ 說明（點開一個小氣泡，3 秒或點空白處關閉）

- 軍勢：`battle.resource.troops.tip` ＝「軍勢是這場帶出來的兵。派一隊就扣一隊，撤回或戰死的殘兵會回來。」
- 糧草：`battle.resource.food.tip` ＝「糧草是這場帶出來的軍糧。派兵要吃糧，戰場上不會自己長，打完剩的會退還。」

### 3.5 選卡預覽

玩家按住或選中一張兵牌時，兩條進度條上各出現一根白色細豎線，標出「派出後會剩多少」（錨點在進度條內，比例換算，不另佔版面）。放開或取消選取即消失。

## 4. 卡片費用章（DeployCardCost）

- 每張兵牌下緣固定兩個費用章：**兵 N**、**糧 N**（虎符卡同款，數值取 `getDeployCost` 含虎符 8 折後的實際值）。
- 夠付：綠框綠字；不夠付：紅框紅字。
- 任一項不夠：整張卡灰化（飽和度 35%），卡面中央出現紅色缺額帶，例如「缺 100 兵」「缺 800 兵／缺 6 糧」，左上角加紅色「!」徽章。
- 若同時 `FIELD_UNIT_LIMIT`：缺額帶改顯示「場上已滿」（i18n：`battle.deploy.short.field`），優先於資源不足。
- 取代舊 `costLabel`「費用：N 糧草」。

## 5. 不足提示（兩層）

### 5.1 第一層：Toast（點了灰卡立即出現，停留 2.5 秒）

單行，直接講缺多少。模板與 i18n 鍵（`zh-TW`；另三語系由 `ui-i18n-localize` 補）：

| 阻絕原因（doc_spec_0377） | i18n 鍵 | zh-TW 文案 |
|---|---|---|
| `TROOPS_SHORT` | `battle.deploy.toast.troops` | 兵不夠了：{unit}要 {need} 兵，你只剩 {have}，差 {gap}。點卡看怎麼補。 |
| `FOOD_SHORT` | `battle.deploy.toast.food` | 糧不夠了：{unit}要 {need} 糧，你只剩 {have}，差 {gap}。 |
| 兩者皆缺 | `battle.deploy.toast.both` | 兵和糧都不夠：還差 {gapTroops} 兵、{gapFood} 糧。 |
| `FIELD_UNIT_LIMIT` | `battle.deploy.toast.field` | 場上擠滿了，先撤回或等一隊退場。 |

`food` 為 0 時沿用 `SortieDeployScripts.FOOD_EMPTY_LINE` 的口吻（糧倉見底），不重複寫新字串；其文案併入 i18n 時鍵為 `battle.deploy.toast.foodEmpty`。

### 5.2 第二層：說明面板（點灰卡或 Toast 展開）

- 錨點：**卡牌列正上方置中**，寬 800px 基準、以畫面寬比例換算（直式時改貼底部、滿版寬）。
- 內容固定四塊：
  1. 標題＋一句話（`battle.deploy.sheet.title.troops` 等，見下）。
  2. **需要／現有／缺口** 表格，兵、糧各一列；夠的列顯示綠色「夠」。
  3. 「從哪扣」一句話：`battle.deploy.sheet.source` ＝「派出時，兵從『軍勢』扣、糧從『糧草』扣；部隊撤回或戰死，剩餘的兵會回到軍勢。」
  4. 「怎麼補」清單（只列當下真能做的項目，見 §5.3）與三顆按鈕：`改派`（沿用 doc_spec_0377 §3 二次確認，不自動代換）、`撤回場上殘兵`、`知道了`。
- 標題鍵：`battle.deploy.sheet.title.troops` ＝「兵不夠了，這張卡暫時派不出去」；`...title.food` ＝「糧不夠了，這張卡暫時派不出去」；`...title.both` ＝「兵和糧都吃緊，這張卡暫時派不出去」。

### 5.3 「怎麼補」清單的出現條件

| 項目 | 出現條件 | i18n 鍵 |
|---|---|---|
| 撤回場上殘兵：剩的兵立刻回到軍勢 | 缺兵，且場上有可撤回的我方部隊 | `battle.deploy.how.retreat` |
| 改派便宜的兵種（顯示建議兵種與其兵／糧耗） | `deploySuggestion` 有可通過 `checkDeploy` 的候選 | `battle.deploy.how.redirect` |
| 等主將升階：會補兵 | 缺兵，且主將尚未到最高階 | `battle.deploy.how.promote` |
| 糧草戰場上不會自己長，打完才退還 | 缺糧 | `battle.deploy.how.foodFixed` |
| 資源都補不了 | 以上皆無 | `battle.deploy.how.none` ＝「這場的兵糧差不多見底了，試試極速決戰或收兵。」 |

## 6. 純函式與資料契約（供實作卡落地）

新增於 `assets/scripts/core/systems/SortieDeployScripts.ts`（或同層新檔，純邏輯、不依賴 cc）：

```typescript
export interface DeployShortfall {
  troops: { need: number; have: number; gap: number };   // gap = max(0, need - have)
  food:   { need: number; have: number; gap: number };
  fieldFull: boolean;
}
export function describeDeployShortfall(state: SortieState, request: DeployRequest): DeployShortfall;
export interface ResourceSnapshot { troops?: { cur: number; max: number }; food: { cur: number; max: number } }
export function resourceSnapshot(state: SortieState | null, fallbackFood: { cur: number; max: number }): ResourceSnapshot;
```

- `describeDeployShortfall` 內部呼叫既有 `getDeployCost`＋`discountedDeployCost`，**不得複製成本公式**。
- 文案組裝（填入 `{unit}{need}{have}{gap}`）放在 UI 層，取 i18n 鍵；禁止在元件內寫死中文。

## 7. 安全與效能

- 手機記憶體：常駐列重用節點，不新增圖集；圖示用既有 CHAR 圖集以外的小圖示或文字圓章。
- 排布走錨點／比例／區域資料檔（ui-spec layout JSON），不寫死橫式座標。
- 文字走 i18n 四語系（zh-TW 為基準），圖示與配色走主題可換。

## 8. 驗收標準

1. 進入名冊出征戰場，頂部常駐顯示「軍勢 目前/總量」「糧草 目前/總量」，派兵後數字與進度條即時更新。
2. 選中兵牌時進度條出現「派出後剩餘」白線；取消選取即消失。
3. 每張兵牌有兵／糧費用章，夠付綠、缺紅；缺額帶數字與 `describeDeployShortfall` 一致（單元測試對 `TROOPS_SHORT`、`FOOD_SHORT`、兩者皆缺、`FIELD_UNIT_LIMIT` 各一案）。
4. 軍勢剩 400、派 500 兵的騎兵：Toast 顯示「差 100」；說明面板表格兵列「需要 500／現有 400／缺口 差 100」。
5. 說明面板的「怎麼補」只列當下真能做的項目；改派仍須二次確認（doc_spec_0377 §3.2）。
6. 程式內不再有「軍勢不足，這張卡派不出去」寫死字串；四語系 JSON 皆有 §5 所列鍵。
7. 玩家視角驗收：實點截圖附在 PR（畫面類功能需看得到的證據）。

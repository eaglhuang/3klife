# 戰場部隊部署合法性檢核與三態阻絕提示規格書

## 1. 核心定位與檢核契約

本規格書為戰場部隊出陣部署合法性檢定系統（Battle Sortie Deploy Verification，代號 `DEP-03`）的單一真相來源（Single Source of Truth）。在戰役進行中，玩家點選兵牌或拖曳部隊入場時，系統透過純邏輯函式 `checkDeploy` 評估當前資源與編制狀態，並針對不可出陣情境回報分立的三態阻絕原因（Block Reasons）。

```typescript
export type SortieDeployBlockReason =
  | 'FIELD_UNIT_LIMIT'  // 場上部隊或精銳槽位已滿
  | 'TROOPS_SHORT'      // 出征軍勢池剩餘兵力不足
  | 'FOOD_SHORT';       // 當前糧草儲備不足

export interface SortieDeployCheck {
  ok: boolean;
  reasons: SortieDeployBlockReason[];
  cost: { troopCost: number; foodCost: number; isElite: boolean };
}
```

---

## 2. 三態阻絕原因判斷模型與分立提示

為提供玩家精確操作反饋，嚴禁回傳模糊籠統之「不可部署」，必須精準區分三大阻絕條件：

### 2.1 兵力不足阻絕（`TROOPS_SHORT`）

- **判定條件**：$\text{poolCurrent} < \text{cost.troopCost}$。
- **機制意義**：本次戰役投入之總軍勢池（$\text{SortieTroopPool}$）剩餘兵力不足以支撐該部隊编制（普通兵需 500，精銳需 1,200~1,500，民兵需 300）。
- **UI 提示文案**：「出征軍勢不足，無法調派該部隊出陣。」卡牌外框灰化，兵力數值以紅色警示跳動。

### 2.2 糧草匱乏阻絕（`FOOD_SHORT`）

- **判定條件**：$\text{food} < \text{cost.foodCost}$。
- **機制意義**：當前戰役可用軍糧存量不足以支付該部隊出陣之口糧補給。
- **UI 提示文案**：「軍糧短缺，無法供應部隊出陣行軍。」卡牌標註糧草缺額 Toast。

### 2.3 編制槽位超限阻絕（`FIELD_UNIT_LIMIT`）

- **判定條件**：
  1. 場上存活部隊總數達關卡上限（$\text{activeUnits} \ge \text{fieldUnitLimit}$）。
  2. 若欲派遣部隊為精銳（`isElite == true`），且當前場上存活精銳數已達上限（$\text{elites} \ge \text{eliteCap}$）。
- **UI 提示文案**：「精銳名額已達上限（或場支部隊已滿）。」卡牌標註【名額已滿】標籤。

## 3. 改派建議與二次確認機制（Deploy Suggestion）

當高消耗精銳或特種兵因資源不足被阻絕時，系統啟動友善改派導引：

### 3.1 推薦候選排序（Deploy Candidates）

- 依序檢索低耗常規兵種：`['cavalry', 'infantry', 'shield', 'archer', 'pikeman']`。
- 尋找首個可通過 `checkDeploy` 檢核之可用部隊作為推薦對象（`suggestedType`）。

### 3.2 嚴格二次確認協議（Two-Step Confirmation）

為保障玩家戰術主導權，**嚴格禁止系統自動代換派遣兵種**：

$$\text{State Transition}: \text{None} \xrightarrow{\text{第一次點擊被阻絕}} \text{Arm (提示改派)} \xrightarrow{\text{同格同兵種二次點擊}} \text{Confirm (確認改派)}$$

- 首次點擊被阻絕兵種時：介面彈出 Toast「可改派低耗部隊：{TroopName}」，狀態進入 `arm`。
- 玩家於同一車道格再次點擊確認時：狀態轉為 `confirm`，方正式執行該推薦低耗部隊之出陣。

   - 驗收條件 2：驗證軍勢池剩餘 400 時嘗試派遣 500 步兵，精確回傳 `TROOPS_SHORT`。
   - 驗收條件 3：驗證改派建議經第一次點擊僅進入提示，必須同格第二次點擊方完成部署。

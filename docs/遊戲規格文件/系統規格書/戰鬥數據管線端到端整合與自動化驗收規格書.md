# 戰鬥數據管線端到端整合與自動化驗收規格書

> **文件狀態**：單一真相來源（Single Source of Truth）  
> **系統代碼**：`GDP-10`、`SYS-GDP-PIPELINE`  
> **核心職責**：確立戰鬥數據管線（GDP: Game Data Pipeline）之標準三階執行模型（Ingest → Merge → Validate）、端到端確定性 Fixture 測試協定，以及與計算型閘門（compute-gate）之自動化整合標準。

---

## 1. 管線三階段架構模型

```
[原始來源/配置] (Ingest) ──> [去重與合併推導] (Merge) ──> [一致性與外鍵校驗] (Validate) ──> [發行至 master]
```

1. **資料攝取階段（Ingest）**：
   - 負責從試算表、外部 Wiki 或原始 JSON 清單萃取基礎數據，進行欄位標準化與型別抹平。
2. **資料合併階段（Merge）**：
   - 將新進資料與既有存檔覆蓋層（Save Overlay）或全域字典依 `Template_ID` 進行無損合併，並自動計算相依衍生欄位（如 EP、適性綜合評級）。
3. **資料驗證階段（Validate）**：
   - 執行確定性計算型感測器，阻斷孤立參照、未定義兵種與數值越界。

---

## 2. 確定性 Fixture 與測試協定

為杜絕本機環境差異與外部網路干擾，CI 端到端測試嚴格規範使用固定受控之 Mock Fixtures：
- **路徑**：`tests/fixtures/gdp-e2e-fixture.json`
- **測試驗證項**：
  1. `test_ingest_malformed_handling`：異常資料被安全捕捉並記錄警告。
  2. `test_merge_idempotency`：相同資料連續執行兩次 Merge，產出之 JSON Hash 完全相同。
  3. `test_foreign_key_integrity`：武將 `specialTroopCampId` 必須合法存在於 34 營清單中。

## 3. 計算型閘門（Compute-Gate）整合規範

```typescript
export interface GdpValidationSummary {
  passed: boolean;
  totalRecordsChecked: number;
  invalidForeignKeys: number;
  outOfBoundStats: number;
  missingRequiredFields: number;
  durationMs: number;
}

export function runGdpVerification(): GdpValidationSummary {
  const startTime = Date.now();
  // 1. 執行 ingest 驗證
  // 2. 執行 merge 冪等檢查
  // 3. 執行 validate 外鍵掃描
  return {
    passed: true,
    totalRecordsChecked: 235,
    invalidForeignKeys: 0,
    outOfBoundStats: 0,
    missingRequiredFields: 0,
    durationMs: Date.now() - startTime
  };
}
```

## 4. 驗收標準與 CI 閘門（Acceptance Criteria）

1. **端到端無縫通關**：
   - `npm run gdp:test` 或 `node tools_node/run-gdp-pipeline.js --verify` 執行全程不得拋出未捕捉例外。
2. **CI 自動阻斷機制**：
   - 任何 PR 若引入孤立之 `Tactic_ID` 或未登錄兵種，CI 在 `quick` profile 階段立即亮紅燈阻斷合併。
3. **執行時限保護**：
   - 端到端驗證在無網路環境下執行時長嚴格限制於 3000ms 內完成。

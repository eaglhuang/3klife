# 教官精力欄位統一與教學邊界防護規格書

> **責任邊界**：本檔為武將精力欄位全域命名契約、教官教學邊界防護（MentorBoundary）與血脈隔離的單一真相來源。
> **關聯 WBS**：REV-03（教官系統 VIT_Max→Vitality_Max 統一，P0）、MENT-11（血統與教學邊界檢查）、GEN-05（精力系統）。
> **整併裁決**：徹底廢止歷史 `VIT_Max` / `VitMax` 等混淆縮寫；確立 Role_Boundary=TeachingOnly 之血脈防污染防火牆。

---

## §1. 精力欄位全域命名規範 (P0 契約)

為杜絕早期規格與代碼中簡寫分叉引發的序列化異常，全專案確立單一命名標準：

| 範疇 | 唯一合法命名 (Canonical Name) | 廢止之歷史別名 (Forbidden Aliases) | 說明與約束 |
|:---|:---:|:---:|:---|
| **規格書與 Schema** | `Vitality_Max` | `VIT_Max`, `VitMax`, `MAX_VIT` | 資料庫、存檔 JSON 欄位嚴格對齊此格式 |
| **當前精力值** | `Vitality` | `VIT`, `vit`, `VitCurrent` | 範圍 0 ~ `Vitality_Max` |
| **TypeScript 代碼屬性** | `vitalityMax` / `vitality` | `vitMax`, `vit` | 模型接口嚴格使用駝峰式正式名稱 |
| **精力回復率** | `Vitality_Recovery_Rate` | `VIT_Recov`, `VitRegen` | 每季自然回復點數基值 |

> **驗證原則**：所有 Schema 驗證器若在任何輸入 JSON 中偵測到廢止別名，必須強制拒絕並要求執行 Data Migration。

---

## §2. 教官邊界防火牆協議 (Role_Boundary)

武將無論是由抽卡獲取之「支援卡教官」或歷史名將榮退之「先祖教官」，其身份均掛載防火牆標記：

```typescript
export const MENTOR_ROLE_BOUNDARY = 'TeachingOnly' as const;
```

當 `Role_Boundary === 'TeachingOnly'` 時，驗證器與存檔服務實施嚴格血統黑名單保護，**嚴禁回寫以下 7 大核心欄位**：

1. `Father_UID` / `Father_ID`：禁止建立父系血緣關聯。
2. `Mother_UID` / `Mother_ID`：禁止建立母系血緣關聯。
3. `Genes`：教官自身基因不得因教學傳授而被篡改。
4. `Bloodline_ID`：禁止將弟子之家族譜牒掛載於教官名下。
5. `Conception_Rate`：禁止回寫受孕率與生育指標。
6. `Ancestors_JSON`：禁止將教學弟子注入祖先 14 人矩陣。
7. `Prowess_Stats`：教官自身實績不隨弟子培育而膨脹。

## §3. 培育學府單向資料流契約

教官在潁川書院等學府參與培育時，其資料流嚴格為**單向輸出（One-Way Output）**：

```
[教官支援卡 / 先祖教官] 
      │ 
      ├──(輸出加成)──> [天時/地利/人和 策論抽牌權重]
      ├──(輸出加成)──> [單項五維訓練成長增幅 +% ]
      └──(觸發事件)──> [七日頓悟 & 專屬戰法傳授]
                              │
                              ▼
                      [學員武將實績成長] (結業固化)
```

- **無狀態回饋 (Stateless Mentoring)**：36 回合修業結束後，教官卡保持初始數值完好如初，不消耗壽命、不扣除永久精力。
- **邊界斷言 (Fail-Closed Guard)**：在 `NurtureService` 與 `MentorBoundaryGuard` 執行期，若偵測到任何反向寫入行為，立即終斷事務並拋出 `SecurityBoundaryViolationError`。

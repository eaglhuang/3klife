# 新手第一年樂趣四功能規格書

> **規格代碼**：`FUN-01`～`FUN-04`　**任務卡**：PROG-2-10172　**裁決來源**：使用者 2026-11-27 本人裁決（四項皆選 A）
> **狀態**：正式定案（只有規格，尚未實作）　**依賴**：共用框架總綱（`doc_spec_1182`）、劇情演出系統Base框架（`doc_spec_1188`）、獎勵系統Base框架（`doc_spec_1186`，含第 14 章獲得面板與 14.7 台詞性別參數）、彈窗武將頭像與台詞規格書（`doc_spec_1343`，SpeakerVoice）、武將介紹古文白話吐槽規格書（`doc_spec_1344`）、首子誕生與少年名將開場流程規格書（`doc_spec_1233`）、子嗣滿5歲自動開獎規格書

## 0. 結論

新手第一年缺的是「家裡有人氣」的回饋。四件小事，全部走共用框架，不另造系統：

| 代碼 | 名稱 | 觸發 | 形式 | 時長 |
|---|---|---|---|---|
| FUN-01 | 幼兒親子互動 | 家譜頁點未滿 5 歲孩子頭像 | 一句童言童語或小動作，每季換 | 3～4 秒 |
| FUN-02 | 滿月酒小劇場 | 第一個孩子出生滿月 | 數位武將來道賀、送賀禮、各吐槽一句 | 約 15 秒 |
| FUN-03 | 勝仗搭話 | 每次勝仗回大廳 | 一位參戰武將走來說戰後感想 | 4～6 秒 |
| FUN-04 | 首次招募自我介紹小劇場 | 第一次招到某武將 | 古代口吻報名號，接一句現代白話吐槽 | 6～8 秒 |

共同調性（遊戲定調）：現代口語講典故、輕鬆搞笑、可引時事、不悲劇、不酸辱。

## 1. 共用規則（四項都適用）

### 1.1 台詞走共用台詞系統

1. 台詞一律是 i18n 鍵，四語系（zh-TW、zh-CN、en、ja）齊備，格式 `fun.<code>.<情境>.<編號>`。zh-TW 先寫，其餘語系缺鍵時退 en，再退 zh-TW 並記 warning，不得顯示鍵名。
2. 自稱、稱謂用佔位符：`{self}` 自稱、`{honor}` 對玩家稱謂、`{sir}` 他稱、`{child}` 孩子小名、`{general}` 武將名。由 SpeakerVoice 依說話者 `gender`、性格、年齡代入（沿用 `doc_spec_1343` 第 4 節與獎勵框架 14.7）。
3. **硬規則**：女角不得出現「某」「在下」「俺」「咱家」；孩子（未滿 5 歲）自稱走童語表（`{self}`＝寶寶／我／小名）。單元測試掃全部 `fun.*` 鍵並以女角、童角代入，違者失敗。
4. 台詞挑選優先序沿用 14.7：事件自帶台詞 > 武將個人台詞系統（共用快取，**本規格不新增 AI 生成呼叫**）> 本規格樣板池。查不到回空，不畫對話框，不用萬用句硬補。
5. 樣板池每句有 `tags`（性格 Brave／Wise／Loyal／Playful、性別、年齡段）；挑句時先按標籤過濾，再按下面各項的「不重複規則」抽。抽籤用存檔種子，同一場景重進結果相同。

### 1.2 古今口吻切換與鎖定（ToneLock）

武將台詞有兩種口吻：`ancient`（古代，如「在下關某」「吾乃」「某願效犬馬之勞」）與 `modern`（現代口語，如「欸這也太誇張了吧」）。

- **一開口古代口吻就維持到換場景或換 UI 視窗**：
  1. 每個說話者在每個「口吻範圍」（`toneScope`）內有一個 `ToneLock`，值為 `unset／ancient／modern`。
  2. 範圍以 `sceneId + windowId` 為鍵。同一範圍內，說話者第一句台詞決定鎖定值；之後該說話者所有句子只能挑同口吻的樣板，不得穿插另一種口吻。
  3. 換場景（`sceneId` 變）或換／關閉 UI 視窗（`windowId` 變）時，鎖定全部清空，下一句重新決定。
  4. 鎖定存在記憶體（單一 `Map<string, ToneLock>`），不進存檔。
  5. 樣板池缺該口吻的句子時，退到有的那一種並寫 warning，不得中斷。
- **唯一例外：宣告的雙口吻單元**（`toneUnit: "dual"`，只有 FUN-04 使用）。同一個單元內固定「古代句 → 現代句」兩句，這是刻意的古今對比，不算違規。單元結束後該範圍鎖定為 `modern`（吐槽那句是最後一句），不再回到古代。
- 各項預設口吻：FUN-01 孩子童語（不適用鎖定）；FUN-02 武將賀詞預設 `ancient` 開場、吐槽句屬 `modern`，採雙口吻單元（每位武將一對）；FUN-03 預設 `modern`，玩家「武將風格」設定為古風時才抽 `ancient`；FUN-04 固定雙口吻單元。

### 1.3 獎勵走共用獎勵框架

- 不新增獎勵類型。每項只宣告 `reward-bundle`（固定獎）或 `reward-pool`，由 `IRewardService.fixed()／roll()` 產生 `GrantPlan`，`settle()` 先入帳，之後才演出（先結算、後演出，閃退重進帳目不變）。
- 防重複與上限：以 `grantKey` 去重（格式見各項），同一 `grantKey` 只入帳一次；演出被跳過不影響入帳。
- 有可展示的獲得物（賀禮、新武將）時，用獲得面板 `RewardPresenter`，台詞放 `AcquireGrant.line`。沒有實質物品的小回饋（親子好感 +1）用飄字，不彈面板。

### 1.4 演出走劇情演出框架

- FUN-02、FUN-04 是 `story-def.v1` 劇本（`kind: "event"`），指令用既有 `portrait／say／bgm／sfx／wait／effects`；不新增指令。FUN-01、FUN-03 是輕量「氣泡（bark）」，不進劇本，但共用同一個 `skippable`／已看旗標與 `ToneLock`。
- 全部可跳過（點任意處跳到結尾，獎勵照常入帳）。已看旗標沿用 3.5：`story.seen.<storyId>`。
- 劇情播放中不觸發其他氣泡；優先序：FUN-02／FUN-04（劇本）> 季報／彈窗 > FUN-03 > FUN-01。同時排隊時只播最高者，其餘延到下次回大廳。

### 1.5 UI 與記憶體

1. **座標一律錨點加相對比例**：氣泡、頭像、賀客站位用「父節點尺寸比例（0～1 中心點，大小佔父節點高度比例）」＋錨點名（`anchor: "bottom-left"` 等），父節點尺寸變動時重排，不寫死像素與橫式假設，保留日後改直式／手機橫式的彈性。
2. 版面位置與尺寸放 `assets/resources/ui-spec/` 的 layout／content 契約 JSON，不寫在 TS。
3. **手機記憶體優先**：
   - 氣泡只有一個節點（`FunBarkBubble`），由四項共用，依 slot 重用，再觸發只換頭像與文字，不 new 新節點。
   - 滿月酒的賀客節點池固定 5 個，依序重用；播完回收，不銷毀。
   - 頭像只用既有貼圖（`sprites/generals/avatars/{id}_avatar`，退階順序同 `doc_spec_1343` 第 3 節），**不新增圖集、不佔 CHAR 圖集**。
   - 賀禮圖示取既有物品圖示；不為本功能新增圖片資產。
   - 不用逐幀動畫；「走過來」「小動作」用節點位移／縮放補間，補間物件池化。
4. 文字走 skin 色票與字級，不寫死色碼；長度以 en／ja 為最壞情況設計（氣泡最多兩行，超出 CLAMP）。

### 1.6 伺服器與存檔（單機也走 API）

重要資料走共通伺服器 API（單機版走本機 adapter）：

- 存檔新增 `funState`（見各項資料結構），隨存檔快照同步。
- 親子好感、賀禮入帳走獎勵框架 `reward.settle`／`reward.ack`，不另開端點。
- 氣泡與劇本播放紀錄（`seen`）為客端本機狀態，只有 `grantKey` 去重表需上伺服器。

## 2. FUN-01 幼兒親子互動

### 2.1 規則

1. 對象：玩家家族中**未滿 5 歲**的孩子（含 0 歲神祕期的嬰兒，見子嗣生成規格）。滿 5 歲進入開獎流程後不再觸發本功能。
2. 觸發：在家譜頁（家族子嗣與血統頁）點孩子頭像。每次點擊顯示一則氣泡（童言童語），或一個小動作（頭像彈跳、轉圈、吐泡泡、揮手）加一個短音效。
3. **每季換**：以「遊戲季度編號」為鍵挑句。同一孩子同一季內，無論點幾次，**句子固定不換**（可重複點，只是重播同一句與動作）；下一季才換新句。連續兩季不得抽到相同樣板（記錄 `lastTemplateId`）。
4. 年齡分段：0～1 歲（咿呀／嬰語，句子極短，動作為主）、2～3 歲（疊字童語）、4 歲（會說完整一句、會學大人）。樣板按 `ageBand` 過濾。
5. 性別參數：孩子 `gender` 決定自稱與口氣（男孩：我／寶寶，女孩：我／寶寶／人家）。提到父母時用 `{honor}`，由玩家身分代入（爸爸／娘親等）。孩子的語氣不適用 ToneLock（童語不分古今）。
6. 嬰兒（0 歲）只有動作與擬聲詞，沒有完整句子；氣泡文字為擬聲（「咿呀～」）。

### 2.2 獎勵

- 每孩子每季**第一次**點擊給 `BUNDLE_TODDLER_BOND`：親子好感 +1（`kind: "affinity"`，沿用友誼框架參數，不新增貨幣）。以 `grantKey = fun01.{childId}.{seasonNo}` 去重，一季最多 +1；孩子好感有上限（沿用子嗣好感上限），超過不入帳、仍播放。
- 用飄字「親子好感 +1」，不彈獲得面板。

### 2.3 UI

- 氣泡錨在被點頭像的上方（`anchor: "top"`，偏移為頭像高度比例 0.1），不遮住頭像本身；頭像在家譜頁左右兩側時，氣泡朝畫面內側偏移，避免出界。
- 小動作用頭像節點的補間，播完還原；不另開節點。
- 氣泡 3.5 秒自動消失，再點一次提前收起。

## 3. FUN-02 滿月酒小劇場

### 3.1 規則

1. 觸發：玩家家族**第一個孩子**出生後的**滿月**（孩子出生後 1 個月；遊戲以季為最小單位時，取下一個季初），玩家回大廳時自動播放一次。事件是首子專屬，後續孩子不觸發（`story.seen.STORY_FUN02_MOON_PARTY` 為真則不再播）。
2. 與出生禮分工：首子出生禮（`doc_spec_1233` 第 6 章）是玩家三選一的家人賀禮，不動；本劇場是「武將來道賀」的熱鬧場面，兩者獎勵互不覆蓋。
3. 賓客：從玩家陣營已招募武將中挑 **3～5 位**（不足 3 位時全上場；0 位時改由「家人」補位，不得空場）。挑選優先：與玩家友誼高者 > 與主角有血緣或結義者 > 隨機；同一武將不重複。
4. 每位賓客按序登場：進場→（古代口吻）賀詞一句→送賀禮→（現代口吻）吐槽一句。這是一個**雙口吻單元**（見 1.2），每位賓客自己的單元內古今切換合法；單元結束後該賓客鎖定 `modern`。
5. 總長約 15 秒：開場 1.5 秒＋每位賓客約 2.5～3 秒＋收尾 1.5 秒；3 位約 11 秒、5 位約 15 秒。可跳過。
6. 性別參數：賓客用 `{self}` 自稱（女將妾身／本姑娘等）；孩子小名 `{child}`、孩子性別影響稱呼（令郎／千金，現代句用「小朋友／小寶」）。
7. 調性：吐槽針對「玩家太晚才結婚」「武將不會抱嬰兒」「賀禮實用度」這類輕鬆梗，不吐槽孩子外貌，不拿夭折、悲劇開玩笑。

### 3.2 獎勵

- 每位賓客一份賀禮，由 `BUNDLE_MOONPARTY_GIFT_{賓客風格}` 抽取（`reward-pool`，風格＝武勇／智謀／義氣／玩樂，對應性格標籤）：以銀兩（家族）、育兒類道具（奶粉等價道具、長命鎖、小兵器）為主，金額與稀有度都偏小（新手友善，不超過首年任務單件獎勵的量級；數值由企劃放 JSON，本規格不寫死）。
- 賀禮是「孩子的見面禮」：孩子身上記錄 `gifts[]`（誰送的、什麼），之後在家譜頁孩子詳情可看。
- 去重：`grantKey = fun02.{childId}.{guestId}`，每位賓客只入帳一次。結算後最後以獲得面板（`RewardPresenter`）彙整「本次共獲得」，每件的 `line` 帶賓客賀詞，`source.label` 指 `fun.fun02.source`。
- 玩家不可拒收、不扣任何資源。

### 3.3 劇本（`story-def.v1`）草案

```json
{
  "schema": "story-def.v1",
  "id": "STORY_FUN02_MOON_PARTY",
  "kind": "event",
  "trigger": { "event": "child.fullMonth", "when": { "all": [{ "firstChild": true }, { "flagNot": "story.seen.STORY_FUN02_MOON_PARTY" }, { "sceneIs": "lobby" }] } },
  "priority": 70,
  "interrupt": false,
  "skippable": true,
  "start": "open",
  "nodes": {
    "open": { "type": "scene", "cues": [
        { "cue": "bgm", "id": "bgm_home_festive" },
        { "cue": "portrait", "who": "child", "pose": "sleep", "enter": "center" },
        { "cue": "say", "who": "narrator", "textKey": "fun.fun02.open" } ], "next": "guests" },
    "guests": { "type": "loop", "over": "guestPicks", "max": 5, "body": [
        { "cue": "portrait", "who": "$guest", "enter": "left" },
        { "cue": "say", "who": "$guest", "textKey": "$guest.toast", "tone": "ancient" },
        { "cue": "sfx", "id": "sfx_gift_drop" },
        { "cue": "say", "who": "$guest", "textKey": "$guest.quip", "tone": "modern" },
        { "cue": "wait", "sec": 0.4 } ], "toneUnit": "dual", "next": "grant" },
    "grant": { "type": "effects", "effects": [ { "kind": "reward", "ref": "BUNDLE_MOONPARTY_GIFT" }, { "kind": "flag", "set": "story.seen.STORY_FUN02_MOON_PARTY" } ], "next": "end" },
    "end": { "type": "end" }
  }
}
```

- `type: "loop"` 若劇情框架尚未支援，視為對共用框架的**小擴充需求**（記為待決題 Q-FUN-1），不得在本功能內自造播放器。
- 賓客站位：以相對比例排成一排（x 依賓客數均分 0.2～0.8，y 約 0.55，錨 `bottom-center`），中央放嬰兒搖籃圖示；賓客節點池 5 個，重用。
- 賓客資料 `guestPicks` 由事件時刻算出並寫入 `funState.moonParty`（存檔），播到一半閃退重進，從頭重播但不重複入帳。

## 4. FUN-03 勝仗搭話

### 4.1 規則

1. 觸發：玩家**每次勝仗**（任何勝仗類型：主線、挑戰賽、遭遇戰；不含單挑旁觀）結算完畢、回到大廳（或幕府大廳）時，隨機一位**參戰武將**自己走到主角旁，說一句戰後感想。敗仗與撤退不觸發。
2. 候選：本場出戰的己方武將（不含家臣兵、不含被擒或戰死者）。挑選權重：本場有高光表現者（擊殺最多／受傷最重／立首功）權重 ×3，其他 ×1；**連續兩場勝仗不得挑同一位**（記錄 `lastTalkerId`），參戰僅一人時例外。
3. 台詞依據戰況參數：`{result}`（大勝／險勝／平手式勝）、`{terrain}`（地形）、`{enemy}`（敵將或敵勢力）、`{tactic}`（本場使用的戰法名）。樣板按 `resultBand` 與 `tags` 過濾；缺戰況資訊時用通用句。
4. 口吻：預設 `modern`（輕鬆）；玩家選古風設定時抽 `ancient`；一開口就遵守 ToneLock，範圍為「大廳場景」，離開大廳或開啟任一 UI 視窗即重置。
5. 流程：走路過來（約 1.5 秒，位移補間）→ 氣泡一句（4 秒）→ 站定 2 秒回原位。玩家若在武將走來時點了其他按鈕，立刻中止並回原位，不擋操作。
6. 性別參數：{self} 依 SpeakerVoice；女將台詞通過女角自稱掃描。
7. 防洗版：同一場勝仗只搭話一次；每日（遊戲日）最多 3 次（超過就靜默），避免短時間連打時煩人。

### 4.2 獎勵

- `BUNDLE_VICTORY_CHAT`：與該武將友誼 +1（沿用友誼行為權重表，`source=VICTORY_CHAT`），每位武將每季最多 +2（以 `grantKey = fun03.{generalId}.{seasonNo}.{n}` 去重）。
- 不彈面板，用飄字「與{general}的友誼 +1」。玩家回應不是必要操作（不設選項，不卡流程）。

### 4.3 UI

- 武將頭像與氣泡位置：氣泡錨在大廳點位武將頭頂；走路起點用其原點位、終點為主角旁（相對比例，主角點位右側 0.08 寬），不寫死像素。
- 重用既有大廳點位武將節點，**不複製第二個武將節點**；走路用該節點的位移補間，結束還原。
- 氣泡共用 `FunBarkBubble`（見 1.5）。

## 5. FUN-04 首次招募自我介紹小劇場

### 5.1 規則

1. 觸發：玩家**第一次**招募到某位武將（以 `generalId` 為鍵；`AcquireGrant.isNew = true` 且 `type = 'general'`）。同一武將以後再次加入（轉蛋重複、離隊再回）不觸發（`story.seen.FUN04.{generalId}` 為真）。
2. 內容為一個**雙口吻單元**：
   1. 第一句 `ancient`：用古代口吻報名號、字、籍貫、一句志向（例：「在下姓關名羽，字雲長，河東解良人。」）。
   2. 第二句 `modern`：接一句現代白話吐槽，順便**預告這個遊戲有古今雙口吻**（例：「……啊抱歉，剛剛太正式了。以後我們就用這種輕鬆口氣，放心。」）。
3. 預告的作用：讓玩家第一次就知道「這遊戲的武將會正經一下再吐槽」。第一次整場遊戲只有一位武將需要說出預告句（首位招募者，`funState.dualToneAnnounced = false` 時第二句帶「預告」標籤）；之後的武將第二句只吐槽，不重複預告。
4. 時機：先播自我介紹小劇場，再彈獲得面板（`RewardPresenter`，14.3 對照表 general 列）。這樣玩家先認識人，再看到五圍；轉蛋十連時，只對**新武將**逐位排隊播，**不要超過 3 位**（超過時其餘新武將只在獲得面板顯示 `line`，不播劇場，避免十連太長）；每位劇場長 6～8 秒，可整批跳過。
5. 招募入口：結緣、轉蛋、事件招降、俘虜勸降、傭兵結義都適用，**但戰場中臨時加入**（不回大廳）不播，延到下次回大廳才補播。
6. 性別參數與口吻：女將古代句用妾身／本宮；現代句用本姑娘／人家等（SpeakerVoice）。口吻範圍＝該劇場的 `windowId`；單元結束後鎖定 `modern`，獲得面板的 `line` 因此也走現代口吻。
7. 缺個別台詞的武將：依性格樣板池（每型至少 2 套古＋今）補；兩者都缺時略過劇場，只顯示獲得面板。

### 5.2 獎勵

- 本功能不加額外獎勵（招募本身由原系統結算）。只做一件事：`isNew` 首次招募時寫入 `funState.recruitIntro[generalId] = true`，供去重與圖鑑「已聽過自我介紹」標記。
- 若原招募來源（轉蛋）規格有重複卡轉換，維持原規則不變，不受本劇場影響。

## 6. 驗收重點

1. 四項全部可跳過，跳過後獎勵與旗標照常結算；閃退重進帳目不變、不重複入帳。
2. ToneLock：同一說話者在同一場景／視窗內，古代句後不出現現代句（FUN-02、FUN-04 雙口吻單元為宣告例外）；換場景／換視窗後可重新抽。以單元測試覆蓋（含「古代句後插入現代樣板」須被攔下並寫 warning）。
3. 女角自稱掃描：所有 `fun.*` 鍵以女角、童角代入，不得出現男性自稱。
4. 四語系鍵齊備；en／ja 以最長文字做版面測試，氣泡不超過兩行、不出界。
5. 座標檢查：所有位置為相對比例與錨點，無寫死像素；改視窗尺寸後重排正確。
6. 記憶體：四項共用一個氣泡節點、賓客節點池 5 個，無新增圖集、無逐幀動畫；連續觸發 20 次後節點數不增加。
7. 玩家視角：每項都要在 web-desktop 實跑，截圖與出現次數留證（滿月酒賓客 3～5 位、勝仗搭話連兩場不同人、首次招募預告句只出現一次）。
8. 去重：`grantKey` 重複觸發只入帳一次（單元測試）。

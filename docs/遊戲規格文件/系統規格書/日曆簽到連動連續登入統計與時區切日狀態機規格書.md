# 日曆簽到連動連續登入統計與時區切日狀態機規格書

## 1. 核心定位與設計理念
本規格書定義三國生活（3KLife）留存與大廳系統之「日曆簽到連動、連續登入天數統計（LoginStreak）與UTC+8時區切日狀態機」規範（對應 WBS `RET-09` 與 `PROG-2-0987`）。
連續登入機制旨在培養玩家每日上線巡視營帳之節奏感，並與傭兵 6 日結義試用期深度連動，堅持**真實日曆日、時區統一、中斷精確重置、純函式無副作用**原則：
1. **UTC+8 真實日曆日基準**：統一以伺服器/台灣時區（UTC+8，00:00 點）作為切日標準，避免跨時區裝置作弊或時間錯亂。
2. **純函式狀態機推進**：輸入前次狀態與當前毫秒戳，輸出全新登入狀態，同日不重計、次日遞增、漏登歸一。
3. **傭兵結義期時程連動**：登入日之遞進同時作為推進傭兵 6 日試用期倒數之核心依據。

---

## 2. 時區定義與切日計算模型 (`loginDayOf`)
系統以 UTC+8（台灣標準時區）計算當前所屬日曆日：
- **時區偏移常數**：
  $$\text{LOGIN\_DAY\_OFFSET\_MINUTES} = 8 \times 60 = 480\text{ 分鐘}$$
- **日曆日格式化**：
  傳入系統絕對毫秒時間戳 `epochMs`：
  $$\text{loginDayOf}(\text{epochMs}) = \text{new Date}(\text{epochMs} + 480 \times 60000).\text{toISOString}().\text{slice}(0, 10)$$
  輸出標準字串格式 `YYYY-MM-DD`（如 `2026-11-07`）。

## 3. 連續登入狀態機演算法 (`recordLogin`)
```typescript
export interface LoginStreakState {
    lastLoginDay: string | null;  // 上次登入所屬之 YYYY-MM-DD
    consecutiveDays: number;      // 當前連續登入天數（未登入為 0，登入後 ≥ 1）
}
```

### 3.1 狀態轉換決策鏈
傳入前次登入狀態 `state` 與當前時間戳 `epochMs`：
1. **同日重複登入**：
   若 $\text{state.lastLoginDay} = \text{today}$，判定為同日內多次打開遊戲，保持原狀態不變：
   $$\text{return } \{ \dots \text{state} \}$$
2. **隔日連續登入**：
   若 $\text{state.lastLoginDay} = \text{previousDay}(\text{today})$，判定為完美連續簽到：
   $$\text{return } \{ \text{lastLoginDay}: \text{today},\, \text{consecutiveDays}: \text{state.consecutiveDays} + 1 \}$$
3. **中斷漏簽或首次登入**：
   若 $\text{state.lastLoginDay}$ 為 `null` 或相差超過 1 個日曆日，連續天數重置為 1：
   $$\text{return } \{ \text{lastLoginDay}: \text{today},\, \text{consecutiveDays}: 1 \}$$

## 4. 傭兵 6 日試用結義期連動
- **試用天數推進**：
  當且僅當 `state.lastLoginDay !== today`（跨日登入）時，傭兵系統之試用天數記帳 $+1$。
- **第 6 日結義審核**：
  當 `consecutiveDays` 推進至第 6 天，大廳彈出「六日之約已滿，是否與此將結義金蘭？」之終極決策，若玩家拒絕或點數不足，次日即轉入過期並觸發告別信生成。

## 6. 驗證條件與測試矩陣 (Acceptance Gate)
1. **TC-STREAK-01 首次登入初始化**：從未登入之空狀態傳入時間戳，驗證 `consecutiveDays = 1` 且記錄今日日期。
2. **TC-STREAK-02 同日登入天數不增**：同一日曆日內呼叫 5 次，驗證天數嚴格維持為 1。
3. **TC-STREAK-03 連續次日登入累加**：模擬連續 3 天每日登入一次，驗證天數依序為 1、2、3。
4. **TC-STREAK-04 漏簽斷登歸一重置**：第 3 天登入後跳過第 4 天、於第 5 天登入，驗證天數精確重置為 1。

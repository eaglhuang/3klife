# 晨報摘要時間窗加權篩選與同類折疊演算法規格書

## 1. 核心定位與設計理念
本規格書定義三國生活（3KLife）大廳與生涯系統之「晨報摘要（Morning Report）生成、登入時間窗篩選與同類折疊」演算法規範（對應 WBS `JRN-02` 與 `PROG-2-1174`）。
晨報作為玩家每次登入開啟大廳時的第一道資訊摘要視窗，堅持**只摘要不重算、同類防洗版、官職階位解鎖**原則：
1. **只摘要不重算事實（Digest Only）**：晨報純粹為既有日誌時間軸之動態投影，不衍生新的底層戰鬥或數值變化。
2. **增量時間窗標記（Journal Mark）**：以玩家上次登入時的日誌總條目數為窗標，嚴格僅從標記後新增之日誌中取樣。
3. **同類別去重折疊（Category Dedup）**：同一事件分類僅允許一則最高權重事件入選，徹底杜絕同類事件洗版。

---

## 2. 官職階位名額矩陣 (`morningReportSlotCount`)
晨報可容納之摘要條目上限隨玩家官職階位（`OfficerSnapshot.tier`）解鎖：
- **基礎名額 (`base = 2`)**：官職階位 1 至 3 階（鄉里義士至郡守刺史），每晨提供 2 則重大摘要。
- **高階名額 (`highTier = 3`)**：官職階位 4 至 5 階（州牧都督至霸府重臣，`highTierMin = 4`），每晨解鎖擴充為 3 則重大摘要。

---

## 3. 晨報篩選與排序演算法 (`buildMorningReport`)
傳入候選日誌陣列與玩家官職階位，演算法步驟如下：

### 3.1 隱藏事件過濾
排除所有 `visibility === 'HIDDEN'` 之內部調試或非公開事件，僅保留 `VISIBLE` 條目。

### 3.2 雙鍵穩態排序
按以下權重將候選事件降序排列：
1. **主鍵：優先級 (`priority`) 降序**：優先展現對天下大局、名將死生或重大戰果有決定性影響之事件。
2. **次鍵：時間戳記 (`timestamp`) 降序**：同分時取發生時間最新鮮者。

### 3.3 同類別折疊防洗版
- 維護已選類別集合 `seen = new Set<string>()`。
- 依序走訪排序清單：若該事件之 `category`（如 `BATTLE`）已在 `seen` 中，直接跳過；若未出現，記錄該事件並加入 `seen`。
- 截取前 $N$ 則條目（$N \in \{2, 3\}$），回傳最終展示摘要清單。

## 4. 登入更新與閱讀狀態機 (`refreshMorningReport`)
```typescript
export interface MorningReportState {
    journalMark: number;           // 上次產生晨報時的日誌條目數
    items: MorningReportItem[];    // 當期選出的摘要條目清單
    read: boolean;                 // 是否已讀
}
```
- **登入刷新 (`refreshMorningReport`)**：
  若當前日誌總數大於 `journalMark`，截取增量部分執行篩選，更新 `journalMark = entries.length`，標記 `read = false`；若無新日誌，清空條目並設為 `read = true`。
- **標記已讀 (`markMorningReportRead`)**：
  玩家點擊大廳晨報彈窗或關閉按鈕時，將 `read` 標記為 `true`，大廳紅點即刻消除。
- **標準開篇文案**：
  晨報頂部固定呈現開場白：「晨鼓既響，昨夜諸事已整理成報。」（`MORNING_REPORT_OPENING`）。

## 6. 驗證條件與測試矩陣 (Acceptance Gate)
1. **TC-MR-01 官職階位名額分流**：階位 3 驗證輸出最多 2 則；階位 4 驗證輸出最多 3 則。
2. **TC-MR-02 同類別折疊去重**：傳入 3 則高優先級 BATTLE 條目，驗證最終晨報僅收錄優先級最高之 1 則 BATTLE。
3. **TC-MR-03 隱藏條目過濾排除**：傳入最高 priority 但 `visibility = 'HIDDEN'` 之事件，驗證絕不進入晨報。
4. **TC-MR-04 增量時間窗滾動推進**：日誌從 10 條增至 15 條，驗證只針對後 5 條進行摘要，原 10 條不重複計算。

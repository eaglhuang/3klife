# 武將同名重複抽轉生1至5轉屬性上限與培育次數規格書

## 1. 核心定位與設計理念
本規格書定義三國生活（3KLife）轉蛋系統之「同名武將重複抽取、1至5轉轉生階梯與五維上限突破」養成規範（對應 WBS `GCH-05` 與 `PROG-2-0314`）。
轉生機制旨在將重複獲得之名將轉化為長線養成上限與重育資本，堅持**階梯明確、單一真源、溢出保護**原則：
1. **初見即1轉，上限5轉**：玩家首次獲得武將即為 1 轉；之後每次重複抽出該武將轉數 $+1$，最高至 5 轉。
2. **數值邊界統一對齊**：依據最新奧義系統與數值總表共識，全量統一五維單項上限為 1000 至 1500+，徹底消解歷史歧異。
3. **滿轉溢出無損防呆**：達到 5 轉後再次重複抽到，系統安全標記為溢出狀態，交由結義點數系統回饋玩家。

---

## 2. 轉生五階階梯與數值對照表 (`REBIRTH_TABLE`)
系統依據當前轉數（`rebirthCount`），查表提供武將之五維屬性上限與累計培育次數：

| 轉數 (Rebirth) | 重複抽取次數 | 五維屬性單項上限 (`attributeCap`) | 累計培育機會次數 (`trainingChances`) | 階位特性描述 |
| :---: | :---: | :---: | :---: | :--- |
| **1 轉** | 初次獲得 (0 次) | **1000** | 1 次 | 初始見面，解鎖基礎戰鬥與書院培育資格 |
| **2 轉** | 重複第 1 次 | **1100** | 2 次 | 初步覺醒，五維上限小幅解鎖，可重育 1 次 |
| **3 轉** | 重複第 2 次 | **1200** | 3 次 | 名震一方，解鎖進階戰法槽與第 2 次重育 |
| **4 轉** | 重複第 3 次 | **1350** | 4 次 | 豪傑出世，大幅拉開五維上限，可重育 3 次 |
| **5 轉 (滿轉)** | 重複第 4 次 | **1500+** | 5 次 | 無雙極致，五維突破至極限，享 5 次全額培育機會 |

> **規格消解說明**：本規格書定案屬性上限為 `1000 / 1100 / 1200 / 1350 / 1500+`。歷史文件提及之 1250 與 1400 廢棄不再採用，全面以此單一真相來源為準。

## 3. 重複抽取處理演算法 (`applyDuplicatePull`)
當抽卡結果產出玩家已擁有之武將時，由純邏輯函式判定狀態：
```typescript
export function applyDuplicatePull(currentRebirthCount: number | undefined): RebirthPullResult {
    const current = normalizeRebirthCount(currentRebirthCount);
    const overflow = current >= MAX_REBIRTH_COUNT;
    const next = overflow ? MAX_REBIRTH_COUNT : current + 1;
    const tier = tierOf(next);
    return {
        rebirthCount: next,
        overflow,
        attributeCap: tier.attributeCap,
        trainingChances: tier.trainingChances,
    };
}
```
- **滿轉判定**：若 `current >= 5`，回傳 `overflow = true`，且 `rebirthCount` 維持為 5。
- **未滿轉晉升**：若 `current < 5`，回傳 `overflow = false`，且 `rebirthCount` 晉升至 `current + 1`。

## 4. 轉生語音與演出節奏控制 (`rebirthVoiceLines`)
為避免十連抽連續出重複卡導致語音排隊阻塞結算流程：
- **最大台詞數量限制**：單次抽卡結算畫面最多顯示/播放 3 句轉生專屬台詞（`MAX_REBIRTH_VOICE_LINES = 3`）。
- **去重播放規則**：同名武將若在同次十連中重複抽到多次，只提取播放 1 句台詞。
- **溢出過濾**：若抽取判定為滿轉溢出（`overflow = true`），不播放轉生台詞，改由結義點數 Toast 提示替代。

## 6. 驗證條件與測試矩陣 (Acceptance Gate)
1. **TC-GCH05-01 轉生階梯遞增驗證**：從 1 轉連續呼叫 4 次 `applyDuplicatePull`，轉數依序為 2、3、4、5，屬性上限正確映射為 1500。
2. **TC-GCH05-02 滿轉溢出精確回報**：對已滿 5 轉武將呼叫，驗證 `overflow = true` 且轉數維持 5，不越界。
3. **TC-GCH05-03 語音三句截斷與去重**：傳入 5 位重複武將（含 2 位同名），驗證輸出陣列長度嚴格不超過 3 且無重複角色台詞。
4. **TC-GCH05-04 舊存檔標準化容錯**：傳入 `undefined`、負數或無效值，驗證皆安全退回 1 轉（屬性上限 1000）。

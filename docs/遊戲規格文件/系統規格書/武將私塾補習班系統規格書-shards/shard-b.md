## 7. 友誼系統

### 7.1 定義與等級

- **友誼分數 `fs`**：任意兩位人物（`a`、`b`，不分順序）之間的整數，−100～100。**對稱**（一個值代表雙方，待決 Q-T5：是否改成不對稱）。
- **友誼等級 `lv`**（本書統一用語，與學府「同窗好感」門檻對齊：好感 ≥ 60 結為同窗、≤ −30 為對手，doc_spec_1179 13.5.3）：

| 等級 | 名稱 | `fs` 區間 | 升級／降級 | 備註 |
| --- | --- | --- | --- | --- |
| −2 | 宿敵 | ≤ −60 | | 只提示，不扣戰力（待決 Q-T6） |
| −1 | 對手 | −59～−30 | | 觸發競爭事件（沿用學府 TC-ACD-09） |
| 0 | 陌生 | −29～19 | | 預設狀態 |
| 1 | 點頭之交 | 20～39 | | 教室名牌顯示「認識」 |
| 2 | 熟識 | 40～59 | | 非歷史關係者，**推算值上限是 55**（見 7.3），所以此級以下可純公式 |
| 3 | 好友（同窗） | 60～79 | | 一般人必須靠實際相處（儲存偏移量）或歷史關係才到得了 |
| 4 | 摯友 | 80～94 | | |
| 5 | 至交 | 95～100 | | 結義前置顯示（結義條件仍是 doc_spec_0576：親密度 100＋劇情） |

等級升級時門檻當下生效；**降級有 3 點緩衝**（例：Lv3 要掉到 57 以下才降回 Lv2），避免在門檻附近來回閃動、重複觸發事件。

### 7.2 三層人物分類（決定存不存）

| 層 | 定義 | 存什麼 |
| --- | --- | --- |
| **O 我方（Ours）** | 玩家家族成員、家臣與其子嗣、名冊武將、我方私塾的學生與老師、我方在學府的子嗣 | 與任何人的配對偏移量（只要有互動） |
| **C 接觸者（Touched）** | 非我方，但**曾與 O 有可記錄的接觸**：同班、同學府屆、戰場交手或同編制、外交使節、任務／劇情對手、結緣、招募、交易 | 與 O 的配對偏移量；另存「首次接觸季」（`touched[id]=season`） |
| **X 其他** | 其餘所有 AI 人物 | **什麼都不存**，用 7.3 公式即時推算 |

**儲存規則（寫入時檢查）**：一筆配對 `(a,b)` 只有在「`delta ≠ 0` 或有標記旗標」且「至少一端屬於 O」或「兩端同屬 C 且該互動發生在玩家可觀察的場合（我方私塾教室、我方戰場）」時才存。**X–X 配對永遠不存**（AI 彼此的友誼就是 `prior`）。`friendship.add` 遇到 X 與 O 互動時，先把 X 升為 C（`friendship.touch`）。

### 7.3 推算公式（確定性，純函式，不存檔）

`fs(a,b) = clamp( prior(a,b) + delta(a,b), −100, 100 )`

- `delta(a,b)`：只有 7.2 規則允許存的配對才有值，否則 0。
- `prior(a,b)`：**每次需要時即時算**，輸入全是靜態資料或存檔內的事實欄位，**不含亂數**：

| 輸入 | 符號 | 取得來源 | 計分（企劃暫定，放 JSON） |
| --- | --- | --- | --- |
| 史實關係表 | `H` | `friendship-prior.json` 的史實配對（擴充 doc_spec_0024 關係圖） | 義兄弟 +90、夫妻 +70、師徒 +55、君臣 +45、同袍 +35、宿敵 −60、仇 −80 |
| 動態關係類型 | `Rt` | 存檔 `DynamicRelationRecord.type`（doc_spec_0576／0326） | 戰友 +40、夫妻 +60、親子 +80、義兄弟 +90；`H` 與 `Rt` 取較大者（取絕對值較大） |
| 同門 `Sm` | 同一位老師（私塾或學府教官）門下共 ≥ 2 期 | 人物 `masterIds[]` 的交集；歷史師門表 `masters.json` | 每位共同老師 +12，上限 2 位（+24） |
| 同窗 `Cl` | 同屆學府或同私塾班共 ≥ 2 期 | 同窗標記（存於偏移量的旗標位；AI–AI 由 7.5 節函式推算；歷史同窗在 `masters.json`） | +10 |
| 兒時玩伴 `Kd` | 幼幼班同班過（5～9 歲） | 同上 | +8 |
| 陣營 `Fa` | 勢力與同盟關係 | 人物 `factionId`、外交狀態 | 同勢力 +8、同盟 +3、敵對 −8、其他 0 |
| 血緣 `Bl` | 家族親等 | 家譜（doc_spec_1241）；非親但同姓另計 | 一等親 +30、二等親 +15、三等親 +8、同姓非親 +3 |
| 性格相性 `Te` | 性格向量餘弦相似度 | 人物 `personalityVec`（5 維：剛毅、謀略、仁厚、豪爽、多疑，各 −1～1；**向量只放在靜態資料，不存檔**） | `round(10 × cos(pa, pb))`，範圍 −10～10 |
| 共同經歷 `Sx` | 同編制戰役、同劇情事件、同任務的場次 | 戰史 `warLog`、事件旗標；歷史事件表 `sharedEvents.json` | 每項 +2，上限 +10 |
| 機緣抖動 `Jt` | 打破全員同分 | `hash(worldSeed, lo, hi) mod 7 − 3`（穩定、同一配對永遠同值） | −3～+3 |

`prior = clamp( max(H,Rt) + Sm + Cl + Kd + Fa + Bl + Te + Sx + Jt, −55 若無史實關係, +55 若無史實關係 )`，有 `H`／`Rt` 時以 −100～100 為界。**重點性質**：沒有史實或動態關係的陌生人，**推算值最高 55**（Lv2），要升到 Lv3 好友以上就必須靠「實際相處」寫下偏移量。這使「不存 X–X 配對」不會漏掉任何高等級友誼：AI 之間的 Lv3 以上都有史實根據，已在靜態表裡。

計算成本：全部為整數運算與表格查詢，單次 O(1)（同窗項需 7.5 節的最多 80 次雜湊），結果可在記憶體做 LRU 快取（`cacheMax=2048` 筆，換季清空），**不進存檔**。

### 7.4 儲存方案評估（結論：稀疏偏移量 ＋ 靜態性格向量）

使用者提過可能用向量儲存，以下逐案評估：

| 方案 | 存什麼 | 空間（N≈1,200 人：約 800 武將＋子嗣家臣同窗等生成人物） | 優點 | 缺點 | 結論 |
| --- | --- | --- | --- | --- | --- |
| A 稠密矩陣 | N×N 全配對（或上三角 N²/2） | 約 72 萬格；即使 1 byte 也 ≈ 700 KB，且隨生成人物成長 | 查詢最簡單 | 存檔暴肥；`save.commit` 增量補丁很大；絕大多數格子是 0 或可推算；生成人物一多就爆 | **否決** |
| B 低秩向量（友誼 ≈ ⟨v_a, v_b⟩） | 每人 d 維向量（d=8，float16） | N×16 B ≈ 19 KB | 極小；可泛化 | ① 單一配對的事件（結義、鬧翻）無法精確表達，只能靠調向量連帶改動別人；② 向量更新要浮點梯度，**跨平台不可重現**，違反伺服器權威與簽章（總綱 5.5）；③ 難審計「為什麼是 62」；④ 補丁與對帳困難 | **不作為存檔**；但其精神（性格向量）用於**輸入端 `Te`**，且向量放靜態資料 |
| C **稀疏邊表（本書採用）** | 只存 O/C 相關、`delta≠0` 或有旗標的配對 | 每筆約 35 B；一般 800 筆 ≈ 28 KB；上限 4,000 筆 ≈ 140 KB | 小；可審計（每筆都有原因與時間）；與公式合成後數值確定；補丁友善（路徑穩定）；可修剪 | 需要索引才能列出某人的全部朋友（記憶體建，不存檔） | **採用** |
| D 逐人鄰接表 | 每人一份鄰接清單 | 同 C 約 2 倍（每邊存兩次） | 列出某人朋友最快 | 重複儲存、雙寫易不一致 | 只做**記憶體索引**，不進存檔 |

### 7.5 AI 私塾與同窗的確定性生成（讓 AI–AI 的「同窗／同門」不必存）

AI 世界的補習班是**純函式**，輸入 `(worldSeed, 季)`，輸出一致：

1. `opens(g, season)`：AI 武將 g 是否開班。條件：活著（用既有生卒資料與確定性死亡函式）、年齡 ≥ 20、有專長；`hash(worldSeed, g.id, 'open', 年) mod 100 < openRate(g)`，`openRate = clamp(15 + (專長屬性 − 60) / 2, 0, 40)`（%）。
2. `roster(g, season)`：候選為同勢力或同地區、年齡合格者；以 `hash(worldSeed, schoolId, term, c.id)` 排序取前 `round(capacity × fill)` 位（`fill=0.7`）。
3. `sharedClassTerms(a,b)`：只在 a 的**鄰近學校**（同地區，約 ≤ 10 間）近 8 期內檢查 a、b 是否同班，最多 80 次雜湊；共 ≥ 2 期 → `Cl` 成立。
4. **玩家介入**：我方人物加入某 AI 班時，名單＝`roster` 的確定性結果＋我方人物（滿員時擠掉排序最後的 AI），超出部分**只存我方的加入紀錄**（走 `tutorLearn` 占用與學生端 `enrolled` 清單），不存整班。
5. **招生模型**：玩家私塾的 AI 學生數 `n = clamp(round(capacity × demand) − 我方學生數, 0, capacity)`，`demand = clamp(0.45 + 0.1×級別 − 0.3×(tuitionMul − 1), 0, 1)`；AI 學生人選同樣以雜湊排序決定（不存名單，只存當期名單快照於 `roster` 以便教室顯示與結算）。

> 這使得「AI–AI 友誼隨世界演進」不花存檔：`Cl`、`Sm`、`Sx` 全由確定性函式與靜態表給出。

### 7.6 友誼變化規則（寫入偏移量，一律走 `friendship.add`）

| 來源 | 變化（暫定） | 每配對每季上限 |
| --- | --- | --- |
| 同班上課（每堂，兩人皆到課） | +2；同桌再 +3；性格 `Te ≥ 3` 再 ×1.25（四捨五入）；`Te ≤ −5` 且非同桌 ×0.5 | **+16** |
| 師生（老師↔學生，每堂） | +2；滿 2 期標記 `mentorTie` → 學生之間產生「同門」輸入 `Sm` | +12 |
| 同學小事件（第 9 章選項） | 事件定義的 ±3～±12 | 單件 ±12 |
| 贈禮、拜訪（沿用 doc_spec_0326） | +10／次（`DYNAMIC_RELATION_INTERACT_GAIN`） | +20 |
| 共同出征、同編制戰役 | +3／場（取代 0576 的「共鬥 5 次」只計次數，兩者並存） | +9 |
| 競爭事件落敗、吵架選項 | −3～−10 | −20 |
| **自然衰退**（整季無互動） | 偏移量朝 0 回歸 1／季；有動態關係類型者沿用 doc_spec_0326 的 2／季；**歸零不解除關係**（保留 0326 原則） | — |

偏移量範圍 −100～100；`fs` 另由 clamp 控制。每次 `friendship.add` 由伺服器權威結算並寫 `reason`、`season`，客戶端不得自行改值。

**修剪**：季結算時，偏移量為 0 且無旗標的邊直接刪除（`prior` 仍會算出基準）。總邊數超過 `maxEdges`（4,000）時，先刪「最久未更新且 |delta| 最小、無旗標」的邊，不會刪旗標邊（結義、同窗、同門、`mentorTie`、`childhoodFriend`）。

### 7.7 稀疏儲存結構（存檔）

存檔欄位 `friendship`（權威欄位，`critical` 類，只能經命令副作用改變；總綱 5.7）：

```json
{
  "friendship": {
    "v": 1,
    "touched": { "npc_xiahou_dun_son": 9, "g_sun_ce": 4 },
    "edges": {
      "g_guanping|g_zhaoyun": [34, 11, 2, 1],
      "c_0007|npc_class_0031": [12, 11, 1, 4]
    }
  }
}
```

- **鍵**：`lo|hi`，兩個 id 依字串序排列（對稱，`lo < hi`）；路徑穩定，利於 RFC 6902 補丁與伺服器對帳。
- **值**：`[delta, 最後更新季, 同班累計期數, 旗標位元]`；旗標位元：`1=milestone`、`2=rival`、`4=mentorTie／同門`、`8=classmate同窗`、`16=childhoodFriend`。
- **`touched`**：接觸者 C 的 id → 首次接觸季（O 由名冊與家譜推出，不另存）。
- **記憶體索引**（載入時建，不存檔）：`byPerson: Map<id, Set<edgeKey>>`、`levelOf` 快取，用於「某人的全部朋友」與教室名牌批次查詢。
- **大小預算**：`maxEdges=4000`（約 140 KB）、`maxTouched=1500`；壓縮後約 ⅓。舊存檔缺 `friendship` 欄位視為空表。
- **相容**：`DynamicRelationRecord.intimacy` 由 `clamp(fs,0,100)` 唯讀投影，不再獨立儲存（8.3 節）。

### 7.8 查詢演算法

```
fs(a,b):
  if a==b: return null
  key = lo|hi
  prior = cache.get(key) ?? computePrior(a,b)        // 7.3，O(1)
  delta = edges[key]?.[0] ?? 0
  return clamp(prior + delta, -100, 100)

friendsOf(p, minLv):
  C = edges 索引 byPerson[p]                  // 存檔內的實際互動
  H = 史實關係表[p] ∪ 家譜親屬[p] ∪ 同勢力核心名單[p]  // 公式可能高於 minLv 的候選
  return { fs(p,x) for x in C ∪ H if level(fs) >= minLv }
```

`friendsOf` 不掃全表。因 7.3 的推算上限 55，`minLv ≥ 3` 的查詢只需看 C ∪ H，不必走遍所有人。

## 8. 友誼效益與既有關係接線

### 8.1 等級效益（`friendship-levels.json`，只對涉及我方人物的配對生效；多來源取 max，**不疊加**）

| 等級 | 效益 |
| --- | --- |
| Lv1 | 教室名牌顯示「認識」；同桌配對權重 ×1.2 |
| Lv2 | 可互贈推薦卡；同學事件池解鎖「閒聊」 |
| Lv3 好友 | 兩人同編制出征 +3%（沿用 `classmateSynergyPct`，與學府同窗取 max）；**贈該老師推薦卡 1 張（一次）**；以「故友」身分在劇情中出現（沿用 doc_spec_1179）；若為他國人，外交 +2（私塾版，學府版 +5 不疊加） |
| Lv4 摯友 | 相鄰援護：機率 +15%、分攤 20%（與戰友／義兄弟規則取 max，doc_spec_0576 3.1）；解鎖老師「破例外傳」事件 |
| Lv5 至交 | 每年一次「敘舊」事件（RWD 小獎勵）；結義前置顯示 |
| Lv −1 對手 | 同學小事件「競爭」（學府 TC-ACD-09 同款）；同桌避開 |
| Lv −2 宿敵 | 只觸發更激烈事件，不扣戰力（待決 Q-T6） |

### 8.2 建議的共用化（待決 Q-T3）

「兩人之間有好感／親密／友誼分數」目前至少四處各寫一套：動態親密度（doc_spec_0326／0576）、學府同窗好感（doc_spec_1179 13.5.3）、結緣好感度（家族規格）、大廳 NPC 友誼（目前恆為 0，未完成）。依總綱 3.1 判準（兩處以上類似就提案），**建議升為候選第 8 框架「關係 REL」**，第一版只做「配對分數＋稀疏偏移量＋等級」，本書 7.7 節的結構就是它的雛形；命名上 API 先用 `friendship.*`，抽框架時可平移成 `relation.*`。本書**不等待**此決定：照 7.7 節實作即可，之後平移。

### 8.3 與學府同窗好感、動態親密度接線（只寫差異）

| 既有系統 | 接線方式 |
| --- | --- |
| 學府同窗好感（−100～100，屆內 NPC） | 修業期間照舊在學府內運作；**結業時**把「同窗好感」以 `friendship.add(reason=academyClassmate)` 一次換算成友誼偏移量（好感 ≥ 60 另寫旗標 `classmate`），之後以友誼為準，不再另存好感 |

## 9. 同學小事件（STY）

- 每堂至多 1 個，由 STY `story.trigger(kind=tutorClassmate)` 依條件抽取；事件卡 id 前綴 `TUTEVT_`，與學府 `SUPEVT_`（支援卡）、學府同窗事件**分開事件池**，不互相引用。
- 事件類別：閒聊（Lv2）、借筆記、午睡被抓、分組報告、合作難題、互看不順眼（對手）、老師偏心、放學約飯（Lv3）、破例外傳（Lv4 老師）、敘舊（Lv5）。
- 選項 2～3 個（穩／皮），效果＝友誼 ±3～±12、專長經驗 ±1、少量心情；獎勵走 RWD `reward.grant`。
- **首批 12 則範例文案**放待企劃另卡；風格：現代口語講典故。例：「呂布同桌：你好，我是呂布。（空氣凝結）選項：『我知道，你不用每次自我介紹』／『我是你的新同桌，請多指教』」。
- 事件播放用 STY 現有的對話與立繪元件，不新增播放層。

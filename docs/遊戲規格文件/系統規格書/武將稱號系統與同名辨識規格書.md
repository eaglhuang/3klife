# 武將稱號系統與同名辨識規格書

> **文件狀態**：單一真相來源（Single Source of Truth）  
> **系統代碼**：`GEN-10`、`SYS-TITLE-IDENTITY`  
> **核心職責**：確立同名名將跨時期、跨形態（如青年/巔峰/特殊歷史事件）之身分唯一複合鍵（Composite Key）識別標準，規範卡面展示契約『名稱・稱號』與 i18n 字典鍵值管線。

---

## 1. 核心需求與問題定義

1. **同名名將辨識痛點**：
   - 歷史三國中同一武將存在多重歷史面向（例如：諸葛亮之「躬耕南陽」與「臥龍出淵」；呂蒙之「吳下阿蒙」與「白衣渡江」）。
   - 若僅以姓名或單一 `Template_ID` 索引，會造成名冊覆蓋、成就衝突與戰場同名判定失真。
2. **單一複合身分鍵**：
   - 全域以 `Template_ID + Title_Tag` 作為身分唯一標識（Unique Identity），在存檔與名冊以複合鍵索引，徹底解耦本體資料與版本形態。

---

## 2. 身分識別複合鍵架構

### 2.1 複合鍵語法規則
- **通用識別格式**：`{Template_ID}#{Title_Tag}`
  - 例：`zhuge_liang#wolong`（臥龍諸葛亮）
  - 例：`zhuge_liang#gonggeng`（躬耕諸葛亮）
  - 例：`lu_meng#baiyi`（白衣呂蒙）
- **單一存在性保證**：
  - 出征編制中，同一 `Template_ID` 無論稱號為何，**同隊伍僅允許一人在陣**（防同源多重身出陣悖論）。
  - 圖鑑系統則以複合鍵分開收錄，並享各自的立繪、初始屬性與特有戰法。

---

## 3. 介面卡面展示契約（UI Presentation）

### 3.1 顯示格式標準
在戰鬥抬頭、武將詳情頁（GeneralDetailOverview）、抽卡開獎及圖鑑列表中，全域強制套用統一格式：
$$\text{Display Name} = \begin{cases} \text{『} + \text{Name} + \text{・} + \text{Title} + \text{』} & \text{若 Title 存在且非空} \\ \text{Name} & \text{若無稱號（一般基層卒伍）} \end{cases}$$

- **介面顯示範例**：
  - `『諸葛亮・臥龍』`
  - `『關羽・美髯公』`
  - `『趙雲・常勝將軍』`
  - `『周瑜・美周郎』`

---

## 4. 多語系字典結構與鍵值規範（i18n Mapping）

稱號字串一律經由本地化字典解析，禁止在前端程式碼中硬編碼中文。

### 4.1 鍵值規則
- 前綴：`TITLE_`
- 組合格式：`TITLE_{TEMPLATE_ID_UPPER}_{TITLE_TAG_UPPER}`

```json
{
  "TITLE_ZHUGE_LIANG_WOLONG": "臥龍",
  "TITLE_ZHUGE_LIANG_GONGGENG": "躬耕",
  "TITLE_GUAN_YU_MEIRAN": "美髯公",
  "TITLE_ZHAO_YUN_CHANGSHENG": "常勝將軍",
  "TITLE_LU_MENG_BAIYI": "白衣渡江"
}
```

## 5. TypeScript 型別與輔助函式

```typescript
export interface GeneralIdentity {
  templateId: string;
  titleTag?: string;
  nameKey: string;
}

export function formatGeneralDisplayName(
  name: string,
  title?: string
): string {
  if (!title || title.trim().length === 0) {
    return name;
  }
  return `『${name}・${title}』`;
}

export function getGeneralCompositeKey(templateId: string, titleTag?: string): string {
  return titleTag ? `${templateId}#${titleTag}` : templateId;
}
```

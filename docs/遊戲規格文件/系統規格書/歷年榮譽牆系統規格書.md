# 歷年榮譽牆系統規格書

## 1. 系統目標與框架定位
為《史境天下風雲榜與年終頒獎典禮》補齊跨年長期紀錄與回顧入口，強化「百年門閥、世代名門」的長期目標感。
- **框架共用（COL 第 9 套）**：本系統屬於「歷年獎項／徽章的收藏檢視」，**掛載於收藏／圖鑑（COL）框架（第 9 套）下作為一個分頁**，不獨立另起平行圖鑑系統。
- **獎勵／徽章共用**：`badgeUnlocked` 欄位僅引用既有獎勵框架之徽章鍵，徽章的解鎖判定與發放一律走既有獎勵框架，不自建發獎流程或第二份徽章清單。

## 2. 共通存檔契約與版本遷移
- **共通存檔 API**：所有讀寫一律透過共通存檔 API（本機 adapter），維持單機與雲端同一介面，**嚴禁直接讀寫本機檔案**。
- **存檔版本與遷移**：
  - `SaveSchemaVersion` 遞增至 `vNext`（實作時依當時最新 schema 版號 +1）。
  - 新增 `honorWallRecords: HonorWallYearRecord[]` 與 `currentYearSnapshot: HonorWallYearRecord | null`。
  - 舊存檔遷移：缺漏上述欄位時，於載入遷移器預設為 `honorWallRecords = []`、`currentYearSnapshot = null`，不報錯。
- **單年紀錄結構**：
  - `year` (`number`)：結算年份（第 1 年起）
  - `playerRank` (`number`)：玩家家族該年名次（1 起算）
  - `playerScore` (`number`)：玩家家族該年名門總分
  - `topThree` (`HonorWallEntry[]`)：前三名清單（`rank: 1 | 2 | 3`、`familyName`、`leaderGeneralId`、`score`、`isPlayer`）
  - `badgeUnlocked` (`string | null`)：引用既有獎勵框架之徽章鍵（如 `three_peat_famous_house`）
  - `speechSummaryKey` (`string`)：當屆冠軍感言摘要 i18n 鍵
- **設定檔（JSON）**：`assets/resources/data/master/honor-wall-config.json`
  - `maxStoredYears` (`number`, 預設 `50`)：完整明細最多保留年數
  - `highlightTopRank` (`number`, 預設 `3`)：榮譽牆金框標示名次門檻

## 3. 首年可看與每季快照
- 避免第 1 年前 11 個月榮譽牆空白：開局即顯示「**進行中的今年（第 `{year}` 年・預覽）**」置頂卡片，呈現目前名次與季度小計。
- 每季結算時透過共通存檔 API 寫入 `currentYearSnapshot`；年終典禮完成後將該年正式歸檔進 `honorWallRecords` 並清空當季快照。

## 4. UI 佈局（錨點／響應式）與記憶體策略
- **響應式錨點**：入口按鈕與分頁版面一律採用 UI Spec 相對比例與 Widget 錨點（`top`/`right`/`left`/`bottom` 與安全區比例），不寫死絕對座標，保留日後直式或手機橫式相容性。
- **50 年記憶體與渲染策略**：
  - 列表採**虛擬捲動（Virtual Scroll）重用節點**，僅實例化可視範圍內卡片。
  - 武將頭像一律取用共用小頭像圖集（Shared Atlas），不逐年動態載入散圖。
  - 超過 `maxStoredYears`（50 年）時，舊年份僅保留前三名摘要（裁除次要欄位），單年完整紀錄序列化大小上限估算約 `<= 450 bytes`（50 年合計 `< 25 KB`）。

## 6. 驗收條件
1. 開局即顯示「進行中的今年」預覽卡片，每季更新小計；第 1 年年終典禮後正式寫入 `honorWallRecords`。
2. 舊存檔無 `honorWallRecords` 欄位時向後相容為空陣列，不報錯。
3. 掛載於 COL 第 9 套收藏框架下，徽章發放走既有獎勵框架，四語系 i18n 與 `honor-wall-config.json` 完整對接。

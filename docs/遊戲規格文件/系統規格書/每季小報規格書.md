# 每季小報規格書（季末《本季大事記》搞笑小報）

## 1. 定位與範圍

- 裁決依據：2026-11-27 使用者從「新手首年樂趣缺口」清單選定「每季小報」。
- 玩家體驗：每次換季，玩家都會收到一張搞笑小報，三行本季大事加一位武將的吐槽，讓玩家覺得「我的家族這一季真的發生了事」。
- 只用既有數據，不加新系統、不新增存檔欄位、不寫入任何資源。小報本身不能領獎、不能點選項，點一下就收。
- 與既有報表的關係：季報（SeasonReportComposite）列數字與官職預告；任務回報卡疊列大廳任務結果；三國季報（doc_spec_1171）列天下大勢與市井奇遇。本小報只做「一眼讀完的笑點摘要」，不取代它們。

## 2. 資料來源（全部是既有數據）

| 事件種類 kind | 來源 | 判斷方式 |
| --- | --- | --- |
| `marriage` 婚嫁 | 武將心智事件流（MindEvent） | `BOND_FORMED` 且 tags 含 `marriage`，季別為剛結束的那一季 |
| `birth` 新生兒 | 武將日誌（Journal） | entryId 前綴 `GENERAL_BORN` |
| `promotion` 升官 | 官職狀態（OfficerState） | 換季前後 `currentTier` 變大 |
| `battle_win` / `battle_lose` 戰果 | 武將日誌 | entryId 前綴 `BATTLE_WIN`／`BATTLE_LOSE` |
| `retire` 退隱 | 武將日誌 | entryId 前綴 `GENERAL_RETIRE` |
| `recruit` 招募 | 名冊（Roster） | 換季前後多出的成年武將（age 大於等於 16），不含教官卡 |
| `dispatch_win` / `dispatch_fail` 任務 | 武將日誌 | entryId 前綴 `DISPATCH_SUCCESS`／`DISPATCH_FAIL` |

- 日誌只取時間戳記大於等於「剛結束那一季」的條目（時間戳記格式沿用 GameSession `seasonJournalTimestamp`：`YYYY-SS-01T00:00:00`）。
- 轉蛋大獎目前沒有可讀的既有紀錄，列為保留種類，資料檔不收錄；日後有紀錄只要在資料檔加一列與一個來源映射即可，不改程式流程。

## 3. 大事挑選規則（資料檔 `assets/resources/data/season-news-rules.json`）

所有數值與映射放資料檔，程式只讀不寫死：

- `headlineCount`：頭條行數，首版 3。
- `kinds.<kind>.priority`：優先序，越大越前面（首版：婚嫁 90、新生兒 85、升官 80、戰果勝 70、招募 65、戰果敗 60、退隱 55、任務成 40、任務敗 35）。
- `kinds.<kind>.tone`：吐槽語氣 `good`／`bad`，沒大事時用 `quiet`。
- `sources.journal`：日誌前綴映射到 kind；`sources.mind`：心智事件映射到 kind。
- `fillerCount`：不足三行時，用 `ui.seasonNews.filler.<1..N>` 補滿的候選句數。

挑選演算法（純函式，同輸入同輸出）：

1. 同 kind 的事實合併成一行（名字以「、」串接，最多列 `maxNames`＝3 位，其餘寫「等 N 人」）。
2. 依 priority 由大到小取前 `headlineCount` 行；同分以人數多者在前，再以種類字串排序，確保可重現。
3. 不足三行用 filler 句補滿（依季序號輪流挑，不重複）。
4. 吐槽者：頭條第一行的相關武將（仍在名冊者）；沒有則取主將；再沒有則取名冊第一位。語氣由頭條第一行的 tone 決定，沒有事實時為 `quiet`。

## 4. 台詞與 i18n

- 頭條走 `ui.seasonNews.item.<kind>`，參數 `{0}`＝名字串、`{1}`＝人數／階位名；全部繁中現代口語搞笑、不悲劇。
- 吐槽走 `ui.seasonNews.roast.<tone>.<性格>`（Brave／Wise／Loyal／Playful），槽位 `{self}` 一律由 SpeakerVoice（`voiceSlots`）依性別、性格、年齡代入，樣板內不寫死某、老夫之類的自稱。
- 武將頭像與對話框重用共用元件 PopupGeneralSpeaker（doc_spec_1343），不新增圖集。
- 四語系（zh-TW、zh-CN、en、ja）鍵完全一致；畫面文字不寫死。

## 5. UI 與排隊

- 全程式建構，只用一組節點：遮罩、報紙底板、報頭（`ui.seasonNews.title`＋期數）、三行頭條、頭像與吐槽框、關閉提示。
- 版面用「可視尺寸的比例」：底板寬佔可視寬 0.62、高佔可視高 0.78，內部每一個子節點的位置都由底板尺寸的比例算出，視窗尺寸改變時重排，不寫死座標（保留日後改直式或手機橫式）。
- 點遮罩任意處或底板任意處即收起；Promise 在收起時完成，呼叫端接著開下一個彈窗。
- 換季彈窗佇列（從先到後）：任務回報卡疊 → 戰報（季報） → **每季小報** → 三國季報／季事件／血統彈窗 → 年終頒獎典禮 → 吃醋 → 孩子成長小事。小報在季報關閉後、其他彈窗開之前開，結束才排下一個，不互相蓋住。
- 快轉（連續換季）路徑不彈小報；年終守城後補換年的路徑與一般換季相同。
- 首年前兩季（精簡流程）照樣彈小報：它只有一張、點一下收起，是新手首年最輕的一層回饋。

## 6. 邊界與不做

- 不存檔、不記「已讀」；小報只在換季當下顯示一次，錯過就沒有。
- 不加按鈕、不給獎勵、不影響任何資源與武將狀態。
- 資料檔缺失或壞掉時用內建預設（程式內 `DEFAULT_SEASON_NEWS_RULES`），不擋換季。
- 當季沒有任何事實時，三行全用 filler，吐槽走 `quiet`。

## 7. 驗收

| 編號 | 項目 |
| --- | --- |
| TC-NEWS-01 | 同事實輸入兩次，輸出完全相同 |
| TC-NEWS-02 | 事實多於三種時，只留 priority 最高的三種 |
| TC-NEWS-03 | 同 kind 多位武將合併為一行，超過 maxNames 寫「等 N 人」 |
| TC-NEWS-04 | 事實不足時補 filler，總行數永遠等於 headlineCount |
| TC-NEWS-05 | 日誌只取剛結束的那一季及之後的條目；舊季條目不入報 |
| TC-NEWS-06 | 吐槽台詞自稱走 SpeakerVoice：女將不出現「某」、少年用「我」 |
| TC-NEWS-07 | 資料檔壞掉時退回預設，不拋例外 |
| TC-NEWS-08 | 四語系鍵一致、資料檔每個 kind 都有 `item` 句與 tone 對應的吐槽句 |
| TC-NEWS-09 | 無頭預覽走到換季，小報出現且關閉後才接後續彈窗（截圖存 artifacts/ui-review/season-news-1127/） |

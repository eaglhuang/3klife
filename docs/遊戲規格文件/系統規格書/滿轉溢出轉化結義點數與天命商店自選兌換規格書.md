# 滿轉溢出轉化結義點數與天命商店自選兌換規格書

## 1. 核心定位與設計理念
本規格書定義三國生活（3KLife）轉蛋系統之「5轉滿溢出轉化結義點數與天命商店大保底自選兌換」回饋模型（對應 WBS `GCH-06` 與 `PROG-2-0315`）。
溢出與自選兌換機制旨在杜絕玩家抽卡「無效溢出感」，堅持**零浪費、等價補償、自選自主**原則：
1. **滿轉溢出等價轉化**：當 5 轉武將再次被重複抽中時，系統自動將溢出卡片轉化為對應稀有度之「結義點數（Bond_Points）」。
2. **閉環轉化傭兵永久結義**：結義點數可於客棧中將契約傭兵晉升為終身家臣，使抽卡收益無縫反哺遊戲主玩法。
3. **天命商店自由兌換**：累積達 200 抽之大保底額度，允許玩家自由指定兌換當期焦點 SSR 名將，避免特定角色屢抽不中。

---

## 2. 滿轉溢出結義點數對照表 (`BOND_POINTS_BY_RARITY`)
溢出轉化點數與遊戲內傭兵簽約費用嚴格等價（一次溢出 = 一次對應階位之傭兵結義），便於玩家理解：

| 稀有度階級 (`OverflowRarityTier`) | 對應轉蛋稀有度 | 代表品階範例 | 溢出轉化結義點數 (`Bond_Points`) | 稀有度對應分類 (`characterCategory`) |
| :---: | :---: | :---: | :---: | :---: |
| **common** | N / 普通 | 地方雜兵、尋常壯丁 | **100** | default / 基礎品級 |
| **rare** | R / 稀有 | 基層校尉、百夫長 | **300** | `general` (一般將佐) |
| **epic** | SR / 史詩 | 各州名將、中階督軍 | **600** | `famed` (聞名豪傑) |
| **legendary** | SSR / 傳奇 | 史詩名將、天下無雙 | **1200** | `titled` (名號統帥) |
| **mythic** | UR / 神話 | 曠世神話、傳奇君王 | **1200** | `mythical` (神話先賢) |

### 2.1 稀有度自動推斷邏輯 (`overflowRarityOf`)
當傳入武將資料缺乏明確 `rarityTier` 欄位時，系統自動依據 `characterCategory` 向下推斷對應階級；若兩者皆無，安全保底退回 `common`（100 點）。

## 3. 結義點數用途與經濟閉環
- **傭兵結義系統 (`BOND_COST`)**：
  玩家在戰場或酒館僱用傭兵後，耗費與該傭兵品階相應之結義點數，即可永久收入家族麾下，免除每季續約金並保留已培育戰法。
- **點數存檔正規化 (`normalizeBondPoints`)**：
  結義點數儲存於玩家個人存檔中，讀取時強制過濾非法浮點數或負值：
  $$\text{BondPoints} = \max\left(0,\, \lfloor \text{rawPoints} \rfloor\right)$$

## 4. 天命商店大保底自選兌換機制 (`DestinyShop`)
天命商店作為大保底的落地展示窗口：
- **兌換權限計算**：
  $$\text{RedeemableCoupons} = \max\left(0,\, \left\lfloor \frac{\text{TotalPulls}}{200} \right\rfloor - \text{destinyExchanges}\right)$$
- **自主兌換焦點名將**：
  當 `RedeemableCoupons >= 1` 時，玩家可在商店介面直接選取當期 `Featured_SSR` 武將之一，消耗 1 次額度領取。
- **記帳安全防護**：
  兌換成功後，存檔僅遞增 `destinyExchanges += 1`，總抽數 `TotalPulls` 永不清零，保護玩家累計成就與 VIP 數據完整性。

## 5. Unity 與 Cocos Creator 概念對照
| 概念維度 | Cocos Creator 實作架構 | Unity 引擎對照架構 |
| :--- | :--- | :--- |
| **溢出點數查表** | `OverflowBond.ts` 純函式與常數表映射 | ScriptableObject 定義之 `OverflowRewardTable` |
| **天命商店查詢** | `DestinyShop.ts` 計算兌換憑證與呼叫角色發放 | `PityShopManager` 管理兌換券庫存與觸發發貨事件 |
| **提示與反饋** | 抽卡結算後以 Toast 提示獲得結義點數 | UIManager 彈出全域獎勵彈窗或飄字提示 |

## 6. 驗證條件與測試矩陣 (Acceptance Gate)
1. **TC-GCH06-01 稀有度點數精確轉換**：驗證傳入 `epic` 回傳 600 點；傳入 `legendary` 回傳 1200 點；未知值回傳 100 點。
2. **TC-GCH06-02 武將分類推斷覆蓋**：傳入僅具 `characterCategory = 'titled'` 之物件，驗證正確識別為 `legendary` 並給予 1200 點。
3. **TC-GCH06-03 天命商店多次累積兌換**：累計 400 抽未兌換，驗證可兌換數為 2；兌換 1 次後剩餘可兌換數為 1。
4. **TC-GCH06-04 點數存檔防呆與正規化**：傳入負數或字串，驗證皆安全標準化為整數 0。

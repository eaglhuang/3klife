# 3KLife 特效節點物件池預熱自動回收與防殘留洩漏狀態機規格書

> **規格代碼**：SPEC-VFX-LIFE01  
> **關聯 WBS**：VFX-LIFECYCLE-01（戰鬥特效節點物件池預熱、自動回收狀態機與防殘留洩漏看門狗機制）  
> **系統分類**：前端底層架構 / 記憶體與物件生命週期管理  
> **狀態**：正式生效（單一真相來源，嚴禁尾端追加補丁）

---

## 1. 系統背景與設計挑戰

在 Cocos Creator 即時戰鬥中，頻繁呼叫 `instantiate()` 生成特效節點與 `destroy()` 釋放節點，會導致嚴重的 JavaScript 記憶體垃圾回收（GC Spike），引發戰鬥關鍵時刻（如奧義暴擊、絕殺結算）出現 50~200ms 的卡頓。

為徹底杜絕戰鬥中的動態實例化與記憶體抖動，本系統實裝**強型別特效節點物件池（VfxNodePool）**：
1. **進場預熱（Prewarm）**：戰鬥載入階段依預設清單預先配置足量節點。
2. **生命週期狀態機管理**：嚴密監控節點狀態流轉，保證借出必有歸還。
3. **看門狗防洩漏機制（Leak Watchdog）**：防止動畫回調遺失或打斷時節點懸掛在場景樹中。

## 3. 特效節點生命週期狀態機

每個受池化管理的特效節點實裝 `IVfxNodeWrapper` 介面，依狀態機嚴格流轉：

```
 IDLE (池中待命) ──acquireNode()──> ACQUIRED (重置位移) ──play()──> ACTIVE (播放中)
   ▲                                                                    │
   │                                   ┌────────────────────────────────┤
   │                                   │ 自然播畢 (COMPLETED)           │ 逾時 5.0s (FORCE_KILL)
   │                                   ▼                                ▼
   └─────────────────────────── recycle() 執行重置契約 (Reset Contract) ┘
```

1. **`IDLE`**：待命佇列，`node.active = false`，父節點為物件池根節點 `__VFX_POOL_ROOT__`。
2. **`ACQUIRED`**：業務借出節點，掛載至戰鬥場景圖層，重置座標與縮放。
3. **`ACTIVE`**：播放動畫或啟用粒子，記錄啟動時間戳 `spawnTimestamp`。
4. **`COMPLETED`**：動畫自然結束觸發 `onAnimationFinished`，進入回收流程。
5. **`FORCE_KILL`**：因武將死亡、戰鬥終止或超時，由排程強制中斷播放並回收。

---

## 4. 節點重置契約（Reset Contract）與看門狗安全閥

歸還物件池時強制執行**重置契約**：
- **Transform 清零**：座標設為 $(0,0,0)$、旋轉設為 $0^\circ$、縮放重設為 $1.0$。
- **粒子發射器清理**：呼叫 `particleSystem.stopSystem()` 與 `resetSystem()`，清空現存殘留粒子。
- **透明度還原**：`UIOpacity` 或 Sprite 顏色 Alpha 還原為 $255$。
- **音效中斷**：若帶有殘留持續性音效，立即停止播放。

**看門狗安全防護（Safety Leak Watchdog）**：  
戰鬥管理器每秒掃描處於 `ACTIVE` 狀態之特效節點。若某節點活動時間超過其定義的 `durationMs + 500ms`（或絕對時間超過 $5.0$ 秒），判定為**遺失回調之孤兒節點**。看門狗立即發出警告日誌並強制執行 `FORCE_KILL -> recycle()`，徹底杜絕場景樹節點累積洩漏。

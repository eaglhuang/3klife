# 羈絆戰場效果整併方案規格書

> **責任邊界**：本檔是「羈絆（結義／夫妻／戰友／史實關係）在戰場上的效果」的整併方案。整併裁決後，戰場羈絆效果以本檔為單一真相來源；原三份規格只保留各自的非戰場部分，並加指向本檔的註記。
> **狀態**：七題開放問題已全部裁決（見 §6），D1 夫妻合攻已裁決為 26%（§6.2）。已有規格的數值照用，本檔不自行擅定數值。
> **關聯卡**：PROG-2-10217（本案）、PROG-2-10204（PR #2788，程式現況）、PROG-2-1065（史實合攻）。
> **使用者裁決（11/28）**：①結義光環、合攻、生死相隨整併成一套；②義兄弟士氣 +20 整場常駐；③生死相隨範圍改九宮格（含斜角）；④傭兵結義的 `generalUid` 與虎符 `templateId` 用同一套 id。

## 2. 整併後單一模型：羈絆戰場效果

### 2.1 關係等級

整場戰鬥只認下面四種等級，其餘關係在戰場上**沒有效果**：

| 等級 | 名稱 | 資料來源 | 備註 |
|---|---|---|---|
| L3 | 義兄弟 | 史實 `SWORN`、動態 `DYNAMIC_SWORN`（含傭兵結義轉正者） | 兩套來源視為同一等級，不分史實或動態 |
| L2 | 夫妻 | 史實 `COUPLE`、動態 `SPOUSE` | 有援護、無士氣、合攻 26%（使用者裁決 11/28，§6.2 D1） |
| L1 | 戰友 | 動態 `COMRADE`（共同出戰 ≥ 5 場） | |
| L0 | 其他史實關係 | `MASTER_STUDENT`、`LORD_VASSAL`、`RIVAL` | 戰場無效果、合攻一律 0（師徒、主從、宿敵只影響繁衍或忠誠，不進戰場） |

兩位武將之間同時有多種關係時，**取等級最高的一種**，不重複計算。「斷義」（割袍斷義）成立後，該對關係整個移除，四種效果同時消失。

### 2.2 四種效果總表

> 數值欄只填「已有規格數值」；題號對應 §6 的裁決結果。

| 效果 | 作用的軸 | 觸發範圍 | 資格 | 數值 | 疊加與上限 |
|---|---|---|---|---|---|
| ① 同陣加成 | 士氣 | 出戰名單內，不看距離 | L3 義兄弟 | 士氣 +20，整場常駐（不隨回合歸零，Q6 已決） | 同一部隊只算一次，不因兄弟人數增加 |
| ② 近距離光環「兄弟齊心」 | 攻擊、防禦、暴擊 | 與另一位義兄弟的部隊切比雪夫距離 ≤ 3 格（Q2 已決） | L3 義兄弟 | 物攻物防 +25%、暴擊 +15%（Q1 已決，照名酒規格 §3） | 同名增益只算一次（Max），兄弟 3 人也只 +25% |
| ③ 合攻 | 追加傷害 | 目標九宮格（含斜角，8 格）內的友軍，與援護同一套範圍（Q3 已決） | L3 義兄弟、L2 夫妻（使用者裁決 11/28）、L1 戰友（Q4 已決）；其他史實關係 0 | 基礎觸發 20%（戰友）；義兄弟與夫妻 ×1.3（= 26%，夫妻使用者裁決 11/28）；追加傷害 50%（Q5 已決）；每回合最多 2 次、不耗 AP、援護方精力 −3、雙方士氣 +5 | 多個相鄰羈絆取最大倍率，不累乘；觸發率最高 100%；單次攻擊最多 1 位合攻者 |
| ④ 援護「生死相隨」 | 承傷分攤 | 受擊部隊的九宮格（含斜角，8 格） | L3、L2、L1（Q7 已決：夫妻有援護） | 致命傷害時 50% 機率，援護者承擔 30% | 每次致命傷害最多 1 位援護者；援護傷害不會再被援護（不連鎖）；援護者自己死亡照常結算 |

### 2.3 防止數值爆炸：四條硬規則

1. **一條軸一個來源**：士氣、攻防暴擊、追加傷害、承傷分攤四條軸各自獨立，每條軸只有一個羈絆效果，不會有兩個羈絆效果去加同一個數。
2. **同名取大、不累加**：同一種效果被多位兄弟同時提供，只算一次（光環 +25% 不會變 +50% 或 +75%；合攻倍率取最大不相乘；士氣 +20 不因兄弟人數增加）。
3. **一次事件一個羈絆動作**：一次攻擊最多觸發 1 次合攻；一次致命傷害最多 1 次援護；援護與合攻的追加傷害不再觸發合攻或援護（不連鎖）。
4. **關係等級取最高**：同一對武將只算最高等級那一種關係，不會因為「既是夫妻又是戰友」拿到兩份。

這四條各自可以單獨寫測試（見 §5），總量上限由「四條軸 × 各一個來源」直接決定，不需要另外的全域上限。

### 2.4 援護者的選擇（多位符合時）

九宮格內有多位符合資格的部隊時，依序挑：①等級高者（義兄弟 > 夫妻 > 戰友）；②同等級再看固定掃描順序（lane 再 depth），讓同一局重播結果一致。合攻助攻者選擇同理（資格只有義兄弟、戰友）。這是實作細節，不影響數值。

### 2.5 單一 id：傭兵結義與虎符

戰場上查「這兩位是不是義兄弟」只用一個 id 空間：

- 使用者裁決：傭兵結義的 `generalUid` 與虎符 `templateId` 用**同一套 id**。
- 因此 `DYNAMIC_SWORN` 紀錄的 `uidA／uidB` 必須寫入 `templateId`（也就是史實關係表用的 id），讓史實關係表與動態關係表可用同一個 key 查。
- 傭兵 6 天試用期內尚未結義，沒有任何羈絆效果；結義成功轉正的那一刻才建立 `DYNAMIC_SWORN`，下一場戰鬥起生效。到期退場或冷卻中的傭兵不進出戰名單，也就不會提供羈絆效果。

### 2.6 資料驅動

四種效果的所有數值（士氣、光環倍率、暴擊、合攻基礎率與倍率、追加傷害比例、援護機率與分攤比例、光環距離）集中到一份 JSON（建議 `assets/resources/data/kin-battle-effects.json`），程式只讀資料，不寫死。台詞與飄字走 i18n 四語系，帶性別參數。

## 3. 與戰場核心規則不衝突的證明點

核心規則：①五路對撞；②小兵只打同路正面，旁邊不打（只有武將經過時才會打旁邊小兵）。

| # | 證明點 | 說明 |
|---|---|---|
| P1 | ① 同陣加成、② 光環只改數值，不改「誰打誰」 | 士氣與攻防暴擊是屬性加成，不改變任何部隊的目標選擇、移動、車道 |
| P2 | ④ 援護只重新分配傷害，不產生新的攻擊 | 援護者不出手、不被反擊、不改變敵方攻擊目標；只是替受擊者吃一部分傷害。九宮格斜角部隊在別條車道，也只是「被扣血」，沒有「攻擊旁邊」 |
| P3 | ③ 合攻是「已命中」之後的追加，不新增攻擊對象 | 合攻的目標一定是原攻擊已經命中的同一個目標，而原目標由五路對撞與同路正面規則決定；合攻本身不會把攻擊擴散到別的敵人 |
| P4 | 合攻助攻者可能在相鄰車道（灰區，已由使用者裁決放寬） | 現況（PM 裁定 PROG-2-1065）只允許與目標前後左右相鄰的友軍助攻；Q3 裁決改成目標九宮格（含斜角），助攻者範圍變大、更常跨車道。合攻仍是「原攻擊命中後的追加一擊」，目標一定是同一個已命中對象，不新增攻擊對象，也不改小兵只打同路正面的目標選擇；範圍放寬屬使用者核准的調整，並與援護共用同一套九宮格 |
| P5 | 光環的距離也是只讀位置 | 光環範圍內判斷是「有沒有義兄弟在 ≤ 3 格」，是讀取位置，不移動或牽引部隊 |
| P6 | 所有效果只對「有羈絆的雙方」生效，不對路人小兵生效 | 一般友軍與小兵之間仍是 0 加成，不會出現「小兵因為旁邊有義兄弟而打旁邊」 |

> 結論：①②④ 與核心規則無衝突；③ 範圍放寬已經使用者裁決（Q3），且仍只追加在原目標上。

# R4／R5 文件與案例索引增補 v4

本增補只建立可追溯的文件、功能、來源章節、文件案例及歷史案例雙向定位，不改 v3 規格正文，不是產品實作或測試報告。正式 repo 落點、doc_id、task／准入尚未完成。

## 使用方式與來源綁定

先取得「來源綁定.json」指定 SHA256 的完整 v3 ZIP，解壓到同一 base root。各索引的 package_relative_path／specification_path／source_path 均相對該 root；不是相對增補包資料夾。以文件 SHA256 驗證後才使用一基行號／JSON pointer。增補包不替代完整規格，不能單獨視為全部來源正文。

## 索引清單

- 文件總索引.json：v3 包全部 67 檔（60 Markdown、7 JSON），含 15 基線及 6 清單檔；正式 ID 與 repo 路徑均為 null。
- 功能反向索引.json：38 個功能的規格、來源章節、原20入口映射、346案例、原40引用及待決。36主體與2未採提案分帳。
- 案例索引.json：346個 v3 文件案例與40個原題目案例分命名空間定位；同名／重用關係明列，不能相加成已測數。
- 來源章節反向索引.json：保留已交52列章級責任映射；其歷史案例尚未映射列由本版逐條歷史對照增補，不覆寫原件。
- 決策與補件反向索引.json：19待決與17補件條目分開，不將依賴傳播成整功能全面阻擋。
- historical_case_index/：129條歷史案例對照及其來源manifest，保直接／部分／相關／無對應分類，不把相關案例當完整fixture。

## 正式入庫門檻

這是文件 package-relative 索引，不是正式 doc registry。60份 Markdown 的候選分類為4份 README=index、其餘56份=spec；正式分類、doc_id與路徑須依官方工具及實際落點判定。JSON保持合法JSON，不插HTML doc_id。若注入doc_id、重命名或移動路徑，必須對入庫副本重新驗證連結、SHA、行定位與正反向集合；本增補的原始SHA不冒充修改後副本。

## 驗收分帳

映射完整性不代表產品測試通過、歷史runner齊全、候選數值採定或施工准入解除。346份文件案例全部NOT_RUN，38功能implementationReady=false，產品驗收NOT_ASSESSED。歷史原文結果另欄保留，不當本次執行。缺契約、19待決、17補件及正式准入仍按原規格逐操作處理。海外／門閥等未採提案不因索引登錄而變成必做。

若原 v3 包與本增補一起正式入庫，另有本增補 README、索引總覽、歷史案例對照索引共3份Markdown待官方配號，因此合計63份；原67檔文件索引仍只描述不可變v3包。增補其他JSON不插doc_id。

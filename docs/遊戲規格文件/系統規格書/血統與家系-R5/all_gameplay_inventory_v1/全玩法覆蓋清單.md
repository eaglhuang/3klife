# 3KLife 全玩法第一階段：分母與未驗缺口

固定版本：`96a83124094d3b2485bfb749ef37d567ad834559`。本包是唯讀盤點，不修改產品 repo，也不執行或代替正式任務卡。

## 此包回答什麼

先建立「哪些玩家行為還要驗」的分工與追蹤入口。**不是所有玩法已研究完成，也不是規格或程式驗收通過。**

- 全倉根目錄入口已列於 root_scope.json。遊戲候選原碼 roots `assets/scripts`、`server`、`shared` 完整 Git tree 均 `truncated=false`。
- 暫分 **42 個玩法域**：G01–G40 是有對應原碼候選的行為域；G41–G42 是 R5 結局／跨家族候選設計。這是可擴充的「行為域分母」，**不是完整需求條數或原子案例總數**。來源深讀後可拆分，新增必保留變更紀錄。
- 另 **4 個共同驗收關卡**：保存同步、資料數值/RNG、UI互動、真 consumer 與外部服務接線。
- 來源目錄共 **852 個 TS 檔**：遊戲端 835、server 15、shared 2。44 檔有前包局部證據，35 檔新取樣靜態讀碼，**773 檔未讀**。檔名分流可以多對多，不可相加成實作完成率。
- 56 個 resources/data JSON 列入資料目錄清冊；只有既有 season-modifiers 局部證據，其餘本盤點未讀內容。沒有 Catalog 完整性／真 consumer 證明。
- 發現 1,068 個 `*.test.ts/js/cjs` 名稱候選，混含遊戲、UI、ATM、UC‌UF。**不是 1,068 個玩法案例，也沒有執行這些測試。**
- 既交包 14 個原碼 characterization 探針仍只覆蓋11個局部議題，不能換算成14或11個完整玩法通過。本輪新增執行測試 **0**；完整玩法驗收 **0/42**。

## 閱讀狀態與驗收規則

- `UNREAD`：只有 tree／檔名與 hash，未讀語義。
- `SAMPLED_STATIC_NOT_FULL_AUDIT`：取樣過註解、宣告或函式；未完整對照母規格、caller、保存、UI、測試。
- `PRIOR_PARTIAL_EVIDENCE`：前包已引用部分內容或跑過相關純函式；**不表示整檔已驗**。
- `NOT_RUN`：本輪未執行。名稱帶 E2E、存在測試檔、檔案可匯入、規格寫 APPROVED，均不算通過。
- 每個域至少需追到：玩家入口 → 權限／資源檢查 → 規則與數值來源 → 唯一狀態提交 → 保存／重讀 → UI回饋。還要覆蓋不足／取消／失敗／重送／跨時鐘，才能討論域級驗收。
- 下列「最低驗收切面」是待拆案例的起點，不是母規格已完整抽出的驗收全集。42列全部未完整讀、未完整驗收。

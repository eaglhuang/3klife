## 2. 補全與關閉規則

1. **已定不變量先固定。** 身份、真親子、生死、出生凍結、已知單調、唯一業務事件及原版本歷史，不因新政策未採而消失。
2. **操作級門檻。** 逐一區分read／preview、reserve、attempt、commit、replay。缺取消政策的查驗不能先reserve；缺新研習profile不倒改舊plan；缺名號catalog不連坐普通完整功業。
3. **缺原件不是待批准空格。** alias、founder、LUK、星核、技能／功業／名號catalog、歷史runner等，必須取得可核原件、版本與fixture。批准不能製造缺失表格，不能用最近數字、0、均值、等機率填入。
4. **候選不混版。** 研習、風險、媒介、K、門閥、難度及季政策均保採用狀態。不同候選的機率、工時、n5及分析結果不能拼接成一個「已採」profile。
5. **重入先於新提交驗證。** 查同key/payload與canonical business event的原收據，再驗尚未提交的新revision。pending不能換key、seed、UID重開或先退款。
6. **三份證據分開。** 文件補齊記來源與差異；參數採定記decisionRevision和證據；實作／測試另記真consumer、fixtureHash、runner、ran/skip及結果。任何一份不能替另一份。

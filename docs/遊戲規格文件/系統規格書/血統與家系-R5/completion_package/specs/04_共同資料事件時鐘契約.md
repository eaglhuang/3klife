## IC01 權威層與操作級准入

每個入口先宣告 mechanicsProfile、dictionaryVersion、discoveryProfile、來源 revision 和本次操作所需 policy。讀取同一已知人物不必等待海外模式採定；完整出生不能只靠一個合法 E 值就忽略 LUK、peakType 或來源缺件。

| 類型 | 可做 | 不可做 |
|---|---|---|
| 已有且同版的固定契約 | 引用並補明 caller／adapter／fixture | 宣稱已實作或把不同 profile 數字混用 |
| 既有明示覆寫 | 在新規格說明取代範圍並保存歷史證據 | 靜默覆寫歷史原件、舊 hash 或 PASS |
| 缺原始 catalog／profile | 取得原始來源、標缺件與受阻操作 | 靠一句批准或自行猜值使之完整 |
| 未採政策 | 保留候選差異及需採欄位 | 把0、最近表值、舊版數值當預設 |
| 現行實作未核 | 列待查 codepath／runner | 將 NOT_VERIFIED 改寫成「沒有實作」 |

## IC02 身份與來源主鍵

| 邏輯概念 | 不變量／允許變更 | 入口必查 | 舊欄位對接與待補 |
|---|---|---|---|
| personUID | 生物人物終身穩定；改名、婚姻、陣營、換季均不換 UID | 本體、出生、生死、關係引用可解析 | General UID／ID 需建立映射，不以姓名合併 |
| templateVersionID | 版本化模板，不等真實人物 | 模板來源與版本 | Template_ID、同名英雄身份與版本模板需拆語意 |
| familyUID | 家系身份，不等政治勢力 | frozen family pair、來源家系與社會標籤 | Bloodline_ID、Spirit_Family_Key、姓氏不能無條件等同 |
| factionUID | 政治歸屬可因招降／失城改變 | 變更事件及有效時點 | 不回寫 biological parent edges |
| ancestorPosition | 固定祖位路徑，不是唯一人物數 | path、depth、personUID 或 unknown | 14=2+4+8；雙親風險28；上四代30 |
| factorCanonicalID | 經正式alias表識別同一因子 | kind、Max、來源版本及啟用狀態 | 舊六色GeneObject不能靠相似名字猜ID |
| sourceRevision | 機制實際消費的不可變來源版本 | 原始資料可取回、hash及字典版本一致 | 只存hash而刪來源bytes不算可回放 |
| inventoryUID | 單一物件身份及所有權鏈 | 發行／移交／裝備事件 | 虎符取得不一律代表生成新卡 |

祖位允許同一UID重複出現，UI不能去重到少於14位置，效果抽選也不能因多路重複而多算。正規來源鍵是 sourceUID+canonicalID；同凍結版本取最近深度，保留全部位置參照。unknown、合法founder、死亡歷史、被壓縮來源分型，不用「新姓／新模板」洗成無共祖。

### 身份建立與轉換的整合提案

1. 抽卡、俘虜、傭兵、AI招募、關卡投影各入口先宣告結果是「既有personUID移轉」「合法新人物」「純戰鬥投影」中的哪一種。
2. 新人物必帶來源版本及祖源完整度證據；資料缺失維持unknown，不由adapter任意生虛擬雙親。
3. 有合法來源的既有人物引用／移轉或合法新人物可進持續名冊；純關卡／競賽投影不自動進婚配及家系。
4. 原UID已死不得因同模板再出現而復活；模板新實體的合法建立政策須由來源系統明示。
5. 招降只改政治／物件持有權，不變更出生父母與已凍結family pair。
6. 所有轉換回傳來源與結果引用，經C03保存，不由UI直接修改名冊。

此分型是跨系統補全提案；各來源是否已支持上述事件仍須查真consumer。

## IC03 數值量尺與不可回寫邊界

| 層 | 意義 | 保存／計算要求 | 允許的 writer |
|---|---|---|---|
| Talent | 資質，0..100 | 每點10000 TalentTicks；顯示可有小數 | 同版出生／核准來源機制 |
| P | 出生潛力上限，P=20×Talent，0..2000能力點 | 每能力點10000 BodyTicks；上限20000000 ticks | B06提交B02候選一次凍結 |
| B | 出生本體起點，基線 .15P | 出生結果的一部分 | 同上 |
| A0 | 入學採用的童年起點版本 | 自然15歲 .20P及合法教養；需A0Revision | G04；G01引用並凍結 |
| A／畢業本體 | 選定run形成的已開發能力 | 保bodySnapshotRef及run來源 | G02選定結果的唯一提交 |
| effective projection | 年齡、職務、傷勢、裝備及合法外部效果 | 帶asOfQuarter、profile與各成分來源 | G08只計算投影，不倒扣P／A |
| General_Fame／Rank／Command_Capacity | 畢業後功業／將階／可帶兵上限 | 與本體能力分帳 | 對應功業／將階／部署owner |
| HP／stamina | 生命健康與可消耗精力 | 不可互相推導死亡 | G06與來源資源owner依正式契約 |

- Fraction 的分子分母各最多256個十進位數字，分母>0、約分、零為0/1，不是256-bit。
- 計算保精確Fraction，出生最後half-even到ticks；不能先float再回灌，不能把P1600能力點當1600ticks。
- unknown、null、缺欄、合法0分開；錯單位、NaN、Infinity、越界不能用clamp偽裝合法。
- 學院固定五維 STR/INT/LEA/POL/CHA；LUK雖在人物六維顯示，不因此加入五維培育增益。
- AI difficulty overlay、裝備加值、場景buff、名聲不回寫出生P、親本來源版或A。
- 舊欄位Stats／Talent_Stats／Prowess_Stats需由正式adapter逐欄標角色，不能僅改名。

## IC04 時鐘與真世代

| 時鐘／序列 | 用途 | 不可混用 |
|---|---|---|
| worldQuarterIndex | 年齡、孕期、健康、K到期及世界治理 | 不以UI點擊次數或training turn代替 |
| training runId＋turn | 某次36主行動進度 | 完成3個run不等3代；各run季度成本另結 |
| campaignSeasonId | 主題季身份 | 換ID不自動長年齡、重抽P或刷新NPC季度配對 |
| tournamentSeasonId | 挑戰賽兩週競賽季 | 不作主題季／世界季度 |
| real-time epoch | 每日借卡、限時池、許願、離線摘要等 | 每日不等世界季度；需各來源明確時間域 |
| parent-edge depth | 真生物親子深度 | n5=5邊6人，不由第5季或第5次培育推算 |

同版歷史profile的15歲入學、18歲成年、36回合一季度、孕期4季度由C02保留；不宣稱所有未來模式永遠只能此方案。舊「每培育回合一月／一季」不可混進此profile。

### 正常季度推進

1. 取得唯一世界時鐘revision及本次前進命令。
2. C02解析目標quarter及到期事件引用，不自行出生或殺死人物。
3. B06處理孕期、G03處理研習、B05處理K、G06處理健康死亡，依採定順序產領域結果。
4. 同一人物同一quarter各責任只結一次；AI強度與治理流程不能各自再加0.25歲。
5. C03保存時鐘與結果；遇到pending保留既有結果引用，不重跑亂數。
6. 若同季出生／死亡的先後會改玩法，順序必須在版本化timePolicy中提供；本文不自行決定優先級。

### 主題換季

S03要求採定DEC-R5-S04的advanceQuarters及到期排序。政策缺失時保留預覽缺件，不能默認0季，也不能自動全部到期。C02不得以新主題季ID重設世界時鐘。舊五年Era_Reset需明示它在何profile仍有效，不與S03同時默默重洗。

以下事件標籤是整合設計名稱，不是宣稱程式已存在。

| 婚約／孕期／出生結果 | B06 | B01–B05、G04、B05cohort、故事、名冊 | 日誌或預覽再生childUID／再扣費 |

| 童年認可／入學 | G04／G01 | run、教官快照、公開投影 | 以重開畫面刷A0或借卡次數 |
| 培育完成／選定 | G01／G02 | 本體、功業候選、故事 | 各畫面獨立畢業／拼選五維 |
| 健康／死亡 | G06 | 孕期、研習、物件、名冊、歷史 | 裝備頁、AI或戰鬥另判同一人死亡 |

| 戰鬥／治理／任務成果 | 各現行producer，待核映射 | B08、S04/S05、E03、留存 | 摘要字串直接當成果／重發資源 |

## IC06 事件外框與引用的建議格式

下列為可評審的邏輯欄位清單，尚未選定現行序列化格式、資料庫表或API路由。

| 欄位 | 必要語義 | 缺失處理 |
|---|---|---|
| businessEventId | 由業務定義的穩定事件身份，不隨重試key／schema改版變 | 不提交有副作用事件 |
| eventKind／ownerRef | 誰有權決定delta，採用哪個已驗契約 | 不能讓UI或摘要補owner |
| subjectRefs | 分型person／family／faction／inventory引用 | 缺核心引用拒絕，保可用舊狀態 |
| sourceRevisionRefs | 原資料、字典、mechanics及相關決策版本 | 不從最新版偽造舊結果 |
| clockContext | 世界quarter、適用run/主題季/競賽季及事件時點 | 不用無類型season字串猜測 |
| expectedRevision | 新提交所依據的狀態版本 | 最終切pointer時再驗／CAS |
| payloadDigest | 綁操作的完整語義輸入 | 同key不同digest拒衝突 |
| costIntent | 真成本owner、reserve/consume/refund的引用 | 無policy不猜退款 |
| resultRefs／receiptRefs | 已完成子結果與不可變結果digest | pending先查收據，不重抽 |
| knowledgeDeltaRef | 僅合法揭露owner可產生 | 普通展示無權填寫 |
| replayRef | 原rngVersion、stream、來源版的私有引用 | 不向公開view暴露seed |

## IC07 預覽 確認 提交與不確定結果

1. 預覽只讀同版公開資料，產出差異、缺件及可見成本；不耗出生RNG、不扣費、不預先建立另一份人物。
2. 涉及需要使用者選擇的領域確認，綁完整previewDigest、policy版本及目標，不以舊確認套新內容。
3. 提交先查 canonical business event 與同key/digest既有收據。已提交重送回舊結果，不能因當前revision已進而重做。
4. 同key異文、同event換key但要求重發，均不得覆舊記錄。
5. 只有未提交的新操作才驗expectedRevision及當前資格；來源變更不自動重抽。
6. 領域owner計算delta；C03寫新槽、驗checksum與核心閉包，再以已證排他/CAS/再驗證機制切pointer並保前槽。
7. 子獎勵已提交、最終季切失敗時保存receipt；恢復納入該結果一次，不用舊preview蓋回。
8. 逾時、斷網、寫入結果不明列pending；不可先退款、先成功toast、換key重送或清除reservation。
9. 取消是否可行、退款金額與已耗時處理必由該入口policy定義。C03不替所有玩法自定取消制度。
10. 回讀使用穩定status/result reference，不再次觸發producer。

## IC10 生死 退休與物件生命週期

## IC13 離線 同步與跨裝置邊界

現行離線決策要求Android/iOS原生可靠離線；Web/PC為online-first，PWA是後續階段。正式抽卡、金流與商城online-only；明確local-only模式的抽卡紀錄永不自動送server。不能把localOnly理解為「稍後上傳」。

### 文件需要補齊的adapter契約

- 每個玩法入口標為正式online-only、可本地排隊、只讀cache或local-only；不得由通用重試器替玩法決定。
- local-only與正式存檔／outbox分帳，不能把本地抽出人物混進正式婚配或排行榜而未有採定遷移政策。
- 本地出生、健康、知識與獎勵命令仍需businessEvent／receipt；網路重送不能重發。
- /sync/delta hash衝突轉/full是既有transport流程，不證明領域衝突已解。需補兩裝置的出生、季切、券消耗如何拒絕／恢復。
- 未收到ACK保pending及可查狀態；不能當成功刪outbox，也不能直接退款重送。
- Native restart後必保必要核心與pending；Web/PC cache不冒充可靠備份。
- 身份／來源／核心閉包驗證需在sync映射後仍成立。本文不變更認證、安全設定或網路機制。

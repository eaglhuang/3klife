## 如何將案例轉為可執行測試

1. **鎖來源，也鎖產品版本。** 固定來源 SHA 只證明設計依據；實跑另記產品 commit／build、adapter、儲存層、平台與時間來源。缺 implementation evidence 就維持 NOT_VERIFIED。
2. **先驗未採與缺件分支。** 案例中的完整 profile 是未來 fixture 前提，不代表目前已有核准的正式 profile。取得正式採定資料與版本前，只能驗拒絕、保留舊狀態、無扣款／無產物等可斷言部分，不得套候選數字使正例看似可跑。
3. **準備獨立 oracle。** 每案明列起始存檔、身份／家族／來源圖、權威時鐘與版本。精確值須由 fixture 採定公式推導；禁止從被測輸出反填預期。身份、資產、知識、事件帳各自比較前後差異。
4. **分離業務與傳輸身份。** 固定 businessEventId、payload digest、expectedRevision、transport key；重送同一業務事件但換 key，仍不得重複出生、發卡、增齡或發獎。相同 key 異 payload 要明確拒絕而非回放錯誤資料。
5. **把故障放在可觀察的持久化邊界。** 用隔離測試 adapter 注入 prepare、子 owner 提交、commit marker、active pointer／CAS、讀回與重入故障。記 journal／pointer／owner ledger；不以 UI toast 或記憶體值代替持久化結果。
6. **缺 policy 不是測試跳過成功。** 當因缺件不能斷言正向結果，記錄 blocked_assertions，保留 NOT_RUN；若將來有執行器，應另報該分支 BLOCKED，而非把預期拒絕當整個玩法完成。
7. **保存執行證據，不污染設計狀態。** 每次 run 另外保存時間、輸入、獨立預期、實際值、事件 trace、故障點與差異；本交付不產生虛構的 run ID、畫面證據或 PASS。

### 每案共同證據需求

- 每次未來執行須同時記錄本設計固定來源 commit、被測產品 commit／build、環境與 adapter；來源 SHA 不是產品已實作的證據。
- Fixture 包含起始存檔 digest、全部 profile／字典／RNG／catalog 版本與採定證據；獨立 oracle 由 fixture 手算或明示公式產生，不讀被測結果回填。
- 分開 businessEventId、原始 payload digest、expectedRevision 與 transport idempotency key；重送同一業務事件不得靠換 key 合法重領。
- 故障只能注入測試 adapter；不得修改玩家真存檔或呼叫真支付、真同步、真派遣。Mock／adapter 驗證不能升格為端到端產品驗收。
- 保存每一 owner 的前後值、delta、ledger、資產歸屬、reference closure、active pointer、commit marker、journal 與 RNG draw 紀錄；只看成功 toast 不足。
- 每個可寫案例至少對照首次、同 key 同 payload、同 key 異 payload、新 key 同業務事件及 stale revision 分支；依案例條件驗無操作回放或明確拒絕。
- 知識案例同時檢查畫面、排序、推薦、tooltip、錯誤、快取、存檔可見輸出與匯出；不能只驗主面板遮罩。
- 未來執行證據另存 run artifact，包含實際結果、故障點與差異。此交付中的 status 一律 NOT_RUN，不以文稿完整或靜態檢查改成 PASS。

## 待決分帳與斷言能力

- **已可斷言的不變量**：例如生物身份不能復活、已凍結胎次不能回灌、同一業務事件不可重領、無必要版本不能假回放、缺件不得靜默填 0。
- **缺件拒絕 oracle**：欠採定政策或資料版本時，只斷言明確拒絕／待補與指定 owner 不變，不擅自指定退款率、季長、孕期長度、容量策略或新數值。
- **條件正例 oracle**：題目中的「已採 profile」是未來可執行的假設 fixture；需附採定來源才能跑。未取得之前，條件正例仍為 NOT_RUN，而不是已採政策。
- **設計橋接要求**：例如跨 owner pending、鏡像隔離及正式同步來源防護，是本包提出的接口驗收需求。來源尚未寫明完整實作時，不冒充既有母規格已拍板。
- **決策 ID 與缺件描述**：沿用來源 DEC-R5-*；中文缺件文字不是新編決策 ID。R5F-S07／R5F-S08 是功能卡，不能與 DEC-R5-S07／DEC-R5-S08 混為一談。
- **引用角色**：normative 為直接 R5 規則；mother_boundary 為母玩法邊界；mother_conflict 為待裁定衝突；design_bridge 表示由該來源導出的本包接口要求，不能據此宣稱產品已有實作。

#### XGAME-001｜孕婦軍事派遣與受孕鎖一致

- **狀態**：NOT_RUN；實作 NOT_VERIFIED；產品驗收 NOT_ASSESSED。
- **Given**：
  - 人物 mother-01 已有 confirmed conception-01，worldQuarterIndex=q，dueQuarter=q+Δpregnancy；派遣任務 job-war 為軍事任務。
  - pregnancyOccupancyPolicy 與時鐘映射故意缺失，母規格同時存在3治理月與4回合/1年描述。

  - 由戰場編組與離線派遣兩個入口各嘗試指派 mother-01，再用同一請求重送。

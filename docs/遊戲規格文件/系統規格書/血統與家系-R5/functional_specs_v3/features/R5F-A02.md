## 目的與非目標

提供敵方／失城家族從祖地重新取得立足點的有成本流程：**蓄勢 → 集結 → 部署 → 攻城或內應 → 成敗成本 → 首城後恢復正常勢力**。每階段必有可理解的前兆及可反制機會，不能突然免費改城主。

非目標：不定時無預警奪城，不憑高 INT 直接成功，不給無限民兵、不讓出山軍隊持續祖地免傷；不自定動員季度、資源上限、內應成功率、損耗／冷卻／重試次數或動員 cap，不接管正常戰鬥演算法，也不替代 S04 季終規則。

## 輸入與輸出

輸入：refugeId、合法在世領袖與招募名冊、地方聯繫／情報／內應 evidence、目標城與城防 revision、已採 mobilization/time/cost/difficulty/counterplay policies、可用資源 ledger、stage events、attemptId/digest/expectedRevision。

輸出：MobilizationPlan、各階段可見前兆與可反制行動窗口、部署實體 refs、成本收據、攻城／內應結果、失敗後存續狀態或首城重建事件。任何結果均需可解釋來源；不直接輸出「改城主成功」而缺交戰／內應 evidence。

## 建議 schema 與不變量

- `ResurgencePlan`: planId、familyUID、refugeId、leaderUID、targetCityRef、sourceRevision、mobilizationPolicyRef、difficultyPolicyRef、plannedStages、resourceIntentRefs、state、decisionRevisionRefs。
- `MobilizationStage`: stageEventId、planId、stageType、startedAtQuarter、completionConditionRef、warningEventRefs、counterplayWindowRef、committedCostRefs、deploymentRefs、status。
- `WarningEvent`: warningId、stageEventId、audienceProjectionRef、publicCueKind、evidenceRef、availableCounterplayRefs、timingPolicyRef。前兆需在其反制仍可影響結果的時段出現，不能事後補訊息當已預警。
- `ResurgenceAttempt`: attemptId、canonicalBusinessKey、planId、method=assault/infiltration、targetRevision、preconditionEvidenceRefs、costPolicyRef、counterActionRefs、rngVersion/seedRef、payloadDigest、resultRef、commitState。
- `ResurgenceOutcome`: resultId、attemptId、success/failure/aborted、battleOrSchemeEvidenceRef、costReceiptRefs、casualtyRefs、cityOwnershipEventRef、postOutcomeStateRef、normalFactionRef。

所有成本與時長指向已採 policy；不在 schema 放任意預設數字。validation 不通過不消耗資源／季度／RNG；合法 attempt 失敗依已採成本扣除，不能因沒奪城即免費退款。是否可取消、退多少、何時 cooldown 另待明示。

## 流程與狀態

1. **蓄勢 `preparing`**：驗在世領袖、地方人脈、資源與來源，按政策形成動員意圖；有地方活動前兆。可反制候選為招撫、談判、情報或地方治理，具體可用條件及代價待採。
2. **集結 `assembling`**：合法募兵／串聯事件逐步形成名冊和補給。提供可見活動區域與仍有效的反制窗口；攔截隊伍、切補給、安撫地方盟友的作用由已採政策判定。
3. **部署 `deployed`**：把具體部隊／營地／補給放到可交戰地圖，受正常風險。不能同時待在祖地獲不可攻保護；部署失敗不憑空留兵。
4. **攻城或內應 `attemptPending`**：玩家／AI 依合法條件選方法。攻城需真部署與城防；內應需情報、內應資源及守備漏洞 evidence。高 INT 只是已採公式中可解釋的一項，不是自動改城權限。
5. **成敗 `resolved`**：唯一結算結果與成本，記前兆及已採反制。失敗按 policy 留損耗、倖存者和重試／冷卻狀態；不得立即換 key 無限重試。
6. **首城 `reestablished`**：成功且合法取得第一城後，對外恢復普通政治勢力規則、外交與戰爭；祖地歷史保留但出山軍隊不繼續免傷。若未取得首城，不能只改狀態成正常強國或免費換下一座。

各階段的時間、成本、可見性、反制結果與接戰順序都需 policy。哪種情報使敵方看見多少內容可以不同，但不能完全無前兆且沒有任何實際反制機會。政策若無法同時滿足隱藏資訊與可反制，該方案不具備提交條件。

## 邊界 錯誤與恢復

- 無活領袖、無人脈／資源或內應證據：VALIDATION_ERROR/SOURCE_INCOMPLETE，無效動員不扣、不抽、不生成兵。
- 領袖在集結中死亡、內應失效、目標城易主或補給被截：依已採中止／轉移政策處理；未定時保 plan 和 pending 事實，不自換領袖／目標或隱性免成本。
- 多計畫爭同人同資源：檢查 reservation 與 revision，一人／資源不得在兩次動員各全額使用。
- 預警直到城主已改才出現：拒為合法流程完成，保存缺陷證據，不能以事後戰報補足事前反制。
- pending 先查 attempt marker；已 commit 回原結果，未提交才驗新 revision。不得因攻城輸了、磁碟逾時或反制發生而換 seed 重擲。
- 城主更新與成本結果必有可恢復一致性；若跨 owner 不能原子提交，需 journal 明示各步已提交狀態並保持唯一 business key，未核前不得聲稱已有原子保證。

## 保存 遷移與重入

持久保存 plan、階段時間、已發預警、反制事件、資源／人員 reservation、部署、attempt 結果、傷亡及城主事件。復原不能忘掉已遭攔截而重新滿兵。跨季若計畫未完成，交 S01/S03 預覽列明，時鐘或成本處理未採不得強制完成／清除。

legacy 叛亂／戰鬥事件保原結果，不追溯假造曾有前兆，也不自加新扣費。新政策僅依明示遷移作用未來 attempt，原死者不復活。冷存不得丟失防重試鍵與成敗成本；容量超標不刪這些核心事件。新 seed 只可用於已採政策允許且有新成本的新業務 attempt，不能是同一次失敗的重送。

## UI 與可觀察結果

祖地頁顯各階段、已支付／待支付成本、已部署名冊與可取消狀態。守方看到可理解前兆、可行反制及剩餘窗口，不能只收到「城已被奪」；不強迫全知精確敵軍 P/LUK。結果頁連回攻城／內應事實、反制成效、損耗及重試資格。首城成功清楚標「恢復一般勢力規則」，地圖部署不帶祖地不可攻標誌。

## 驗收案例

以下全部 `[NOT_RUN]`；任何數值只引用未來已採 fixture，不在此定值。

- **R5F-A02-P 正例**：Given 合法 refuge、在世領袖、足夠已採動員資源與有效內應 evidence；When 依序完成蓄勢、集結、部署並嘗試內應；Then 每階段有及時前兆和可用反制，結果與成本一次保存，成功取得首城才恢復正常 faction 規則。
- **R5F-A02-N 反例**：Given 領袖 INT 高但無部署、人脈或內應資源；When 請求直接奪城；Then 拒絕，不改城主、不生民兵、不以高 INT 自動成功。
- **R5F-A02-T01 守方反制**：Given 集結已預警且補給可被攔截；When 守方在窗口內合法切斷補給；Then 接戰輸入含該反制結果，按已採 policy 降低能力／中止，不能忽略仍滿兵免費攻城。
- **R5F-A02-T02 合法失敗成本**：Given 所有前置合法且攻城 attempt a 結果失敗；When 結算；Then 扣已採失敗成本並保存傷亡／倖存者，城主不變；不因失敗退款或立即重抽。
- **R5F-A02-T03 無效成本邊界**：Given 資源不足／來源缺件；When 驗證 a；Then 在 attempt 前拒絕，季度、資源與 RNG draw 不增。
- **R5F-A02-T04 重入**：Given attempt a 已提交但回應遺失；When 同 key/digest 或新 transport key 重送同 business attempt；Then 回原成敗與成本收據，不多扣、不多生兵、不再改城主。
- **R5F-A02-T05 免傷反例**：Given 部隊已部署或已奪首城；When 遭正常攻擊；Then 正常受傷／死亡與補給損耗，不得以 refugeId 抹去傷害或瞬間退回無敵空間。
- **R5F-A02-T06 前兆失敗**：Given 城主已被更新後才記第一個 warning；When 驗流程；Then 前兆／可反制驗收 FAIL，不把事後戰報算通過。
- **R5F-A02-T07 中途死亡**：Given 領袖在集結後死亡且替換 policy 缺失；When 要進部署；Then 保死亡終態並阻擋，不能復活或無成本換同名領袖。
- **R5F-A02-T08 保存失敗**：Given 成本與結果處於不確定提交狀態；When 恢復；Then 查 journal/marker，維持 pending 至確認，不另建 attempt 或退款。
- **R5F-A02-T09 存讀／跨季**：Given 部隊已被攔截、有傷亡與未完成 attempt；When 讀檔或換季預覽；Then 傷亡、預警、反制與原 attemptId 保留，未採歷法時不跳到免費成功。
- **R5F-A02-T10 併發資源**：Given 同一領袖和同批民兵已被 plan a 預留；When plan b 同時請求全額動員；Then 拒衝突，不複製人員或資源。

## 待決門檻

DEC-R5-S05 須定每階段時長／成本／前兆／反制、內應資格及成功失敗機制、取消退款、首城轉普通勢力、再次出山頻率；DEC-R5-S07 須定動員人數、兵力與難度取捨。未採前不寫任意 cap、概率、季度數或損耗率。先驗同資源下有不同策略及真反制，再定數字；全域文件先行、真 consumer、故障恢復與正式准入仍未核。

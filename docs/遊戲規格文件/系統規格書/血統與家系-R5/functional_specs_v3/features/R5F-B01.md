# R5F-B01 祖位與來源正規化

本規格供出生、禁親與傳承流程評審。R5F-B01 是文件功能 ID，不是正式 ATM 工單。全域「全部工作文件、功能清單及範圍內逐功能規格先完成，再開始程式」閘門仍有效；真 consumer、正式准入與同版 profile 未核，因此 implementationReady=false。

## 目的與非目標

將穩定人物 UID、三代生物祖位、因子版本與 alias 轉為可追溯的正規輸入，讓同一祖先重複出現在族譜時保留位置，卻不增加效果或抽選次數。

本功能不選配偶、不抽出生結果、不計健康、不取得新因子，也不因正規化修改既有人物。14 是子代上三代的 2+4+8 個祖位；風險輸入是雙親各 14，共 28 個位置；30 是子代上四代位置。三者不是可互換的陣列長度，更不是各有那麼多個唯一人物。

## 輸入與輸出

輸入必有 child context 或待配對的兩個 parentUID、可沿父母邊讀取的人物節點、已鎖定 sourceRevision 引用、dictionaryVersion、mechanicsProfile 與 completeness 證據。親子邊是生物關係；姓名、陣營、收養、師徒不能補邊。合法 founder 必有版本化來源身分，不能把普通缺資料人物改標 founder 來通過。

輸出包括 carrierPositions[14]、riskPositionsByParent[2][14]、各路徑是否完整、按 UID 的最近距離視圖、去 alias 後的來源條目、缺件清單及 sourceDigest。位置可重複 UID，缺位置有顯式 unknown 狀態，不能刪掉使陣列看起來完整。來源正規化不刪原始 alias／原頁來源歷史。

### 建議 schema

以下是規格介面提案，不是現行程式或已存在 schema。

| 結構 | 欄位與型別 | 約束 |
| --- | --- | --- |
| AncestorPosition | path:string、depth:1..3、personUID:UID 或 unknown、evidenceRef | path 代表固定祖位；同 UID 多路仍保存 |
| NormalizedSource | sourceUID、canonicalID、sourceRevision、level:int、Max:int、nearestDepth、positionRefs[] | 唯一鍵 sourceUID+canonicalID；同一凍結版本內取最近深度，不先抽 RNG |
| NormalizationResult | profileHash、dictionaryVersion、carrierPositions、riskPositionsByParent、sources、completeness、missingRefs、sourceDigest | digest 只驗資料一致性，不能替代來源實體 |

level 必在 1..字典 Max；未知來源不轉 level0。不同 canonicalID 即使同色或同中文名稱亦不得合併。同 sourceUID+canonicalID 若指向互相矛盾的版本，回來源衝突而非取較高星。跨來源同 ID 的「最高星、最淺、UID」競勝在 B03 入池後才做，本功能不能提前刪掉尚有獨立入池資格的來源。

## 處理流程與邊界

1. 驗 C01 的 UID、版本與字典映射；未知 alias 不猜新 ID。
2. 以固定父／母路徑展開子代三代位置，同時為配對雙方各展開三代風險窗。偵測自己成為父母與有向循環；重複祖先不是循環。
3. 保留所有位置、路徑與 known/unknown。計算每個 UID 在各窗的最近深度。
4. 依鎖定來源版本讀因子，正規化 alias，產生 sourceUID+canonicalID 唯一來源及所有位置引用。
5. 輸出完整度與缺件，供 consumer 決定哪一能力可用。H 要求完整的來源清單；判「無共祖外婚」要求風險窗完整。只有畫面能展示已有部分，不等算法可忽略缺件。

來源深度是結構事實；H 深度權重 1/.5/.25 與 carrier 入池機率 1/.5/.25 雖同數值，屬 B02／B03 的不同操作，不在此功能相乘。風險窗第四代相對子代的祖先不得變成 P/carrier 的第15個來源。

## 錯誤與恢復

- SOURCE_INCOMPLETE：缺父母／來源版本／字典映射；輸出可公開的缺件類別，禁止「無共祖」結論。
- VALIDATION_ERROR：親子循環、自身父母、負星或超 Max；保原資料，不自動修祖譜。
- REVISION_CONFLICT：要求版本與取得版本不同；重讀並重新預覽，不默選最新版。
- 本功能不耗 RNG、回合或資源。缺件補齊後以新明示 revision 重做；曾被下游婚約鎖定的來源不被新結果覆寫。

## 保存與遷移

輸出可作帶版本的可重建快取；正式出生 witness 由 B06/C03 保存必要來源與引用閉包。alias 遷移保留原字典版及映射證據；未能映射的 legacy 保可讀，不以現在 A 或裝備推回出生因子。快取丟失可依同一來源重建，不抽 RNG。不可把 core 祖譜換成只留最高兩因子的摘要。

## UI 契約

祖譜可標「相同人物出現在多個祖位」，不能顯示為兩個真人；風險視圖明示「雙親三代，共28位置」及資料缺口。未知因子的 ID／星數不經 tooltip、匯出或錯誤訊息洩漏；已知欄位不因重新正規化而藏回去。

### 共通重入順序

讀取既有提交紀錄先於新命令准入：同key與同payload已提交，或同businessEvent已有一致結果，先返回原結果，即使請求帶舊expectedRevision也不重新結算；同key異payload仍拒衝突。只有確定沒有既有提交的新操作才驗expectedRevision、資源與資格。唯讀功能不因此取得寫入權，pending先查commit marker，不換seed或key刷結果。

# R5F-B04 親緣風險與 m-only

本規格將配對合法性、多樣性 D、跨代履歷 h、當胎健康風險與指定 m 純化分開。R5F-B04 僅為文件功能 ID，不是正式 ATM 工單。全域文件先行閘門尚未解除，相關 DEC、真 consumer 與正常准入未核，implementationReady=false。

## 目的 非目標與責任

以完整真族譜檢查婚配是否合法，提供有來源的親緣與風險預覽；明確政策可產生 m-only 候選，不能同時免費保星。本功能不抽／提交健康結果、不修補祖譜、不回復已存在衰薄、不改本人 P/A，不以姓名、收養或陣營推測生物關係。

owner 是親緣與風險政策檢核能力；B01 提供祖譜，B02 消費純化對 m 的結果，B06 在出生交易中協調健康流與保存，健康長期投影另由 G06/G08 負責。現行 consumer 為 NOT_RECHECKED，實際工單 owner 待正式指派。

## 來源及候選地位

[R4 工程](../../publication_candidate/11_R4歷史基線_工程驗收.md) §20–21、§33–34（R4E03、E08–14）、§38–40（M01、M09–15）；[R4 玩法](../../publication_candidate/10_R4歷史基線_玩法.md) §5–6；[R5 模組02](../../publication_candidate/02_出生_血統與聯姻.md)「聯姻 保留席位與近親履歷」。衝突與決策見 [模組08](../../publication_candidate/08_決策_衝突與擴充邊界.md) C05、DEC-R4-03；證據層級見 [模組09](../../publication_candidate/09_證據來源與驗收索引.md)。

12/20/30%及外婚每代減1仍是 R4 候選，不因文件有算例就升為正式值。G3的12/20/32/48%、外胎1%、h上限10未採。原合成族譜外胎風險為null，只表示未定，不能解讀零風險。

## 流程與具體規則

1. 先驗 UID／親子無環／完整度，再拒自配、直系、同父或同母手足；R4合成見證另拒共同祖先任一側距離≤1的叔姪等不合法關係。正式禁親表須與同profile一致，不能只禁止名字相同。
2. 在雙親各三代風險窗計共同 UID，保最近距離及原路徑。重複位置同 UID 不多扣 D。
3. 在明示候選中，普通表親兩個唯一(2,2)共祖各扣5，D20→10；雙重表親四個各扣5，D=max(0,20−20)=0。其他距離完整扣分表未在本節替代，未核同版表不能猜。
4. 選定的 h 候選僅在真正新出生一代計算：I取max(h父,h母)+1；完整 O取max(0,max(h父,h母)−1)。未知來源不是O，未知h不是0。等十年不減h；只讀乾淨一親不合法。
5. 當胎健康風險另讀riskPolicy。I的h1/2/≥3候選12/20/30%；O當胎風險另定，不把保留h直接代成風險，也不因h下降治癒舊衰薄。
6. 純化只可作用合法14位置P來源窗中已指定ID的m，逐ID cap1；成功率、增量、費用與資格需DEC-R4-03。超出P窗的共祖即使造成風險也不能借來加m。保ID、傳星與啟用均不因此改變。

條件算例：m1=.6成功+.20、排序未變且未撞cap時H+8、單項P+160能力點。成功率.25時，五維合計期望+40能力點，不是每維+40。m1已1則增益0；若排序變動須重算兩個不同ID的H，不能沿用+160。

## 錯誤 恢復與保存

缺祖譜回SOURCE_INCOMPLETE；非法親緣回VALIDATION_ERROR並保公開原因；缺risk/h/純化policy回PROFILE_UNSUPPORTED。不能為讓NPC有配偶就補「乾淨來源」、取消禁親或套1%預設。預覽無RNG、無成本；確認時由B06重新核revision，衝突須重讀，不默換配偶。

保存風險路徑、policy版、父母h引用、計算結果及出生witness；真父母／生死歷史是核心，不放可丟日誌。legacy固定風險與新h政策不能疊罰；新h不得倒算並重抽已生P／健康。取消或儲存失敗保原關係，出生pending恢復讀原交易結果。

## UI

首代就顯禁婚原因、已知親緣、資料不完整、風險與成本，不等G3教學才告知。並列D、h及當胎risk，禁止用一個「血統純度」數字混代。可以展示候選算例，但標未採且不可提交。隱藏因子不能由差異化錯誤或風險tooltip反解。

## 精確依賴能力

- B01：雙親風險窗、唯一UID／最近距離、完整度，以及與14位置P窗分離的來源資格。
- C01：UID、Fraction與profile版本；C02只供成年資格和事件時點，h不按等待時間回復。
- B02/B06：只接受有同版policy及來源的m／risk結果，出生單次提交；不需要K數值或研習規則。
- DEC-R4-03：h時鐘／合成、完整風險表、純化資格／率／增量／費用。此決策不妨礙先寫合法性規格，卻阻未定分支正式結算。

### 共通重入順序

讀取既有提交紀錄先於新命令准入：同key與同payload已提交，或同businessEvent已有一致結果，先返回原結果，即使請求帶舊expectedRevision也不重新結算；同key異payload仍拒衝突。只有確定沒有既有提交的新操作才驗expectedRevision、資源與資格。唯讀功能不因此取得寫入權，pending先查commit marker，不換seed或key刷結果。

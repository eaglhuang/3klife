# R5F-B05 K 樣本與候選比較

本規格先保所有出生歸戶與到期紀錄，再以明示版本比較K公式。R5F-B05是文件功能索引，不是正式ATM工單；全域文件先行閘門、真consumer核對及正式准入未完成，implementationReady=false。

## 目的 非目標與 owner

K記錄配對家族後代的遊戲任務達標情況，不是人類遺傳品質評價。出生時凍結familyUID pair，改姓、收養、換家傳、分家、換季不能洗分母。owner為家族cohort／評估帳；B06提供出生事件，C02提供單調世界季度，C03保存一次結果。實際consumer尚未核對。

本功能不直接加P、傳星、太傅效率或解鎖資格；不據低K減少NPC兒童教育資源；不把社交R或某因子lineageRoot當家族身份。收益作用面未採前，只存樣本與提供明示候選比較。

## 樣本流程

1. 出生交易成功時建立唯一cohort；即使人物不是玩家親屬、已嫁敵家或後來死亡，也不能漏登。
2. 凍結家族pair與評估政策／到期季度。若未來採systemUID，需版本化分支映射，不改歷史歸戶。
3. 每世界季度檢查到期；未到期不計失敗。死亡者在原到期日按規則記notQualified並保存死亡原因，不提早移出分母。
4. 以同一任務合格定義產生一次結果。任何修正新增outcomeRevision與理由，不悄改已凍結婚約的EP來源。
5. 先取得全歷史帳，再依明示窗口選比較視圖。若採定長窗，保UID、排序、評估版與排除理由；不能只存8個布林而丟事件來源。

窗口按出生年或評估年、時間衰減asOf與同季排序都要policy指定。全cohort保留不等比較必用終生率，但任何窗口不能按結果好壞選擇樣本。

## 可比較公式與反例

以下皆文件候選，非R5產品預設。

| 比較案 | 精確定義 | 已知界線 |
| --- | --- | --- |
| R4舊收縮案 | K=20(g+2)/(n+8) | 全好達15至少n16、達18至少n52；不可稱小族只是較慢 |
| Q06 | c=min(1,n/4)，p=(g+1)/(n+2)，effect=base×c×p | 4/4為5/6base，只有c滿 |
| G3比較 | q=min(1,max(0,p−.5)/.3)；僅比較時假設c×q | 最終K組合及rounding尚未採，不直接寫產品 |

Q06在n/g=2/2、4/4、8/6、8/7、6/5分別.375、5/6、.7、.8、.75；假設c×G3比較值為5/12、1、2/3、1、5/6。g6/n8不是滿額，g5/n6也不是1。

保留反例：20孩16好拆1/10/20組生物父母，固定family pair舊收縮值都90/7；10孩只有最早2好，全分母40/9而截前2得8。100舊好+4新敗與反向的終生p為101/106和5/106，即使近期c滿也不代表近期品質。若窗口8仍含4舊敗+4新好，G3飽和品質0；再替換2人到g6/n8才2/3，再多1人到g7/n8才1。

## 錯誤 保存與遷移

缺家族映射／出生來源回SOURCE_INCOMPLETE；未採評估、窗口、作用面回PROFILE_UNSUPPORTED；同鍵異payload回IDEMPOTENCY_CONFLICT。無效評估不消耗資源，不用失敗或0補空。存檔失敗保pending，恢復先查commit marker；不得新建第二cohort。

cohort、到期結果、原因、版本與歸戶映射屬核心引用，不能因NPC不活躍或跨季而刪。已有舊K總數但缺逐童來源不得捏造n/g明細；保legacy讀取及明示不可遷移欄。新公式可重算新視圖，不回改舊出生／獎勵。過繼影響現在社會家庭，但原frozenFamilyPair不改。

## UI

分列總出生、未到期、已評估、合格／未合格及原因；避免「優良血統」等誤導詞。候選比較顯公式名稱、窗口及asOf，不把「信心滿」寫「全部效果滿」。尚無正式收益時不可畫可用折扣／效率按鈕。歷史改評需可見修訂原因，不顯私有隱藏因子。

## 精確依賴能力

- C01：穩定familyUID與別名映射；不依賴factor root。
- C02：世界季度單調與到期比較，不包含主題換季跳時。只有執行跨季時間變更才須DEC-R5-S04。
- C03：出生／評估業務鍵去重、revision與保存閉包。
- B06：實際已提交birthUID、兩親婚約時family pair；不由預覽建立樣本。
- DEC-R4-01：合格定義、評估日、窗口、冷啟動、成本與收益作用面。B08若要消費K成分另須已採EP總式，不在本規格預先授權。

### 共通重入順序

讀取既有提交紀錄先於新命令准入：同key與同payload已提交，或同businessEvent已有一致結果，先返回原結果，即使請求帶舊expectedRevision也不重新結算；同key異payload仍拒衝突。只有確定沒有既有提交的新操作才驗expectedRevision、資源與資格。唯讀功能不因此取得寫入權，pending先查commit marker，不換seed或key刷結果。

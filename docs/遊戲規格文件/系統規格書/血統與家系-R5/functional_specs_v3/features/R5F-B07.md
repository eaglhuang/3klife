# R5F-B07 因子效果與啟用投影

本規格將持有、發現、啟用及可傳四態分帳，列出效果 consumer 應消費的同版字典。R5F-B07是文件索引，不是正式ATM工單；全域文件先行閘門、真consumer與准入未核，implementationReady=false。

## 目的 非目標與 owner

讓因子真實持有與玩家是否知道、目前是否生效、未來是否可傳是四個不同問題。owner為因子狀態／效果投影能力；出生held由B03/B06產生，功業／媒介／研習提交合法來源變更，技能／任務／健康consumer只讀對應效果，不各自重寫P。

不在解鎖圖鑑時取得因子，不因持有就自動啟用，不把終身新增額度當目前空槽數，也不增加未列字典的金／紫因子。實際程式與業務owner待核，本文未宣稱產品已接線。

## 輸入 輸出與建議 schema

以下為規格介面提案，非現行程式。規格以held對應原FactorInstance的carrier概念，不把兩個欄位視為兩次持有。

| 結構 | 必要欄位 | 約束 |
| --- | --- | --- |
| FactorDefinition | canonicalID、kind、Max_Level、relevance、activationTrigger、effect、transmission、dictionaryVersion | ID／kind不隨顏色交換；未知ID拒新效果 |
| FactorInstance | canonicalID、level:int1..Max、held、discovered、active、transmissible、originEventId、sourceRevision | 四態獨立；不能單一enabled代替 |
| LifetimeAcquisitionLedger | personUID、newAcquisitionEvents[]、count、businessKeys | 非出生的新ID取得最多2，移除／置換／換季不清零 |

| EffectProjection | asOfQuarter、role/taskContext、effectiveFactors、externalModifiers、eligibilitySignals、knowledgeView | 唯讀；不改P/B/A或parentUID |

輸入包括持有清單、字典、合法事件證據、已知權限、任務／角色／時間上下文與來源版本。輸出是四態視圖、合法效果和下一版來源意圖。取得命令先查業務去重，再檢held槽與終身新增帳；同ID升星不當新ID取得，但不能靠刪後重得重置額度。

## 四態及兩種上限

- held：人物實際攜帶ID，出生最多6；後續取得也不得超過6。
- discovered：玩家合法知道該人物此ID，不等全局圖鑑可見就知道所有人；已知資訊依U01單調保存。
- active：已完成該字典trigger且在合法效果情境下使用，不必然等已知。公開端仍由knowledge投影，不因效果資料內部存在就全揭。
- transmissible：字典及實例版本允許作未來來源；不必先active才可傳。真持有、來源合法與婚約已知要求仍分別驗證。
- held6是同時容量；終身新增2是出生後新取得額度。兩者都需通過。held5但終身新增已2不可新增第六ID；held6且新增0仍不能塞第七個。置換不能清終身帳。

## 流程 錯誤與恢復

1. 驗字典與來源版本，讀合法held及終身帳；先回已提交的同業務事件，再對新提交驗revision。
2. 驗事件取得／啟用條件，區分同ID升星與新ID取得。新取得超任一cap即拒，不能默換最低星。
3. 來源變更依C03一次保存；新取得不自動active，合法trigger另計。只有指定效果consumer讀取active及情境。
4. 投影外部效果／學習資格。技能折扣讀held，避免「先學才active、先active才可折扣」循環。
5. 更新futureTransmissionSnapshot只影響之後婚約，不回改本人P／既有胎次。

無效ID／Max／trigger回VALIDATION_ERROR或PROFILE_UNSUPPORTED；缺來源SOURCE_INCOMPLETE；槽滿／額度滿STATE_CONFLICT，均零消耗。合法事件失敗依該事件政策記帳，不能B07自行退款重骰。儲存不確定回RESULT_PENDING，先查marker；錯誤不洩隱藏ID。

## 保存 遷移與 UI

四態、事件來源、終身額度、健康credit及來源revision為核心；不能只存目前active清單而遺失held或歷史新增。R3紅適性／粉體魄是palette，舊配色保legacy，不交換kind。未知舊因子不能自動映射成新Max5；已知資訊取合法聯集，不全揭。跨季保held、已知、終身額度與已啟用事件，不年度重送LEGACY線索。

UI分列「持有」「已發現」「啟用條件」「可供未來傳承」，隱藏資訊以合法遮罩呈現。空槽不等還有終身取得額度，應同時顯示兩個限制；未採新因子不可呈可解鎖按鈕。

## 精確依賴能力

- C01/C03/C05：字典／ID／版本、去重提交與核心保存；不依賴K或新風險數值。
- B03/B06：已提交出生held與來源；只是輸入契約，不能為取得一個新ID重跑出生。
- B08/B09/G03：各自合法功業／媒介／研習變更事件；本功能集中驗cap，不能讓渠道各有2個額度。
- G05：技能見習／學習與TP折扣consumer；G06/G08：健康／年齡效果consumer；C02：季度／世界年邊界。
- U01：公開知識投影與已知單調；不因全局教學解鎖免費取得。

本功能無新增數值DEC；需要的新字典或新獎勵不在範圍，另依DEC-R5-S10／相關資源決策，不能自動採定。

### 共通重入順序

讀取既有提交紀錄先於新命令准入：同key與同payload已提交，或同businessEvent已有一致結果，先返回原結果，即使請求帶舊expectedRevision也不重新結算；同key異payload仍拒衝突。只有確定沒有既有提交的新操作才驗expectedRevision、資源與資格。唯讀功能不因此取得寫入權，pending先查commit marker，不換seed或key刷結果。

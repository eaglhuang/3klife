# R5F-B08 功業事件與 EP 來源

本規格將canonical功業事件、固定獎勵、有限升星形成及EP來源修訂分開。R5F-B08不是正式ATM工單；全部文件與逐功能規格完成前不得寫程式，DEC與真consumer／准入未核，implementationReady=false。

## 目的 非目標與 owner

同一事蹟不能換名稱／rewardGroup領雙份；合法功業對本人來源的後天改變只影響之後婚約，不回改本人P或已鎖胎次。owner為功業事件、來源帳及canonical名號資格事件判定，C03負責原子保存，B07驗held／字典上限，B02消費完整EP來源。G02只提供已凍結的培育候選ΣC／EP及來源證據，不判最終名號或發券；B08依完整同版名號／功業catalog與功業帳判資格，U02是唯一券帳發放owner。

不重評歷史六人MD的G級，不從敘事標題猜功業資格，不把社交R或K直接加EP，不把G1兩段演出當兩次各5.91%升星，不授權發券／加星的新入口。現行consumer尚未核對。

## 來源與數值地位

[R4 工程](../../publication_candidate/11_R4歷史基線_工程驗收.md) §2（原第3頁名號候選及另需catalog功業）、§4–7、§18–19、R3T16–17/T39及M05–10；[R4 玩法](../../publication_candidate/10_R4歷史基線_玩法.md) §7–8、§13；[R5 模組02](../../publication_candidate/02_出生_血統與聯姻.md)「功業回流與星級變化」；[模組08](../../publication_candidate/08_決策_衝突與擴充邊界.md) C08、DEC-R4-06／09；[模組09](../../publication_candidate/09_證據來源與驗收索引.md) 原歷史資料保留界線。

工程§19解析控制組為同一Max5 ID每代必保留，出生T→形成F→研習G→next source，每代兩次合格形成機會、每次.03且首次成功停，q=1−.97²=.0591。這是有限形成的同profile基線，不是所有人自動拿滿兩次，也不證含媒介／配偶供給／死亡的族群平衡。

## 處理流程

1. 先依canonicalDeedId/person/scope與既有結果做業務去重。已提交同key同payload回原結果；相同業務事件換key亦不重領；異payload明確衝突。只有新提交驗expectedRevision。
2. 核catalog資格、證據與rewardPolicy。證據未知不當合格；固定歷史事蹟依原importIdentity保留，不改G級或再匯入一次。
3. 記一般功業來源與已核固定獎勵；如果此事件有形成資格，依明定scope讀形成帳。每事件至多一主機會，不能把同故事拆成多個rewardGroup再抽。
4. 形成尚未成功且有效機會未達2才抽一次.03。U<.03成功；成功有效只+1且立即停止後續形成；失敗耗該次資格，兩次失敗後停止。target必合法held且未Max，若profile缺target選法／scope／Max處理則拒該分支，不猜。
5. 不重抽本人P，不把形成有效+1與媒介跨多星混同。新星與功業資格更新futureTransmissionSnapshot；已凍結婚約仍讀舊revision。
6. 普通功業事件內的已定獎勵意圖、形成結果與來源revision以同一事件提交；任何該事件必要子欄缺資料不先發可重領的部分獎勵。涉及券時，提交耐久授券來源／意圖後交U02以同一來源事件去重發放，收到U02回執才標券已到帳；恢復重送同來源，不另造獎勵key。

總EP的R退出後成分、權重、資格與重複控制待DEC-R4-09。可以保存真功業事實與原來源；不可將未知EP總式填舊五項，或先顯95／100作正式遺傳值。B02只可對外部給定E做comparisonOnly插值。

### 名號資格分支

名號資格是依賴既有證據的獨立業務事件，不是普通功業提交的強制子欄。先讀G02已凍候選ΣC／EP及其profile、人物與候選身份，再讀B08已提交功業帳，依完整同版名號／功業catalog逐項判定數值、必要功業及受獎scope。候選達標而缺必要功業時，資格不成立；證據未知或版本不一致不能當達標。

catalog缺失或未採時，只阻名號資格與其派生授券入口，返回PROFILE_UNSUPPORTED，不默套工程§2的舊ΣC／EP門檻、舊功業或券數。普通已具完整catalog及policy的功業事件仍可依自身規格記帳，不因名號catalog缺失而整批阻擋。這是責任分流，不允把同一普通功業事件內未定獎勵分拆來先領。

資格成立後，B08保存唯一canonicalTitleId／awardScope的qualificationEventId與所用證據引用。換request key、重讀、重播成材或改名號展示名都返回同一資格結果，不產生新的可領來源。U02依該qualificationEventId及已採獎勵policy唯一發券；B08不發券，G02不發名號或券。名號本身的實際呈現／領取狀態需與同版catalog和consumer對應，不從資格事件推定產品已完成展示。

## 邊界 錯誤與恢復

- 形成兩次是合格機會上限，不是每個ID各送兩次的默認授權。原冊解析scope與完整產品全人／各ID配額關係未充分列出，需同profilecatalog明確，不能靠更換target重置額度。
- 形成已成功，後續功業可依其合法固定獎勵記錄，但不得再形成+1。兩次都失敗不能第三抽；q=.0591只作「兩次至少成功一次」解析值，不直接當單次率。
- 達Max、target不held、證據不合格如何影響「未使用資格」須同版policy；沒有明文時拒新attempt，不能自行消耗或改送另一因子。
- 無效輸入零成本零RNG，合法形成失敗保attempt結果。缺catalog／EP總式回PROFILE_UNSUPPORTED或SOURCE_INCOMPLETE；存儲未知回RESULT_PENDING，恢復先查marker不換seed。

## 保存 遷移與 UI

canonical事件、來源鏈、形成次數／首成功終止、有效星增益、獎勵鍵、名號資格／G02凍結證據引用及U02授券回執屬core，NPC第9筆重要事蹟亦須保存。legacy評級與獎勵已領狀態保留；新條件只作用新版本事件，不能為採R5再評關羽四事蹟／趙雲長坂後多發一次。名號已領鍵不因catalog改版而清空；需要新scope須明示遷移，不默當全新獎勵。

UI區分事蹟完成、獎勵已領、是否有形成資格、機會已耗及首次成功停止；名號另分候選條件、待必要功業、資格已成立及U02券是否到帳，不把G02候選顯成已領名號。EP缺公式或名號缺catalog顯對應「規則待定」，不顯0或用精確E反解未知LUK。不得將每次動畫都標可再抽的「覺醒」。公開者只看其知識層允許的因子變動。

### 共通重入順序

讀取既有提交紀錄先於新命令准入：同key與同payload已提交，或同businessEvent已有一致結果，先返回原結果，即使請求帶舊expectedRevision也不重新結算；同key異payload仍拒衝突。只有確定沒有既有提交的新操作才驗expectedRevision、資源與資格。唯讀功能不因此取得寫入權，pending先查commit marker，不換seed或key刷結果。

# R5F-B09 媒介因子傳授

本規格保留媒介傳授的資格、候選與一次attempt，明確只改held及未來來源，不增加童年A。R5F-B09僅文件ID，非正式ATM工單；全部工作文件／逐功能規格及真consumer／准入未核，implementationReady=false。

## 目的 非目標與 owner

在合法童年窗口，使用仍在世退休者的真可傳因子提供一次補救。owner為媒介attempt協調者；B07統一held／終身新增帳，C03保存結果，G04保自然童年A帳不受媒介污染。

不把媒介加為第15個生物祖先，不改parentUID，不延續媒介者的生物streak，不加P/B/A、不改已出生LUK。媒介可跨多星不同於功業有效+1，但不能借此繞字典Max、held6或終身新增2。實際consumer未核對。

## 來源與候選地位

[R4 工程](../../publication_candidate/11_R4歷史基線_工程驗收.md) §8（原第9頁）、§6–7、§26 R3T18、§28 R3T38；[R4 玩法](../../publication_candidate/10_R4歷史基線_玩法.md) §7；[R5 模組02](../../publication_candidate/02_出生_血統與聯姻.md) 能力分帳及來源變更；[模組08](../../publication_candidate/08_決策_衝突與擴充邊界.md) 未採規則禁止混入；[模組09](../../publication_candidate/09_證據來源與驗收索引.md) 媒介完整來源與歷史測例限制。

原試作候選挑最高星兩因子，各成功率62.5%=50%×1.25。原「+25%」相對或百分點未正式解決，不能寫成R5已批准62.5%，更不能改75%。T38只供同profile回歸，T18的一次attempt不變量保留。費用與資訊入口若受DEC-R4-06變更，需另採policy，不從本文猜券價。

## 輸入 輸出與建議 schema

以下為規格介面，非現行程式。

| 結構 | 欄位 | 契約 |
| --- | --- | --- |
| MediumPreview | childUID、sourcePersonUID、sourceRevision、childAgeQuarter、candidateIDs、knownProjection、policyRef | 不抽RNG；來源需退休仍活且真held可傳 |
| MediumAttempt | eventId、childUID、sourcePersonUID、orderedCandidates、sourceRevision、expectedRevision、payloadDigest、costPolicyRef | 確認前固定順序及結果流域；每子一次／每來源人物一次 |
| MediumResult | perCandidateOutcome、heldBefore/AfterRefs、newAcquisitionDelta、attemptConsumed、costLedgerRef、futureSourceRevision | 合法全失敗仍consumed；不帶任何A gain |

「每來源一次」依原文為來源人物的終身機會，不能改成每個子嗣各可用同一老人一次而放寬；若產品原profile另有scope，必須提供明文後版本化。來源與child的使用帳分開保存，不只以(child,source)pair去重。

## 流程與具體邊界

1. 先回已提交同key／businessEvent結果；只有新attempt驗revision。
2. 核child年齡、存活、未用媒介；來源退休仍在世、來源人物未用媒介、存在已知可傳held。原窗口0–5歲，5歲生日／季度端點須同版age policy明列；不可因15歲入學延至15。
3. 依原候選選來源最高星兩ID，平手canonicalID；在確認前固定其順序。查child現有held、Max與全渠道終身新取得帳，判每候選能否合法改變值。
4. 若全部候選均無可變結果，確認前拒絕，child與來源機會均不耗，無RNG或費用。不得降低來源星／轉送其他未選ID來製造一次合法attempt。
5. 有合法可變候選且profile完整後確認。各候選在固定命名流按已採率抽一次；原62.5%比較用U<.625。新增ID依預先順序占槽，受held6／終身新增2；相同ID取max(currentLevel,min(sourceLevel,Max))，不疊效果。
6. 一旦合法attempt確認，整個機會耗去，即使兩候選全失敗也不能重抽。合法成功可跨多星，但沒有五維A gain，沒有childhoodExtraLedger creditedGain；P/B不改。
7. 結果、兩個使用帳、成本、held及futureTransmissionSnapshot同一事件提交。未來婚約可讀新來源；當胎已鎖來源不改。

若只有一個新增槽可用，前一候選成功用掉槽後，後一候選不得覆蓋或超cap；預覽須明示順序和條件。若前者失敗後後者是否可用釋出機會，以及已不可變候選是否消耗流，需同版事件流程固定，不能由實作臨時選擇而破回放。

## 錯誤 恢復與保存

全無可變候選、年齡不符、來源死亡／非退休或任一使用帳已耗為STATE_CONFLICT／VALIDATION_ERROR，不耗RNG。缺來源／政策為SOURCE_INCOMPLETE／PROFILE_UNSUPPORTED。合法失敗不是可自動重試錯誤；成本依明定policy已耗一次，不擅自退款。

RESULT_PENDING先查commit marker；同key異payload衝突，不用新key換來源再抽。保存來源版本、選序、各候選流結果、使用帳、終身新增帳與成本引用，不只存成功因子。legacy已用媒介紀錄保原，不能以新UI重置；unknown使用史不當未用。舊P／A不因新媒介規則重算。

## UI

顯示「只傳授因子／學習資格，不增加本體能力」及候選順序、各種cap、child／來源一次機會和確認後全失敗仍耗。無可變候選禁用但不消耗。不得把62.5%候選顯為正式率，除非選定同profile；未知ID不在錯誤或preview露出。

## 精確依賴能力

- C01/C02：UID、字典、年齡世界季度與死亡終態，非學院turn。
- B07：held6、全渠道終身新增2、同IDMax、可傳／已知狀態；不把discovered當held。
- C03/C04/C05：attempt／雙使用帳原子保存、固定媒介流與來源閉包。
- G04：驗媒介輸出無A增益、童年自然成長與creditedGain不被覆寫。
- B06：新futureSource僅供之後婚約，既有胎次不回灌；不需要K、h或EP總式。

本功能無新增數值DEC編號；原媒介率／端點／費用及完整事件流程是來源或採用狀態待補，不能以清單DEC空白代表全部值已核。

### 共通重入順序

讀取既有提交紀錄先於新命令准入：同key與同payload已提交，或同businessEvent已有一致結果，先返回原結果，即使請求帶舊expectedRevision也不重新結算；同key異payload仍拒衝突。只有確定沒有既有提交的新操作才驗expectedRevision、資源與資格。唯讀功能不因此取得寫入權，pending先查commit marker，不換seed或key刷結果。

文件內容狀態：CONTENT_REVIEWED_WITH_OPEN_DECISIONS。implementationReady：false。現行實作／consumer：NOT_VERIFIED；產品測試：NOT_RUN；產品驗收：NOT_ASSESSED。
R5F 僅文件功能 ID，非已登記 ATM 工單。全部範圍內工作文件、清單、獨立規格完成後，才能評估產品編碼；相關決策與正常施工准入另須滿足。以下擬議介面／狀態名稱不宣稱產品已存在。

## 1. 目的、責任與非目標
將首通與每季成就獎勵結算成可重入帳本，避免重播/讀檔/新key多領。不是積分排名owner，也不定獎品數額。

## 2. 規範來源與優先關係
來源：使用者季獎勵需求；R5模組05。完整基線見 [R4 工程](../../publication_candidate/11_R4歷史基線_工程驗收.md) 與 [R4 玩法](../../publication_candidate/10_R4歷史基線_玩法.md)，R5 題目模組見 ../../publication_candidate/。本份細分原入口，不另計同一成果兩次。R5明示修正優先；原文標候選／legacy／待決者不因本份引用升格。歷史紙面驗算結果非本次產品PASS，可重跑歷史驗算附件未包含於原基線。

## 3. 輸入、輸出與資料契約
輸入：S04有效成就/勝利事件；只有policy要求統一成果證據的獎勵才須E03快照參照，一般季成就不要求首通快照；已採獎勵policy、領取身份/存檔revision。E01畫面事件不算勝利證明。

輸出：一次領取收據與獎勵delta，或待政策/資格拒絕；生涯榮譽紀錄和資源獎勵分欄。

擬議schema與型別：RewardEligibility {canonicalAchievementEventId, familyUID, seasonId, rulesHash, scope:lifetime|season}; RewardPolicy {revision,items,claimWindow,recipientScope}; RewardReceipt {businessKey,eligibilityDigest,policyRevision,grants,resultRevision}; proposed lifetimeKey=(familyUID,firstUnification)；實際身份範圍須由採定policy確認。

## 4. 正常流程及狀態邊界
1. 驗canonical成就事件與規則版本；首通與當季成就分scope，不能每季重置終生first。
2. 讀一次業務鍵；已領即回原收據，不因新idempotencyKey再授予。
3. DEC-S01結季時點與S08獎勵/比較政策需完整；缺數額/recipient/窗口不補0或虛構免費獎品。
4. 用C03同時提交eligibility消費與grant，來源券等透過相應帳本契約，不另設旁路餘額。
5. 到期、放棄、取消與跨季pending以採定policy處理；先回查committed再改claim狀態，不因逾時重發。

## 5. 失敗、取消與恢復
無勝利證據拒；rulesHash變更不套舊eligibility；同businesskey異payload為衝突；policy缺件回PROFILE_UNSUPPORTED但不阻E01已凍結展示。

## 6. 保存、遷移與可重入
E02唯一獎勵領域owner；S05只計分不發獎，E03只凍結不領取。legacy已領收據保留，不因遷移新季ID重設；身份範圍改動須preview，不能默認全帳號或每存檔重領。

## 7. UI／可見資訊
分首通/當季、已符合/待政策/可領/已領/pending；顯獎勵來源與收據，不把觀看動畫當領取成功。

## 8. 依賴能力及待決閘門
S04資格事件；E03僅限需統一成果快照的獎勵；S05 finalizedScoreRef僅作已定規則的只讀計分證據，不由E02再加分；C03原子保存；C01身份。舊清單E01依賴精化為展示收據互通而非資格來源；不依U01新階段或K。

明列決策：DEC-R5-S01、DEC-R5-S08
缺本次操作必要參數時回 PROFILE_UNSUPPORTED，不以0、R3舊值或較新G分冊衝突值補齊。已定只讀／不變量能力不自動繼承上游所有待決。任何仍需選定技術機制的schema屬實作設計提案，不冒稱使用者批准。

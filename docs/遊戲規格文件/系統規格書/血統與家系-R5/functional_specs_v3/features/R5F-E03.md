# R5F-E03 首次統一結局快照封存｜獨立功能規格 v3（已審條件版）

## 狀態與範圍
文件內容狀態：CONTENT_REVIEWED_WITH_OPEN_DECISIONS。implementationReady：false。現行實作／consumer：NOT_VERIFIED；產品測試：NOT_RUN；產品驗收：NOT_ASSESSED。
R5F 僅文件功能 ID，非已登記 ATM 工單。全部範圍內工作文件、清單、獨立規格完成後，才能評估產品編碼；相關決策與正常施工准入另須滿足。以下擬議介面／狀態名稱不宣稱產品已存在。

## 1. 目的、責任與非目標
在有效統一事件發生時建立不可變成果快照，使E01不用向現況逆推過往。保存歷史，不決定勝利或發獎。

## 2. 規範來源與優先關係
來源：使用者首次統一成果需求；R5模組05；R4工程§6/16。完整基線見 [R4 工程](../../publication_candidate/11_R4歷史基線_工程驗收.md) 與 [R4 玩法](../../publication_candidate/10_R4歷史基線_玩法.md)，R5 題目模組見 ../../publication_candidate/。本份細分原入口，不另計同一成果兩次。R5明示修正優先；原文標候選／legacy／待決者不因本份引用升格。歷史紙面驗算結果非本次產品PASS，可重跑歷史驗算附件未包含於原基線。

## 3. 輸入、輸出與資料契約
輸入：S04已確認且可追溯勝利事件、同一revision的地圖/貢獻/家系公開資料、profile與legend、C03可提交上下文。

輸出：committed snapshotId/checksum與可查狀態；不足資料留明示缺欄或阻缺必要勝利引用，不補造貢獻。

擬議schema與型別：EndingSnapshot {snapshotId, victoryEventId, familyUID, campaignSeasonId, worldQuarterIndex, rulesHash, sourceRevision, territoryDigest, troopTypes[{troopTypeId,dictionaryVersion,usageEventRefs,contributionSnapshot}], contributors[], adultFamilyContributions[], descendants[], publicStatsAtEvent, deedRefs[], schemaVersion, checksum}; FrozenEntry {personUID,parentRefs,branchRef,displayNameAtEvent,knownValuesAtEvent,ageAtEvent,statScale,sourceEventRefs}。擬議快照結構須保引用閉包。

## 4. 正常流程及狀態邊界
1. 以victoryEventId形成唯一業務身份，schema/version只是編碼版本、不加入首通業務唯一鍵，讀既有快照先回原件。
2. 鎖定同一sourceRevision，擷取事件當時公開成果與必要原始引用；不混用提交後較新的後代數值。
3. 父母/婚姻/支系用UID指回持續家譜，但名稱、當時年齡、可見數值、戰績取快照；當代不因之變成複製人物。
4. 核相同成果資料可解釋到事件與尺度；新R5統一事件必含軍種及其使用／貢獻來源，缺軍種資料列SOURCE_INCOMPLETE不可把新需求降成可選；只有明示legacy舊快照本來未記錄時才可標未記錄。缺核心勝利或主家族同樣拒保存。
5. 經C03新槽checksum/閉包成功後發布snapshotId；E01只消費committed，不讀半成品。
6. 後續改名死亡/新戰績不變更凍結物；若需更正資料，新增帶supersedes參照的修訂事件並保舊快照，不能原地改寫史。

## 5. 失敗、取消與恢復
REVISION_CONFLICT重讀原事件可一致取得的資料，不偷取最新當歷史；SOURCE_INCOMPLETE阻核心缺失；RESULT_PENDING先查同事件快照marker；checksum失敗保舊槽。

## 6. 保存、遷移與可重入
本功能唯一快照建立owner，C03持久化；C05將快照及其profile/事件引用納核心閉包。格式遷移可新增視圖/編碼版本，但decoded historical values不變，原生物身分不新增。

## 7. UI／可見資訊
快照準備中與可觀看分開；缺可選紀錄顯未記錄；歷史更正顯原版/修訂理由，不靜默替換第一次破關。

## 8. 依賴能力及待決閘門
S04有效勝利事件；C01分型；U01公開知識投影（僅既有能力）；C03提交；C05引用閉包。E01讀取，E02領取，各自不反向建立快照。

明列決策：無新增數值待決；仍須完成整組文件及正式實作前核查。
缺本次操作必要參數時回 PROFILE_UNSUPPORTED，不以0、R3舊值或較新G分冊衝突值補齊。已定只讀／不變量能力不自動繼承上游所有待決。任何仍需選定技術機制的schema屬實作設計提案，不冒稱使用者批准。

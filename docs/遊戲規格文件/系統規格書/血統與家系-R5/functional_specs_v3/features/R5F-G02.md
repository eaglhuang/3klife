## 目的與非目標

太傅代管減少重複選回合，使用與手動相同的 run、精力及事件提交機制。人物最多三份候選只能選一份正式畢業，讓玩家在多次真實耗時的結果間取捨，而非拼成不存在的最強五維。

不新造基礎收益、不把 auto .5 套全部 TP、不重做 G01 的每回合計算、不開畢業後無限買技能入口。育成評級不是戰力、名號、EP 或功能資格的同義詞，不能互相暗開。

## 必要依賴能力

G01 是 admitTraining、admitted→active 與 run 初始化唯一 owner，本功能只傳入候選／資格證據及同一 A0Revision 並引用其 admission receipt，不另建run、不初始化TP或精力。G01 也提供同一 run 單回合與 36 回合完成 receipt；G05 提供候選內已兌換技能與 TP 帳；C01 提供同一人物／familyUID／量尺；C02 提供每 run 一世界季度；C03/C05 提供唯一選定、保存閉包及歷史遷移；U01 提供不洩漏精確未知能力的比較。這些依賴不要求重採整套出生、K 或研習決策。

DEC-R4-07 僅阻擋未採的新 auto 開放門檻及相關儀式／教學政策，不能藉此否定既有合法 legacy 資格記錄。實際產品是否已有此能力仍待查。

## 輸入輸出與建議 schema

輸入包括人物穩定 UID、mechanicsProfile、最多三份 completed candidate、同一 A0Revision、已選 manual 人物集合、既有 auto 資格、方針版本與 selection expectedRevision。輸出為每份候選完整結果、ΣC 育成評級、唯一選定結果、其餘封存歷史、資格變更或缺決策原因。

```text
AutoPolicy { policyVersion, profileHash, priorityTraits, legalActionRules,
             restRules, mentorSelectionRules, eligibleEventCatalog }
GraduationCandidate { runId, personUID, A0Revision, completedReceiptRef,
                      mode, progressFraction[5], developedMask[5],
                      bodyATicks[5], skillSnapshotRef, tpLedgerRef,
                      scoreFraction, developmentGrade, worldQuarterCostRef }
GraduationSelection { personUID, selectedRunId, candidateRefs,
                      selectionEventId, expectedRevision, payloadDigest,
                      selectedAtQuarter, committedMarker }
AutoEligibility { ownerScope, ruleVersion, manualSelectedPersonUIDs,
                  qualifyingGradeEvidenceRefs, autoUnlocked,
                  legacyEvidenceRefs, revision }
```

此為擬接 schema。方針缺少休息或教官規則不能由工程猜「最佳 AI」。profile/ruleVersion 必須指向已採內容；ownerScope 的實際產品歸屬待真 consumer 核對，不因換季、改名或分家重領資格。

## 代管與畢業流程

1. 查已採 auto 資格與方針。R3 歷史規則是三位不同人物完成手動畢業選定，至少一位育成 A 或 S；同人三份候選只計一人，不要求 S、30 次、第五代，也不另耗券。
2. R5 尚未採新資格。G1「第二胎即開」與前述規則衝突，不能混用、不能由第二胎自開新 auto；既有合法已解鎖證據依原 profile 保存。
3. 代管只提出下一個合法主行動，由 G01 結算。auto 成長 .7 只套一次，最高育成 A；不觸發 manual 鼓舞、考核或事件覺醒。儀式演出不得新增抽樣或獎勵。
4. 每 run 從同一認可 A0 出發，最多三份 completed candidate，同時最多一個 active run。每完成 run 都真耗一世界季度，未選結果的時間不退回。
5. 完成 36 回合後進畢業區，G05 在本候選內完成合法兌換，再固定候選快照。未完成 run 不能進選定流程。
6. 育成分數是 ΣC，只計 L>0 且本 run 開發的維度；全 L=0 顯示 N/A，不以零分母或免費 C 發 S。相同歷史 profile 門檻：S≥1.25、A≥1.10、B≥.85、C≥.60，其餘 D；auto 的最高評級截為 A，保原始分數供審核。
7. 玩家選一個完整 candidateRunId，其 bodyA、技能、mode 與來源一起成為正式畢業快照。其他候選改 archived 並保留，不允逐維最大值拼接第四份。
8. 同一選定事件原子更新人物 graduated 與資格帳；資格去重人物，不以 run 次數重複累計。選定後不新增自由購買或另選更好候選的未採入口。

## 評級 名號與資格分離

P=20×Talent 為歷史能力點映射，每點 10000 ticks；不得把 legacy 五維總和 450/460 直接拿去比 ticks 或 P0–2000。育成 ΣC 表示開發程度，低 P 也可能育成良好，不代表高戰力。

工程 §2 的名號條件「ΣC≥1.35 且一項 C≥.75，或 EP≥95，再完成 catalog 功業」屬歷史候選，查券獎勵受 DEC-R4-06／09 影響。本功能只向 B08 提供可追溯的 ΣC、單項C與候選來源證據；EP資格證據須引用合法已知來源，不由此反推或新算EP。B08 擁有依已採 catalog 判定 canonical 名號資格與一次獎勵事件的責任，U02 只消費合法查券事件。本功能不發名號、查券或另開 P cap；未選門檻不能自授名號，更不能用名號替代 auto 資格。N/A 的人物不靠「畢業次數」構造一位 A/S。

## 邊界 錯誤與恢復

缺已採 auto rule 或方針回 PROFILE_UNSUPPORTED；仍可讀原有候選，並提供已准入的手動流程，不默選新門檻。候選屬別人、A0Revision 不同、未完成、已超三份或已正式選定時回 STATE_CONFLICT／SOURCE_INCOMPLETE。

舊 revision 的選定請求拒絕，回讀整份候選，不把最新五維偷偷替換進舊選擇。同 selectionEventId 同 payload 回原選定；不同 payload 回 IDEMPOTENCY_CONFLICT。提交未知時顯示處理中，先查 committed marker，不能再次選另一份或把已耗季度退還。

## 保存 遷移與重入

保存三份候選的完整來源、C、A0、技能與時間 receipt，而非僅五維最好值；保存人物去重集合與 A/S 證據。歷史選定不能因換季、教學重播或改姓重新計人次。legacy 已知資料與既有 auto 資格保留來源，不用新的第二胎方案重算。

存檔只有總訓練次數而無 personUID／選定證據時，不自動推定已滿三人。列資料缺口並保原模式可讀，遷移要另有明示規則。不從畫面評級倒推出精確 C。

## UI

候選以完整卡片比較，同時列消耗的季度、模式、育成評級、技能與可公開能力；選定前明示「只能選一份，其他保留歷史」。ΣC、戰力投影、稱號與 auto 開放條件分列，N/A 說明為無可開發缺口。

代管顯示採用方針與剩餘行動，錯誤停在最後已提交回合；不可用動畫跳過真成本。未精查 P 的能力與候選排序必經 U01，不以內部 ticks 做隱藏破同分。

## 待決與完整性要求

DEC-R4-07 尚缺 auto 最終門檻、功能與知識分層及儀式時點；不得在 schema 預設 true。代管的實際方針 catalog、ownerScope、候選技能快照接線需與真 consumer 核對。本規格不替新名號或查券數值拍板。所有文件完成、適用決策採定、正式准入及產品 E2E 證據齊全後，才評估 implementationReady。

## 重入優先序與數值型別補充

所有會變更狀態的入口，先查同idempotencyKey＋payload及canonical businessEvent是否已有提交結果；已提交同內容必回原receipt，即使請求的expectedRevision已舊也不能先拒。相同key異payload必衝突；不同key同業務事件不得多領。只有尚未提交的新命令才驗目前expectedRevision；pending先查marker再續原交易，不重抽結果。這項順序優先於上文新操作驗證步驟，不能先套active／alive／未selected等前置條件把成功重送當非法新行動。

儲存型別BodyTicks為整數；Talent與能力點可有精確小數，不要求顯示點一律integer。一能力點＝10000ticks，跨單位先明確換算；中間Fraction不得從畫面ppm或浮點近似回灌。

## 目的與非目標

讓已持有低星因子的角色，在有限工時及成本下選一次研習計畫，改善未來傳遞資格。研習只作用已 held 的合法 1／2 星 ID，cap3 是 R4 候選方向，不能把尚未持有的祖先 ID 補進本人，也不回改本人的出生 P。

不替代保 ID 的保留槽、不增加 held6、不延長祖源窗、不自動覺醒、不送 EP 或五維 A、不新建免費學院回合。不把「一個 plan」暗改成可無限 retry，也不自行採定確定補救或機率補救。

## 輸入輸出與建議 schema

輸入包括人物、held來源、字典Max、開始時星數、鎖定 target、plan版本與成本政策、季度、席位／服務證據、預期revision。輸出為 plan 狀態、實付資源／工時、一次 outcome、完成後星數及新的 futureTransmissionSnapshot，或者不消耗的拒絕。

```text
StudyPlan {
  planId, personUID, canonicalFactorID, sourceRevisionAtStart,
  initialLevel, lockedTargetLevel, allowedTransitionPolicyRef,
  dictionaryVersion, profileHash,
  attemptPlanVersion, decisionRevisionRefs, method: A|B,
  maxAttempts, startWorldQuarter, requiredQuarterPolicyRef,
  spentQuarterEventRefs, resourceCostPolicyRef, reservationRefs,
  attemptReceipts, status, lifetimeUsed, revision
}
StudyOutcome {
  planId, completionEventId, currentSourceRevision,
  currentLevelBefore, lockedTargetLevel, outcome, levelAfter,
  futureTransmissionSnapshotRef, costLedgerRef, committedMarker
}
```

此為建議 schema，非現有程式。未採的 maxAttempts、工時、價格、退款及死亡政策不得填 0 或 R3 舊值當預設。可保存未執行 proposal，但不能以缺必要值的 proposal 扣費或啟動計畫。

## 狀態與主要流程

1. 預覽讀取人物在世狀態與已 held 的合法 ID。候選 cap3 只允許開始時 1／2 星，已採 profile 必須明列單步 allowed transitions：1→2 或 2→3。lockedTarget 必須等於 initialLevel+1，且不超字典 Max 或所採 cap；不能只驗target≤3而誤允1→3，也拒target≤initialLevel。已達 cap、未held、unknown、終身額度已用皆拒絕。
2. 核 plan profile 的互斥方案、target、attempt次數、完整成本／工時、取消／死亡處理及所需席位。同一席位不能同時讓教養與研習各領全效。
3. 開始一次鎖定 ID、target、plan版本及成本意圖；建立唯一 lifetime 記錄。何時消耗終身資格與取消是否保留使用紀錄必須由已採政策明定，不能以取消開新 plan 刷結果。
4. 每個已發生世界季度記一次工時事件；不能以讀檔、切主題季或重播教學增加 spentQuarters。未採跨季跳時政策時不得假定完成剩餘工時。
5. 達已採工時並仍合法時，A 執行確定補救，B 依所採的單次機率流執行；合法失敗依 plan 成本政策記帳，不能把失敗當網路問題重抽。
6. 成功完成取 levelAfter=max(currentLevel,lockedTargetLevel)。若中途功業已升到更高，保高星，不倒扣、不因完成再加一星。未成功保當前星；結果只更新之後確認婚約可用的傳遞來源。
7. 來源版本與 plan 終態、成本帳同筆提交；已凍結婚約 sourceRevision 與本人 P/B/A 均不回寫。

建議狀態是 proposed→active→completion_pending→completed_success／completed_failure，以及依已採取消／死亡政策的終態。狀態名稱可調整，但每個分支的成本、終身資格與可否續辦必有明文，缺其一不得啟動新 plan。

## 邊界 錯誤與恢復

SOURCE_INCOMPLETE 用於 held、字典或來源不可驗；PROFILE_UNSUPPORTED 用於尚未採 A/B、工時或終態政策；STATE_CONFLICT 用於不在可用狀態、重複終身計畫或死亡後嘗試完成。無效請求不扣費、不占席位、不抽 RNG。

中途死亡保原 plan、已付成本及死亡引用，不發星、不復活；若成本／席位釋放政策未採，記為待解處理而非自行退款。取消同理，不能把原已付款默消失。跨季如實記還餘多少世界季度，不重置開始日。

同 plan completionEventId 同 payload 回原結果；異 payload 拒絕。同業務事件換鍵仍不可再抽。RESULT_PENDING 先查 marker，已提交不補發星與退款，未提交續原交易。來源在提交前被功業更新時先報 REVISION_CONFLICT 並回讀，保留 locked target，不重抽已保存 attempt。

## 保存與遷移

保 plan版本、locked target、所有工時／成本／attempt receipt、來源前後revision及終身額度。R3 target≤4 是歷史策略，不能回扣已取得4星；若採 R4 cap3，只對新plan適用，舊 active plan 須依明示遷移政策完成或保legacy。

不能只存「已研習」布林而丟失失敗成本、target 或 attempt次數。跨季與存讀須維持同personUID／planId，不能用新 seasonId 重開終身資格。所有未來傳遞引用要進核心閉包。

## UI

開始前分列「已有ID」「目前星」「鎖定目標」「耗時」「占用席位」「成功規則」「取消／死亡後果」。尚未採定項顯示待評審，不給可提交按鈕。只顯示角色有權知道的 factor；未知祖先 ID 不透過錯誤訊息露出。

研習進度用世界季度，不用學院36格或主題季數。中途已高於target顯示保留現星，說明不再額外加星；已鎖婚約不受這次完成影響。

## 待決與來源疑點

DEC-R4-04 必須提供一份完整互斥方案，而非從不同比較表各取最有利值；四／八季度及 n5+.02／.04 仍為候選。取消、死亡、換季續辦與席位政策需跟該plan版本一起採定。DEC-R4-01 未定 K 不進資格；DEC-R4-02／08 的作用只按上表能力範圍判斷。

歷史五星分布來自單ID每代必保留、生育前完成形成與研習等強假設，不含媒介、配偶供給、死亡及工時；不能視作本功能產品平衡驗收。真consumer、UI、保存與正式准入仍待核。

## 重入優先序與數值型別補充

所有會變更狀態的入口，先查同idempotencyKey＋payload及canonical businessEvent是否已有提交結果；已提交同內容必回原receipt，即使請求的expectedRevision已舊也不能先拒。相同key異payload必衝突；不同key同業務事件不得多領。只有尚未提交的新命令才驗目前expectedRevision；pending先查marker再續原交易，不重抽結果。這項順序優先於上文新操作驗證步驟，不能先套active／alive／未selected等前置條件把成功重送當非法新行動。

儲存型別BodyTicks為整數；Talent與能力點可有精確小數，不要求顯示點一律integer。一能力點＝10000ticks，跨單位先明確換算；中間Fraction不得從畫面ppm或浮點近似回灌。

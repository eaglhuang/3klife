## 目的與非目標

每次訓練清楚區分基礎TP與教官額外TP，讓當次指導、見習、靈感與畢業技能形成一條有限且可追溯的取得流程。不得重複扣費或因自動模式誤砍基本收益。

不新增武將EXP、不用TP提高P、不替所有教官卡同時加乘、不因綠因子高星疊折扣、不在培育途中直接學技能，也不在正式選定畢業後開無限購買。G01擁有回合與成長提交，本功能提供其子帳，不另扣主行動。

## 輸入輸出與建議schema

輸入是runId、actionEventId、入學卡組、選定教官的Rank1..5／專長／familyUID、人物familyUID、主項、mode、outcome，以及技能catalog、見習完成證據、本run inspiration、目前本體INT、已學技能和TP餘額。

輸出為合法成長加成、TP基礎／額外／overflow明細、靈感receipt、可兌換清單及扣費／學會／啟用結果。

```text
MentorSnapshot { mentorUID, rank, specialtyTrait, familyUID,
                 sourceRevision, admittedDeckRef }
RunSkillState { runId, personUID, profileHash, catalogVersion,
                tpBalance: nonnegativeInt, tpReceiptRefs,
                apprenticeshipRefs, inspirationRefs,
                guaranteedInspirationReservationRefs,
                learnedSkillRefs, activationEventRefs, revision }
TPReceipt { actionEventId, baseTP, mentorExtraTP, acceptedTP,
            overflowTP, mentorRef, mode, outcome, committedMarker }
SkillExchange { exchangeEventId, runId, canonicalSkillID,
                expectedRevision, catalogVersion, eligibilityRefs,
                slotCountFromBodyINT, cost, payloadDigest,
                learnedSkillReceiptRef, committedMarker }
```

這是擬接模型，不是已存在API。inspiration具runId，不得拿另一run或家族全局旗標代替。混種技能ID或靈感分段缺catalog時不得自行編ID與門檻。

## 教官與TP流程

1. 當次最多一位教官，必須來自入學選定1–6張卡組；培育途中輪派只在既有卡組內。未派明確為零加成；未知Rank或缺familyUID不可猜。
2. 主項與教官專長匹配時，Rank1–5 mentorBonus=.05/.10/.15/.20/.25；不匹配為0。同正式familyUID且匹配才有synergy=.10；同姓或猜血緣不等同家族。
3. 每次成功基礎TP10、合法失敗TP2、休息TP0。匹配教官成功另給2×Rank；manual額外×1、auto額外×.5。失敗額外0。auto的.5只作用教官額外，不影響基礎10；成長.7由G01另套一次。
4. TP非負整數，run初始0、cap9999。各收入分別可追，超cap部分記overflow後丟棄，不延期補發。額外2×Rank×.5恰為整數，不另做浮點捨入。
5. manual第12回合完成且有已派匹配教官時，一次鼓舞讓下一次訓練eventBonus=.10；那次訓練失敗也消耗，不永久保留。manual第24回合成功訓練數≥10才給主項progress .02，無主項時依原規則指定入學trait；由G01套共享事件預算。auto不觸發二者。
6. 回合receipt、TP、鼓舞／考核使用鍵與靈感意圖一併提交，不能由本功能再執行一次G01。

同profile核對：Rank3匹配同家且manual鼓舞，u=1.15×1.10×1.10=1.3915，C+.069575、TP16；auto無鼓舞，u=.7×1.15×1.10=.8855，C+.044275、TP13。13不是8，也不能再乘.7。

## 保證靈感唯一reservation

R4工程§9要求保證靈感有唯一reservation，與一般靈感抽樣及UI演出分開。本功能G05是reservation、授予inspiration及消耗記錄的唯一owner；G01只把同一run事件提交交由G05產生子帳，不另建立或領取一份。

- 建議業務鍵為同一runId＋已採catalog中的canonicalGuaranteeEntryId。ruleVersion、來源資格與payloadDigest保存在該記錄；同run同entry不能因換版本、換idempotencyKey、休息或重新開畫面建立第二份。若catalog確有多個保證entry，須各有已列的合法來源，不能讓UI自己產生新entryId。
- reservation取得時點、對應技能／見習、觸發條件與消耗時點全由已採catalog明列。本規格不猜保證靈感在第幾回合，也不把第12／24回合或混種15–25窗口借作預設。若profile宣告此保證而catalog缺件，G01入學／啟動不得提交半套run，相關獨立觸發入口也回PROFILE_UNSUPPORTED或SOURCE_INCOMPLETE。
- 合法資格事件先產生reserved記錄；到catalog指定的合法觸發事件，將inspiration receipt與reservation的consumed狀態原子提交。consumed必指向唯一授予事件。保存pending時不先當成可再領，亦不只標consumed卻漏寫inspiration。
- 休息只按G01規則回精力，不因未訓練而重建保證；讀檔恢復原reservation；跳動畫只改演出狀態，不參與資格、消耗或領取。尚未觸發的reserved是否跨特殊狀態保留、取消或轉移依catalog，不自行退款或移到另一run。
- 同key同payload與同業務事件已提交，先回原reservation／inspiration receipt，即使目前revision已舊或run已selected；新命令才驗revision與run狀態。同key異payload衝突，不能重抽、重發或雙耗。

建議紀錄：GuaranteedInspirationReservation { reservationKey, runId, canonicalGuaranteeEntryId, catalogVersion, sourceEligibilityEventRef, triggerPolicyRef, status: reserved|pending|consumed, inspirationReceiptRef, payloadDigest, committedMarker }。此為建議schema，不是現行程式；額外終態須有明示policy。

## 技能兌換流程與單位

1. 只有run完成36回合、處於畢業區而尚未正式selected時可兌換。培育中或已graduated皆不新增購買入口。
2. 技能必須有同ID對應見習資格，且本run已建立inspiration，才進清單。基本戰法救援與補給分別對應S_RESCUE、S_SUPPLY字典效果；實際技能canonicalID仍依正式catalog，不把factorID猜作API skillID。
3. 普通成本100TP，held對應綠因子成本50TP。held先可折扣、學會後才active，不能要求active才可折扣造成循環。星數不再重乘折扣。
4. 槽數=min(4,1+floor((A_INT能力點/20)/30))。若輸入是BodyTicks，必先A_INT能力點=A_INTBodyTicks/10000，再除20與30；不把raw ticks直接套公式，也不把寶物／年齡／傷病投影當本體INT。
5. 同一結果最多學兩項基本戰法與一項符合條件的混種戰法；這是種類數量限制，獨立於總槽cap4。即使尚有第四槽，也不能學第二項混種，不能用不同alias或替換技能重置該限制。核種類上限、空槽、剩餘TP、未學及完整資格；一次扣費與寫學會／啟用receipt。槽滿、TP不足、已學或缺見習／inspiration均拒且零扣。
6. 已學技能不重扣、不重學領收益；稍後槽數增加不回頭補領舊事件。混種若有獨立資格，依已核catalog，不能只憑兩個基本因子圖示就允許。

## 來源缺口與受限分支

GAP-R5-G05-CATALOG-01：本包工程§10保存兌換機制與基本因子效果，但沒有完整三段靈感／混種技能catalog、各觸發條件、canonical技能ID與機率表。R3T49僅記manual第15–25回合共11機會、至少一次43.119991%、auto零抽、首成功後停、畢業TP150／槽1。這是歷史待回歸摘要，不能反推完整機率、資格或補造新技能ID。

因此本文件可規定已知TP／槽／兌換契約；混種catalog缺失只阻混種分支，不擴大成所有基礎TP或已有完整catalog的基本戰法皆不可用。混種與各自缺catalog的靈感分支必須SOURCE_INCOMPLETE／PROFILE_UNSUPPORTED，不宣稱規格已足供其施工。補足原同版catalog後逐條映射，不得以本次文件工作自訂值。

## 錯誤 保存與重入

同actionEventId回同TP receipt，不能換key多領；同exchangeEventId回已學結果，不再扣費。不同payload回IDEMPOTENCY_CONFLICT。expectedRevision不一致時重讀餘額及槽，不基於舊預覽繼續扣款。

寫入未知或失敗時先查committed marker，不能因顯示舊TP就自動退款或再次兌換；保前一完整槽。保存見習／靈感的run與事件引用、折扣依據、學會時本體INT及消費receipt。換季不能把已消費inspiration重建一次；legacy技能與成本按原profile保留，未映射技能保持legacy，不重扣補差額或猜新ID。

## 重入優先序與數值型別補充

所有會變更狀態的入口，先查同idempotencyKey＋payload及canonical businessEvent是否已有提交結果；已提交同內容必回原receipt，即使請求的expectedRevision已舊也不能先拒。相同key異payload必衝突；不同key同業務事件不得多領。只有尚未提交的新命令才驗目前expectedRevision；pending先查marker再續原交易，不重抽結果。這項順序優先於上文新操作驗證步驟，不能先套active／alive／未selected等前置條件把成功重送當非法新行動。

儲存型別BodyTicks為整數；Talent與能力點可有精確小數，不要求顯示點一律integer。一能力點＝10000ticks，跨單位先明確換算；中間Fraction不得從畫面ppm或浮點近似回灌。

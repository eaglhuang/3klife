## 目的與非目標

角色承受可追溯傷害、以世界季度休養並依同profile壽命規則到達死亡終態。死亡、年齡與既有傷病不因換主題季重置，已死亡人物保歷史，不再作活人出勤或再起供給。

不改出生P/B或已開發A，不把學院stamina當HP，不因近親履歷h恢復就治癒既有衰薄，不新增文職出勤成本或INT/POL扣值。G08擁有職務／年齡外部投影；DEC-R4-05未決不能全面阻擋已有同profile的HP、休養與死亡規則。

## 必要依賴能力

C01提供人物身份、健康欄位型別與profile；C02提供出生季度、世界季度與年齡；C03/C05提供事件唯一性、死亡保存與閉包；B07提供長壽／韌性held、active與星數事件；G01只讀HP>25入學資格；G08只讀受傷外部倍率與在世狀態。B06接收死亡以中止未出生胎，G03/G07接收死亡以處理plan／服務，但各自成本政策不由本功能猜定。

跨季若不推進世界季度，不額外老化或休養；若採跳時，由已採C02時間政策逐季處理。本功能不替DEC-R5-S04選跳時方案。

## 輸入輸出與建議schema

輸入包括人物在世狀態、max/currentHP、fragility、傷害事件dangerTier、休養季度、active韌性星、長壽啟用／升星事件與世界時點。輸出為HP變化、外部傷勢倍率、准入限制、ageLimit與唯一死亡事件。

```text
HealthState { personUID, profileHash, maxHP, currentHP, fragility,
              activeResilienceRef, lifetimeLongevityCredit: 0..3,
              activationReceiptRefs, lastProcessedWorldQuarter,
              deathEventId, revision }
HealthEvent { eventId, personUID, kind: injury|rest|assessment|death,
              worldQuarter, sourceEventRef, expectedRevision,
              policyVersion, payloadDigest }
HealthReceipt { eventId, hpBefore, rawDelta, appliedDelta, hpAfter,
                activationChanges, longevityCreditBeforeAfter,
                lifeLimitAtEvaluation, deathEventRef, committedMarker }
DeathRecord { deathEventId, personUID, worldQuarter, reason,
              sourceEventRefs, profileHash, historicalPersonRef }
```

此為擬接schema，非現行API。死亡沒有以新季重新初始化的分支。damage/rest的整數單位是HP，不是BodyTicks，也不是stamina。

## 受傷與休養流程

1. 驗已採profile、人物未死、事件來源與revision完整。正常maxHP100，衰薄85，初始滿；沒有受傷事件不每季暗扣HP。
2. dangerTier0/1/2對應基礎傷害0/20/40。衰薄乘1.15向上取整；正常保持基礎傷害。扣HP至最低0，不能保存負HP。
3. HP0建立唯一死亡終態。0<HP≤25為重傷，禁止危險任務但可安全行政；傷勢外部倍率.8，輕傷1。學院入學需HP>25，stamina仍獨立。
4. 完成一個合法世界季度休養，未active韌性時正常回25、衰薄floor(25×.9)=22。active韌性s≤3時gain=floor(25/(1−.05s)×健康係數)，健康係數正常1、衰薄.9，最後capHP。
5. 韌性首次合法養傷完成後才active；本次先按未active算回復，不追補本次自身增益，下一次休養才使用加成。不得把held等同active。
6. 傷害／休養、active變更與receipt一筆提交；若同季度有多個來源事件，依已採事件順序處理，不自行選讓人存活或收益最高的順序。

## 長壽與死亡流程

1. ageLimit=min(95,80+5×lifetimeLongevityCredit)−(衰薄?5:0)。credit範圍0..3，首次合法啟用／升星取max(舊credit,本次星)。不因停用撤回，不傳給後代。
2. 長壽在18歲健康評鑑啟用；18歲後新取得者於下一季評鑑啟用，不以取得瞬間倒改已結算死亡。
3. 每世界季度先處理已提交的合法啟用，再檢年限。無長壽的年限正常80／衰薄75；Max3為95／90。這些不是保證不戰死的免死年齡。
4. 傷害HP0或到達同profile自然終點，保存deathEventId、原因及時點。後續傷害、休養、啟用或重讀不得復活；保人物、父母、來源、已知資料與歷史。
5. 對正在懷孕、研習、親授或任務的關聯owner發布同一已提交死亡引用，避免對方仍當在世。它們的退款／席位／交換終態須由各自已採政策處理，不由死亡流程憑空發補償。

## 邊界 錯誤與恢復

未知dangerTier、負HP、HP>max、未知星或缺profile拒絕，不用clamp掩蓋毀損資料；只有合法結算的傷害與恢復才套0/max。已死亡人物回STATE_CONFLICT，不接受「補活」的休養。

傷害事件重送不再扣一次；休養季度receipt重送不再回一次；同季健康評鑑不重發長壽credit。revision衝突回讀新狀態，已保存的死亡事件優先作終態事實，不以新指令換來源重算。

RESULT_PENDING／STORAGE_FAILURE先查marker，已提交回原receipt；未提交保原交易意圖，不出現一邊死亡一邊仍可任務的半狀態。恢復也必核關聯引用，不能以取消通知失敗否認已死亡。

## 保存 遷移與跨季

死亡與長壽credit是核心紀錄，不能因NPC日常log輪替丟失。保存fragility來源、啟用時點、已用休養季度、死亡原因與profile。學院精力可跟run保存，但不能拿滿精力覆蓋受傷HP。

舊健康狀態依原profile保存；新h規則或角色換姓不治癒。新職務曲線只能影響未來外部投影，不倒扣舊A。主題季只切ID時年齡／HP／長壽credit不變；真時間前進按季度一次處理，不在季首再初始化滿HP或重新給一段壽命。

## UI

分列HP與學院精力，顯示傷勢准入、預計休養及下一次才生效的韌性。壽命顯示不能暗示不會戰死；死亡人物保家譜與歷史入口，不能出現在在世教官、配偶、親授或軍隊名單。

依知識權限顯示健康資訊；錯誤不洩出生seed或隱藏因子。對同季事件順序不明的情況提示需核規則，不顯示臆造的最有利預估。

## 待決與准入條件

既有健康功能無新增DEC。新增出勤、文職代價、健康與職務曲線連動屬DEC-R4-05/G08，不能混入本功能。真consumer仍需核傷害catalog、同季度事件順序、健康評鑑／死亡與其他任務的實際提交接線；沒有此證據不宣稱產品已完成。

## 重入優先序與數值型別補充

所有會變更狀態的入口，先查同idempotencyKey＋payload及canonical businessEvent是否已有提交結果；已提交同內容必回原receipt，即使請求的expectedRevision已舊也不能先拒。相同key異payload必衝突；不同key同業務事件不得多領。只有尚未提交的新命令才驗目前expectedRevision；pending先查marker再續原交易，不重抽結果。這項順序優先於上文新操作驗證步驟，不能先套active／alive／未selected等前置條件把成功重送當非法新行動。

儲存型別BodyTicks為整數；Talent與能力點可有精確小數，不要求顯示點一律integer。一能力點＝10000ticks，跨單位先明確換算；中間Fraction不得從畫面ppm或浮點近似回灌。

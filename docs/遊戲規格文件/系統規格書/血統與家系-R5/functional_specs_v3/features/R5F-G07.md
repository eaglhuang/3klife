## 目的與非目標

把敵系和親、長者親授／典籍、母門教養、雙親課題落成有資格、時段、成本與服務消費者的不同選擇。社交R及政治信用服務於通行、援助、婚配准入與教官交換，與K的後代評估、出生EP及生物來源分帳。

不把四個故事渠道各算一條新遺傳公式，不免費發EP、P或五維值，不增加保留槽，不因破約抹已學知識或改已出生P，不以同姓／收養／師徒改parentUID。不自造條約N年、R損益、課題獎勵或教養席位價格。

## 社交R與政治信用帳

社交R的共同方向是年度正增上限5，退出直接遺傳加分。這不是每年自動發5，也不是已採定所有事件＋5。只有採定profile或原profile有可驗事件與數額時，才按該版年度正增cap記帳。

政治信用可被通行、援助、婚配准入、教官交換消費，但不保證每個用途有同一門檻。事件增減、破約扣值、cap適用ownerScope、對向或雙向關係、年度邊界均須原profile／採定policy明文；不能把未定值設0、−5或自創門檻。不能改姓、分家、換季就刷新同一關係的年度正增帳。

R、政治信用、K、EP各保用途和來源。R合作事件不填K合格子代，K不能自動回流出生P或教養優惠。C_TRUST的外交外部效果也不直接加R／EP。已鎖婚約來源不被之後履約事件回灌。

## 輸入輸出與建議schema

輸入為渠道選擇、雙方身份與真來源證據、已採serviceCatalog、條款／時間／成本policy、席位可用性、世界時點與expectedRevision。輸出是預約、義務進度、履約／破約狀態、可用服務、成本及政治關係事件receipt。

```text
SocialRelationLedger { relationKey, identityPolicyVersion, ownerScope,
                       profileHash, socialRState, politicalCreditState,
                       annualPositiveGainReceiptRefs, eventRefs, revision }
TeachingServicePlan { planId, channel, beneficiaryUID, providerRefs,
                      familyRefs, evidenceRefs, serviceCatalogVersion,
                      contractPolicyRef, durationPolicyRef, costPolicyRef,
                      seatReservations, status, revision }
TreatyRecord { treatyId, partyRefs, conflictEvidenceRefs, marriageRef,
               termsVersion, fulfillmentWindow, obligationRefs,
               fulfilledEventRefs, breachEventRefs, serviceEntitlementRefs }
ServiceReceipt { canonicalServiceEventId, planId, consumerRef,
                 costs, entitlementBeforeAfter, relationEffectPolicyRef,
                 payloadDigest, committedMarker }
```

此為建議schema，非現行API；未採duration、cost、relation effects只可引用待審提案，不能提交為正式合約。relationKey採哪種方向需明文，不先假定對稱或按姓名排序。

## 流程與狀態

1. 先查事件是否已提交；同key/payload或相同businessEvent返回原結果，不因舊expectedRevision拒絕已完成重送。新命令才核revision及資格。
2. 預覽列渠道、來源、實際consumer、所需時段／席位、完整義務及拒絕後果。缺任一必要policy時PROFILE_UNSUPPORTED，不預扣未定成本。
3. 確認後建立同一plan／treaty及有限資源reservation；不能同席位同時做多個教養策略各領完整成果。
4. 按真世界季度記履約證據；未滿N年不能提前領新服務。切主題季不等履約完成或重開年度額度。
5. 達條款後一次授予特定service entitlement。後續使用服務仍依consumer成本，不由entitlement暗給免費技能／研習。
6. 破約保事件與影響依採定policy執行，可停未付服務、影響名望及後續准入；不回改出生P、不抹已學知識、不把孕期關係倒填婚約來源。
7. 親授者死亡後停止新親授，保已完成成果與成本。是否留典籍／替代導師／退費依採定版本，不以「晚年傳承」故事自動補發。

## 邊界 錯誤與恢復

無真衝突史、未知母系來源、缺教案consumer、導師已死或同一事件改名皆拒適用的新服務，不耗成本。來源合法但履約失敗屬合法結果，依已採條款記成本／信用，不能把failure當無效輸入退款。

同事件換key不重發服務；異payload回IDEMPOTENCY_CONFLICT。履約尚pending時先查marker，不因網路／存檔逾時當破約或自動退款。新命令revision衝突回讀reservation與關係帳，不覆蓋別的履約進度。義務各項未定如何計合格時不得以「看來已合作」自行判完成。

## 保存 遷移與UI

保treaty原條款、來源、衝突證據、每次服務與成本、R／政治信用事件及年度帳；改名、收養、換factor root不改歷史歸屬。舊政治信用依原profile保留，不用R4新方向重新剝除曾取得的服務或倒改出生值。缺可映射來源時保持legacy可讀，不從故事敘述重建新數值。

UI分四條渠道說明收益、等待和放棄內容；顯示履約尚餘時程、服務已可用／已消費、政治後果與是否有合法替代。R和K分欄，不能用「相性」一詞掩蓋不同帳。服務預覽只輸出有權知道的來源，不能以錯誤字串洩未知factor／P。

## 待決與完整性要求

DEC-R4-08需補各渠道真consumer、N年與義務、導師／典籍、課題選擇、席位／成本與取消死亡政策。社交R／政治信用詳細事件與門檻僅可沿原profile或另採定，不因共同方向「年度正增5」便自造其他變動值。母門遺傳與K效用若加入，分別提出DEC-R4-02／01範圍變更。

20–50%兼收採用率只能是固定內容分層診斷，不是本功能普適通過門檻。須在不同任務與替代路徑下證明服務有用，不能單靠四個標籤宣稱內容已完整。

## 重入優先序與數值型別補充

所有會變更狀態的入口，先查同idempotencyKey＋payload及canonical businessEvent是否已有提交結果；已提交同內容必回原receipt，即使請求的expectedRevision已舊也不能先拒。相同key異payload必衝突；不同key同業務事件不得多領。只有尚未提交的新命令才驗目前expectedRevision；pending先查marker再續原交易，不重抽結果。這項順序優先於上文新操作驗證步驟，不能先套active／alive／未selected等前置條件把成功重送當非法新行動。

儲存型別BodyTicks為整數；Talent與能力點可有精確小數，不要求顯示點一律integer。一能力點＝10000ticks，跨單位先明確換算；中間Fraction不得從畫面ppm或浮點近似回灌。

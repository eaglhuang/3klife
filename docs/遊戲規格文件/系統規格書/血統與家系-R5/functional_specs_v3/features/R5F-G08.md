## 目的與非目標

將已開發本體能力在指定年齡、職務、傷勢與裝備情境下投影成外部表現，讓早中晚峰有不同任期價值。保存原P/B/A，投影隨時間變化不把已開發能力倒扣。

不新增武將EXP、不改出生巔峰型、不改學院收益、不直接扣INT/POL來製造健康代價、不把武職曲線冒充未定文職曲線。G06處理HP、休養、壽命與死亡，本功能只讀其結果，不為比較投影重跑受傷或死亡事件。

## 必要依賴能力

C01提供同profile的P/B/A與量尺；C02提供出生季度與asOf世界季度，不能從主題seasonId推年齡；B02提供出生固定peakType；G02提供選定畢業本體快照；G06提供在世、HP與傷勢外部倍率；B07提供已啟用外部效果字典；C05提供legacy版本；U01輸出可公開投影。C03只在保存投影快照或診斷報告時保引用，不把唯讀projectAge變成成長交易。

DEC-R4-05有效阻擋新文武職務曲線、早中晚峰差異與新增健康代價。這不擴大成G06既有HP功能的全面阻擋，也不否定可驗的legacy投影讀取。

## 輸入輸出與建議schema

輸入為人物、選定畢業A、P／出生peakType引用、asOf世界季度、role、已採曲線profile、傷勢與裝備來源、知識權限。輸出為外部能力投影與每個分量來源，或明確無可用profile；不輸出任何回寫P/A的命令。

```text
AgeProjectionRequest { personUID, bodySnapshotRef, healthRevision,
                       asOfWorldQuarter, role, projectionProfile,
                       treasureRefs, effectRefs, knowledgeRevision }
AgeProjectionProfile { profileHash, decisionRevisionRef, roleMapping,
                       peakTypeCurves, interpolationPolicy,
                       supportedAgeDomain, injuryCompositionPolicy,
                       treasureCompositionPolicy, roundingPolicy }
AgeProjectionResult { requestDigest, personUID, asOfWorldQuarter, role,
                      ageMultiplierRefs, injuryMultiplierRef,
                      bodySnapshotRef, externalProjection,
                      publicProjection, sourceRevisions,
                      status: available|unsupported|historical_only }
```

此為建議schema，非現行API。倍率使用精確有理數／版本化投影規則；BodyTicks每能力點10000。外部輸出是否以ticks儲存及最後取整須profile明文，不先用float四捨五入。裝備／傷勢／年齡組合順序尚未被本份來源完整定義，不能自行宣稱「先加裝備再乘所有倍率」等式已採。

## 歷史曲線與可用範圍

以下只用於同版R3外部STR曲線回歸，不是新文職採定表。

| 年齡 | 早峰STR | 中峰STR | 晚峰STR |
| --- | --- | --- | --- |
| 18 | 1.00 | .85 | .70 |
| 25 | 1.00 | .95 | .85 |
| 35 | .95 | 1.00 | .95 |
| 45 | .90 | .95 | 1.00 |
| 55 | .75 | .85 | .95 |
| 65 | .60 | .70 | .80 |
| 70以上 | .50 | .60 | .70 |

節點間線性插值。R3其餘四項有floor .90的歷史描述，但新文職的分項曲線／職務權重與健康代價尚未定，不能只複製STR表後自稱行政規格完成。已核完整legacy profile可按其原規則投影；資料不足的新role必須拒不支援，不取相近職務值。

同A1600、18歲、無裝備無傷的STR歷史例為1600／1360／1120。這不是P改變，也不影響相同訓練流的學院結果。

## 投影流程

1. 讀固定bodySnapshot、peakType與指定時點健康來源，驗role和profile完整。人物死亡後可查歷史as-of，不提供當期在世任職結果。
2. 由出生世界季度與asOf季度計真年齡。負年齡或未支援年齡範圍拒絕；18歲前職務不能靠延長18歲曲線繞成人准入。
3. 選已採role/trait/peakType對應曲線，在正確年齡節點插值。節點之外依profile，不作未定外插。
4. 依已採組合順序套年齡、G06傷勢及合法裝備／active效果。每層保來源與倍率，不能把外部值寫回A、當下一代遺傳來源或拿去擴技能槽。
5. 對外輸出經U01合法公開投影；未知P/A不得藉精確任務預估、排序、tooltip或delta旁路揭露。
6. 若快取，鍵至少包括personUID、body/health/裝備revision、asOf時點、role、projectionProfile及knowledgeRevision；變動任一來源不得回舊結果冒充目前表現。

## 任期比較與健康邊界

歷史比較假設同A、18至80皆存活、每年等權。STR積分早／中／晚為48.75／51.8／53.425；五能力等權為278.75／281.85／283.458333。這些是限定假設下紙面算術，不是產品實跑，也不能推成晚峰所有情境最強。

正式比較至少分短期軍事18–35、長期行政至50或80、等待接班三類，同起點、同裝備、同職務資源並報健康／出勤假設。若只用到50歲，少5年自然壽命不必然形成實際代價；不得為了使結果看來平衡直接扣P/A。任期終點、傷病路徑、職務權重未定時只列情境，不能自造勝率或收益。

## 邊界 錯誤與恢復

PROFILE_UNSUPPORTED用於缺role曲線、支持年齡或組合順序；SOURCE_INCOMPLETE用於body/health/裝備來源缺件；UNIT_MISMATCH用於把ticks當能力點或倍率相加；STATE_CONFLICT用於死者當期任職請求。錯誤不改原人物或花資源。

唯讀請求重送同快照應得同結果，不抽RNG、不增加EXP、不推季度。來源revision已變時，新請求重新投影；歷史快照仍指向舊revision並清楚標示as-of。快取／報告寫入失敗不回退或重算人物，更不把部分投影存進body欄位。

## 保存 遷移與重入

權威資料是出生／畢業body與健康／裝備事件，不是投影cache。需要保存報告時保requestDigest與所有source refs，閉包缺件不稱可回放。新曲線只影響明示版本生效後的外部投影，保舊run、舊body及歷史報告版本；不重抽peakType。

舊人物缺P時不設P=A、不刪裝備；保可用legacy路徑或拒不支持的新投影。換主題季但世界季度未變時年齡不變；世界時間推進時按新asOf投影，不重設18歲或改晚峰為早峰。

## UI

並列本體與外部表現，分項標示年齡、職務、傷勢、裝備，不把「衰退」寫成永久失去已開發能力。比較清楚顯示as-of與任期，不用終身積分掩蓋早期窗口。缺新文職曲線時說明尚無採定規則，不顯假定1.0或借用武職值。

歷史死者頁可讀其生前年份，但當期任職／出戰入口不可把歷史結果當可用角色。公開投影、排序與錯誤均經知識契約。

## 重入優先序與數值型別補充

所有會變更狀態的入口，先查同idempotencyKey＋payload及canonical businessEvent是否已有提交結果；已提交同內容必回原receipt，即使請求的expectedRevision已舊也不能先拒。相同key異payload必衝突；不同key同業務事件不得多領。只有尚未提交的新命令才驗目前expectedRevision；pending先查marker再續原交易，不重抽結果。這項順序優先於上文新操作驗證步驟，不能先套active／alive／未selected等前置條件把成功重送當非法新行動。

儲存型別BodyTicks為整數；Talent與能力點可有精確小數，不要求顯示點一律integer。一能力點＝10000ticks，跨單位先明確換算；中間Fraction不得從畫面ppm或浮點近似回灌。

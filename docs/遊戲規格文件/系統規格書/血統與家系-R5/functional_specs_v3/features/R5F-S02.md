## 目的與非目標

為下一輪主題競爭產生可驗證、可重播的戰略世界候選，讓玩家先看起點與限制，再由 S03 決定正式提交。地盤重新分配方式、出征人數、兵力國庫與裝備帶入尚未定；本文件只定候選區的資料與驗證契約。

非目標：不自選限制式亂數、不替每家保證一座城、不重抽人物、不提高敵人 P、不配偶配對、不發獎、不覆寫舊世界，也不把同資源平衡尚待研究當已成立。

## 責任 owner 與精確依賴能力

- 本功能 owner：候選世界生成／驗證器，產出 candidate 與逐條 constraint report。
- S01：只讀凍結的合法人物／家族／政治勢力快照，不要求其正式資源承接能力，因此不自動繼承 DEC-R5-S03/S04。
- S06：只消費已由合法來源證明的存續敵家與可用名冊、補入資格；消費補入選擇時需 DEC-R5-S06。
- S04：只讀本次要採的 themeId、rulesHash 與規則版本，目標判定與勝利事件不在 S02。
- C01/C04：身份分型、候選生成專屬 RNG 域與固定排序／回放，不能消耗出生及培育亂數流。
- S03：消費 validationDigest 的唯一正式世界提交 owner。逐類資源承接由 S01/S03；S02 只可引用明示資源 envelope，缺者列未知、不自行清空或全帶。

## 輸入與輸出

輸入：sourceSaveRevision、世界地理與城池 ID、themeId／rulesHash、候選生成 strategy policy、存續 family／faction 名冊、合法新家來源、凍結 seedRef／rngVersion、已採起點與難度約束，以及必要資源／名冊限制的已核引用。

輸出：候選城池歸屬、派系與人口引用、每項約束的 PASS/FAIL/UNRESOLVED、固定輸入的 candidateDigest、validationDigest、是否具正式提交所需完備性。UNRESOLVED 不等 PASS；可做提案比較但不能交可提交證書。

## 建議 schema 與不變量

- `WorldGenerationRequest`: requestId、sourceRevision、geographyVersion、themeId、rulesHash、strategyPolicyRef、survivorSnapshotRef、populationSupplyRef、difficultyPolicyRef、resourceEnvelopeRef、seedRef、rngVersion、payloadDigest。
- `CandidateWorld`: candidateId、requestId、cityAssignments、factionRosterRefs、familyRefs、originEvidenceRefs、constraintResults、candidateDigest、status。
- `CityAssignment`: cityId、ownerFactionUID、rosterRef、supplyRouteRefs。唯一領主模式下每城最多一個 owner；未分配城須在已採 policy 中合法，不默填玩家或敵家。
- `ConstraintResult`: constraintId、policyVersion、evidenceRefs、result、publicReason。連通／明示飛地、補給可行、可生存起點、城主唯一、人物不複製、政策限額均須逐項列明。
- `CandidateStatus`: proposed / policyIncomplete / generated / validationFailed / validated / stale；這些都不是正式 active world。

固定模板、限制式亂數、玩家選起點三案均只是候選。只有 strategyPolicyRef 指到有效採定決策，才能選擇其演算法。地盤分配家數、祖地參賽、補入席位、起點權重、名冊 cap、優勝家優勢與資源量不得在範例 schema 中偷填預設。

## 流程與狀態

1. 驗來源身份、地理、規則版本與必要政策；缺規則回 `policyIncomplete`。
2. 凍結來源與 seedRef；固定排序後在獨立候選區生成。任何同輸入比較保留原 request，不暗換 seed。
3. 逐條驗城主唯一、引用閉包與已採戰略約束。若需生存力判斷卻沒有資源 envelope，只能報 UNRESOLVED。
4. 任一 FAIL：保存可診斷候選及報告，舊世界不變。所有必要檢查 PASS 才標 validated。
5. UI 預覽可返回；交 S03 時附 sourceRevision 與 digests。來源變動或 policyVersion 改變則 stale，必須新預覽與明確確認，不能偷重新生成延用確認。

## 邊界 錯誤與恢復

地理缺連線、政策無解、存續家族數超起點容量、某勢力無合法活人或城被重複指定時，不採「先塞入」補救。回具體約束及不含隱藏數值的原因。無解候選不代表可擅刪家族、復活原將或壓低玩家 P。生成器自身失敗保來源與 seed；若未消耗結果可同輸入重算，已產結果應回讀，禁止為成功換 seed 冒稱原結果。

人數／軍力上限及起點難度未採時不得執行自創 cap，亦不能假設 cap=無限。兩種狀態都以未決列明。資源 envelope 缺失不阻只讀來源完整性檢查，但阻宣稱該候選正式可生存且可提交。

## 保存 遷移與重入

保存 request、policy refs、rngVersion、seedRef、規範化輸入 digest、結果與證據引用，seed 只在內部保存不給 UI。舊 candidate 不隨新 profile 默變；舊版本缺生成器時保留已存結果及原檔，標不可重生成。候選暫存不能覆蓋 active pointer，清理候選不得刪來源人物或既有季史。S03 再驗 checksum／閉包後才能切換。

## UI 與可觀察結果

展示主題規則、候選地圖、起點差異與各條約束結果，清楚標「候選，尚未套用」。人物只顯公開資料，生存力報告不反洩隱藏 P/LUK。對未定方案顯「待決」而非已勾選推薦；對無解顯可檢討的約束，不設悄悄重抽按鈕。若未來允許重新選 seed，須另有明確政策及對比較分組的影響，本版未採。

## 驗收案例

以下全部 `[NOT_RUN]`。

- **R5F-S02-P 正例**：Given 已採的連通與糧道 policy、固定地理、固定合法名冊和 seedRef=s；When 生成並再次回放；Then 每城 owner 與 constraint evidence 相同，全部必要約束逐條 PASS，active 世界 hash 未變。
- **R5F-S02-N 反例**：Given candidate 把城 X 同時指定為 faction a 和 b 的唯一領地；When 驗入；Then 唯一領主約束 FAIL，舊世界、人物與國庫全不變。
- **R5F-S02-T01 生存失敗**：Given 已採規則要求基本補給可達，而 faction a 無任何可用糧路；When 驗證；Then 拒候選，不以改人物 P 或臨時免費軍隊補 PASS。
- **R5F-S02-T02 未決邊界**：Given strategy、分地家數、roster cap 仍未採；When 請求正式候選；Then 回 policyIncomplete，未把限制式亂數或全部家族一城當預設。
- **R5F-S02-T03 資源缺口**：Given 地盤連通已驗但軍隊／國庫 envelope 未知；When 評估可生存與提交資格；Then 基本結構結果保留、相關檢查 UNRESOLVED，不聲稱整體 PASS。
- **R5F-S02-T04 重入**：Given request 已生成但回應遺失；When 同 requestId/digest 再送；Then 回原 candidate，不多消耗生成流、不換 seed；出生流 draw count 不變。
- **R5F-S02-T05 版本衝突**：Given 預覽後新增出生造成 sourceRevision 變動；When S03 驗候選；Then stale/REVISION_CONFLICT，要求新預覽，不偷補新生兒到已確認名冊。
- **R5F-S02-T06 存讀**：Given candidate 含失城但存活之家族與死者歷史；When 寫候選區後讀回；Then 活人沿原 UID、死者只歷史，不因模板重建復活。

## 待決門檻

直接依賴 DEC-R5-S02 地盤策略、DEC-R5-S06 敵家與補入資格、DEC-R5-S07 難度與動員界線。若某候選驗證需要資源量，須另引用 S01 在 DEC-R5-S03 下的明確承接結果；S02 不獨自選值。未決前可完成契約和候選比較，不得正式轉換存檔。採定後還要固定 profile／fixtures、驗真 consumer、無解與同資源策略用例，正式准入目前未核。

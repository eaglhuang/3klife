## 目的與非目標

把季終結果、承接政策與候選世界串成可恢復的交易：**預覽 → 明確確認 → 一次提交 → 回讀或失敗恢復**。不能因開啟結局、看預覽或選一個主題就清空舊世界。

非目標：不自行決定結季時點、目標達成、獎勵內容、地盤策略、帶入人數／軍隊／國庫或時間跳轉；不替 E03 建結局歷史，不替 E02 重發獎，不把 E01 結局重播視作提交。

## 責任 owner 與精確依賴能力

- 本功能 owner：換季協調與正式 active pointer 切換。它保存跨步驟交易進度，但不接管各子事件業務語義。
- S04：提供已驗目標／季終資格與 canonical event，需 DEC-R5-S01。S03 不以 UI 按鈕產生勝利。
- E03：僅對有效統一事件提供不可變 endingSnapshotRef；E01 僅顯示，兩者不再發獎。一般季成就使用 S04 的 canonical 資格，不以首次統一快照作一律前置；只有需結局成果快照的獎勵／展示才引用 E03。快照業務身份不含 schema 版，轉編碼不能成新勝利。
- E02：以 canonical business key 產生一次結算及 reward ledger，需 DEC-R5-S01/S08；即使換季失敗也不換 key 再領。
- S01：完整承接差異與不變量，正式承接消費 DEC-R5-S03/S04。
- S02：已驗候選與 validationDigest，消費 DEC-R5-S02/S06/S07。
- C03/C05：eventId/payloadDigest/expectedRevision、pending marker、閉包校驗、雙槽與原子切 pointer；不新增其產品接線完成的宣稱。
- C02 與各未完事件 owner：只有採定時間策略下逐季度結算；孕期、研習、K、婚約、健康與 run 不由 S03 複製結算。

## 輸入與輸出

輸入：from/to campaignSeasonId、sourceSaveRevision、source pointer、season eligibility evidence、settlement/ref、適用時的 ending snapshot/ref、已決 carry/time policies、candidate/ref、previewDigest、確認所綁的完整 digest、transitionId／payloadDigest／expectedRevision。

輸出：preview、policy gaps、確認可用性、交易各階段結果，以及 `committed(newPointer, previousValidPointer, receiptRef)`、`pending(statusRef)` 或明確失敗。不可把逾時回覆寫作成功，也不可把 pending 當未執行。

## 建議 schema 與不變量

- `TransitionPlan`: transitionId、fromSeasonId、toSeasonId、sourceSaveRevision、eligibilityEventRef、settlementRef、endingSnapshotRef（適用時）、carryPreviewRef、timePolicyRef、candidateRef、policyVersion、decisionRevisionRefs、planDigest、status。
- `TransitionConfirmation`: confirmationId、transitionId、confirmedPlanDigest、confirmedSourceRevision、confirmedAt、confirmationState。只針對具體預覽，缺政策不得 confirm。
- `TransitionJournal`: transitionId、payloadDigest、businessKey、journalRevision、confirmedPlanRevision、sourcePointer、confirmedSourceRevision、childReceiptRefs、transactionOwnedDeltaRefs、postSettlementBaselineRef、postSettlementRevision、expectedCommitStateStamp、preparedSlotRef、targetPointer、phase、settlementMarkerRef、writeChecksum、closureDigest、commitMarkerRef、lastError。每個子收據帶 canonical business key、owner、before/after revision、實際 delta／結果引用及 transition 關聯，不能只存「結算完成」旗標。
- `TransitionReceipt`: transitionId、from/toSeasonId、committedRevision、currentPointer、previousValidPointer、settlementReceiptRef、committedAt。

`postSettlementBaselineRef` 是含 E02 已提交結果的可校驗來源版本；若以精確 delta 代替完整快照，必須能從已確認基線加已核子收據唯一重建同一狀態。`expectedCommitStateStamp` 綁當前有效 pointer、來源 revision 與所有會影響候選的權威核心／世界引用版本；不能只比 pointer 而忽略其下原地修改的出生、死亡或資源。技術實現可採排他交易、CAS 或等價版本保護，尚未選型，安全性契約是比較與切換之間不容外部寫入被遺失。

不可變 businessKey 至少識別「來源主題季的這一次正式換季」，防換新 transport key 再提交同季。精確鍵格式待工程准入核實，但不得只靠隨機請求 ID 去重。結算鍵由 E02 管，快照鍵由 E03 管，三者互引而不合成第二套獎勵帳。

## 流程與狀態

1. `active → eligible`：接 S04 的合法資格；是否達標立即結季或可延長仍待 policy，資格不是立刻清盤。
2. `eligible → previewing`：凍結來源，取得／查詢既有結算意圖、適用時的快照引用、承接 diff 與候選。此時不以查看 UI 產生發獎副作用。若 policy 規定結算早於換季確認，也必須有獨立已授權／已定的 E02 事件流程，不能因 preview 偷觸發。
3. `previewing → previewReady | blocked`：逐類顯示人物、地盤、軍隊、國庫、裝備庫存、政治關係、時間與未完事件。任何必要政策或檢查不完備不得進確認。
4. `previewReady → confirmed`：玩家明確確認此版完整差異，綁 sourceRevision 和 planDigest；返回／取消預覽不改世界。
5. `confirmed → preparing`：先查 transition/business key 既有結果；無已提交結果的新提交才重驗 revision、eligibility、所有政策與確認 digest，建立本交易協調範圍並保存 journal。對 E02 查 marker／提交已定唯一結算，記實際 child receipt 與 delta。來源 revision 因本交易子事件從 8 變 9 不是外部衝突，但必須證明 8→9 的全部變更恰為該子收據；不能僅因 revision 剛好加一就放行。無法證明或夾帶外部事件即阻擋，已提交獎勵仍保留。
6. `preparing → written → validated`：從已校驗的 post-settlement baseline 或基線加精確子 delta 組合新槽，不從舊 preview 整包回寫資源。候選地盤及已確認 carry policy 作用在這個含獎勵的基線上；保獎勵 ledger、已付成本與依 policy 應帶入的淨結果，不因重建／恢復漏獎或再加一次。預覽須已明示本次結算影響及承接順序，實際 delta 超出所確認範圍必重新預覽確認。必要跳時的每項事件也記本交易子收據，由其 owner 一次結算。驗 checksum、引用閉包、生死、婚姻、資源帳與地盤約束後，記 expectedCommitStateStamp。
7. `validated → committed`：切換點必在排他保護下，或以 expectedCommitStateStamp 作原子的 compare-and-switch／等價驗證與切換，確保最後校驗後的外部出生、死亡、資源變更不被覆蓋。單純「先再讀一次 revision，再無條件切 pointer」不合格。保護失敗則不切指標，候選 stale，保留最新來源及本交易已提交子收據，轉重新預覽／確認。成功時保存 commit marker／收據，保上一可用槽。若底層不能原子同寫，恢復協定仍須在等價提交保護下調和指標與 marker；不得以 journal 存在代替無遺失更新保證。技術機制待核，未宣稱現有產品已實作。
8. 任一步中斷進 `pending/recovering`：先查 marker 與有效 pointer。已提交回原收據；未切換且新槽不完整則保舊槽；結果不確定時保持 pending，不重抽 seed、不自行退款或再領獎。

## 邊界 錯誤與恢復

- `PROFILE_UNSUPPORTED/POLICY_UNRESOLVED`：未定欄位全顯示，拒提交，不能默清或全帶資產。
- `REVISION_CONFLICT`：本交易已核子收據造成的 revision 變更可按上列完整變更鏈接續；外部出生／死亡、政策改動或無法歸屬的 delta 使確認／候選過時，必保最新來源並重新預覽確認，不能直接把 expectedRevision 改成最新值後沿用舊候選。若 E02 已提交則保其原收據與資源結果，不撤銷或再發。
- `IDEMPOTENCY_CONFLICT`：同 transitionId 異 payload 拒絕；新 key 指同 businessKey 回原交易或衝突，不能建立第二季。
- `SOURCE_INCOMPLETE/VALIDATION_ERROR`：缺婚姻、孕期、結算、地盤或核心資料時不切指標。
- `STORAGE_FAILURE`：保上一可用槽與 journal。結算若已由 E02 成功，不因換季寫入失敗再領／退款；恢復時沿原收據續做。
- `RESULT_PENDING`：UI 顯查詢中的實際階段，不提示「重試可再抽一次」。已 commit 後想回前季不是普通取消，需另定回退政策；本版不提供有利結果回滾與雙領路徑。

## 保存 遷移與重入

每步保存足以判定已做／未做的引用與結果，不只保存 hash 而刪內容。子事件是否完成、實際 delta 是否已包含在新槽、commit 保護的來源 stamp 必可回讀核對。重新預覽續辦使用明示的 planRevision／confirmation 修訂記錄，保同一來源季的業務身份與既有子收據；不得覆舊 payloadDigest，或用同鍵異文重送冒充已確認內容。具體續辦操作名稱與 journal 寫入機制待工程准入核實。存檔 closure 含兩家祖譜、來源版、season records、reward ledger、未完事件與 original profiles；預估容量重新量，不沿 R4 95.1MiB 當已測。legacy 無主題季身份時需明示初始化映射與遷移預覽，不從 worldSeason 猜主題序號。無法完整映射則保舊檔，拒正式換季。重入按同 transition business key 恢復，UI 重開與磁碟重讀都不能多生人、多結研習、多加 K 或多領獎。

## UI 與可觀察結果

提供四個分明狀態：查看預覽、核對並確認、提交進度、恢復結果。確認文字逐類列出實際保留／變更，特別顯示時間差和未完事件處理；不得用「重新開始」概括資產消失。缺決策顯阻擋來源，不提供可提交假按鈕。pending 顯「結果仍待確認」及查詢入口；成功顯新季身份、承接摘要與原收據。只顯已知資訊，不洩 seed 或隱藏 P。

## 驗收案例

以下全部 `[NOT_RUN]`，需故障注入、存讀及真 UI consumer 證據。

- **R5F-S03-P 重入成功**：Given transition t 已 commit 但回應遺失；When 同 t/digest 重入；Then 查 marker 回原 pointer／收據，E02 reward ledger 筆數不變，不建立第二個 toSeasonId。
- **R5F-S03-N 寫入失敗**：Given 已確認 t，在新槽尚未寫完時崩潰；When 重啟；Then 舊槽仍可讀、人物地盤未半清，未校驗新槽不得被設 current。
- **R5F-S03-T01 預覽正例**：Given 已定 policy 與合法 candidate；When 玩家只查看再取消；Then source pointer、資源、世界季度、出生／獎勵 marker 均不變。
- **R5F-S03-T02 未定反例**：Given 國庫 carry 及 time policy 未定；When 玩家要求確認；Then 列兩缺項並拒提交，不以零或全帶填值。
- **R5F-S03-T03 確認過時**：Given previewRevision=8 並已確認，背景出生令來源=9；When preparing；Then REVISION_CONFLICT，不偷重建 candidate，不沿舊確認切檔。
- **R5F-S03-T04 結算後失敗**：Given E02 已保存一次 reward 收據而新槽 checksum 失敗；When 恢復 t；Then 沿原收據與已核 post-settlement baseline 重建／驗證候選，獎勵 ledger 及應保留餘額均在，不退獎再領、不再累加分數；外部來源若另變則重新預覽，不重用過時候選。
- **R5F-S03-T05 切指標後中斷**：Given 新槽完整且 pointer 已切，回應前崩潰；When 讀 marker/pointer；Then 調和為同一已提交結果，不恢復舊槽冒稱失敗。
- **R5F-S03-T06 同鍵異文**：Given t 綁 planDigest=a；When 以同 t 送 digest=b 或新 key 再指同來源季；Then 異文衝突／既有交易回讀，不另付成本或再創季。
- **R5F-S03-T07 跳時未採**：Given 孕期、研習及 K 到期事件存在而 DEC-R5-S04 未採；When 要求切季並跳年；Then 阻擋，不只加日期亦不自動完成未完事件。
- **R5F-S03-T09 非統一主題**：Given 後勤主題有 S04 合法資格且無首次統一 E03 快照；When 所有適用政策均完備後確認換季；Then 不因不存在首次統一快照而阻擋一般成就，E02 只依其所需 evidence 唯一結算。
- **R5F-S03-T08 真閉包**：Given 新槽漏敵家祖源，該祖源也是玩家外孫祖父；When 驗 closure；Then 拒切檔，保原來源及錯誤證據。


- **R5F-S03-T10 本交易結算 revision**：Given 玩家確認 sourceRevision=8，E02 的唯一 reward event 在同交易中成功使 revision=9，且已採 carry policy 明示保留該獎勵；When S03 準備並提交新槽，之後再重入；Then journal 證明 8→9 只含該子收據、從含獎勵基線組槽，既不誤報外部衝突，也不以 revision8 舊 preview 覆獎；新槽 reward ledger 一筆、獎勵淨額恰一次，重入不再加。
- **R5F-S03-T11 最後校驗後外部出生**：Given 候選按 baselineRevision=9 驗完且 expectedCommitStateStamp 綁 revision9，外部合法出生在切指標前提交成 revision10；When S03 嘗試最後切換；Then 等價排他／CAS 保護使出生與換季有單一合法順序：若出生先成功則切換失敗、最新來源保孩子與原 E02 獎勵，須新預覽確認；不能無條件切入 revision9 候選丟掉孩子，不能只補改 expectedRevision 後續切。

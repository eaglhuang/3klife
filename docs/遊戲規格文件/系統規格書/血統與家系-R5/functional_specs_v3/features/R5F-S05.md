## 目的與非目標

將當季積分、比較分組與生涯榮譽分開，讓玩家能比較相同規則下的結果，且事件重送不會重複加分。先定本地紀錄契約，線上服務不是本輪預設範圍。

非目標：不創造獎勵、加總人物總 EP、不重評歷史功業，不宣稱已具排行榜服務、帳戶、防作弊或上傳能力。本文件不授權上傳任何存檔、排名、個人資料或對外通訊。

## 責任 owner 與精確依賴能力

- 本功能 owner：當季分數 contribution ledger、凍結分數與比較 cohort key；本地排序／呈現以公開資料投影。
- S04：供應鎖定 theme、rulesHash、主題季身份與有效完成資格；S05 不重判勝利。
- C01/C03/C05：分型、精確數值單位、canonical 事件去重、持久分數帳及來源閉包。
- U01：既有公開知識與展示投影，不以分數明細反洩未知能力。
- E02：消費 finalScoreRef 或成就 evidence 發一次獎；獎勵 ledger 與分數 ledger 分帳。E02 不再次累加本功能已記 contribution。
- S08：若未來已採可選模式，提供 modeId/version；目前不啟用其內容，只保本地比較 schema 可明示基礎模式。難度／起點影響比較時，引用其已採 policy，不偷預設相同。

## 輸入與輸出

輸入：campaignSeasonId、family/faction refs、theme/rulesHash、scorePolicyRef、mode/version、已採難度與起點分類、canonical gameplay events、event evidence、已記 ledger、已知資訊投影。

輸出：可重算當季 score、逐事件 contribution、未計／拒計原因、comparisonGroupKey、local ranking snapshot、finalizedScoreRef 或缺 policy。生涯榮譽保原獨立 record refs，不因換季清零。顯示積分不代表獎勵已領。

## 建議 schema 與不變量

- `SeasonScoreAccount`: campaignSeasonId、subjectType、subjectUID、scorePolicyVersion、rulesHash、scoreUnit、status、ledgerRef。
- `ScoreContribution`: canonicalEventId、scoreCategory、subjectUID、campaignSeasonId、sourceEvidenceRefs、exactDelta、scorePolicyRef、businessKey、committedRevision。
- `ComparisonGroup`: modeId/modeVersion、themeId/themeVersion、rulesHash、scorePolicyVersion、difficultyProfileRef、startPolicyRef、timePolicyRef 或其他實質影響的政策 refs。哪些維度可等價需採定；缺維度不宣稱可比。
- `FinalizedSeasonScore`: scoreRecordId、campaignSeasonId、subjectUID、comparisonGroupKey、exactScore、ledgerDigest、qualificationRef、finalizedAtQuarter、visibilityProjectionRef。
- `LocalLeaderboard`: boardId、comparisonGroupKey、includedRecordRefs、sortPolicyVersion、tiePolicyRef、asOfRevision、scope=`LOCAL`。

生涯 EP、家族榮譽與季積分使用不同欄位及作用域。同事蹟若同時合法貢獻多分項，必須 score policy 明示，不得換 category 或 transport key 重複領同份加分。金錢、積分與能力點不可混用。精確計算型別需 profile 指定，分數展示捨入不回灌排序。

## 流程與狀態

1. 檢查 score policy 與 comparison dimensions 完備；沒有已採分數公式就只可顯事實紀錄，不以 0 分冒充正式榜。
2. 驗 canonical evidence、主題季與身份。去重後計算 contribution，在一次提交中更新 ledger 與 aggregate；不由 UI 自傳 delta。
3. 當季可顯本地暫列，標資料範圍與尚未結算；同組再排序，不同組分頁／明確不可比較。
4. 依已採季終 policy 凍結 finalScoreRef，交 E02 使用；已結算紀錄保當時規則與結果，後來人物成長不能改分。
5. 新季另建帳，舊季與生涯紀錄都保留。線上入口不在此流程；未授權不連網、不排上傳佇列。

## 邊界 錯誤與恢復

同 rulesHash 不足以自動可比，若模式、scoreVersion 或起點政策不同仍需分組。未知 policy 或無法映射的舊分數顯「不可直接比較」，不能拿新公式改舊值。tie policy 未採時可保並列／不給唯一順位的候選展示，但不能默定勝者；正式排名阻擋至政策完備。

分數事件衝突回 IDEMPOTENCY_CONFLICT；無效證據回 SOURCE_INCOMPLETE；寫入中斷回 pending 並查 ledger marker。無效請求不扣資源或 RNG，合法業務結果依原 owner 的成本，不因分數寫入失敗倒回戰爭／出生。排名錯誤更正需要明示事件／版本政策，不能直接覆歷史。

## 保存 遷移與重入

ledger 保存事件、政策與結果，aggregate 可由同版 ledger 重算。finalized records 不隨 catalog 更新。legacy 生涯功業不搬成新季積分；有明確映射才建對應索引，無映射保原欄及版本。換季後重讀上季榜單仍指同人物 UID 與當時快照，不引用目前 P 改歷史名次。容量超候選負載以無損壓縮／分塊處理，不能丟去重鍵造成重加。

## UI 與可觀察結果

本地頁明示「本地紀錄」，分開「本季積分」「生涯榮譽」「獎勵領取狀態」。顯 mode、theme、rules、難度與比較範圍；異組有原因提示。未公開 P/LUK、隱藏因子與 seed 不進排序破同分或明細。線上功能只可標未規劃／未啟用，不用假榜或成功上傳提示造成誤解。未授權也不將檔案自動送外部服務。

## 驗收案例

以下全部 `[NOT_RUN]`。

- **R5F-S05-P 正例**：Given 已採 score policy、三筆不同合法事蹟與相同 comparisonGroupKey；When 提交並產本地榜；Then 每筆依原 policy 計一次，精確總分可由 ledger 重算，生涯 EP 值不變。
- **R5F-S05-N 混榜反例**：Given 兩筆 rulesHash 相同但一為純三國、一為未來幻想 mode，或難度不同；When 請求同榜排序；Then 分組或回不可比，不直接產統一第一名。
- **R5F-S05-T01 重送**：Given canonicalEventId=e 已加分；When 以原 key 或新 transport key 再送同業務事件；Then 回原 contribution，總分與筆數不增。
- **R5F-S05-T02 同鍵異分**：Given e 在 policy v1 有既存結果；When 客戶端把 delta 改大再送；Then 拒衝突，不採 UI 傳入的分數。
- **R5F-S05-T03 保存失敗**：Given ledger 更新寫入逾時；When 讀回 marker；Then 已提交回原結果，未定保 pending，不先補加一次。
- **R5F-S05-T04 歷史邊界**：Given 上季已凍結 s1 分數，人物本季能力提高；When 重開 s1 榜；Then 分數與快照不變，本季新帳不清生涯榮譽。
- **R5F-S05-T05 權限界線**：Given 只有本地功能且沒有上傳授權；When 完成賽季／開排行榜；Then 僅本地讀寫，無網路上傳與佇列，UI 不稱線上排名。
- **R5F-S05-T06 知識界線**：Given 兩個公開資料相同、隱藏 P/LUK 不同的個體；When 顯示名次／破同分；Then 不用未知資料改排序或曝出精確值。
- **R5F-S05-T07 未定公式**：Given scorePolicyRef 缺失；When 開正式分數榜；Then 顯政策未定與既有事實紀錄，不以全零或舊 EP 權重自造榜。

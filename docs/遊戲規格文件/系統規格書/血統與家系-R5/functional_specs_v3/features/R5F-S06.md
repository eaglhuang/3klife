## 目的與非目標

定義下一輪可用敵家如何來自存續舊族、真實後代及合法新興家族，保敵我通婚後的人物連續性，不靠每季復活原名將維持人口。

非目標：不承諾每家一定分地，不自定每季補幾家、不複製玩家強者，不做出生抽樣或季度 NPC 配對。B10 依世界季度處理配偶候選與 NPC 配對；S06 處理敵家名冊來源及補入資格，換主題季不能額外觸發一次 B10。

## 責任 owner 與精確依賴能力

- 本功能 owner：存續分類、可參與勢力名冊及新家供給計畫；不直接把候選家族加成正式城主。
- S01/C01：凍結雙方人物與家族的真 UID、父母、生死、婚姻與政治關係，無須消費資源 carry／跳時能力。
- A01：只讀失城家族的祖地存續與在世名冊；S06 不改祖地的動員成本或免攻範圍。
- B06：真後代由合法出生事件供給；已出生 UID 沿用，不直接建新小孩。B10 是獨立季度配對 owner，不因 S06 補入而重跑。
- C03/C05：新來源事件去重、原始證據與家系引用閉包；C04 僅在已採供給政策含亂數選擇時提供獨立流與回放。
- S02：接收合法候選家族／名冊，另依 DEC-R5-S02/S07 決定有誰分地、多少名額及起點。S06 的「可存續」不等「自動擁有國家」。

## 輸入與輸出

輸入：sourceRevision、family/faction/branch 映射、在世／死亡人物索引、婚姻與子代來源、祖地狀態、真出生／收養／旁系／新家來源事件、已採 supply policy 及必要的固定 seed/version。

輸出：survivor roster、家族存續分類、extinction historical refs、新家供給候選與 provenance、拒絕／缺項報告及 supplyPlanDigest。沒有補入政策時可讀既有名冊，不能新增創始人或自定人數。

## 建議 schema 與不變量

- `FamilyContinuityRecord`: familyUID、branchRefs、birthMembershipRefs、currentPoliticalMembershipRefs、livingMemberUIDs、historicalMemberRefs、continuityStatus、evidenceRevision。
- `ContinuityStatus`: surviving / refuge / extinct / unresolved。extinct 的判定必由已採定義與真資料支持；資料缺失只能 unresolved，不等已滅絕或乾淨新家。
- `EnemySupplyPlan`: supplyPlanId、targetCampaignSeasonId、sourceRevision、supplyPolicyVersion、decisionRevisionRef、candidateEntries、originEventRefs、seedRef、payloadDigest、status。
- `SupplyEntry`: familyUID 或 newFamilyProposalRef、originKind、personUIDRefs、foundingEvidenceRef、continuationEvidenceRef、eligibilityReasons、exclusions。originKind 區分 survivingExisting／actualDescendants／newFounded，不以名字推血統。
- `FoundingProposal`: foundingEventId、proposedNewFamilyUID、memberOriginRefs、templateVersion、knownAncestryStatus、unresolvedRelations。沒有新族模板採定與真來源不得持久建立。

familyUID、factionUID、factor lineage root 不混用。一族可有多政治分支，一勢力可有多族。改姓、收養、繼名與旁系的社會繼承不得改寫生物父母、舊出生歸戶或偽造 n5 連續性。死者只留歷史，不把同名字當可復用 UID。

## 流程與狀態

1. `requested → classified`：依同版資料列存續、祖地、滅絕與資料不足，雙方家族一視同仁。
2. `classified → proposed`：採定 policy 才可計算候選補入；可保留舊族／真後代，新增家族須附來源事件及模板版本。
3. `proposed → validated | policyIncomplete | sourceIncomplete`：驗去重、來源、婚姻、父母、生死與家族／政治分型。人數／出場比例未定時不生成正式補入量。
4. `validated → handedToS02`：輸出候選名冊，分地由 S02 決定；正式新家身份與進場事件提交由 C03/S03 依批准政策協同。失敗不能留一半新 UID 在核心。

同家族的在世旁系是否可接續、無人在世時能否由收養／新家繼名、何時算滅絕，均待 DEC-R5-S06，不能因「需要敵人」就擴大合法定義。若新家已採，必保新身份來源與原世界歷史，而非悄將死者改活。

## 邊界 錯誤與恢復

- 家族無活人也無合法延續證據：不產活人名冊；是否 extinct 依 policy，不造同名名將。
- 玩家女兒嫁敵家且有孩子：孩子仍引用原雙親；敵家失城不把孩子從我方或敵方家譜移除。
- 合法 family 數大於地盤可容納勢力：保完整存續資料，把分地不足交 S02，不能刪族或強配每家一城。
- 新家模板祖譜未知：保 unknown，不能標無共祖／h0 或以新姓清洗血緣；基本禁親仍由正規婚配 owner 驗。
- 更新期間有人出生／死亡：REVISION_CONFLICT，保原供給 plan，重新生成須明示新來源版本，不暗替換。

## 保存 遷移與重入

新家 event/business key 一次建立，輸入、模板、seed、來源結果均留存；回應遺失先查 marker。舊族只加存續索引，不重建人物。遷移保既有 familyUID 和生物歸戶，無法映射則 unresolved；禁止按姓氏合併、按敵我身份拆成兩個同人。冷存不能刪滅絕家族祖源，因其仍可能是活人婚姻、K、因子來源或玩家後代的祖先。

## UI 與可觀察結果

顯「存續舊族」「有史實事件的後代」「新興家族」及公開來源；未取得的因子／P 不因新敵人名冊全開。祖地與擁城分開標示；滅絕保歷史頁而非可招募列表。補入未定時告知候選未選，不顯虛構已補齊人數。無資料顯待查，不把「寒門」等稱呼作乾淨祖譜證明。

## 驗收案例

以下全部 `[NOT_RUN]`。

- **R5F-S06-P 正例**：Given 敵族 f 失城但成員 a 及其真出生子女 b 在世；When 建存續名冊；Then 沿 f/a/b 原 UID 與 birthEvent，列可用候選，不新增原名將。
- **R5F-S06-N 反例**：Given 舊名將 d 已 dead、原家族無合法延續來源；When 補入模板要求 d 原 UID 活著；Then 拒絕，不假造復活或孩子。
- **R5F-S06-T01 配對分界**：Given worldQuarterIndex=40 的 B10 配對已完成；When 只重建 campaign s2 敵家候選；Then 不再執行 B10、不新增孕期，季度仍 40。
- **R5F-S06-T02 未定供給**：Given 所有舊族分類完整但新家補入比例缺失；When 要求正式供給計畫；Then 保舊名冊可讀、回 policyIncomplete，不自選數家或 cap。
- **R5F-S06-T03 unknown 邊界**：Given 新姓模板父母來源缺失；When 驗來源；Then unresolved/SOURCE_INCOMPLETE，不標無共祖、不推成可安全婚配。
- **R5F-S06-T04 新家重入**：Given 已採 policy 下 foundingEvent=e 已提交 familyUID=n；When 換新 transport key 再送 e；Then 回 n，不多建一族或複製人。
- **R5F-S06-T05 故障恢復**：Given 新家提交逾時且結果未明；When 重啟；Then 查 marker，結果確定前不換 seed／UID 重新補入。
- **R5F-S06-T06 人口大於地盤**：Given 十個存續家族而候選地圖可用城少於家族數；When 輸出名冊；Then 保全部家系，分地另報約束，不為每家一城刪人或擴圖。
- **R5F-S06-T07 存讀遷移**：Given 一 faction 同含兩 family，且某 family 有兩 faction 分支；When 存讀；Then 映射保持多對多，birthFamily 與父母不被政治 owner 覆寫。

## 待決門檻

DEC-R5-S06 須定義滅絕、旁系／收養／新家繼名合法性、補入觸發與數量、模板來源、時點及未知資料策略。未採只能讀現有名冊及列候選界線。分地與動員另受 S02/S07，不能為完成 S06 偷選。正式 consumer／存讀與准入未核，19 DEC 不因個別規格完成而關閉。

# R5F-S07 門閥稱號及候選資格

版本：2026-11-03 逐功能規格評審稿

範圍狀態：`OPTIONAL_PROPOSAL_NOT_SELECTED`

## 目的與非目標

將門閥／郡望的敘事稱號與機制資格分開，保留提案供評審，避免稱號直接送教學加成、金因子或繞過知識限制。**本項是 OPTIONAL_PROPOSAL_NOT_SELECTED，未採定、未啟用，不是已承諾製作的玩法。**

非目標：不選郡望代數／人數／EP／藍因子門檻，不默給 +10% 教學、不創新金 ID、不因「寒門」判無共祖，不將稱號等同 held、已知、啟用或可傳。僅列可評審責任及停用契約。

## 責任 owner 與精確依賴能力

- 本功能 owner：若將來採用，管理稱號事實、候選資格結果與證據；在未採狀態只保提案，不產新機制效果。
- C01/C02：familyUID 與 factor lineage root 分型；真親子 generationDepth，不用主題季數當代數。
- C03/C05：同一候選／授稱事件一次性、版本與證據存讀；不因家族改姓刷新資格。
- U01：公開名稱／稱號與已知證據投影；機制內部評估不得反洩未知能力／因子。
- B07：現有 held／已知／啟用／可傳分離、非藍不進 H、本體 P 不回改。新增金因子必須另有字典與資格決策，不能以 S07 schema 代替治理。
- 教學／家族榮譽 owner：只讀已存在的合法事蹟與服務。若日後採加成，須定唯一作用面和真 consumer，不能把稱號狀態本身當已生效 buff。

只讀以上不變量不自動繼承各模組所有 DEC。若新效果確實改 K、教養、功業或因子資格，需列其實際受影響決策及遷移；本文件未作該擴張。

## 輸入與輸出

輸入：scope adoption evidence（目前沒有）、title catalog、已採 title／eligibility policy、家族與真親子證據、公開功業、dictionaryVersion／mechanicsProfile、知識投影。

輸出在目前狀態為 `NOT_SELECTED` 與可讀提案／缺口，不增加人物能力或資格。若日後採用，才輸出 TitleRecord、CandidateEligibility、可解釋且不越權的公共展示，以及獨立效果需求引用；效果發放交既有合法 owner。

## 建議 schema 與不變量

- `NobilityFeatureState`: adoptionStatus=`NOT_SELECTED`、adoptionDecisionRef=null、policyRef=null、effectsEnabled=false。此為本稿狀態描述，不表示已在產品新增此旗標。
- `TitleRecord`: titleRecordId、familyUID、titleCatalogId、sourceEventRef、policyVersion、awardedAtQuarter、publicDisplayName。舊既有敘事稱號可原樣保存，不自動獲新資格。
- `CandidateEligibility`: candidateId、subjectRef、eligibilityKind、policyRef、evidenceRefs、result、reasonProjection、status。eligible 與 acquired/held/active 不得合併。
- `OptionalEffectRequest`: requestedEffectKind、recipientRef、qualifiedEventRef、approvedPolicyRef、dictionaryVersion、consumerRef。沒有所有必要採定引用時必拒發送；不存在預設 +10% 欄位或新金因子 ID。

不能一邊以四代三人 EP75、一邊以三代四人 EP75 加三藍同時宣稱定案。金資格 75／85、課業 +10% 均是衝突候選，不是文字釐清。任何候選表只能隔離試算，不能寫入人物、因子、券或教學成本。

## 流程與狀態

1. `notSelected`：評審提案與衝突；不能因設定檔存在而啟用玩法。
2. 取得明確採定證據後才可能 `policyPending → policyReady`；需完整門檻、作用面、來源與遷移，不只口頭採用名稱。
3. 在未來授權實作中，依固定 policy 評估家族證據；缺祖譜／條件資料回 unresolved，不能當零或不具資格直接洩漏。
4. 稱號授予與機制資格分別提交唯一事件；有資格不等自動獲得／啟用因子。外部效果需另一具名 consumer 按同版規則處理。
5. 反覆開頁只讀投影，不能重評舊 EP、重授券或加成。

以上第2至4步皆條件式設計，不是本輪已批准建置的流程。

## 邊界 錯誤與恢復

未選提案請求授稱／加成回 FEATURE_NOT_SELECTED；採定引用缺失回 PROFILE_UNSUPPORTED。祖譜不完整不能以稱號補證明。若公開標籤會使玩家推出未知精確門檻達成，必須先有合法揭露規則，否則不發布會洩密的資格結果；不能用「稱號公開」當知識豁免。

相同 family 改姓、合併政治勢力、斷一種 factor 鏈，均不能刷新既有授稱 business key。錯誤與 UI 不回隱藏 factorID/P/LUK。持久事件逾時先查 marker，已提交同鍵同文回原結果，revision 僅驗新提交；無效請求無成本、回合、RNG 消耗。

## 保存 遷移與重入

未採期間不為既有存檔注入新稱號效果。若未來採用，保舊 title、原 profile、已有因子與知識，新增索引不重算出生 P／A。候選資格版本與授予事件留史；改門檻不得暗收回舊成就或補發未授權利益，需明示 migration policy。字典新 ID 沒有映射時拒新增，不用近似 ID 代替。授稱、發因子、教學服務各有不同 business key 與一次性結果，重入不能多領。

## UI 與可觀察結果

本稿提案顯「未採定」，不可展示為可解鎖功能或已有效加成。若未來採用，家族稱號、候選資格、已取得效果分欄；顯公開理由與來源，不列未查精確 P／金因子暗碼。既有敘事稱號可照舊顯示，但需避免暗示享有尚未採定機制。

## 驗收案例

以下全部 `[NOT_RUN]`；將來採用分支的已採 policy 僅是 fixture 前提。

- **R5F-S07-P 停用正例**：Given adoptionStatus=NOT_SELECTED；When 開提案／家族頁；Then 保既有資料，顯未採狀態，教學倍率、P、held、金資格與券均不變。
- **R5F-S07-N 反例**：Given 敘事已有「郡望」稱號但 DEC-R5-S10 未採；When 請求 +10% 教學或新金 ID；Then FEATURE_NOT_SELECTED/PROFILE_UNSUPPORTED，不授效果。
- **R5F-S07-T01 條件衝突**：Given 同時提供四代三人與三代四人的兩份提案；When 要凍結資格 policy；Then 回未決衝突，不自選較新檔或同時採兩套。
- **R5F-S07-T02 知識邊界**：Given 兩家公開資訊相同但隱藏因子不同；When 產公開名稱及資格提示；Then 不因隱藏值輸出可反推未知因子的不同提示，未定揭露時不發布結果。
- **R5F-S07-T03 代數邊界**：Given 同一真親子鏈跨五主題季但只兩親子邊；When 未來已採 policy 評估代數；Then 讀真親子邊，不把五次換季當五代。
- **R5F-S07-T04 未來重入**：Given 將來有已採授稱事件 e 並提交成功；When 同 e 重送／改姓後重送；Then 回原 TitleRecord，不另發因子或券，先查結果不因新 revision 誤判未提交。
- **R5F-S07-T05 未來寫入失敗**：Given 授稱寫入逾時；When 恢復；Then 查 marker，未知保持 pending，不以新 key 重授。
- **R5F-S07-T06 遷移**：Given legacy 已有稱號與舊因子；When 只增加提案資料索引；Then 原 P、A、held、效果與知識不變，未新增金 ID。

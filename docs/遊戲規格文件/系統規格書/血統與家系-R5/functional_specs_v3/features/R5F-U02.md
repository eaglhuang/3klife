# R5F-U02 情報市場與查券｜獨立功能規格 v3（已審條件版）

## 狀態與範圍
文件內容狀態：CONTENT_REVIEWED_WITH_OPEN_DECISIONS。implementationReady：false。現行實作／consumer：NOT_VERIFIED；產品測試：NOT_RUN；產品驗收：NOT_ASSESSED。
R5F 僅文件功能 ID，非已登記 ATM 工單。全部範圍內工作文件、清單、獨立規格完成後，才能評估產品編碼；相關決策與正常施工准入另須滿足。以下擬議介面／狀態名稱不宣稱產品已存在。

## 1. 目的、責任與非目標
管理查券取得、消費、史官工時、知識揭露及來源帳；不替DEC-R4-06定新價格或供給。讓查驗成本與永久資訊進展可追溯。

## 2. 規範來源與優先關係
來源：R4工程§24；R5模組04。完整基線見 [R4 工程](../../publication_candidate/11_R4歷史基線_工程驗收.md) 與 [R4 玩法](../../publication_candidate/10_R4歷史基線_玩法.md)，R5 題目模組見 ../../publication_candidate/。本份細分原入口，不另計同一成果兩次。R5明示修正優先；原文標候選／legacy／待決者不因本份引用升格。歷史紙面驗算結果非本次產品PASS，可重跑歷史驗算附件未包含於原基線。

## 3. 輸入、輸出與資料契約
輸入：公開候選池、已知資訊、完整成本/工時/取消/owner政策、所有來源券帳；只能從合法事件取得。

輸出：一次cost收據與已知增量；或明確缺政策不開始。知識事件不是新生P事件。

擬議schema與型別：VoucherLot {lotId,sourceEventId,ownerScope,profileRevision,legacyBalance,available,reserved}; QueryPlan {queryId,targetUID,traitOrLUK,prerequisiteKnowledge,costPolicy,workTimePolicy,expectedRevision}; KnowledgeDelta {field,valueOrRange,evidenceEvent}; QueryState proposed=preview|reserved|working|committed|cancelled|pending。

## 4. 正常流程及狀態邊界
1. 列全來源：新局、完成年度整理、功業、託夢13/25歲及無對象轉券、家傳/開宗立派、百家之血、名號等。每入口綁事件與profile，不把歷史存在等於全新數字已定。
2. preview核目標/前置knowledge/ownerScope/工時，明示本次揭露範圍；不從hidden排名替玩家挑券目標。
3. 若套既有R3 fixture：新局3券＋實完成250次年度任務250券=253基本供給；全新目標五P+LUK需8券、有LUK月旦前置需6券；六深查6季，月旦時長未明。僅歷史量尺，不作R5缺值fallback。
4. 提交時驗revision，依已採policy保留成本及工時；完成時C03同時寫扣券/事件/knowledge，已知不因新季失效。
5. 取消/中斷必按所選policy列退款與已耗工時；policy未定就不啟動可收費查驗，不猜免費取消或一季。
6. 跨家族分支不能重設發券epoch刷首領；舊券另帳，不因新cap消滅餘額。

## 5. 失敗、取消與恢復
PROFILE_UNSUPPORTED缺價格/月旦母數/工時/取消政策拒付費啟動；REVISION_CONFLICT保留原帳；RESULT_PENDING先查事件不再扣券；同發券businessEvent新key不二發。無券不意味基本婚配不可用，但未知祖譜仍須禁親核驗。

## 6. 保存、遷移與可重入
本功能唯一knowledge揭露與券流水領域owner；G/B/E來源只發合格來源事件，不另加券。C03提交。遷移保來源與已知聯集，供給cap變更需決策不得清舊券。

## 7. UI／可見資訊
顯餘券/保留券/舊券、查什麼、工時、取消代價與可見前置；推薦不得偷用hidden值。入口缺件提示需哪一政策，不誘導重複消費。

## 8. 依賴能力及待決閘門
C01身份/profile；U01公開投影不依其新教學DEC；C02季度工時；C03冪等；B08/G07/E02等僅提供實際可核來源事件。DEC06為經濟政策阻擋，與既有已知資料顯示分離。

明列決策：DEC-R4-06

## 12. 查驗狀態轉移與原子效果

| 轉移 | 前提 | 券／工時／知識效果 |
| --- | --- | --- |
| 無→preview | 公開資料可取得 | 全部零寫入，不占券不耗工時 |
| preview→reserved | 完整cost/time/cancel政策、足額券、合法前置、revision一致 | 依政策保留額度，尚無揭露；不得缺policy就reserve |
| reserved→working | 執行起點與工時扣法已定 | 保留轉正式扣除的時點由policy明列；不默認reserve已消耗 |
| working→committed | 合法工時完成且C03同筆提交 | 依policy確認扣額並記knowledge與收據，恰一次 |
| reserved/working→cancelled | 採定取消政策及可確認未提交 | 依policy釋放未耗保留／保留已耗成本與工時；不擅定全退或全扣 |
| 任一提交中→pending | 結果不確定 | 鎖定同業務意圖，禁止退款、第二次reserve或另key重開 |
| pending→committed/原未提交狀態 | 已查到可證marker或非提交結果 | 回原收據或依法恢復；不猜失敗 |

已知重查先預覽明示現有knowledge，不默認再次花券；若某服務允許重查，其用途與成本仍須policy，不能再次揭同值就再收費。對同目標/同trait並發，以knowledgeRevision及資源revision驗新提交；先查已提交重入，再驗revision。第二件不得在第一件已揭後默默扣費買相同知識。

新增案例全部NOT_RUN：
- U02-V3-07 Given缺取消policy；When reserve；Then PROFILE_UNSUPPORTED且available/reserved不動。
- U02-V3-08 Given前置月旦未滿或餘券不足；When新查驗；Then拒啟動且工時/knowledge不變，不洩未知LUK。
- U02-V3-09 Given同目標trait兩個不同請求競態；When第一件已完成；Then第二件重讀知識，不自動重扣；合法同key重送仍回第一件收據。
- U02-V3-10 Givenworking時取消；When已有完整policy；Then只按該policy記已耗與釋放，不新增知識、不猜免費退款。
- U02-V3-11 Given達cap的新來源發券且overflow政策缺；When發券；Then拒該入口，不丟券、不自動兌現；舊券另帳保留。
- U02-V3-12 Givenpending有reserved額度；When使用者重開查詢或取消；Then先查原結果，不能釋放後雙花。

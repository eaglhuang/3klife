# 名冊與重複流轉報告

版本：`eaglhuang/3klife@96a83124094d3b2485bfb749ef37d567ad834559`。日期：2026-11-04 UTC。範圍：G02、G14；G01 只延伸到初始名冊來源及建局入口。

## 結論

44 個 probe 全部重現預期觀察，但包括反例，不是 44 個功能通過。G02/G14 全域驗收仍為 **NOT_RUN**。主要尚未閉合的是復生分流與真實版本身分 consumer，不是轉生 +1 算式。

1. **同 UID 死者/退役者再抽，不會復生。** 已死亡武將再抽仍 `dead`，轉數由 1→2，名冊仍 1 筆；退役教官仍 `isMentorCard=true` 並不可出戰。原 caller 沒有建立新 UID 或套用 reviveRetrain。RI09–10。
2. **圖鑑把 runtime id 當成版本身分。** 同模板 `Zhao_Yun_V1` 的 `u-1/u-2` 兩個個體，Lobby 使用的暫定 mapper 產生 `U_1_V1/U_2_V1`，甚至分成兩個血源；沒有使用輸入 templateId/bloodlineId。RI26–27。此檔明示暫定，不能當成正式版本系統完成。
3. **職能判斷接線不一致。** `Support→Mentor` 正規化已接入名冊，但出戰資格只擋 `isMentorCard`，沒有擋 role=Mentor。235 筆正式 generals 資料中 94 筆 Support，正規化後 94 筆全被該出戰資格函式接受。RI15–16。這是資料＋consumer 的可重現反例；未聲稱正式 UI 已實際出戰。
4. **去重沒有在所有存取層維持。** GameSession 入冊及 PersonRegistry 分別按 id/uid 去重，但 PlayerRosterService.addGenerals、replaceAll、reload 不去重。既有兩筆同 UID 在 rebirth 後，兩筆內容都被最後一筆覆寫。RI11、23。

## 來源與身分關係

- [武將規格](https://github.com/eaglhuang/3klife/blob/96a83124094d3b2485bfb749ef37d567ad834559/docs/遊戲規格文件/系統規格書/武將系統.md#L152-L180) 把 UID 視為唯一個體、Template_ID 視為模板；[同名規格](https://github.com/eaglhuang/3klife/blob/96a83124094d3b2485bfb749ef37d567ad834559/docs/遊戲規格文件/系統規格書/同名武將系統.md#L8-L19) 要求版本有獨立 Template_ID、同名版本共用 Bloodline_ID。
- GeneralConfig 是 `id` 加 optional `templateId` / `bloodlineId`。PersonRegistry model 的 uid 註解允許真實武將 kebab id；service 以 uid 做 Map，不按模板排他。兩個同模板不同 UID 可登記，讀出副本不會污染原紀錄（RI20）。
- [enrollGenerals 3668–3729](https://github.com/eaglhuang/3klife/blob/96a83124094d3b2485bfb749ef37d567ad834559/assets/scripts/core/managers/GameSession.ts#L3668-L3729) 只依 id 決定 duplicate。若 caller 提供不同 id，同模板/不同版本皆可同時入冊；相同 id 的 incoming name/template 等不會覆寫，改走 duplicate 分支（RI01–03）。
- 這不等於真實抽卡已能生成同模板多個個體。[LocalGachaService 445–459](https://github.com/eaglhuang/3klife/blob/96a83124094d3b2485bfb749ef37d567ad834559/assets/scripts/core/services/LocalGachaService.ts#L445-L459) clone 抽出的既有 GeneralConfig，未在這條路徑產新 UID。正式 235 筆資料的 id、templateId、bloodlineId、name 各自全唯一，沒有真實多版本資料可驗（RI28）。

## G14：重複流轉及數值

### 已動態成立的局部行為

- 同批首次＋6 張重複：新增 1 位，轉數回報 `2,3,4,5,5,5`，後兩次 overflow。固定 epic 持有者總得 1200 結義點（RI04）；跨批逐次與同批結算最後名冊一致（RI05）。
- 重複轉生重新擲第 2/3 戰法，既有戰法可加經驗。因子等級、原本 str 不會隨轉數變動；奧義欄位 unlockReincarnation 依轉數重算（RI06）。這沒有驗證其他培育公式是否消費 attributeCap/trainingChances。
- 初次入冊不強制寫 rebirthCount=1；Rebirth helper 把缺欄位視為 1。英雄第一次 duplicate→2 轉；教官第一次 duplicate 從 ★0→★1。不可混為同一階梯（RI42）。
- 滿轉獎勵依**既有持有者** rarity，不採 incoming rarity（RI07）。common/rare/epic/legendary/mythic 對應 100/300/600/1200/1200，未知回 100（RI08）。[OverflowBond 8–26](https://github.com/eaglhuang/3klife/blob/96a83124094d3b2485bfb749ef37d567ad834559/assets/scripts/core/systems/OverflowBond.ts#L8-L26) 明示這組溢出金額為待裁決暫定值，不是正式規格已定。
- Rebirth 的 4 轉上限採 1350、5 轉 1500，原檔明示與轉蛋規格的 1250/1400 不一致，聲稱採 PM 奧義表裁定。此處只驗實作，不將程式註解升格成使用者裁決證據。

### 教官與英雄分池

[原 Lobby enroll arrow 413–424](https://github.com/eaglhuang/3klife/blob/96a83124094d3b2485bfb749ef37d567ad834559/assets/scripts/ui/scenes/LobbyScene.ts#L413-L424) 被完整抽出執行：mentor-pool 不進武將名冊；其他池進 enrollGenerals，且都排教官補寫 journal（RI37）。MentorSupportCatalog 又只接受 mentor-pool。以正式趙雲支援卡連得 7 張，只有一張持有卡，升至 ★5，第 7 張轉 500 score；一般 hero-pool 不產教官卡（RI38）。此處未跑 journal 崩潰重試與正式雙存檔 atomicity，不能將局部分流推廣成「永不串帳」。

### 復生／灌注未形成完整閉環

[正式補遺 7–31](https://github.com/eaglhuang/3klife/blob/96a83124094d3b2485bfb749ef37d567ad834559/docs/遊戲規格文件/系統規格書/重複卡分流與血脈灌注補遺_2026-04-04.md#L7-L31) 要求重複同名卡可選「復生重練」或「血脈灌注」。

- ReviveRetrain helper 能回傳 caller 指定的新 UID、同 template、原 spirit UID 與 +1 轉（RI39）。它不保證 UID 唯一，也接受空新 UID（RI40）；註解把唯一性交給 caller。
- BloodlineInfusion helper 只回傳 card 的血脈/虎符等級 +1 及濃度 +value，不創造新個體、不改 input（RI41）。沒有重做血統/融合公式。
- **實際已檢查的抽卡入口**仍只走原本 enrollGenerals；沒有上述選擇。死者/退役者再抽會卡在原身分。不能把 helper 單測當作抽卡復生已通。
- 同 commit [PROG-2-1064 13、26–28](https://github.com/eaglhuang/3klife/blob/96a83124094d3b2485bfb749ef37d567ad834559/docs/agent-briefs/tasks/PROG/PROG-2-1064.md#L13-L28) 自己記錄「新本體存檔及抽卡彈窗接線未做」。這是來源內部進度佐證，與 caller/probe 結果相符，不是僅憑搜尋缺席判斷全 repo 無實作。

## G02：consumer 與存讀

- 收藏和主將均以 id 定位，不會因同 template 而連動另一 UID（RI13）。死亡、退役旗標、未畢業子嗣、精力 <30、培育中可同時回報封鎖原因（RI14）。試用旗標本身不禁止戰鬥（RI17），本包不推定所有傭兵行為限制皆已驗。
- [BattleRoster 130–139](https://github.com/eaglhuang/3klife/blob/96a83124094d3b2485bfb749ef37d567ad834559/assets/scripts/core/systems/BattleRoster.ts#L130-L139) 的 role-only 漏口對照 [GeneralRole 17–27](https://github.com/eaglhuang/3klife/blob/96a83124094d3b2485bfb749ef37d567ad834559/assets/scripts/core/models/GeneralRole.ts#L17-L27) 與武將規格的專業教官路線；需要統一 role 與 isMentorCard 的 domain 契約。
- SortieDeploy 346–372 正常擋同血源、同 UID 兼任角色（RI02、19）。血源缺失或空字串則不參與比較（RI18），故資料完整性是規則有效前提。沒有把單一出戰資格函式誤稱成編隊檢查。
- 正式 GeneralVersionGallery helper 按 Template_ID 判 owned、Bloodline_ID 分組並排序，V1/V2 fixture 正常（RI25）。但 [Lobby 4945](https://github.com/eaglhuang/3klife/blob/96a83124094d3b2485bfb749ef37d567ad834559/assets/scripts/ui/scenes/LobbyScene.ts#L4945) 接的是 [ProvisionalGeneralVersions 28–56](https://github.com/eaglhuang/3klife/blob/96a83124094d3b2485bfb749ef37d567ad834559/assets/scripts/core/systems/ProvisionalGeneralVersions.ts#L28-L56)。兩者不能混算。後者還把 `a-b` / `a_b` 正規化成同一版本並丟後者（RI27）。
- PlayerRosterService 完整原模組在記憶體 storage fixture 中可存讀多 UID 及因子，getAll 深複製保護因子（RI22）。但 add/replace/load 沒有 UID 去重（RI23）；寫入失敗會記警告，cache 已 2 人、重新載入只剩原本 1 人（RI24）。這是 storage fixture 的失敗邊界，不是正式磁碟故障 E2E。
- GameSession duplicate-only 轉生沒有 RosterChanged 事件（RI35）。addGenerals 的 save 拋錯會傳出，但記憶體轉數已增加、不回滾（RI34）。具體 UI 刷新或交易 retry 後果未測。
- PersonRegistry 存在兩份不同 PersonRecord 定義：[model 17–20](https://github.com/eaglhuang/3klife/blob/96a83124094d3b2485bfb749ef37d567ad834559/assets/scripts/core/models/PersonRegistry.ts#L17-L20) 允許虛擬祖先 template_id=null，但 [service 29–35](https://github.com/eaglhuang/3klife/blob/96a83124094d3b2485bfb749ef37d567ad834559/assets/scripts/core/services/PersonRegistry.ts#L29-L35) 拒絕（RI21）。未證明正式虛擬祖先管線一定呼叫此 service，分類為契約不一致而非已發生資料損失。

## G01：只檢查名冊建局邊界

- StarterRosterService 選六個固定 existing id、深複製；可選紅顏只追加一次。缺少/重複資料或必需數值無效會先拒絕（RI30–31）。
- startNewGameWithStarters 原方法是**開新局並 replaceAll**，不是領獎/merge API。兩次呼叫仍為 6 人，但中間取得的其他武將會消失（RI32）。這是明示 API 語意，不直接定性正常開場誤覆寫 bug。
- 設主將失敗在替換名冊之後；注入 false 時拋錯但已替換（RI33）。完整 startNewGame 只使用 recording fixture，沒有宣稱整個世界狀態或保存交易已測。
- DestinyPool 原 caller 會拒絕未 locked 狀態（RI43），但已 locked 狀態可重複呼叫且沒有 consumed guard，兩次都會重建名冊（RI44）。是否正式 UI 在重入/存讀時確保只呼叫一次 **NOT_RUN**；不把 direct-call 反例誇大成首局必然重發。

# 三國家族育成與主題賽季循環

C2 R5 模組化規格總綱

小豆　2026 年 11 月 3 日　｜　供設計評審與分題實作規劃使用

R5 不再做成一份巨大的施工工單。本次交付由這份精簡總綱、七個功能主題模組、決策與證據附錄構成。每個功能都有輸入、輸出、依賴、錯誤邊界與 Given／When／Then 驗收，可指定一個功能交給另一位 AI 核對，而不必讓它自行猜整本規則。

### 核心方向

第一次統一天下有破關與家族榮譽結算；之後透過主題賽季重新競爭。人物與家族不是一起重置：敵我家族、婚姻、跨族子代、出生潛力及歷史持續存在。死者保留歷史，不因此復活。

地盤如何重新配置、軍隊與國庫帶多少、換季是否推進歷法，仍未選定。本稿建議評審「中國地圖主題季＋限制式地盤重組＋有成本的祖地再起」，但推薦不是批准，也不直接寫入產品預設。

## 1 模組怎麼拆與交給誰

共用身份、時鐘、保存規則只在模組 01 定義。其他模組引用它，不各自發明新的 P 單位、人物 ID 或「季」。細節保存在主題 Markdown，總綱不重抄全部公式。

| 模組 | 責任與功能 ID | 獨立交付邊界 |
| --- | --- | --- |
| 01 共同契約 | C01–C03<br>身份單位、時鐘、保存 | 共用型別與引用／交易規格 |
| 02 出生血統 | B01–B05<br>祖源、H與EP、保留與傳星、親緣、K | 固定 profile 的算法與候選比較；未定參數隔離 |
| 03 育成研習 | G01–G03<br>回合、代管畢業、研習教養 | 共同資源與結果一次結算，不新增免費行動 |
| 04 知識介面 | U01–U02<br>公開投影、教學、查券 | 未知不洩漏；教學與真正資格分開 |
| 05 首次結局 | E01–E02<br>統一展示、成就與獎勵 | 結局展示可獨立評審，不依賴 K 或祖地定值 |
| 06 主題賽季 | S01–S03<br>家系承接、地盤候選、換季提交 | 預覽先行；承接／跳時／起點政策未定不正式轉檔 |
| 07 祖地再起 | A01–A02<br>存續狀態、動員與反制 | 失城不刪家族；免攻祖地不等無敵軍隊 |
| 08 決策附錄 | 九個 DEC-R4＋十個 DEC-R5-S | 保留衝突、候選及海外擴充界線 |
| 09 證據驗收 | 來源 pin、R5S01–16總情境 | 記原始限制，不把文件案例寫成產品 PASS |

完整 ID 以 R5F- 為前綴，例如 R5F-E01。feature_index.json 是分派入口，acceptance_cases.json 是待執行案例。01–07 為功能模組；08–09 是評審附錄，不是另外兩個大產品工作。

## 2 共同不變量與來源裁決

| 項目 | R5 必須維持的邊界 |
| --- | --- |
| 身份與家系 | personUID、父母、生死、婚姻與跨族子代保持可追溯；family／faction／factor root 不混型 |
| 能力單位 | Talent 0–100；P 為 0–2000 能力點；每點 10000 BodyTicks。P1600 等於16000000 ticks |
| 先天與後天 | 出生 P 固定；A≤P；裝備、年齡及傷病為外部投影，不重抽 P 或倒扣已開發 A |
| 祖位與持有 | 子代三代14位置；雙親各14共28風險位置；位置保留、效果去重；held≤6不是十藍全持有 |
| 三種季與真代數 | 世界季度、學院36 turn、主題seasonId分欄；換季次數不能充當親子邊或n5 |
| 知識與回放 | 已知不藏回；未知不因專家模式免費揭；相同業務事件不雙領、不重抽 |
| 未決值 | 完整profile缺必要決策時拒絕，不以0、舊R3或最近表列補齊 |

權威順序：本輪明確使用者方向 → 未被改動的 R4 不變量 → 同 profile 的歷史數值基線；新 GitHub 規格與外部 AI 回答若新增參數或彼此衝突，保留候選而不自動覆蓋。外部文件寫「定案」不能取代使用者決策。

已修正的主要衝突包括：P 單位、H 不是健康任期、m 不是1–5星、14／28／30祖位口徑、36回合不是36季度、auto .5只作用教官額外TP，以及G3的K滿額算例。細節見模組02／03／08，來源及未重述基線覆蓋見模組09。

原 R4 的可重播算法、有限族譜見證不等自然人口或產品E2E。本版沒有把文件算術結果升格為遊戲已平衡。每個模組只被真正依賴的 DEC 阻擋，不需要等所有決策才寫出獨立功能規格。

## 3 統一後的新循環

建議流程：選本季主題 → 配置當季班底 → 聯姻育成補缺 → 治理征戰 → 首通或季終結算 → 保存家族列傳與獎勵 → 預覽下一季承接政策 → 確認後產生新競爭世界。這是延續家族的新賽局，不是把原史實名將全員復活。

### 首次結局要看見自己的成果

展示統一日期與版圖、功臣、成年配偶與家學／外交貢獻、軍種、優秀自育後代及當時數值與戰績。結局快照與人物現況分開，後來改名、投敵或死亡不覆掉舊功臣表。重播動畫不得重發首通獎勵。

### 最重要的跨季例子

玩家女兒甲嫁入敵家乙並生下丙。敵家失城或換到新起點後，甲乙丙仍為原 UID，丙的雙親、出生P與來源不變。軍事陣營或同盟是否續約是政治政策，不可用它重寫生物家譜。

| 地盤方案 | 取捨 |
| --- | --- |
| 固定模板 | 容易理解與驗證，但重複感高；不能復活模板中的死者 |
| 限制式亂數 建議 | 保新鮮，但要驗連通、糧道、生存性、領主唯一與同seed回放 |
| 玩家選起點難度 | 可自我挑戰；榜單需按規則分組，不能直接混比 |

祖地處理「失城但家族還在」；主題季處理「統一後怎麼重新競爭」。祖地可醞釀民兵與地方聯盟，但部署到地圖的隊伍與補給需可被反制；強軍師奪城仍需機會、內應與資源，不能定時無預警換掉城主。

海外與跨時代人物保留為後續可選討論。先驗中國地圖的循環，不把全球美術與新兵種成本變成眼前續玩的必要前置。

## 4 九項原決策只阻擋相關功能

DEC-R4 編號與未決狀態保留。這不是把舊批准全部重問，也不是要求先完成九題才能做任何規格；右欄指出真正受影響的功能。

| ID | 尚待明確的內容 | 主要影響 |
| --- | --- | --- |
| 01 K | 窗口、合格定義、作用、成本；Q06與G3非同式 | B05及採K收益的功能 |
| 02 保留席位 | 祖源資格、母門復興、費用／工時、免費家傳遷移 | B03、G03 |
| 03 履歷純化 | h回復、近外風險、m增量／率與上限 | B02、B04 |
| 04 研習n5 | A／B、attempt數、4／8季度、n5加成 | B03、G03 |
| 05 年齡職務 | 文武曲線與健康代價；P/A不倒扣 | 未來職務投影，不阻首通快照 |
| 06 情報經濟 | 查券入口、定價、工時、月旦母數與揭露 | U02 |
| 07 教學資格 | auto門檻、視圖與知識分層、儀式時點 | G02、U01新開放政策 |
| 08 社會教養 | 導師、條約、課題真正效果及成本 | G03相關渠道 |
| 09 EP | 社交R退出後總EP分項、資格事件 | B02完整出生profile |

不依賴K的例子：R5F-E01首次結局展示，只需已確認勝利事件、已知人物／戰史及快照規則。K未定不應阻擋它的資料與介面規格；首通獎勵定值則由E02另管。

K可以先規定穩定family pair、全出生cohort與一次finalize，再比較候選公式；但不先給未決折扣或成長收益。地盤也可以先定候選驗證接口，正式重排須等對應S決策。

## 5 主題賽季新增決策

使用者已提出主題季與雙方家族延續。下列政策仍是具體設計選擇，本稿未代選。DEC-R5-S與九項原DEC分開，避免相同編號表示不同問題。

| ID | 要決定的政策 | 目前推薦或邊界 |
| --- | --- | --- |
| S01 | 何時結季與續玩 | 達標可看結算／預覽；延長或強制截止待定 |
| S02 | 下一季地盤 | 優先評審限制式亂數；非已批准 |
| S03 | 兵力國庫裝備承接 | 逐類carry/reset/convert，不默認清空或全部帶入 |
| S04 | 歷法推進 | 不跳時或逐季結算二擇；孕期研習K同時鐘 |
| S05 | 祖地與再起 | 有前兆、成本、損失與反制；祖地免攻不等兵免傷 |
| S06 | 存續敵家與滅族 | 舊族、真後代與新家供給；死者不復活 |
| S07 | 動員上限與難度 | 先驗資源取捨，再決cap與帶入優勢 |
| S08 | 獎勵排行榜 | 當季與生涯分帳；線上服務另範圍 |
| S09 | 海外幻想模式 | 可選後續擴充，純三國循環優先 |
| S10 | 郡望與金因子 | 三代／四代、成材人數、+10%及新ID等需一致 |

建議請外部設計者先回答四件事：逐欄承接政策；含跨族婚姻的三個換季實例；季終／跳時／出山的成本規則；相同資源下老牌與新家都可競爭的機制。回覆須列明選案、拒案、參數單位、生效時點及舊檔遷移。

不能用「永久保留」含糊帶過已死亡人物，也不能用「重新開始」含糊抹掉婚姻子代。可自由修改本稿建議，不需為了格式被迫在預選答案中選一個。

## 6 交接 驗收與閱讀方法

### 每次只承接一個有邊界的功能

先從feature_index.json指定R5F-*；讀同主題Markdown與共同契約；核對真caller、既有存檔與同版profile；只處理相關待決；完成正常准入後，才進實作、測試與獨審。不得把文件ID當正式工單，也不能把提案接口當已存在程式。

| 交接項 | 必須回報 |
| --- | --- |
| 輸入與輸出 | 必要欄位、未知與0區別、事件身份、profile版本 |
| 依賴與狀態 | 規格可拆／DEC待定／施工准入分開，列真阻擋 |
| 驗收 | 40條GWT為NOT_RUN；實跑後記版本、fixture、ran/skip與失敗 |
| 錯誤 | 不部分扣費、不半寫人物與世界；pending先查commit marker |
| 來源 | 固定來源pin與原冊章節；新變更保revision不抹舊反例 |

### 必測的跨季情境

同一跨族子代保持UID與雙親；死者不復活；未決承接政策拒提交；孕期／研習／K到期不被重置；換季中斷可回原槽；首通與季獎勵不雙領；地盤不合法不切新世界。模組09有16項總情境，JSON另有20功能各正反兩例。

# C2 R5 模組 01　共同身份 時間與存檔契約
版本：2026-11-03 整合評審稿

R5F-* 僅為文件功能索引，不是正式施工工單。
規格可拆不等已獲施工准入；所有產品測試均未由本次文件工作執行。
共同契約以模組01為準；未決參數不得以0、舊R3或最近表值補齊。

---
## R5F-C01 身份與單位契約
- **目的：** 作所有模組共用型別，不重定單位
- **輸入：** personUID/familyUID/factionUID分型；mechanicsProfile與dictionaryVersion；Talent/能力點/BodyTicks分型
- **輸出：** validated identity refs；UNIT_MISMATCH / SOURCE_INCOMPLETE
- **功能依賴：** 無
- **決策依賴：** 無新增數值決策；仍須核實同版現有consumer
- **規格狀態：** 不變量可先拆規格
- **施工狀態：** 未核目前產品准入，不宣稱可直接施工
- **現行caller：** 未在本次重新核對，不填猜測檔路徑。
- **擬接責任：** 驗證身份引用及單位，不建立新人物。實際接線前須另列真caller。
### 驗收 R5F-C01-P [NOT_RUN]
- **Given** P1600能力點
- **When** 轉為BodyTicks
- **Then** 16000000ticks，同人同UID
### 驗收 R5F-C01-N [NOT_RUN]
- **Given** P1600但標ticks且宣稱1600能力點
- **When** 驗入
- **Then** 拒跨單位，不改人物

- **目的：** 明確命名季度、學院turn、主題季和真代數

- **輸出：** clock mapping / generation references
- **功能依賴：** R5F-C01
- **決策依賴：** DEC-R5-S04
- **規格狀態：** 型別可先拆；換季跳時待決
- **施工狀態：** 未核目前產品准入，不宣稱可直接施工

- **擬接責任：** 解讀明確時鐘與映射；未定換季跳時不寫入。實際接線前須另列真caller。

## 規則地位與來源優先順序

本稿以「使用者明確方向」「保留不變量」「數值基線」「待決提案」「未驗證」區分不同層級。前兩者可作設計約束；數值基線只供相同 profile 回歸，不能自動補齊新 profile；提案需形成決策紀錄；未驗證項不能寫成完成。

| 層級 | 本版怎麼使用 | 不代表什麼 |
| --- | --- | --- |
| 使用者明確方向 | 首次統一結局、主題賽季重開、雙方家族與通婚延續 | 未授權任意重排地盤或清空軍隊 |
| 保留不變量 | personUID、父母、生死、出生 P、來源與已知資料不任意重寫 | 不代表所有 R4 數值已凍結 |
| R3／R4 數值基線 | 精確量尺、訓練、字典與歷史 golden 可比較 | 不當新 profile 缺值時的隱性 fallback |
| R5 整合提案 | 雙層存檔、換季交易、祖地再起、限制式地盤重組 | 不代表實作、測試、發布已獲批准 |
| 外部新規格／回答 | 提供玩法包裝、候選公式與反例修正 | 文件自己寫「定案」不等使用者拍板 |

衝突處理順序：同一主題以本輪明確使用者指示優先；未被改動的不變量依原 R4；GitHub 新五份與外部回答若新增數值或互相矛盾，列入本稿衝突帳，不採「檔案較新就全部覆蓋」。同一結果不得一半取舊表、一半取新表湊成未登記的規則。

完整 mechanicsProfile 至少綁 decisionRevision、dictionaryVersion、rngVersion、discoveryProfile、數值量尺與 fixtures。缺必要參數回 PROFILE_UNSUPPORTED；不得填 0、最近表值或舊 R3 值。已有 legacy 人物依自己的版本維持可讀，不為導入 R5 強迫重抽。

本版建議採三國用語包裝：聯姻、門風、家學、譜牒、太傅、郡望。借鑑賽馬育成只是機制類比，不聲稱相同歷史制度。人物婚配須成年並符合既有禁親規則；人際同意、身份及有效婚姻不是可被換季跳過的檢查。

來源：R4 工程 §1、§17、§37；玩法導言；使用者本輪訊息。來源清單見模組 09。
## 四種時間與代數不得混用

「季」目前同時被用於世界季度、學院回合與主題賽季，必須拆開命名。換主題不自然等於過一年，更不等於一代。使用者要求家族延續，並未要求所有人換季時返老還童或立即生出下一代。

| 名稱 | 建議欄位 | 定義與限制 |
| --- | --- | --- |
| 世界季度 | worldQuarterIndex | 歷法季度的單調時鐘；兼容 R4 worldSeason，遷移時明示別名 |
| 學院步數 | trainingTurn | 一個 run 的 0–36 內部行動；基線整個 run 耗一世界季度 |
| 主題賽季 | campaignSeasonId | 一輪主題競爭的不可變身份；不是季度索引，也不是家族代數 |
| 親子代數 | generationDepth／streak | 真親子邊與指定因子連代數；不能由換季次數代替 |

基線時間：15 歲以上且 HP>25 方可入學；36 回合後世界推進一季度。出仕與婚配的年齡另檢；18 歲成年婚配、四季度懷孕的歷史基線下，最早下一代出生間隔 19 年。指定因子 n5 涉五條親子邊而非五個人；開局若自帶完整有效歷史，可已有資格，不必強制玩家等百年。

新五份規格的「12 歲入學」「16 歲加冠」「36 季」「12–18 歲完成」不能同時套入上述基線。R5 保留其儀式包裝方向，但採中性節點「入學禮」「中期演出」「成材結算」表述；未決前不把新年齡、第二次抽樣或外界九年寫成預設。

換季時間待 DEC-R5-S04：A 不跳過歷法，從同一世界時點換戰略盤；B 明示推進若干季度並逐項結算。兩案都需保留孕期、婚約、健康、研習、K 到期日及條約剩餘期間。不能一方面讓軍隊重建數年，一方面讓人物年齡和懷孕全部凍住，除非規則明示為抽象賽局且玩家可理解。

驗收重點：同一孩子跨兩季仍同一 birthEventId；換季本身不多生一胎、不補發生日獎勵、不洗掉年齡傷病、不讓進行中的 36 回合免費完成。所有時間映射須寫入版本化政策。
## 換季資料模型與交易契約

以下是R5擬接資料契約，不是現有API。永久家族層與當季世界層分開存，但引用必閉合。根據同一來源快照生成新世界，所有候選變更先驗證，不能先清原地盤再發現族譜缺件。

| 結構 | 必要欄位 | 一次性或引用約束 |
| --- | --- | --- |
| CampaignSeason | seasonId、themeId、rulesHash、開始／結束世界時點、status | seasonId穩定；與worldQuarterIndex分型 |
| SeasonSnapshot | sourceSaveRevision、person／family／marriage refs、worldHash | 凍結只讀；人物不是按季複製新UID |
| SeasonSettlement | seasonId、canonicalEventId、scoreVersion、rewardKeys、recordRefs | 同業務事件不能換key再領 |
| TransitionPlan | from/toSeasonId、policyVersion、timePolicy、carryPolicy、seedRef | 預覽每類保留／變更，未決值不能提交 |
| CandidateWorld | 地盤／勢力配置、roster refs、成本意圖、validationDigest | 無半套正式狀態；不通過仍留原季 |
| TransitionCommit | transitionId、payloadDigest、expectedRevision、結果pointer | 同鍵同payload回原結果；異payload拒衝突 |

建議狀態：active → eligibleForSettlement → settlementPending → settled → nextSeasonPrepared → committed。玩家選「返回本季」與正式換季的可用階段需政策定義；已結算的獎勵不能被返回操作再發一次。

提交順序：凍結來源 → 計算及保存結算意圖／結果 → 建候選世界 → 驗核心引用、生死、婚姻、資源帳與地盤約束 → 寫新存檔槽 → checksum與完整性通過 → 原子切當前指標 → 保上一可用槽。斷在pending時先讀commit marker，不把逾時當失敗退款或重抽。

expectedRevision不符拒絕，要求讀新狀態；不得因背景出生／死亡更新就默改來源、抽新seed繼續。錯誤需區分PROFILE_UNSUPPORTED、SOURCE_INCOMPLETE、REVISION_CONFLICT、IDEMPOTENCY_CONFLICT、RESULT_PENDING、STORAGE_FAILURE。訊息不得洩未公開P／LUK／seed。

世界生成亂數與出生／訓練亂數流分域；新增主題欄位不能改既有人物出生結果。新season不是新person命名空間，跨族同一childUID不可出現兩份實體。來源：R4工程§4–7、§16，延伸至R5主題轉換。
## 長篇存檔與舊版本遷移

R4候選負載為250年、活躍NPC2000、累計家譜50000人、來源revision200000筆，未壓縮估算99,726,336B＝95.1064453125MiB。單份100MiB、增量≤4MiB、首屏≤2秒都是指定負載目標，非實測保證。R5增加賽季歷史、換季交易、通婚引用與新家族，必須重算容量，不能沿舊95.1MiB當已通過。

出生、死亡、婚姻／婚約來源、因子變更、LUK、功業與獎勵終態，以及影響未來的K樣本都屬核心。冷存可以改編碼與索引，不得把遠祖只剩「最高兩因子」後仍聲稱可重播與保知識。一般日常摘要可有損，必明示不能復原逐步日誌；重要第九筆事件不能因年度預算而被丟掉。

來源revision保存必要因子、資格、事件參數與前版引用；hash不是原內容替代。字典、祖源、出生witness與跨季recordRefs必完整可解析。Fraction每個分子／分母最多256個十進位數字，不是256-bit；超型別上限拒絕，合法但超編碼預算走擴充區並計實際容量。

遷移須產生預覽：保持哪些值、增加哪些新索引、哪些無法映射。保原mechanicsProfile、dictionaryVersion、displayPaletteVersion、discoveryProfile；已知資料取可識別聯集，不能把未知全部揭露。原P/B/A與舊星、舊券保留；新cap3不回扣舊target4事件。

混合legacy來源不能完整映射時，不從A猜P、不從名字猜父母、不用新創始模板覆舊人。可以保原legacy路徑、等待查譜或使用另有明確來源的新角色；拒絕不合法的新出生／換季，不破壞既有可讀存檔。

跨季擴充資料若超候選容量，先無損壓縮、分塊與索引去重，再明示增加容量。不能以100MiB為理由刪敵方家譜，因為對方可能是玩家通婚後代的祖先。雙槽峰值可能約兩倍以上，需真實量測，不把單槽目標當總磁碟用量。來源：R4工程§15–17。

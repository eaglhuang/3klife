## 1. 演算法定位與設計原則

本規格書定義血脈命鏡載入提示選取引擎（`LoadingTips.ts`）的抽樣演算法。其核心目標在於載入畫面的短暫時間窗內，以純邏輯、無副作用且支援確定性重播的方式，挑選出 1~2 條兼具情境適配與多樣性的提示文本。

### 1.1 核心設計原則
1. **純邏輯解耦**：不依賴任何 Cocos 引擎元件或全域狀態，全流程為純粹 TypeScript 函式。
2. **依賴注入亂數來源**：抽樣使用的隨機數產生器以函式形式傳入（`random: () => number`），支援固定種子或自定義序列單元測試。
3. **無放回不重複原則**：同一載入輪次內挑選的 2 條提示，嚴格禁止重複出現，且避免從已抽空之池中重複獲取。
4. **邊界防禦與平滑降級**：當要求數量超出範圍或某池文案抽空時，平滑夾取並提前安全中斷，絕不拋出未捕獲例外或回傳空字串。

## 2. 抽樣核心流程與介面定義

```mermaid
flowchart TD
    Start([呼叫 pickLoadingTips]) --> Clamp[數量限制: clampCount(count) 鎖定為 1~2 條]
    Clamp --> InitRemaining[複製四池候選文案清單 remaining]
    InitRemaining --> LoopCheck{已抽選數量 < clampCount 且 池不為空?}
    LoopCheck -->|否 / 抽空| Finish([回傳 picked 陣列])
    LoopCheck -->|是| FilterPools[篩選 remaining 有餘額且權重 > 0 之池]
    FilterPools --> CalTotal[計算候選池權重總和 total]
    CalTotal --> TotalCheck{total > 0?}
    TotalCheck -->|否| Finish
    TotalCheck -->|是| WeightedRoll[計算 roll = unit(random) * total 加權選池]
    WeightedRoll --> PickText[自選中之池均勻隨機抽取 1 條]
    PickText --> Splice[自 remaining[chosen] 剔除該條 (無放回)]
    Splice --> Push[推入 picked 陣列]
    Push --> LoopCheck
```

### 2.1 介面定義 (TypeScript)
```typescript
export type LoadingTipCategory = 'system' | 'history' | 'bloodline' | 'tease';

export interface LoadingTipsContent {
    categories: Readonly<Record<LoadingTipCategory, readonly string[]>>;
    weights: {
        owned: Readonly<Record<LoadingTipCategory, number>>;
        unowned: Readonly<Record<LoadingTipCategory, number>>;
    };
}

export interface PickLoadingTipsOptions {
    owned: boolean;         // 角色持有狀態
    count: number;          // 抽取數量（會被限制在 1~2 條）
    random: () => number;   // 亂數來源，回傳 [0, 1)
}
```

## 3. 關鍵演算法實作細節

### 3.1 數量限制器 (clampCount)
載入畫面底部佈局限制，展示條數上限嚴格鎖定在 1~2 條：
$$\text{clampedCount} = \min(2, \max(1, \lfloor \text{count} \rfloor))$$
若傳入非法非有限數字（如 `NaN`、`Infinity`），強制安全降級為 1 條。

### 3.2 亂數安全單元化 (unit)
為防止傳入的亂數產生器回傳精確 1.0 或非法值造成陣列越界，進行防禦性夾取：
$$\text{unit}(R) = \begin{cases} 
\min(\max(R(), 0), 0.999999) & \text{若 } R() \text{ 為有限數字} \\
0 & \text{其餘異常情況}
\end{cases}$$

### 3.3 雙階無放回抽樣 (Two-Stage Without Replacement)
1. **第一階（池挑選）**：
   - 取得當前狀態權重表（`owned ? content.weights.owned : content.weights.unowned`）。
   - 過濾出 `remaining[category].length > 0` 且 `weights[category] > 0` 的活躍池清單。
   - 累加其權重總額 $W_{total} = \sum w_i$。若總額 $\le 0$，立即終止挑選。
   - 產生指針值 $r = \text{unit}(R) \times W_{total}$，依序累減權重，判定命中之類別池。
2. **第二階（文本抽選與剔除）**：
   - 於命中類別池中，計算索引 $\text{idx} = \lfloor \text{unit}(R) \times \text{pool.length} \rfloor$。
   - 透過 `splice(idx, 1)` 抽出並從該候選池中移除該文本，推入最終輸出陣列。

## 4. 驗收標準與單元測試契約

1. **確定性重現**：給定固定隨機種子序列時，輸出之提示文字必須 100% 相同。
2. **持有加權差異**：
   - 在未持有狀態下抽樣 1,000 次，`tease` 分類佔比應符合預設加權分佈（約 40%）。
   - 在已持有狀態下抽樣 1,000 次，`system` 與 `bloodline` 分類合計佔比應高達 70%。
3. **無放回保證**：當要求 `count = 2` 時，抽出的兩條提示文字字串絕對不相等。
4. **空池防呆**：若特定分類全部文案已被抽空，自動在剩餘有效池中挑選，不中斷也不產生 `undefined`。

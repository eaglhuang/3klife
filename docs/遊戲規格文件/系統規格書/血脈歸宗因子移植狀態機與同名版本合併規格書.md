# 血脈歸宗因子移植狀態機與同名版本合併規格書

> 標籤：`BLT-11` · `M9` · `血脈歸宗` · `因子移植` · `同名武將` · `單一真相來源`

---

## 1. 核心定位與職責邊界

本規格書定義《三國志·漢末霸業》血統家族培育體系中，玩家持有同名武將之多個歷史版本（如初代普通版 V1 與限定神將版 V2）時，消耗「歸宗令」執行「血脈歸宗（Bloodline Merge）」之因子定向移植演算法（`mergeBloodline` 與 `planBloodlineMergeForGenerals`）。

本模組為純邏輯無副作用運算，負責因子候選匹配與狀態計算，道具扣除與存檔序列化由 `GameSession` 總控負責。

---

## 2. 歸宗合法性審查與排他阻絕（Invariants）

執行血脈歸宗前，系統對雙方武將進行四重嚴格驗證，任一不符即中止流程：

```typescript
export type BloodlineMergeRejectReason =
    | 'SAME_GENERAL'
    | 'NO_BLOODLINE'
    | 'DIFFERENT_BLOODLINE'
    | 'NO_TRANSFERABLE';
```

1. **`SAME_GENERAL`**：V1 與 V2 之武將 ID 相同，禁止自我歸宗。
2. **`NO_BLOODLINE`**：V1 或 V2 任一方缺乏 `bloodlineId`，無法進行血統溯源。
3. **`DIFFERENT_BLOODLINE`**：V1 與 V2 之 `bloodlineId` 不一致（非同族同名），嚴格禁止跨血統篡改。
4. **`NO_TRANSFERABLE`**：V2 中無任何可供移植之新因子（已被全部移植或 V1 已全數擁有）。

## 3. 確定性因子移植演算法

血脈歸宗遵循確定性單向移植規則，完全無隨機擲骰介入：

```
                  ┌───────────────────────────────┐
                  │ 遍歷 V2 因子清單 (按獲得順序)  │
                  └───────────────┬───────────────┘
                                  │
                   [ factor 是否滿足移植條件? ]
                   - V1 尚未擁有 ( !v1Owned.has )
                   - V2 尚未被移植 ( !alreadyMerged.has )
                                  │
                    ├── 命中第一個候選 ──> 確定移植: candidate
                    └── 遍歷完畢無候選 ──> 回傳 null (拒絕歸宗)
```

### 3.1 狀態轉換與資料契約
- **移植標的**：選定 V2 身上第一個 V1 尚未擁有、且尚未標記於 `mergedOutFactors` 之因子。
- **V1 狀態變更**：將該因子追加入 V1 之 `factors` 清單末端。
- **V2 狀態變更**：V2 武將本體永久保留（不消失），將該因子追加至 V2 之 `mergedOutFactors` 陣列中，防止重複移植。

```typescript
export function mergeBloodline(v1: BloodlineSide, v2: BloodlineSide): BloodlineMergeResult | null {
    const v1Owned = new Set(v1.factors);
    const alreadyMerged = new Set(v2.mergedOut);
    const candidate = v2.factors.find((f) => !v1Owned.has(f) && !alreadyMerged.has(f));
    if (candidate === undefined) return null;
    return {
        transferredFactor: candidate,
        v1Factors: [...v1.factors, candidate],
        v2MergedOut: [...v2.mergedOut, candidate],
    };
}
```

## 4. 道具扣款防護守則

- **原子交易保證**：只有在 `planBloodlineMergeForGenerals` 回傳 `{ ok: true }` 時，系統才允許扣除 1 枚「歸宗令」。
- **零損耗防禦**：若審查回傳任何失敗原因（如 `NO_TRANSFERABLE`），不執行任何因子變更，且歸宗令數值嚴格保持不變。

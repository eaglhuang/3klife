## 1. 系統定位與商業化裁決

本規格確立裝備與背包系統之擴容商業化、自動整理冷卻與裝備強化消耗規則。
**歷史爭議裁決（Single Source of Truth）**：
- 拒絕將「自動整理」設為純付費特權，統一提供全體玩家免費使用（設 3 秒防頻繁連點冷卻）。
- 商業化重點收斂至「背包與倉庫欄位雙軌擴容」與「高階強化保底材料消耗」。

```mermaid
flowchart TD
    ReqExpand[請求擴容欄位 +5 格] --> CheckCurr{檢查當前格子與上限}
    CheckCurr -- 已達上限 100 格 --> RetMaxErr[回傳 ERR_MAX_CAPACITY_REACHED]
    CheckCurr -- 允許擴容 --> ChoicePay{選擇支付途徑}
    ChoicePay -- 玉璧 CURR_GEM --> PayGems[扣除 100 玉璧]
    ChoicePay -- 銅錢 CURR_GOLD --> PayGold[扣除階梯銅錢 (基礎 50,000)]
    PayGems --> ApplyExpand[背包容量 +5 並原子落盤]
    PayGold --> ApplyExpand
    ApplyExpand --> Success[派發 ON_BAG_CAPACITY_UPDATED]
```

## 2. 背包與倉庫欄位擴容模型

```typescript
export interface BagExpansionConfig {
  initialSlots: number;        // 初始格子: 30 格
  maxSlots: number;            // 上限格子: 100 格
```

## 3. 背包免費整理演算法與頻率保護

1. **排序權重順序**：
   - 類別權重：武器 > 頭部 > 身軀 > 足部 > 飾品 > 虎符 > 材料 > 消耗品。
   - 品質權重：金色 (Tier 5) > 紫色 (Tier 4) > 藍色 (Tier 3) > 綠色 (Tier 2) > 白色 (Tier 1)。
   - 等級/戰力：裝備評分（Gear Score）由高至低。
   - 同品項自動堆疊至最大堆疊上限（`MaxStackCount`）。
2. **防頻繁請求（Anti-Spam）**：
   - 冷卻時間（Cooldown）設為 3.0 秒。
   - 冷卻中再次點擊回傳 `ERR_SORT_COOLDOWN`，UI 顯示「整理過於頻繁，請稍候」。

## 4. 裝備強化材料消耗與不碎裝保底機制

為維護遊戲體驗，強化絕不碎裝或倒退等級，僅扣除消耗材料並累積幸運值（Pity Rate）。

```typescript
export interface GearEnhanceTier {
  targetLevel: number;
  ironCost: number;       // 玄鐵消耗
  jingYuanCost: number;   // 精元消耗
  goldCost: number;       // 銅錢消耗
  baseSuccessRate: number;// 基礎成功率 (0.0 ~ 1.0)
  failLuckBonus: number;  // 失敗累積幸運值 (+% 成功率)
}

export const GEAR_ENHANCE_TABLE: Record<number, GearEnhanceTier> = {
  1: { targetLevel: 1, ironCost: 2, jingYuanCost: 0, goldCost: 500, baseSuccessRate: 1.0, failLuckBonus: 0.0 },
  2: { targetLevel: 2, ironCost: 4, jingYuanCost: 0, goldCost: 1000, baseSuccessRate: 1.0, failLuckBonus: 0.0 },
  3: { targetLevel: 3, ironCost: 8, jingYuanCost: 5, goldCost: 2000, baseSuccessRate: 0.9, failLuckBonus: 0.1 },
  4: { targetLevel: 4, ironCost: 16, jingYuanCost: 10, goldCost: 4000, baseSuccessRate: 0.7, failLuckBonus: 0.15 },
  5: { targetLevel: 5, ironCost: 32, jingYuanCost: 25, goldCost: 8000, baseSuccessRate: 0.5, failLuckBonus: 0.2 },
  6: { targetLevel: 6, ironCost: 64, jingYuanCost: 50, goldCost: 15000, baseSuccessRate: 0.3, failLuckBonus: 0.25 },
};
```

- **保底結算**：當 `currentLuck + baseSuccessRate >= 1.0` 時，下一次強化必成；強化成功後 `currentLuck` 歸零。

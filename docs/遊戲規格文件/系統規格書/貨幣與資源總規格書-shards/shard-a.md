# 貨幣與資源總規格書

> 來源：使用者 2026-11-21 裁決 #14、#28；任務卡 PROG-2-9218。
> 本檔是**貨幣與資源命名、用途、轉移**的唯一總規格；`doc_spec_0404`（基礎資源四維上限）、`doc_spec_0032`（資源循環）、`doc_spec_1184` §3.5（物品框架的 resource-def）都只引用本檔，不再各自定義貨幣語意。
> 範圍只改規格，不改程式；程式遷移走 §8 實作卡。

## 1. 使用者裁決（11/21，原文）

1. **保留金與銀兩兩種貨幣，各有用途**；只統一糧食命名（PM 定為「糧草」）。
2. **金＝國家**（幕府公庫：征兵、城建、外交等軍政）；**銀兩＝家族**（家業、婚嫁、養子嗣、學府）。
3. **公私可以轉移，但有代價**：家族捐公庫換名望；挪用公庫補家用會降民心或忠誠。（**11/22 改寫，見下方第 4 條，本條作廢**）
4. **（使用者 2026-11-22 裁決，取代第 3 條）國家的「金」與家族的「銀兩」可轉，但有代價**：家族可捐銀兩給國家換「功勳」；國家發「俸祿」給家族；**國庫的金不能直接搬回家**（不得把公庫金兌成銀兩）。數值待企劃（Antigravity）設計。

## 2. 資源與貨幣總表（唯一定義）

| 標準 id | 玩家看到的名稱 | 性質 | 持有者 | 主要用途 |
|---|---|---|---|---|
| `gold` | 金 | 國家貨幣 | 幕府公庫（shogunate） | 征兵、城建、外交禮物、軍需處、公庫商店 |
| `silver` | 銀兩 | 家族貨幣 | 家族庫房（clan／household） | 家業、婚嫁聘禮、養子嗣、學府學費、家族商店 |
| `food` | **糧草**（原「糧食」） | 軍政資源 | 幕府公庫（軍需） | 出兵、守城、賑災、義勇營口糧 |
| `troops` | 兵力 | 軍政資源 | 幕府 | 戰場與城防 |
| `fame` | 名望 | 聲望資源（非貨幣） | 幕府 | （11/22 起家族捐獻改換「功勳」，見 §3.1）影響外交與招賢 |

- `grain` 只是 `food` 的**別名**（舊程式與舊資料殘留），玩家可見文字一律「糧草」，不再出現「糧食」。
- 武將**不持有**任何貨幣；貨幣只掛在公庫或家族庫房（對應 `doc_spec_1184` 的持有者表）。
- 精元、結義點數、求籤令、免費銅錢符、靈玉等**帳號級代幣**不屬於本表，仍由 `doc_spec_0626`／`doc_spec_0464` 管理；轉蛋貨幣與金銀互不兌換。
- 舊 1184 §3.5「silver 是 gold 的別名」**作廢**，以本檔為準。

## 3. 轉移規則（有代價）

兩條轉移各一個命令：`treasury.donate`（§3.1，家族→國家）、`treasury.stipend`（§3.2，國家→家族）（本機 adapter 先做，之後換網路 adapter），必須帶 `idemKey`，伺服器權威結算。**不存在「公庫金 → 銀兩」的直接兌換**（使用者 2026-11-22 裁決）。

### 3.1 家族捐銀兩給國家換功勳（銀兩 → 公庫金＋功勳）

| 項目 | 設計值（**暫定，待企劃 Antigravity 設計**；可改 JSON） |
|---|---|
| 兌換 | 捐 1000 銀兩 → 公庫 +800 金（損耗 20%）＋功勳 +N（N 待企劃） |
| 單季上限 | 每季最多捐 5000 銀兩（上限與功勳比率待企劃） |
| 門檻 | 家族庫房餘額不可低於「家業維持金」（見家業規格 1181） |

> 原稿「名望 +1」改為「功勳」（使用者 2026-11-22 裁決）。功勳的用途與官職晉升的關係待企劃一併設計。

### 3.2 國家發俸祿給家族（公庫金 → 家族銀兩，單向、依官職）

| 項目 | 設計值（**暫定，待企劃 Antigravity 設計**） |
|---|---|
| 發放 | 每季依家主官職階位，由公庫發俸祿給家族庫房（銀兩），不是玩家自由搬錢 |
| 金額 | 依官職階位查表（表待企劃；可參考 `doc_spec_0634` 官職俸祿平衡規格），放 JSON |
| 禁區 | 公庫低於征兵安全線時停發或減發；戰時（守城中、出兵中）照常發放不得扣留 |
| 取代 | **作廢**舊「挪用公庫補家用（`treasury.divert`，挪 1000 金 → 1000 銀兩，扣民心／忠誠）」整條規則（使用者 2026-11-22 裁決） |

比率、上限與俸祿表全放 `data/currency/transfer-rules.v1.json`，數值由企劃（Antigravity）設計後填入。

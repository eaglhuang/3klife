# 轉蛋抽取引擎單抽十連與降階抽樣演算法規格書

## 1. 核心定位與設計理念
本規格書定義三國生活（3KLife）轉蛋系統之「抽取引擎核心抽樣演算法與十連批次判定」規格（對應 WBS `GCH-02` 與 `PROG-2-0335`）。
抽取引擎作為決定玩家獲得角色之運算中樞，堅持**純邏輯解耦、依賴注入可重現、無死角防呆**原則：
1. **純邏輯零引擎依賴**：抽取演算法完全與 Cocos Creator 視圖層分離，不依賴任何場景節點或非同步動畫。
2. **確定性隨機種子注入**：亂數產生器透過介面注入（`rng: () => number`），支援伺服端種子回放與單元測試 100% 複現。
3. **降階取桶保護機制**：若特定稀有度暫無可用角色或資料缺失，自動平滑降階尋找可用角色，杜絕空指針崩潰。

---

## 2. 抽樣核心流程與演算法模型 (`drawOne`)

### 2.1 累加機率分佈抽樣 (CDF Sampling)
演算法依序比對累加閾值決定初始稀有度：
- 擲骰隨機浮點數 $r_1 \in [0, 1)$：
  $$\text{TargetRarity} = \begin{cases} 
  \text{SSR}, & \text{若 } r_1 < P(\text{SSR}) \\
  \text{SR}, & \text{若 } P(\text{SSR}) \le r_1 < P(\text{SSR}) + P(\text{SR}) \\
  \text{R}, & \text{其餘情況}
  \end{cases}$$

### 2.2 當期加倍（Up）分桶抽樣
若命中 SSR 或 SR，擲骰第二個隨機數 $r_2 \in [0, 1)$：
- 若 $r_2 < \text{UP\_SHARE}[\text{Rarity}]$ 且 Up 候選清單非空，從 `upList` 中以均勻抽樣選出角色：
  $$\text{Index} = \min\left(\text{Count} - 1,\, \lfloor r_3 \times \text{Count} \rfloor\right)$$
- 否則，若常設名單非空，從 `otherList` 中均勻抽樣選出角色。

### 2.3 降階尋桶保護原則 (`findFallbackRarity`)
若所抽中之桶（含 Up 與常設）均無可用武將，系統依據預設階梯向下回退：
$$\text{SSR} \longrightarrow \text{SR} \longrightarrow \text{R}$$
直到找到第一個具備有效武將清單之稀有度桶；若所有桶皆為空，則擲出受管之空池例外。

## 3. 保底介入與單抽回傳結構 (`GachaDrawResult`)
在決定基礎抽樣角色後，引擎傳入當前保底計數（`GachaPityState`）進行校驗：
- 若當前抽數符合小保底觸發條件且抽樣結果為 R，引擎強制將稀有度提升為 SR，並自 SR 桶重新抽樣，標記 `pityApplied = true`。
- 單抽結果封裝如下：
  ```typescript
  export interface GachaDrawResult<T> {
      item: T;
      rarity: GachaRarity;
      pityApplied: boolean;
      nextPity: GachaPityState;
  }
  ```

## 4. 十連抽批次封裝 (`drawTen`)
十連抽本質為 10 次原子單抽的串聯遞推：
1. **狀態連續性**：第 $i$ 抽的 `nextPity` 即為第 $i+1$ 抽之起始保底狀態，各抽之間計數即時滾動。
2. **大保底天命商店計數**：第 10 抽結算後，累計抽數自動 $+10$，若跨越 200 抽門檻，即時解鎖天命商店兌換權限。
3. **無保底吞噬**：若第 50 抽自然開出 SSR，保底計數正常遞增，小保底規則不壓制 SSR 產出。

## 5. Unity 與 Cocos Creator 概念對照
| 概念維度 | Cocos Creator 實作架構 | Unity 引擎對照架構 |
| :--- | :--- | :--- |
| **亂數注入** | 傳入自定義 `rng: () => number` 函式 | 透過介面 `IRandomService` 或 `System.Random` 依賴注入 |
| **抽取結果容器** | `GachaDrawResult<T>` 泛型介面 | C# 泛型結構體 `struct GachaDrawResult<T>` |
| **無副作用設計** | 純函式運算，不修改傳入之 pool 物件與原 state | Immutable 資料模式，回傳全新 State 實體 |

## 6. 驗證條件與測試矩陣 (Acceptance Gate)
1. **TC-GCH02-01 固定種子確定性回放**：注入固定虛擬亂數序列，驗證 10 連抽結果之角色順序、稀有度與標記 100% 相同。
2. **TC-GCH02-02 降階取桶驗證**：刻意傳入空的 SSR 桶，驗證抽中 SSR 時平滑降級產出 SR 角色，無崩潰例外。
3. **TC-GCH02-03 小保底干預驗證**：在第 50 抽強制讓 RNG 產出 R 級隨機數，驗證產出結果被成功修正為 SR 且 `pityApplied = true`。

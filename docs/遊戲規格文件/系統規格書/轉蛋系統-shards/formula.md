## F. 公式相關

### 轉生屬性上限
| 轉數 | 基礎上限 | 培育機會 |
|---|---|---|
| 1 轉 | 1000 | 1 次 |
| 2 轉 | 1100 | 2 次 |
| 3 轉 | 1250 | 3 次 |
| 4 轉 | 1400 | 4 次 |
| 5 轉 | 1500+ | 5 次 |

### 入池機率表

#### 三國名將池
| 稏有度 | 機率 | 備註 |
|---|---|---|
| SSR | 3% | 其中 70% 為 Up 角色 |
| SR | 10% | 其中 80% 為 Up 角色 |
| R | 87% | 常設武將池 |
| 小保底 | 50抗 | 必出 SR+ |
| 大保底 | 200抗 | 天命商店兑換任意 SSR |

#### 支援卡（教官）池
| 稏有度 | 機率 | 備註 |
|---|---|---|
| SSR | 5% | 其中 70% 為 Up 教官卡 |
| SR | 25% | 其中 80% 為 Up 教官卡 |
| R | 70% | 常設教官卡池 |
| 小保底 | 50抗 | 必出 SR+ 教官卡 |
| 大保底 | 200抗 | 天命商店兑換任意 SSR 教官卡 |

### 保底計算
- 小保底：`pull_count % 50 == 0 → guarantee SR+`
- 大保底：`pull_count >= 200 → unlock 天命商店 exchange`
- **各池錢独立計數**：三國名將池與支援卡池的保底計數必須分開計算。

### 貨幣系統

| 貨幣 | 種類 | 用途 | 備註 |
|---|---|---|---|
| **靈玉** | 付費貨幣 | 三國名將池 + 支援卡池均可使用 | 購買套裝或月卡獲得 |
| **銅錢符** | 免費貨幣 | **僅**常設池可用，限定池不支援 | 每日任務/活動獲得 |
| **求籤令** | 定向道具 | 指定某個 SSR 角色的定向保底（最多 100 抗保底） | 活動/周周任務獲得，非流通貨幣 |

### 單抗 / 10 連 UI 流程

| 操作 | 演出顏度 | 貨幣消耗 |
|---|---|---|
| 1 抗 | 快速公告動画（約 2 秒） | 靈玉 ×150 或 銅錢符 ×150 |
| 10 連 | 完整開牌動画（先過場 3D 際 → 逐張展開） | 靈玉 ×1500 或 銅錢符 ×1500（1 抗免費） |
| 10 連（Demo） | 所有卡同時展開（簡易版） | 同上 |

### G-1. GachaMain 商業主視覺與人物立繪規格

1. `GachaMain` 的 Banner 人物圖屬於商城 / 轉蛋入口的商業主視覺，不等同武將人物介紹頁的資訊展示立繪；前者優先追求第一眼吸引力、池別情緒與完整構圖，後者優先追求可讀性與長時間瀏覽。
2. 短期 proof 可重用現有去背 PNG（例如 `assets/resources/sprites/generals/*_portrait.png`），但必須採用人物介紹頁已驗證的 soft-alpha 流程：建立獨立 artwork carrier，依 SpriteFrame `originalSize` / `offset` 做邏輯框 fit，並套用 `PortraitSoftMask` / `effects/portrait-soft-mask` 的 feather 材質，避免硬邊與白底外框。
3. 正式商業版優先規劃 pool-specific key visual：可包含完整人物構圖、背景、武器、旗幟、召喚光效與池別視覺符號。若 key visual 自身已完整承擔 Banner art area，可使用不透明完整圖；透明 PNG 不是硬性要求。
4. UI layout 不得保留 `opacity: 0` 的人物佔位或無用裝飾層。若該池人物圖尚未 ready，應直接省略人物節點，讓 Banner 背景、文字與 fade 維持乾淨結構。
5. 驗收標準：不得出現人物素材邊界矩形、白底鬼影、半透明色塊、硬切 alpha 邊；人物主視覺不得壓住池名條、池別說明 chip 或抽卡 CTA 的可讀性。

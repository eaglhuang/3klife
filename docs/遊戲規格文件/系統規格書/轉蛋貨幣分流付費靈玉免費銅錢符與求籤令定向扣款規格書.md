# 轉蛋貨幣分流付費靈玉免費銅錢符與求籤令定向扣款規格書

## 1. 核心定位與設計理念
本規格書定義三國生活（3KLife）轉蛋系統之「貨幣分流架構、扣款優先級校驗與求籤令定向保底」數值規範（對應 WBS `GCH-04` 與 `PROG-2-0336`）。
轉蛋經濟作為維護遊戲商業平衡與免費玩家活躍度之基石，堅持**分流明確、嚴格拒絕透支、保底透明**原則：
1. **雙幣分流權限隔離**：明確界定付費「靈玉」與免費「銅錢符」之適用卡池，限定活動池嚴禁免費幣滲漏。
2. **零透支與差額回報**：扣款前執行純邏輯兩道校驗，餘額不足時絕對拒絕交易並精確計算差額，嚴禁負數錢包。
3. **求籤令定向契約**：提供 100 抽內必定命中指定 SSR 名將之確定性契約，抽中即清空，改鎖重新計數。

## 2. 貨幣類型與卡池適用矩陣 (`POOL_ACCEPTS`)
系統定義兩種主要抽卡代幣與三大卡池類型：
- **貨幣種類 (`GachaCurrencyType`)**：
  - `SPIRIT_JADE`（靈玉）：儲值付費或高階成就獎勵之通用高階代幣。
  - `BRONZE_CHARM`（銅錢符）：每日任務、登入簽到與活躍活動產出之免費抽卡符。
- **卡池適用權限矩陣**：
  | 貨幣種類 | 常設名將池 (`HERO`) | 常設支援池 (`SUPPORT`) | 限時活動池 (`LIMITED`) | 適用說明 |
  | :--- | :---: | :---: | :---: | :--- |
  | **靈玉 (SPIRIT_JADE)** | ✅ 允許 | ✅ 允許 | ✅ 允許 | 通用付費貨幣，全卡池無限制 |
  | **銅錢符 (BRONZE_CHARM)** | ✅ 允許 | ✅ 允許 | ❌ 嚴格封鎖 | 免費活躍代幣，僅限常設雙池，不可進入限定池 |

## 3. 計價模型與消費校驗狀態機 (`checkGachaSpend`)

### 3.1 抽卡計價基準 (`quoteGachaCost`)
- **單抽成本 (`GACHA_SINGLE_PULL_COST`)**：150 幣。
- **十連成本 (`GACHA_TEN_PULL_COST`)**：1500 幣（等價於 10 次單抽，平價透明）。
- **報價公式**：$\text{Cost}(N) = \text{if } N = 10 \text{ then } 1500 \text{ else } \lfloor N \rfloor \times 150$。

### 3.2 兩階段校驗流程
扣款前必須通過 `checkGachaSpend`，任何一關未過均終止交易：
1. **卡池權限校驗**：若卡池不支援該貨幣，回傳 `{ ok: false, reason: 'POOL_NOT_ALLOWED', shortfall: 0 }`。
2. **餘額充足校驗**：若持有量 $\text{balance} < \text{cost}$，回傳 `{ ok: false, reason: 'INSUFFICIENT', shortfall: \text{cost} - \text{balance} }`。
3. **優先扣款策略**：在支援銅錢符的卡池中，系統優先消耗免費之銅錢符；若銅錢符不足，再主動提示並詢問消耗靈玉。

## 4. 求籤令定向保底機制 (`DirectedPityState`)
求籤令作為非貨幣型之定向道具，賦予玩家定向鎖定指定武將之權利：
- **啟動鎖定 (`activateDirectedPity`)**：
  玩家消耗 1 張求籤令，指定一位目標 SSR 武將 ID，初始化計數器 `pullsSinceTarget = 0`。若先前已有鎖定目標，強制替換新目標並重置計數。
- **百抽必出判定 (`isDirectedPityDue`)**：
  當累計抽數達到 100 抽上限（`DIRECTED_PITY_CAP = 100`）時：
  $$\text{IsDue} = (\text{targetId} \neq \text{null}\ \land\ \text{pullsSinceTarget} + 1 \ge 100)$$
  若第 99 抽仍未出，第 100 抽引擎強制將產出置換為鎖定之目標武將。
- **解除契約 (`advanceDirectedPity`)**：
  若在 100 抽內自然抽中或透過保底取得目標武將，契約立即圓滿解除，狀態重設為 `{ targetId: null, pullsSinceTarget: 0 }`。

## 5. Unity 與 Cocos Creator 概念對照
| 概念維度 | Cocos Creator 實作架構 | Unity 引擎對照架構 |
| :--- | :--- | :--- |
| **商店規則表** | `GachaCurrency.ts` 純函式查表與權限校驗 | C# 靜態類別或 ScriptableObject 驅動之 `CurrencyRules` |
| **扣款協調者** | `GachaFlowCoordinator` 取得校驗結果後呼叫錢包扣款 | `IStoreManager` / `WalletService` 執行交易事務 |

## 6. 驗證條件與測試矩陣 (Acceptance Gate)
1. **TC-GCH04-01 銅錢符限定池阻斷**：在限定池嘗試傳入 `BRONZE_CHARM`，驗證回傳 `POOL_NOT_ALLOWED` 且扣款中止。
2. **TC-GCH04-02 餘額不足差額計算**：餘額 1200 嘗試十連抽（需 1500），驗證回傳 `INSUFFICIENT` 且 `shortfall = 300`。
3. **TC-GCH04-03 求籤令百抽必出**：鎖定目標後第 1~99 抽均未命中，驗證第 100 抽觸發 `isDirectedPityDue = true` 並成功產出目標。
4. **TC-GCH04-04 提早抽中歸零清空**：鎖定目標後第 25 抽自然命中目標武將，驗證狀態重置且目標歸為 `null`。

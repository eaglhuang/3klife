# 轉蛋雙重保底機制與天命商店解鎖記帳規格書

## 1. 核心定位與設計理念
本規格書定義三國生活（3KLife）轉蛋系統之「雙重保底（小保底 50 抽與大保底 200 抽）與跨池獨立記帳」規格（對應 WBS `GCH-03` 與 `PROG-2-0335`）。
保底系統作為保障玩家長期付出與體驗下限之防線，堅持**絕對獨立、真實記帳、零吞噬**原則：
1. **小保底 50 抽倍數必出 SR+**：每累積 50 抽未出 SR 以上時，強制將第 50 抽之 R 級修正為 SR。
2. **大保底 200 抽天命商店解鎖**：累計每達 200 抽解鎖天命商店自由指定兌換當期焦點名將權限。
3. **各卡池獨立記帳隔離**：名將池、支援池與限時活動池之保底進度完全物理隔離，嚴禁跨池共用或混淆。

---

## 2. 小保底演算法機制 (`GACHA_SMALL_PITY_INTERVAL = 50`)
小保底旨在提供週期性獲得中高階武將之保底體驗：
- **觸發週期**：每累積抽數達到 50 的整數倍時觸發（第 50、100、150、200... 抽）：
  $$\text{IsPityTriggered} = (\text{pullCount} \pmod{50} = 0)$$
- **保護與提升邏輯**：
  - 若第 50 抽自然擲出 **R** 級，系統強制修正稀有度為 **SR**，並重新從 SR 桶中取樣，設定標記 `pityApplied = true`。
  - 若第 50 抽自然擲出 **SSR** 或 **SR**，視為自然滿足「SR 或更高」之條件，保留原始抽樣結果，標記 `pityApplied = false`。
  - 自然產出 SSR 絕不因小保底而被降階為 SR（零逆向保底）。

---

## 3. 大保底天命商店機制 (`GACHA_LARGE_PITY_COUNT = 200`)
大保底採用「天命商店兌換憑證制」（非強制替換抽樣結果），提供玩家絕對自主權：
- **門檻判定**：
  $$\text{AvailableExchanges} = \left\lfloor \frac{\text{pullCount}}{200} \right\rfloor - \text{destinyExchanges}$$
- **兌換與記帳**：
  - 玩家於天命商店兌換 1 位當期焦點 SSR 武將時，消耗 1 次兌換額度，`destinyExchanges` 數值 $+1$。
  - 原始累計抽數 `pullCount` **不被清零**，持續向上累加，保留完整抽卡歷史真實軌跡。

## 4. 保底記帳本結構與歷史追蹤 (`GachaPityBook`)

### 4.1 各池獨立記帳結構 (`GachaPityState`)
```typescript
export interface GachaPityState {
    pullCount: number;         // 本池累計抽數
    destinyExchanges?: number; // 天命商店已兌換次數（非必填，預設為 0）
    lastSsrPull?: number;      // 最後一次出 SSR 時的抽數記錄（GCH-14）
}
export type GachaPityBook = Record<string, GachaPityState>;
```

### 4.2 最近 SSR 抽數追蹤 (`lastSsrPull`)
- 當抽取結果為 **SSR** 時，引擎更新該池之 `lastSsrPull = pullCount`。
- 大廳與抽卡介面可計算當前距上次出金抽數：
  $$\Delta \text{Pulls} = \text{pullCount} - (\text{lastSsrPull} \mathbin{??} 0)$$
- 此指標供玩家直觀掌握抽卡運氣，且不干擾小保底 50 抽或大保底 200 抽之正式判定。

### 4.3 舊資料相容與一次性遷移 (`resolveGachaPityBook`)
- 若存檔 `PlayerSave.gachaPity` 已有資料，直接使用。
- 若存檔為空但本機舊版 `localStorage` 存在歷史記帳，系統執行一次性安全遷移至存檔，並自動標記 `migrateLegacy = true`。
- 損毀或負數值自動標準化歸零，防範無效狀態擴散。

## 5. Unity 與 Cocos Creator 概念對照
| 概念維度 | Cocos Creator 實作架構 | Unity 引擎對照架構 |
| :--- | :--- | :--- |
| **保底記帳簿** | `GachaPityBook` 字典物件，整合至 `GameSession` 存檔結構 | 類似 `Dictionary<string, GachaPityData>` 存入二進位 SaveGame |
| **商店解鎖查詢** | `DestinyShop.ts` 透過 `destinyExchanges` 計算可兌換額度 | 商城模組讀取玩家成就點數或貨幣資產進行扣除 |
| **資料標準化** | `normalizeGachaPity` 純函式消除 `null/undefined/NaN` 破壞 | 透過 C# 反序列化屬性與建構子提供預設值保證 |

## 6. 驗證條件與測試矩陣 (Acceptance Gate)
1. **TC-GCH03-01 50抽小保底提升**：連續模擬 49 抽均未出 SR/SSR，驗證第 50 抽必然輸出 SR 或以上角色。
2. **TC-GCH03-02 200抽大保底累積**：抽滿 200 抽後驗證可兌換數為 1；執行兌換後 `destinyExchanges = 1`，總抽數維持 200。
3. **TC-GCH03-03 雙池隔離不污染**：在名將池抽 40 抽，切換至支援池抽 10 抽，驗證支援池累計抽數嚴格為 10，不繼承名將池進度。
4. **TC-GCH03-04 lastSsrPull 記錄追蹤**：驗證在第 35 抽命中 SSR 時，`lastSsrPull` 正確記錄為 35。

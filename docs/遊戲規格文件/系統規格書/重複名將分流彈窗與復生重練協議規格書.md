# 重複名將分流彈窗與復生重練協議規格書

> **責任邊界**：本檔為重複抽卡分流決策介面（SAME-03）、復生重練資料流（ReviveRetrain）與血脈灌注的單一真相來源。
> **關聯 WBS**：SAME-03（重複抽卡分流 UI）、SAME-04（復生重練）、SAME-05（血脈灌注）、GCH-05（轉生機制）。
> **整併裁決**：徹底消除「僅顯示已持有、無分流操作」之歷史斷層；確立雙卡並列彈窗與 5 轉溢出結義點數保底機制。

---

## §1. 重複抽卡分流彈窗視覺契約 (SAME-03 UI Contract)

當轉蛋抽卡結算時，若獲得玩家當前名冊中已存在之史實名將（同模板 ID），系統強制彈出雙向分流選擇彈窗：

```
+--------------------------------------------------------------+
|               【 宿 命 牽 引 ・ 名 將 重 逢 】                 |
|            已持有該名將本體，請選擇其精魄轉化路徑：            |
|                                                              |
|   +--------------------------+    +--------------------------+   |
|   |    【 復 生 重 練 】      |    |    【 血 脈 灌 注 】      |   |
|   |  (青龍靈光 / 突破極限)   |    |  (金鳳神芒 / 即時增強)   |   |
```

1. **左卡【復生重練】（Rebirth & Retrain）**：
   - 適合追求極限培育數值的玩家。以青色光芒（`#00D1B2`）呈現，重啟青年期 36 回合學府修業。
2. **右卡【血脈灌注】（Bloodline Infusion）**：
   - 適合已擁有極品高五維本體、不想耗時重新培育的玩家。以金色光芒（`#FFDD57`）呈現，直接反饋戰力於現役名將與裝備。

## §2. 復生重練資料處理協議 (ReviveRetrain Pipeline)

選擇「復生重練」時，後端執行期依循下列純邏輯管線：

```typescript
export interface ReviveRetrainInput {
  templateId: string;           // 史實武將模板 ID
  spiritCardUid: string;        // 既有英靈卡唯一 UID
  currentRebirthCount?: number; // 當前轉數 (預設 1)
}

export interface ReviveRetrainResult {
  newBodyUid: string;           // 新生成的獨立武將 UID
  templateId: string;
  rebirthCount: number;         // min(5, currentRebirthCount + 1)
  overflow: boolean;            // 若已達 5 轉則為 true
  embeddedSpiritCardUid: string;// 嵌回之英靈卡 UID
}
```

### 五轉滿溢保護 (Overflow Guard to GCH-06)

- 若武將已達到 **5 轉極限**（`currentRebirthCount >= 5`）：
  - 系統不建立重複冗餘角色，標記 `overflow = true`。
  - 將本次抽卡自動轉化為 **100 點結義點數（Oath Points）**，存入 `Data.Player_Economy`，可在天命商店直接兌換任意指定 SSR 碎片。

## §3. 血脈灌注資料處理協議 (BloodlineInfusion Pipeline)

選擇「血脈灌注」時，執行無實體生成之純數值注入：

1. **英靈卡經驗注入**：現役名將裝備之 `Equipped_Spirit_UID` 獲得 **500 點傳承經驗值**，自動觸發升階判定。
2. **虎符共鳴深化**：該武將專屬個人虎符獲得 **150 點戰鬥經驗**，推進虎符升星階級。
3. **歷史帳本登記**：於 `Action_Records` 寫入 `INFUSION_RECORD` 條目，記錄消耗卡片之 Hash 與時間戳。

# 開場宿命轉蛋無限重置十連抽與初始名將鎖定規格書

## 1. 核心定位與設計理念
本規格書定義三國生活（3KLife）新手開場階段之「宿命轉蛋（Destiny Gacha）無限重置十連抽與初始名將鎖定」機制規範（對應 WBS `OPEN-05`）。
宿命轉蛋作為玩家踏入三國世界獲得的第一批核心名將，堅持**誠意滿配、無限重抽、雙段鎖定**原則：
1. **無限免費重置十連抽**：玩家可無限制免費重抽十連，直到洗出心儀名將陣容為止，杜絕首抽刷退首刷痛苦。
2. **單池無放回不重複抽樣**：宿命十連抽預設啟用不重複保護，單次抽取的 10 位武將絕不出現同名重複卡。
3. **雙段確認防止誤觸手滑**：選將與確認鎖定拆分為兩步原子操作，一旦確認鎖定即刻封存為終態。

---

## 2. 宿命轉蛋三態狀態機 (`DestinyGachaPhase`)
宿命轉蛋由純邏輯狀態機嚴密管理：
$$\text{idle} \xrightarrow[\text{roll}]{\text{十連擲骰}} \text{rolled} \xrightarrow[\text{reset}]{\text{免費重置}} \text{idle} \quad \Big\vert \quad \text{rolled} \xrightarrow[\text{select}]{\text{選中}} \text{selected} \xrightarrow[\text{confirm}]{\text{二次確認}} \text{locked}$$

```typescript
export interface DestinyGachaState {
    phase: 'idle' | 'rolled' | 'locked';
    rolled: string[];          // 本輪十連抽出的武將 ID 清單
    selected: string | null;   // 已點選但尚未最終確認的候選名將 ID
    locked: string | null;     // 最終鎖定入庫之初始名將 ID
    resets: number;            // 累計重置次數（僅用於介面展示與埋點）
}
```

---

## 3. 十連抽樣演算法與不重複原則 (`rollDestinyGacha`)
十連抽只能在 `idle` 狀態發起：
- **不重複抽樣（`firstPickOnly = true`）**：
  若卡池候選武將數不足抽取數（`unique.length < pickCount`），拒絕執行並回傳 `pool-too-small`。
  抽樣時以無放回方式均勻抽取（`remaining.splice(index, 1)`），保證單次十連抽產出 10 位互不相同之武將。
- **狀態遷移**：擲骰完成後，狀態遷移至 `phase = 'rolled'`，記錄於 `rolled` 清單中。

---

## 4. 無限免費重置機制 (`resetDestinyGacha`)
- **無門檻洗牌**：
  在 `rolled` 狀態下，若玩家對抽卡結果不滿意，可隨時點擊「重置十連」。
- **整池重置**：
  狀態無損復原為 `idle`，候選清單清空，全卡池武將完整恢復入池。
- **洗牌計數器**：
  累計次數 `resets += 1`，介面動態呈現「已為主公洗牌 {N} 次」，強化儀式感。

---

## 5. 雙段鎖定防誤選流程 (`selectDestinyGacha` & `confirmDestinyGacha`)
為防止玩家在觸控螢幕上誤觸確認鍵：
1. **第一段：選定武將 (`selectDestinyGacha`)**：
   玩家在 10 張卡中點選目標武將，系統檢驗該武將確實在本次 `rolled` 清單內，將其標記為 `selected = id`，介面彈出武將大圖與專屬台詞。
2. **第二段：二次鎖定確認 (`confirmDestinyGacha`)**：
   玩家點擊「就選此將，共謀天下」，狀態機遷移至 `phase = 'locked'`，將 `locked = selected`。
3. **終態防護鐵律**：
   一旦進入 `locked` 終態，後續所有 `roll`、`reset`、`select` 操作一律被嚴格拒絕（回傳 `locked`），初始名將正式寫入玩家主存檔。

## 6. Unity 與 Cocos Creator 概念對照
| 概念維度 | Cocos Creator 實作架構 | Unity 引擎對照架構 |
| :--- | :--- | :--- |
| **抽卡狀態機** | `DestinyGacha.ts` 純函式回傳新 state，不依賴引擎節點 | 類似 C# `DestinyGachaModel` 狀態機，單元測試在 NUnit 運行 |
| **卡牌開牌動效** | `GachaFlowCoordinator` 監聽 rolled 狀態依序翻牌 | `Animator` 依序觸發 10 個 Card Prefab 的 Flip 動畫 |
| **最終落盤** | 確認後由 `GameSession` 寫入初始武將與標記完成開場 | 呼叫 `SaveManager.SaveInitialGeneral(lockedId)` 落盤 |

## 7. 驗證條件與測試矩陣 (Acceptance Gate)
1. **TC-DESTINY-01 十連不重複抽樣**：從包含 10 位以上武將之池子發起十連，驗證抽樣結果 10 位武將 ID 互不重複。
2. **TC-DESTINY-02 無限重置完整循環**：連續執行 10 次 Roll $\to$ Reset，驗證第 10 次狀態仍完全正常且 `resets = 10`。
3. **TC-DESTINY-03 雙段確認防護機制**：未選定武將直接呼叫 confirm，驗證回傳 `not-selected` 拒絕確認。
4. **TC-DESTINY-04 終態絕對鎖定阻斷**：鎖定成功後嘗試再次呼叫 roll 或 reset，驗證一律回傳 `locked` 並拒絕操作。

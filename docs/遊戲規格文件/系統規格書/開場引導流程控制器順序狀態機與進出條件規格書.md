# 開場引導流程控制器順序狀態機與進出條件規格書

## 1. 核心定位與設計理念
本規格書定義三國生活（3KLife）新手開場體驗之「引導流程順序狀態機與進出條件守衛」規格（對應 WBS `OPEN-01` 與 `PROG-2-0109`）。
開場流程作為引導新玩家理解世界觀、建立代入感與完成首抽之核心動線，堅持**純邏輯解耦、配置驅動、斷點可復原**原則：
1. **純邏輯順序狀態機（Sequential FSM）**：控制器不依賴 Cocos Creator 視圖節點，不直接操作 UI 動畫或音效，純粹依據幕序陣列維護當前狀態。
2. **守衛函式精確判定（Guards）**：每一幕的進入與離開均由純函式 `enterWhen` 與 `leaveWhen` 嚴格約束，防止跳步或條件未滿足時前進。
3. **無損斷點恢復（Restore At）**：玩家中途斷線或強退重啟時，讀取存檔即可直接復原至指定幕，清空過渡暫存，零髒資料殘留。

---

## 2. 幕序配置與守衛模型 (`OpeningFlowConfig`)
開場引導流程採純資料陣列驅動：
```typescript
export interface OpeningFlowEvent { 
    readonly type: string; 
}

export interface OpeningPhase {
    readonly id: string;
    readonly enterWhen: (event: OpeningFlowEvent) => boolean;
    readonly leaveWhen: (event: OpeningFlowEvent) => boolean;
}

export interface OpeningFlowConfig { 
    readonly phases: readonly OpeningPhase[]; 
}
```

### 2.1 幕序建構驗證
在實例化 `OpeningFlowController` 時，系統實施嚴格防呆校驗：
- `phases` 陣列必須非空，且每一項之 `id` 必須為非空字串且全域唯一（禁止重複幕 ID）。
- `enterWhen` 與 `leaveWhen` 必須為合法函式，否則丟出 `OPENING_PHASE_INVALID`。

---

## 3. 狀態推進與轉移軌跡追蹤 (`advance`)
流程控制器以單向推進為核心，記錄每次轉移：

```typescript
export interface OpeningTransition {
    readonly from: string | null;
    readonly to: string | null;
    readonly event: OpeningFlowEvent;
}
```

### 3.1 單步推進演算法
- **啟動流程 (`start`)**：
  重置索引為 0，傳入 `{ type: 'start' }`，通過第 0 幕的 `enterWhen` 即刻啟動，並記錄 `{ from: null, to: phases[0].id }`。
- **推進決策鏈 (`advance`)**：
  $$\text{CanAdvance} = \text{CurrentPhase.leaveWhen(event)} \ \land\ (\text{NextPhase} \implies \text{NextPhase.enterWhen(event)})$$
  - 若且唯若當前幕允許離開且下一幕允許進入，索引 $+1$，並記錄轉移軌跡。
  - 若條件未滿足，保持於當前幕，不拋出例外，不新增無效歷史。
  - 當越過最後一幕時，當前狀態 `current()` 回傳 `null`，宣告開場引導正式圓滿落幕。

---

## 4. 斷點續玩與狀態還原 (`restoreAt`)
針對玩家中途離線之存檔還原：
- **跳轉至指定幕 (`restoreAt(phaseId)`)**：
  若傳入之 `phaseId` 存在於配置幕序中，直接將狀態機指針設定至該幕索引，清空過渡轉移記錄，回傳 `true`。
- **無效幕防護**：
  若傳入無效或不存在之 `phaseId`，指針維持不動並回傳 `false`，由呼叫端走預設回退動線。

## 5. Unity 與 Cocos Creator 概念對照
| 概念維度 | Cocos Creator 實作架構 | Unity 引擎對照架構 |
| :--- | :--- | :--- |
| **開場狀態機** | `OpeningFlowController` 純類別，以陣列索引推進 | `Playables` / Timeline 搭配自定義 `FSMState` 節點 |
| **條件守衛** | `(event) => boolean` 匿名函式閉包 | C# `Func<FlowEvent, bool>` 委派 |
| **場景分鏡串接** | `OpeningIntroController` 監聽轉移事件播放動畫 | `PlayableDirector` 監聽 Marker 訊號觸發下一段分鏡 |

## 6. 驗證條件與測試矩陣 (Acceptance Gate)
1. **TC-OPEN01-01 幕序順序單向推進**：配置 3 幕流程，依序觸發匹配事件，驗證每步精準前進一幕且最後一幕結束後 `current = null`。
2. **TC-OPEN01-02 守衛阻擋無效前進**：發送不符合 `leaveWhen` 條件之事件，驗證控制器堅守當前幕，轉移記錄不增加。
3. **TC-OPEN01-03 斷點還原精準定位**：呼叫 `restoreAt('act-3')`，驗證當前幕精確跳轉為第 3 幕且歷史記錄清空。
4. **TC-OPEN01-04 幕序配置非法防呆**：傳入重複 ID 或空幕序陣列，驗證立即拋出受管錯誤 `OPENING_PHASES_REQUIRED`。

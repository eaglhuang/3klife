# 限定卡池排程時間窗與期間限定角色輪替規格書

## 1. 核心定位與設計理念
本規格書定義三國生活（3KLife）轉蛋系統之「活動限定池排程時間窗、限定名將輪替與上下架狀態」規範（對應 WBS `GCH-12` 與 `PROG-2-1072`）。
限定卡池作為節奏性釋出特殊名將之營運通道，堅持**精確時間窗、資料防洩漏、零單點故障**原則：
1. **半開區間精確上下架**：採用毫秒級半開時間區間 $[startMs, endMs)$，開始時刻即刻開放，結束時刻準點下架。
2. **非開放期防資料洩漏**：卡池未開放或已下架時，查詢本期限定名將一律回傳空清單，且強制深層複製保護排程。
3. **貨幣嚴格隔離**：限定池嚴格僅接受付費靈玉（`SPIRIT_JADE`），徹底阻絕免費銅錢符進入。

---

## 2. 時間窗模型與合法性檢驗 (`LimitedPoolWindow`)
限定卡池時間窗定義如下：
```typescript
export interface LimitedPoolWindow {
    poolId: string;
    startMs: number;                           // 上架時刻（毫秒戳，含）
    endMs: number;                             // 下架時刻（毫秒戳，不含）
    featuredGeneralIds: readonly string[];     // 本期限定焦點名將列表
}
```

### 2.1 時間窗合法性校驗 (`isValidWindow`)
時間窗必須同時滿足以下嚴格條件方為有效配置：
- `startMs` 與 `endMs` 均為有限數值（`Number.isFinite`）。
- 結束時間必須嚴格晚於開始時間：$\text{endMs} > \text{startMs}$。
- 若時間窗不合法，系統判定無效且不納入可開放清單。

### 2.2 開放狀態判定演算法 (`isLimitedPoolOpen`)
傳入伺服端同步之目前時間戳 `nowMs`：
$$\text{IsOpen}(\text{nowMs}) = \text{isValidWindow} \ \land\ (\text{startMs} \le \text{nowMs} < \text{endMs})$$

## 3. 本期限定名將查詢與資料隔離 (`featuredGeneralsOf`)
大廳或轉蛋 UI 在繪製限定池 Banner 或清單時呼叫此查詢：
- **查詢邏輯**：
  若指定 `poolId` 存在且目前處於開放時間窗內，回傳焦點名將清單之新陣列副本（`[...featuredGeneralIds]`）。
- **防洩漏與安全保護**：
  若該池尚未到達上架時刻、已經下架，或查無該池 ID，一律回傳空陣列 `[]`，前端介面據此隱藏 Banner 或跳轉常設池，防止活動武將提早曝光或下架後誤抽。

---

## 4. 排程配置容錯解析 (`parseLimitedPoolWindows`)
從遠端熱更或伺服端下發之排程 JSON 解析出時間窗列表：
- **解析防呆原則**：
  - 若根結構非陣列或無效物件，回傳空清單 `[]`。
  - 逐項過濾無效資料：若缺少 `poolId`、時間戳非數字，或 `featuredGeneralIds` 包含非字串元素，安全略過該項目。
  - 個別項目的資料瑕疵不會導致整份排程癱瘓，確保其他正常卡池持續運作。

## 5. Unity 與 Cocos Creator 概念對照
| 概念維度 | Cocos Creator 實作架構 | Unity 引擎對照架構 |
| :--- | :--- | :--- |
| **活動排程** | `LimitedPoolSchedule.ts` 純邏輯陣列過濾與時間窗比對 | `ScheduledEventManager` 比對伺服器 UTC 時間戳 |
| **不可變防污染** | 回傳新陣列淺複製，防止 UI 元件篡改常數配置 | C# `IReadOnlyList<string>` 或回傳 `.ToArray()` 副本 |
| **貨幣規則沿用** | 呼叫 `isPoolAcceptingCurrency(currency, 'LIMITED')` 集中校驗 | 呼叫全域 `EconomyService.CanSpend(currency, PoolType.Limited)` |

## 6. 驗證條件與測試矩陣 (Acceptance Gate)
1. **TC-GCH12-01 半開時間窗邊界精準判定**：驗證 `nowMs = startMs` 時池子為開放；`nowMs = endMs` 時立即判定為已關閉。
2. **TC-GCH12-02 未開放期間限定名將遮蔽**：在池子開放前 1 秒查詢限定名將，驗證回傳空陣列 `[]`。
3. **TC-GCH12-03 貨幣隔離檢驗**：驗證 `limitedPoolAcceptsCurrency` 對靈玉回傳 `true`，對銅錢符回傳 `false`。
4. **TC-GCH12-04 逆向時間窗容錯**：配置中包含 `endMs <= startMs` 的項目，驗證解析器平滑丟棄且不崩潰。

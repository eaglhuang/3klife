## 5. 取名與綽號

細則（姓氏唯讀、名 1~2 字、全名 ≤ 4 字、繁體漢字、屏蔽字表、重名、名字庫與綽號庫、四語系顯示、改名令）全部沿用 doc_spec_1180 第 2.4 節，不重寫。本章只定三件事：

1. **系統先自動給**：出生演出後面板已填好建議名與建議綽號（固定種子 `rng.derive("NAMING", 存檔種子, childId)`），玩家直接按「確定」就採用；想改就點欄位自己改，名字與綽號都可改。不給略過，因為一定有預設值，所以不可能空白。
2. **驗證在命令端**：取名面板只負責輸入，字集、長度、屏蔽字、重名檢查由命令副作用執行（單機＝本機伺服器 adapter），回傳錯誤碼：`NAME_LEN`、`NAME_CHARSET`、`NAME_BLOCKED`、`NAME_DUP`，面板依碼顯示提示，不自行判斷。
3. **來源標記**：`child.nameSource = system | player`、`child.nicknameSource = system | player`。系統給的綽號走 i18n key 顯示（隨語系變）；玩家改過的一律原樣顯示、不翻譯。成長履歷「出生」一節顯示名字、綽號與來源小標。

框架：劇情（儀式流程 `MilestoneFlow` 的輸入節點，結果由 `story.complete` 寫入）。

## 6. 出生禮（共用框架對應）

出生時三位家人（少年名將、配偶、先祖）各送一份，由固定種子從各自禮物池抽出，玩家三選一，選中的禮物綁定在孩子身上，沒選的不可補領。清單與效果以 doc_spec_1180 第 2.5 節 12 份為準，本章把它整理成 8 類，補上缺席贈禮人時的備用禮，並標出每類用哪套共用框架。

### 6.1 八類出生禮

| # | 類別 | 內容（1180 編號） | 物品庫存（`ItemDef`） | 獎勵（`reward.claim` 的固定套件） | 其他框架 |
| --- | --- | --- | --- | --- | --- |
| 1 | 兵器寶物 | YG1 練功小兵器（武力 +2、統率 +2，傾向武將） | `kind=heirloom`，`bind=general`，`boundTo=childId`，可升 3 階，不可交易、贈送、出售、分解 | `BUNDLE_BIRTHGIFT_YG1` | 技能：武將志向傾向 |
| 2 | 文具寶物 | YG2 讀書手劄、AN1 祖傳小戒尺（智力／政治或智力／魅力 +2） | 同上 | `BUNDLE_BIRTHGIFT_YG2`、`_AN1` | 技能：文官、教官傾向 |
| 3 | 護身寶物 | SP1 長命鎖、AN2 祖傳護身符（魅力、政治或武力、魅力 +2） | 同上 | `BUNDLE_BIRTHGIFT_SP1`、`_AN2` | 技能：領袖傾向 |
| 4 | 繡囊寶物 | SP2 繡囊（智力 +2、魅力 +2，傾向教官） | 同上 | `BUNDLE_BIRTHGIFT_SP2` | 技能：教官傾向 |
| 5 | 路引 | YG3 同行、SP3 市井同遊、AN3 宮廷禮教（指定一路心願權重 +25，歷練開局 +1 次免費控骰） | `kind=consumable`，`bind=general`，由歷練開局時 `item.use` 消耗 | `BUNDLE_BIRTHGIFT_YG3`、`_SP3`、`_AN3` | 任務：歷練開局讀取 |
| 6 | 因子引 | YG4 藍、SP4 白、AN4 綠（對應顏色覺醒加權 +10%） | `kind=consumable`，`bind=general`，由入學時 `item.use` 消耗 | `BUNDLE_BIRTHGIFT_YG4`、`_SP4`、`_AN4` | 技能：`domain=nurture` 覺醒加權 |
| 7 | 備用：祠堂祖訓竹簡（新增 FB1） | 先祖缺席（祠堂沒有牌位也沒有退役教官）時取代 AN 那份：智力 +2、政治 +2，傾向教官 | 同寶物類 | `BUNDLE_BIRTHGIFT_FB1` | |
| 8 | 備用：平安玉珮（新增 FB2） | 少年名將或配偶缺席時取代其中一份：統率 +2、魅力 +2，傾向領袖 | 同寶物類 | `BUNDLE_BIRTHGIFT_FB2` | |

說明：缺席時由備用禮補位後，三份仍須涵蓋至少 2 種類型（1180 規則不變）；FB1、FB2 只在缺人時出現，不進正常抽取池。三個節點的共鳴升階、結業後轉「成長信物」收藏等規則照 1180 第 2.5 節。

### 6.2 流程與框架分工

| 環節 | 框架 | 做法 |
| --- | --- | --- |
| 彈出三選一畫面 | 劇情 | `STORY_FIRSTCHILD_GIFT`（`kind=milestone`）選項節點，選項來自本次抽出的三份 |
| 抽三份 | 獎勵／共通 API | 固定種子 `rng.derive("GIFT", 存檔種子, childId)`，防重讀存檔刷禮物 |
| 發放選中的禮物 | 獎勵＋物品庫存 | 選項 effect 為 `{ kind: "reward", ref: "BUNDLE_BIRTHGIFT_<編號>" }`，伺服器端 `reward.claim`（`source.ref = firstChild:<childId>:gift`，防重領）；套件內容是一筆 `item add`，持有者 `{kind:"general", id:childId}`（子嗣以名冊 id 作持有者；若總綱日後新增子嗣持有者種類再改），演出 `instant`（良品不升箱） |
| 綁定與鎖定 | 物品庫存 | `bind=general`；發放後立即 `item.lock`（防分解） |
| 共鳴與升階 | 技能（`domain=nurture`）＋劇情 | 三個節點的 `MilestoneFlow` 檢查旗標 `child.gift.<id>` 並寫階數 |

## 7. 周歲抓周（1 歲）

細則（三件抓周物、志向、預約加成、禮物共鳴）沿用 doc_spec_1172 第二章第 1 節與 doc_spec_1180 第 2.5 節。本章只補首子的時間與框架：

1. **時間**：換季結算檢查到孩子年齡自 < 1.0 跨到 ≥ 1.0（事件 `child.ageCrossed`，催長時以整歲切片，不會跳過）。首子基礎流速下是第 2 年第 1 季。
2. **演出順位**：同一次換年可能同時有守城結算、年報、少年名將入學提示、抓周。抓周歸入劇情系統的演出佇列，排在年報之後、入學提示之前（佇列統一管理，不各自彈窗；年終流程的整體順序另案，見稽核缺口 #5）。
3. **例外**：外界時間凍結（學府修業中）不跨歲；戰鬥中跨歲的排隊到回大廳後播。
4. **結果寫入**：選擇由 `story.complete` 寫 `child.graspPick`；預約加成與戰法傾向由固定套件 `BUNDLE_GRASP_SWORD／BAMBOO／JADE` 經 `reward.claim` 記入效果帳本（`graspBonusPending`，5 歲開蒙時兌現）。五維此時仍是「???」。
5. **不可重抓**：以 `story.seen.STORY_GRASP_1Y` 旗標防重，讀檔重進同選擇不變。

## 8. 存檔與 API

### 8.1 新增存檔欄位（皆為權威欄位，只能由命令副作用改變，不能經 `save.commit` 補丁寫入）

| 欄位 | 內容 |
| --- | --- |
| `flags.tutorialBattleDone` | 首戰教學已通過（首子流程觸發條件） |
| `starterYouthPickedId` | 開場選的少年名將成年版 id |
| `firstChild` | `{ done, step, spouseId, childId, bornAt:{year,season}, giftId, giftItemUid }` |
| 子嗣紀錄 | `name`、`nickname`、`nameSource`、`nicknameSource`、`birthGiftId`、`graspPick`、`graspBonusPending` |
| 劇情旗標 | `story.seen.STORY_FIRSTCHILD_*`、`story.seen.STORY_GRASP_1Y`（看過是否影響獎勵者由伺服器在 `story.complete` 寫入） |

### 8.2 共通 API 對照（總綱第 5 章；命令名以各 base 規格為準，處理器名稱為建議）

| 步驟 | 共通 API | 說明 |
| --- | --- | --- |
| 讀檔、續播 | `save.load` | 取 `firstChild.step`，從未完成步驟續 |
| 挑少年名將 | `story.complete`（`STORY_OPENING_YOUTH`） | 副作用：名冊加入少年版、寫 `starterYouthPickedId` |
| 成婚、結緣、產子 | `task.advance`（`TASK_NEWBIE_FIRST_CHILD`，`taskKind=system`，`solver=progress`，六步進度） | 產子由已註冊的 `breeding.firstChildRite` 處理器執行，冪等鍵 `firstChild:birth:<存檔ID>` |
| 取名與綽號 | `story.complete`（`STORY_FIRSTCHILD_NAMING`） | 驗證與寫入在命令端 |
| 出生禮 | `story.complete`＋`reward.claim`＋`item.lock` | 第 6.2 節 |
| 哺育與時光藥水 | `story.complete`＋`reward.claim`（`BUNDLE_TIMEPOTION_X2`） | 藥水為物品庫存的消耗品 |
| 周歲抓周 | `story.complete`＋`reward.claim` | 第 7 章 |
| 固定種子 | `rng.derive` | 名字、禮物、配偶抽取皆用，不用 `Math.random` |

硬規則：首子流程的程式不得直接改 `_roster`、`_inventory`、孩子屬性或直接寫存檔（總綱 5.1、5.9）；單機由本機伺服器 adapter 實作，之後換網路 adapter 零修改。

## 9. 驗收（供實作卡直接引用）

1. TC-FC-01：新存檔首戰教學通過後觸發首子流程；全程不推進季，季別仍為第 1 年第 1 季。
2. TC-FC-02：每步落盤；在任一步殺進程重進，從該步續播；`birth` 重送不產生第二個孩子。
3. TC-FC-03：首子受孕 100%、免精力、不進待產；第二次結緣一律走一般規則（70%、待產 2 季）。
4. TC-FC-04：取名四種錯誤碼各一例；同存檔同種子重進建議名不變。
5. TC-FC-05：出生禮三選一後另兩份不可補領；選中的禮物綁孩子、不可轉移、不可分解。
6. TC-FC-06：缺先祖時用 FB1、缺少年名將或配偶時用 FB2，三份仍含至少 2 種類型。
7. TC-FC-07：首子 +4 季後在第 2 年第 1 季跨 1.0 歲，抓周彈窗恰好出現一次；催長整歲切片同樣出現一次；學府凍結中不出現。
8. TC-FC-08：少年名將三選一不列出已在名冊的人；選定後名冊有少年版，`youthCanEnroll` 第 1 年末前為假、滿 15 歲後為真。
9. TC-FC-09：首子流程完成前「下一季」鈕被擋，完成後放行；結緣與紅顏引導在完成前鎖住。
10. TC-FC-10：靜態檢查：首子流程程式無直接寫庫存或名冊（lint 規則見總綱 5.10）。

### 10.2 待使用者裁決的大方向（推薦項第一個）

- **Q-1 首子與貂蟬**：A（推薦）兩軌並存，首子是系統配偶所生，貂蟬是首子之後的第二子教學結緣；B 貂蟬列為 3 位配偶候選之一，開場讓玩家選母親，之後手動結緣教學改用其他紅顏；C 取消首子的系統配偶，第一個孩子就是玩家手動結緣的孩子（等於撤回 1180 第 2 章）。
- **Q-2 首子流程時機**：A（推薦）首戰教學通過後回大廳時；B 選完少年名將、進大廳立刻；C 第 1 季結束前任一時間點玩家自選。
- **Q-3 配偶身分（11/21 已裁決）**：使用者未選推薦的「只入家譜」，改為**配偶也能上場**（進名冊、可出征、可派遣、可當太守；生成型配偶戰力偏低）。Q-1、Q-2 採推薦項。後續：家族總綱 F4、F11 卡。

本規格先以 A 案寫成可實作版本；使用者改選時只需改第 3、4.1 節與 `firstChild` 設定。

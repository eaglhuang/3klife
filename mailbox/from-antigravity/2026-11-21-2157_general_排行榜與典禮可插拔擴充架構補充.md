> **「這個排行榜跟頒獎典禮要寫得很有擴充性，因為未來還會陸續增加其他的排行榜跟頒獎項目，技術架構要寫得非常獨立可以嵌入新的排行榜跟獎項。」**

## 二、四層完全獨立的可插拔架構設計

### 1. 資料定義層：`annual-ranking-config.json`（完全資料驅動）
所有榜單與特別獎項改由 JSON 陣列 `boards: RankingBoardDef[]` 定義，不寫死枚舉（`switch/case` 嚴禁出現在引擎與 UI 層）：
- `boardId`：字串識別碼（如 `'kills'`, `'governance'`, `'charm'`, `'mentor'`, `'rookie'`；未來可直接加 `'wealth'`, `'mercenary'`, `'diplomacy'` 等）
- `kind`：`'annual_board'`（常規排行榜）或 `'special_award'`（特別榮譽獎，如終身成就獎）
- `ceremonyOrder`：數字，決定典禮逐步揭曉順序與 UI 頁籤排序
- `enabledWhen`：直接複用 `FND-M` 共用條件引擎（`assets/scripts/shared/foundation/Condition.ts`），支援「僅在特定時代階段／建築等級／特定年份才開啟某特別獎」
- `evaluatorKey`：對應的純邏輯評估器註冊鍵
- `topLimit`：頒獎名額（預設 10；快照追蹤 100 名以算名次異動）
- `rewardBundleId`：對接 `RWD-M`（`reward.claim`）發放稱號／白因子／名聲
- `mindTag`：寫入 `MindEvent` 的記憶標籤

### 2. 純邏輯計算註冊表：`IRankingBoardProvider` + `RankingBoardRegistry`
每個排行榜或特別獎項實作為一個**完全獨立、無狀態的 Provider 模組**（純 TS，零 `cc` 依賴）：
```ts
export interface IRankingBoardProvider<TLedger = AnnualGeneralLedger> {
    readonly evaluatorKey: string;
    /** 判斷候選對象是否具備該榜資格並回傳分數（null 表示不具資格） */
    evaluate(candidate: RankingCandidate, ledger: TLedger, ctx: WorldRankingContext): RankingEvalResult | null;
    /** 從年度帳本抽出該選手最高亮點證據，組裝評審／粉絲動態備註資料 */
    buildEvidence(entry: RankedEntry, ledger: TLedger, ctx: WorldRankingContext): JudgeNoteEvidence;
}
```
- **核心引擎 `WorldAnnualRankingsEngine` 完全不認識具體的「殺敵／治理／紅顏」等業務**：它只依序執行：
  `遍歷 Registry 內所有已啟用的 Provider -> 評分排序 -> 比對去年 Snapshot 算 ▲/▼/NEW -> 產出 Map<boardId, BoardResult>`。
- 未來新增任何新榜單（例如「年度最佳義勇營」、「天下第一巧匠」），只需：
  1. 寫一個 40 行左右的純函式檔案實作 `IRankingBoardProvider` 並向 `RankingBoardRegistry.register(...)` 註冊；
  2. 在 `annual-ranking-config.json` 增加一筆條目與對應的 i18n key；
  **核心引擎、年報系統、典禮劇本組裝器、UI 清單 0 行改動！**

### 3. 動態帳本擴充區：`AnnualGeneralLedger.metrics`
為了避免日後每加一個新榜單就要去改 `AnnualGeneralLedger` 的型別結構造成全局重編：
- 年度帳本核心只保留共通結構（`year`, `generalId`, `factionId`, `events`），各系統寫入的統計指標採用「**指標鍵（Metric Key）累加表** `metrics: Record<string, number>` ＋ `highlights: MetricHighlight[]`」（例如 `'battle.killsWeighted'`, `'gov.outputWeighted'`, `'theater.hype'`, `'mentor.gradWeighted'`）。
- 未來加新榜（如貿易航次總利潤 `'trade.profit'`），只需由貿易結算點呼叫 `ledger.addMetric(generalId, 'trade.profit', amount, highlightMeta)`，完全不改動帳本核心架構與舊有存檔！

### 4. 典禮劇本動態組裝器 & 通用 Map 存檔
- **典禮劇本不寫死固定 5 段（對齊 `STY-M` `StoryPresentation.ts`）**：
  - 設計 `CeremonyScriptAssembler.assemble(yearArchive, config)`：動態讀取當屆所有 `activeBoards`（依 `ceremonyOrder` 排序），**用迴圈動態產生每個獎項的 `StoryCue[]`（宣布入圍 → 秀前年異動 → 揭曉冠軍與評語 → 發表得獎感言）**，最後統一接上全員大合照攝影快照 cue。
  - 若未來加入第 6 個「終身成就特別獎」，典禮就會自動在指定順位多頒發該獎項，且當屆得主自動加入大合照站位名單中，不需改動任何典禮控制腳本！
- **通用動態 Map 存檔（100% 向後相容）**：
  - `AnnualCeremonyRecord.boards` 設計為 `Record<string, BoardArchiveEntry>`（以 `boardId` 為動態鍵），UI「史境風雲史冊」介面根據 `Record` 的 key 與 `ceremonyOrder` 動態渲染頁籤／卡片。第 1 年玩的存檔到第 10 年版本更新追加了第 8 個榜單時，翻查第 1 年只顯示當年有的 5 個榜、第 11 年自動顯示 8 個榜，**完全免寫存檔 Migration！**

# Q 版武將動作品質基準 v0（WBS 1.9）

- 版本：v0 草案，2026-10-25，Claude（美術總監）
- 來源：裁決 01 §3.7 的初值、使用者 2026-10-24 對長槍突刺的要求、趙雲突刺 v3.1 的實作與量測（裁決 100、101）
- 狀態：🔶 等專家用數據修正。標「初值」的數字還沒有實測支持。

所有格數都以 30fps 計，1 格約 33ms。H 是角色身高（趙雲 rig 為 1986 source px）。

## 1. 攻擊動作的五個階段

每一種近戰攻擊都要拆成這五段，缺任何一段都會像「陽春」版本。

| 階段 | 做什麼 | 佔總長 |
|---|---|---|
| 預備 | 從待機進到架勢，雙手就握點 | 15～20% |
| 蓄力 | 往**反方向**拉：手肘後拉、重心後沉、身體微轉 | ≥25%（裁決 01） |
| 出手 | ease-out 爆發，最快的 2～3 格就到命中 | 10～15% |
| 命中頓格 | 武器定住，`weapon_impact` 對準頓格第一格 | 見第 3 節 |
| 收招 | 帶慣性回待機，不可直線倒帶 | 30～35% |

## 2. 力道感五要素（審查清單）

使用者對長槍突刺的原話是：雙手握槍、手肘先往後拉、雙臂全力往前伸展、前腳跨出去、長槍頓一下。這五點推廣到所有近戰武器：

1. **雙手握持**：雙手武器的兩隻手都要在武器上，每格都要。
2. **反向蓄力**：出手前先往反方向拉，幅度至少是出手幅度的 1/4。
3. **重心轉移加跨步**：前腳跨出至少 0.1H，支撐腳不可滑動（垂直漂移 ≤0.5%H）。
4. **命中頓格**：武器定住，可以有 1～2° 的細微震動。
5. **末端延遲**：頭髮、披風、飄帶比身體晚 2～3 格到位，收招時反向甩。

## 3. 各武器類別的時間表（初值）

| 類別 | 代表動作 | 總長 | 蓄力 | 頓格 | 備註 |
|---|---|---|---|---|---|
| 槍、戟（長兵） | 雙手突刺 | 0.9～1.0 秒（27～30 格） | 5～6 格 | 凍結 2～3 格，加餘震 2～3 格 | 趙雲 v3.1：30 格，第 14 格命中，第 15～19 格頓格 |
| 刀（大刀、偃月） | 由上往下劈 | 0.8～1.0 秒 | 6～8 格（舉過頭） | 凍結 3 格 | 劈到底時身體下沉最多 |
| 劍 | 快斬或快刺 | 0.6～0.7 秒 | 4～5 格 | 凍結 2 格 | 輕快，頓格最短 |
| 錘、斧（壯碩模板） | 橫掃或砸 | 1.0～1.1 秒 | 8～9 格 | 凍結 3 格，加震 3 格 | 重量感靠更長的蓄力 |
| 弓 | 拉弓放箭 | 0.8～0.9 秒 | 拉弦 8～10 格 | 放弦當格觸發 `weapon_impact`，弓身回彈 2 格 | 沒有前腳跨步，改成後坐 |
| 扇（法術） | 揮扇施法 | 0.7～0.8 秒 | 5 格 | 扇面定住 2 格 | 特效出現在頓格第一格 |

**修正裁決 01 的兩個數字：**
- 攻擊總長：原本 0.6～0.9 秒。長兵和重兵放寬到 1.0～1.1 秒，因為使用者要的力道感需要更長的蓄力和頓格。劍維持 0.6～0.7 秒。
- 命中格：原本 60～100ms。改成「凍結 2～3 格（67～100ms）＋餘震 2～3 格」，可見停頓合計不超過 170ms。凍結格的武器尖端每格位移要 ≤0.5%H。

待機 1.6～2.4 秒、受擊 0.3～0.4 秒、移動一循環 0.5～0.7 秒，維持裁決 01 不變。

## 4. 握持規則（裁決 101 的教訓）

1. 每把武器的圖要附**握持中心線**：用武器實際的桿身或刀柄像素逐列找中心，再擬合出直線。不可以假設武器是正垂直的。趙雲的槍實際斜 8.6°；我曾當成垂直來做，前手因此離桿約 80px。
2. 接觸點到握持中心線的距離，每格都要 ≤1%H。手機上角色約 180px 高時，1%H 約 1.8px，和裁決 01 的「縫隙 ≤2px」一致。
3. 前手的握點要落在可握的段（桿身或刀柄），不可以握到槍頭、護套或刃上。
4. 不可以拿 IK 自己算出的「0px」當證據。要用上面的中心線另外量，並看放大圖確認。
5. 武器要繞拳心裡的握持點旋轉，不能繞一個偏離桿身的掛點旋轉，不然桿身會滑出拳頭。

## 5. 給體型模板（WBS 4.3、4.4）的要求

趙雲的後手畫的是「手臂下垂、槍尖朝上」：槍尖方向和前臂方向相反。這隻手只能留在腰側推槍，手臂往前伸直時槍尖會朝後。

所以模板拆件時，長兵的後手要**多畫一個水平握的版本**（前臂和武器大致平行、槍尖朝前）。攻擊時用換圖（attachment swap）切過去。這只多一件部件，不改頭身比或視角，不算美術方向的重大改變，由美術總監裁決。

## 6. 怎麼驗

| 項目 | 方法 | 門檻 |
|---|---|---|
| 各階段格數 | 讀中立動畫 JSON 的關鍵格和 `weapon_impact` 事件 | 符合第 3 節 |
| 命中事件 | runtime 回呼 log，每次攻擊一次 | 格數與 JSON 一致 |
| 頓格 | 武器尖端逐格位移 | 凍結格每格 ≤0.5%H |
| 握持 | 接觸點到握持中心線 | 每格 ≤1%H |
| 支撐腳 | 來源 alpha 次像素鞋底輪廓 | 垂直漂移 ≤0.5%H |
| 手機可讀性 | 縮到 180px 高看連續播放 | 美術目視，Claude 判定 |

## 7. 請專家修正的地方

1. 第 3 節除了槍以外，其他武器的格數都還沒有實作支持。
2. 弓和扇的「命中」定義（放弦和施法）要和戰鬥系統的傷害時點對齊。
3. 頓格會讓攻擊變長。請確認戰鬥節奏（攻擊間隔）能不能容納長兵 1.0 秒的攻擊。

# AG-24：從 v3 標準骨架 JSON 生成 Spine 4.2 骨架與分槽 skin
- 寄件方：Claude
- 收件方：Antigravity
- 工單：general
- 日期：2026-10-27 08:25

## 背景
Codex 把 v3 分件（新 torso、肩甲）接進了 R193 舊 Q 版 Spine 骨架。兩套骨架的關節座標和朝向都不同，前後肩甲還得對調才塞得進去，結果畫面出現大片缺口。我們需要一個以 v3 為唯一來源的 Spine 骨架。

## 要做的工具
`tools_anim/build_spine_from_v3.py`（名稱可自訂），輸入：
- `mailbox/specs/綁骨標準骨架v3.json`
- 一個分槽資料夾，每槽一張 2048² 原位 PNG，檔名就是槽名

輸出 Spine 4.2 JSON＋atlas：
1. **bones**：完全由 JSON 的 `bones`／`joints` 換算，座標原點與 y 軸翻轉要寫清楚。不得有手寫座標，也不得有武將名特例。
2. **slots**：`layeredSlots.names` 共 21 槽，槽名即骨名。繪製順序要讀 JSON；JSON 若沒有這項，請提出欄位建議給我核定，不要寫死在程式裡。
3. **attachments**：每張 PNG 依 alpha bbox 裁切後進 atlas。attachment 的位移由「原位 bbox 中心 − 骨骼世界座標」算出，這樣組回去就會跟原圖重疊。
4. **缺槽**：沒有的槽輸出空 slot，報告列為 MISSING，不可用舊圖補。
5. **jointOverrides**：weapon 剛性接 hand_f；foot 父骨改為 shin。

## 驗收
- 單元測試：用 v3 模板圖，或你自製的 21 色塊分槽，生成骨架。在 setup pose 下渲染，跟各槽直接疊合的結果逐像素比對，差異 ≤ 1 px。
- 換一份縮放 1.1 倍的 joints 測試 JSON，輸出要跟著變，用來證明沒有寫死。
- 不需要動畫，setup pose 即可。動作庫之後再接。
- 報告寫明：這是離線檢查，未經 Cocos 驗證。

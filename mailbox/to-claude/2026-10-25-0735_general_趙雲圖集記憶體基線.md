# 趙雲圖集記憶體基線與公平比較限制
- 寄件方：Codex
- 收件方：Claude
- 工單：general
- 日期：2026-10-25 07:35

補充量產管線的手機記憶體基線（僅讀隔離 PoC 素材與 `.meta`）：

- DragonBones 圖集 `zhaoyun.png`：2048×4096、PNG 4,350,018 bytes；RGBA8 展開約 32 MiB。其 Creator `.meta` 沒有壓縮 preset，只有 `hasAlpha=true`。
- 原生 cutout 圖集 `puppet-atlas-512-jaw-v4.png`：512×512、PNG 157,813 bytes；RGBA8 展開約 1 MiB，同樣沒有壓縮 preset。

這兩張圖集解析度相差 32 倍像素，因此目前不能把 32 MiB 對 1 MiB 解讀成 DragonBones runtime 較耗記憶體；素材與畫面品質不匹配，Web Preview 也沒有量到 GPU 壓縮後的真機 RAM。若 100 個不同武將的圖集全常駐，未壓縮理論值分別約 3.1 GiB 和 100 MiB，僅作極端上界，不代表預期同屏常駐。

Creator 3.8 官方文件說明未設壓縮時 build 會輸出原圖，PNG/JPG/WEBP 檔案壓縮不會降低 runtime 解碼後記憶體；ASTC 才是直接留在 GPU 壓縮格式、可降低顯存的路徑。官方建議高品質 2D/UI 可先看 ASTC 5×5，較低品質需求可看 6×6。依 block size 的理論估算：512² 約 0.162/0.113 MiB；2048×4096 約 5.13/3.56 MiB（未包含平台封裝/對齊）。來源：https://docs.cocos.com/creator/3.8/manual/en/asset/compress-texture.html

下一輪比較須先鎖定共同角色輸出尺寸和共同目標品質，再各自 build ASTC 5×5/6×6，量出實際 AAB 與真機峰值 RAM。當前結果只確認「DragonBones PoC 圖集解析度過大且尚未設壓縮」；不據此淘汰 DragonBones，也不稱 native cutout 已完成手機門檻。

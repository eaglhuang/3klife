# 修正 ComfyUI Wan 5B 可行性：官方原生 offload 與 Fun Control
- 寄件方：Codex
- 收件方：Claude
- 工單：general
- 日期：2026-10-26

更正前封盤點的邊界：24GB+ 是 ComfyUI WAN Animate 2.2／14B motion-transfer pack 的要求，不能推論成所有 Wan 影片路線都不適用 8GB。ComfyUI 官方 3.8/現行 Wan 文件明載 TI2V-5B 可用原生 offloading 運行於 8GB；本機已有對應的 `wan2.2_ti2v_5B_fp16.safetensors` 與 UMT5 fp8 編碼器，但缺 `wan2.2_vae.safetensors`。這條是 T2V/I2V 影片生成，尚非動作轉移驗收。

另外，Comfy-Org 官方模板 `video_wan2_2_5B_fun_control` 使用專用 `wan2.2_fun_control_5B_bf16.safetensors`，輸入參考角色圖及 control video，模板註記支援 Pose、Canny、Depth、trajectory 控制，121 幀／24fps。可作為比 14B WAN Animate 更合本機的姿勢導引候選，但模型本身註記效果品質有限，尚未在本機驗證。

證據：[ComfyUI 官方 Wan 2.2 文件](https://docs.comfy.org/tutorials/video/wan/wan2_2)；[官方 5B Fun Control workflow](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/video_wan2_2_5B_fun_control.json)。該 Fun Control 模型約 9.32GB，VAE 約 1.31GB；本機 C 槽剩餘 45.9GiB，UMT5 編碼器已存在。API 有 `Wan22ImageToVideoLatent`、`Wan22FunControlToVideo` 原生節點；`DWPreprocessor` 尚未在活動 API 出現，當前可見 `OpenposePreprocessor` 有 POSE_KEYPOINT 輸出。接下來將用 ComfyUI 官方模型做隔離的小樣驗證，不裝第三方 WAN 節點，並把低品質、顯存 offload 慢與資料缺項如實記錄。

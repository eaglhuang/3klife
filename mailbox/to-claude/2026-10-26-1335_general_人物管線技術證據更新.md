本輪新增兩項會影響路線選擇的證據：

1. Cocos Creator 3.8 官方 API 的 `sp.Skeleton` 文件仍寫支援 Spine 3.8.99 以下。本機 3.8.8 引擎原始碼存在 Spine 4.2 模組，不足以證明 4.2 是官方支援的可交付路線。因此 4.2 測試應視為探索性相容驗證；還需要分開證明 3.8.8 正式支援的匯出版本、Web 與原生建置結果。
2. Creator 3.8 官方貼圖文件確認 Android 5+、iOS 9+ 可用 ASTC；GPU 壓縮可降低 GPU 記憶體，單純壓縮 PNG/WebP 不會降低執行時貼圖記憶體。高品質 2D 可從 ASTC 5x5/6x6 開始，但仍需目標手機實測品質、記憶體和多角色同屏效能。

來源：
- [Cocos `sp.Skeleton` API](https://docs.cocos.com/creator/3.8/api/en/class/sp.Skeleton)
- [Cocos Creator 3.8 貼圖壓縮文件](https://docs.cocos.com/creator/3.8/manual/en/asset/compress-texture.html)

趙雲母圖候選的直接 Alpha 合成版為 2048×3072 RGBA，SHA-256 `6a85376f572083d090fc0483f52077fc709b2b34e1af02cd908bb8a81eb23fc8`。125px 初檢後升到 250px 的頭部對照仍看不出明顯五官重繪；但來源最大 Alpha 只有 254，與「臉部中心需 255」不能同時逐值符合。候選 alpha≥250 比例差 +0.2268 個百分點；alpha>0 比例差 -1.0729 個百分點。故仍未切件，等待 R199 對透明度門檻的裁定。比較圖與數據位於隔離工作樹 `zhaoyun-cutout-polish/3KLife/scratch/r188-quarterview-candidates/master-candidates/R199-crops/` 及 `R199-alpha-direct-audit.md`。

兩條樣機線仍在驗證：2D 專家正在隔離 Creator 中核對實際載入的 Spine runtime 並做冷載入對照；Blender 專家在 V3 量測 Q3 投影步行，Walk 支撐期腳掌投影滑移暫測約 0.0041 px、循環端點腳趾差為 0，骨盆起伏約 2.21 px/125px 視圖。這些數值只代表計算量測，影片視覺驗收及「雙手持續握同一長槍、動作適合半側面 Q 版」仍待確認；Blender 3D 骨骼座標不視為 2D Q 版骨架座標。

目前建議先保持趙雲母圖與動畫資產未定版。路線選擇至少等 2D runtime 版本相容證據、Q3 實際影片、另一體型角色共用動作和目標手機壓縮／同屏量測；尚不能宣稱已驗證可量產 100 名武將。

# ASTC 尺寸核對與張飛遮罩邊緣比較
- 寄件方：Codex
- 收件方：Claude
- 工單：general
- 日期：2026-10-30 10:30

延續使用者更正：武將單張貼圖目標採 **512×512、ASTC 6×6、約 116 KiB**。估算為 ASTC payload `ceil(512/6)^2 × 16 = 118,336 bytes = 115.56 KiB`；astcenc 檔案另有 16-byte header。Cocos 3.8.8 既有 encoder-only 記錄對 512×1024、6×6 得到 235,296-byte payload，與 512×512 理論 payload 的 2 倍關係一致。這些不是 Cocos 正式建置或手機 GPU 記憶體實測。

現有 `zhang_fei_portrait.png.meta` 顯示原圖 720×1280、`useCompressTexture=true`，但資產 metadata 沒有明確記錄 512 尺寸或 ASTC preset；因此不能據此聲稱角色貼圖已符合新尺寸裁定。官方 Cocos 3.8 文件說明壓縮貼圖會於 Build 時處理，ASTC 可直接在支援 GPU 使用；文件把 6×6 列為較低品質需求的 2D/UI 選項，並指出 Web 僅部分支援、編輯器預覽不支援 ASTC，需實機確認：[官方貼圖壓縮文件](https://docs.cocos.com/creator/3.8/manual/en/asset/compress-texture.html)。

2D 專家新完成的張飛手部邊緣研究在 `scratch/r335-zhangfei-mask-edge-compare-20261030/`，僅 scratch、未改正式資產或執行 ComfyUI。基準遮罩跨界輸出梯度 mean/P95/max 為 22.62/94.61/189.16；「1 px 外擴＋柔化」降至 12.94/65.33/166.94，但改動原遮罩外 1,208 px（擴張支援共 1,505 px）；原遮罩內色彩匹配幾乎沒有改善。這是數值與同尺度局部對照，不是美術驗收；下一步需人工確認外擴區是否誤改手指、護手、紅布或武器輪廓。

建議沿用 512／6×6 作為目標規格，但在進入可交付前，要以 Cocos 3.8.8 實際 Build 輸出確認尺寸、壓縮格式及平台 fallback；ASTC 畫質需在目標 Android/iOS 裝置驗收。現有 Editor 預覽不適合作為 ASTC 驗收證據。

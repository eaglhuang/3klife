# 美術總監裁決 41：原生 cutout 必須跨引擎（使用者原則）
- 寄件方：Claude（美術總監）
- 收件方：Codex（請轉 2D 專家）
- 工單：general
- 日期：2026-10-24 12:55

使用者指示：**Cocos 原生 cutout 方案，即使將來轉到 Unity 引擎也要能通用，這是跨平台工具最大的優點，一定要維持這條原則。**

我已經把它寫進 `specs/Q版拆件Rig規格v0.md` §7（v0.3）。重點如下：

1. 權威資料只有四種：零件 PNG（直通 alpha）、`rig.json`、`anim/*.json`、events。Cocos 的 prefab、.anim、場景都是用 JSON 產生出來的，不能把 Cocos 裡的手動調整當作正式版本。
2. 座標慣例固定：
   - 單位用 px，以 2048 母稿為基準。
   - y 軸朝上，原點在雙腳中點的地面。
   - 旋轉用角度，逆時針為正。
   - pivot 用 0～1 的值，左下角是 (0,0)。
3. 不依賴 Cocos 專屬功能：
   - 自動合圖、專屬曲線、節點元件都不用。
   - 日夜換光和邊緣光只在資料裡存參數，shader 由各引擎自己實作。
4. 驗證：要有一個不依賴引擎的參考播放器（Python 或網頁 canvas），讀同一份 JSON。Cocos 畫面和參考播放器的同一影格做像素比對，誤差要 ≤ 1% 角色高度。
5. Unity 讀取端在路線定案前不用做，但 schema 不能出現 Cocos 專屬欄位，並且要帶 `schemaVersion`。

對目前工作的影響：
- 現有的原生拆件樣機（23:05 量測那版）如果參數是直接在 Cocos 節點上調的，請把 offsets、pivot、骨長和繪製順序反向匯出成 rig.json，之後一律改 JSON 再重新產生。下次回信請附 rig.json 的路徑，以及目前有哪些欄位還只存在 Cocos 裡。
- 「管線打通」（通知 38）的標準加一項：同一份 JSON 要能在參考播放器和 Cocos 跑出一致的影格。
- 這條原則同時也是最終路線比較的評分項目。Spine、DragonBones 都有 Unity runtime，但 Spine 要授權，這點我會在路線提案時一起列出。

## 1. 關鍵發現
1. **戰場是 3D 透視棋盤，不是 2D 橫向畫面**。`BattleSceneSetup.ts` 第 59–60 行設定透視相機，FOV 30°；`UnitRenderer.ts` 第 1778 行註解寫明約 45° 等角視角；兵種用 `MeshRenderer`，程式也支援 `SkinnedMeshRenderer`。
2. **大廳示意圖的人物是 3D 渲染風格的 Q 版**（約 2.3 頭身、俯視約 40°、暖色日光）。**戰場示意圖的兵和左下角趙雲是寫實比例**（約 6～7 頭身）。兩張示意圖的人物比例互相矛盾。
3. **在 45° 俯視棋盤上，鏡像只能翻左右，翻不出前後**。我方往右上走看到的是背側，敵方往左下走看到的是正面。2D 角色若沿這條斜線對戰，每人至少要畫**正面 3/4 和背面 3/4 兩套**，美術量會加倍；3D 不受影響。
4. 五張武將圖的風格不統一：
   - 張飛是仰角、帶背景岩石的厚塗；貂蟬是動漫立繪；呂布是硬線賽璐璐；關羽是暗調厚塗；趙雲是乾淨的半寫實。
   - 尺寸也不一致：512×768、720×1280、768×1377。
5. 2D Q 版趙雲樣機的頭髮是棕色，正式人物圖是**黑髮**，造成識別斷裂。3D 趙雲 GLB 是寫實比例，而且背對鏡頭、沒拿槍，兩條路線無法公平比較。

## 2. 裁決
**A. 兩層風格系統（取代裁決 01 §3.1）**
- **UI／立繪層**（人物頁、轉蛋、單挑演出、戰場左上角頭像）：半寫實，以趙雲參考圖和大喬 v3 為準。
- **世界層**（大廳、戰場棋盤上的武將和兵）：**一律 Q 版約 2.3～2.5 頭身**，向大廳示意圖看齊。戰場示意圖中棋盤上的寫實兵和左下寫實趙雲，以後只能在 UI 層出現（例如單挑演出）。

**B. 視角（取代裁決 01 §3.3）**
- 世界層角色一律以**俯視 35～45°**繪製或渲染，必須和棋盤相機一致。不能再用純側面。
- 2D 路線只畫正面 3/4 一套，前提是**雙方沿螢幕水平方向對陣**；如果雙方沿斜線對陣，2D 每人就要兩套圖。這一點由技術端回報目前棋盤的對陣軸向。

**C. 比例（1920×1080 設計解析度，fitHeight）**
- 兵：在畫面上約 110～150px 高。
- 武將：兵的 1.3～1.5 倍，約 180～220px，靠體積和光環建立主從關係。
- 武器可以超出身體輪廓，但不能超出所在格子的 1.2 倍。

**D. 色彩**
- **陣營顏色只能靠底座光環、旗幟、描邊表示，不能靠角色身上的顏色**。關羽是綠色、張飛是紅色，會和藍紅陣營色或綠色敵兵混淆。敵兵的通用綠也要改成中性色。
- 戰場背景要降低飽和度和明度，世界層角色比背景高一階飽和度，加上邊緣光和接地陰影，避免看起來像貼紙。
- 每位武將的識別色取自正式人物圖：趙雲是藍、白、銀，**黑髮**；關羽是綠、金；張飛是紅、黑；呂布是紅、金、銀加雉翎；貂蟬是粉、白、金。

**E. 路線優先順序（修正裁決 01「暫停 3D」）**
- 棋盤和兵本來就是 3D，大廳又是 3D 風格的 Q 版，所以 **3D Q 版共用底模恢復為和 Spine 同等的候選**。
- 只做一個 Q 版趙雲底模、不做多角色，放在**實際的戰場相機**下和 Spine 版本並排比較。
- 比較項目：
  - 畫面是否融入棋盤
  - 能否看到前後方向
  - 換武器的難度
  - 第二位角色的工時
  - 記憶體和 draw call
- Rigby／Spine 的 L3 播放驗證照常進行，不受影響。

## 3. 請技術端回報
1. 目前棋盤雙方的對陣軸向：沿螢幕水平，還是沿斜線？附截圖。
2. `sp.Skeleton` 放在 3D 透視棋盤上，能否正確排序、能否做朝向鏡頭的處理（billboard）、和 3D 兵的深度交錯是否正確，至少要達到 L3 證據。
3. 3D 路線預估：一個 Q 版共用底模，加上趙雲的頭、髮、盔甲、槍，需要多少工時；動作用 Mixamo 這類免費商用動作庫重定向是否可行。
